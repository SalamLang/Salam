\chapter{Structs and Methods}%
\label{ch:structs-methods}

So far our data has been loose: an \code{int} here, a \code{str} there. But the
things we model are rarely single values. A bank account has an owner \emph{and} a
balance; a point has an $x$ \emph{and} a $y$. A \textbf{struct} lets you bundle
several values into one named type, and \textbf{methods} let you attach behaviour
to that type. Together they are how you build your own data types in Salam.

\section{Defining a struct}

A struct is declared with the \code{struct} keyword, a name, and a list of
\textbf{fields} (each a name, a type, and an optional default value), closed
with \code{end}:

\begin{salamen}
struct Point:
    pub x: int = 0
    pub y: int = 0
end
\end{salamen}

This defines a new type, \code{Point}, with two fields. Each field has a default
value (here \code{0}), which is used when you do not supply one. \code{Point} is
now a type you can use anywhere a type is expected, just like \code{int} or
\code{str}.

The word \code{pub} (short for \emph{public}) matters. Fields and methods are
\textbf{private} by default: only the struct's own methods may use them. Code
outside the struct, including \code{main}, may read or write a field only if it
is marked \code{pub}; reading a private one is error \code{E017} (``field \textquotesingle{}x\textquotesingle{} is
private in struct \textquotesingle{}Point\textquotesingle{} (mark it \textquotesingle{}pub\textquotesingle{})''). This lets a struct keep some of its
data to itself, as we will see with the bank account later in the chapter.

\section{Creating instances}

To make a value of a struct type (an \textbf{instance}), write the type name
followed by braces listing the fields you want to set:

\begin{salamen}
struct Point:
    pub x: int = 0
    pub y: int = 0
end

func main:
    origin := Point {}                 // both fields default to 0
    p := Point { x = 3, y = 4 }        // set both fields
    println origin.x, origin.y
    println p.x, p.y
    println p
end
\end{salamen}

\begin{progout}
0 0
3 4
Point {x = 3, y = 4}
\end{progout}

Inside the braces you assign fields by name with \code{field = value}. Any field
you leave out keeps its default: \code{Point \{\}} relies on the defaults for
both, giving \code{(0, 0)}. You reach a field of an instance with a dot:
\code{p.x} is \code{p}'s \code{x} field. And as the last line shows,
\code{println} can print a whole struct, field by field.

\begin{note}
Because \emph{both} of \code{Point}'s fields have defaults, \code{Point \{\}} is
a valid, fully formed value: there is no such thing as a half-built struct with
missing fields.
\end{note}

A default is \emph{optional}. A field written without \code{= value} becomes a
\textbf{required} field: every literal must supply it, or the compiler reports an
error. This is how you mark the data a struct genuinely cannot do without, while
letting the rest fall back to sensible defaults:

\begin{salamen}
struct User:
    pub name: str                 // required: no default
    pub role: str = "member"      // optional: defaults to "member"
    pub active: bool = true
end

func main:
    u := User { name = "Sara" }              // role and active default
    admin := User { name = "Max", role = "admin" }
    println u.name, u.role, u.active
    println admin.name, admin.role, admin.active
end
\end{salamen}

\begin{progout}
Sara member true
Max admin true
\end{progout}

Writing \code{User \{\}} here is a compile-time error, because the required field
\code{name} was not supplied: \code{E028}, ``struct literal \textquotesingle{}User\textquotesingle{} requires field
\textquotesingle{}name\textquotesingle{}\,''. Default fields, by contrast, may always be omitted.

\section{Reading and changing fields}

Field access with the dot works both ways: you can read a \code{pub} field, and
you can assign to one:

\begin{salamen}
struct Point:
    pub x: int = 0
    pub y: int = 0
end

func main:
    p := Point { x = 1, y = 1 }
    p.x = 10
    p.y = p.y + 5
    println p.x, p.y
end
\end{salamen}

\begin{progout}
10 6
\end{progout}

As with the slots of an array (Chapter~7), assigning to a field does not need
\code{mut}: \code{mut} is about giving \code{p} a whole new value, as in
\code{p = Point \{\}}. (Later in this chapter you will meet \code{mut func},
which lets a struct ask for stricter rules.)

\section{Structs are copied by value}

A struct behaves like the simple values of Chapter~2: assigning it, passing it to
a function, or returning it makes a \emph{copy}. Changing the copy does not affect
the original:

\begin{salamen}
struct Point:
    pub x: int = 0
    pub y: int = 0
end

func main:
    p := Point { x = 1, y = 2 }
    q := p                 // q is a copy of p
    q.x = 99
    println p.x, q.x       // p is untouched
end
\end{salamen}

\begin{progout}
1 99
\end{progout}

This ``value semantics'' makes structs predictable: a \code{Point} you hand to a
function cannot be quietly modified by that function (unless the function asks
for a reference parameter, \code{\&:}, as shown in Chapter~6). It is the same guarantee you
saw for ordinary arguments in Chapter~6, now extended to your own types.

\section{Methods: behaviour on a struct}

A struct can carry not just data but \textbf{methods}: functions that belong to
the type and act on a particular instance. You write a method inside the
\code{struct} block, exactly like a function, and refer to the current instance
as \code{this}. Like fields, methods need \code{pub} to be called from outside
the struct:

\begin{salamen}
struct Counter:
    value: int = 0
    pub mut func increment():
        this.value = this.value + 1
    end
    pub func get(): int:
        ret this.value
    end
end

func main:
    mut c := Counter {}
    c.increment()
    c.increment()
    c.increment()
    println c.get()
end
\end{salamen}

\begin{progout}
3
\end{progout}

You \emph{call} a method through an instance with the dot: \code{c.increment()}.
Inside the method, \code{this} refers to the instance the method was called on,
so \code{this.value} is \emph{that} counter's \code{value}. Each \code{Counter}
keeps its own \code{value}, and a method always works on the one it was called
through. Notice that \code{value} is \emph{not} \code{pub}: \code{main} cannot
touch it directly, only through \code{increment} and \code{get}.

Unlike an ordinary argument, a method \emph{can} change the instance it is called
on: \code{increment} really does update \code{c}'s \code{value}. That is why it
is declared \code{mut func}. Marking a method \code{mut func} tells the compiler
``this one changes the struct'', and once a struct has one, the compiler checks
the whole struct:

\begin{itemize}[leftmargin=1.4em]
  \item Every method \emph{not} marked \code{mut} gets a read-only \code{this}.
        If \code{get} tried \code{this.value = 5}, that would be error
        \code{E105} (``cannot modify \textquotesingle{}this\textquotesingle{} in method \textquotesingle{}get\textquotesingle{}: declare it \textquotesingle{}mut
        func'\,'').
  \item A \code{mut func} may only be called on a \code{mut} variable. Had we
        written \code{c := Counter \{\}} without \code{mut}, the call
        \code{c.increment()} would be error \code{E106} (``cannot call \textquotesingle{}mut func\textquotesingle{}
        \textquotesingle{}increment\textquotesingle{} on immutable \textquotesingle{}c\textquotesingle{}; declare it with \textquotesingle{}mut\textquotesingle{}\,'').
\end{itemize}

\begin{note}
\code{mut func} is optional: a struct with no \code{mut func} at all lets every
method change \code{this}. But marking the methods that change the struct makes
your intent visible, and the compiler then catches accidental changes for you.
It is good practice for any struct that has methods.
\end{note}

\section{Methods that compute and methods that act}

Just like free functions, a method may return a value or return nothing. A method
that returns a value is written with a return type after its parameter list:

\begin{salamen}
struct Rectangle:
    pub width: int = 0
    pub height: int = 0
    pub func area(): int:
        ret this.width * this.height
    end
    pub func is_square(): bool:
        ret this.width == this.height
    end
end

func main:
    r := Rectangle { width = 4, height = 4 }
    println "area:", r.area()
    println "square?", r.is_square()
end
\end{salamen}

\begin{progout}
area: 16
square? true
\end{progout}

Here \code{area} and \code{is\_square} only \emph{read} the rectangle (through
\code{this}) and compute an answer; they do not change anything. A method may also
take parameters of its own, in addition to the implicit \code{this}:

\begin{salamen}
struct Rectangle:
    pub width: int = 0
    pub height: int = 0
    pub mut func scale(factor: int):
        this.width = this.width * factor
        this.height = this.height * factor
    end
end

func main:
    mut r := Rectangle { width = 2, height = 3 }
    r.scale(5)
    println r.width, r.height
end
\end{salamen}

\begin{progout}
10 15
\end{progout}

\section{A fuller example: a bank account}

Let us combine fields and methods into something realistic: a bank account that
guards its own balance. The \code{withdraw} method returns a \code{bool} reporting
whether the withdrawal succeeded:

\begin{salamen}
import str

struct Account:
    owner: str = ""
    balance: int = 0
    pub mut func deposit(amount: int):
        this.balance = this.balance + amount
    end
    pub mut func withdraw(amount: int): bool:
        if amount > this.balance:
            ret false
        end
        this.balance = this.balance - amount
        ret true
    end
    pub func describe(): str:
        ret this.owner + " has " + str.FromInt(this.balance as i64)
    end
end

func main:
    mut acc := Account { owner = "Sara", balance = 100 }
    acc.deposit(50)
    println acc.describe()
    println "withdraw 30?", acc.withdraw(30)
    println "withdraw 1000?", acc.withdraw(1000)
    println acc.describe()
end
\end{salamen}

\begin{progout}
Sara has 150
withdraw 30? true
withdraw 1000? false
Sara has 120
\end{progout}

This is the heart of good design: the \code{Account} \emph{owns} its balance, and
because \code{balance} is private, the only way to change it after creation is
through \code{deposit} and \code{withdraw}, which enforce the rules (you cannot
withdraw more than you have). A line such as \code{acc.balance = 1000000} in
\code{main} would not compile. The data and the operations that protect it live
together in one place.

\section{Static functions: building instances}

Sometimes a function belongs to the \emph{type} rather than to one instance. The
most common case is a \textbf{constructor}, a function that builds a ready-made
value. Mark it \code{static func}: it has no \code{this}, you call it through
the type name, and because it lives inside the struct it may set private fields:

\begin{salamen}
struct Account:
    owner: str = ""
    balance: int = 0
    pub static func Open(owner: str): Account:
        ret Account { owner = owner, balance = 10 }   // a welcome bonus
    end
    pub func describe(): str:
        ret this.owner + " has " + this.balance
    end
end

func main:
    acc := Account.Open("Ali")
    println acc.describe()
end
\end{salamen}

\begin{progout}
Ali has 10
\end{progout}

\code{Account.Open("Ali")} reads naturally and keeps the rules for a new account
(here, the opening bonus) in one place. A struct may also hold constants that
belong to the type, written \code{pub const Bonus := 10} inside the struct and
used as \code{Account.Bonus}.

\section{Structs within structs}

A field may itself be a struct, letting you build larger structures from smaller
ones. You reach a nested field by chaining dots:

\begin{salamen}
struct Point:
    pub x: int = 0
    pub y: int = 0
end

struct Line:
    pub start: Point = Point {}
    pub finish: Point = Point {}
end

func main:
    ln := Line {
        start = Point { x = 0, y = 0 },
        finish = Point { x = 5, y = 5 }
    }
    println ln.start.x, ln.finish.y
end
\end{salamen}

\begin{progout}
0 5
\end{progout}

\code{ln.finish.y} reads the \code{y} field of the \code{finish} field of
\code{ln}. Composing structs this way is how you model anything with structure:
a line from two points, a person with an address, a game piece with a position
and a colour.

\subsection{Embedding with \texttt{use}}

Sometimes one struct is ``another struct plus a bit more''. A pixel is a point
with a colour. Instead of a field you would have to name every time
(\code{px.position.x}), you can \textbf{embed} the inner struct with
\code{use}. Its fields and \code{pub} methods are then reachable directly on the
outer struct:

\begin{salamen}
struct Point:
    pub x: int = 0
    pub y: int = 0
    pub func describe(): str:
        ret "(" + this.x + ", " + this.y + ")"
    end
end

struct Pixel:
    pub use Point
    pub color: str = "black"
end

func main:
    px := Pixel { x = 2, y = 3, color = "red" }
    println px.x, px.color
    println px.describe()
    println px
end
\end{salamen}

\begin{progout}
2 red
(2, 3)
Pixel {Point = Point {x = 2, y = 3}, color = "red"}
\end{progout}

\code{pub use Point} adds a field named \code{Point} to \code{Pixel} and
\emph{promotes} its members: \code{px.x} means \code{px.Point.x}, and
\code{px.describe()} calls \code{Point}'s method on that field. The literal may
set the promoted fields directly. The \code{pub} in front of \code{use} makes the
embedded \code{Point} visible outside the struct, just as for a field. If
\code{Pixel} declared its own \code{describe}, that one would win. Salam has no
class inheritance; embedding is how you reuse one struct inside another.

\begin{deep}[In Depth: structs become C structs]
Each Salam struct compiles to a plain C \code{struct} with the same fields in the
same order, and a method compiles to an ordinary C function that takes a pointer
to the struct as a hidden first argument, which is exactly what \code{this} is.
Because the layout is a direct, flat C struct, accessing a field is a single
memory read with no indirection, and passing a struct by value is a simple
memory copy. This is why structs are both convenient \emph{and} fast, and why
they map so cleanly onto C libraries through the foreign function interface
(Chapter~19).
\end{deep}

\section{Chapter summary}

\begin{itemize}[leftmargin=1.4em]
  \item A \code{struct} bundles named fields into a new type. Each field may
        carry an optional default value; a field with no default is
        \emph{required}.
  \item Fields and methods are private unless marked \code{pub}.
  \item Create an instance with \code{Type \{ field = value, ... \}}; omitted
        fields use their defaults, while required fields must be supplied.
  \item Read and write fields with the dot: \code{p.x}.
  \item Structs are copied by value on assignment, argument passing, and return.
  \item Methods live inside the \code{struct} block, refer to the instance as
        \code{this}, and are called with the dot: \code{c.increment()}.
  \item A method may read or modify \code{this}, take its own parameters, and
        return a value or nothing. Mark the methods that modify \code{this} as
        \code{mut func}; they can then only be called on a \code{mut} variable,
        and the other methods get a read-only \code{this}.
  \item A \code{static func} belongs to the type, has no \code{this}, and is
        called as \code{Type.Name(...)}; it is the place for constructors.
  \item Struct fields may themselves be structs; chain dots to reach nested
        fields. \code{use} embeds a struct and promotes its fields and methods.
\end{itemize}

\section{Exercises}

\exercise Define a \code{struct Circle} with a \code{radius: f64} field and a
method \code{area(): f64} that returns $\pi r^2$ (use \code{3.14159} for $\pi$).
Print the area of a circle of radius 2.

\exercise Add a \code{describe()} method to \code{Point} that returns a string
like \code{"(3, 4)"}, and print it for a couple of points.

\exercise Build a \code{struct Stack} around a \code{Vector<int>} field, with
\code{push} and \code{pop} methods and a \code{size()} method. Push three values
and pop them back, then free the vector.

\exercise Extend the \code{Account} example with a function
\code{transfer(src \&: Account, dst \&: Account, amount: int): bool} that
withdraws from one account and deposits into the other, only if the withdrawal
succeeds.

\exercise Define a \code{struct Rectangle} with a \code{perimeter()} method as well
as \code{area()}, and print both for a $3 \times 5$ rectangle.

\exercise Model a \code{struct Person} containing a \code{name} and an
\code{Address} struct (street, city). Create one and print the city via chained
field access.
