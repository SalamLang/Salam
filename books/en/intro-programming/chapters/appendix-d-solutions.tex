\chapter{Solutions to Selected Exercises}%
\label{app:solutions}

Here are worked solutions to a selection of exercises from across the book. They
are not the only correct answers (programming rewards many paths to the same
result), but each is complete, idiomatic, and runs as shown. Try the exercise
yourself before reading the solution; the struggle is where the learning happens.

\section*{Chapter 1: Getting Started}

\textbf{Exercise 1.2} (print a labelled calculation):

\begin{salamen}
func main:
    println "12 * 8 =", 12 * 8
end
\end{salamen}

\begin{progout}
12 * 8 = 96
\end{progout}

\section*{Chapter 2: Variables and Data Types}

\textbf{Exercise 2.3} (average as a float):

\begin{salamen}
func main:
    sum := 10 + 15 + 20
    avg := (sum as f64) / 3.0
    println "average =", avg
end
\end{salamen}

\begin{progout}
average = 15
\end{progout}

The cast to \code{f64} is what makes this a real division; without it
\code{45 / 3} would (here, coincidentally) also give 15, but for totals that do
not divide evenly, integer division would throw the remainder away.

    println 13, "in 1..12?", in_range(13)

\end{salamen}

\begin{progout}

\end{progout}

\textbf{Exercise 3.6} (cube in place with \code{**=}):

\begin{salamen}
func main:
    mut side := 3.0
    side **= 3
    println side
end
\end{salamen}

\begin{progout}
27
\end{progout}

Starting from \code{mut side := 3} instead gives a compile error:

\begin{shell}
error[E002]: cannot assign 'f64' to 'i32'
\end{shell}

\noindent The literal \code{3} makes \code{side} an \code{int} (which is
\code{i32}), while \code{**} always produces an \code{f64}. An \code{f64} cannot
be stored back into an \code{int} variable without an explicit \code{as int}
cast, so \code{side **= 3} is rejected the same way \code{side = side ** 3}
would be.

\section*{Chapter 6: Functions}

\textbf{Exercise 6.4} (recursive sum):

\begin{salamen}
func sum_to(n: int): int:
    if n <= 0: ret 0 end       // base case
    ret n + sum_to(n - 1)      // recursive step
end

func main:
    println sum_to(10)
end
\end{salamen}

\begin{progout}
55
\end{progout}

The \code{if n <= 0} line is the base case: it answers without calling
\code{sum\_to} again. The last line is the recursive step: it solves a smaller
problem, \code{sum\_to(n - 1)}, and adds \code{n} to the result.

\begin{progout}

\end{progout}

\textbf{Exercise 9.4} (a transfer between accounts):

\begin{salamen}
import str

struct Account:
    owner: str = ""
    balance: int = 0
    pub mut func deposit(amount: int):
        this.balance = this.balance + amount
    end
    pub mut func withdraw(amount: int): bool:
        if amount > this.balance:
            ret false
        end
        this.balance = this.balance - amount
        ret true
    end
    pub func describe(): str:
        ret this.owner + " has " + str.FromInt(this.balance as i64)
    end
end

func transfer(src &: Account, dst &: Account, amount: int): bool:
    if not src.withdraw(amount):
        ret false
    end
    dst.deposit(amount)
    ret true
end

func main:
    mut a := Account { owner = "Sara", balance = 100 }
    mut b := Account { owner = "Ali", balance = 20 }
    println transfer(a, b, 30)
    println transfer(a, b, 500)
    println a.describe()
    println b.describe()
end
\end{salamen}

\begin{progout}
true
false
Sara has 70
Ali has 50
\end{progout}

The \code{\&:} parameters let \code{transfer} change the caller's two accounts.
Because \code{withdraw} is checked first, a failed withdrawal leaves both
accounts untouched.

\section*{Chapter 10: Enums and Matching}

\textbf{Exercise 10.3} (turn right):

\begin{salamen}
enum Direction: North, East, South, West end

func turn_right(d: Direction): Direction:
    ret match d:
        Direction.North: Direction.East end
        Direction.East: Direction.South end
        Direction.South: Direction.West end
        Direction.West: Direction.North end
    end
end

func main:
    mut d := Direction.North
    d = turn_right(d)
    println "now facing index:", d as int
    d = turn_right(turn_right(turn_right(d)))
    println "back to index:", d as int
end
\end{salamen}

\begin{progout}
now facing index: 1
back to index: 0
\end{progout}

Because \code{match} is exhaustive, forgetting one of the four directions is a
compile error rather than a silent wrong answer.

\end{salamen}

\begin{progout}

\end{progout}

\textbf{Exercise 14.3} (the order of two \code{defer}s):

\begin{salamen}
func work:
    defer println "first defer"
    defer println "second defer"
    println "body"
end

func main:
    work()
end
\end{salamen}

\begin{progout}
body
second defer
first defer
\end{progout}

The body runs first; then the deferred statements run when the function ends,
the most recently deferred one first.

\textbf{Exercise 14.6} (percentages with \code{Result} and \code{?}):

\begin{salamen}
import result

func parse_percent(n: int): result.Result<int, str>:
    if n < 0 or n > 100:
        ret result.Result.Err("not a percentage: " + n)
    end
    ret result.Result.Ok(n)
end

func add_percents(a: int, b: int): result.Result<int, str>:
    x := parse_percent(a)?
    y := parse_percent(b)?
    ret result.Result.Ok(x + y)
end

func main:
    println result.UnwrapOr(add_percents(30, 45), -1)
    println result.UnwrapOr(add_percents(30, 450), -1)
end
\end{salamen}

\begin{progout}
75
-1
\end{progout}

The first \code{?} that meets an \code{Err} returns it from
\code{add\_percents} at once, so with 450 the addition never happens and the
caller gets the error (here replaced by \code{-1}).

\section*{Chapter 21: Testing and Debugging}

\textbf{Exercise 21.1} (testing factorial):

\begin{salamen}
import testing

func factorial(n: int): int:
    if n <= 1: ret 1 end
    ret n * factorial(n - 1)
end

func test_factorial:
    testing.AssertEqInt(factorial(0), 1)
    testing.AssertEqInt(factorial(5), 120)
    testing.AssertEqInt(factorial(3), 6)
end

func main:
    test_factorial()
    ret testing.Summary()
end
\end{salamen}

\begin{progout}
--
tests: 3 passed, 0 failed
\end{progout}

\code{testing.Summary} returns the number of failed checks, so returning it from
\code{main} makes the program's exit code 0 exactly when every test passed.
