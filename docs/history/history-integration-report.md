# History work on the master branch

`master` is `main` plus two commits. `main` was not touched and the default branch was not changed.

## What changed

1. Contributor restoration (merge commit `96c185fa6`).
   - Cause: after the history on `main` was rewritten, many contributors' commits were no longer reachable from `main`, so GitHub's contributor list dropped them.
   - Source: their original commits still exist under `refs/pull/N/head`, saved in the mirror backup.
   - Method: for every merged pull request not authored by the owner or a bot, each non-merge commit missing from `main` was recreated as an empty commit. It keeps the original author name, email, author date and message, and adds one line, `Restored-from: PR #N, original commit <sha>`. The commits form one chain rooted at the first commit, joined to `main` with `git merge -s ours`, so `main`'s file contents are unchanged.
   - Deduplication: a commit that appears in two pull request branches under different hashes is restored once, keyed by author email, author date and subject. 76 duplicates were removed.
   - Excluded: bots, Copilot, and two placeholder addresses (`you@example.com`, `frank@gmail.com`).
   - Result: 890 commits by 34 author emails. Their author dates run from 2024-03-01 to 2026-10-31 and none was changed. The committer of each is the repository owner, because the commits were created here.

2. `.gitattributes` (commit `808a4c1e8`). Generated files are marked `linguist-generated`, so diffs collapse and GitHub's language statistics leave them out. Each path was confirmed generated by its own header or generator:
   - editor syntax files from `extensions/tools/gen_syntaxes.salam`
   - `std/unicode/tables.salam` from `tools/salam/gen-unicode-tables.salam`
   - `docs/ai/stdlib-index.json`, kept by the stdlib-index prek hook
   - `docs/CSS_PROPERTIES.md` and `docs/LAYOUT_ELEMENTS.md`, generated from `std/layout`
   - `benchmark/results/**`, written by the benchmark runner
   - lockfiles
   - `books/fonts/**` is marked `linguist-vendored`

3. These reports in `docs/history/`.

## What was not done

- One's history was not merged or grafted. See `history-investigation.md`.
- No dates were changed. No commit was backdated.
- No existing commit on `main` was rewritten.

## Reading the history

- `git log --first-parent` shows only the real mainline plus the one restoration merge.
- `git log --grep '^Restored-from:'` lists the restored commits.
- Restored commits have no file changes. Use `git log --no-merges --first-parent` or `git blame` for code history.

## Limits and manual steps

- GitHub lists a contributor only when a commit email matches an account. Commits made with an email that GitHub cannot link will not count.
- Restoration covers merged pull requests only. Commits from closed, unmerged pull requests were not restored.
- The contributor count on GitHub changes only after `master` becomes the default branch.
- Deleting `main` closes or breaks pull requests, branch rules and workflows that reference it. Check them before the swap.
- The restored committer name is the owner's. If you prefer another committer identity, the chain can be rebuilt from the backup.
