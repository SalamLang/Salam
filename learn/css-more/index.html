Lists and their markers

Every item of a list has a marker: the bullet of a list or the number of an ordered list. The browser draws it, and you choose how with three properties. list style type sets the look. It takes a keyword such as disc, square, decimal, lower-roman or upper-alpha, none for no marker, or a text of your own. A text must keep its quotes in the CSS, so in Salam write it between backticks: list style type = `"» "`. list style position says whether the marker hangs outside the text (outside, the default) or sits inside the first line (inside). list style image uses a picture or a gradient instead of a character.

list style is the shorthand for all three, written as one string such as "square outside". Look at the last two lists in the preview: with a marker outside, every line of a long item starts at the same edge, and with a marker inside the second line wraps under the marker.

web-more-lists.salam
page:
    title = "List markers"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    heading: size = 3 content = "Roman numerals" end
    ordered list: list style type = lower-roman
        item: content = "Preface" end
        item: content = "Chapters" end
        item: content = "Index" end
    end
    heading: size = 3 content = "Your own marker" end
    list: list style type = `"» "`
        item: content = "Open the box" end
        item: content = "Read the label" end
    end
    heading: size = 3 content = "Inside and outside" end
    list: list style position = inside background = "#ccfbf1" max width = "20rem" padding = 8
        item: content = "The marker sits inside the text, so a second line starts under it." end
    end
    list: list style = "square outside" background = "#e2e8f0" max width = "20rem" padding = 8 padding inline start = 32
        item: content = "The marker hangs outside, so every line starts at the same edge." end
    end
    list: list style image = "linear-gradient(#0f766e, #38bdf8)"
        item: content = "An image as the marker" end
    end
end

These properties style the marker as a whole. You cannot give one marker a color of its own with them. The marker takes the color and the font of its item, so to change it, change the item.

Counters: numbering with CSS

A counter is a number that the browser keeps under a name. Three properties work with it. counter reset creates it on an element, or sets it back to a start value: "chapter" starts at 0 and "chapter 4" at 4. counter increment adds to it each time an element that has the property is drawn, by 1 or by the number you give. counter set puts a value into it without adding. When both increment and set sit on one element, the set wins.

A counter is invisible until you print it. For that, write counter(chapter) in the generated content of a before or after rule, which adds text in front of or behind an element. A text next to it goes in quotes inside the string: "counter(chapter) \". \"". If you reset a lesson counter on every chapter heading, it starts again in each chapter and gives 1.1, 1.2, 2.1. The example does exactly that: every chapter heading resets the lesson counter and every lesson paragraph increments it.

web-more-counters.salam
page:
    title = "Numbered outline"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    box: counter reset = chapter
        heading:
            size = 3
            counter increment = chapter
            counter reset = lesson
            before generated content = "counter(chapter) \". \""
            content = "Getting started"
        end
        paragraph: counter increment = lesson before generated content = "counter(chapter) \".\" counter(lesson) \"  \"" content = "Install the compiler" end
        paragraph: counter increment = lesson before generated content = "counter(chapter) \".\" counter(lesson) \"  \"" content = "Your first page" end
        heading:
            size = 3
            counter increment = chapter
            counter reset = lesson
            before generated content = "counter(chapter) \". \""
            content = "Styling"
        end
        paragraph: counter increment = lesson before generated content = "counter(chapter) \".\" counter(lesson) \"  \"" content = "Colors and fonts" end
        heading:
            size = 3
            counter set = "chapter 9"
            counter reset = lesson
            before generated content = "counter(chapter) \". \""
            content = "Appendix"
        end
        paragraph: counter increment = lesson before generated content = "counter(chapter) \".\" counter(lesson) \"  \"" content = "Glossary" end
    end
end

The appendix heading uses counter set = "chapter 9": it jumps to 9 and its lessons follow as 9.1. The counter() function takes a second value, a list style, and the Persian version of the example uses it as counter(chapter, persian) to print Persian digits. For nested numbers such as 1.2.3 in one go, counters(name, ".") joins every level of the counter with a separator.

The before and after prefixes work on elements and components, but not inside a global rule, where they are silently dropped. If the numbering does not appear, check where the rule is written. Also note that two elements with the same styles share one CSS class, while two with different styles that you named with the same class are a compile error, so name a class only on elements that really look alike.

Quotation marks

The quote element puts quotation marks around its text, and which marks it uses comes from the quotes property. The value is pairs of strings: the first pair is the outer level, the second pair is for a quote inside a quote, and so on. Quote marks in the value need backticks again. The first two paragraphs of the example show the same nested sentence with two sets of marks. quotes = "none" removes the marks, and for a block quote, which has none of its own, you can add them with the keywords open-quote and close-quote in generated content, as in the last line of the example. Those keywords use the same quotes pairs, so the marks stay consistent.

web-more-quotes.salam
page:
    title = "Quotation marks"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    paragraph: quotes = `"“" "”" "‘" "’"`
        content = "Sara said, "
        quote: content = "Omid told me "
            quote: content = "never stop" end
        end
        span: content = "." end
    end
    paragraph: quotes = `"«" "»" "‹" "›"`
        content = "The same sentence with other marks: "
        quote: content = "Omid told me "
            quote: content = "never stop" end
        end
    end
    block quote: quotes = "none" border = "none" margin = "1rem 0" color = "#475569"
        content = "Quote marks off."
    end
    block quote: quotes = `"[" "]"` color = "#0f766e"
        before generated content = open-quote
        after generated content = close-quote
        content = "Added with open-quote and close-quote."
    end
end

Table borders and layout

A table has two models for its borders. With border collapse = separate (the default) every cell keeps a complete border of its own and the gaps between cells are set with border spacing: one length for both directions, or two for horizontal and vertical. With collapse neighbouring borders merge into a single line and border spacing does nothing. empty cells = hide leaves out the border and background of a cell with no content, but only in the separate model. caption side moves the caption to the bottom. The first table below shows the separate model with its hidden empty cell, and the second shows collapsed borders.

web-more-table.salam
page:
    title = "Table settings"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    global: selector = "td, th" border = "2px solid #0f766e" padding = "6 14" end
    table: border collapse = separate border spacing = "10 4" empty cells = hide caption side = bottom margin = "0 0 1.5rem"
        caption: content = "Separate borders, empty cells hidden" end
        header:
            row:
                column: content = "Item" end
                column: content = "Note" end
            end
        end
        row:
            cell: content = "Tea" end
            cell: end
        end
    end
    table: border collapse = collapse table layout = fixed width = "22rem"
        caption: content = "Collapsed borders, fixed layout" end
        header:
            row:
                column: content = "Item" end
                column: content = "A long heading in a column of fixed width" end
            end
        end
    end
end

The second table uses table layout = fixed. With the default auto layout the browser measures every cell before it decides on column widths, so one long cell can stretch its column and the table can end up wider than you asked. A fixed layout reads only the table width and the first row and divides the space, so the columns stay put and long text wraps inside them. It also draws a big table faster. It needs a width on the table to have any effect.

Scrolling that snaps

Scroll snapping makes a scrolling box come to rest on chosen points instead of anywhere, like the pages of a gallery. It takes two sides. On the scroll container, scroll snap type turns it on: an axis (x, y or both) and a strictness. mandatory always comes to rest on a point, proximity only when the scroll stops near one. On each child, scroll snap align says which edge of the child lines up with the container: start, center or end. scroll snap stop = "always" adds that a fast flick may not skip past the child, which is what you want for a slide show.

The example below is a strip of four slides. The container has overflow x = auto to scroll and scroll snap type = "x mandatory". The slides are styled with one global rule using the selector #strip > *, which is shorter than repeating the same line on four boxes. Scroll the strip with your finger, a mouse wheel or the keys and watch it settle on a slide.

web-more-snap.salam
page:
    title = "Snapping slides"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    global: selector = "#strip > *" flex = "0 0 80%" height = 120 color = white font size = "1.6rem" display = flex align items = center justify content = center border radius = 12 scroll snap align = start scroll snap stop = always end
    style: content = "#strip::scroll-marker-group { display: flex; gap: 8px; justify-content: center; padding: 8px } #strip > *::scroll-marker { content: ''; width: 10px; height: 10px; border-radius: 50%; background: #94a3b8 } #strip > *::scroll-marker:target-current { background: #0f766e }" end
    box: id = "strip" display = flex gap = 12 overflow x = auto padding = "0 20" scroll snap type = "x mandatory" scroll padding = "0 20" scroll marker group = after
        box: background = "#0f766e" content = "One" end
        box: background = "#2563eb" content = "Two" end
        box: background = "#c2410c" content = "Three" end
        box: background = "#7c3aed" content = "Four" end
    end
    paragraph: content = "Scroll the strip sideways. It always stops with a slide at the edge." end
end

Two more properties adjust where "start" is. scroll padding goes on the container and shrinks the area that counts: "0 20" keeps a slide 20 pixels away from the left and right edges, so that the next slide peeks in, and it stops a fixed header from covering a heading that the page jumps to. scroll margin goes on the child and grows its snap area on its own. Both come in sides: top, right, bottom and left, and the logical ones, block and inline with start and end, which turn around in a right to left page. Use the logical ones for anything that scrolls sideways, because in a Persian page the first slide is at the right.

The little dots in the preview are made by the browser, not by elements. scroll marker group = "after" asks for a row of markers after the container, one for each child, and the raw style element styles them with ::scroll-marker and ::scroll-marker-group, which the page language has no names for. The dot of the slide in view also matches :target-current, so it can have its own color, and clicking a dot scrolls to its slide. scroll target group = "auto" does the same job for a list of links, such as a table of contents that highlights the section you are reading. Both exist today in Chromium browsers only, so keep the page usable without them.

Snapping only helps readers who scroll. Do not use it to hide content: keep everything within reach of a plain scroll, and try the page with the keyboard too, which moves the container in the same way.

Anchor positioning

A tooltip, a menu or a popup belongs next to the thing it explains. For years that needed JavaScript that measured the page. Anchor positioning does it in CSS. You give an element a name with anchor name, which must start with two hyphens, like "--target". Another element that is position = absolute chooses that name with position anchor and says where to sit with position area. The area is a cell of a three by three grid around the anchor: top, bottom, left, right, center, corners such as top right, and stretched cells like top span-right.

The example has four buttons. Each one runs a small function when it is clicked, and the function sets the position-area of the tooltip with dom.SetStyle. The tooltip jumps around the anchor and no coordinates are calculated anywhere. The functions of dom are described on the dom page.

web-more-anchor.salam
import dom

page:
    title = "Anchored tooltip"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    box: display = flex gap = 8 margin = "0 0 1rem"
        button: click = (): dom.SetStyle(dom.ById("tip"), "position-area", "top") end content = "Top" end
        button: click = (): dom.SetStyle(dom.ById("tip"), "position-area", "right") end content = "Right" end
        button: click = (): dom.SetStyle(dom.ById("tip"), "position-area", "bottom") end content = "Bottom" end
        button: click = (): dom.SetStyle(dom.ById("tip"), "position-area", "left") end content = "Left" end
    end
    box: position = relative height = 220 border = "1px dashed #94a3b8" border radius = 8
        box: id = "target" anchor name = "--target" margin = "80 auto 0" width = 120 padding = 12 text align = center background = "#0f766e" color = white border radius = 6 content = "Anchor" end
        box: id = "tip" position = absolute position anchor = "--target" position area = top position try fallbacks = flip-block position visibility = anchors-visible margin = 6 padding = "4 10" background = "#0f172a" color = white border radius = 6 content = "Tooltip" end
    end
end

Two more properties make the tooltip behave near the edge of the screen. position try fallbacks = "flip-block" lists other places to try when the first one would run off screen: flip-block mirrors it to the other side, flip-inline does so sideways. position visibility = "anchors-visible" hides the tooltip when its anchor has scrolled out of view, so that it does not float alone. position try order and the shorthand position try rank the fallbacks by the room they leave. Finally anchor scope keeps names local to a part of the page, so that a component used ten times can use the same name in each copy without mixing them up.

Anchor positioning is new. Chromium browsers have it and the others are catching up, and a browser that lacks it ignores these lines, so the tooltip stays where it would be without them. Test it in the browsers your readers use, and have a plain fallback such as showing the text below the button.

SVG presentation properties

The svg element holds a drawing. Its content is raw SVG markup that the compiler passes on unchanged, so shapes such as <circle> and <path> are written as text. What the page language adds is the styling. The properties of this section are SVG presentation properties, and they reach the shapes in two ways.

The first way is inheritance. fill, stroke, stroke width, paint order, text anchor and the marker properties are inherited, so one line on the svg element styles every shape inside. fill is the color inside a shape and stroke is the line along its edge; with no stroke only the fill shows. The first example puts them on three drawings. fill rule = "evenodd" leaves a hole in the star where its lines cross. stroke dasharray alternates dash and gap, stroke dashoffset shifts the pattern, and a round stroke linecap turns the dashes into dots. stroke linejoin shapes a corner, and stroke miterlimit cuts a sharp point flat when it would stick out too far.

web-more-svg-stroke.salam
page:
    title = "Fill and stroke"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    box: display = flex gap = 24 flex wrap = wrap
        box:
            svg: view box = "0 0 100 100" width = 120 height = 120 fill = "#5eead4" fill opacity = 0.6 fill rule = evenodd stroke = "#0f766e" stroke width = 3 stroke linejoin = round
                content = "<polygon points='50,5 80,95 5,35 95,35 20,95'/>"
            end
            paragraph: content = "Even-odd fill" end
        end
        box:
            svg: view box = "0 0 100 100" width = 120 height = 120 fill = none stroke = "#c2410c" stroke width = 8 stroke linecap = round stroke dasharray = "1 14" stroke dashoffset = 4
                content = "<circle cx='50' cy='50' r='38'/>"
            end
            paragraph: content = "Dotted line" end
        end
        box:
            svg: view box = "0 0 100 100" width = 120 height = 120 fill = none stroke = "#2563eb" stroke width = 14 stroke linejoin = miter stroke miterlimit = 2
                content = "<polyline points='15,85 50,15 85,85'/>"
            end
            paragraph: content = "Sharp corner, cut by the limit" end
        end
    end
end

Text in SVG has its own rules. text anchor decides which part of the text sits on its x point: middle centres it. paint order = "stroke fill" draws the outline first, so the fill covers its inner half and outlined letters stay thick. dominant baseline and baseline shift change the line that letters rest on, and they are not inherited, so they go on one text only. That is the second way to reach a shape: a global rule with a selector such as "#b". The page language does not name the shapes inside the raw markup, but CSS can still find them by id, class or tag.

web-more-svg-text.salam
page:
    title = "Text in SVG"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    global: selector = "#a" dominant baseline = hanging end
    global: selector = "#b" dominant baseline = middle end
    global: selector = "#sup" baseline shift = super font size = 14 end
    svg: view box = "0 0 360 140" width = 360 height = 140 font size = 20 font weight = bold fill = "#fde68a" stroke = "#0f172a" stroke width = 4 paint order = "stroke fill" text anchor = middle
        content = "<line x1='0' y1='45' x2='360' y2='45' stroke='#ef4444' stroke-width='1'/><text id='a' x='60' y='45'>hanging</text><text id='b' x='180' y='45'>middle</text><text x='300' y='45'>alphabetic</text><text x='180' y='110'>E = mc<tspan id='sup'>2</tspan></text>"
    end
end

The same way works for the properties that only a shape has. cx, cy and r place and size a circle, rx and ry do it for an ellipse or round the corners of a rectangle, x and y move a rectangle, and d holds the outline of a path. They are attributes in old SVG and CSS properties in modern browsers, which is what lets a hover rule grow the circle below and a transition animate it.

web-more-svg-geometry.salam
page:
    title = "Geometry from CSS"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    global: selector = "#c" cx = 60 cy = 60 r = 30 transition = "r 0.2s" end
    global: selector = "#c:hover" r = 48 end
    global: selector = "#e" cx = 170 cy = 60 rx = 40 ry = 22 end
    global: selector = "#r" x = 230 y = 30 rx = 14 ry = 14 end
    global: selector = "#p" d = "path('M 10 135 C 70 112 130 112 190 135 L 290 135')" end
    svg: view box = "0 0 300 140" width = 300 height = 140 stroke = "#0f172a" stroke width = 2
        content = "<circle id='c' fill='#5eead4'/><ellipse id='e' fill='#fde68a'/><rect id='r' width='60' height='60' fill='#fca5a5'/><path id='p' fill='none'/>"
    end
    paragraph: content = "Point at the circle: its radius is a CSS property here." end
end

Write the path in d with C or L rather than Q. A number followed by a space and Q can be read by the page compiler as the length unit q, which breaks the path. This only happens in CSS written with the page language: the d attribute inside the raw markup is passed on untouched.

Gradients and filters are written in the raw markup too, but their colors are CSS properties. stop color and stop opacity color a gradient stop, flood color and flood opacity color an feFlood step of a filter, and lighting color does so for the lighting steps. color interpolation filters picks the color space in which a filter works, sRGB or linearRGB. Because stops and filter steps are not inherited, you reach them through global rules again.

web-more-svg-paint.salam
page:
    title = "Gradient stops and filters"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    global: selector = ".s1" stop color = "#0f766e" stop opacity = 1 end
    global: selector = ".s2" stop color = "#2563eb" stop opacity = 0.25 end
    global: selector = ".tint" flood color = "#7c3aed" flood opacity = 0.5 end
    global: selector = "filter" color interpolation filters = sRGB end
    svg: view box = "0 0 220 120" width = 220 height = 120
        content = "<defs><linearGradient id='g' x1='0' x2='1'><stop class='s1' offset='0'/><stop class='s2' offset='1'/></linearGradient><filter id='f'><feFlood class='tint' result='c'/><feComposite in='c' in2='SourceGraphic' operator='in' result='t'/><feMerge><feMergeNode in='SourceGraphic'/><feMergeNode in='t'/></feMerge></filter></defs><rect x='5' y='10' width='100' height='100' rx='10' fill='url(#g)'/><rect x='115' y='10' width='100' height='100' rx='10' fill='#38bdf8' filter='url(#f)'/>"
    end
    paragraph: content = "Left: a gradient whose stops are colored with CSS. Right: a filter whose flood color comes from CSS." end
end

Markers are small shapes drawn on the points of a line. marker start, marker mid and marker end take url(#id) of a marker element, and the shorthand marker sets all three at once. Put the marker elements in a separate svg as the example does, because markers inherit the stroke and the marker properties of the drawing they sit in. vector effect = "non-scaling-stroke" keeps a line the same thickness when the drawing is scaled, and shape rendering and color interpolation are hints for how edges and gradients are drawn.

web-more-svg-markers.salam
page:
    title = "Markers on a line"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    svg: width = 0 height = 0 position = absolute
        content = "<defs><marker id='start' viewBox='0 0 10 10' refX='5' refY='5' markerWidth='6' markerHeight='6'><circle cx='5' cy='5' r='5' fill='#2563eb'/></marker><marker id='mid' viewBox='0 0 10 10' refX='5' refY='5' markerWidth='5' markerHeight='5'><rect width='10' height='10' fill='#f59e0b'/></marker><marker id='end' viewBox='0 0 10 10' refX='8' refY='5' markerWidth='8' markerHeight='8' orient='auto'><path d='M0 0 L10 5 L0 10 z' fill='#dc2626'/></marker></defs>"
    end
    svg: view box = "0 0 300 120" width = 300 height = 120 fill = none stroke = "#0f766e" stroke width = 3 marker start = "url(#start)" marker mid = "url(#mid)" marker end = "url(#end)"
        content = "<polyline points='20,90 100,30 180,80 270,30'/>"
    end
    paragraph: content = "A dot at the start, squares at the corners, an arrow at the end." end
end

Math

The math element draws a formula. Like svg, its content is raw markup, here MathML, such as <mfrac> for a fraction and <msup> for a power. Three properties change how it is set. math style is normal for a display formula, with large operators and limits above and below, or compact for one inside a line of text, with everything tighter. math depth says how deeply the formula is nested, so that it can be drawn smaller. It changes the size only where font-size is the keyword math, which the page language does not accept yet, so the example sets it in a raw style element. math shift chooses how far superscripts are raised: compact raises them less, as in the denominator of a fraction.

web-more-math.salam
page:
    title = "Math styles"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    global: selector = "math" font size = "1.6rem" margin = "0 1.5rem 0 0" end
    paragraph: content = "Math style: normal, then compact" end
    box: display = flex
        math: math style = normal
            content = "<munderover><mo>&#x2211;</mo><mrow><mi>i</mi><mo>=</mo><mn>1</mn></mrow><mi>n</mi></munderover><mfrac><mn>1</mn><mi>i</mi></mfrac>"
        end
        math: math style = compact
            content = "<munderover><mo>&#x2211;</mo><mrow><mi>i</mi><mo>=</mo><mn>1</mn></mrow><mi>n</mi></munderover><mfrac><mn>1</mn><mi>i</mi></mfrac>"
        end
    end
    style: content = "#d0, #d1, #d2 { font-size: math }" end
    paragraph: content = "Math depth 0, 1 and 2 side by side" end
    box: display = flex align items = baseline font size = "3rem"
        math: id = "d0" math depth = 0 content = "<mi>x</mi><mo>+</mo><mn>1</mn>" end
        math: id = "d1" math depth = 1 content = "<mi>x</mi><mo>+</mo><mn>1</mn>" end
        math: id = "d2" math depth = 2 content = "<mi>x</mi><mo>+</mo><mn>1</mn>" end
    end
end

Reading order, the top layer and HDR

Keyboard focus and screen readers move through a page in the order of the source. When a layout changes the visual order, for example with flex direction = row-reverse, the two disagree and a keyboard user jumps around the screen. reading flow on the container fixes that: flex-visual follows what is drawn, grid-rows and grid-columns do the same for a grid, and source-order lets the reading order number of each child decide, lowest first. In the example press Tab: the first row is read in source order, the second in the order you see.

web-more-reading.salam
import dom

page:
    title = "Reading order"
    global: selector = "body" font family = "system-ui, sans-serif" margin = "1.5rem" line height = 1.6 end
    paragraph: id = "out" content = "Press Tab and watch the focus." end
    box: display = flex flex direction = row-reverse gap = 8 margin = "0 0 1rem"
        button: focus = (): dom.SetText(dom.ById("out"), "Focus: A") end content = "A" end
        button: focus = (): dom.SetText(dom.ById("out"), "Focus: B") end content = "B" end
        button: focus = (): dom.SetText(dom.ById("out"), "Focus: C") end content = "C" end
    end
    box: display = flex flex direction = row-reverse gap = 8 reading flow = flex-visual
        button: focus = (): dom.SetText(dom.ById("out"), "Focus: D") end content = "D" end
        button: focus = (): dom.SetText(dom.ById("out"), "Focus: E") end content = "E" end
        button: focus = (): dom.SetText(dom.ById("out"), "Focus: F") end content = "F" end
    end
end

In a right to left page the visual order starts at the right, so the same property gives a different sequence, and the Persian version of this example shows it. Two more properties are for special cases. overlay reports whether an element is in the top layer, where popovers and dialogs are drawn; you list it in a transition so that an element leaving the top layer can finish its exit animation first. dynamic range limit limits how bright HDR images and video may get on a screen that supports it, from standard to no-limit.

Reference: the remaining properties

Every property of this lesson is below with its Persian name, the CSS name, what it accepts and an example that the compiler has checked. A bare number is a length in pixels, and any CSS keyword can be written without quotes unless it is also a word of the page language, such as end, in which case put it in quotes.

[normal / source-order / flex and grid flow keywords]box: display = flex flex direction = row-reverse reading flow = "flex-visual" button: content = "One" end button: content = "Two" end end

ترتیب خواندن
reading-order		Chromium only. A whole number that ranks a child inside a container whose reading-flow is not normal.
