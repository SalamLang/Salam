What the compiler insists on

The Salam compiler catches a great many mistakes before the program ever runs, and every message says where the problem is and usually how to fix it. This lesson shows the ones you will meet most.

In this lesson
  1. Why so strict?
  2. The errors you will meet most
  3. A few hints

Why so strict?

Every error the compiler catches is an error that never reaches a user. That is why Salam treats as errors several things other languages only warn about. Each message carries a code, the exact line and column, and a suggestion.

The errors you will meet most

What you wroteWhat the compiler says
number := 5 and never using itE059 unused variable 'number': nothing uses it after it is declared
number := 5 then number = 6E013 cannot reassign immutable variable 'number'; declare it 'mut' to reassign it
mut number := 5 never changedE069 variable 'number' is declared 'mut' but never mutated; remove 'mut' or declare it 'const'
if number:E021 if condition must be bool, got 'i32'
if false:E068 'if' condition is always false: its body can never run
An empty if branchE060 the 'if' branch is empty: add a statement to it, or remove the 'if'
number = "five"E002 cannot assign 'str' to 'i32'
A const after a functionE084 constant 'RATE' must be declared before any function or type definition
A function nothing callsE066 unused function 'helper': it is private and nothing calls it

A few hints

  • If you deliberately do not use something, start its name with _.
  • The message usually tells you the fix as well; read to the end of it.
  • Salam has no exceptions. Report failure with a returned value, such as a bool or an enum like Result.
