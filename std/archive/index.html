An archive gathers several files into one. Zip compresses each file on its own; tar only puts the files one after another and is usually gzipped afterwards (.tar.gz).

The functions work both in memory and on files. They take the archive data as an address and a length, such as b.data and b.len of a byte buffer.

Limits to know about

  • Zip: zip64 is read and written (64-bit sizes and offsets, the zip64 end record, more than 65535 entries), but the package counts bytes in an int, so in practice an archive and each entry must stay under 2 GB. A bigger entry is listed with its true size, and extracting it reports ZIP_TOO_BIG; ZipCreate returns an empty buffer (and ZipCreateFile false) for input it cannot hold: a negative length, a null address with a length, a name over 65535 bytes, or about 1.9 GB in total. ZipCreate switches to zip64 on its own only for 65535 entries or more; ZipCreate64 always writes the zip64 form, which unzip and 7z read. Methods 0 (stored), 8 (DEFLATE), 12 (bzip2), 14 (LZMA) and 93 (zstd) are read and written, and 9 (Deflate64, what 7-Zip writes with -mm=Deflate64) is read; any other method is reported as ZIP_UNSUPPORTED, and encrypted entries are written as ZipCrypto or WinZip AES-128, AES-192 or AES-256 (ZipFileInput.password and encryption); the in-memory readers refuse them, use ZipOpenFile. ZipExtractByName and ZipExtractByNameMax do not check the CRC-32; ZipExtractVerified, ZipVerify and ZipExtractAll do, and ZipExtractAll skips an entry that fails the check and returns false.
  • Zip names and dates: a name with non-ASCII bytes is written with the UTF-8 flag (general purpose bit 11), so Windows Explorer, unzip and 7-Zip show Persian names correctly. When reading, a name is taken as it is (UTF-8) unless the Info-ZIP "Unicode path" field is present, which then wins. Names from other code pages are not converted. Dates are DOS dates: two second steps, between 1980 and 2107, with no time zone, read here as UTC. Set ZipFileInput.mtime (seconds since 1970) to date an entry; 0, or any time before 1980, writes 1 January 1980. The extra timestamp field is not written. ZipExtractAll sets the modification time of the files it writes from that date, except on Windows and 32 bit systems, and does not touch folders.
  • Tar: names of any length round-trip: a long name is stored in the ustar prefix field when it splits at a slash, otherwise in a PAX path record, and reading understands ustar prefixes, PAX (x and g) and GNU long names and links. Symbolic and hard links are real entries (Entry.kind and Entry.link); devices, pipes and other special entries are listed with kind 4 and skipped by TarExtractAll. Times and modes you set are written (a time past the ustar range goes into a PAX record), and extraction applies the mode and the modification time of files and folders, but not their owner. On Windows symbolic links are not created (the call returns false), hard links become copies and times are not set; times are not set on 32 bit systems either. Entries that are not given a time get 0, and the mode you leave at 0 becomes 644 for files, 755 for folders and 777 for symbolic links.
  • Tar extraction: TarExtractAll skips, and returns false for, a name that is absolute or climbs out with .., a name that passes through a symbolic link it created, a symbolic link whose target is absolute or leaves the target folder (a .. after a name is refused too), and a hard link to a name outside the folder. Set-user-id and similar mode bits are never applied.
  • RAR: RAR 5 archives are read completely: every compression level, solid archives and the built-in filters, with each entry's CRC-32 checked. Older archives (RAR 1.5 to 4.x) are read the same way, including PPMd text compression and the standard filters. Password-protected archives open with RarOpen and a password, including ones whose file names are encrypted; without it they report RAR_ENCRYPTED, and a wrong password reports RAR_BAD_PASSWORD. Multi-volume archives open from the list of volumes (RarOpenVolumes, or RarReadVolumes to load a set from disk); a set with a missing volume reports RAR_MULTIVOLUME for the files that cross it. A file that is both encrypted and split across volumes is read too (checked against the reference unrar on RAR 1.5, 2.0, 3 and 5 sets). The old RAR 1.5 and 2.x passwords work as well, tested with a real WinRAR 2.02 file. The RAR 7 format version 1 (dictionaries over 4 GB, fractional sizes) is read; only a match distance beyond 4 GB has never been run. The in-memory functions need the archive and each entry under 2 GB (a bigger entry reports RAR_TOO_BIG); for bigger RAR 5 files use RarFileOpen, which reads from disk and unpacks in pieces. Extraction restores the Unix permissions and the modification time (on 64-bit systems other than Windows), recreates symbolic links whose target stays inside the destination, and writes hard links and file copies as plain copies; a link that points outside is skipped and reported as RAR_UNSAFE_PATH. New archives are RAR 5 with the files stored, because only WinRAR itself can compress to RAR; any RAR tool opens them.
  • 7z: read, and written with stored data only. LZMA, LZMA2, PPMd, BZip2, Deflate, Deflate64, copy, BCJ2, the branch filters (x86, ARM, ARM64, RISC-V and others), byte swap and delta are supported, with AES-256 passwords (headers too); Multi-volume sets (.7z.001) and self-extracting archives (an executable stub before the archive) are read. Unix modes, times and symbolic links are restored on extraction, and a link that would point outside the target folder is refused. The calls that take a pointer and a length hold everything unpacked in memory, so a solid block is capped at about 1 GiB and the dictionary of an LZMA stream may not pass 1 GiB; SevenZipOpenFile has no such limit (see below). Names are UTF-8; the time is the last change.

The guide below shows the usual jobs: zipping a set of files, making and reading a .tar.gz, telling formats apart by their first bytes, and extracting without letting an archive write outside the target folder.

Zip a set of files

Each file you put into a zip is a ZipFileInput: its path inside the archive, the address and length of its bytes, and the method: 8 for DEFLATE, 0 to store it as it is, or 12, 14 and 93 for bzip2, LZMA and zstd (the ZipMethod... constants). MakeZipFileInputLevel also sets a level for those compressors. Every unzip reads bzip2 entries; LZMA and zstd entries are read by 7-Zip and by Python's zipfile (zstd from Python 3.14), but not by older tools such as Info-ZIP unzip, so use them only when you know the reader. A name that ends with / is a folder. ZipCreateFile writes the archive to disk and returns false when it cannot; bzip2, LZMA and zstd entries are streamed through the encoders in std/compress, so an entry of any size needs only the encoder window in memory (about 1 MiB for zstd at the default level, a few MiB for LZMA, one block for bzip2); ZipCreate keeps it in memory, for example to send it as an HTTP response.

archive-guide-bundle.salam
import archive
import compress

func main:
    html := compress.BufFromStr("<html><body><h1>Hello</h1><p>Hello again, hello once more.</p></body></html>\n")
    css := compress.BufFromStr("body { margin: 0; }\nh1 { margin: 0; }\np { margin: 0; }\n")
    logo := compress.GzipCompressStr("pretend this is an image that is already compressed")
    mut files := Vector {} as Vector<archive.ZipFileInput>
    files.Push(archive.MakeZipFileInput("site/", null, 0, 0))
    files.Push(archive.MakeZipFileInput("site/index.html", html.data, html.len, 8))
    files.Push(archive.MakeZipFileInput("site/style.css", css.data, css.len, 8))
    files.Push(archive.MakeZipFileInput("site/logo.bin", logo.data, logo.len, 0))
    if not archive.ZipCreateFile(files, "site.zip"):
        println "could not write site.zip"
        ret 1
    end
    mut ok := false
    z := archive.ReadBinaryFile("site.zip", ok)
    mut entries := archive.ZipList(z.data, z.len)
    each e in entries:
        if e.is_dir:
            println e.name, "(folder)"
        else:
            println e.name, e.size, "->", e.compressed_size, "method", e.method
        end
    end
    archive.FreeEntries(entries)
    ret 0
end
Outputsite/ (folder) site/index.html 77 -> 63 method 8 site/style.css 55 -> 29 method 8 site/logo.bin 64 -> 64 method 0

Text shrinks well. The logo is already compressed, so it uses method 0: running DEFLATE on it again would only cost time and could even make it bigger. The same rule holds for JPEG, PNG, MP4 and other zips.

Make and read a .tar.gz

Tar does not compress. It puts each file after a 512 byte header and pads its contents to a multiple of 512 bytes, so three small files already take 3.5 KB. The usual answer is to gzip the whole tar, and all that padding then nearly disappears. In memory that is TarCreate followed by compress.GzipCompressBuf; for a tar that is already on disk, GzipCompressFile and GzipDecompressFile do it file to file. TarGzCreate and TarGzCreateFile do both steps at once.

archive-guide-targz.salam
import archive
import compress

func main:
    readme := compress.BufFromStr("Backup of the config folder.\n")
    conf := compress.BufFromStr("port = 8080\nworkers = 4\nport_admin = 8081\n")
    mut files := Vector {} as Vector<archive.TarFileInput>
    files.Push(archive.MakeTarFileInput("config", null, 0, true))
    files.Push(archive.MakeTarFileInput("config/README", readme.data, readme.len, false))
    files.Push(archive.MakeTarFileInput("config/app.conf", conf.data, conf.len, false))
    tar := archive.TarCreate(files)
    tgz := compress.GzipCompressBuf(tar)
    println "tar:", tar.len, "bytes, tar.gz:", tgz.len, "bytes"
    archive.WriteBinaryFileBuf("config.tar.gz", tgz)

    mut ok := false
    packed := archive.ReadBinaryFile("config.tar.gz", ok)
    plain := compress.GzipDecompressBuf(packed, ok)
    if not ok:
        println "config.tar.gz is not valid gzip"
        ret 1
    end
    mut entries := archive.TarList(plain.data, plain.len)
    each e in entries:
        println e.name, e.size, e.is_dir
    end
    archive.FreeEntries(entries)
    app := archive.TarExtractByName(plain.data, plain.len, "config/app.conf", ok)
    print compress.BufToStrUnsafe(app)
    ret 0
end
Outputtar: 3584 bytes, tar.gz: 208 bytes config 0 true config/README 29 false config/app.conf 42 false port = 8080 workers = 4 port_admin = 8081

Reading goes the other way: TarGzList, TarGzExtractByName and TarGzExtractAll gunzip and read in one call, and set ok to false when the data is not a valid gzip. They refuse to inflate past 1 GiB; give the Max forms a smaller limit for input you do not trust. Directory entries in a tar have size 0 and is_dir set.

Zstandard works the same way: TarZstdCreate builds the tar and compresses it, and TarZstdList, TarZstdExtractByName and TarZstdExtractAll decompress and read in one call, with Max forms to cap the unpacked size. A .tar.zst made with tar --zstd reads the same way. For a single file there is ZstdCompressFile and ZstdDecompressFile.

Read a 7z archive

7z archives are read, and can be made with stored data (no compression). SevenZipList and SevenZipListStatus list the entries, SevenZipExtractByName unpacks one, and SevenZipExtractAll writes everything under a folder. The LZMA, LZMA2, PPMd, BZip2, Deflate and Deflate64 methods are understood, with BCJ2, the branch filters (x86, ARM, ARM64, RISC-V, PowerPC, SPARC, IA-64), byte swap and delta in front of them, solid blocks, empty files and folders, encrypted data and encrypted headers (AES-256). The signature header, the header, every solid block and every file are checked against their CRC-32. Anti items, which mean "delete this name" in an update archive, are left out.

func nib(c: int): int:
    if c >= 48 and c <= 57:
        ret c - 48
    end
    if c >= 97 and c <= 102:
        ret c - 87
    end
    ret -1
end

func unhex(s: str): compress.ByteBuf:
    mut b := compress.NewByteBuf()
    bp := s as u8*
    mut hi := -1
    repeat s.Len() in i:
        v := nib(bp[i] as int)
        if v < 0:
            continue
        end
        if hi < 0:
            hi = v
        else:
            compress.BufPush(b, hi * 16 + v)
            hi = -1
        end
    end
    ret b
end

A solid block is one compressed stream holding several files, so reading one file out of it unpacks the whole block; to get many files out of one archive use SevenZipExtractAll, which unpacks each block once. Every call returns a SEVENZIP_... status instead of guessing: a wrong password is SEVENZIP_BAD_PASSWORD, a missing password SEVENZIP_ENCRYPTED, a damaged file SEVENZIP_BAD_CRC or SEVENZIP_CORRUPT. Tell the format from the first bytes

A file name can lie, the bytes cannot. Every format starts with a fixed signature, so a program that accepts uploads should look at the bytes before it picks a reader:

FormatSignatureCheck
zip50 4b 03 04 (PK) at the startcompare the first four bytes
gzip1f 8b at the startcompare the first two bytes
xzfd 37 7a 58 5a 00 at the startcompare the first six bytes
RARRar! at the startIsRar
7z37 7a bc af 27 1c at the start (a self-extracting archive has it later)IsSevenZip
tarustar at byte 257compare five bytes from offset 257
archive-guide-detect.salam
import archive
import compress

func kind(b: compress.ByteBuf): str:
    if b.len >= 4 and compress.BufGet(b, 0) == 80 and compress.BufGet(b, 1) == 75 and compress.BufGet(b, 2) == 3 and compress.BufGet(b, 3) == 4:
        ret "zip"
    end
    if b.len >= 2 and compress.BufGet(b, 0) == 31 and compress.BufGet(b, 1) == 139:
        ret "gzip"
    end
    if archive.IsRar(b.data, b.len):
        ret "rar"
    end
    if b.len >= 262 and compress.BufGet(b, 257) == 117 and compress.BufGet(b, 258) == 115 and compress.BufGet(b, 259) == 116 and compress.BufGet(b, 260) == 97 and compress.BufGet(b, 261) == 114:
        ret "tar"
    end
    ret "unknown"
end

func count(b: compress.ByteBuf): int:
    k := kind(b)
    if k == "zip": ret archive.ZipList(b.data, b.len).Len() end
    if k == "tar": ret archive.TarList(b.data, b.len).Len() end
    if k == "rar": ret archive.RarList(b.data, b.len).Len() end
    if k == "gzip":
        mut ok := false
        inner := compress.GzipDecompressBuf(b, ok)
        if ok: ret count(inner) end
    end
    ret 0
end

func main:
    note := compress.BufFromStr("a short note\n")
    mut zf := Vector {} as Vector<archive.ZipFileInput>
    zf.Push(archive.MakeZipFileInput("note.txt", note.data, note.len, 8))
    mut tf := Vector {} as Vector<archive.TarFileInput>
    tf.Push(archive.MakeTarFileInput("note.txt", note.data, note.len, false))
    tar := archive.TarCreate(tf)
    samples := [archive.ZipCreate(zf), tar, compress.GzipCompressBuf(tar), note]
    each s in samples:
        println kind(s), s.len, "bytes,", count(s), "entries"
    end

Extract safely

ZipExtractAll and TarExtractAll create the folders they need under the target directory. An archive from someone else can hold names like ../escape.txt or /etc/passwd that would land outside it; both functions skip such entries, write the rest, and return false so you know something was left out. ZipExtractByName and TarExtractByName set ok to false when the name is not in the archive.

Gzip a single file (.gz)

A .gz holds one file, not a folder. GzipCompressFile and GzipDecompressFile go from a path to a path and return false when they cannot read, write or decode; in memory, compress.GzipCompressBuf and compress.GzipDecompressBuf do the same on a buffer. Decompressing checks the trailer, so a damaged or cut file is refused instead of giving back wrong bytes. For data from someone else use compress.GzipDecompressMax, which stops at a size you choose, so a tiny file cannot expand into gigabytes.

archive-guide-gzip.salam
import archive
import compress

func main:
    note := compress.BufFromStr("a log line that repeats, a log line that repeats, a log line that repeats\n")
    archive.WriteBinaryFileBuf("note.txt", note)

    println "gzip a file:", archive.GzipCompressFile("note.txt", "note.txt.gz")
    println "gunzip it:", archive.GzipDecompressFile("note.txt.gz", "note-copy.txt")
    mut ok := false
    copy := archive.ReadBinaryFile("note-copy.txt", ok)
    println "same bytes:", compress.BufEquals(copy, note)

    packed := compress.GzipCompressBuf(note)
    println "in memory:", note.len, "bytes become", packed.len
    back := compress.GzipDecompressBuf(packed, ok)
    println "round trip:", ok, compress.BufEquals(back, note)

    p := packed.data as u8*
    p[packed.len / 2] = ((p[packed.len / 2] as int) ^ 1) as u8
    _ := compress.GzipDecompressBuf(packed, ok)
    println "damaged copy accepted:", ok

    capped := compress.GzipCompressBuf(note)
    _ := compress.GzipDecompressMax(capped.data, capped.len, 10, ok)
    println "over a 10 byte limit accepted:", ok
end

Check an archive

"Check" means two different things. To see what is inside without unpacking, list it: ZipList, TarList and RarList (or RarEntries) give every name, size, folder flag and, for zip and RAR, the stored CRC-32; free the list with FreeEntries. To know the data is intact, you need a checksum, and formats differ:

  • gzip and RAR verify themselves. A gzip call returns ok = false; a RAR call sets the status to RAR_BAD_CRC, or RAR_BAD_PASSWORD when a password was wrong.
  • zip stores a CRC-32 for each entry. ZipExtractVerified compares it with the data and sets status to ZIP_OK, ZIP_BAD_CRC and so on; ZipVerify checks every entry and returns how many failed; ZipBadEntries lists them. ZipExtractByName stays unchecked, for speed and for old code: compare compress.CRC32Buf(data) with Entry.crc32 yourself, as the example below does.
  • tar has no checksum for the contents. All you can check is that the listing is sane (names, sizes); for integrity gzip the tar and rely on the gzip trailer, or keep a hash next to the file.
archive-guide-check.salam
import archive
import compress

func main:
    a := compress.BufFromStr("first file, stored as it is\n")
    b := compress.BufFromStr("second file, a little longer than the first one\n")

    files.Push(archive.MakeZipFileInput("a.txt", a.data, a.len, 0))
    files.Push(archive.MakeZipFileInput("b.txt", b.data, b.len, 0))

    p[40] = ((p[40] as int) ^ 1) as u8

    mut ok := false
    each e in entries:

        good := compress.CRC32Buf(data) == e.crc32

    mut out := compress.NewByteBuf()
    bytes := text as u8*
    mut high := -1
    repeat text.Len() in i:
        v := digit(bytes[i] as int)
        if v < 0:
            continue
        end
        if high < 0:
            high = v
        else:
            compress.BufPush(out, high * 16 + v)

One door for every format

Open reads the first bytes, finds the format and returns an Archive; List, Read, Extract and ExtractAll then work the same for every format and report one set of ARCHIVE_ codes. OpenFile, ListFile and ExtractFile do the same from a path. Gzip, bzip2 and xz files are unpacked on opening, and a tar inside is recognized, so a .tar.gz, .tar.bz2 and .tar.xz open like any other archive. The per-format functions below keep working unchanged.

ExtractAll is the safe way to unpack data you do not trust. Before it writes anything it checks every entry against Limits (entry count, size of one entry, size of all, and the ratio of unpacked size to archive size, which catches compression bombs) and refuses names that are absolute or climb out with .., links that leave the folder, files written through a link, and device entries. If a check fails nothing is written and status says why. The limits use the sizes the archive declares; each format still verifies the real sizes while unpacking. Multi-volume RAR and 7z sets, and large-file streaming, stay with the per-format functions.

The same calls work from a path. ListFile and ExtractFile open the file, do the job and close it; OpenFile gives you an Archive to reuse, and SetLimits tightens the Limits of one archive. Every call reports a status code, and ArchiveStatusText turns it into words. Big zip files on disk

The functions that take a pointer and a length hold the whole archive in memory, which stops at 2 GiB. For a zip of any size use ZipOpenFile: it reads only the end of the file and the list of entries, and ZipFileExtractTo and ZipFileExtractAll unpack straight to disk in 64 KiB pieces, checking the CRC-32 and the size as they go. Sizes and offsets are 64 bit, zip64 included, so an entry of several gigabytes works and memory use stays small. The only limit is the one you pass: cap is a number of bytes (0 for none), and an entry over it returns ZIP_TOO_BIG before anything is written.

import archive
import compress
import os

    body := "a large file would be unpacked straight to disk\n"

    compress.BufFree(made)

    mut entries := archive.ZipFileEntries(zf)
    each e in entries:
        println e.name, e.size
    end
    archive.FreeEntries(entries)

    println archive.ZipFileExtractTo(zf, "data/log.txt", "log.out", 10 as i64) == archive.ZIP_TOO_BIG

Big 7z files on disk

SevenZipOpenFile opens a 7z on disk and keeps only its header in memory. SevenZipFileExtractTo and SevenZipFileExtractAll unpack straight to disk: LZMA and LZMA2 data goes through a window as big as the dictionary and out in 64 KiB pieces, so an entry of several gigabytes needs only a few megabytes of memory. Every method streams the same way: PPMd needs only the model memory its properties ask for, bzip2 holds one block, the branch filters (BCJ, ARM, ARM64, RISC-V and the rest), delta, byte swap and BCJ2 are stages that pass each piece on, and AES-256 decrypts in pieces in front of the next coder, so AES then LZMA2 then BCJ reads straight from the file with no temporary file. Encrypted headers go through the same path. BCJ2 reads its range coder stream from the file; its call and jump streams are read from the file when stored and decoded into small buffers (at most memcap) when compressed. A solid block is read once for all of its files. cap limits the bytes of one entry and memcap the memory the decoder may use; both take 0 for no limit.

Big tar files on disk

TarFileOpen reads a tar from disk one entry at a time: TarFileNext fills an Entry (sizes and offsets are 64 bit, so a 5 GB entry is just an entry), TarFileExtractTo copies its data to a file in 64 KiB pieces, and TarFileExtractAll unpacks the whole archive with the same safety rules as TarExtractAll. Nothing but one entry's header is ever in memory. cap is the only size limit and it is yours (0 for none): TAR_TOO_BIG means an entry is over it. TarGzFileExtractAll and GzipDecompressFileCap do the same for gzip, which is read as a stream. A compressed tar needs no temporary file: TarGzFileExtractAll, TarBz2FileExtractAll, TarXzFileExtractAll and TarZstdFileExtractAll (or TarCompressedFileExtractAll) feed the decoder's output into the tar reader piece by piece, and TarCompressedFileEntries lists one the same way.

import compress
import os

Big RAR files on disk

RarFileOpen reads a RAR 5 file's headers only (offsets and sizes are 64 bit); RarFileExtractTo and RarFileExtractAll then unpack to disk, writing the result in pieces and checking the CRC-32 as they go. Compressed entries, solid archives and the built-in filters work. What is held in memory is the packed data of one entry and the decoder window, so the unpacked size can be anything: an entry of several gigabytes is unpacked from a file of a few megabytes in constant memory. The size limits are yours: cap for the unpacked bytes and memcap for that memory, and RAR_TOO_BIG means one of them was passed, and RAR_WINDOW_TOO_BIG that the data needs a window bigger than memcap or 1 GiB. Passwords and volumes work from disk too: RarFileOpenWith opens archives with encrypted files or file names, and RarFileOpenVolumes a set of volumes, decrypting and joining pieces as it unpacks. RarFileExtractAll restores permissions and times and creates safe symbolic links. Older RAR formats (1.5 to 4.x) work the same way, passwords, encrypted file names and volumes included: the packed data is read from the file in pieces and the unpacked data goes to disk in pieces (the VM filters are applied on the way), so an entry or a volume over 4 GiB works with a few megabytes of memory (sizes and offsets are 64 bit, including the high size fields of the headers). Only entries encrypted with the very old RAR 1.5 or 2.0 ciphers still need their packed data in memory, up to 256 MiB.

func unhex(s: str): compress.ByteBuf:
    mut b := compress.NewByteBuf()
    bp := s as u8*
    mut hi := -1
    repeat s.Len() in i:
        c := bp[i] as int
        mut v := -1
        if c >= 48 and c <= 57:
            v = c - 48
        else c >= 97 and c <= 102:
            v = c - 87
        end
        if v < 0:
            continue
        end
        if hi < 0:
            hi = v
        else:

func nib(c: int): int:
    if c >= 48 and c <= 57:
        ret c - 48
    end
    if c >= 97 and c <= 102:
        ret c - 87
    end
    ret -1
end

func save(dir: str, name: str, hex: str): str:
    mut b := compress.NewByteBuf()
    bp := hex as u8*
    mut hi := -1
    repeat hex.Len() in i:
        v := nib(bp[i] as int)
        if v < 0:
            continue
        end
        if hi < 0:
            hi = v
        else:
            compress.BufPush(b, hi * 16 + v)
            hi = -1
        end
    end
    path := filepath.Join(dir, name)
    _ := archive.WriteBinaryFileBuf(path, b)
    compress.BufFree(b)
    ret path
end

func nib(c: int): int:
    if c >= 48 and c <= 57:
        ret c - 48
    end
    if c >= 97 and c <= 102:
        ret c - 87
    end
    ret -1
end

func unhex(s: str): compress.ByteBuf:
    mut b := compress.NewByteBuf()
    bp := s as u8*
    mut hi := -1
    repeat s.Len() in i:
        v := nib(bp[i] as int)
        if v < 0:
            continue
        end
        if hi < 0:
            hi = v
        else:
            compress.BufPush(b, hi * 16 + v)
            hi = -1
        end
    end
    ret b
end

    dir := filepath.Join(os.TempDir(), "salam_xz_example")
    os.RemoveAll(dir)
    os.MkdirAll(dir)
    xz_path := filepath.Join(dir, "notes.txt.xz")
    lzma_path := filepath.Join(dir, "notes.txt.lzma")
    out_path := filepath.Join(dir, "notes.txt")
    archive.WriteBinaryFileBuf(xz_path, unhex(XZ))
    archive.WriteBinaryFileBuf(lzma_path, unhex(LZMA))

    println "xz:", archive.XzDecompressFile(xz_path, out_path)
    mut ok := false
    text := archive.ReadBinaryFile(out_path, ok)
    println ok, text.len, "bytes"
    println "lzma:", archive.LzmaDecompressFile(lzma_path, out_path)

func nib(c: int): int:
    if c >= 48 and c <= 57:
        ret c - 48
    end
    if c >= 97 and c <= 102:
        ret c - 87
    end
    ret -1
end

func unhex(s: str): compress.ByteBuf:
    mut b := compress.NewByteBuf()
    bp := s as u8*
    mut hi := -1
    repeat s.Len() in i:
        v := nib(bp[i] as int)
        if v < 0:
            continue
        end
        if hi < 0:
            hi = v
        else:
            compress.BufPush(b, hi * 16 + v)
            hi = -1
        end
    end
    ret b
end

func digit(c: int): int:
    if c >= 48 and c <= 57:
        ret c - 48
    end
    if c >= 97 and c <= 102:
        ret c - 87
    end
    ret -1
end

func from_hex(text: str): compress.ByteBuf:
    mut out := compress.NewByteBuf()
    bytes := text as u8*
    mut high := -1
    repeat text.Len() in i:
        v := digit(bytes[i] as int)
        if v < 0:
            continue
        end
        if high < 0:
            high = v
        else:
            compress.BufPush(out, high * 16 + v)
            high = -1
        end
    end
    ret out
end
