collections

Data structures: vector and map, stack, queue, deque, set, linked list, priority queue and counter.

This package holds Salam's data structures. Vector and HashMap, which turn up in every program, are defined here but built in: you can use them without an import. The rest (Stack, Queue, Deque, Set, Counter, PriorityQueue, OrderedMap, LinkedList, CircularList, Pair) and the vector helpers such as clone and index_of need import collections. To sort or search a vector use sort; to share a structure between threads, guard it with sync, because none of these types locks.

All of them are generic: you set the element type with <...>, as in collections.Stack<str>, and build an empty one with collections.Stack {} as collections.Stack<str>. All of them allocate, so write defer x.free() right after creating one. free releases the structure itself, not heap strings or other objects stored in it.

Which should you pick? For an ordinary list, Vector; for "last in, first out", Stack; for "first in, first out", Queue; for adding and removing at both ends, Deque; for fast lookup by a key, HashMap; for removing duplicates, Set; for "always give me the smallest", PriorityQueue; and for string settings that must keep their order, OrderedMap. Most of them are thin layers over Vector: a stack is one vector, a queue and a deque are two.

What people get wrong:

  • Copying with =. b := a copies only the vector's header, so both names see the same elements: b.set(0, x) changes a too, and a push on one can move the memory under the other. Take a real copy with the built-in v.copy() or with collections.clone(v). The same goes for a HashMap (m.copy()) and for any struct holding one.
  • Changing a struct you got from a map. m.get(k) returns a copy; change it and put it back.
  • Reading from an empty structure. pop, peek, dequeue, first, last and an index past the end stop the program with a message such as Vector.pop: empty. Check is_empty() first. A --release build leaves the check out, and the same mistake then reads garbage.
  • Printing a map in its own order. each key, value in m visits the slots in hash order, which changes as the map grows. Collect and sort the keys when the order shows.

Vector: insert, remove, copy

push and pop work at the end in constant time. insert and remove_at shift every later element, so they are fine for short lists and slow inside a loop over a long one. index_of and contains scan from the front. The example also shows the copy trap from the list above: alias writes straight into line, while the clone keeps its own elements.

collections-guide-vector.salam
import collections

func main:
    mut line := Vector {} as Vector<str>
    defer line.free()
    each name in ["Ali", "Sara", "Reza"]:
        line.push(name)
    end
    line.insert(1, "Mina")
    println "after insert:", line
    served := line.remove_at(0)
    println "served", served, "->", line
    println "Reza is at", collections.index_of(line, "Reza"), "and Omid at", collections.index_of(line, "Omid")

    backup := collections.clone(line)
    defer backup.free()
    alias := line
    alias.set(0, "Neda")
    println "alias wrote into line:", line.get(0)
    println "the clone kept:       ", backup.get(0)

    front := collections.slice(line, 0, 2)
    defer front.free()
    println "first two:", front, "last:", line.last()
end
Outputafter insert: ["Ali", "Mina", "Sara", "Reza"] served Ali -> ["Mina", "Sara", "Reza"] Reza is at 2 and Omid at -1 alias wrote into line: Neda the clone kept: Mina first two: ["Neda", "Sara"] last: Reza

slice returns a new vector and clamps a range that runs past the end, so it never fails. Printing a vector with println shows its elements, which is handy while debugging.

HashMap: stock by product code

A HashMap finds a value by its key in constant time. get on a missing key returns the zero value of the type (0, empty text, a struct of zeros) and never fails, so ask has first when a missing key is an error, or use get_or when a default is right. Struct values come back as copies: change the copy and put it again.

collections-guide-inventory.salam
import sort

struct Stock:
    pub name: str = ""
    pub qty: int = 0
end

func main:
    mut stock := HashMap {} as HashMap<str, Stock>
    defer stock.free()
    stock.put("TEA-01", Stock { name = "Green tea", qty = 40 })
    stock.put("COF-02", Stock { name = "Coffee beans", qty = 12 })
    stock.put("MUG-07", Stock { name = "Mug", qty = 2 })

    each sku in ["COF-02", "MUG-07", "TEA-01", "MUG-07", "BAG-99"]:
        if not stock.has(sku):
            println "unknown product", sku
            continue
        end
        mut item := stock.get(sku)
        item.qty -= 1
        stock.put(sku, item)
    end
    println "a missing key gives a zero value:", stock.get("BAG-99").qty

    mut reorder_at := HashMap {} as HashMap<str, int>
    defer reorder_at.free()
    reorder_at.put("TEA-01", 10)

    mut skus := Vector {} as Vector<str>
    defer skus.free()
    each sku, item in stock:
        if item.qty > 0:
            skus.push(sku)
        else:
            println item.name, "is sold out"
        end
    end
    sort.Sort(skus)
    each sku in skus:
        item := stock.get(sku)
        low := item.qty <= reorder_at.get_or(sku, 5)
        println sku, item.name, item.qty, "reorder:", low
    end
end
Outputunknown product BAG-99 a missing key gives a zero value: 0 Mug is sold out COF-02 Coffee beans 11 reorder: false TEA-01 Green tea 39 reorder: false

Do not put or remove while an each loop walks the same map: a put can grow the table and move every entry. Collect the keys first, as the example does, then change the map.

Stack: matching brackets

A stack is the tool when the most recent thing must be dealt with first. Checking brackets is the classic case: push every opening bracket, and on a closing bracket the top of the stack must be its partner. peek looks at the top without removing it, and whatever is left at the end was never closed.

collections-guide-brackets.salam
import collections
import str

func opener(c: char): char:
    if c == ')': ret '(' end
    if c == ']': ret '[' end
    ret '{'
end

func check(s: str): str:
    mut open := collections.Stack {} as collections.Stack<char>
    defer open.free()
    repeat str.Len(s) in i:
        c := s[i]
        if c == '(' or c == '[' or c == '{':
            open.push(c)
        else c == ')' or c == ']' or c == '}':
            if open.is_empty() or open.peek() != opener(c):
                ret "mismatch at " + str.FromInt(i)
            end
            open.pop()
        end
    end
    if not open.is_empty():
        ret str.FromInt(open.size()) + " left open"
    end
    ret "balanced"
end

func main:
    each s in ["f(a[1], {b: 2})", "(1 + 2]", "{[()]}", "((x)", "x)"]:
        println s, "->", check(s)
    end
end
Outputf(a[1], {b: 2}) -> balanced (1 + 2] -> mismatch at 6 {[()]} -> balanced ((x) -> 1 left open x) -> mismatch at 1

Queue: shortest path in a grid

A queue hands items out in the order they arrived, which is exactly what a breadth first search needs: every cell at distance 1 is handled before any cell at distance 2, so the first time the search reaches the exit, it has found a shortest path. enqueue adds at the back and dequeue takes from the front.

collections-guide-maze.salam
import collections

func main:
    maze := ["S.#.....", ".##.###.", "....#...", ".##...#E"]
    rows := maze.len()
    cols := 8
    dr := [-1, 1, 0, 0]
    dc := [0, 0, -1, 1]
    mut dist := Vector {} as Vector<int>
    defer dist.free()
    repeat rows * cols:
        dist.push(-1)
    end

    mut todo := collections.Queue {} as collections.Queue<int>
    defer todo.free()
    todo.enqueue(0)
    dist.set(0, 0)
    mut goal := -1
    until not todo.is_empty():
        cell := todo.dequeue()
        r := cell / cols
        c := cell % cols
        if maze[r][c] == 'E':
            goal = cell
            break
        end
        repeat 4 in k:
            nr := r + dr[k]
            nc := c + dc[k]
            if nr >= 0 and nr < rows and nc >= 0 and nc < cols:
                next := nr * cols + nc
                if maze[nr][nc] != '#' and dist.get(next) == -1:
                    dist.set(next, dist.get(cell) + 1)
                    todo.enqueue(next)
                end
            end
        end
    end
    println "shortest path to E:", dist.get(goal), "steps"
    mut seen := 0
    each d in dist:
        if d >= 0: seen += 1 end
    end
    println "cells reached:", seen, "of", rows * cols
end
Outputshortest path to E: 12 steps cells reached: 22 of 32

Deque and Stack together: undo with a limit

An undo history adds at one end and, once it is full, drops the oldest step at the other end, so it needs a Deque. Undone steps go onto a Stack for redo, and any new edit clears that stack, as editors do.

collections-guide-history.salam
import collections

func main:
    limit := 3
    mut undo := collections.Deque {} as collections.Deque<str>
    defer undo.free()
    mut redo := collections.Stack {} as collections.Stack<str>
    defer redo.free()

    mut doc := ""
    each word in ["Salam", " is", " a", " small", " language"]:
        undo.push_back(doc)
        if undo.size() > limit:
            undo.pop_front()
        end
        redo.clear()
        doc = doc + word
        println "typed: [" + doc + "]"
    end

    until not undo.is_empty():
        redo.push(doc)
        doc = undo.pop_back()
        println "undo:  [" + doc + "]"
    end
    println "the history keeps only", limit, "steps, so the rest are gone"

    doc = redo.pop()
    println "redo:  [" + doc + "]", redo.size(), "more redo steps"
end
Outputtyped: [Salam] typed: [Salam is] typed: [Salam is a] typed: [Salam is a small] typed: [Salam is a small language] undo: [Salam is a small] undo: [Salam is a] undo: [Salam is] the history keeps only 3 steps, so the rest are gone redo: [Salam is a] 2 more redo steps

Counter and Set: counting words

Counter keeps a count for each value it has seen; count answers 0 for a value it never saw, so no check is needed first. A Set answers "have I seen this?" quickly and here keeps the words in order of first use. A stable sort by count then keeps that order among words with the same count.

collections-guide-wordcount.salam
import collections
import sort
import str

func main:
    text := "to be or not to be that is the question to ask"
    mut counts := collections.Counter {} as collections.Counter<str>
    defer counts.free()
    mut seen := collections.Set {} as collections.Set<str>
    defer seen.free()
    mut order := Vector {} as Vector<str>
    defer order.free()

    each w in str.Fields(text):
        counts.add(w)
        if not seen.has(w):
            seen.add(w)
            order.push(w)
        end
    end
    println counts.distinct(), "different words, in order of first use:"
    println order

    sort.StableSortBy(order, (a: str, b: str): ret counts.count(a) > counts.count(b) end)
    println "most frequent:"
    repeat 3 in i:
        w := order.get(i)
        println "  " + w, counts.count(w)
    end
end
Output9 different words, in order of first use: ["to", "be", "or", "not", "that", "is", "the", "question", "ask"] most frequent: to 3 be 2 or 1

PriorityQueue: the most urgent job first

PriorityQueue is a binary min-heap: push and pop take log n steps, and pop always returns the smallest element. It compares elements with <, so it holds numbers or strings, not structs. To queue records, pack the priority and a position into one number, here urgency * 1000 + index, and keep the records in a vector. The position also breaks ties in arrival order, which a heap would not do by itself. For the largest first, push negative numbers.

collections-guide-scheduler.salam
import collections

func main:
    jobs := ["nightly backup", "send invoices", "resize images", "page the on-call", "rebuild index"]
    urgency := [3, 2, 3, 1, 2]
    mut queue := collections.PriorityQueue {} as collections.PriorityQueue<i64>
    defer queue.free()
    repeat jobs.len() in i:
        queue.push((urgency[i] as i64) * 1000 + (i as i64))
    end
    until not queue.is_empty():
        key := queue.pop()
        println "urgency", key / 1000, jobs[(key % 1000) as int]
    end

    mut largest := collections.PriorityQueue {} as collections.PriorityQueue<int>
    defer largest.free()
    each kb in [120, 4800, 35, 990]:
        largest.push(0 - kb)
    end
    println "largest upload first:", 0 - largest.pop(), "KB, then", 0 - largest.peek(), "KB"
end
Outputurgency 1 page the on-call urgency 2 send invoices urgency 2 rebuild index urgency 3 nightly backup urgency 3 resize images largest upload first: 4800 KB, then 990 KB

OrderedMap: settings that keep their order

A HashMap gives its keys back in no particular order, which is a nuisance when you write a configuration file back to disk. OrderedMap keeps keys in the order they were first set; changing a value keeps its position, and set returns that position. get_or supplies a default for a missing key.

collections-guide-config.salam
import collections
import str

func main:
    mut conf := collections.OrderedMap {}
    defer conf.free()
    conf.set("host", "127.0.0.1")
    conf.set("port", "8080")
    conf.set("workers", "4")
    conf.set("log", "info")

    overrides := ["port=9000", "log=debug", "tls=on", "broken"]
    each line in overrides:
        cut := str.IndexOf(line, "=")
        if cut < 0:
            println "skipping", line
            continue
        end
        key := line.substr(0, cut)
        value := line.substr(cut + 1, str.Len(line) - cut - 1)
        known := conf.has(key)
        pos := conf.set(key, value)
        if known:
            println "changed", key, "at position", pos
        else:
            println "added", key, "at position", pos
        end
    end

    conf.remove("workers")
    repeat conf.len() in i:
        println conf.key_at(i) + " = " + conf.val_at(i)
    end
    println "timeout:", conf.get_or("timeout", "30")
end
Outputchanged port at position 1 changed log at position 3 added tls at position 4 skipping broken host = 127.0.0.1 port = 9000 log = debug tls = on timeout: 30

Every one of these types allocates. Put defer x.free() on the line after you create it, as the examples do, and the memory is released when the function returns. Set and Counter have no way to list their contents; when you need that, walk their inner map with each value, _ in s.m, or keep a vector beside them as the word count example does.

A list whose size changes: the data structure you will use most. The elements sit next to each other in memory and access by index is immediate. You can also read and write elements with [i].

func main:
    mut v := Vector {} as Vector<int>
    defer v.free()
    v.reserve(8)
    println v.len(), v.cap() >= 8, v.is_empty()
    v.push(10)
    v.push(20)
    v.push(30)
    println v, v.first(), v.last(), v.get(1), v[2]
