core

The smallest package in Salam, for when the program must not carry on.

import core
On this page

  2. Marking code that should never run
  3. Panic or Result?
  4. What a panic does
  5. Types
  6. Functions

The core package has exactly one function, but an important one. Sometimes a program reaches a point where carrying on makes no sense: data is corrupt, or a condition that "can never happen" has happened. In that case it is better to stop right there with a clear message than to quietly hand back a wrong answer.

For ordinary errors, such as bad input from a user, declare the function throws and throw an Error instead, so that the caller decides what to do with try and catch. A panic is for when there is no correct way to continue, and catch does not stop it.

core also defines the built-in error types, Error and ErrorKind, which every program can use without an import. The error package explains how to throw, pass on and catch them.

Guarding an invariant

An invariant is something your own code promises is always true: a balance never drops below zero, a list stays sorted, an index stays in range. Checks for ordinary, expected failures return a value the caller can act on. A check for a broken invariant calls Panic, because if it fails the bug is in the program itself and any result computed after that point would be wrong.

core-guide-invariant.salam
import core

struct Account:
    pub owner: str = ""
    pub balance: int = 0
end

func withdraw(acc &: Account, amount: int): bool:
    if amount > acc.balance:
        ret false
    end
    acc.balance = acc.balance - amount
    if acc.balance < 0:
        core.Panic("balance went negative for " + acc.owner)
    end
    ret true
end

func main:
    mut acc := Account { owner = "Sara", balance = 100 }
    println withdraw(acc, 30), acc.balance
    println withdraw(acc, 500), acc.balance
    println withdraw(acc, 70), acc.balance
end
Outputtrue 70 false 70 true 0

Asking for more money than the account holds is an ordinary situation, so withdraw answers false. The Panic after the subtraction can only run if someone later changes the function and breaks it; it is there so that mistake shows up at once, with the owner's name in the message, instead of as a strange number weeks later.

Marking code that should never run

A function that must return a value for every input still needs something at the end, after all the known cases. When the remaining inputs are impossible by design, a Panic with the bad value in the message is the honest way to finish it. A made up return value, such as an empty string, would hide the bug and let it travel further.

core-guide-unreachable.salam
import core

func next_light(light: str): str:
    switch light:
        "red":
            ret "green"
        end
        "green":
            ret "yellow"
        end
        "yellow":
            ret "red"
        end
    end
    core.Panic("unknown light: " + light)
end

func main:
    mut light := "red"
    repeat 4:
        nxt := next_light(light)
        println light, "->", nxt
        light = nxt
    end
end
Outputred -> green green -> yellow yellow -> red red -> green

Because Panic never returns, the compiler accepts it as the last statement of a function with a result type. Put the unexpected value into the message: unknown light: blue tells you far more than unreachable.

When the cases are the members of an enum, prefer match: it must cover every member, so the compiler finds the missing case for you and no Panic is needed.

Panic or Result?

The two work together. Anything that comes from outside the program, such as user input, files, the network or another service, can be wrong in normal operation, so it goes through result and the caller decides what to do. Once the value has been checked, inner functions may treat a bad value as a programming error and panic.

core-guide-vs-result.salam
import core
import result

func parse_percent(text: str): result.Result<int, str>:
    n := text.to_int()
    if n < 0 or n > 100:
        ret result.Result.Err("a percentage must be between 0 and 100, got " + text)
    end
    ret result.Result.Ok(n)
end

func apply_discount(price: int, percent: int): int:
    if percent < 0 or percent > 100:
        core.Panic("apply_discount called with " + percent)
    end
    ret price - price * percent / 100
end

func main:
    each typed in ["20", "250"]:
        r := parse_percent(typed)
        match r:
            Ok(p): println "price after discount:", apply_discount(80, p) end
            Err(msg): println "rejected:", msg end
        end
    end
end
Outputprice after discount: 64 rejected: a percentage must be between 0 and 100, got 250
SituationUse
The user typed something invalidResult with an error message
A file or server is missingResult, or the Error out-parameter of that package
A value may be absentoption
Your own code broke a rule it promised to keepPanic
A case that cannot happen by designPanic, or match on an enum

What a panic does

  • It writes salam panic: and your message to standard error, then calls the C abort. The process ends with signal SIGABRT, which a shell reports as exit status 134, and the system may write a core dump.
  • defer statements do not run, so open files are not flushed and temporary files stay behind.
  • Text the program printed shortly before the panic can be lost when standard output is a pipe or a file, because println keeps it in a buffer that the panic does not write out. In a terminal every line appears. If the last lines matter, for example in a log a CI job reads, print them with printerrln, which is not buffered.
  • In a server, one bad request that panics takes down every other request too.

That is the main reason to keep Panic for real bugs only.

core-ErrorKind.salam
func retryable(e: Error): bool:
    ret e.is(ErrorKind.Io) or e.is(ErrorKind.Timeout) or e.is(ErrorKind.Unavailable)
end

func main:
    kinds := [ErrorKind.Io, ErrorKind.Timeout, ErrorKind.Unavailable, ErrorKind.NotFound, ErrorKind.PermissionDenied, ErrorKind.Internal]
    each kind in kinds:
        e := Error.New(kind, "failed")
        if retryable(e):
            println e.kind_name() + ": try again"
        else:
            println e.kind_name() + ": give up"
        end
    end
end
OutputI/O error: try again timed out: try again unavailable: try again not found: give up permission denied: give up internal error: give up

Error

struct Error
The error that throw sends and catch receives. It holds only text and numbers, so copying it is cheap and safe.
NameTypeDescription
kindErrorKindThe general category, one of ErrorKind.
codestr = ""A precise code chosen by the package that threw the error, such as json.trailing_data; empty when there is none.
messagestr = ""What went wrong, for a person to read.
contextstr = ""The explanations added by wrap, outermost first, joined with ": ".
pathstr = ""Where in the data the problem is, such as $.users[3].age, or a file path; empty when unknown.
offsetint = -1The byte offset of the problem in the input, or -1 when unknown.
lineint = 0The line of the problem, counting from 1, or 0 when unknown.
columnint = 0The column of the problem, counting from 1, or 0 when unknown.
core-Error.salam
func parse age(text: str): int throws:
    if text == "":
        throw Error.New(ErrorKind.MissingKey, "the age is missing")
    end
    n := text.to_int()
    if n < 0 or n > 150:
        throw Error.New(ErrorKind.OutOfRange, "the age " + n + " is out of range").with_code("age.range")
    end
    ret n
end

func main:
    each text in ["42", "", "200"]:
        try:
            println "age", parse age(text)
        catch e:
            println e.kind_name() + ":", e.message
            println "  code:", e.code, "| out of range:", e.is(ErrorKind.OutOfRange)
        end
    end
    e := Error.At(ErrorKind.Syntax, "expected a digit", 4).with_path("$.age")
    println e.to_str()
    placed := e.with_position(4, 2, 3).wrap("reading the form")
    println placed.to_str()
    println placed.offset, placed.line, placed.column, placed.context
end
Outputage 42 missing key: the age is missing code: | out of range: false out of range: the age 200 is out of range code: age.range | out of range: true expected a digit at $.age (offset 4) reading the form: expected a digit at $.age (line 2, column 3) 4 2 3 reading the form

is

core-Error.is.salam
func read note(name: str): str throws:
    if name == "":
        throw Error.New(ErrorKind.InvalidArgument, "the name is empty")
    end
    if name != "notes.txt":
        throw Error.New(ErrorKind.NotFound, name + " does not exist")
    end
    ret "contents of " + name
end

func main:
    each name in ["notes.txt", "todo.txt", ""]:
        try:
            println read note(name)
        catch e:
            if e.is(ErrorKind.NotFound):
                println "create it first:", e.message
            else:
                println "cannot go on:", e.message
            end
        end
    end
end
Outputcontents of notes.txt create it first: todo.txt does not exist cannot go on: the name is empty

wrap

func wrap(message: str): Error
A copy with an explanation added in front of the context. The kind, code and position stay.
core-Error.wrap.salam
func read port(text: str): int throws:
    n := text.to_int()
    if n < 1 or n > 65535:
        throw Error.New(ErrorKind.OutOfRange, "port " + n + " is not valid")
    end
    ret n
end

func load config(text: str): int throws:
    try:
        ret read port(text)
    catch e:
        throw e.wrap("reading the port")
    end
end

func main:
    try:
        println load config("80")
        println load config("70000")
    catch e:
        println e.to_str()
        println "context:", e.context
        println "kind:", e.kind_name()
    end
end
Output80 reading the port: port 70000 is not valid context: reading the port kind: out of range

At

static func At(kind: ErrorKind, message: str, offset: int): Error
Like New, and also records the byte offset in the input where the problem is.
core-Error.At.salam
func digit(text: str, at: int): int throws:
    c := text.substr(at, 1)
    if c < "0" or c > "9":
        throw Error.At(ErrorKind.Syntax, "a digit was expected", at)
    end
    ret c.to_int()
end

func main:
    text := "12x4"
    repeat text.len() in i:
        try:
            println "digit", digit(text, i)
        catch e:
            println e.to_str()
            println "offset", e.offset
        end
    end
end
Outputdigit 1 digit 2 a digit was expected (offset 2) offset 2 digit 4

Throws

type Throws = Variant<auto<T>, auto<T>>
What a throws function returns under the hood. You never write it: try and catch take it apart for you.

Functions

Panic

func Panic(msg: str)
Stops the program where it stands: writes salam panic: and the message to standard error and aborts the process (exit status 134). It never returns, defer statements do not run, and buffered standard output that was not yet written can be lost. The example below is not run here, because it deliberately kills the program; its output looks like salam panic: cannot divide by zero.
core-Panic.salam
import core

func divide(a: int, b: int): int:
    if b == 0:
        core.Panic("cannot divide by zero")
    end
    ret a / b
end

func main:
    println divide(10, 2)
    println divide(1, 0)
end
