db.clickhouse

A ClickHouse client over the HTTP interface: statements, typed rows, batch inserts and the shared db interface.

import db.clickhouse
On this page

  2. Connect and create a table
  3. Insert in batches
  4. Read the rows back
  5. Types
  6. Constants and variables
  7. Functions

ClickHouse is a column oriented database for analytics: it scans billions of rows fast, and takes inserts in large batches. This package talks to it over its HTTP interface (port 8123, or 8443 with TLS) with net.http, so there is no driver library to install and no native protocol to speak. Results arrive as JSONCompact, with 64 bit integers quoted so that none of them loses digits.

Open a connection with Open or OpenURL, send statements with Exec, read rows with Query, and load many rows at once with a batch. Values go into the SQL through the argument functions, such as StrArg and IntArg, which escape them, or through ClickHouse's own typed {name:Type} placeholders. AsDb adapts a connection to the shared db interface. A statement that fails behind a 200 status, because the server hit an exception while already streaming the reply, is caught too: it shows in Error and Code like any other failure.

The package does not speak the native TCP protocol or RowBinary, does not compress, and has no SQL dialect in db.sql yet. Each page section below is one part of the API, and each has a runnable example.

Put values into SQL safely

Never build SQL by joining strings. Make each value with an argument function, which quotes and escapes it, and let Bind put the values into the ? places in order. Bind does not run anything, so it is also a good way to see the final text. A ? inside quotes or a comment is not a place, and when the number of values differs from the number of places the result is empty.

db-clickhouse-guide-args.salam
import db.clickhouse

func main:
    mut args := Vector {} as Vector<str>
    args.push(clickhouse.StrArg("o'brien"))
    args.push(clickhouse.IntArg(42 as i64))
    println clickhouse.Bind("SELECT * FROM users WHERE name = ? AND age > ?", args)
    mut one := Vector {} as Vector<str>
    one.push(clickhouse.IntArg(7 as i64))
    println clickhouse.Bind("SELECT '?' AS mark, ? /* ? */", one)
    println clickhouse.QuoteIdent("my table")
    println clickhouse.Bind("SELECT ?", args).len()
end
OutputSELECT * FROM users WHERE name = 'o\'brien' AND age > 42 SELECT '?' AS mark, 7 /* ? */ `my table` 0

The quote in o'brien is escaped for you. Table and column names are not values, so they go through QuoteIdent. Exec and Query do the same binding when you give them the values.

Connect and create a table

Start from DefaultOptions (a server on this machine, user default) and change what differs. Open sends nothing yet, so call Ping to see whether the server answers. Exec runs a statement that returns no rows and gives true on success; on failure Error and Code say why.

db-clickhouse-guide-connect.salam
import db.clickhouse

func main:
    mut o := clickhouse.DefaultOptions()
    o.addr = "127.0.0.1:8123"
    o.database = "default"
    o.username = "default"
    mut c := clickhouse.Open(o)
    defer c.Close()
    if not c.Ping():
        println "no ClickHouse at", o.addr
        ret 1
    end
    println c.ServerVersion()

    none := Vector {} as Vector<str>
    ok := c.Exec("CREATE TABLE IF NOT EXISTS visits (day Date, page String, hits UInt32) ENGINE = MergeTree ORDER BY (day, page)", none)
    if not ok:
        println "create failed:", c.Code(), c.Error()
        ret 1
    end
    println "table ready"
end

The table uses the MergeTree engine, the usual one, and its ORDER BY is the sort key that makes queries on day and page fast. ClickHouse has no auto increment key and no transactions to wait for; a statement is done when Exec returns.

Insert in batches

ClickHouse likes a few large inserts, not many small ones. PrepareBatch takes the INSERT INTO table (columns) part, Append adds one row of ready SQL values, and SendBatch sends all the rows in one request. Append returns false if the row has a different number of values than there are columns.

db-clickhouse-guide-insert.salam
import db.clickhouse

func row(day: str, page: str, hits: i64): Vector<str>:
    mut r := Vector {} as Vector<str>
    r.push(clickhouse.StrArg(day))
    r.push(clickhouse.StrArg(page))
    r.push(clickhouse.IntArg(hits))
    ret r
end

func main:
    mut c := clickhouse.Open(clickhouse.DefaultOptions())
    defer c.Close()
    mut b := c.PrepareBatch("INSERT INTO visits (day, page, hits)")
    if b.Error().len() > 0:
        println b.Error()
        ret 1
    end
    b.Append(row("2026-11-01", "/", 120 as i64))
    b.Append(row("2026-11-01", "/docs", 45 as i64))
    b.Append(row("2026-11-02", "/", 98 as i64))
    println b.Len(), "rows queued"
    if not c.SendBatch(b):
        println "insert failed:", c.Error()
        ret 1
    end
    println "inserted"
end

Hundreds or thousands of rows per batch is a good size to start with. A batch with no rows, or one that already has an error, is not sent.

Read the rows back

Query returns a Rows. Check Ok, then call Next in a loop and read the current row by column number with Text, Int64 and the other readers; Close it when done. The loop is until rows.Next(): because until runs while its condition is true. For a value that comes from outside, the typed placeholders {name:Type} of QueryParams let the server check the type.

db-clickhouse-guide-query.salam
import db.clickhouse

func main:
    mut c := clickhouse.Open(clickhouse.DefaultOptions())
    defer c.Close()
    mut args := Vector {} as Vector<str>
    args.push(clickhouse.StrArg("2026-11-01"))
    mut rows := c.Query("SELECT page, sum(hits) AS total FROM visits WHERE day >= ? GROUP BY page ORDER BY total DESC", args)
    if not rows.Ok():
        println rows.Error()
        ret 1
    end
    until rows.Next():
        println rows.Text(0), rows.Int64(1)
    end
    rows.Close()

    mut params := HashMap {} as HashMap<str, str>
    params.put("page", "/docs")
    mut one := c.QueryParams("SELECT sum(hits) FROM visits WHERE page = {page:String}", params)
    until one.Next():
        println "docs:", one.Int64(0)
    end
    one.Close()
end

An aggregate such as sum(hits) is a 64 bit integer in ClickHouse, which arrives quoted in the JSON and is read back without losing digits by Int64.

import db.clickhouse

func main:
    mut o := clickhouse.DefaultOptions()
    o.addr = "127.0.0.1:8123"
    o.database = "shop"
    o.username = "default"
    o.password = ""
    o.secure = false
    o.timeout_ms = 10000
    o.settings.put("max_threads", "4")
    o.headers.put("X-Request-Source", "docs")
    println clickhouse.DEFAULT_PORT, clickhouse.DEFAULT_SECURE_PORT

    mut c := clickhouse.Open(o)
    if not c.Ping():
        println "no server:", c.Error(), c.status
        ret
    end
    println c.ServerVersion(), c.base, c.connected

    byurl := clickhouse.OpenURL("clickhouse://default:@127.0.0.1:8123/shop?max_threads=4")
    println byurl.Ok(), byurl.opts.database

    none := Vector {} as Vector<str>
    println c.Exec("CREATE TABLE IF NOT EXISTS events (id UInt64, name String) ENGINE = MergeTree ORDER BY id", none)
    mut ins := HashMap {} as HashMap<str, str>
    ins.put("id", "1")
    ins.put("name", "first")
    println c.ExecParams("INSERT INTO events VALUES ({id:UInt64}, {name:String})", ins)
    println c.ExecWith("OPTIMIZE TABLE events", none, o.settings)
    mut pn := HashMap {} as HashMap<str, str>
    pn.put("n", "7")
    println c.ExecFull("SELECT {n:UInt8}", pn, HashMap {} as HashMap<str, str>)
    if not c.Ok():
        println "failed with code", c.Code(), c.Error()
    end
    println c.query_id, c.read_rows, c.written_rows
    c.Close()
end

Query

func Query(sql: str, args: Vector<str>): Rows
Runs a query and returns its rows, with ? placeholders as in Exec. Check Ok on the result, and call Close when done.
db-clickhouse-Query.salam
import db.clickhouse

func main:
    mut c := clickhouse.Open(clickhouse.DefaultOptions())
    defer c.Close()
    none := Vector {} as Vector<str>

    mut args := Vector {} as Vector<str>
    args.push(clickhouse.UIntArg(10 as u64))
    mut rows := c.Query("SELECT id, name, price, tags, active FROM events WHERE id >= ?", args)
    if not rows.Ok():
        println rows.Error()
        ret
    end
    println rows.ColumnCount(), rows.RowCount(), rows.total
    repeat rows.ColumnCount() in i:
        println i, rows.ColumnName(i), rows.ColumnType(i), rows.ColumnKind(i), rows.ColumnIndex(rows.ColumnName(i))
    end
    until rows.Next():
        println rows.UInt64(0), rows.Int64(0), rows.Int(0), rows.Text(1), rows.Float(2), rows.Bool(4)
        println rows.IsNull(1), rows.Raw(3), rows.List(3).len(), rows.Row().len()
        println rows.TextBy("name"), rows.Int64By("id"), rows.FloatBy("price")
    end
    println rows.pos, rows.names.len(), rows.types.len(), rows.rows.len(), rows.cells.len()
    rows.Close()

    mut params := HashMap {} as HashMap<str, str>
    params.put("min", "10")
    mut byname := c.QueryParams("SELECT count() FROM events WHERE id >= {min:UInt64}", params)
    println byname.Ok()
    byname.Close()

    mut limits := HashMap {} as HashMap<str, str>
    limits.put("max_execution_time", "5")
    mut limited := c.QueryWith("SELECT sum(id) FROM events", none, limits)
    println limited.Ok()
    limited.Close()

    mut full := c.QueryFull("SELECT {min:UInt64}", params, limits)
    println full.Ok()
    full.Close()

    first := c.QueryRow("SELECT id, name FROM events ORDER BY id LIMIT 1", none)
    if first.len() == 2:
        println first.get(0), first.get(1)
    end
    println c.QueryText("SELECT version()"), c.QueryInt("SELECT count() FROM events")
end

PrepareBatch

func PrepareBatch(sql: str): Batch
Starts a batch insert from INSERT INTO table (columns); a trailing VALUES or semicolon is dropped. Anything else gives a batch whose Error says why.
db-clickhouse-Batch.salam
import db.clickhouse

func main:
    mut c := clickhouse.Open(clickhouse.DefaultOptions())
    defer c.Close()

    mut b := c.PrepareBatch("INSERT INTO events (id, name, tags, score)")
    if b.Error().len() > 0:
        println b.Error()
        ret
    end
    println b.head, b.width

    mut tags := Vector {} as Vector<str>
    tags.push(clickhouse.StrArg("a"))
    tags.push(clickhouse.StrArg("b"))
    mut row := Vector {} as Vector<str>
    row.push(clickhouse.IntArg(1 as i64))
    row.push(clickhouse.StrArg("o'brien"))
    row.push(clickhouse.ArrayArg(tags))
    row.push(clickhouse.FloatArg(2.5))
    println b.Append(row)

    again := clickhouse.Args(row)
    println b.Append(again)
    println c.SendBatch(b)

    mut broken := c.PrepareBatch("INSERT INTO events (id, name, tags, score)")
    mut bad := Vector {} as Vector<str>
    bad.push(clickhouse.NullArg())
    println broken.Append(bad), broken.Error(), broken.Len(), broken.rows.len()
    broken.Abort()

    keys := clickhouse.Args(tags)
    println clickhouse.MapArg(keys, keys)
    println clickhouse.TupleArg(keys), clickhouse.BoolArg(true), clickhouse.RawArg("now()")
    println clickhouse.QuoteIdent("my table")
end

AsDb

func AsDb(c: Conn): dyn db.Connection
Wraps a connection as a dyn db.Connection, so code written against the shared db interface runs on ClickHouse too. Exec returns 0 or -1, Changes is the rows the last request wrote, LastInsertId is always 0, and a transaction runs each statement at once: ClickHouse has none, so Commit returns 0 and Rollback returns -1.
db-clickhouse-Shared.salam
import db
import db.clickhouse

func total(c: dyn db.Connection, table: str): int:
    ret db.QueryInt(c, "SELECT count() FROM " + table)
end

func main:
    c := clickhouse.Open(clickhouse.DefaultOptions())
    d := clickhouse.AsDb(c)
    defer d.Close()
    println d.Kind() == db.CLICKHOUSE, d.Ping()
    println total(d, "events")
    r := d.Query("SELECT id, name FROM events LIMIT 5")
    until r.Next():
        println r.Int64(0), r.Text(1), r.ColumnType(0)
    end
    r.Close()
    t := d.Begin()
    println t.Exec("INSERT INTO events VALUES (99, 'x')"), t.Commit()
end
