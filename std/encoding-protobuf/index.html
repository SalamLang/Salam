encoding/protobuf

Reading .proto files, the Protocol Buffers wire encoding, and generating Salam code from them.

Protocol Buffers is Google's binary format for structured messages. The shape of the messages is defined in a .proto file, and this package reads it, generates Salam code for the messages and services, and also carries the low level tools for writing and reading fields.

In the bytes, every field comes as a tag, the field number and the wire type, followed by its value. Numbers are usually written as a varint: each byte holds 7 bits of the number and its top bit says whether another byte follows.

Use Protocol Buffers when you talk to a service that already speaks it, usually over grpc, or when several languages share one schema. Between Salam programs, or when no .proto file exists, encoding/msgpack needs no schema and encoding/json stays readable.

What trips people up

  • Generated readers do not accept packed repeated numbers. Proto3 writers such as protoc, Go and Java send a repeated int32 as one length-prefixed block by default. The generated Unmarshal reads one tag per element and does not check the wire type, so a packed field fails or gives wrong numbers. The generated Marshal writes the unpacked form, which every reader accepts. Decode packed fields by hand as in the packed guide, or mark the field [packed = false] on the other side.
  • The generator skips message, enum and map fields. Members of a oneof become ordinary fields, so nothing stops two of them being set. Write those parts by hand.
  • Varints are u64. ReadVarint returns a u64; cast to i64 or int yourself, and run sint fields through ZigZagDecode64.
  • Check ok once, at the end. Every reader clears the shared ok flag when the data runs out; nothing stops the program, so test it before you use the result.

The guide below works through the jobs you meet in practice: writing a message by hand, reading one back while skipping fields you do not know, nesting messages, packed repeated numbers, choosing between int64 and sint64, and generating the code from a .proto file instead of writing it. Every byte buffer here is a compress.ByteBuf from compress, so programs import both packages.

Writing a message by hand

A message is nothing more than its fields one after another. For each field call WriteTag with the field number from the .proto file and the wire type, then the writer for the value: WriteVarint for integers, enums and booleans, WriteLenPrefixedStr for strings and WriteLenPrefixedBytes for bytes and nested messages. The program below writes User { id: 42, name: "Sara", admin: true } and prints the bytes in hex.

encoding-protobuf-encode-user.salam
import encoding.protobuf
import compress

func hex(b: compress.ByteBuf): str:
    digits := "0123456789abcdef"
    mut out := ""
    repeat compress.BufLen(b) in i:
        v := compress.BufGet(b, i)
        if i > 0: out = out + " " end
        out = out + digits.substr(v / 16, 1) + digits.substr(v % 16, 1)
    end
    ret out
end

func main:
    mut b := compress.NewByteBuf()
    protobuf.WriteTag(b, 1, protobuf.WT_VARINT)
    protobuf.WriteVarint(b, 42 as u64)
    protobuf.WriteTag(b, 2, protobuf.WT_LEN)
    protobuf.WriteLenPrefixedStr(b, "Sara")
    protobuf.WriteTag(b, 3, protobuf.WT_VARINT)
    protobuf.WriteVarint(b, 1 as u64)
    println "bytes:", compress.BufLen(b)
    println hex(b)
    compress.BufFree(b)
end
Outputbytes: 10 08 2a 12 04 53 61 72 61 18 01

Read the output in pairs: 08 is field 1 with wire type 0, 2a is 42; 12 is field 2 with wire type 2, 04 the length and then the four letters; 18 01 is field 3 set to true. Proto3 leaves out fields that hold their default value (0, an empty string, false), so a sender usually checks the value before it writes the tag.

Reading a message and skipping unknown fields

Decoding is a loop: read a tag, look at the field number, read the value with the reader that matches, and repeat until the reader is empty. A field number you do not know must still be stepped over, which is what SkipField does with the wire type. That is how an old program keeps reading messages from a newer one that added fields. Every reader takes the same ok flag, so one check after the loop catches a message that was cut short.

encoding-protobuf-decode-loop.salam
import encoding.protobuf
import compress

struct User:
    pub id: int = 0
    pub name: str = ""
    pub admin: bool = false
end

func decodeUser(data: void*, n: int, ok &: bool): User:
    mut u := User {}
    mut r := compress.NewByteReader(data, n)
    ok = true
    until compress.RdLeft(r) > 0 and ok:
        mut number := 0
        mut wire := 0
        protobuf.ReadTag(r, number, wire, ok)
        if not ok: ret u end
        switch number:
            1:
                u.id = protobuf.ReadVarint(r, ok) as int
                break
            end
            2:
                u.name = protobuf.ReadLenPrefixedStr(r, ok)
                break
            end
            3:
                u.admin = protobuf.ReadVarint(r, ok) != (0 as u64)
                break
            end
            else:
                println "skipping unknown field", number
                protobuf.SkipField(r, wire, ok)
            end
        end
    end
    ret u
end

func main:
    mut b := compress.NewByteBuf()
    protobuf.WriteTag(b, 1, protobuf.WT_VARINT)
    protobuf.WriteVarint(b, 42 as u64)
    protobuf.WriteTag(b, 9, protobuf.WT_LEN)
    protobuf.WriteLenPrefixedStr(b, "added in v2")
    protobuf.WriteTag(b, 2, protobuf.WT_LEN)
    protobuf.WriteLenPrefixedStr(b, "Sara")
    mut ok := false
    u := decodeUser(b.data, b.len, ok)
    println ok, u.id, u.name, u.admin
    _ := decodeUser(b.data, b.len - 2, ok)
    println "truncated:", ok
    compress.BufFree(b)
end
Outputskipping unknown field 9 true 42 Sara false skipping unknown field 9 truncated: false

The second call reads the same bytes minus the last two: the string length promises four bytes that are not there, ReadLenPrefixedStr clears ok, and the loop stops. Always test ok before you trust the struct you filled.

Nested and repeated messages

A field whose type is another message is written as bytes: encode the inner message into its own buffer, then write it with wire type WT_LEN and WriteLenPrefixedBytes. A repeated field is the same tag written once per element. On the reading side ReadLenPrefixedBuf hands you the inner bytes as a new buffer, which you decode with the same loop and then free.

encoding-protobuf-nested.salam
import encoding.protobuf
import compress

func writeItem(order &: compress.ByteBuf, name: str, qty: int):
    mut item := compress.NewByteBuf()
    protobuf.WriteTag(item, 1, protobuf.WT_LEN)
    protobuf.WriteLenPrefixedStr(item, name)
    protobuf.WriteTag(item, 2, protobuf.WT_VARINT)
    protobuf.WriteVarint(item, qty as u64)
    protobuf.WriteTag(order, 2, protobuf.WT_LEN)
    protobuf.WriteLenPrefixedBytes(order, item.data, item.len)
    compress.BufFree(item)
end

func printItem(b: compress.ByteBuf):
    mut r := compress.ReaderFromBuf(b)
    mut ok := true
    mut name := ""
    mut qty := 0
    until compress.RdLeft(r) > 0 and ok:
        mut number := 0
        mut wire := 0
        protobuf.ReadTag(r, number, wire, ok)
        if number == 1: name = protobuf.ReadLenPrefixedStr(r, ok)
        else number == 2: qty = protobuf.ReadVarint(r, ok) as int
        else: protobuf.SkipField(r, wire, ok) end
    end
    println "  item", name, "x", qty
end

func main:
    mut order := compress.NewByteBuf()
    protobuf.WriteTag(order, 1, protobuf.WT_VARINT)
    protobuf.WriteVarint(order, 1001 as u64)
    writeItem(order, "pen", 3)
    writeItem(order, "notebook", 1)
    println "order bytes:", compress.BufLen(order)

    mut r := compress.ReaderFromBuf(order)
    mut ok := true
    until compress.RdLeft(r) > 0 and ok:
        mut number := 0
        mut wire := 0
        protobuf.ReadTag(r, number, wire, ok)
        if number == 1:
            println "order", protobuf.ReadVarint(r, ok)
        else number == 2:
            mut sub := protobuf.ReadLenPrefixedBuf(r, ok)
            printItem(sub)
            compress.BufFree(sub)
        else:
            protobuf.SkipField(r, wire, ok)
        end
    end
    compress.BufFree(order)
end
Outputorder bytes: 26 order 1001 item pen x 3 item notebook x 1

Packed repeated numbers

A repeated field of numbers can travel in two shapes. Unpacked, each element has its own tag. Packed, the default in proto3, there is one tag with wire type WT_LEN and the varints follow one after another inside it. A correct reader accepts both, so look at the wire type: for WT_LEN, take the block with ReadLenPrefixedBuf and read varints until it is empty.

encoding-protobuf-packed.salam
import encoding.protobuf
import compress

func readScores(b: compress.ByteBuf): Vector<int>:
    mut out := Vector {} as Vector<int>
    mut r := compress.ReaderFromBuf(b)
    mut ok := true
    until compress.RdLeft(r) > 0 and ok:
        mut number := 0
        mut wire := 0
        protobuf.ReadTag(r, number, wire, ok)
        if number == 1 and wire == protobuf.WT_LEN:
            mut packed := protobuf.ReadLenPrefixedBuf(r, ok)
            mut pr := compress.ReaderFromBuf(packed)
            until compress.RdLeft(pr) > 0 and ok:
                out.push(protobuf.ReadVarint(pr, ok) as int)
            end
            compress.BufFree(packed)
        else number == 1 and wire == protobuf.WT_VARINT:
            out.push(protobuf.ReadVarint(r, ok) as int)
        else:
            protobuf.SkipField(r, wire, ok)
        end
    end
    ret out
end

func main:
    scores := [7, 150, 3]

    mut body := compress.NewByteBuf()
    each s in scores:
        protobuf.WriteVarint(body, s as u64)
    end
    mut packed := compress.NewByteBuf()
    protobuf.WriteTag(packed, 1, protobuf.WT_LEN)
    protobuf.WriteLenPrefixedBytes(packed, body.data, body.len)

    mut unpacked := compress.NewByteBuf()
    each s in scores:
        protobuf.WriteTag(unpacked, 1, protobuf.WT_VARINT)
        protobuf.WriteVarint(unpacked, s as u64)
    end

    println "packed:  ", compress.BufLen(packed), "bytes ->", readScores(packed)
    println "unpacked:", compress.BufLen(unpacked), "bytes ->", readScores(unpacked)
    compress.BufFree(unpacked)
    compress.BufFree(packed)
    compress.BufFree(body)
end
Outputpacked: 6 bytes -> [7, 150, 3] unpacked: 7 bytes -> [7, 150, 3]

Packing saves one tag byte per element, which adds up in long lists of small numbers. This is also the code to use in place of the generated Unmarshal for a field that comes from protoc-generated code in another language.

Negative numbers: int64 or sint64

A plain int32 or int64 field writes a negative number as a huge unsigned value, which always takes ten bytes. The sint32 and sint64 types first map the number with ZigZag (0, -1, 1, -2 become 0, 1, 2, 3), so small negative numbers stay small. Use ZigZagEncode64 before WriteVarint and ZigZagDecode64 after ReadVarint, and pick sint64 in the .proto file for fields such as offsets or temperature deltas that are often below zero.

encoding-protobuf-zigzag.salam
import encoding.protobuf
import compress

func varintSize(n: u64): int:
    mut b := compress.NewByteBuf()
    protobuf.WriteVarint(b, n)
    size := compress.BufLen(b)
    compress.BufFree(b)
    ret size
end

func main:
    values := [5, -1, -64, 300, -300]
    each v in values:
        wide := v as i64
        plain := varintSize(wide as u64)
        zig := varintSize(protobuf.ZigZagEncode64(wide))
        println v, "takes", plain, "bytes as int64 and", zig, "as sint64"
    end
    println "zigzag of -1 is", protobuf.ZigZagEncode64(-1 as i64), "and back", protobuf.ZigZagDecode64(1 as u64)
end
Output5 takes 1 bytes as int64 and 1 as sint64 -1 takes 10 bytes as int64 and 1 as sint64 -64 takes 10 bytes as int64 and 1 as sint64 300 takes 2 bytes as int64 and 2 as sint64 -300 takes 10 bytes as int64 and 2 as sint64 zigzag of -1 is 1 and back -1

Generating the code from a .proto file

For more than a couple of messages, let the package write the code. GenerateSingle turns a .proto source into a Salam package with one struct per message and a Marshal and Unmarshal function for each; GenerateWithServices adds gRPC client stubs for the services (see grpc). The program below prints only the declarations of the generated code.

encoding-protobuf-codegen.salam
import encoding.protobuf

func main:
    proto := "syntax = \"proto3\";\nmessage Point {\n  sint32 x = 1;\n  sint32 y = 2;\n  string label = 3;\n}\n"
    mut ok := false
    code := protobuf.GenerateSingle(proto, ok)
    if not ok:
        println "the proto file did not parse"
        ret 1
    end
    lines := code.split("\n")
    each line in lines:
        if line.starts_with("pub ") or line.starts_with("package "):
            println line
        end
    end
    ret 0
end
Outputpackage generated_pb pub struct Point: pub func MarshalPoint(m: Point): compress.ByteBuf: pub func UnmarshalPoint(data: void*, n: int, ok &: bool): Point:

Save the text to a file such as point_pb.salam, add include pb "point_pb.salam" to your program, and call pb.MarshalPoint(p) to get a ByteBuf and pb.UnmarshalPoint(buf.data, buf.len, ok) to read one back. The generator covers scalar fields, strings, bytes and repeated scalars. It leaves out fields whose type is another message or an enum, gives map fields no code and turns oneof members into ordinary fields, so write those few by hand as in the nested example above, or keep the enum as an int32 in the .proto file. Repeated numbers are read only in the unpacked form; see the packed guide.

GenerateSingle

func GenerateSingle(protoSource: str, ok &: bool): str
Generates Salam code from .proto text: one struct per message, with its serialising functions. Message, enum and map fields are left out, and the generated reader expects repeated numbers unpacked.
encoding-protobuf-Generate.salam
import encoding.protobuf
import str

func main:
    src := "syntax = \"proto3\";\nmessage Ping { string text = 1; }\nservice Echo {\n  rpc Say (Ping) returns (Ping);\n  rpc Stream (stream Ping) returns (stream Ping);\n}\n"
    mut ok := false
    code := protobuf.GenerateSingle(src, ok)
    println ok, str.Contains(code, "struct Ping")
    p := protobuf.ParseFile(src, ok)
    println protobuf.ServiceCount(p), protobuf.ServiceNameAt(p, 0), protobuf.ServiceMethodCount(p, 0)
    println protobuf.ServiceMethodSignature(p, 0, 0)
    println protobuf.ServiceMethodSignature(p, 0, 1)
    println str.Contains(protobuf.GenerateServices(p), "Echo")
    all := protobuf.GenerateWithServices(src, ok)
    println ok, str.Len(all) > str.Len(code)
    println protobuf.ServiceSummary(src, ok)
end
