gui.device

Phone features for Salam apps: share sheet, haptics, permissions, notifications, location and photos on Android, with the same calls returning false on other systems.

gui.device reaches the features of a phone that a page cannot draw: the share sheet and more as they are added. Every call has the same signature on every system. On a desktop, or when the phone does not offer the feature, the call returns false or an empty value and the program carries on.

Platform names the system the program runs on: android, ios or none on a desktop. CanShare tells whether a share sheet exists, and Share opens it with a text and a link. Either may be empty, but not both. The call returns once the sheet is shown; it does not tell what the user chose.

Haptic gives a short system feedback (Tap, Heavy, Success or Failure) and needs no permission. Vibrate runs the motor for a number of milliseconds, at most 5000; on Android the build script adds the VIBRATE permission to the manifest only when the program calls it.

Runtime permissions: CheckPermission answers NotAsked, Granted or Denied at once, and RequestPermission opens the system dialog. The answer arrives later: OnChange sets a function that runs on the UI thread when any request finishes, and a gui.ui app calls ui.Invalidate there and reads CheckPermission in its view. A program that uses gui.window directly receives an EventKind.HostResult event and calls Notify. On Android the manifest must declare the permission: build with --permission camera (also microphone, location, notifications). Without a declaration the request is denied at once. Systems without permissions report Denied.

Notifications: ShowNotification posts one now, ScheduleNotification posts one after a number of seconds, even when the app is not in front, and CancelNotification removes it. The id replaces an earlier notification with the same id. Tapping a notification opens the app. They return false until the Notifications permission is granted (ask with RequestPermission first; from Android 13 it is asked at run time). The build script adds the permission to the manifest when the program shows or schedules a notification. A scheduled notification is inexact and does not survive a restart of the phone.

Location, one fix at a time: RequestLocation asks for the current position and returns at once, LocationStatus says Pending, Ready or Failed, and LastLocation reads the answer. OnChange runs when the fix arrives. The Location permission must be granted first; the build script declares it when the program asks for a location. GPS is used when it is on, the network provider otherwise, and a fix can take several seconds.

Photos: PickPhoto opens the system photo picker and TakePhoto opens the camera app, both without any permission, because the system apps do the work. PhotoStatus says Pending, Ready or Failed (also when the user cancels) and LastPhoto is the path of a JPEG copy in the app cache directory, which image can open. OnChange runs when the picture is ready. The camera app asks for its own permission; if the app declares the camera permission itself (--permission camera) it must be granted before TakePhoto.

App folders: DataDir is the private folder for files the app keeps, CacheDir holds files the system may delete when space runs low, DocumentsDir is the folder the user can reach (the app folder on shared storage on Android, Documents on iOS) and TempDir is for short lived files. Each returns the path of a folder that exists, or an empty string where the system has no such folder. No permission is needed.

Secure storage keeps small secrets such as a login token: SecureSet saves a value under a key, SecureGet reads it back (empty when there is none) and SecureDelete removes it. On Android the value is encrypted with an AES key that never leaves the Android Keystore; on iOS it goes to the Keychain. Keys are up to 200 bytes and values up to 16000 bytes. Where the system has no secure storage, SecureSet and SecureDelete return false and SecureGet returns an empty string.

Device and app information: Model, OSName and OSVersion name the phone and its system; Language is the preferred language tag, Languages the whole list and TimeZone the zone name; ScreenDensity is the pixels per layout point; AppVersion and BuildNumber are the values given with --version and --build when building; IsDarkMode tells the appearance. BatteryLevel gives percent, or -1 when unknown, and IsCharging tells whether the phone is plugged in. Network answers Offline, Wifi, Cellular, Ethernet or Other, and a change of connection runs the function set by OnChange, the way a permission answer does. Each call returns an empty string, zero, false or Offline where the system has no such information, and no permission is needed except ACCESS_NETWORK_STATE for Network on Android, which the build adds.

Links into the app: build with --scheme NAME to open links like NAME://path (a URL type on iOS, an intent filter on Android) and, on Android, with --link-host HOST to open https://HOST links; the site must also serve its assetlinks.json. LaunchURL is the link that started the app, empty when it was started in the usual way, and OnOpenURL sets the function that runs with a link that arrives while the app is running (the host event wakes the loop, so it runs on the UI thread). OpenSettings opens the settings page of the app, where the user can change permissions.

Screen behaviour: KeepAwake stops the screen from sleeping while the app is in front, LockOrientation locks to Portrait or Landscape at run time (the build option --orientation sets the start) and Auto frees it. Immersive hides the status bar and the navigation bar for a full screen page, SetBarStyle picks light or dark status bar icons, and SetBrightness and Brightness use values from 0.0 to 1.0. They need no permission. Each returns false where the system has no such control.

Biometrics: CanAuthenticate tells whether the phone has a fingerprint or face the user has set up, and Authenticate opens the system prompt with a reason. It returns at once; AuthStatus then says Pending, Success or Failed, and OnChange runs when the answer arrives. No biometric data reaches the app, only the verdict.

Calls go through the host layer of the phone shell, so they work in apps built with tools/bash/build-android-app.sh.

/*
 * Salam Programming Language (2018-2026)
 *
 *   +-------------------+
 *   |     S A L A M     |

import gui.device

        b.On("click", (): _ok := device.RequestPermission(device.Permission.Camera) end)
        b.Text(label())
        b.Close()
    end)
end

Where am I

A button that asks for the permission, then for one fix, and shows the position.

gui-device-Location.salam
/*
 * Salam Programming Language (2018-2026)
 *
 *   +-------------------+
 *   |     S A L A M     |
 *   +-------------------+
 *
 * Designed by Seyyed Ali Mohammadiyeh and the Salam Team
 *
 * Repository: https://github.com/SalamLang/Salam
 *
 */


import gui.device
import gui.ui
import str

func where(): str:
    state := device.LocationStatus()
    if state == device.LocationState.Ready:
        here := device.LastLocation()
        ret "lat " + str.FromFloat(here.latitude) + " lon " + str.FromFloat(here.longitude) + " within " + str.FromFloat(here.accuracy) + " m"
    end
    if state == device.LocationState.Pending:
        ret "looking for the position"
    end
    if state == device.LocationState.Failed:
        ret "no position"
    end
    ret "tap to locate"
end

func ask():
    if device.CheckPermission(device.Permission.Location) == device.PermissionState.Granted:
        _ok := device.RequestLocation()
        ui.Invalidate()
    else:
        _ok2 := device.RequestPermission(device.Permission.Location)
    end
end

func main:
    println where()
    device.OnChange((): ui.Invalidate() end)
    ui.RunPage((): ret ui.NoPatches() end, (b: ui.Builder):
        b.Open("button")
        b.On("click", (): ask() end)
        b.Text(where())
        b.Close()
    end)
end

Where a photo request stands.
NameTypeDescription

FailedThe user cancelled or the system has no picker or camera.
