gui.style

The Salam UI style standard: every property with its English and Persian name, value syntax, validation with clear errors, defaults per element, inheritance, interpolation for transitions and the CSS the web target writes.

gui.style is the style standard of the Salam UI, in the spirit of QML: one vocabulary of properties that works the same on the web and in a native window. A page never contains CSS. The compiler checks every style attribute with this package, writes CSS from it for the web target and builds typed values from it for the native target, so both look the same.

Every property has an int id (P_WIDTH, P_PADDING, ...), an English and a Persian name, a value kind, a keyword set with English and Persian names, a default, and flags that say whether it is inherited and whether it can be animated. The table is in the package, and Info returns one row of it.

The value syntax:

  • Numbers in the property's natural unit: pixels for lengths, milliseconds for times, degrees for angles, a plain number for opacity, grow and scale. Units: px, %, em, rem, vw, vh, vmin, vmax, fr, ms, s, deg, turn, rad, also as calls like px(12).
  • Length arithmetic: 100% - 20 and 50% + 1em; the web target writes calc().
  • Lists with a comma (padding = 8, 16) and groups in brackets (shadow = [0, 4, 8, black], [0, 1, 2, red]).
  • Composites in any order where the parts differ: border = 2, solid, #3366aa or border = red, 1.
  • Calls: linear(90, red, blue), radial(circle, [30%, 40%], white, black), conic(...), image("a.png"), minmax(100, 1fr), repeat(fill, 200), fit(300), ease(0.2, 0, 0, 1), steps(4), spring(170, 26), and every colour of gui.color.
  • Persian: keywords and property names in Persian, Persian digits, ٪ and the comma ،.
  • Strings are read with the same syntax: "8, 16" is the same as 8, 16.

Things to know

  • Sides and corners follow the text direction: four values are top, end, bottom, start, and radius goes top start, top end, bottom end, bottom start. left and right become start or end by the direction when they are set.
  • gap has no effect in flow (the lines and items there are spaced by margins and line height), on both targets; it is accepted and ignored. min width and min height start at auto, the automatic minimum, so a flex child does not shrink below its content unless a smaller minimum is given.
  • In flow, inline text elements (span, bold, italic, code, link and the like) stay inline content on the web so text wraps across them; every other child is one atomic item on the line, baseline aligned.
  • Every box is a column by default and text elements use flow. BaseCss gives the web the same defaults, so plain HTML does not look different from the native window.
  • Css returns declarations. Filters and reverse set --salam-* variables that the base sheet reads, and layout = stack and flow end with a nested &>* rule for the children, so the web target has to put them in a style rule, not in a style attribute.
  • Source writes code that uses only this package, for programs the compiler generates for the native target.

One style for the web and a native window

A card is described with attribute values as a page would write them. Each one is parsed and checked; a value out of range gives a message with the expected form. The same values become CSS for the web and typed fields that a native renderer reads.

gui-style-guide-card.salam
import gui.style

func main:
    names := ["layout", "gap", "padding", "radius", "background", "color", "shadow", "width", "max width", "opacity"]
    values := ["row", "12", "16, 24", "12", "linear(90, #3366aa, #5588cc)", "white", "0, 4, 12, #00000040", "100% - 32", "480", "120%"]
    mut s := style.Default("box")
    mut rule := ""
    repeat names.Len() in i:
        p := style.PropByName(names[i])
        mut v := style.Value {}
        if not style.Parse(p, values[i], v):
            println style.Error(p, values[i])
            continue
        end
        style.Set(s, p, v)
        rule += style.Css(p, v) + ";"
    end
    println "web:", ".card{" + rule + "}"
    println "native: row", s.layout_kind == style.KW_ROW, "gap", s.gap_column.px, "padding", s.padding_top.px, s.padding_start.px
    println "native: width", s.width.len.pct, "% plus", s.width.len.px, "px, at most", s.max_width.len.px
    println "native: shadow blur", s.shadow.Get(0).blur.px, "background layers", s.background.Len()
end
Outputopacity: 1.2 is out of range; expected a number from 0 to 1 or a percent, for example opacity = 0.5 web: .card{display:var(--salam-o,block) flex;flex-direction:var(--salam-dir,row);--salam-rev:row-reverse;gap:12px;padding-block:16px;padding-inline:24px;border-radius:12px;background-color:transparent;background-image:linear-gradient(90deg,#3366aa,#5588cc);color:#ffffff;box-shadow:0 4px 12px 0 #00000040;width:calc(100% - 32px);max-width:480px;} native: row true gap 12 padding 16 24 native: width 100 % plus -32 px, at most 480 native: shadow blur 12 background layers 1

Lengths keep their units until layout: 100% - 32 stays a percent plus pixels, and the native layout resolves the percent against the parent.

A hover transition, frame by frame

A transition needs the same curve on both targets. The web gets the CSS timing function, and a native renderer computes each frame with EaseAt and Lerp, which mix colours in oklab and lengths unit by unit.

gui-style-guide-hover.salam
import gui.style

func value(p: int, text: str): style.Value:
    mut v := style.Value {}
    style.Parse(p, text, v)
    ret v
end

func main:
    rest := value(style.P_BACKGROUND, "#3366aa")
    hover := value(style.P_BACKGROUND, "#5588cc")
    lift := value(style.P_TRANSLATE, "0, -2")
    still := value(style.P_TRANSLATE, "0")
    tr := value(style.P_TRANSITION, "200ms, ease out")
    mut s := style.Style {}
    style.Set(s, style.P_TRANSITION, tr)
    easing := s.transition.Get(0).easing
    println "web:", style.Css(style.P_TRANSITION, tr)
    repeat 5 in frame:
        ms := (frame as f64) * 50.0
        k := style.EaseAt(easing, ms / s.transition.Get(0).duration)
        bg := style.Lerp(style.P_BACKGROUND, rest, hover, k)
        y := style.Lerp(style.P_TRANSLATE, still, lift, k)
        println ms, "ms:", style.Format(style.P_BACKGROUND, bg), "translate", style.Format(style.P_TRANSLATE, y)
    end
    println style.Error(style.P_TRANSITION, "fast")
end
Outputweb: transition-duration:200ms;transition-timing-function:ease-out;transition-delay:0ms 0 ms: #3366aa translate 0, 0 50 ms: #4073b7 translate 0, -0.7563 100 ms: #4a7dc1 translate 0, -1.3693 150 ms: #5285c9 translate 0, -1.8131 200 ms: #5588cc translate 0, -2 transition: 'fast' is not a time or an easing; expected a duration, an easing and a delay, with [ ] around each transition when there are several, or none, for example transition = 200ms, ease out

spring(stiffness, damping) works the same way: the native target uses EaseAt, and Css writes the same curve as a CSS linear() timing function.

import gui.style

func main:
