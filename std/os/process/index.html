os.process

Running other programs, talking to them through pipes, reading with a time limit, telling an exit code from a signal, and stopping them.

The os.process package runs another program directly, with no shell in between. The program's path and its arguments are given separately, so nothing has to be quoted and spaces or special characters in an argument cause no trouble. Use it to call tools such as git, ffmpeg or a compiler with file names that came from a user. For a quick one-line shell command use os (Run, RunCapture) or os.shell; when a program cannot start at all, the reason is recorded in os.error.

A run has up to four steps: Start or StartCaptured launches the program and returns at once, Wait blocks until it exits and returns the exit code, ReadStdout and ReadStderr read what a captured run printed, and Cleanup deletes the two temporary files that held it. A captured program gets an empty standard input.

For a program you talk to while it runs, with pipes, time limits and exit codes or signals, use Command, Launch and Child, described in the sections below. For a program that must see a terminal, use os.pty.

What people get wrong:

  • Treating IsRunning as a live check. It reports a flag that Start sets and only Wait, Kill or Terminate clear; it stays true after the program has exited on its own.
  • Killing without waiting. Kill and Terminate only send the signal. Call Wait afterwards, or the finished process stays in the process table as a zombie.
  • Expecting a timeout from Wait. Wait on a Process waits as long as the program runs. To give up after a while use a Child (see below), whose Wait takes a time limit.
  • Forgetting Cleanup. Each captured run leaves two files in the temporary folder until you call it.

On Windows the arguments are joined into one command line with quotes around those that contain spaces, and the ANSI CreateProcessA starts the program. An argument that itself contains a ", or text outside the system code page such as Persian, does not arrive intact there; Fork and WaitPid return -1.

Pass arguments exactly as they are

Each element of the argument vector reaches the program as one argument, byte for byte. Spaces, quotes, a $ or a ; mean nothing special, because no shell reads them. That makes this package the safe way to pass file names and other text that came from a user.

os-process-guide-args.salam
import os.process

func main:
    mut args := Vector {} as Vector<str>
    defer args.free()
    args.push("[%s]\n")
    args.push("two words")
    args.push("it's quoted")
    args.push("$HOME")
    args.push("*.txt; rm -rf x")
    mut p := process.StartCaptured("printf", args)
    process.Wait(p)
    print process.ReadStdout(p)
    process.Cleanup(p)
end
Output[two words] [it's quoted] [$HOME] [*.txt; rm -rf x]

The program name is looked up on the PATH like in a terminal, so printf works without a full path. The vector does not include the program name itself; the package adds it. This exactness holds on Linux and macOS; see the note above for Windows.

Exit code, output and error output

A program reports success with exit code zero and anything else on failure, and it writes its complaints to the error output. After Wait, read both: ReadStdout for the results and ReadStderr for the reason it failed. Call Cleanup after reading, because the captured output is kept in temporary files until then.

os-process-guide-exitcode.salam
import os.process

func main:
    mut args := Vector {} as Vector<str>
    defer args.free()
    args.push("-c")
    args.push("echo copying files; echo disk is full >&2; exit 3")
    mut p := process.StartCaptured("sh", args)
    code := process.Wait(p)
    out := process.ReadStdout(p).trim()
    err := process.ReadStderr(p).trim()
    process.Cleanup(p)
    println "output:", out
    if code != 0:
        println "failed with code", code, "and said:", err
        ret 0
    end
    println "all good"
end
Outputoutput: copying files failed with code 3 and said: disk is full

Run several programs at once

StartCaptured returns as soon as the program has started, so you can start several and wait for them afterwards. The total time is about that of the slowest one rather than the sum of all. Waiting in the order you started them keeps the output in a fixed order, even when a later job finished first.

os-process-guide-parallel.salam
import os.process

func job(name: str, seconds: str): process.Process:
    mut args := Vector {} as Vector<str>
    defer args.free()
    args.push("-c")
    args.push("sleep " + seconds + "; echo " + name + " done")
    ret process.StartCaptured("sh", args)
end

func main:
    mut jobs := Vector {} as Vector<process.Process>
    defer jobs.free()
    jobs.push(job("thumbnails", "0.3"))
    jobs.push(job("search index", "0.1"))
    jobs.push(job("sitemap", "0.2"))
    println "started", jobs.len(), "jobs"
    repeat jobs.len() in i:
        mut p := jobs.get(i)
        code := process.Wait(p)
        println code, process.ReadStdout(p).trim()
        process.Cleanup(p)
    end
end
Outputstarted 3 jobs 0 thumbnails done 0 search index done 0 sitemap done

Keep the number of programs you run at once reasonable; os.platform's CpuCount is a good limit for work that keeps the processor busy.

A helper that runs a program and returns its output

Most programs need the same few lines every time: start, check that it started, wait, read, clean up. Put them in one function. A defer right after the start makes sure Cleanup runs on every way out of the function, and an out-parameter tells the caller whether the program succeeded.

os-process-guide-helper.salam
import os.error
import os.process

func capture(program: str, args: Vector<str>, ok &: bool): str:
    error.Clear()
    mut p := process.StartCaptured(program, args)
    if error.HasError():
        ok = false
        ret ""
    end
    defer process.Cleanup(p)
    ok = process.Wait(p) == 0
    ret process.ReadStdout(p)
end

func main:
    mut args := Vector {} as Vector<str>
    defer args.free()
    args.push("-c")
    args.push("printf 'pear\\napple\\nfig\\n' | sort")
    mut ok := false
    out := capture("sh", args, ok)
    println "worked:", ok
    print out
    capture("/no/such/tool", args, ok)
    println "missing tool worked:", ok
end
Outputworked: true apple fig pear missing tool worked: false

Stop a program

Terminate sends SIGTERM, which a well-behaved program catches to save its work and exit; Kill sends SIGKILL, which cannot be caught. Either way, Wait collects the program afterwards. A program ended by a signal reports 128 plus the signal number as its exit code, so 143 means SIGTERM and 137 means SIGKILL, the same numbers a shell shows.

os-process-guide-stop.salam
import os.process

func main:
    mut args := Vector {} as Vector<str>
    defer args.free()
    args.push("30")
    mut worker := process.Start("sleep", args)
    println "started, running:", process.IsRunning(worker)
    if process.Terminate(worker) != 0:
        println "could not signal it"
        ret 1
    end
    code := process.Wait(worker)
    println "stopped with exit code", code, "= 128 + signal", code - 128
    println "running:", process.IsRunning(worker)
    ret 0
end
Outputstarted, running: true stopped with exit code 143 = 128 + signal 15 running: false

Talk to a running child

Start and StartCaptured run a program to the end. When you need to talk to it while it runs, describe it with a Command (NewCommand gives one for a program), pass it to Launch, and use the Child it returns. Set stdin_mode, stdout_mode and stderr_mode to Pipe (or call Piped) to connect a stream to your program, to Null to throw it away, or leave Inherit to share your own. Merge on the error stream puts it into the output pipe in the order it was written. Arg, Env, Unset and the cwd and clear_env fields set the arguments, the environment and the folder. Writing to a child that has already gone returns false and never kills your program.

os-process-guide-launch.salam
import os.process

func main:
    mut cmd := process.NewCommand("sh")
    cmd.Arg("-c")
    cmd.Arg("read name; echo hello $name")
    cmd.stdin_mode = process.Pipe
    cmd.stdout_mode = process.Pipe
    mut child := process.Launch(cmd)
    if not child.ok:
        println "could not start:", child.error
        ret 1
    end
    child.Write("Sara\n")
    reply := child.ReadLine(2000)
    println reply.data
    reply.Free()
    println "exit code:", child.Wait(2000).code
    child.Close()
    cmd.Free()
end
Outputhello Sara exit code: 0

Read with a time limit

Every read takes a time in milliseconds: 0 only looks, a positive number waits that long, a negative number waits for ever. ReadAvailable returns whatever has arrived, ReadLine one complete line, Read an exact number of bytes, ReadUntil everything up to a given text (the way to wait for a prompt) and ReadFor everything that arrives in a period. A read returns a Chunk: check timed_out (nothing came, and the child may still be working) and eof (the stream ended) before using data, and Free it. Bytes that were read but not yet returned stay in the child, so a timed-out call loses nothing. The ReadErr methods do the same for the error pipe, and ReadBytes reads binary data into a buffer.

os-process-guide-read.salam
import os.process

func main:
    mut cmd := process.NewCommand("sh")
    cmd.Arg("-c")
    cmd.Arg("echo first; sleep 0.3; echo second")
    cmd.stdout_mode = process.Pipe
    mut child := process.Launch(cmd)
    a := child.ReadLine(2000)
    println "line:", a.data
    b := child.ReadLine(50)
    println "nothing yet:", b.timed_out
    c := child.ReadLine(2000)
    println "line:", c.data
    d := child.ReadLine(2000)
    println "closed:", d.eof
    a.Free()
    b.Free()
    c.Free()
    d.Free()
    _status := child.Wait(2000)
    child.Close()
    cmd.Free()
end
Outputline: first nothing yet: true line: second closed: true

Exit code or signal

Child.Wait takes a time limit and returns a Status. A child that ended by itself has exited set and its code in code; one that a signal ended has signaled set and the number in signal. This differs from Process.Wait, which folds a signal into 128 plus the number. ReturnCode gives the Python-style number (the code, or the negative signal), and Success is true for code 0. When the limit passes first, timed_out is set and the child keeps running; Poll asks whether it is still running without waiting.

os-process-guide-status.salam
import os.process

func describe(script: str):
    mut cmd := process.NewCommand("sh")
    cmd.Arg("-c")
    cmd.Arg(script)
    mut child := process.Launch(cmd)
    st := child.Wait(2000)
    if st.exited:
        println "exited with code", st.code
    else st.signaled:
        println "killed by signal", st.signal
    end
    child.Close()
    cmd.Free()
end

func main:
    describe("exit 3")
    describe("kill -TERM $$")
    describe("kill -KILL $$")
end
Outputexited with code 3 killed by signal 15 killed by signal 9

Run with a timeout

RunTimeout is the one-call version: it writes the input text, collects the whole output and error output, and kills the child when the time runs out. It reads both pipes while it writes, so a child that prints a megabyte on each stream cannot deadlock it. RunCommand does the same for a Command with an environment or folder. The result is a RunResult: started, status, stdout, stderr and timed_out; call Free on it.

os-process-guide-timeout.salam
import os.process

func main:
    mut args := Vector {} as Vector<str>
    defer args.free()
    args.push("-c")
    args.push("cat; echo done")
    mut ok := process.RunTimeout("sh", args, "from stdin\n", 2000)
    print ok.stdout
    println "timed out:", ok.timed_out
    ok.Free()

    mut hang_args := Vector {} as Vector<str>
    defer hang_args.free()
    hang_args.push("-c")
    hang_args.push("sleep 30")
    mut hang := process.RunTimeout("sh", hang_args, "", 200)
    println "timed out:", hang.timed_out, "return code:", hang.status.ReturnCode()
    hang.Free()
end
Outputfrom stdin done timed out: false timed out: true return code: -9

Stop a child and everything it started

Kill a shell and the programs it started keep running. Start the child with new_group and KillGroup (or SignalGroup with any signal) stops the whole group. RunTimeout does this for you. Signal, Kill and Terminate reach only the child itself.

os-process-guide-group.salam
import os.process

func main:
    mut cmd := process.NewCommand("sh")
    cmd.Arg("-c")
    cmd.Arg("sleep 30 & sleep 30 & wait")
    cmd.new_group = true
    cmd.stdout_mode = process.Pipe
    mut child := process.Launch(cmd)
    println "group killed:", child.KillGroup()
    st := child.Wait(2000)
    println "signal:", st.signal
    tail := child.ReadAvailable(2000)
    println "pipe closed:", tail.eof
    tail.Free()
    child.Close()
    cmd.Free()
end
Outputgroup killed: true signal: 9 pipe closed: true

On Unix a program that cannot be found, or a folder that cannot be entered, makes Launch return a child whose ok is false and whose error says why; the check happens before Launch returns, so there is no need to wait for an exit code 127.

On Windows Launch uses CreateProcessW and anonymous pipes. Every signal ends the child at once and is reported as a signal, RunCommand writes all of its input before it starts reading, and the pseudo terminal of os.pty is not available. The tests that start real children run on Linux and macOS.

NameTypeDescription

argsVectorThe arguments, not including the program name. Each reaches the child as one argument.

envHashMapVariables to add to the child's environment, replacing any with the same name.
unset_envVectorNames of variables to remove from the child's environment.

os-process-Command.salam
import os.process

func main:
    mut cmd := process.NewCommand("sh")
    cmd.Arg("-c")
    cmd.Arg("echo $GREETING from $(pwd); echo trouble 1>&2")
    cmd.Env("GREETING", "salam")
    cmd.cwd = "/"
    cmd.stdout_mode = process.Pipe
    cmd.stderr_mode = process.Merge
    mut child := process.Launch(cmd)
    all := child.ReadFor(2000)
    print all.data
    all.Free()
    println "exit:", child.Wait(2000).code
    child.Close()
    cmd.Free()
end
Outputsalam from / trouble exit: 0

Success

func Success(): bool
True when the child exited with code 0.
os-process-Read.salam
import os.process

func main:
    mut cmd := process.NewCommand("sh")
    cmd.Arg("-c")
    cmd.Arg("printf 'abcdef'; sleep 0.2; printf 'ghi:tail\\n'")
    cmd.stdout_mode = process.Pipe
    mut child := process.Launch(cmd)
    first := child.Read(4, 2000)
    println "four bytes:", first.data
    upto := child.ReadUntil(":", 2000)
    println "up to the colon:", upto.data
    rest := child.ReadLine(2000)
    println "rest of the line:", rest.data
    end_of := child.ReadAvailable(2000)
    println "ended:", end_of.eof
    first.Free()
    upto.Free()
    rest.Free()
    end_of.Free()
    status := child.Wait(2000)
    println "success:", status.Success()
    child.Close()
    cmd.Free()
end

import os.process

func main:

    defer args.free()

    code := process.Wait(p)
    println code, process.ExitCode(p), process.IsRunning(p)
