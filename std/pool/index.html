pool

Running one loop in parallel across several processor cores.

import pool
On this page
  1. One turn per row
  2. Chunks, not single items
  3. Combine results with an atomic counter
  4. Rules for the loop body
  5. Functions

If each turn of a loop is independent of the others, such as processing each slot of an array on its own, ParallelFor spreads the turns across several worker threads and waits for all of them. The loop body is a function taking an i64, the turn's number.

Despite the name there is no pool that lives on: each call to ParallelFor starts its worker threads, hands out the turn numbers one at a time to whichever worker is free, and joins every worker before it returns. That makes it the shortest way to use every core for one loop. For work that arrives over time, use your own threads from thread fed by a chan; for shared state, sync and atomic.

The things people get wrong:

  • Relying on the order of the turns, or changing shared data from them without a lock. Each turn writing to its own slot is safe; anything else needs atomic or a mutex.
  • Making the turns too small. Taking the next turn number costs a lock, and every call starts and joins threads, so a turn should do a fair amount of work (see chunks).
  • Calling ParallelFor in a hot loop. Each call pays for creating threads; parallelize the outer loop instead of the inner one.

One turn per row

The natural fit for ParallelFor is data laid out in rows, such as the pixels of an image or the lines of a table. Make each turn handle one row: the turns touch different memory, so they need no lock, and the result is the same whatever order they ran in.

pool-guide-pixels.salam
import pool
import mem
import str

mut pixels := null as int*
width := 8
height := 6

func brighten row(y: i64):
    repeat width in x:
        i := (y as int) * width + x
        mut v := pixels[i] + 60
        if v > 255:
            v = 255
        end
        pixels[i] = v
    end
end

func main:
    pixels = mem.AllocateZeroed(sizeof(int) * ((width * height) as u64)) as int*
    repeat width * height in i:
        pixels[i] = (i * 37) % 256
    end
    pool.ParallelFor(height, 3, (y: i64): brighten row(y) end)
    repeat height in y:
        mut line := ""
        repeat width in x:
            line = line + str.FromInt(pixels[y * width + x]) + " "
        end
        println line.trim()
    end
    mem.Free(pixels as void*)
end
Output60 97 134 171 208 245 255 63 100 137 174 211 248 255 66 103 140 177 214 251 255 69 106 143 180 217 254 255 72 109 146 183 220 255 255 75 112 149 186 223 255 255 78 115 152 189 226 255

The loop body here is a short lambda that calls a named function. Keeping the real work in a named function makes it easy to test on its own, without any threads.

Chunks, not single items

Each turn has a small cost of its own, so a million turns that each add one number spend more time on bookkeeping than on adding. Cut the work into a few large chunks instead, let each turn handle one chunk and write its partial result to its own slot, and combine the slots on the main thread at the end.

pool-guide-chunks.salam
import pool
import mem

mut partial := null as i64*
total numbers := 1000000 as i64
chunks := 8

func add chunk(c: i64):
    size := total numbers / (chunks as i64)
    first := c * size + 1
    mut last := first + size - 1
    if c == chunks as i64 - 1:
        last = total numbers
    end
    mut s := 0 as i64
    mut n := first
    until n <= last:
        s += n
        n += 1
    end
    partial[c] = s
end

func main:
    partial = mem.AllocateZeroed(sizeof(i64) * (chunks as u64)) as i64*
    pool.ParallelForAuto(chunks, (c: i64): add chunk(c) end)
    mut sum := 0 as i64
    repeat chunks in c:
        sum += partial[c]
    end
    println "chunks:", chunks
    println "sum of 1 to", total numbers, "=", sum
    println "check:", sum == total numbers * (total numbers + 1) / 2
    mem.Free(partial as void*)
end
Outputchunks: 8 sum of 1 to 1000000 = 500000500000 check: true

ParallelForAuto picks the number of workers from the processor count. A few chunks per worker is a good size: enough for the work to even out when some chunks are slower, few enough that the overhead stays small.

Combine results with an atomic counter

When the turns produce something that has to be added into one place, such as a count of matches, the simplest safe choice is an atomic.I64. Here every number below 100000 is one turn, and each turn that finds a prime adds one to the shared counter.

pool-guide-primes.salam
import pool
import atomic

mut found := atomic.I64 {}

func is prime(n: i64): bool:
    if n < 2:
        ret false
    end
    mut d := 2 as i64
    until d * d <= n:
        if n % d == 0:
            ret false
        end
        d += 1
    end
    ret true
end

func main:
    found = atomic.NewI64(0)
    pool.ParallelFor(100000, pool.CPUCount(), (n: i64):
        if is prime(n):
            atomic.Add(found, 1)
        end
    end)
    println "primes below 100000:", atomic.Load(found)
    atomic.DestroyI64(found)
end
Outputprimes below 100000: 9592

An atomic add per match is fine when matches are rare compared with the work of each turn. If every turn would update the counter, use partial results per chunk as in the previous section instead.

Rules for the loop body

  • Never rely on the order of the turns. Turn 5 can finish before turn 0.
  • A turn may write to its own slot freely. Anything shared needs a sync.Mutex or an atomic.
  • Do not print from the loop body; the lines come out mixed up. Store the results and print after ParallelFor returns.
  • ParallelFor waits for every turn, so as soon as it returns all results are ready and no join is needed.
  • Small loops are faster without threads. Parallelize only when one run of the loop takes noticeable time.

Functions

CPUCount

func CPUCount(): i64
The number of processor cores that are online, at least one.
pool-ParallelFor.salam
import pool
import mem

mut squares := null as i64*

func main:
    println pool.CPUCount() >= 1
    squares = mem.AllocateZeroed(80 as u64) as i64*
    pool.ParallelFor(10, 4, (i: i64): squares[i] = i * i end)
    mut total := 0 as i64
    repeat 10 in i:
        total += squares[i]
    end
    println total
    pool.ParallelForAuto(10, (i: i64): squares[i] = -i end)
    println squares[9]
    mem.Free(squares as void*)
end
Outputtrue 285 -9

ParallelFor

func ParallelFor(n: i64, workers: i64, body: func(i64))
Runs the body for the numbers zero to n - 1 on workers new threads, at most n of them, and returns when every turn is done. Nothing happens when n is zero or less.

The example for this item is shown with the ones above: pool-ParallelFor.salam

ParallelForAuto

func ParallelForAuto(n: i64, body: func(i64))
Like ParallelFor, with one thread per core from CPUCount.
