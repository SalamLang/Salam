sshd

An SSH server with password and public key login, commands, a shell and SFTP, written in Salam.

import sshd
On this page

  2. Serve files with public keys only
  3. Which function for which job

  5. Constants and variables
  6. Functions

This package is an SSH server written in Salam. Make a configuration, add the users who may log in, call Listen and then Serve, and an ordinary client such as OpenSSH, or the ssh package, can connect, log in with a password or a public key, run a command, open an interactive shell, and move files with SFTP. It needs no OpenSSH on the machine.

The package holds the settings and the lifecycle of the server: what to listen on, who may log in, and what a logged-in user may do. The protocol itself, the key exchange, the encryption and the channels, is done by the same ssh package that the client uses.

What to know before you use it:

  • Set a host key. A client trusts the server by its host key. With host_key_file the server reads an unencrypted OpenSSH ed25519 or RSA private key (made with ssh-keygen -t ed25519 -N "") and keeps the same identity on every start. Without it Listen makes a new random key, so the server has a different identity each time it starts and clients that remember it will warn; that is fine for tests, but a real server needs the file.
  • Public keys are listed in authorized_keys_file, one OpenSSH public key per line. Unlike sshd the list is shared: a key in it can log in as any user in users, so give each service its own server and file. Turn off allow_password when keys are enough.
  • Each user has a name, a password and a home. The home is a directory below root, and it is where that user's SFTP session starts. All users share the same root.
  • Switches for what is allowed: allow_exec for single commands, allow_shell for an interactive shell and allow_sftp for file transfer. allow_shell alone does not stop a user from running commands, because a command is run through /bin/sh -c with the rights of the server process; switch allow_exec off too for a server that only moves files.
  • Each connection is served on its own thread, up to max_connections (64 by default) at once; a connection over the limit is closed right away. A client must finish logging in within login_grace_ms (two minutes by default), or the server closes it, so a client that connects and stays silent does not hold a slot for long. ServeOnce still serves a single connection on the calling thread.
  • Listen is false when host_key_file names a file that is not there or cannot be read as a private key, and it prints why on standard error. The server never starts with some other key in its place.

Users, defaults and a free port

NewConfig listens on all interfaces on port 22 and allows passwords, public keys, commands, a shell and SFTP. AddUser appends a user; when the home is left out it is /. Binding to port 0 on the loopback address lets the system pick a port and Port tells you which, so this program runs without a network and without clashing with a real SSH server.

sshd-users.salam
import sshd

func main:
    mut cfg := sshd.NewConfig()
    println cfg.port, cfg.allow_password, cfg.allow_publickey, cfg.allow_shell
    cfg.host = "127.0.0.1"
    cfg.port = 0
    cfg.root = "/srv/files"
    cfg.allow_shell = false
    cfg.banner = "authorized use only"
    sshd.AddUser(cfg, "alice", "s3cret", "/home/alice")
    sshd.AddUser(cfg, "bob", "hunter2")
    each u in cfg.users:
        println u.name, u.home
    end
    mut srv := sshd.New(cfg)
    println sshd.Listen(srv)
    println sshd.Port(srv) > 0
    sshd.Close(srv)
    println sshd.DefaultVersion
end
Output22 true true true alice /home/alice bob / true true SSH-2.0-SalamServer_1.0

Listen returns false when the port cannot be bound, and Close frees it again. The banner is shown to a client before it logs in.

Serve files with public keys only

A server that exists to receive deployments should not accept passwords and should not hand out a shell. The example reads its identity from a host key file, lets in only the keys listed in authorized_keys_file, and does not give out a shell. Commands stay allowed there; switch allow_exec off as well for a server that only moves files.

sshd-serve.salam
import sshd

func main:
    mut cfg := sshd.NewConfig()
    cfg.port = 2222
    cfg.root = "/srv/files"
    cfg.host_key_file = "/etc/deploy/host_key"
    cfg.authorized_keys_file = "/etc/deploy/authorized_keys"
    cfg.allow_password = false
    cfg.allow_shell = false
    sshd.AddUser(cfg, "deploy", "", "/")
    mut srv := sshd.New(cfg)
    if not sshd.Listen(srv):
        println "cannot listen on port", cfg.port
        ret 1
    end
    println "ssh server on port", sshd.Port(srv)
    sshd.Serve(srv)
    ret 0
end

This runs until it is stopped, so it is only checked here. Connect to it with ssh -p 2222 deploy@host or with ssh.Connect and a key.

import sshd

func main:
    mut cfg := sshd.NewConfig()
    cfg.host = "127.0.0.1"
    cfg.port = 0
    mut srv := sshd.New(cfg)
    println srv.running
    println sshd.Listen(srv), srv.running
    println sshd.Port(srv) > 0
    sshd.Close(srv)

ServeOnce

func ServeOnce(srv &: Server): bool
Waits for one connection and serves it until the client leaves; false when the port is not open or the accept failed.
sshd-Serve.salam
import sshd
import env

func main:
    mut cfg := sshd.NewConfig()
    cfg.port = 2222
    cfg.root = "/srv/files"
    cfg.host = "127.0.0.1"
    cfg.allow_shell = false
    cfg.allow_exec = false
    sshd.AddUser(cfg, "alice", env.Get("SSH_PASSWORD"))
    mut srv := sshd.New(cfg)
    if not sshd.Listen(srv):
        ret 1
    end
    handled := sshd.ServeOnce(srv)
    println "one connection served:", handled
    sshd.Serve(srv)
    sshd.Close(srv)
    ret 0
end

Serves each connection on its own thread, at most max_connections at once, until running becomes false or the listener fails, then waits for the open sessions to end.
