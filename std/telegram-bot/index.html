telegram/bot

Building a bot with the Bot API: messages, buttons, webhooks and a polling loop.

import telegram.bot
On this page

  6. Constants and variables
  7. Functions

This is an official package that does not ship with Salam. Add it to a project first: salam add telegram.bot

To build a bot, get a token from BotFather and make one with NewBot. A bot has two ways of taking messages: Poll, which asks Telegram itself and suits testing and simple servers, or a webhook, where Telegram POSTs the messages to your server.

With a webhook you can send the answer straight in the body of the HTTP response; the Reply... functions build that JSON text. Set a secret with SetWebhookSecret and check its header on every request.

Things that catch people out:

  • Every API call is an HTTP GET with the parameters in the URL. Media therefore go by file_id or by a public URL that Telegram downloads; a file on your disk cannot be uploaded with this package. The URL also contains the token, so do not log request URLs.
  • Poll never returns, and it runs your function for one update at a time. A slow handler delays every chat. When getUpdates fails it writes the reason to standard error and tries again a second later.
  • An answer sent in the webhook response is fire and forget: you do not learn whether it worked or get the new message id. When you need either, call the matching Send... function instead.

Answering commands

Keep the logic of a bot in a function that takes an Update and returns the answer. Then the same function serves a webhook, which sends the answer back in the HTTP response, and a test like this one, which feeds it updates written by hand and needs no network and no token. IsCommand, CommandName and CommandArgs split /add 2 3 into its parts, and CommandName drops the @my_bot suffix Telegram adds in groups.

telegram-bot-guide-router.salam
import telegram.bot
import str

func answer(update: bot.Update): str:
    if not update.has_message:
        ret ""
    end
    m := update.message
    if not bot.IsCommand(m.text):
        ret bot.ReplyMessage(m.chat.id, "You said: " + m.text)
    end
    switch bot.CommandName(m.text):
        "start":
            ret bot.ReplyMessage(m.chat.id, "Hello " + m.from_user.first_name + "! Try /add 2 3")
        end
        "add":
            parts := str.Split(bot.CommandArgs(m.text), " ")
            if parts.len() != 2:
                ret bot.ReplyMessage(m.chat.id, "usage: /add A B")
            end
            sum := str.ToInt(parts.get(0)) + str.ToInt(parts.get(1))
            ret bot.ReplyMessage(m.chat.id, str.FromInt(sum))
        end
    end
    ret bot.ReplyMessage(m.chat.id, "I do not know that command")
end

func main:
    inbox := [`{"update_id":1,"message":{"message_id":1,"text":"/start","chat":{"id":42,"type":"private"},"from":{"id":42,"first_name":"Sara"}}}`,
        `{"update_id":2,"message":{"message_id":2,"text":"/add 2 3","chat":{"id":42,"type":"private"}}}`,
        `{"update_id":3,"message":{"message_id":3,"text":"/add 2","chat":{"id":42,"type":"private"}}}`,
        `{"update_id":4,"message":{"message_id":4,"text":"/weather@my_bot","chat":{"id":42,"type":"private"}}}`,
        `{"update_id":5,"message":{"message_id":5,"text":"good morning","chat":{"id":42,"type":"private"}}}`]
    each raw in inbox:
        println answer(bot.ParseUpdate(raw))
    end
end
Output{"method": "sendMessage", "chat_id": 42, "text": "Hello Sara! Try /add 2 3"} {"method": "sendMessage", "chat_id": 42, "text": "5"} {"method": "sendMessage", "chat_id": 42, "text": "usage: /add A B"} {"method": "sendMessage", "chat_id": 42, "text": "I do not know that command"} {"method": "sendMessage", "chat_id": 42, "text": "You said: good morning"}

The switch has no else, so a command it does not list falls out of it to the line after, which answers that the command is unknown. Always give some answer: a bot that stays silent looks broken to the user.

Inline buttons

An inline keyboard is a list of rows, and each row a list of buttons. InlineButton carries a callback_data string of up to 64 bytes that comes back when the user taps it; InlineButtonURL opens a link instead. A tap arrives as an update with has_callback_query set. Answer it with ReplyAnswerCallbackQuery, or the button keeps showing a spinner, and usually edit the original message so the chat shows what was chosen.

telegram-bot-guide-menu.salam
import telegram.bot

func menu(): str:
    mut first := Vector {} as Vector<str>
    first.push(bot.InlineButton("Tea", "order:tea"))
    first.push(bot.InlineButton("Coffee", "order:coffee"))
    mut second := Vector {} as Vector<str>
    second.push(bot.InlineButtonURL("Opening hours", "https://example.com/hours"))
    mut rows := Vector {} as Vector<str>
    rows.push(bot.Row(first))
    rows.push(bot.Row(second))
    ret bot.InlineKeyboardMarkup(rows)
end

func main:
    mut opts := bot.SendOptions {}
    opts.reply_markup = menu()
    println bot.ReplyMessageOptions(42, "What would you like?", opts)

    click := bot.ParseUpdate(`{"update_id":7,"callback_query":{"id":"cq7","data":"order:tea","from":{"id":42,"first_name":"Sara"},"message":{"message_id":31,"chat":{"id":42,"type":"private"}}}}`)
    if click.has_callback_query:
        q := click.callback_query
        println bot.ReplyAnswerCallbackQuery(q.id, "Got it", false)
        if q.has_message:
            println bot.ReplyEditMessageText(q.message.chat.id, q.message.message_id, "One tea for " + q.from_user.first_name, "")
        end
    end
end
Output{"method": "sendMessage", "chat_id": 42, "text": "What would you like?", "reply_markup": {"inline_keyboard": [[{"text": "Tea", "callback_data": "order:tea"}, {"text": "Coffee", "callback_data": "order:coffee"}], [{"text": "Opening hours", "url": "https://example.com/hours"}]]}} {"method": "answerCallbackQuery", "callback_query_id": "cq7", "text": "Got it"} {"method": "editMessageText", "chat_id": 42, "message_id": 31, "text": "One tea for Sara"}

Give callback_data a small format of your own, such as order:tea, and split it with str when it arrives. Never trust it: anyone can send any data to your bot, so check that the order exists before acting on it.

A bot that runs with long polling

Polling needs no public address, so it is the easiest way to run a bot from your own computer. Poll asks Telegram for new updates, waits up to the given number of seconds when there are none, calls your function for each one and remembers the offset, so every update is handled once. A bot can use either polling or a webhook, not both, which is why the program removes any webhook first. SetMyCommands fills the command menu Telegram shows next to the text box.

telegram-bot-guide-poll.salam
import telegram.bot
import env

func main:
    token := env.Get("TELEGRAM_TOKEN")
    if token.len() == 0:
        println "set TELEGRAM_TOKEN to the token BotFather gave you"
        ret 1
    end
    robot := bot.NewBot(token)
    me := bot.GetMe(robot)
    if not bot.Ok(me):
        println "the token was refused:", me.error_code, me.description, me.http_err
        ret 1
    end
    _ := bot.DeleteWebhook(robot)
    mut commands := Vector {} as Vector<str>
    commands.push(bot.BotCommand("start", "say hello"))
    commands.push(bot.BotCommand("echo", "repeat your text"))
    _ := bot.SetMyCommands(robot, commands)
    println "polling, press Ctrl+C to stop"
    bot.Poll(robot, 30, (update: bot.Update):
        if not update.has_message:
            ret
        end
        m := update.message
        _ := bot.SendChatAction(robot, m.chat.id, "typing")
        if bot.CommandName(m.text) == "echo":
            _ := bot.SendMessage(robot, m.chat.id, bot.CommandArgs(m.text))
        else:
            _ := bot.SendMessage(robot, m.chat.id, "Hello " + m.from_user.first_name + ", send /echo something")
        end
    end)
end

Run it with the token from BotFather in the environment:

TELEGRAM_TOKEN=123456:ABC... salam run telegram-bot-guide-poll.salam

Every Send... call returns an ApiResponse. Check it with Ok: when it fails, error_code and description hold Telegram's reason (429 means you are sending too fast) and http_err is set when Telegram could not be reached at all.

A webhook server

In production a webhook is the usual choice: Telegram sends each update to your HTTPS address as soon as it arrives, so nothing has to poll. SetWebhookSecret registers the address and a secret, and Telegram then puts that secret in the X-Telegram-Bot-Api-Secret-Token header (the constant SECRET_HEADER) of every request. Anything without it did not come from Telegram and gets a 401.

telegram-bot-guide-webhook.salam
import telegram.bot
import net.http
import net.router
import env

mut secret := ""

func hook(ctx: i64):
    if http.Header(ctx, bot.SECRET_HEADER) != secret:
        http.SetStatus(ctx, 401)
        http.Text(ctx, "")
        ret
    end
    update := bot.ParseUpdate(http.Body(ctx))
    if not update.has_message:
        http.Text(ctx, "")
        ret
    end
    m := update.message
    http.SetHeader(ctx, "Content-Type", "application/json")
    http.Text(ctx, bot.ReplyMessage(m.chat.id, "Got it: " + m.text))
end

func main:
    token := env.Get("TELEGRAM_TOKEN")
    public_url := env.Get("PUBLIC_URL")
    secret = env.Get("WEBHOOK_SECRET")
    if token.len() == 0 or public_url.len() == 0 or secret.len() == 0:
        println "set TELEGRAM_TOKEN, PUBLIC_URL and WEBHOOK_SECRET"
        ret 1
    end
    robot := bot.NewBot(token)
    set := bot.SetWebhookSecret(robot, public_url + "/telegram", secret)
    if not bot.Ok(set):
        println "setWebhook failed:", set.error_code, set.description
        ret 1
    end
    mut r := router.NewRouter()
    router.Post(r, "/telegram", hook)
    mut s := http.NewServer(8443)
    http.Use(s, r)
    println "webhook on port 8443"
    http.Run(s)
end

The answer goes back in the response body: ReplyMessage builds the JSON for a sendMessage call, and Telegram runs it. Reply with an empty body when there is nothing to say, and answer quickly, because Telegram waits for the response before it sends the next update for that chat. Telegram only calls HTTPS addresses on ports 443, 80, 88 or 8443, so run the program behind a proxy with a certificate, or behind a tunnel while you develop. SetWebhookSecret also drops updates that were waiting, so a restart does not replay old messages.

SECRET_HEADER

const SECRET_HEADER: str = "X-Telegram-Bot-Api-Secret-Token"
The name of the header the webhook secret arrives in.
telegram-bot-Webhook.salam
import telegram.bot
import net.http
import net.router

func webhook(ctx: i64):
    if http.Header(ctx, bot.SECRET_HEADER) != "my-secret":
        http.SetStatus(ctx, 403)
        http.Text(ctx, "forbidden")
        ret
    end
    update := bot.ParseUpdate(http.Body(ctx))
    if update.has_message and bot.IsCommand(update.message.text):
        answer := "the command " + bot.CommandName(update.message.text) + " arrived"
        http.Json(ctx, bot.ReplyMessage(update.message.chat.id, answer))
    else update.has_callback_query:
        http.Json(ctx, bot.ReplyAnswerCallbackQuery(update.callback_query.id, "all right", true))
    else:
        http.Text(ctx, "ok")
    end
end

func main:
    mut r := router.NewRouter()
    router.Post(r, "/hook", webhook)
    mut s := http.NewServer(19632)
    http.Use(s, r)
    _ := http.RunBackground(s)

    mut headers := http.NewHeaders()
    headers.insert(bot.SECRET_HEADER, "my-secret")
    headers.insert("Content-Type", "application/json")
    a := http.PostWith("http://127.0.0.1:19632/hook", `{"update_id":1,"message":{"message_id":2,"text":"/start","chat":{"id":42,"type":"private"}}}`, headers)
    println http.Status(a), http.Body(a)
    b := http.PostWith("http://127.0.0.1:19632/hook", `{"update_id":2,"callback_query":{"id":"cq9","data":"x","from":{"id":42}}}`, headers)
    println http.Body(b)
    c := http.Post("http://127.0.0.1:19632/hook", "{}")
    println http.Status(c)
