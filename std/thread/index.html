thread

Holding and waiting for the threads that spawn creates.

import thread
On this page

  2. Do something else while a thread works
  3. Deep recursion on a bigger stack
  4. Pitfalls, and which tool to use
  5. Types
  6. Functions

In Salam you start a function that should run alongside the rest of the program with spawn. It takes a function with no parameters and no result and gives back a number, the thread's handle. join, or thread.Join, waits for that thread to finish.

The thread package wraps that handle in a Thread so you can keep several of them in a vector and wait for all of them at once, and SpawnStack starts a thread with a stack of the size you choose. Threads share the program's globals and heap; for shared data use sync or atomic, to pass values between threads chan, and to spread a loop over every core pool. A thread cannot be stopped from outside; to ask one to finish early, use ctx or an atomic flag it checks.

Split one job across threads

The most common use of threads is to cut a big job into parts and give each part its own thread. Give each thread its own piece of memory to write its answer into, start them all, then wait for all of them with JoinAll. Because no two threads write to the same place, there is nothing to lock. spawn also takes a second argument, a pointer the function receives as its parameter; that is how each thread learns which part is its own.

thread-guide-split.salam
import thread
import mem

struct Part:
    pub first: i64 = 0
    pub last: i64 = 0
    pub sum: i64 = 0
end

func add range(p: Part*):
    mut total := 0 as i64
    mut i := p[0].first
    until i <= p[0].last:
        total += i
        i++
    end
    p[0].sum = total
end

func new part(first: i64, last: i64): Part*:
    p := mem.Allocate(sizeof(Part)) as Part*
    p[0] = Part { first = first, last = last }
    ret p
end

func main:
    size := 250 as i64
    mut parts := Vector {} as Vector<Part*>
    defer parts.Free()
    mut group := Vector {} as Vector<thread.Thread>
    defer group.Free()
    repeat 4 in w:
        p := new part((w as i64) * size + 1, (w as i64 + 1) * size)
        parts.Push(p)
        group = thread.Collect(group, spawn(add range, p))
    end
    thread.JoinAll(group)
    mut total := 0 as i64
    each p in parts:
        println p[0].first, "to", p[0].last, "=", p[0].sum
        total += p[0].sum
        mem.Free(p as void*)
    end
    println "total:", total
end
Output1 to 250 = 31375 251 to 500 = 93875 501 to 750 = 156375 751 to 1000 = 218875 total: 500500

The parts may finish in any order, but the program reads the answers only after JoinAll and in the order it stored them, so the output is always the same.

Do something else while a thread works

A thread does not have to be part of a group. Start one slow task in the background, carry on with other work on the main thread, and call Join at the point where you need the result. Until Join returns, do not read what the thread is writing.

thread-guide-background.salam
import thread

mut words := 0
mut lines := 0

func count text():
    text := "the quick brown fox\njumps over\nthe lazy dog"
    mut reading := false
    lines = 1
    repeat text.Len() in i:
        c := text[i]
        if c == '\n':
            lines++
        end
        if c == ' ' or c == '\n':
            reading = false
        else not reading:
            reading = true
            words++
        end
    end
end

func main:
    worker := thread.New(spawn(count text))
    println "main thread: loading settings"
    println "main thread: opening the report"
    thread.Join(worker)
    println "lines:", lines, "words:", words
end
Outputmain thread: loading settings main thread: opening the report lines: 3 words: 9

Here only the main thread prints. If both threads printed, the lines could come out in a different order on every run.

Deep recursion on a bigger stack

A thread from spawn gets the system's default stack, which deep recursion can overflow. SpawnStack starts the function on a stack of the size you ask for. The system may refuse a very large stack, so check the thread with Valid and have a plan for the case where it is not.

thread-guide-fallback.salam
import thread

mut depth := 0 as i64

func walk(n: i64): i64:
    if n == 0:
        ret 0
    end
    ret 1 + walk(n - 1)
end

func deep work(_arg: void*):
    depth = walk(300000)
end

func main:
    t := thread.SpawnStack(deep work, null, (128 * 1024 * 1024) as u64)
    if thread.Valid(t):
        thread.Join(t)
    else:
        println "no big stack, running on this thread"
        deep work(null)
    end
    println "depth reached:", depth
end
Outputdepth reached: 300000

The function given to SpawnStack takes a void*, so the same function can also be called directly with null when no thread could be started.

Pitfalls, and which tool to use

  • Join every thread you start. A program that returns from main while threads are still running cuts them off midway.
  • Globals are shared by every thread. Two threads that change the same variable without a lock give a different answer from run to run.
  • Output from several threads interleaves in no fixed order. Collect results and print them from one thread.
  • A handle of zero means the thread did not start. Join on it does nothing, so check Valid when it matters.
  • Join each thread exactly once. On Linux and macOS Join also frees the handle, so a second Join of the same thread uses freed memory and can crash.
  • Collect returns the vector it was given, grown by one; always assign the result back, as in group = thread.Collect(group, spawn(work)).

thread-Join.salam
import thread
import sync

mut total := 0
mut lock := sync.Mutex {}

func worker():
    repeat 1000:
        sync.Lock(lock)
        total++
        sync.Unlock(lock)
    end
end

func main:
    lock = sync.NewMutex()
    first := thread.New(spawn(worker))
    println thread.Valid(first), thread.Handle(first) != 0
    mut group := Vector {} as Vector<thread.Thread>
    defer group.Free()
    repeat 3:
        group = thread.Collect(group, spawn(worker))
    end
    thread.Join(first)
    thread.JoinAll(group)
    println group.Len(), total
    empty := thread.New(0)
    println thread.Valid(empty), empty.handle
    thread.Join(empty)
    sync.Destroy(lock)
end
Outputtrue true 3 4000 false 0

SpawnStack

func SpawnStack(fn: i64, arg: void*, stack: u64): Thread
Starts a function on a new thread with a stack of the size you give, in bytes, for work that needs more than the default, such as deep recursion. The function takes a void* and returns nothing. If the system cannot give that stack it returns an invalid handle, so check with Valid.
thread-SpawnStack.salam
import thread

mut total := 0 as i64

func count(n: i64): i64:
    if n <= 0:
        ret 0
    end
    ret 1 + count(n - 1)
end

func work(_arg: void*):
    total = count(200000)
end

func main:
    stack := (64 * 1024 * 1024) as u64
    t := thread.SpawnStack(work, null, stack)
    println thread.Valid(t)
    thread.Join(t)
    println total
end
Outputtrue 200000

SetLimit

func SetLimit(n: i64)
Sets the most threads that can be alive at once; spawn returns zero when the limit is reached. Zero means no limit. A thread counts as alive until it is joined.
thread-Limit.salam
import mem
import thread

mut stop := null as i64*

func hold():
    until atomic_load(stop) != 0:
        continue
    end
end

func main:
    stop = mem.AllocateZeroed(8 as u64) as i64*
    atomic_store(stop, 1 as i64)
    thread.SetLimit(2 as i64)
    a := spawn(hold)
    b := spawn(hold)
    c := spawn(hold)
    println "live: ", thread.Live()
    println "third refused: ", c == 0
    atomic_store(stop, 0 as i64)
    join(a)
    join(b)
    join(c)
    println "after join: ", thread.Live()
    d := spawn(hold)
    println "slot free again: ", d != 0
    join(d)
    thread.SetLimit(0 as i64)
    mem.Free(stop as void*)
end
Outputlive: 2 third refused: true after join: 0 slot free again: true
