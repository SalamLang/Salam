tui

Full-screen terminal programs: widgets, layout, focus, keys, mouse and resizing, drawn into a buffer and repainted only where something changed.

tui builds full-screen terminal programs: file managers, dashboards, installers, editors, anything that takes over the window instead of printing lines. It is retained mode: you build a tree of long-lived widgets once, change their state when something happens, and the Screen turns key presses, clicks and resizes into events, and widget drawings into frames. It repaints only the cells that changed, so a large screen stays fast over a slow connection. It sits on top of term and uses os.signal to learn about window resizes.

The library started as basalam by Parsa and is now part of the standard library.

The pieces:

  • Screen owns the terminal, the widget tree, the focus and the event loop. NewTerminalScreen sizes it to the terminal; NewScreen gives a fixed size and never touches the terminal, which is how you test.
  • Widgets are structs that embed BaseWidget and override what they need: render to draw, handle_event to react, focusable to take keys. Ready-made ones: Text, Input, Button, Checkbox, List, Progress, Separator, Table, TableView, Panel and Modal.
  • Layout containers (Row, Column, Grid, Stack) give their children positions, so you never compute coordinates by hand.
  • Events go first to the focused widget and bubble up to its parents until one consumes them; whatever nobody consumes reaches the optional Keymap and then your loop.

A complete program

A widget, a screen, and the event loop. start switches the terminal to raw mode and the alternate screen; the defer screen.close() right after it puts the terminal back on every exit path, so a crash never leaves the user's shell broken. next_event waits for the next key, click, tick or resize; dispatch hands it to the widgets; present draws what changed. A key the widgets did not consume is yours: here q quits. This program needs a real terminal, so the page only compiles it.

tui-guide-hello.salam
import term
import tui

struct Hello:
    pub use tui.BaseWidget
    pub presses: int = 0

    pub func render(buf: tui.Buffer, bounds: tui.Rect):
        buf.put_str(bounds.x + 2, bounds.y + 1, "Hello from tui!", tui.Style { bold = true, fg = tui.Cyan })
        buf.put_str(bounds.x + 2, bounds.y + 3, "Enter pressed " + this.presses + " times", tui.StyleDefault)
        buf.put_str(bounds.x + 2, bounds.bottom() - 1, "q quits", tui.Style { dim = true })
    end

    pub func handle_event(event: tui.Event): bool:
        if event.is_key(term.KeyEnter):
            this.presses++
            ret true
        end
        ret false
    end
end

func main:
    if not term.IsTerminal():
        printerrln "run me in a terminal"
        ret 1
    end
    mut screen := tui.NewTerminalScreen(Hello {})
    screen.start()
    defer screen.Close()
    screen.present()
    mut ev := tui.Event {}
    until screen.next_event(ev):
        consumed := screen.dispatch(ev)
        if not consumed and (ev.is_char("q") or ev.is_ctrl("c")):
            screen.stop()
        end
        screen.present()
    end
    ret 0
end

See a frame without a terminal

A screen made with NewScreen never touches the terminal. You can still send it events with dispatch (or post and next_event), draw with draw, and read every row back with buffer.row_text. That is how the examples on this page produce their output, and how you write tests for your own screens.

tui-guide-preview.salam
import term
import tui

struct Hello:
    pub use tui.BaseWidget
    pub presses: int = 0

    pub func render(buf: tui.Buffer, bounds: tui.Rect):
        tui.DrawBorder(buf, bounds, tui.BorderStyle.Rounded, tui.StyleDefault, "hello")
        buf.put_str(bounds.x + 2, bounds.y + 1, "Hello from tui!", tui.Style { bold = true })
        buf.put_str(bounds.x + 2, bounds.y + 2, "Enter pressed " + this.presses + " times", tui.StyleDefault)
    end

    pub func handle_event(event: tui.Event): bool:
        if event.is_key(term.KeyEnter):
            this.presses++
            ret true
        end
        ret false
    end
end

func show(s: tui.Screen):
    s.draw()
    repeat s.buffer.height in y:
        println s.buffer.row_text(y)
    end
end

func main:
    mut s := tui.NewScreen(Hello {}, 30, 4)
    defer s.Close()
    show(s)
    enter := tui.Event { kind = tui.KeyEvent, key = term.Key { code = term.KeyEnter } }
    _ := s.dispatch(enter)
    _ := s.dispatch(enter)
    show(s)
end

Lay out a screen

Hand widgets to a container and the container places them. A Column stacks its children; set_height with a LayoutSize chooses each share: Fixed cells, a Fill weight of what is left, or Pref for the widget's own preferred size. Make the container the root of the screen, and add each child to the screen too: the container decides where, the screen decides what is drawn and focused. On a resize the screen gives the root the new size and the layout runs again.

tui-guide-layout.salam
import tui

func fixed(n: int): tui.LayoutSize:
    ret tui.LayoutSize { kind = tui.SizeKind.Fixed, cells = n }
end

func main:
    title := tui.NewText("Downloads") as dyn tui.Widget
    rule := tui.NewSeparator() as dyn tui.Widget
    mut bar := tui.NewProgress()
    bar.set_progress(40)
    progress := bar as dyn tui.Widget
    mut body := tui.NewText("salam-0.6.3.tar.gz is 40% done. The rest of this line wraps inside the column.")
    body.set_wrap(tui.WrapMode.Word)
    text := body as dyn tui.Widget

    mut col := tui.NewColumn()
    col.set_padding(tui.UniformInsets(1))
    i := col.Add(title)
    j := col.Add(rule)
    k := col.Add(progress)
    _ := col.Add(text)
    col.set_height(i, fixed(1))
    col.set_height(j, fixed(1))
    col.set_height(k, fixed(1))

    mut s := tui.NewScreen(col as dyn tui.Widget, 32, 8)
    defer s.Close()
    _ := s.Add(tui.RootId, title)
    _ := s.Add(tui.RootId, rule)
    _ := s.Add(tui.RootId, progress)
    _ := s.Add(tui.RootId, text)
    s.draw()
    repeat s.buffer.height in y:
        println "|" + s.buffer.row_text(y) + "|"
    end
end

A form: focus, typing and callbacks

Focusable widgets take turns receiving keys. The first focusable widget added gets the focus; with NewDefaultKeymap installed, Tab and the arrow keys move it. Values come back through callbacks: on_submit for an Input when Enter is pressed, on_toggle for a Checkbox, on_click for a Button. Callbacks are lambdas and cannot capture local variables, so keep the state they change in globals or in your own widget.

tui-guide-form.salam
import term
import tui

mut name := ""
mut subscribed := false
mut saved := 0

func rect(x: int, y: int, w: int): tui.Rect:
    ret tui.Rect { x = x, y = y, width = w, height = 1 }
end

func key(seq: str): tui.Event:
    ret tui.Event { kind = tui.KeyEvent, key = term.Decode(seq) }
end

func typing(s &: tui.Screen, text: str):
    repeat text.Len() in i:
        _ := s.dispatch(key(text.Substr(i, 1)))
    end
end

func main:
    mut s := tui.NewScreen(tui.BaseWidget {}, 30, 4)
    defer s.Close()
    s.set_keymap(tui.NewDefaultKeymap())

    label := s.Add(tui.RootId, tui.NewText("Name:") as dyn tui.Widget)
    s.widget(label).SetBounds(rect(1, 0, 6))
    mut entry := tui.NewInput()
    entry.set_placeholder("your name")
    entry.on_submit = (value: str):
        name = value
        ret true
    end
    field := s.Add(tui.RootId, entry as dyn tui.Widget)
    s.widget(field).SetBounds(rect(7, 0, 20))
    mut box := tui.NewCheckbox("Send me news", false)
    box.on_toggle = (enabled: bool): subscribed = enabled end
    news := s.Add(tui.RootId, box as dyn tui.Widget)
    s.widget(news).SetBounds(rect(1, 1, 20))
    mut button := tui.NewButton("Save")
    button.on_click = (): saved++ end
    save := s.Add(tui.RootId, button as dyn tui.Widget)
    s.widget(save).SetBounds(rect(1, 2, 10))

    println "focused first:", s.focused_id() == field
    typing(s, "Sara")
    _ := s.dispatch(key("\r"))
    _ := s.dispatch(key("\t"))
    _ := s.dispatch(key(" "))
    _ := s.dispatch(key("\t"))
    _ := s.dispatch(key("\r"))
    println "name:", name, "news:", subscribed, "saved:", saved

    s.draw()
    repeat s.buffer.height in y:
        println "|" + s.buffer.row_text(y) + "|"
    end
end

Lists and tables

List shows one selectable item per row and moves with j and k (the arrow keys stay free for focus moves); Enter calls on_select. TableView is a scrolling table with a selected row; Up and Down move it and Enter calls activate with the data row. Columns take a LayoutSize width, an alignment and what to do with text that does not fit.

tui-guide-lists.salam
import term
import tui

mut opened := -1

func row(a: str, b: str): Vector<str>:
    mut v := Vector {} as Vector<str>
    v.Push(a)
    v.Push(b)
    ret v
end

func column(width: int, align: tui.Alignment): tui.TableColumn:
    ret tui.TableColumn { width = tui.LayoutSize { kind = tui.SizeKind.Fixed, cells = width }, align = align }
end

func down(): tui.Event:
    ret tui.Event { kind = tui.KeyEvent, key = term.Key { code = term.KeyDown } }
end

func main:
    mut s := tui.NewScreen(tui.BaseWidget {}, 34, 6)
    defer s.Close()

    mut files := Vector {} as Vector<str>
    files.Push("main.salam")
    files.Push("util.salam")
    files.Push("README.md")
    list := s.Add(tui.RootId, tui.NewList(files) as dyn tui.Widget)
    s.widget(list).SetBounds(tui.Rect { x = 0, y = 0, width = 12, height = 3 })

    mut t := tui.NewTableView()
    _ := t.add_column(column(8, tui.Alignment.Left))
    _ := t.add_column(column(7, tui.Alignment.Right))
    t.header = true
    _ := t.add_row(row("Name", "Lines"))
    _ := t.add_row(row("tui", "8956"))
    _ := t.add_row(row("signal", "976"))
    _ := t.add_row(row("term", "1944"))
    t.activate = (index: int):
        opened = index
        ret true
    end
    table := s.Add(tui.RootId, t as dyn tui.Widget)
    s.widget(table).SetBounds(tui.Rect { x = 13, y = 0, width = 20, height = 5 })

    _ := s.focus(list)
    _ := s.dispatch(tui.Event { kind = tui.KeyEvent, key = term.Decode("j") })
    _ := s.focus(table)
    _ := s.dispatch(down())
    _ := s.dispatch(tui.Event { kind = tui.KeyEvent, key = term.Key { code = term.KeyEnter } })
    names := ["tui", "signal", "term"]
    println "opened:", names[opened]
    s.draw()
    repeat s.buffer.height in y:
        println "|" + s.buffer.row_text(y) + "|"
    end
end

What to keep in mind:

  • Always defer screen.close() on the line after start().
  • A child given to a container or a Panel must also be added to the screen, or it is placed but never drawn.
  • A dyn Widget cannot be turned back into its struct, so read values through callbacks or keep them in your own state.
  • Draw only inside render; change state in handle_event or in your loop, then the next present shows it. After changing state the widgets cannot see, set screen.dirty = true.
  • Glyphs fall back to ASCII on terminals without UTF-8; set SALAM_TUI_GLYPHS to ascii or unicode to choose. Colors follow NO_COLOR, COLORTERM and TERM.
  • On Windows resizes are noticed by polling the size about every 20 milliseconds instead of by a signal.

Widget

interface Widget
The interface every widget satisfies. Store widgets as dyn Widget.
tui-widget.salam
import term
import tui

struct Counter:
    pub use tui.BaseWidget
    pub count: int = 0

    pub func focusable(): bool:
        ret true
    end

    pub func handle_event(event: tui.Event): bool:
        if event.is_char("+"):
            this.count++
            ret true
        end
        ret false
    end

    pub func render(buf: tui.Buffer, bounds: tui.Rect):
        mut style := tui.StyleDefault
        if buf.focused:
            style = tui.Style { reverse = true }
        end
        buf.put_str(bounds.x, bounds.y, "count " + this.count, style)
    end
end

func main:
    base := tui.BaseWidget {}
    println "defaults:", base.Focusable(), base.Hits(), base.Visible(), base.PreferredSize(10).width
    m := base.Measure(tui.Axis.X, 10)
    println "measures:", m.ok

    mut tree := tui.NewTree(tui.BaseWidget {} as dyn tui.Widget)
    id := tree.Add(tui.RootId, Counter {} as dyn tui.Widget)
    println "tree:", tree.count(), tree.valid(id), tree.parent(id) == tui.RootId, tree.valid(tui.NoWidget)
    plus := tui.Event { kind = tui.KeyEvent, key = term.Decode("+") }
    println "handled by:", tree.dispatch(id, plus) == id
    w := tree.Get(id)
    w.SetBounds(tui.Rect { width = 10, height = 1 })
    mut buf := tui.NewBuffer(10, 1)
    w.Render(buf, w.Bounds())
    println buf.row_text(0)
    buf.Free()
    tree.Free()
    _ := base.rect
end

Keymap

struct Keymap
A table of key and key-sequence bindings. Build it with NewKeymap, NewDefaultKeymap or NewVimKeymap (or empty with Keymap {}), fill it with bind and its variants, feed events to handle, and release it with free. Never copy a Keymap value.
NameTypeDescription
pending_timeout_msint = 0How long a pending key sequence may wait for its next key, in milliseconds. 0 (the default) never expires a prefix, which is the behavior without a timeout. The timeout is evaluated lazily, on the next KeyEvent only; non-key events never expire a prefix. Set it directly (keymap.pending_timeout_ms = 700); there is no constructor.
pending_since_msint = 0The clock reading, in milliseconds, when the current pending sequence started waiting; it is refreshed on every prefix step and is 0 when nothing is pending. handle maintains it; an application sets pending_timeout_ms instead.
tui-events.salam
import term
import tui

mut quits := 0
mut tops := 0

func main:
    k := tui.Event { kind = tui.KeyEvent, key = term.Decode("q") }
    println "is q:", k.is_char("q"), "is Ctrl+C:", k.is_ctrl("c"), "is Enter:", k.is_key(term.KeyEnter)
    click := tui.Event { kind = tui.MouseEvent, key = term.Key { raw = "\x1b[<0;5;3M" }, mouse = term.DecodeMouse("\x1b[<0;5;3M") }
    p := click.mouse_point()
    println "click at", p.x, p.y
    resize := tui.Event { kind = tui.ResizeEvent, width = 100, height = 30 }
    println "kinds:", tui.NoEvent, tui.KeyEvent, tui.MouseEvent, resize.kind, tui.TickEvent, "size", resize.width, resize.height, "bubbled", resize.bubbled

    mut s := tui.NewScreen(tui.BaseWidget {}, 10, 2)
    defer s.Close()
    mut km := tui.NewKeymap()
    km.bind(term.Decode("q"), (_s: tui.Screen*, _e: tui.Event):
        quits++
        ret true
    end)
    km.bind_seq("gg", (_s: tui.Screen*, _e: tui.Event):
        tops++
        ret true
    end)
    km.bind_for(tui.RootId, term.Decode("x"), (_s: tui.Screen*, _e: tui.Event): ret true end)
    km.bind_for_seq(tui.RootId, "dd", (_s: tui.Screen*, _e: tui.Event): ret true end)
    km.pending_timeout_ms = 1000
    s.set_keymap(km)
    _ := s.dispatch(k)
    _ := s.dispatch(tui.Event { kind = tui.KeyEvent, key = term.Decode("g") })
    println "sequence timeout:", s.keymap.pending_timeout_ms, "ms"
    _ := s.keymap.pending_since_ms
    _ := s.dispatch(tui.Event { kind = tui.KeyEvent, key = term.Decode("g") })
    println "q pressed", quits, "gg pressed", tops
    s.keymap.unbind(term.Decode("q"))
    s.keymap.unbind_for(tui.RootId, term.Decode("x"))
    s.keymap.unbind_for_seq(tui.RootId, "dd")
    s.keymap.cancel_pending()
    println "after unbind:", s.dispatch(k)

    mut arrows := tui.NewDefaultKeymap()
    arrows.Free()
    mut vim := tui.NewVimKeymap((_s: tui.Screen*, _e: tui.Event): ret false end)
    vim.Free()
end

SplitMain

func SplitMain(length: int, sizes: Vector<LayoutSize>, gap: int): Vector<int>
Splits a main-axis length of length cells between sizes, in order (R5). Fixed takes max(0, cells) and ignores weight. gap is the cells between adjacent slots. A negative gap clamps to 0. The budget is gap * max(0, k - 1), where k is the slot count, including zero-size slots; k <= 1 charges nothing. Fill and Pref share the leftover R = max(0, length - sum of those Fixed sizes - budget). Arrange resolves a measured Pref to Fixed before this call, and a Pref that cannot measure to Fill weight 1. This function does not measure; a Pref still in the vector stays in the weight pool. Each pool entry's weight is max(0, weight). The share is floor(R * weight / sum of weights), then one extra cell goes to each remaining cell, given to the pool entries with the largest (R * weight) mod sum of weights. Ties go to the earliest pool slot. A weight sum of 0 gives every pool entry 0 and leaves R unused, with no division. Fixed overflow, or a budget that uses up the length, makes R 0, so every pool entry is 0 and Fixed is not shrunk. The gap is not part of the returned sizes and is not refunded. The vector has one entry per input. Weight 1 on every pool entry is an equal split, remainder to the earliest entries.

The example for this item is shown with the ones above: tui-layout.salam

DrawBorder

func DrawBorder(buf: Buffer, rect: Rect, border: BorderStyle, style: Style, title: str)
Paints a one-cell ring of border around rect into buf, every cell in one foreground color taken from style.fg. Rules: - BorderStyle.None, or a rect with no area, writes nothing. - A one-row rect is a horizontal rule and a one-column rect is a vertical rule; neither has corners or a title. - Otherwise the four corners are drawn, then the horizontal edges, then the vertical edges. Edges run strictly between the corners. - title sits on the top edge starting at rect.x + 2, with one space before and after it. It is trimmed; an empty title draws nothing; it is cut to rect.width - 5 display cells on the right and needs a width of at least 6. - Only foreground color is used. Attributes in style are ignored, and a Color.Default fg writes an empty style (the terminal default). Writes go through Buffer.set, which clips to the grid and the clip region, so a rect partly outside the buffer paints only its inside part.
