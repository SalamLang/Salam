# Program leak budget.
#
# One line per test program:
#
#   <tests/en/stdlib name, without .salam> <max_leaked_allocations>
#
# Enforced by tools/bash/leakcheck-programs.sh, which builds each program
# with `--asan` and reads LeakSanitizer's count of blocks still unreachable
# when it exits. This measures the PROGRAM, not the compiler that built it -
# the compiler has its own ratchet in compiler/tools/selfhost-leak-budget.txt
# and a much larger budget, for the reasons that file explains.
#
# Unlike the compiler's, most of these are 0 and must stay 0. A Salam program
# that owns its memory carefully can reach zero, and the std/ code these
# demos exercise does. Where a line is not 0 the reason is written beside it.
#
# This is a ratchet: the script FAILS when a program leaks more than its
# number and asks you to LOWER the number when it leaks less. The list of
# cases is this file - adding a line is what adds a case.
#
# Measured 2026-08-29 on Linux/x86-64, gcc 13.
#
# archive_demo is the one line above zero, and what is left in it is
# std/archive's RAR reader: the block scanners set a name out-param per
# block and nothing releases it. The zip and tar paths are at zero.
