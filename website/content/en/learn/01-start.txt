<h2 id="hello">Hello, world</h2>
<p>Every Salam program starts at <code>func main</code>, the first thing that runs. A block opens with a colon (<code>:</code>) and closes with <code>end</code>, and indenting the lines inside it keeps the code readable. Text goes between double quotes, and <code>println</code> takes its value without parentheses.</p>
{{example.hello}}

<h2 id="run">Running a program</h2>
<p>Save your code in a file with a <code>.salam</code> extension, say <code>hello.salam</code>. <code>salam run hello.salam</code> compiles it and runs it straight away. If you want a standalone executable instead, use <code>salam build hello.salam</code> and a native binary appears next to your source. You can also run every example here in the <a href="https://editor.salamlang.ir">online editor</a> without installing anything.</p>
<div class="table-wrap"><table>
<thead><tr><th>Command</th><th>What it does</th></tr></thead>
<tbody>
<tr><td><code>salam run hello.salam</code></td><td>Compiles the program, runs it, and keeps nothing afterwards</td></tr>
<tr><td><code>salam build hello.salam</code></td><td>Builds a native executable named <code>hello</code> that runs without Salam installed</td></tr>
<tr><td><code>salam exec hello.salam</code></td><td>Runs the program in the interpreter, with no C compiler involved</td></tr>
<tr><td><code>salam format hello.salam</code></td><td>Rewrites the file in the standard layout; <code>--check</code> only reports</td></tr>
<tr><td><code>salam translate fa hello.salam</code></td><td>Writes a Persian copy, <code>hello.fa.salam</code>; <code>translate en</code> goes the other way</td></tr>
<tr><td><code>salam new shop</code></td><td>Creates a project folder <code>shop</code> with a <code>salam.salam</code> inside; <code>salam run</code> in that folder runs it</td></tr>
<tr><td><code>salam version</code></td><td>Prints the version of the compiler</td></tr>
</tbody></table></div>

<h2 id="print">Printing output</h2>
<p><code>println</code> prints its values and moves to the next line; <code>print</code> stays on the same line. Separate several values with commas and Salam writes them out with one space between them.</p>
{{example.start-print}}
<p>Any value can be printed as it is: whole and decimal numbers, <code>true</code> and <code>false</code>, the result of a calculation, even a whole list. Here is a small receipt:</p>
{{example.start-values}}
<p>Three rules cover nearly every printing mistake:</p>
<ul>
<li>No parentheses around the values: <code>println "hi"</code>, not <code>println("hi")</code>.</li>
<li>A comma between every two values: <code>println "a", "b"</code>. Leaving it out is an error, not a joined string.</li>
<li><code>println</code> always needs a value. For an empty line write <code>println ""</code>.</li>
</ul>
<p>For error messages use <code>printerrln</code> and <code>printerr</code>. They write to standard error, so they stay out of the program's real output and survive being piped elsewhere: with <code>salam run app.salam &gt; out.txt</code>, the normal lines land in the file and the errors still show on screen.</p>
{{example.start-stderr}}

<h2 id="exit">Exit codes</h2>
<p>When a program ends it hands the operating system a number, its exit code. Zero means success and anything else means something went wrong; scripts and build tools read it to decide whether to carry on. Give <code>main</code> the return type <code>int</code> and the value you <code>ret</code> becomes the exit code. A plain <code>func main:</code> that simply reaches its <code>end</code> exits with 0.</p>
{{example.start-exit}}
<p>With 820 MB free the check passes and the program returns 0. Change <code>free_mb</code> to 300 and it prints the message to standard error and exits with 1, which you can see with <code>echo $?</code> right after running it in a Unix shell.</p>

<h2 id="input">Reading input</h2>
<p><code>input</code> reads one line from the user and gives it back as a string. Like <code>print</code> it takes no parentheses, and it always wants a prompt, which it prints before reading. If you do not want one, write <code>input ""</code>. What comes back is always text; when you need a number, convert it with <code>to_int()</code> (or <code>to_float()</code> for decimals):</p>
{{example.start-input}}
<p>If the user types something that is not a number, <code>to_int()</code> gives 0 rather than stopping the program, so check the value before trusting it. This example waits for a person at the keyboard, which is why it shows no output here.</p>

<h2 id="comments">Comments</h2>
<p>Anything after <code>//</code> to the end of the line, and anything between <code>/*</code> and <code>*/</code>, is a comment and is not run.</p>
{{example.start-comments}}
<p>Block comments nest: a <code>/* ... */</code> inside another one is fine, so you can wrap a stretch of code that already contains a block comment to switch it off for a moment.</p>

<h2 id="shape">The shape of a program</h2>
<p>A real program is more than <code>main</code>. A source file is read from the top, in this order: <code>import</code> lines for libraries, then constants, then global variables, then your own types, then functions. Functions can call each other in any order, so <code>main</code> is free to sit at the top and use helpers that are written further down.</p>
{{example.start-shape}}
<p><code>import str</code> brings in the string library, and <code>str.Repeat</code> is one of its functions; the <a href="/learn/packages/">packages lesson</a> covers libraries properly. A constant below a function, or an <code>import</code> below a constant, is a compile error that tells you where to move it.</p>

<h2 id="errors">When the compiler says no</h2>
<p>Salam checks a lot before it runs anything, and it points at the exact line and column with a message that says what to do. These are the ones a beginner meets first:</p>
<div class="table-wrap"><table>
<thead><tr><th>You wrote</th><th>The compiler says</th></tr></thead>
<tbody>
<tr><td><code>println("hi")</code></td><td>print arguments must not be wrapped in parentheses; remove them</td></tr>
<tr><td><code>println</code> on its own</td><td>print needs a value: write 'println ""' for an empty line</td></tr>
<tr><td><code>println "a" "b"</code></td><td>expected ',' between the values to print</td></tr>
<tr><td><code>x := 5</code>, and <code>x</code> is never used</td><td>E059: unused variable 'x'</td></tr>
<tr><td><code>a &amp;&amp; b</code></td><td>'&amp;&amp;' is not a Salam operator; write 'and'</td></tr>
</tbody></table></div>
<p>Read the first message first: one mistake can cause a few more errors below it, and those usually go away once the first is fixed. The <a href="/learn/rules/">compiler rules lesson</a> explains the stricter checks and why they help.</p>
