<h2 id="define">Declaring a variable</h2>
<p><code>:=</code> introduces a new name and gives it a value. The type comes from the value, so you do not have to write it: <code>"Maryam"</code> makes a <code>str</code> and <code>85</code> makes an <code>int</code>. From then on the type is fixed, and putting text into a number variable later is an error. Names can be several words, such as <code>book price</code>.</p>
{{example.variables}}
<p>A variable always starts with a value. There is no way to declare a name now and fill it in later, so you never read a variable that holds leftover garbage.</p>

<h2 id="mutable">Changeable variables</h2>
<p>A variable declared with <code>:=</code> never changes again. If you want to give it a new value later, write <code>mut</code> before the name and then assign with <code>=</code>. The shorthands <code>+=</code>, <code>-=</code> and <code>++</code> are there too.</p>
{{example.var-mut}}
<div class="note"><p>Salam is strict about this: if you declare something <code>mut</code> and never change it, or declare a variable and never use it, the program does not compile. The rule catches dead code and typos.</p></div>

<h2 id="scope">Where a variable lives</h2>
<p>A variable exists from the line that declares it to the <code>end</code> of the block it was declared in. A name made inside an <code>if</code> is gone once the <code>if</code> closes, and using it afterwards is an "unknown identifier" error. Keep a variable in the smallest block that needs it.</p>
{{example.var-scope}}
<p>The second <code>if</code> declares its own <code>label</code>. That is allowed in an inner block, and it hides the outer one until the block ends; the outer <code>label</code> is never touched, as the last line shows. This is called shadowing, and it is easy to misread, so use a new name unless you really mean it. Declaring the same name twice in the same block is an error.</p>

<h2 id="choose">Choosing a value without mut</h2>
<p>A common reason to reach for <code>mut</code> is a value that depends on a condition: declare it empty, then set it in each branch of an <code>if</code>. Most of the time the <a href="/learn/operators/#ternary">ternary operator</a> does the same job in one line and the variable can stay unchangeable:</p>
{{example.var-choose}}
<p>With more than two cases, a <a href="/learn/match/">match</a> expression plays the same role. Fewer <code>mut</code> variables means fewer places where a value can change behind your back.</p>

<h2 id="typed">Choosing the type</h2>
<p>When you want a type other than the default, convert the value with <code>as</code>. A whole number is <code>int</code> (32 bits) by default and a decimal one is <code>f64</code>.</p>
{{example.var-typed}}
<p>Older Salam code wrote the type before the value, as in <code>age: int = 17</code>. That form was removed and is now a parse error that tells you to write <code>age := 17</code>, or <code>age := 17 as i64</code> when the type matters. The <code>name: Type</code> form lives on only for function parameters and struct fields.</p>

<h2 id="global">Global variables</h2>
<p>Outside any function you can declare global variables with <code>mut</code> and constants with <code>const</code>; every function in the program can reach them. Here a global counts how many times a function has been called:</p>
{{example.var-global}}
<p>Globals go near the top of the file: after the <code>import</code> lines and the constants, and before any type or function. Use them sparingly: a value passed in as a parameter is easier to follow than one that any function might change.</p>

<h2 id="const">Constants</h2>
<p><code>const</code> declares a value that is fixed when the program is compiled. A constant can be computed from numbers and from other constants, so you can name the parts of a calculation instead of writing a bare <code>604800</code>. Constants also work inside a function, where they are visible only in that function.</p>
{{example.var-const}}
<p>The name of a constant has to be a single word: <code>MAX VALUE</code> is a parse error, so write <code>MAX_VALUE</code> or <code>MAXVALUE</code>. Global variables and ordinary variables may still have names of several words.</p>
<p>There is a difference between <code>:=</code> and <code>const</code> that matters once a variable holds several values, such as an <a href="/learn/arrays/">array</a>. <code>:=</code> fixes the name: it cannot be pointed at a whole new value, but the elements inside can still be changed. <code>const</code> freezes everything, elements included.</p>
{{example.var-contents}}
<p>Here a wrong reading is corrected in place even though <code>readings</code> is not <code>mut</code>. Writing <code>DAYS[2] = "Fri"</code> instead is an error, because a <code>const</code> is fully immutable.</p>

<h2 id="naming">Naming rules</h2>
<ul>
<li>Names are made of English or Persian letters, digits and <code>_</code>, and may not start with a digit.</li>
<li>Upper and lower case are different: <code>name</code> and <code>Name</code> are two variables.</li>
<li>Keywords, such as <code>if</code>, <code>and</code>, <code>to</code> or <code>in</code>, cannot be used as names, and not as one word of a longer name either: <code>max to go</code> is rejected.</li>
<li>A variable cannot share its name with a function in the same file, so a name always means one thing.</li>
<li>Starting a name with <code>_</code> silences the unused variable error. The compiler advises against it for dead code, since the code stays in the program; keep it for values you really mean to ignore.</li>
</ul>
