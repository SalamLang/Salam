<h2 id="literals">Ways to write a string</h2>
<ul>
<li><code>"..."</code> is an ordinary string. Escapes work inside it: <code>\n</code> (a new line), <code>\t</code> (a tab), <code>\"</code>, <code>\\</code>, and <code>\uHHHH</code> for any Unicode character by its code.</li>
<li><code>`...`</code> (backticks) is a raw string: everything inside stays exactly as written, backslashes and quotes included, and it may span several lines. It is the easy way to write file paths, regular expressions and JSON.</li>
<li><code>"""..."""</code> is a multi-line string in which escapes still work.</li>
</ul>
{{example.str-literals}}
<p>An ordinary <code>"..."</code> string has to end on the line where it starts; for text over several lines use <code>"""</code> or backticks. Persian files have one more form, <code>«...»</code>, which an English file does not accept.</p>

<h2 id="concat">Joining strings</h2>
<p>Join strings with <code>+</code>. When one side is a number or a <code>bool</code>, it is turned into text for you, so no separate conversion is needed. <code>+=</code> adds to the end of a <code>mut</code> string. Salam has no <code>"{name}"</code> style interpolation; <code>+</code> is how text is put together.</p>
{{example.str-concat}}
<p>Look at the second line of output. <code>+</code> works from left to right, so <code>"Total: " + 2</code> is already text by the time <code>3</code> arrives, and the result is <code>Total: 23</code>. Put the arithmetic in parentheses when you want the sum.</p>

<h2 id="chars">Bytes and characters</h2>
<p>A string is stored as UTF-8. An English letter takes one byte, but <code>é</code> takes two, and so does a Persian letter. That is why there are two kinds of length and two kinds of position:</p>
<ul>
<li><code>len()</code>, <code>substr</code> and <code>find</code> count <strong>bytes</strong>. They are fast, and exact for ASCII text.</li>
<li><code>char_count()</code>, <code>char_substr</code>, <code>char_at</code> and <code>char_find</code> count <strong>characters</strong>. Use them whenever the text might not be plain English.</li>
</ul>
{{example.str-chars}}
<p><code>"سلام"</code> is 8 bytes but 4 characters, and the letter <code>م</code> is character 3 but byte 6. The <code>preview</code> function cuts a title to a number of characters, which is what a reader expects. Cutting it with <code>substr</code> could split a letter in half and print a broken symbol. Indexing with <code>word[0]</code> also reads a single byte, as a <code>char</code>, so it is only the right tool for ASCII.</p>

<h2 id="methods">String methods</h2>
<p>These methods are built into every string. None of them changes the string it is called on; they give back a new value.</p>
{{example.str-methods}}
<div class="table-wrap"><table>
<thead><tr><th>Method</th><th>What it does</th></tr></thead>
<tbody>
<tr><td><code>len()</code></td><td>The length of the string in bytes</td></tr>
<tr><td><code>char_count()</code></td><td>The number of characters, which differs from the byte count outside ASCII</td></tr>
<tr><td><code>substr(start, count)</code></td><td>Cut a piece out of the string, counted in bytes</td></tr>
<tr><td><code>char_substr(start, count)</code>, <code>char_at(i)</code></td><td>The same, counted in characters</td></tr>
<tr><td><code>find(text)</code>, <code>char_find(text)</code></td><td>Where some text starts (in bytes or in characters), or <code>-1</code></td></tr>
<tr><td><code>starts_with(text)</code>, <code>ends_with(text)</code>, <code>includes(text)</code></td><td>Test the start, the end, or anywhere in the string</td></tr>
<tr><td><code>split(separator)</code></td><td>Break the string into a <code>Vector&lt;str&gt;</code> of pieces</td></tr>
<tr><td><code>trim()</code></td><td>Remove the spaces at both ends</td></tr>
<tr><td><code>concat(text)</code></td><td>Join text onto the end</td></tr>

<tr><td><code>to_int()</code>, <code>to_float()</code></td><td>Turn text into a number</td></tr>
</tbody></table></div>
<p>A string can never be changed in place: <code>s[0] = 'x'</code> is a compile error. Build a new string instead.</p>

<h2 id="str">The str package</h2>
<p>For more than the built-in methods, import the <a href="/std/str/">str</a> package. It splits and joins, trims prefixes and suffixes, replaces, counts and changes case. The example reads a settings line of the kind you find in a config file or a form.</p>
{{example.str-parse}}
<p><code>Split</code> and <code>Fields</code> return a <code>Vector</code>, which has to be freed, hence the <code>defer ... free()</code> lines. <code>Fields</code> splits on any run of spaces, so it is the one to use on words a person typed.</p>

<h2 id="builder">Building text in pieces</h2>
<p>Every <code>+</code> makes a new string. That is fine for a line or two, but text built up in a loop is better made with a <code>StringBuilder</code>: <code>str.NewBuilder</code> starts one, <code>str.BufAppend</code> adds text, <code>str.BufStr</code> reads out the result and <code>str.BufFree</code> releases it. <code>fmt.PadLeft</code> and <code>fmt.PadRight</code> from the <a href="/std/fmt/">fmt</a> package pad text to a width in characters, which lines up the columns of this receipt.</p>
{{example.str-builder}}

<h2 id="compare">Comparing strings</h2>
<p><code>==</code> and <code>!=</code> compare the contents of two strings, and <code>&lt;</code> and <code>&gt;</code> put them in order. <code>str.Compare</code> gives <code>-1</code>, <code>0</code> or <code>1</code>, the shape a sort function wants. <code>str.EqualFold</code> compares without caring about upper and lower case, which is what you want for user names and email addresses.</p>
{{example.str-compare}}
<p>The order is the order of the character codes, not dictionary order. Every capital letter comes before every small one, so <code>"Zebra" &lt; "apple"</code> is true. Persian has the same catch: the letters <code>پ چ ژ گ</code> have higher codes than the rest of the alphabet, so <code>"گل" &lt; "لاله"</code> is false even though <code>گ</code> comes before <code>ل</code> in Persian.</p>

<h2 id="numbers">Text and numbers</h2>
<p><code>to_int()</code> and <code>to_float()</code> read a number from the start of a string, and they accept Persian and Arabic digits as well as English ones. They never report an error: they stop at the first character that is not part of the number, and text with no number at all gives <code>0</code>. So when the text comes from a user, check it first. The example cleans up a phone number typed with Persian digits and then checks that only digits are left.</p>
{{example.str-digits}}
<p><code>str.ToEnglishDigits</code> and <code>str.ToPersianDigits</code> convert the digits inside a string and leave everything else alone. Salam always prints numbers with English digits, so <code>ToPersianDigits</code> is the last step when the output is for Persian readers.</p>

<h2 id="pitfalls">Things to watch for</h2>
<ul>
<li><code>len()</code> counts bytes. For anything a person reads (a character limit, a column width, a preview) use <code>char_count()</code> and the <code>char_</code> methods.</li>
<li><code>+</code> goes left to right: <code>"n" + 3 + 4</code> is <code>"n34"</code>, and <code>3 + 4 + "n"</code> is <code>"7n"</code>.</li>
<li><code>"12abc".to_int()</code> is <code>12</code> and <code>"abc".to_int()</code> is <code>0</code>; neither tells you something was wrong.</li>
<li>A string ends at its first zero byte: <code>"a\0b".len()</code> is <code>1</code>. Keep binary data in a byte buffer, not in a <code>str</code>.</li>
<li>Ordering with <code>&lt;</code> follows character codes, not the alphabet of any language.</li>
</ul>
