<h2 id="repeat">repeat</h2>
<p><code>repeat 3:</code> runs the body three times. Add <code>in i</code> to get a counter called <code>i</code> that starts at zero, so <code>repeat 4 in i</code> gives 0, 1, 2 and 3. The count may be any whole number expression, such as a variable or <code>v.len()</code>, and a count of zero runs the body no times at all. <code>repeat 1 to 10</code> walks a range with both ends included, <code>by 3</code> sets the step, and if the start is greater than the end the loop counts down.</p>
{{example.loop-count}}
<p>The counter belongs to the loop: assigning to <code>i</code> inside the body is a compile error, so the loop always runs the number of times its header says.</p>

<h2 id="range">Ranges and steps</h2>
<p>The step after <code>by</code> is always written as a positive number, even when the loop counts down: the bounds alone decide the direction, so <code>repeat 10 to 1 by 3</code> gives 10, 7, 4 and 1. The step may be a variable. A step of <code>0</code>, or a negative number written in the code such as <code>by -2</code>, is a compile error (E063). A step held in a variable is only known at run time and is not checked: if it turns out negative, the loop quietly runs zero times.</p>
{{example.loops}}
<p>The direction is decided when the loop starts, from the values the bounds have at that moment. That leads to a trap when a bound is a variable. <code>repeat from to 1</code> counts down from 3 as expected, but when <code>from</code> is 0 the start is below the end, so the loop counts <em>up</em> and prints <code>0 1</code> instead of nothing:</p>
{{example.loop-range-trap}}
<p>If the start can fall below the end, guard the loop with an <code>if</code>, as <code>safe_countdown</code> does.</p>

<h2 id="until">The until loop</h2>
<p><code>until condition:</code> repeats <strong>for as long as the condition holds</strong>, and stops once it becomes false. It is the loop other languages call <code>while</code>; Salam has no <code>while</code> keyword. So write the condition the way you want the loop to carry on: <code>until n != 0</code> keeps going while <code>n</code> is not zero. Reach for <code>until</code> when you do not know in advance how many turns are needed.</p>
{{example.loop-until}}
<p>The condition is checked before every turn, including the first. That is why <code>digit_sum(0)</code> gives 0: the body never runs. It is also why an inverted condition is dangerous. Write <code>until n == 0</code> by mistake and the loop runs zero times, with no error at all. When a loop seems to do nothing, check which way round its condition is before anything else.</p>

<h2 id="forever">Loops that end with break</h2>
<p>Sometimes the place to decide whether to stop is the middle or the end of the body, not the top. Write <code>until true:</code> and leave with <code>break</code> where the decision falls. This is also how to write a loop that runs at least once, which other languages call do-while. The example pages through 23 search results, 10 to a page, and stops after the page that holds the last result.</p>
{{example.loop-forever}}
<p><code>until false:</code>, on the other hand, is a compile error, because its body could never run.</p>

<h2 id="each">each ... in</h2>
<p><code>each item in list</code> walks every element of an array, a vector or a map. The form <code>each index, item in list</code> gives you the position as well.</p>
{{example.loop-each}}
<p>A map always needs two names, <code>each key, value in map</code>, and a name you do not need is written <code>_</code>, because an unused loop variable is an error. The loop variable is a copy of the element and cannot be assigned. To change the elements themselves, take the index and write through it, as the price update below does.</p>
{{example.loop-each-map}}
<p>A map is walked in its own internal order, not the order the keys were added, so do not rely on that order; this example only adds things up. A string cannot be walked with <code>each</code> directly. To visit its characters, walk <code>str.Chars(s)</code>, which is covered in the <a href="/learn/strings/">strings lesson</a>.</p>

<h2 id="nested">Nested loops</h2>
<p>A loop inside another loop runs completely for every turn of the outer one. Here the outer loop picks a row, the inner loop fills its columns, and <code>fmt.PadLeft</code> keeps the numbers lined up.</p>
{{example.loop-nested}}

<h2 id="break">break and continue</h2>
<p><code>break</code> leaves the loop and <code>continue</code> jumps to the next turn. Inside nested loops, <code>break 2</code> leaves two loops at once, <code>break 3</code> three, and so on; the number cannot be larger than the number of loops around it.</p>
{{example.loop-break}}
<p>In an <code>until</code> loop, be careful with <code>continue</code>: it jumps straight back to the condition, so if the line that moves the loop forward comes after the <code>continue</code>, it is skipped and the loop never ends. Update the counter before you <code>continue</code>.</p>

<h2 id="choose">Which loop to use</h2>

<tbody>

<h2 id="rules">Rules worth remembering</h2>
<ul>
<li><code>until</code> loops while its condition is true. An inverted condition makes the loop run zero times without any error.</li>
<li>The direction of <code>repeat a to b</code> comes from the bounds when the loop starts, so a variable start below the end counts up.</li>
<li>The step after <code>by</code> is positive. Zero or a negative literal is a compile error; a negative step held in a variable makes the loop silently run zero times.</li>
<li>Loop variables cannot be assigned. Change a collection through its index.</li>
<li>A loop that could never run, such as <code>until false:</code>, is a compile error.</li>
</ul>
