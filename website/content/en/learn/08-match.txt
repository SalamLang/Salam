<h2 id="match">match</h2>
<p><code>match</code> is an expression: it compares a value against the cases and gives back the result of the branch that matched. Each branch is a pattern, a colon, the result and <code>end</code>. Several cases can share one branch by separating them with commas, and <code>else</code> catches everything left over.</p>
{{example.match-values}}
<p>When match gives back a value, every branch has to produce one, all of the same type.</p>

<h2 id="statement">match as a statement</h2>
<p>match can also stand on its own as a statement. A branch may then hold several lines, closed by its <code>end</code>. The subject does not have to be a number: strings work too, and are compared by their contents. The example plays back a list of commands, the way a small command-line tool or chat bot would.</p>
{{example.match-command}}
<p>Unlike a switch, a match branch never falls into the next one; exactly one branch runs. The patterns for a number or a string are exact values. Ranges such as <code>1 to 9</code> and comparisons such as <code>&lt; 0</code> are not match patterns: for those use <code>switch</code>, shown below.</p>

<h2 id="enum">Matching an enum</h2>
<p>Over an enum, the patterns are the bare names of its cases (<code>Spring</code>, not <code>Season.Spring</code>), and match checks that no case has been left out:</p>
{{example.match}}
<p>Delete the <code>Winter</code> branch and the program no longer compiles, and the error names the missing case. So when you add a case to an enum later, the compiler shows you every match that has to learn about it. An <code>else</code> branch turns that check off, so leave it out when you can list every case.</p>

<h2 id="data">Pulling out data, and guards</h2>
<p>When enum cases carry data, a pattern can take that data apart: <code>Cash(a)</code> binds the amount to <code>a</code>, and <code>_</code> skips a value you do not need. <code>Card c</code> binds the whole case, so its fields are reached as <code>c.amount</code>. A branch can also add a guard: <code>if</code> and a condition after the pattern. The guard can use the names the pattern bound, and if it is false, matching goes on to the next branch.</p>
{{example.match-data}}
<p>A guarded branch does not count as covering its case, which is why <code>Cash(a)</code> appears a second time without a guard. Enums with data are introduced in the <a href="/learn/enums/">enums lesson</a>.</p>

<h2 id="struct-patterns">Struct patterns</h2>
<p>match can test a struct against its fields. <code>x = 0</code> means the field has to equal zero, and a bare name such as <code>y</code> binds the field's value to a variable of that name. Because patterns carry conditions, a final <code>else</code> is required.</p>
{{example.match-struct}}

<h2 id="switch">switch</h2>
<p><code>switch</code> is a statement for choosing between cases. A case label can be one value, several values separated by commas, or a range such as <code>1 to 3</code>. If a case does not end with <code>break</code>, execution falls into the next one, so write <code>break</code> wherever you do not want that.</p>
{{example.switch}}
<p>A switch label may begin with a comparison operator, such as <code>&gt;= 90</code>. <code>switch true</code> takes the place of a chain of ifs: every label is a condition, and the first one that holds runs.</p>
{{example.switch-true}}

<h2 id="fallthrough">Falling through on purpose</h2>
<p>Fallthrough is usually something to guard against, but it is handy when each case adds to the ones below it. In this subscription plan, Premium has everything Standard has and more, and Standard has everything Basic has. Ordering the cases from the richest down and leaving out <code>break</code> lists each plan's features with no repetition.</p>
{{example.switch-fallthrough}}
<p>A switch on an enum must cover every case or have an <code>else</code>; otherwise it is error E103, just as with match. A switch on anything else that finds no matching label simply does nothing.</p>

<h2 id="switch-loop">switch inside a loop</h2>
<p>Inside a switch, <code>break</code> leaves the switch only, not the loop around it. To leave the loop as well, write <code>break 2</code>. <code>continue</code> is not caught by the switch: it goes straight to the next turn of the loop. The example averages sensor readings, skips the value that means "offline" and stops at the end marker.</p>
{{example.switch-loop}}

<h2 id="choose">match or switch?</h2>
<div class="table-wrap"><table>
<thead><tr><th>Situation</th><th>Use</th></tr></thead>
<tbody>
<tr><td>You need a value back</td><td><code>match</code></td></tr>
<tr><td>Enum cases carry data, or you need guards or struct patterns</td><td><code>match</code></td></tr>
<tr><td>Ranges such as <code>10 to 19</code>, or labels such as <code>&gt;= 90</code></td><td><code>switch</code></td></tr>
<tr><td>One case should continue into the next</td><td><code>switch</code> without <code>break</code></td></tr>
<tr><td>Several statements per case, on a plain enum or value</td><td>either; both check that an enum is fully covered</td></tr>
<tr><td>A handful of unrelated conditions</td><td><code>switch true</code>, or plain <code>if</code> and <code>else</code></td></tr>
</tbody>
</table></div>

<h2 id="rules">Things to remember</h2>
<ul>
<li>A match branch never falls through; a switch case always does, unless it ends with <code>break</code>.</li>
<li>Enum patterns are bare case names. <code>Season.Spring:</code> as a pattern is a parse error.</li>
<li>A match on an enum must cover every case, and so must a switch on an enum (E103), unless there is an <code>else</code>.</li>
<li>A guarded branch, or a struct pattern with a test, does not cover its case on its own.</li>
<li><code>break</code> in a switch leaves the switch; <code>break 2</code> also leaves the loop around it.</li>
<li>In a switch, <code>else</code> must be the last label.</li>
</ul>
