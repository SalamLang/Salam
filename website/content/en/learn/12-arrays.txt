<h2 id="basics">Building and reading an array</h2>
<p>Build an array with square brackets. Positions start at zero, and <code>len()</code> gives the number of elements. To change elements, declare the array <code>mut</code>. <code>println</code> prints a whole array at once, and an array may itself hold arrays, as <code>table</code> does here.</p>
{{example.arr-basics}}
<p>The type of <code>numbers</code> is <code>int[4]</code>: the length is part of the type and never changes. When you need a list that grows, use a <code>Vector</code> from the <a href="/learn/collections/">collections lesson</a>.</p>

<h2 id="sized">An array of a given size</h2>
<p>When you know the length but not yet the values, declare the array with its type: <code>mut votes: int[4]</code>. Numbers start at zero and <code>bool</code> elements at <code>false</code>. Counting things by number is the classic use:</p>
{{example.arr-sized}}
<div class="note"><p>Do not read the elements of a <code>str</code> array declared this way before you have set them: they hold no string yet, and reading one crashes the program. Build a <code>str</code> array from a literal instead, such as <code>["", "", ""]</code>.</p></div>

<h2 id="each">Walking an array</h2>
<p><code>each item in array</code> visits the elements in order. With two names, <code>each i, item in array</code>, you also get the position.</p>
{{example.arrays}}

<h2 id="search">Searching and adding up</h2>
<p>Most work on an array is one loop that carries a result along: a running total, the position of the largest value so far, or the first position that matches. Keep the position rather than the value when you will need both, as with <code>wettest</code> below. A search function returns <code>-1</code> when nothing matches, a value that cannot be a real position.</p>
{{example.arr-stats}}
<p>Two arrays cannot be compared with <code>==</code> (that is error E021); compare them element by element in a loop.</p>

<h2 id="grid">Two dimensional arrays</h2>
<p>An array of arrays is a table: <code>sales[r][c]</code> is row <code>r</code>, column <code>c</code>. <code>len(sales)</code> is the number of rows and <code>len(sales[0])</code> the number of columns. An array literal may span several lines, which keeps a table readable. <code>each</code> does not walk a two dimensional array (E065), so use <code>repeat</code> with indexes. A single row, <code>sales[r]</code>, is an ordinary array and can be handed to a function.</p>
{{example.arr-grid}}
<p>To declare an empty table, give both sizes: <code>mut grid: int[3][4]</code>.</p>

<h2 id="copy">Arrays are values</h2>
<p>Assigning an array to another variable copies all of it. So does passing it to a parameter with a fixed size such as <code>int[3]</code>, and so does returning one. Changing the copy never touches the original.</p>
{{example.arr-copy}}
<p>That makes arrays safe to pass around, but copying a large array on every call costs time. When a function should only read an array, or should change the caller's array, give it a slice instead.</p>

<h2 id="slices">Slices</h2>
<p><code>array[start: end]</code> makes a slice over the elements from <code>start</code> up to but not including <code>end</code>. It is not a copy: it points at the same data. <code>[: 2]</code> takes from the beginning and <code>[4:]</code> runs to the end. A parameter of type <code>int[]</code> accepts any array or slice of ints, whatever its length, and an array passes to it directly, with no copy.</p>
{{example.arr-slices}}

<h2 id="write">Slices write through</h2>
<p>Because a slice points at the caller's data, a function that changes elements of an <code>int[]</code> parameter changes the caller's array. Pass a slice of part of the array and only that part changes.</p>
{{example.arr-slice-write}}
<p>A function that returns a slice must not return one that points into its own local array, since that array is gone once the function returns; the compiler rejects it (E012).</p>

<h2 id="bounds">Index errors</h2>
<p>Reading or writing past the end of an array is always a mistake, and Salam catches it. When the index is a constant, the build stops: <code>a[3]</code> on a three element array gives "index 3 is out of bounds for an array of length 3" (E021). When the index is only known at run time, the program stops with "array index 5 out of bounds [0,3)" instead of reading memory that is not part of the array.</p>
<div class="note"><p>A build with <code>--release</code> leaves out these run time checks to save time, so an index error there is no longer caught. Test without <code>--release</code> first.</p></div>

<h2 id="rules">Rules of thumb</h2>
<ul>
<li>Use an array when the length is known and fixed, and a <code>Vector</code> when it is not.</li>
<li>Take an array parameter as <code>int[]</code> (a slice) unless the function needs its own copy.</li>
<li>Remember that a slice writes through to the array it came from.</li>
<li>Walk a two dimensional array with <code>repeat</code> and two indexes.</li>
<li>Return <code>-1</code> from a search that finds nothing, and check for it.</li>
</ul>
