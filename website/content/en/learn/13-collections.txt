<h2 id="vector">Vector</h2>
<p>Build one with <code>Vector {} as Vector&lt;type&gt;</code>. <code>push</code> adds an element at the end, <code>get</code> and <code>set</code> read and replace one by its position, <code>pop</code> takes the last one off and returns it, and <code>len</code> gives the count. <code>each</code> walks the elements in order.</p>
{{example.vector}}
<div class="note"><p>A Vector and a HashMap both allocate memory. Write <code>defer name.free()</code> on the line after creating one, so the memory is released when the function ends, however it ends.</p></div>

<h2 id="edit">Inserting and removing</h2>
<p>A Vector is not limited to its end. <code>insert(i, x)</code> puts a value at position <code>i</code> and moves the rest along, and <code>remove_at(i)</code> takes one out and gives it back. <code>first()</code> and <code>last()</code> read the two ends, <code>clear()</code> empties the Vector and <code>is_empty()</code> tells you whether anything is left. Square brackets work as they do on an array: <code>v[i]</code> reads and <code>v[i] = x</code> writes.</p>
{{example.vector-edit}}
<p>Positions start at 0 and end at <code>len() - 1</code>. Reading past the end is not quietly ignored: the program stops with <code>Vector.get: index out of bounds</code>. Inserting or removing near the front moves every element after it, so on a very long Vector, work at the end when you can.</p>

<h2 id="structs">A Vector of structs</h2>
<p>The element type can be anything, and most real programs keep a list of records: tasks, orders, players. <code>each i, t in tasks</code> gives you the position and the element together.</p>
{{example.vector-structs}}
<p>The loop variable <code>t</code> is a copy of the element. Changing <code>t.done</code> inside the loop would change only the copy and leave the Vector as it was. To change an element in place, take a pointer to it with <code>ref(i)</code> and write through that, as the example does with the first task. The other way is to read the element, change it and put it back with <code>set(i, x)</code>.</p>
<p>The <a href="/learn/structs/">next lesson</a> covers structs themselves.</p>

<h2 id="sort">Sorting</h2>
<p>The <code>sort</code> package sorts a Vector in place. <code>sort.Sort</code> puts numbers and strings in ascending order and <code>sort.SortDesc</code> in descending order. For structs, or for any order of your own, <code>sort.SortBy</code> takes a function that answers one question: should <code>a</code> come before <code>b</code>?</p>
{{example.vector-sort}}
<p>The comparison here is <code>a.score &gt; b.score</code>, so higher scores come first. <code>sort.SortBy</code> does not promise to keep equal elements in their original order. When that matters, for example when a list already sorted by name is sorted again by score, use <code>sort.StableSortBy</code>, which takes the same arguments. The package also has <code>sort.Sorted</code> (a sorted copy), <code>sort.BinarySearch</code>, <code>sort.Min</code> and <code>sort.Max</code>; see the <a href="/std/sort/">sort reference</a>.</p>

<h2 id="map">HashMap</h2>
<p>A HashMap connects keys to values: <code>put</code> stores a pair (and replaces the value if the key is already there), <code>get</code> returns the value for a key, <code>has</code> tests whether a key is there, <code>remove</code> takes it out and <code>size</code> gives the number of pairs. <code>each key, value in map</code> walks all of them.</p>
{{example.hashmap}}
<p><code>get</code> on a missing key does not fail; it returns the zero value of the value type, such as 0 or an empty string. When 0 could be a real value, check with <code>has</code> first, or use <code>get_or(key, fallback)</code> to choose what comes back for a missing key.</p>

<h2 id="count">Counting with a HashMap</h2>
<p>Counting how often something occurs is the job a HashMap is made for. Here every word of a sentence is a key and its count is the value. <code>get_or(w, 0) + 1</code> covers both the first time a word is seen and every time after that.</p>
{{example.hashmap-count}}
<p>A HashMap does not remember the order in which keys were added, and walking it gives them in an order that has nothing to do with your data. When the output needs an order, collect the keys into a Vector, sort it, and look each key up, as the example does.</p>

<p>A Stack is the natural way to check that brackets are balanced: every opening bracket is pushed, and every closing one must match the bracket on top.</p>

<h2 id="copy">Sharing and copying</h2>
<p>Assigning a Vector to another variable does not copy its elements. <code>same := prices</code> gives a second name for the same storage, so a change made through one name shows through the other. When you need an independent copy, for example a snapshot to compare with later, call <code>copy()</code>. The copy has its own memory, so it needs its own <code>free()</code>.</p>
{{example.vector-copy}}
<p>The same goes for parameters. A function that only reads a Vector can take it by value, but a function that adds to the caller's Vector must take it with <code>&amp;:</code>, as <code>add_fee</code> does; elements pushed onto a by-value parameter never reach the caller. A HashMap behaves the same way and has a <code>copy()</code> too.</p>
<div class="note"><p>Free each piece of storage exactly once. In the example, <code>same</code> and <code>prices</code> are the same storage, so only <code>prices</code> is freed; <code>saved</code> is separate and is freed on its own.</p></div>

<h2 id="rules">Rules of thumb</h2>
<ul>
<li>Use an array when the size is fixed, a Vector when it grows, and a HashMap when you look things up by a key.</li>
<li>Write <code>defer x.free()</code> on the line after every Vector, HashMap or collection you create, including the ones returned by functions such as <code>str.Split</code>.</li>
<li>The loop variable of <code>each</code> is a copy. Change elements with <code>ref(i)</code>, <code>set(i, x)</code> or <code>v[i] = x</code>.</li>
<li>Do not rely on the order of a HashMap. Sort the keys when the order matters.</li>
<li><code>b := a</code> shares a Vector and <code>a.copy()</code> makes a new one. A function that pushes to the caller's Vector takes it with <code>&amp;:</code>.</li>
</ul>
