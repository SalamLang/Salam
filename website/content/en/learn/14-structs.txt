<h2 id="define">Declaring a struct</h2>
<p>Every field has a name, a type and, optionally, a default value. A method is a <code>func</code> written inside the struct, and inside it <code>this</code> refers to the value the method was called on. Fields and methods are private by default; <code>pub</code> makes them reachable from outside the struct.</p>
{{example.structs}}

<h2 id="print">Creating and printing</h2>
<p>A struct literal names the fields it sets: <code>Point { x = 3, y = 4 }</code>. Any field you leave out takes its default value. A field declared without a default has to be given every time, or the compiler stops with <code>E028: struct literal 'P' requires field 'x'</code>. A struct can be printed directly, with all of its fields:</p>
{{example.struct-print}}

<h2 id="to-str">Your own text with to_str</h2>
<p>The printed form shows every field, which is handy while you write a program but not always what a user should see. Give the struct a method <code>pub func to_str(): str</code> and <code>println</code> uses it instead. It is also used when the struct sits inside another struct, a Vector or an array.</p>
{{example.struct-tostr}}
<p><code>Item</code> has no <code>to_str</code> of its own, so it is printed field by field, but its <code>price</code> field uses the one from <code>Money</code>. To get the text without printing it, call <code>to_str()</code> yourself, as the last line does.</p>

<h2 id="private">Public and private</h2>
<p>A private field can only be read and written by the struct's own methods. Code outside that tries <code>acc.balance</code> gets <code>E017: field 'balance' is private in struct 'Account' (mark it 'pub')</code>. That is how a struct protects its rules: here nobody can make the balance negative, because the only way to change it is through <code>deposit</code> and <code>withdraw</code>, and both check the amount first.</p>
{{example.struct-private}}
<p>A good habit is to make fields private unless there is a reason to expose them, and to give the outside world methods that say what can be done (<code>deposit</code>) rather than how the data is stored (<code>balance</code>).</p>
<div class="note"><p>A method cannot have the same name as a field of its struct. That is why the method that returns the balance is called <code>current</code> and not <code>balance</code>.</p></div>

<h2 id="mut">Mutating methods</h2>
<p>A method that changes the struct's fields is declared <code>mut func</code>. As soon as a struct has one, the compiler checks every method: a plain <code>func</code> that assigns to a field of <code>this</code> is an error (<code>E105: cannot modify 'this' in method 'reset': declare it 'mut func'</code>), and a <code>mut func</code> can only be called on a variable declared with <code>mut</code> (<code>E106</code>). So by reading a method's first line you know whether it can change the value.</p>
{{example.struct-mut}}

<h2 id="static">Static members and constructors</h2>
<p><code>static func</code> and <code>const</code> inside a struct belong to the type rather than to one value; call them through the struct's name. A static func has no <code>this</code>, but it can set private fields, which makes it the natural place for constructors. <code>Account.open</code> in the example above is one; here is another that builds a ready-made value:</p>
{{example.struct-static}}

<h2 id="copy">Structs are values</h2>
<p>Assigning a struct copies it. After <code>goal := start</code> the two are separate values, and changing <code>goal</code> leaves <code>start</code> alone. Passing a struct to a function copies it too, so a function that should change the caller's struct takes it with <code>&amp;:</code>. Two structs compare with <code>==</code> and <code>!=</code> field by field, with no code of your own.</p>
{{example.struct-copy}}
<p><code>reset_copy</code> changed its own copy, which was thrown away when it returned. <code>reset</code> took a reference and changed the caller's <code>goal</code>. A <code>&amp;:</code> parameter is also cheaper for a large struct, because nothing is copied. One exception to "a struct is a value": a Vector or a HashMap field is copied as a handle, so both copies share the same elements (see <a href="/learn/collections/#copy">sharing and copying</a>).</p>

<h2 id="embed">Composition with use</h2>
<p><code>use</code> places one struct inside another and makes its public fields and methods reachable directly. That is composition instead of inheritance: a <code>Dog</code> is built from an <code>Animal</code> plus a breed.</p>
{{example.struct-embed}}
<p>The embedded struct is also a field of its own, named after its type. If the outer struct defines a method with the same name as an embedded one, its own method wins, and it can still call the embedded version through that field:</p>
{{example.struct-embed-override}}
<p>A literal can set embedded fields directly (<code>created = ...</code>), and printing shows the embedded struct as a nested value. <code>pub use</code> makes the embedded struct visible outside; a plain <code>use</code> keeps it private.</p>

<h2 id="rules">Rules of thumb</h2>
<ul>
<li>Give fields sensible defaults, so a literal only names what differs.</li>
<li>Keep fields private and expose methods; use <code>pub</code> fields for plain data with no rules to protect.</li>
<li>Mark every method that changes the struct <code>mut func</code>, and declare the variable you call it on with <code>mut</code>.</li>
<li>Put constructors in a <code>static func</code>, especially when the value needs checking or has private fields.</li>
<li>Assignment and parameters copy a struct. Use <code>&amp;:</code> when a function must change the caller's value.</li>
</ul>
