<h2 id="alias">Aliases and distinct types</h2>
<p><code>type Id = int</code> is only another name for <code>int</code> and mixes freely with it. <code>type Meter: int</code>, on the other hand, builds a new type on top of <code>int</code> that cannot be confused with a plain int, and that can carry its own methods and operators in a body closed by <code>end</code>.</p>
{{example.type-alias}}
<p>An alias is useful for a long type you write often, or to give a name to an enum from another place: after <code>type Paint = Color</code>, <code>Paint.Red</code> is the same case as <code>Color.Red</code>. A type error that involves an alias names it too, as in <code>cannot pass 'str' to 'i32' ('Age' is an alias of 'i32')</code>.</p>

<h2 id="distinct">Distinct types for meaning</h2>
<p>A distinct type keeps every operator of its base type, and the result has the new type: adding two <code>Cents</code> gives <code>Cents</code>, and <code>&lt;</code> and <code>&gt;</code> work as before. What it does not do is mix with plain numbers. <code>price + 4</code> with <code>4</code> in an int variable stops with <code>E021: operator cannot be applied to 'Cents' and 'i32'</code>; a conversion with <code>as</code> has to be written out, so it is always visible. When an operation with another type makes sense, declare it, as <code>*</code> by a count does here:</p>
{{example.type-money}}
<p><code>println total</code> prints the underlying number, so the example asks for the formatted text with its own <code>text()</code> method. A number literal adopts the type it meets, so <code>price + 100</code> needs no cast, while <code>price * 3</code> uses the <code>*</code> declared in the type.</p>
<p>The base can also be <code>str</code>, <code>bool</code>, <code>char</code> or a float. An <code>Email</code> is still text, but a function that takes one can no longer be handed any string by mistake (<code>E012: argument 1: cannot pass 'str' to 'Email'</code>):</p>
{{example.type-email}}

<h2 id="operators">Operator overloading</h2>
<p>A method whose name is the operator itself, such as <code>func +(other: Vec): Vec</code>, defines that operator for the struct. It is called when the struct is the left operand. The operators you can define are <code>+ - * / % ** == != &lt; &gt; &lt;= &gt;= not [] []=</code>; inventing a new symbol is an error.</p>
{{example.operator}}

<h2 id="more-operators">Indexing, negation and the rest</h2>
<p>The number of parameters decides the kind of operator. <code>func -: Vec</code> with no parameters is negation (<code>-pos</code>), and <code>func -(other: Vec)</code> would be subtraction; define both if you need both. <code>[]</code> takes the index and <code>[]=</code> takes the index and the new value, which lets a struct be used with square brackets like an array:</p>
{{example.operator-more}}
<p>Some operators come for free. <code>a += b</code> uses your <code>+</code>, and <code>!=</code> uses your <code>==</code> when you have not written a <code>!=</code>. The right operand of <code>*</code> does not have to be the same type: here a <code>Vec</code> is scaled by an <code>int</code>.</p>
<div class="note"><p>Define an operator only when its meaning is obvious to a reader. <code>+</code> on two vectors is clear; <code>+</code> that saves a record to disk is not, and a method with a name is the better choice.</p></div>

<h2 id="variant">Variant</h2>
<p><code>Variant&lt;int, str&gt;</code> is a value that may be any one of several types. Match on the type names to get the value back with its real type. The match has to cover every type in the list.</p>
{{example.variant}}
<p>A Variant is often a field: a setting whose value may be a number, a switch or a name. Assign a value of one of the listed types directly, without a cast:</p>
{{example.variant-settings}}
<p>A Variant cannot be printed as it is (<code>E002: cannot print value of type 'Variant&lt;i32, str&gt;' directly</code>); match on it and print the part you got, as <code>show</code> does. When the choices need names of their own or carry several values, an <a href="/learn/enums/#data">enum with data</a> is usually the clearer tool.</p>

<h2 id="choose">Which one to use</h2>
<div class="table-wrap"><table>
<thead><tr><th>You want</th><th>Use</th></tr></thead>
<tbody>
<tr><td>A shorter or clearer name for an existing type</td><td><code>type Name = T</code></td></tr>
<tr><td>A number or string that must not be mixed up with others</td><td><code>type Name: T ... end</code></td></tr>
<tr><td>Several named fields together</td><td><a href="/learn/structs/">a struct</a></td></tr>
<tr><td>One of a fixed list of cases, perhaps with data</td><td><a href="/learn/enums/">an enum</a></td></tr>
<tr><td>A value of one of a few existing types</td><td><code>Variant&lt;A, B&gt;</code></td></tr>
<tr><td>One function or struct that works for many types</td><td><a href="/learn/generics/">generics</a></td></tr>
</tbody>
</table></div>

<h2 id="rules">Rules of thumb</h2>
<ul>
<li>Give a distinct type to values that are easy to confuse: money, units, ids, already-escaped text.</li>
<li>Convert in and out with <code>as</code> at the edges of the program, and keep the distinct type everywhere in between.</li>
<li>Overload operators only where they read naturally, and keep them free of side effects.</li>
<li>Prefer an enum with data to a Variant when the cases have meanings beyond their types.</li>
</ul>
