<h2 id="generic">Generic functions and structs</h2>
<p>Write <code>&lt;T&gt;</code> after the name and the function or struct works for any type <code>T</code>. For every type you actually use, the compiler builds a separate, fully specialised copy, so generic code runs as fast as code written by hand for that type.</p>
{{example.generics}}
<p>The type of a generic function comes from its arguments: <code>larger(3, 9)</code> uses <code>int</code> and <code>larger("a", "b")</code> uses <code>str</code>. You cannot name the type at the call (<code>larger&lt;int&gt;(3, 9)</code> does not parse), so if a literal should have another type, cast it with <code>as</code>. A generic struct takes its type from the cast, as in <code>Box { ... } as Box&lt;str&gt;</code>.</p>
<p>The body has to make sense for every type you call it with. <code>larger</code> compares with <code>&gt;</code>, which works for numbers and strings. Call it with two structs and the compiler stops with <code>E021: cannot compare 'P' and 'P'</code>.</p>

<h2 id="container">A generic container</h2>
<p>Most generic code you write will be a container: a struct that holds values of some type and offers a small, clear set of operations on them. This stack keeps its items in a <code>Vector&lt;T&gt;</code> and exposes only what a stack should do. The same code serves as an undo history of strings and as a list of page numbers.</p>
{{example.generics-stack}}
<p>The struct owns a Vector, so it also gets a <code>free</code> method, and each stack is released with <code>defer</code> right after it is created. That is the same habit as for a plain Vector; the <a href="/learn/memory/">memory lesson</a> explains why.</p>

<h2 id="several">Several type parameters</h2>
<p>A generic can take more than one type, separated by commas. <code>Pair&lt;A, B&gt;</code> holds two values of different types, and <code>swap</code> turns a <code>Pair&lt;A, B&gt;</code> into a <code>Pair&lt;B, A&gt;</code>. Printing a generic struct shows the types it was built with.</p>
{{example.generics-pair}}

<h2 id="interface">Interfaces</h2>
<p>An <code>interface</code> is a list of method signatures. A struct that has all of those methods implements the interface automatically; there is no "implements" line to write. A parameter of type <code>dyn Shape</code> accepts any value whose type implements <code>Shape</code>.</p>
{{example.interface}}
<p>An interface method may carry a default body. A struct that does not write that method gets the default, and a struct that does write it keeps its own. The default can call the other methods of the interface through <code>this</code>.</p>
{{example.interface-default}}
<p>If a type is missing a method, the compiler says so where the value is used as the interface: <code>E002: 'Box' does not implement interface 'Scored': missing method 'score'</code>.</p>

<h2 id="impl">impl: an interface for an existing type</h2>
<p><code>impl Interface on Type</code> gives the methods of an interface to a type you did not write, even a built-in one like <code>int</code> or <code>str</code>. Inside those methods, <code>this</code> is the value itself. The <code>&lt;T: Ranked&gt;</code> in this example is a bound: the function accepts only types that implement <code>Ranked</code>.</p>
{{example.impl}}

<h2 id="bounds">Bounds: generics that call methods</h2>
<p>A plain <code>&lt;T&gt;</code> knows nothing about <code>T</code>, so the body cannot call methods on it. A bound such as <code>&lt;T: Scored&gt;</code> promises that every <code>T</code> has the methods of <code>Scored</code>, and the body is free to use them. Bounds work on structs too: <code>Board&lt;T: Scored&gt;</code> is a leaderboard for players, bids or anything else that has a score.</p>
{{example.generics-bound}}
<p>Each <code>Board</code> holds a single type: a <code>Board&lt;Player&gt;</code> cannot also hold a <code>Bid</code>. That is the other side of the speed of generics, and it is exactly the problem <code>dyn</code> solves.</p>

<h2 id="dyn">Mixed collections with dyn</h2>
<p><code>dyn Notifier</code> is a value of any type that implements <code>Notifier</code>, decided at run time. With it, one list can hold different types: the <code>Vector&lt;dyn Notifier&gt;</code> below holds an email sender and two SMS senders, and one loop sends through all of them. A struct field can be <code>dyn</code> as well, so an alert can be wired to whichever channel you choose.</p>
{{example.interface-dyn}}
<p>A <code>dyn</code> value lives in a small box on the heap. Storing a value copies it into the box, so changing the original later does not reach the stored copy. Freeing a <code>Vector&lt;dyn ...&gt;</code> frees the list but not the boxes in it, which is why the example frees each element before the Vector itself. A <code>dyn</code> field is released the same way, with <code>field.free()</code>.</p>

<h2 id="choose">Generic or dyn?</h2>
<div class="table-wrap"><table>
<thead><tr><th></th><th><code>&lt;T: Shape&gt;</code></th><th><code>dyn Shape</code></th></tr></thead>
<tbody>
<tr><td>The type is chosen</td><td>While compiling, with one copy of the code per type</td><td>At run time, with one copy of the code for all types</td></tr>
<tr><td>Calls</td><td>Direct, as fast as hand-written code</td><td>Through a small dispatch step</td></tr>
<tr><td>Different types in one collection</td><td>No, one type per instance</td><td>Yes, <code>Vector&lt;dyn Shape&gt;</code></td></tr>
<tr><td>Memory</td><td>Values are stored directly</td><td>Each value is boxed, and the box has to be freed</td></tr>
<tr><td>Good for</td><td>Containers and algorithms</td><td>Handlers, plugins, lists of different things</td></tr>
</tbody>
</table></div>

<h2 id="rules">Rules of thumb</h2>
<ul>
<li>Use a generic when the same code works for many types, and add a bound as soon as the body needs a method.</li>
<li>Use <code>dyn</code> only when one collection or field must hold different types.</li>
<li>Keep interfaces small. Two or three methods are easy to implement and easy to give defaults.</li>
<li>Use <code>impl ... on</code> to teach an existing type, even <code>int</code> or <code>str</code>, a new interface without touching its code.</li>
<li>A generic container that owns a Vector or a HashMap needs a <code>free</code> method, and boxed <code>dyn</code> values are freed one by one.</li>
</ul>
