<h2 id="package">Packages</h2>
<p>A file that begins with <code>package name</code> is a package. Only the functions, constants and types marked <code>pub</code> are visible outside it; everything else is an internal detail.</p>
{{example.pkg-lib}}

<h2 id="include">Including a file</h2>
<p><code>include name "file.salam"</code> brings a file from your own project in under a short name, and you reach its public members as <code>name.thing</code>. The path is relative to the file doing the including.</p>
{{example.pkg-include}}

<h2 id="import">Importing a library</h2>
<p>Standard library packages are imported by name, without quotes, as in <code>import str</code> or <code>import os</code>. <code>import</code> is for libraries and <code>include</code> is for your own files.</p>
{{example.pkg-import}}
<p>In an English file you have to use the English names, and a Persian one such as <code>str.طول</code> is an error. Every standard library function carries its Persian name next to its English one in the library source, under the <code>std</code> directory, written with <code>@fa</code>. You can make your own public functions bilingual the same way, so that Persian files can call them too:</p>
{{example.pkg-bilingual}}

<h2 id="order">The order of definitions</h2>
<p>Salam asks for a fixed order among the top-level definitions in a file, so that every file reads the same way:</p>
<ol>
<li><code>package</code></li>
<li>Imports, then includes</li>
<li>Constants and global variables</li>
<li>Types, structs, enums and interfaces</li>
<li>Functions, with the public ones last</li>
</ol>
<p><code>salam format</code> tidies a file up and does much of this moving for you.</p>
