<h2 id="why">Why so strict?</h2>
<p>Every error the compiler catches is an error that never reaches a user. That is why Salam treats as errors several things other languages only warn about. Each message carries a code, the exact line and column, and a suggestion.</p>

<h2 id="common">The errors you will meet most</h2>
<div class="table-wrap"><table>
<thead><tr><th>What you wrote</th><th>What the compiler says</th></tr></thead>
<tbody>
<tr><td><code>number := 5</code> and never using it</td><td><code>E059</code> unused variable 'number': nothing uses it after it is declared</td></tr>
<tr><td><code>number := 5</code> then <code>number = 6</code></td><td><code>E013</code> cannot reassign immutable variable 'number'; declare it 'mut' to reassign it</td></tr>
<tr><td><code>mut number := 5</code> never changed</td><td><code>E069</code> variable 'number' is declared 'mut' but never mutated; remove 'mut' or declare it 'const'</td></tr>
<tr><td><code>if number:</code></td><td><code>E021</code> if condition must be bool, got 'i32'</td></tr>
<tr><td><code>if false:</code></td><td><code>E068</code> 'if' condition is always false: its body can never run</td></tr>
<tr><td>An empty <code>if</code> branch</td><td><code>E060</code> the 'if' branch is empty: add a statement to it, or remove the 'if'</td></tr>
<tr><td><code>number = "five"</code></td><td><code>E002</code> cannot assign 'str' to 'i32'</td></tr>
<tr><td>A <code>const</code> after a function</td><td><code>E084</code> constant 'RATE' must be declared before any function or type definition</td></tr>
<tr><td>A function nothing calls</td><td><code>E066</code> unused function 'helper': it is private and nothing calls it</td></tr>
</tbody></table></div>

<h2 id="tips">A few hints</h2>
<ul>
<li>If you deliberately do not use something, start its name with <code>_</code>.</li>
<li>The message usually tells you the fix as well; read to the end of it.</li>
<li>Salam has no exceptions. Report failure with a returned value, such as a <code>bool</code> or an enum like <code>Result</code>.</li>
</ul>
