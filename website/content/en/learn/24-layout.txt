<h2 id="common">What is shared</h2>
<p>In both targets you describe the interface as a tree of elements. A <code>page:</code> block (or <code>صفحه:</code>) is the root, each element opens with its name and a colon and closes with <code>end</code> (<code>پایان</code>), and attributes/styles are written as <code>name = value</code>. Element text is usually its <code>content</code>, elements can nest, and the structure stays readable.</p>
<p>Top-level page settings such as <code>title</code>, <code>lang</code>, and <code>dir</code> belong to the page. English files default to left-to-right; Persian files default to right-to-left. You can set them explicitly when needed.</p>
{{example.layout-page}}

<h2 id="values">Simpler value syntax</h2>
<p>In layout/style values you can now write many values in a shorter form: percentages like <code>50%</code> and <code>100%</code> without quotes, hex colors like <code>#0f766e</code> without quotes, units such as <code>12px</code>/<code>1rem</code>/<code>200ms</code> in value contexts, and value lists/groups where supported. For example:</p>
<pre class="code snip" dir="ltr"><code>box:
    width = 50%
    max width = 480
    padding = 16, 24
    background = #f8fafc
    color = #0f766e
    border = 1, solid, #0f766e
end</code></pre>
<p>Bare numbers are typically treated as pixels for length-like properties. Strings (such as text <code>content</code>, URLs, or specific textual values) still use quotes.</p>

<h2 id="elements">Elements, attributes, and styles</h2>
<p>Element and property names are readable (English and Persian aliases). Common elements include <code>box</code>/<code>div</code>, <code>paragraph</code>, <code>heading</code>, <code>link</code>, <code>image</code>, <code>list</code>/<code>item</code>, <code>form</code>, <code>input</code>, and <code>button</code>. Boolean attributes like <code>required = true</code> are meaningful, while <code>false</code> is usually omitted. CSS properties are written alongside elements as attributes.</p>
{{example.layout-form}}
<p>Use constants, <code>global</code> rules, and components to keep styles consistent and avoid repetition:</p>
{{example.layout-style}}

<h2 id="components">Components and reuse</h2>
<p>A <code>component</code> (<code>بخش</code>) is a reusable piece of UI with parameters, used like a custom element. <code>content: end</code> marks the slot where nested children are inserted. To share components across files, include them (e.g. <code>include = "parts.salam"</code>, path relative to the including file).</p>
{{example.layout-component}}

<h2 id="params">Parameterized pages and dynamic structure</h2>
<p>A layout/page can take parameters (e.g. <code>layout Card(name: str, score: int):</code>) and be rendered with runtime values. Inside parameterized layouts you can use conditions (<code>if</code>/<code>else</code>) and loops (<code>each</code>) to build dynamic UI. Parameter text is handled safely when inserted into the page.</p>
{{example.layout-runtime}}
{{example.layout-inbox}}

<h2 id="targets">Two targets: web and native</h2>
<p>The same DSL can target different runtimes, with different outputs and capabilities:</p>
<ul>
<li><strong>Web:</strong> build with <code>salam page build</code> to produce HTML/CSS/JS for browsers, with DOM/events and web/server integration. See <a href="/learn/layout/web/">Layout on the web</a>.</li>
<li><strong>Native (desktop):</strong> run/build with <code>salam run --ui=native</code> or <code>salam build --ui=native</code> to open a native window rendered by Salam's UI engine (no browser). See <a href="/learn/layout/native/">Layout in native apps</a>.</li>
</ul>
<p>For desktop apps that host web UI inside a native window (WebView, like Tauri/Electron model), see <a href="/std/gui/webview/">gui.webview</a>; that is a different path from native DSL rendering.</p>

<h2 id="check">Compile-time checks</h2>
<p>The compiler checks element/attribute names and many values and reports helpful errors. This catches mistakes early for both web and native targets. For parameterized pages and untrusted input, follow the safety/validation rules of the chosen runtime (especially web/server paths).</p>
