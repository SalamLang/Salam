lesson.body <<
<h2 id="page">A page</h2>
<p>A <code>layout:</code> block is a tree of page elements. Each element opens with its name and a colon and closes with <code>end</code>, and attributes and styles are written as <code>name = value</code> inside it, with no commas between them. The settings at the top of the block, such as <code>title</code>, <code>lang</code> and <code>dir</code>, belong to the page itself:</p>
{{example.layout-page}}

<h2 id="build">Building the page</h2>
<p><code>salam layout build page.salam</code> turns that file into <code>page.html</code> and <code>page.css</code>, plus a <code>page.js</code> when the page has scripts. <code>--inline</code> puts everything into one self-contained HTML file. Given several files, <code>salam layout build home.salam about.salam</code> writes one HTML file per page and a single <code>style.css</code> they share. With no file name at all it builds <code>salam.salam</code> if there is one, and otherwise every layout page in the folder.</p>
<p>The styles do not end up on the elements. Each element that has styles gets a short generated class, such as <code>.a</code> or <code>.b</code>, and the rules go into the stylesheet, so the HTML stays small.</p>

<h2 id="elements">Elements and attributes</h2>
<p>Most HTML elements have a readable name: <code>box</code> is a <code>div</code>, <code>paragraph</code> a <code>p</code>, <code>link</code> an <code>a</code>, <code>list</code> and <code>item</code> are <code>ul</code> and <code>li</code>, and <code>nav</code>, <code>form</code>, <code>label</code>, <code>input</code> and <code>button</code> keep their HTML names. The text of an element is its <code>content</code>. Links and images both take <code>url</code>, which becomes <code>href</code> or <code>src</code> as needed, and some values have words of their own, such as <code>target = "new"</code> for a link that opens in a new tab:</p>
{{example.layout-form}}
<p>A <code>true</code> attribute, such as <code>required = true</code>, becomes a bare HTML attribute, and a <code>false</code> one is left out. Every element and its names, English and Persian, are listed in the <a href="https://github.com/SalamLang/Salam/blob/main/docs/LAYOUT_ELEMENTS.md">element reference</a>.</p>

<h2 id="style">Styles</h2>
<p>CSS properties are written the same way, with spaces instead of dashes: <code>border radius</code>, <code>font family</code>, <code>box sizing</code>. A property with <code>hover</code> in front of it applies while the pointer is over the element. A <code>global</code> element holds rules for the whole page: on its own it styles every element, and with <code>selector</code> it styles whatever the selector matches. Values can be built from constants declared above the layout, so a colour or a spacing is written once:</p>
{{example.layout-style}}
<p>The <code>Pro</code> box ends up with the rule <code>border:2px solid #0f766e</code> and its button with a <code>:hover</code> rule, all worked out while compiling. One thing to avoid: if you give two elements the same <code>class</code> and different styles, both rules are written under that one class name and the later one wins for both elements. Leave <code>class</code> out on styled elements, or style a shared class once with <code>global</code>. Nearly the whole of CSS is covered this way, including grid, animation, scroll-driven timelines, anchor positioning and the SVG-only properties; the <a href="https://github.com/SalamLang/Salam/blob/main/docs/CSS_PROPERTIES.md">property reference</a> lists every one, English and Persian, with what it accepts.</p>

<h2 id="events">Making it interactive</h2>
<p>An attribute named after a browser event, such as <code>click</code>, <code>submit</code>, <code>key down</code> or <code>change</code>, takes a function instead of a value. A plain function name is compiled through the JavaScript backend and dropped into the page's own script, so the behaviour stays ordinary Salam instead of hand-written JS; an inline function works the same way and gets a generated name of its own:</p>
{{example.layout-events}}
<p>Inside the handler, <code>dom.ById</code> and <code>dom.Query</code> are checked against the ids actually used in the same file's layout, so a misspelled id such as <code>dom.ById("counter")</code> is caught before the page ever runs. A plain string such as <code>click = "alert(42)"</code> still works too, for a one-line call into existing JavaScript.</p>

<h2 id="table">Tables</h2>
<p>One name can produce a different element depending on where it sits. Inside <code>table</code>, <code>header</code>, <code>main</code> and <code>footer</code> are <code>thead</code>, <code>tbody</code> and <code>tfoot</code>, and <code>column</code> becomes <code>th</code> in a header row and <code>td</code> everywhere else:</p>
{{example.layout-table}}

<h2 id="components">Components</h2>
<p>A <code>component</code> is a piece of page you define once and use as often as you like, as if it were a new element. Its parameters are set like attributes. Inside it, <code>content: end</code> marks the slot: whatever you nest inside the component where you use it lands there.</p>
{{example.layout-component}}
<p>Both plans share one generated class, because their styles are identical. To share components between pages, put them in a file of their own and write <code>include = "parts.salam"</code> at the top of the layout; the path is relative to the page that includes it.</p>

<h2 id="runtime">Layouts with parameters</h2>
<p>A layout can take a name and parameters. It then becomes a function that returns the page as a string of HTML, and a normal Salam program can call it with values it only knows while running:</p>
{{example.layout-runtime}}
<p>Inside such a layout you can use <code>if</code>, <code>else</code> and <code>each</code>, and a component with typed parameters can be called on its own to get just its piece of HTML. Text that comes from a parameter is escaped for you, so a <code>&lt;b&gt;</code> or a <code>&lt;script&gt;</code> in the data shows up as text and never becomes part of the page:</p>
{{example.layout-inbox}}
<p>The structure of the page is still fixed while compiling; only the values change. Two rules keep it that way. A layout with parameters is a <code>pure</code> function, so it cannot do anything else while building the page: even <code>subjects.len()</code> is not allowed inside it, which is why the count arrives as a parameter of its own. And a plain <code>str</code> cannot go where a URL, a colour or a length belongs, because text from a user could break out of it. Parse it first with <code>web.ParseUrl</code>, <code>web.ParseColor</code> or <code>web.ParseLength</code> from the <code>web</code> package, which reject anything unsafe, and give the layout the resulting <code>web.Url</code>, <code>web.Color</code> or <code>web.Length</code>.</p>

<h2 id="program">A page from a Salam program</h2>
<p>Because a layout with parameters is just a function, a web server written in Salam can answer each request with a fresh page. This program serves a greeting at <code>http://localhost:8080/?name=Sara</code>:</p>
{{example.layout-server}}
<p>The server keeps running until you stop it, so the example has no output here. The name comes straight from the address bar, and thanks to the escaping, a visitor who sends <code>?name=&lt;b&gt;</code> sees the text <code>&lt;b&gt;</code> and nothing else.</p>

<h2 id="font">Web fonts</h2>
<p>The <code>font</code> element produces an <code>@font-face</code>. <code>name</code> and <code>url</code> are required; if you leave <code>type</code> out, Salam works it out from the extension in the URL and then from the bytes of a file sitting next to the program. Use the font afterwards with <code>font family</code>:</p>
{{example.layout-font}}

<h2 id="check">Checked while compiling</h2>
<p>Salam checks every element and attribute before it builds the page. A misspelled name, an attribute that element does not have, a malformed value such as a URL in the wrong shape, a required attribute left out, or an element in the wrong place is an error, and the message suggests the nearest valid name. For example, <code>hint = "x"</code> on an <code>input</code> gives "unknown attribute 'hint' on 'input'; did you mean 'enterkeyhint'?", and an <code>item</code> outside a <code>list</code> gives "element 'item' cannot be placed inside 'layout'". Inside a layout with parameters, an unknown element name is only a warning and is built as a <code>div</code>, so read the warnings there too.</p>
<div class="note"><p>The layout language turns into plain HTML and CSS, so anything you know about the web still applies. For the server side, the <code>net.http</code> and <code>net.router</code> packages used above handle requests, query strings and responses.</p></div>
