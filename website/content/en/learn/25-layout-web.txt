<h2 id="build">Building web output</h2>
<p><code>salam page build page.salam</code> produces <code>page.html</code> and <code>page.css</code>, plus <code>page.js</code> when scripts/events are present. Use <code>--inline</code> for a single self-contained HTML file. With multiple inputs (e.g. <code>salam page build home.salam about.salam</code>) each page gets its own HTML and they can share a common <code>style.css</code>. With no file name, the tool typically builds <code>main.salam</code> if present, otherwise layout pages in the folder.</p>
<p>Styles are extracted into generated classes/rules in the stylesheet so HTML stays compact and reusable.</p>

<h2 id="events">Browser events and DOM</h2>
<p>Event attributes such as <code>click</code>, <code>submit</code>, <code>input</code>, <code>change</code>, etc. become interactive behavior in the browser. Salam handlers attached to events are compiled into the page script for web builds. In handlers you can work with the DOM (e.g. <code>dom.ById</code>/<code>dom.Query</code>) as covered in the events lessons.</p>
<p>See <a href="/learn/events-mouse/">Mouse events</a> through <a href="/learn/events-dom/">State, the DOM and timers</a> for the full browser event/DOM model.</p>

<h2 id="runtime">Parameterized layouts and runtime rendering</h2>
<p>Parameterized layouts can render HTML at runtime with request-specific data, which is useful for Salam web servers. Inserted parameter text is escaped for safety. For sensitive/structured values (URLs, colors, lengths, etc.) validate/parse them appropriately before use.</p>

<h2 id="serve">Serving and web projects</h2>
<p>Built files can be hosted on any static web server, or served locally/production with <a href="/learn/serve/"><code>salam serve</code></a>. Salam programs can also return rendered HTML using networking packages such as <code>net.http</code> and <code>net.router</code>.</p>

<ul>
<li>Browser features (forms behavior, media APIs, scrolling, clipboard, storage, etc.) are web-environment specific.</li>
<li>Interactive pages rely on the page script running in the browser.</li>
<li>For browserless native windows, see <a href="/learn/layout-native/">Layout in native apps</a>.</li>
