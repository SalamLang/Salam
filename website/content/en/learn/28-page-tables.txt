<h2 id="when">When to use a table</h2>
<p>Use a table for data that you would also put in a spreadsheet: every cell means something because of its row and its column. A list of prices, a school timetable and a table of results are all tables. A page that has a menu on the left and text on the right is not: that is a job for layout with CSS, which the <a href="/learn/css-layout/">layout lesson</a> teaches. Screen readers announce a table as a table and read each cell together with its headings, so a table used for layout makes the page harder to understand for the people who depend on them.</p>

<h2 id="structure">The parts of a table</h2>
<p>A <code>table</code> holds rows, and a <code>row</code> holds cells. A cell is written <code>column</code> in Salam. The name can mislead you: <code>column</code> is one cell (HTML <code>td</code>), and the rows are what make up the columns. Rows can go straight into the table, but real tables are split into three sections: <code>header</code> for the headings, <code>main</code> for the data and <code>footer</code> for totals. Inside a table these three words mean the HTML <code>thead</code>, <code>tbody</code> and <code>tfoot</code>. Outside a table the same words are the page header, the main part and the page footer, and the compiler picks the right one from where you wrote it.</p>
<p>The <code>caption</code> is the title of the table. It must be the first thing inside the table: the compiler stops with an error if it is not. A table can have only one <code>header</code> and one <code>footer</code>, but as many <code>main</code> sections as you need to group rows.</p>
{{example.web-tables-basic}}
<p>Two global rules do the styling here. <code>th, td</code> selects every cell, and the rule gives them padding and a line under them. <code>table</code> with <code>border collapse = collapse</code> joins the lines of neighbouring cells into one. Without CSS a table has no borders at all, so every table you want to look like a table needs some.</p>
<p>The cells of the header row became <code>th</code> without you asking. That is the context rule: a <code>column</code> inside <code>header</code> is a heading cell. Browsers draw heading cells in bold and centred, and, more important, they tell assistive technology that these cells are headings. The footer is different. It only holds data cells unless you say otherwise, so the word Total in the last row is plain here. The next section fixes that.</p>

<h2 id="heading-cells">Heading cells and scope</h2>
<p>Headings are not only in the top row. When the first cell of every row names that row, it is a heading too. Write <code>heading = true</code> on a <code>column</code> and it becomes a <code>th</code>. The word <code>heading</code> here is an attribute of the cell, not the heading element of the text lesson.</p>
<p>Then tell the browser which way the heading points with <code>scope</code>: <code>col</code> for a heading that describes the cells below it and <code>row</code> for one that describes the cells to its right. There are two more values for headings that cover a whole group of rows or columns: <code>rowgroup</code> and <code>colgroup</code>. For a simple table browsers guess the scope correctly, but writing it costs nothing and removes the guess.</p>
<p>If a heading is long, give it a short form in <code>abbr</code>. A screen reader may read the short form when it repeats the heading for every cell, which saves the listener time.</p>
{{example.web-tables-scope}}
<div class="note"><p><code>header column</code> and <code>heading column</code> are the two names the reference below gives to the heading cell: the first is a cell that stands in a header row, the second a cell that you marked with <code>heading = true</code>. Both are written <code>column</code> in your code and both produce <code>th</code>.</p></div>

<h2 id="spans">Cells that span</h2>
<p>A cell can cover more than one place. <code>colspan</code> stretches it over several columns and <code>rowspan</code> over several rows. When you stretch a cell, the cells it covers must not be written: a row with a <code>colspan = 2</code> cell has one cell less, and the row below a <code>rowspan = 2</code> cell has one cell less on that side. If you write too many, the table looks broken and no error appears, so count the cells of every row as you write it.</p>
{{example.web-tables-span}}
<p>In the timetable the Maths cell has <code>rowspan = 2</code>, so the second row lists only Music, which fills Room B. The lunch row has <code>colspan = 2</code> and fills both rooms.</p>

<h2 id="complex">Complex tables and headers</h2>
<p>Sometimes one heading is not enough to explain a cell. In a table with two levels of headings, or with spanning cells, a data cell may belong to several headings. Give each heading cell an <code>id</code> and list those ids in the <code>headers</code> attribute of the data cell, separated by spaces. Salam checks that every id exists. The example below gives every data cell both of its headings, the row heading and the column heading, so you can see the shape. Do not write <code>headers</code> on a simple table: <code>scope</code> is enough there and is much less work.</p>
{{example.web-tables-headers}}

<h2 id="columns">Styling whole columns</h2>
<p>You often want a colour or a width for a whole column. Writing it on every cell is long and easy to get wrong. A <code>column group</code> before the sections of the table lets you describe the columns once. Each <code>column definition</code> inside stands for one column from the left (from the right in a Persian page). Give it <code>span</code> to cover several columns with one line. Only a few properties work on these elements: <code>background</code>, <code>width</code>, <code>visibility</code> and, when borders are collapsed, <code>border</code>. They have no text and no children.</p>
{{example.web-tables-columns}}
<p>The first definition colours the first column grey, the second one has <code>span = 2</code> and colours the next two green, and the last one colours the final column red.</p>

<h2 id="style">Making a table look good</h2>
<p>Four properties do most of the work. <code>border collapse = collapse</code> merges the borders of neighbouring cells into one line, where the default <code>separate</code> draws a double line. <code>border spacing</code> sets the gap between cells when they are separate. <code>padding</code> on the cells makes the text breathe, and <code>text align</code> lines the numbers up, usually to the right. <code>vertical align</code> chooses where a short cell's text sits in a tall row.</p>
<p>Stripes make long rows easier to follow. You can colour every other row yourself, but it is simpler to write one CSS rule. The page-wide <code>style</code> element takes raw CSS, and <code>tbody tr:nth-child(even)</code> selects every second row of the body. The hover colour uses the <code>hover</code> prefix in front of a style property, written on the row; the CSS lessons cover such states in detail. The table itself gets <code>width = "100%"</code> so that it fills the space, and <code>max width</code> stops it from growing past 28rem. <code>color = white</code> on the heading cells keeps the text readable on the dark green. The caption sits above the table by default, and <code>caption side = bottom</code> moves it under.</p>
{{example.web-tables-style}}
<div class="note"><p>Do not make a table narrower with <code>width</code> on every cell. Put <code>width</code> or <code>max width</code> on the table, and use <code>table layout = fixed</code> if you want the columns to take the widths of the first row, which also makes large tables draw faster.</p></div>

<h2 id="scroll">Wide tables on small screens</h2>
<p>A table is as wide as its content needs, and a phone is narrow. If the table cannot shrink, it pushes the whole page sideways. The fix is a box around the table with <code>overflow = auto</code>: the page keeps its width and the table scrolls inside the box. Give the box a <code>max height</code> as well and it scrolls up and down too, and then a heading row with <code>position = sticky</code> and <code>top = 0</code> stays visible while the data moves under it. Put the sticky rule on the <code>th</code> cells, not on the row: that is the form that works in every browser.</p>
{{example.web-tables-scroll}}
<p>Scroll the preview above to see the heading stay in place. The box has a <code>max width</code> and a <code>max height</code> that are smaller than the table, <code>overflow = auto</code> adds the scroll bars only when they are needed, and the table is given a fixed <code>width</code> of 40rem so that it is wider than the box. Put a background on sticky cells, or the text that scrolls under them shows through.</p>

<h2 id="access">Accessible tables, in short</h2>
<ul>
<li>Give every table a <code>caption</code>. It says what the table is before anyone reads a cell.</li>
<li>Make every heading a heading cell, in a <code>header</code> row or with <code>heading = true</code>, and write <code>scope</code>.</li>
<li>Do not leave a cell empty to make space: use padding for space. A cell that really has no data can say "none" or "n/a", so that a screen reader has something to read.</li>
<li>Keep the table simple. Two tables are better than one with spans in every row.</li>
</ul>

<h2 id="reference">Reference: every table element</h2>
<p>Each element is shown with an example, and the attributes that belong only to that element are listed under it. The attributes that every element has are in <a href="/learn/page-head/">the lesson on the head and global attributes</a>. The examples are checked by the compiler, so you can paste any of them into a <code>page:</code> block. Persian names work in any file, and the Persian lessons use them.</p>
<h3 id="el-table"><code>table</code><span class="ref-alt"> (Persian: <code>جدول</code>; HTML: <code>&lt;table&gt;</code>)</span></h3>
<p>A table of data in rows and columns. Use it for information that has a natural grid, such as prices, schedules or results, and never to lay out a page. Browsers draw no borders by default, so style it with CSS. Its children are, in this order: an optional <code>caption</code>, optional <code>column group</code>s, the sections <code>header</code>, <code>main</code> and <code>footer</code> (or plain <code>row</code>s), and cells go inside rows.</p>
<pre class="code snip" dir="ltr"><code>table:
    caption: content = &quot;Pets&quot; end
    row:
        column: content = &quot;Cat&quot; end
        column: content = &quot;4 legs&quot; end
    end
end</code></pre>
<h3 id="el-caption"><code>caption</code><span class="ref-alt"> (Persian: <code>عنوان جدول</code>; HTML: <code>&lt;caption&gt;</code>)</span></h3>
<p>The title of the table. It must be the first child of the table, and the compiler reports an error when it is not. Screen readers announce it before the cells, so it is better than a heading placed above the table. <code>caption side</code> moves it below.</p>
<pre class="code snip" dir="ltr"><code>table:
    caption: content = &quot;Pets&quot; end
    row: column: content = &quot;Cat&quot; end end
end</code></pre>
<p class="ref-meta">Only inside: <code>table</code></p>
<h3 id="el-column-group"><code>column group</code><span class="ref-alt"> (Persian: <code>گروه ستون</code>; HTML: <code>&lt;colgroup&gt;</code>)</span></h3>
<p>A group of column definitions that describe whole columns, so that you can style a column without touching every cell. It goes before the sections of the table. Without children it covers as many columns as its <code>span</code> says.</p>
<pre class="code snip" dir="ltr"><code>table:
    column group:
        column definition: background = &quot;#fee2e2&quot; end
        column definition: end
    end
    row:
        column: content = &quot;Red column&quot; end
        column: content = &quot;Plain column&quot; end
    end
end</code></pre>
<p class="ref-meta">Only inside: <code>table</code></p>

<h3 id="el-column-definition"><code>column definition</code><span class="ref-alt"> (Persian: <code>تعریف ستون</code>; HTML: <code>&lt;col&gt;</code>)</span></h3>
<p>Describes one column, or several with <code>span</code>, inside a <code>column group</code>. It has no content and no children. Only a few properties work on it: <code>background</code>, <code>border</code>, <code>width</code> and <code>visibility</code>. Text properties on it do nothing.</p>

<h3 id="el-table-header"><code>table header</code><span class="ref-alt"> (Persian: <code>سرصفحه</code>; HTML: <code>&lt;thead&gt;</code>)</span></h3>
<p>Written as <code>header</code> inside a table. It becomes the <code>thead</code> section, which holds the heading rows and repeats on every page when the table is printed. A table has at most one. The same word outside a table is the page <code>header</code> element, the compiler decides by where it stands. Cells in its rows turn into heading cells.</p>
<pre class="code snip" dir="ltr"><code>table:
    header:
        row:
            column: content = &quot;Name&quot; end
            column: content = &quot;Age&quot; end
        end
    end
    main:
        row:
            column: content = &quot;Sara&quot; end
            column: content = &quot;31&quot; end
        end
    end
end</code></pre>
<p class="ref-meta">Only inside: <code>table</code></p>
<h3 id="el-table-body"><code>table body</code><span class="ref-alt"> (Persian: <code>اصلی</code>; HTML: <code>&lt;tbody&gt;</code>)</span></h3>
<p>Written as <code>main</code> inside a table. It becomes <code>tbody</code>, the section with the data rows. You may have several of them to group rows. Rows written directly inside the table, with no section, work too, and then the browser adds an implicit body.</p>
<pre class="code snip" dir="ltr"><code>table:
    main:
        row:
            column: content = &quot;Sara&quot; end
            column: content = &quot;31&quot; end
        end
    end
end</code></pre>
<p class="ref-meta">Only inside: <code>table</code></p>
<h3 id="el-table-footer"><code>table footer</code><span class="ref-alt"> (Persian: <code>پاورقی</code>; HTML: <code>&lt;tfoot&gt;</code>)</span></h3>
<p>Written as <code>footer</code> inside a table. It becomes <code>tfoot</code>, the place for a totals row. A table has at most one. Browsers draw it at the bottom even though it can be written before the body.</p>
<pre class="code snip" dir="ltr"><code>table:
    main:
        row:
            column: content = &quot;Tea&quot; end
            column: content = &quot;3&quot; end
        end
    end
    footer:
        row:
            column: heading = true content = &quot;Total&quot; end
            column: content = &quot;3&quot; end
        end
    end
end</code></pre>
<p class="ref-meta">Only inside: <code>table</code></p>
<h3 id="el-row"><code>row</code><span class="ref-alt"> (Persian: <code>ردیف</code>; HTML: <code>&lt;tr&gt;</code>)</span></h3>
<p>One row of cells. It goes inside the table or inside <code>header</code>, <code>main</code> or <code>footer</code>, and its children are cells.</p>
<pre class="code snip" dir="ltr"><code>table:
    row:
        column: content = &quot;Left&quot; end
        column: content = &quot;Right&quot; end
    end
end</code></pre>
<p class="ref-meta">Only inside: <code>table</code>, <code>table header</code>, <code>table body</code>, <code>table footer</code></p>
<h3 id="el-column"><code>column</code><span class="ref-alt"> (Persian: <code>ستون</code>; HTML: <code>&lt;td&gt;</code>)</span></h3>
<p>A data cell, the <code>td</code> element. Despite its name it is one cell, not a whole column. Inside a <code>header</code> row it becomes a heading cell automatically, and anywhere else you ask for a heading cell with <code>heading = true</code>.</p>
<pre class="code snip" dir="ltr"><code>table:
    row:
        column: content = &quot;Plain data&quot; end
        column: content = &quot;More data&quot; background = &quot;#f1f5f9&quot; end
    end
end</code></pre>
<p class="ref-meta">Only inside: <code>row</code></p>

<h3 id="el-header-column"><code>header column</code><span class="ref-alt"> (Persian: <code>ستون</code>; HTML: <code>&lt;th&gt;</code>)</span></h3>
<p>The name of a <code>column</code> when it stands in a <code>header</code> row: the compiler writes <code>th</code> for it, with no extra work from you. It takes <code>scope</code> (<code>col</code> or <code>row</code>, <code>colgroup</code> or <code>rowgroup</code>), <code>abbr</code> (a short form that screen readers read instead of a long heading), and also <code>colspan</code>, <code>rowspan</code> and <code>headers</code>.</p>
<pre class="code snip" dir="ltr"><code>table:
    header:
        row:
            column: content = &quot;Temperature&quot; scope = col abbr = &quot;Temp&quot; end
            column: content = &quot;Rain&quot; scope = col end
        end
    end
end</code></pre>
<h3 id="el-heading-column"><code>heading column</code><span class="ref-alt"> (Persian: <code>ستون</code>; HTML: <code>&lt;th&gt;</code>)</span></h3>
<p>A heading cell outside the header, made by writing <code>heading = true</code> on a <code>column</code>. Use it for the first cell of every row (a row heading) with <code>scope = row</code>, or in a footer for the word Total. It takes the same attributes as the header cell, <code>scope</code> and <code>abbr</code> among them.</p>
<pre class="code snip" dir="ltr"><code>table:
    row:
        column: heading = true scope = row content = &quot;Monday&quot; end
        column: content = &quot;Sunny&quot; end
    end
end</code></pre>
<p class="ref-meta">Only inside: <code>row</code></p>
