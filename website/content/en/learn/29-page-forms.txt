<h2 id="form">The form and the submit</h2>
<p>A <code>form</code> holds controls and knows where to send them. <code>action</code> is the address that receives the data and <code>method</code> is how it travels: <code>get</code> puts the data into the address and suits searches, <code>post</code> puts it into the body of the request and is the right choice for everything that changes something or is private. When the form has a file input, add <code>enctype = "multipart/form-data"</code>. The other form attributes are in the reference below: <code>autocomplete</code>, <code>novalidate</code>, <code>target</code>, <code>rel</code>, <code>accept charset</code> and <code>name</code>.</p>
<p>A real send would leave the page, and the previews in this lesson must stay on it. So most examples here listen to the button and decide for themselves what happens. The <code>click</code> attribute of a submit button is a function that runs when the button is pressed. It receives the event, and <code>dom.PreventDefault</code> stops the default action, which is sending the form. That also skips the browser's checks, so the function asks for them: <code>reportValidity</code> checks every field and shows the browser's message at the first bad one, and <code>as bool</code> turns its answer into true or false. After that you read each field with <code>dom.GetValue(dom.ById("id"))</code> and use the text as you like. The event is the plain <code>i64</code> parameter of the function.</p>
<p>On a page of your own you can give the same function to the <code>submit</code> attribute of the <code>form</code>. The browser then runs its checks first and calls your function only when they pass, so <code>reportValidity</code> is not needed.</p>
{{example.web-forms-signup}}
<p>Leave the fields empty and press Join: the browser shows its message and nothing else happens, because <code>reportValidity</code> answered no. Write something that is not an address in the Email field and it refuses again. Only a complete form gets past the <code>if</code>, which is why you can trust the values inside it, at least as far as the browser checks go.</p>
<div class="note"><p>Browser checks are for the visitor's comfort, not for security. Anyone can send a request without your page. Whatever your server receives has to be checked on the server again.</p></div>

<h2 id="labels">Labels</h2>
<p>Every control needs a <code>label</code>. Connect them in one of two ways. Give the control an <code>id</code> and write the same id in <code>for</code> of the label, as the sign up example does: Salam checks at compile time that an element with that id exists, so a typo cannot silently break the link. Or put the control inside the label, as the pizza example further down does, and no <code>for</code> is needed. Either way a click on the label text focuses the control or ticks the checkbox, and a screen reader reads the label when the control gets the focus.</p>
<p>The <code>placeholder</code> attribute is not a label. It is a hint in the empty box, it vanishes when the visitor types and many people find the grey text hard to read. Use it for an example of the format, and keep the label.</p>

<p>The form above is a grid with two columns, set with <code>display = grid</code> and <code>grid template columns</code>, so that every label stands to the left of its control. <code>gap</code> is the space between rows and columns. Open it on a phone and each control brings its own keyboard.</p>

<h2 id="validation">Letting the browser check</h2>
<p>Most of the checking comes from attributes on the control. <code>required</code> forbids an empty value. <code>minlength</code> and <code>maxlength</code> bound the number of characters, and <code>pattern</code> takes a regular expression that the whole value must match. For numbers and dates, <code>min</code>, <code>max</code> and <code>step</code> set the range and the grid of allowed values. <code>size</code> only changes how wide a text box looks, and does not check anything. <code>readonly</code> keeps a value from being edited but still sends it, while <code>disabled</code> also keeps it from being sent. <code>autofocus</code> puts the cursor in a field when the page opens, <code>multiple</code> allows several files or addresses, and <code>autocomplete</code> tells the browser what the field holds so that it can offer the saved value.</p>
<p>Besides the message that the browser shows, your code can ask each control about its <code>validity</code>. The example reads it on every keystroke with the <code>input</code> event. <code>dom.GetProp(field, "validity")</code> gives an object whose properties are true or false: <code>valueMissing</code> when a required field is empty, <code>tooShort</code> when it is shorter than <code>minlength</code>, <code>patternMismatch</code> when it does not match the pattern, and <code>rangeUnderflow</code> and <code>rangeOverflow</code> when a number is outside <code>min</code> and <code>max</code>. <code>dom.EventTarget(e)</code> tells the shared handler which field it was called for.</p>
{{example.web-forms-validate}}
<p>The two border colours come from a CSS rule written with the page wide <code>style</code> element: <code>input:user-invalid</code> and <code>input:user-valid</code>. These match only after the visitor has touched the field and left it, so a form that is still empty does not show red from the first second. The older <code>:invalid</code> matches at once and looks angry on a fresh form.</p>
<div class="note"><p>One handler can serve many fields. <code>dom.EventTarget(e)</code> is the control that fired the event, and <code>dom.GetStr(field, "id")</code> is its id, so the message for the field named <code>user</code> goes into the element with the id <code>user-note</code>.</p></div>

<h2 id="text">Longer text</h2>
<p>For text that may take several lines use <code>text area</code>. It has <code>rows</code> and <code>cols</code> for its starting size, <code>maxlength</code> and <code>minlength</code> for the length, and <code>wrap</code>: with <code>soft</code> long lines only wrap on the screen, with <code>hard</code> the line breaks are also put into the text that is sent, which needs <code>cols</code>. The text between the tags in HTML is the starting text, and in Salam it is <code>content</code>. An <code>input</code> with <code>type = "textarea"</code> is the same element written differently.</p>
<p>A counter that tells the visitor how many characters are left is a small kindness when you set a limit. The example reads <code>textLength</code> from the box, which counts characters, not bytes, so it is right for Persian text as well.</p>
{{example.web-forms-textarea}}

<h2 id="choices">Checkboxes, radio buttons and groups</h2>
<p>A <code>checkbox</code> is a yes or no. Several checkboxes with the same <code>name</code> are sent as a list of the ticked ones. A <code>radio</code> is one choice out of a set: all radio buttons that share a <code>name</code> belong together and the browser keeps one of them ticked. <code>value</code> is the text that is sent when the control is chosen, and <code>checked</code> chooses it from the start. To read a choice in code, use <code>dom.GetBool(control, "checked")</code>.</p>
<p>Wrap a related set in a <code>field set</code> with a <code>legend</code>. A sighted visitor sees a box with a title. A screen reader announces the legend as the question when the visitor enters the group, and then reads each option, which a bare row of radio buttons cannot do. The form in the example reacts to the <code>change</code> event, which fires on the form for every change of any control inside it.</p>
{{example.web-forms-choices}}
<p>A <code>field set</code> can also be switched off in one go: <code>disabled</code> on the set disables every control inside. The next example reads a checkbox and sets <code>disabled</code> with <code>dom.SetBool</code>.</p>
{{example.web-forms-fieldset}}

<h2 id="lists">Choosing from a list</h2>
<p><code>select</code> is a drop-down list, and <code>option</code> is each line of it. The visitor sees the text of the option, and the form sends its <code>value</code>, so give a short code that your server understands. <code>selected</code> picks the starting option and <code>disabled</code> greys one out: a first line that is disabled and selected makes a good prompt, such as Choose a city. <code>option group</code> puts a heading over several options and needs a <code>label</code>. <code>multiple</code> turns the list into a box where several lines can be chosen, and <code>size</code> says how many lines are visible.</p>
{{example.web-forms-select}}
<p>When the visitor should also be allowed to type something that is not in your list, use a <code>data list</code>. It is a list of suggestions that has no look of its own. Give it an <code>id</code> and name it in the <code>list</code> attribute of a text input: the browser then offers the matching suggestions while the visitor types.</p>
{{example.web-forms-datalist}}

<h2 id="buttons">Buttons</h2>
<p>A <code>button</code> has a <code>type</code>. A <code>submit</code> button sends the form, a <code>reset</code> button puts all fields back, and a <code>button</code> button does nothing until a script gives it something to do. Inside a form a button without a type is a submit button, which is how many forms get sent by accident: always write the type.</p>
<p>A submit button with a <code>name</code> and a <code>value</code> tells you which one was pressed, so one form can have Save and Delete. The buttons can also override the form for one press: <code>form action</code>, <code>form method</code>, <code>form enctype</code>, <code>form target</code> and <code>form novalidate</code> replace the form's own attribute. A Save draft button with <code>form novalidate</code> sends a half filled form. With <code>form = "id"</code> a button may stand outside the form it belongs to. In a <code>submit</code> handler on a real page, <code>dom.GetProp(e, "submitter")</code> is the button that was used. In the example each button has its own <code>click</code> handler instead, which reads the button's <code>value</code> with <code>dom.GetStr(dom.EventTarget(e), "value")</code>. The reset button below the form belongs to it through <code>form = "note"</code>.</p>
{{example.web-forms-buttons}}
<p>Two more groups of attributes belong to buttons. <code>popover target</code> and <code>popover target action</code> show or hide an element that has the <code>popover</code> attribute, with no code. <code>command</code> and <code>commandfor</code> give a command such as <code>show-modal</code> to a <code>dialog</code>. Both are newer, so check the browsers your visitors use.</p>

<h2 id="feedback">Showing results</h2>
<p>Three elements show values instead of asking for them. <code>output</code> holds a result, like the number beside a slider; its <code>for</code> lists the controls it is calculated from, and Salam checks the ids. <code>progress</code> is a bar for how much of a job is done, with <code>value</code> out of <code>max</code>. <code>meter</code> shows a value on a known scale, and <code>low</code>, <code>high</code> and <code>optimum</code> tell the browser which part of the scale is good: the bar turns green, yellow or red.</p>
{{example.web-forms-gauges}}
<p>Drag the slider and all three change. <code>progress</code> and <code>meter</code> look alike and mean different things. A task that is going to finish is a progress. A reading that goes up and down, such as battery charge, is a meter.</p>

<h2 id="files">Files</h2>
<p>A <code>file</code> input opens the file chooser. <code>accept</code> filters what it offers, with MIME types such as <code>image/png</code>, wildcards such as <code>image/*</code> and extensions such as <code>.pdf</code>. It is a convenience: a visitor can still pick another file, so check the type on the server. <code>multiple</code> allows several files. A form that sends files must be a <code>post</code> form with <code>enctype = "multipart/form-data"</code>. In code, <code>dom.GetProp(input, "files")</code> is the list of chosen files, <code>dom.CountOf</code> counts them and <code>dom.ItemAt</code> picks one.</p>
{{example.web-forms-file}}

<h2 id="jalali">The Jalali date</h2>
<p>Salam has an input type of its own for Persian dates, <code>jalali date</code> (in Persian files <code>تاریخ شمسی</code>). It is a text box that types Persian digits whatever keyboard the visitor has, adds the slashes, and tells the browser the date is invalid when the month or the day does not exist, which also respects leap years. Latin and Arabic digits that the visitor pastes are converted. The box shows the digits <code>۱۴۰۵/۰۸/۰۴</code>, and the same date with Latin digits, <code>1405/08/04</code>, is kept in the <code>data-value</code> attribute for your code to read with <code>dom.GetAttr</code>.</p>
{{example.web-forms-jalali}}
<div class="note"><p>The value that a real form send puts on the wire is the text as the box shows it, with Persian digits. Convert on the server, or read <code>data-value</code> in a submit handler.</p></div>

<h3 id="el-input"><code>input</code><span class="ref-alt"> (Persian: <code>ورودی</code>; HTML: <code>&lt;input&gt;</code>)</span></h3>
<p>A single form control. Its <code>type</code> decides what it is: a text box, a checkbox, a colour picker, a button and so on, 20 kinds in all that Salam names (see the table in the lesson). It has no content and no children. Give it a <code>name</code>, because a control without a name is not sent, and a <code>label</code>, because a control without a label is a puzzle for a screen reader.</p>
<pre class="code snip" dir="ltr"><code>label: for = &quot;city&quot; content = &quot;City&quot; end
input: id = &quot;city&quot; name = &quot;city&quot; placeholder = &quot;Oslo&quot; end</code></pre>

<h3 id="el-textarea-input"><code>textarea input</code><span class="ref-alt"> (Persian: <code>ورودی</code>; HTML: <code>&lt;textarea&gt;</code>)</span></h3>
<p>The form of <code>text area</code> that is written as an <code>input</code> with <code>type = "textarea"</code>. It produces the same <code>&lt;textarea&gt;</code> tag, and its text comes from <code>content</code>. Prefer <code>text area</code>, which has the attributes that belong to a multi-line box (<code>rows</code>, <code>cols</code>, <code>wrap</code>).</p>

<h3 id="el-progress"><code>progress</code><span class="ref-alt"> (Persian: <code>پیشرفت</code>; HTML: <code>&lt;progress&gt;</code>)</span></h3>
<p>A bar for how far a task has got, such as an upload. Without <code>value</code> it shows an endless busy animation. For a measurement that is not progress, such as disk use, take <code>meter</code>. Put a text next to it as well, since the bar alone says little to a screen reader.</p>
<pre class="code snip" dir="ltr"><code>progress: value = 30 max = 100 end</code></pre>
<div class="table-wrap"><table class="ref-table"><thead><tr><th>Attribute</th><th>What it does</th><th>Example</th></tr></thead><tbody>
<tr id="at-progress-value"><td><code>value</code><br><span class="ref-alt">مقدار</span></td><td>A number from 0 to <code>max</code>: how much is done. Leave it out for an unknown amount. <small class="ref-accepts">[float]</small></td><td><code class="snip" dir="ltr">progress: value = 70 max = 100 end</code></td></tr>
<tr id="at-progress-max"><td><code>max</code><br><span class="ref-alt">بیشینه</span></td><td>The number that means finished. The default is 1, so a <code>value</code> of 0.3 is thirty percent. <small class="ref-accepts">[float]</small></td><td><code class="snip" dir="ltr">progress: value = 3 max = 5 end</code></td></tr>
</tbody></table></div>
<h3 id="el-meter"><code>meter</code><span class="ref-alt"> (Persian: <code>سنجه</code>; HTML: <code>&lt;meter&gt;</code>)</span></h3>
<p>A gauge for a value inside a known range: battery level, a score, how full a disk is. Browsers colour it green, yellow or red from <code>low</code>, <code>high</code> and <code>optimum</code>. It is not for progress: use <code>progress</code> for that.</p>
<pre class="code snip" dir="ltr"><code>meter: value = 6 min = 0 max = 10 low = 3 high = 8 optimum = 10 end</code></pre>
<p class="ref-meta">Required: <code>value</code></p>
