<h2 id="links">Links</h2>
<p>A <code>link</code> takes the reader somewhere. Its <code>url</code> is required and its <code>content</code> is the text the reader clicks. The address can point to another site, to a file next to your page, or to a place on the same page: a <code>url</code> that starts with <code>#</code> scrolls to the element whose <code>id</code> is the rest of it. Two more kinds are worth knowing. <code>mailto:</code> opens the mail program with a new message, and <code>tel:</code> offers to call the number on a phone.</p>
{{example.web-media-links}}
<p>The attributes in the example each do one job. <code>target</code> says where the page opens: <code>new</code> is a new tab (the HTML word is <code>_blank</code>, and both work), <code>same</code> is the current tab, and <code>parent</code> and <code>top</code> matter only inside frames. <code>rel</code> describes the relationship to the target. With <code>noopener</code> the new tab cannot reach back to your page, which matters for a link to a site you do not control, and <code>nofollow</code> asks search engines not to count the link. <code>download</code> makes the browser save the file instead of showing it, and its value is the suggested file name. <code>type</code> is the kind of file you expect and <code>hreflang</code> the language of the target page. Both are hints. <code>ping</code> lists addresses that are told when someone follows the link, and <code>referrer policy</code> controls how much of your address the target site is given.</p>
<div class="note"><p>Write link text that makes sense on its own, such as "the house rules", and not "click here": screen readers can read out a list of all the links on a page. A link cannot contain another link or a button, and the compiler reports an error (E116) if you try. It also refuses addresses like <code>javascript:</code> that would run code (E018).</p></div>

<h2 id="images">Images</h2>
<p><code>image</code> shows a picture. The <code>url</code> is required. The text description is the <code>alt</code> attribute, and <code>content</code> sets the same attribute, so you can write whichever reads better. The description is what a screen reader says and what the browser shows when the file cannot be loaded. Describe what the picture tells, not what it is: "A red kite over green hills", not "image". If the picture is only decoration, give it an empty description, <code>alt = ""</code>, and screen readers will skip it. When you give neither, the compiler writes the empty one for you.</p>
{{example.web-media-image}}
<p>Always set <code>width</code> and <code>height</code> to the real size of the file. The browser then reserves the space before the picture arrives, and the text below does not jump when it does. <code>loading = lazy</code> tells the browser to fetch the picture only when the reader scrolls near it, which saves data for pictures far down the page. Leave the first picture on the page at the default, <code>eager</code>. <code>decoding</code> chooses whether decoding may happen off to the side (<code>async</code>) and <code>fetch priority</code> lets you mark the most important picture as <code>high</code>.</p>
<p>The long text in <code>url</code> is a data address: the whole picture written as text, so the example needs no extra file. The compiler accepts data addresses for images, audio, video and fonts and refuses the rest. In your own pages you will usually write a file name or an address instead.</p>

<h2 id="responsive">One picture, many sizes</h2>
<p>A phone and a large monitor do not need the same file. <code>srcset</code> lists several versions of the picture, and the browser picks one. There are two ways to describe them. With density descriptors, as in the example, each file is marked <code>1x</code>, <code>2x</code> and so on, and the browser chooses by the pixel density of the screen. With width descriptors, <code>photo-480.jpg 480w, photo-960.jpg 960w</code>, each file is marked with its real width, and <code>sizes</code> tells the browser how wide the picture will be drawn, for example <code>sizes = "(max-width: 600px) 100vw, 600px"</code>. The <code>url</code> stays as the fallback for browsers that do not know <code>srcset</code>.</p>
{{example.web-media-srcset}}
<p>The files in this example do not exist, so the browser draws nothing. It still decides which one it would load, and the function named after <code>error =</code> runs when the image cannot be loaded and reads that choice from the <code>currentSrc</code> property of the image. On a screen with twice the pixels you would read the second name.</p>
<p>When the versions are not the same picture, for example a wide crop for a desktop and a tall one for a phone, use <code>picture</code>. Inside it, each <code>source</code> has a <code>media</code> condition and a <code>srcset</code>, and the browser takes the first source whose condition is true. The last child is always a normal <code>image</code>: it is the fallback and it carries the description. A <code>source</code> can also have a <code>type</code>, such as <code>image/webp</code>, so that browsers that do not know the format skip it.</p>
{{example.web-media-picture}}

<h2 id="maps">Clickable image maps</h2>
<p>An image map makes parts of one picture into separate links. The <code>image</code> names the map with <code>use map = "#shapes"</code>, and an <code>image map</code> with <code>name = "shapes"</code> holds one <code>area</code> per hotspot. An <code>area</code> has a <code>shape</code>: <code>rect</code> with the coordinates <code>left,top,right,bottom</code>, <code>circle</code> with <code>center-x,center-y,radius</code>, <code>poly</code> with the corners as <code>x1,y1,x2,y2</code> and so on, or <code>default</code> for everything not covered. The coordinates are in pixels of the picture as it is drawn. An <code>area</code> is a link, so it also takes <code>url</code>, <code>target</code>, <code>rel</code>, <code>download</code>, <code>ping</code> and <code>referrer policy</code>, and it needs <code>alt</code>, the text for people who cannot click the picture.</p>
{{example.web-media-map}}
<p>In the example each area also has a <code>click</code> handler that writes into the paragraph. The older <code>ismap</code> attribute is different: on an image inside a link it makes the browser send the clicked coordinates to the server, which then decides what to do.</p>

<h2 id="media">Audio and video</h2>
<p><code>audio</code> and <code>video</code> play sound and moving pictures without any plug-in. Add <code>controls</code> or the reader gets no way to start them. Give the file with <code>url</code> or, better, with one or more <code>source</code> children, each with its <code>type</code>. The browser takes the first one it can play, so list the best format first. The <code>content</code> text is shown only by a browser that cannot play the element at all.</p>
{{example.web-media-audio}}
<p><code>preload</code> says how much to fetch before the reader presses play: <code>none</code>, <code>metadata</code> (only the duration and size) or <code>auto</code>. <code>loop</code> starts again at the end, and <code>muted</code> starts silent. <code>autoplay</code> starts at once, but browsers usually refuse it for sound, so it works reliably only together with <code>muted</code>. A <code>video</code> also has <code>width</code> and <code>height</code>, a <code>poster</code> picture shown until it plays, and <code>plays inline</code>, which stops phones from forcing it to full screen.</p>
{{example.web-media-video}}
<p>The <code>track</code> element adds text to a video or an audio file from a WebVTT file. Its <code>kind</code> is <code>subtitles</code> (a translation), <code>captions</code> (speech and sounds, for the deaf), <code>descriptions</code>, <code>chapters</code> or <code>metadata</code>. <code>srclang</code> is the language of the text, <code>label</code> is the name in the menu, and <code>default</code> turns it on at the start. The file in the example does not exist. Real pages need captions for anything that is spoken.</p>

<h2 id="frames">Frames and embedded objects</h2>
<p><code>iframe</code> shows another page inside yours. The page can be an address in <code>url</code> or a short document written in <code>srcdoc</code>. Give it a <code>title</code> so screen readers can announce it, and a <code>width</code> and <code>height</code>. Use <code>loading = lazy</code> for frames far down the page.</p>
{{example.web-media-iframe}}
<p>A frame can bring a stranger's code into your page, so lock it down with <code>sandbox</code>. An empty <code>sandbox = ""</code> removes every permission: no scripts, no forms, no popups. You then give back only what the frame needs, by listing words such as <code>allow-scripts</code> or <code>allow-forms</code>, separated by spaces. Never combine <code>allow-scripts</code> with <code>allow-same-origin</code> for a page you do not trust. <code>allow</code> is a separate list for browser features, such as <code>"fullscreen; camera"</code>, and <code>allow fullscreen</code> permits the full screen button. <code>name</code> gives the frame a name for scripts, and <code>referrer policy</code> works as for links.</p>
<p><code>embed</code> and <code>object</code> place an external resource, such as a PDF, into the page. Both take a <code>url</code>, a <code>type</code> and a size. <code>embed</code> has no content. <code>object</code> shows its <code>content</code> when the browser cannot display the file, which is the place for a download link, and its <code>form</code> and <code>name</code> attributes connect it to a form. For a PDF, a plain <code>link</code> is often the better choice.</p>

<h2 id="drawing">Canvas, SVG and math</h2>
<p><code>canvas</code> is a blank rectangle you draw on with code. Set its size with the <code>width</code> and <code>height</code> attributes, which are the number of pixels of the drawing surface. A size set with CSS only stretches those pixels, and the drawing turns blurry. Drawing itself is done through the <code>dom</code> package. <code>dom.GetContext(canvas, "2d")</code> returns the drawing tool, <code>dom.SetStr</code> sets a property of it such as <code>fillStyle</code>, and <code>dom.Call4</code> calls one of its methods with four numbers. The example stamps a square where you click: <code>dom.GetNum(e, "offsetX")</code> reads the click position inside the canvas from the event. The two functions above the page, <code>stamp</code> and <code>wipe</code>, are connected to the canvas and the button with <code>click = stamp</code> and <code>click = wipe</code>.</p>
{{example.web-media-canvas}}
<p>Text inside the canvas element, if you add some, is shown only when the browser cannot draw, and screen readers cannot see into the drawing. Put any information the drawing carries into the page as text as well.</p>
<p><code>svg</code> draws with shapes that stay sharp at every size. The <code>content</code> of an <code>svg</code> is the markup of its shapes, written as it is, and it is not escaped, so use it only for markup you wrote yourself. <code>view box</code> is the coordinate system inside, four numbers <code>min-x min-y width height</code>, and <code>width</code> and <code>height</code> are the size on the page. The drawing scales to fit. <code>xmlns</code> is only needed when the SVG is a file of its own. <code>math</code> works the same way for mathematics, with MathML in its <code>content</code>: <code>mi</code> for a name, <code>mo</code> for an operator, <code>mn</code> for a number, <code>mfrac</code> for a fraction and <code>msup</code> for a power.</p>
{{example.web-media-svg}}

<h3 id="ref-frames">Frames and embedded objects</h3>
<h3 id="el-iframe"><code>iframe</code><span class="ref-alt"> (Persian: <code>قاب درونی</code>; HTML: <code>&lt;iframe&gt;</code>)</span></h3>
<p>A frame that shows another page inside this one. The page is an address in <code>url</code> or a short document in <code>srcdoc</code>. Give it a <code>title</code> and a size, and lock it down with <code>sandbox</code>.</p>
<pre class="code snip" dir="ltr"><code>iframe: url = &quot;https://example.com/widget&quot; title = &quot;Widget&quot; width = 400 height = 240 sandbox = &quot;allow-scripts&quot; end</code></pre>
<div class="table-wrap"><table class="ref-table"><thead><tr><th>Attribute</th><th>What it does</th><th>Example</th></tr></thead><tbody>
<tr id="at-iframe-width"><td><code>width</code><br><span class="ref-alt">عرض</span></td><td>The width of the frame. A bare number means pixels. Browsers give a frame 300 pixels by default. <small class="ref-accepts">[ulength]</small></td><td><code class="snip" dir="ltr">iframe: url = &quot;https://example.com/embed&quot; title = &quot;Embedded&quot; width = 480 height = 270 end</code></td></tr>
<tr id="at-iframe-height"><td><code>height</code><br><span class="ref-alt">ارتفاع</span></td><td>The height of the frame. A bare number means pixels. The default is 150 pixels. <small class="ref-accepts">[ulength]</small></td><td><code class="snip" dir="ltr">iframe: url = &quot;https://example.com/embed&quot; title = &quot;Embedded&quot; width = 480 height = 270 end</code></td></tr>
<tr id="at-iframe-name"><td><code>name</code><br><span class="ref-alt">نام</span></td><td>A name for the frame, so that scripts can find it as a named window. The page language accepts only the four words (<code>new</code>, <code>same</code>, <code>parent</code>, <code>top</code>) as the <code>target</code> of a link. <small class="ref-accepts">[string]</small></td><td><code class="snip" dir="ltr">iframe: name = &quot;preview&quot; title = &quot;Preview&quot; width = 300 height = 160 srcdoc = &quot;&lt;p&gt;Empty&lt;/p&gt;&quot; end</code></td></tr>
<tr id="at-iframe-referrer-policy"><td><code>referrer policy</code><br><span class="ref-alt">سیاست ارجاع</span></td><td>How much of this page's address is sent when the frame's page is requested, with the same words as for a link. <small class="ref-accepts">[enum: referrer_policy]</small></td><td><code class="snip" dir="ltr">iframe: url = &quot;https://example.com/embed&quot; title = &quot;Embedded&quot; width = 300 height = 160 referrer policy = &quot;no-referrer&quot; end</code></td></tr>
<tr id="at-iframe-loading"><td><code>loading</code><br><span class="ref-alt">بارگذاری</span></td><td>When to load the frame: <code>eager</code> at once or <code>lazy</code> when the reader scrolls close to it. Use <code>lazy</code> for a frame far down the page. <small class="ref-accepts">[enum: loading]</small></td><td><code class="snip" dir="ltr">iframe: url = &quot;https://example.com/map&quot; title = &quot;Map&quot; width = 400 height = 240 loading = &quot;lazy&quot; end</code></td></tr>
<tr id="at-iframe-srcdoc"><td><code>srcdoc</code><br><span class="ref-alt">محتوای سند</span></td><td>A complete small document, written as HTML text, to show in the frame instead of loading an address. It is escaped for you. <small class="ref-accepts">[string]</small></td><td><code class="snip" dir="ltr">iframe: title = &quot;Note&quot; width = 300 height = 80 srcdoc = &quot;&lt;p style=&#x27;font-family:sans-serif&#x27;&gt;Hello from the frame&lt;/p&gt;&quot; end</code></td></tr>
<tr id="at-iframe-allow-fullscreen"><td><code>allow fullscreen</code><br><span class="ref-alt">اجازه تمام‌صفحه</span></td><td>A boolean. With <code>true</code> the page in the frame may go full screen. <small class="ref-accepts">[bool]</small></td><td><code class="snip" dir="ltr">iframe: url = &quot;https://example.com/player&quot; title = &quot;Player&quot; width = 400 height = 240 allow fullscreen = true end</code></td></tr>
<tr id="at-iframe-sandbox"><td><code>sandbox</code><br><span class="ref-alt">قرنطینه</span></td><td>Restrictions for the frame. An empty value removes every permission. Words separated by spaces give some back: <code>allow-scripts</code>, <code>allow-forms</code>, <code>allow-popups</code>, <code>allow-same-origin</code> and others. Do not give <code>allow-scripts</code> and <code>allow-same-origin</code> together to a page you do not trust. <small class="ref-accepts">[string]</small></td><td><code class="snip" dir="ltr">iframe: url = &quot;https://example.com/form&quot; title = &quot;Form&quot; width = 400 height = 240 sandbox = &quot;allow-forms allow-scripts&quot; end</code></td></tr>
<tr id="at-iframe-allow"><td><code>allow</code><br><span class="ref-alt">اجازه</span></td><td>A list of browser features the frame may use, separated by semicolons, such as <code>fullscreen</code>, <code>camera</code>, <code>microphone</code> or <code>geolocation</code>. The default is to allow none for pages from another site. <small class="ref-accepts">[string]</small></td><td><code class="snip" dir="ltr">iframe: url = &quot;https://example.com/call&quot; title = &quot;Video call&quot; width = 400 height = 300 allow = &quot;camera; microphone&quot; end</code></td></tr>
<tr id="at-iframe-url"><td><code>url</code><br><span class="ref-alt">نشانی</span></td><td>The address of the page to show in the frame. Use <code>srcdoc</code> instead for a short document written right here. <small class="ref-accepts">[url]</small></td><td><code class="snip" dir="ltr">iframe: url = &quot;https://example.com/embed&quot; title = &quot;Embedded page&quot; width = 400 height = 200 end</code></td></tr>
</tbody></table></div>
<h3 id="el-embed"><code>embed</code><span class="ref-alt"> (Persian: <code>جاسازی</code>; HTML: <code>&lt;embed&gt;</code>)</span></h3>
<p>Places an external resource, such as a PDF, into the page (HTML <code>embed</code>). The <code>url</code> is required. It has no content, so there is no fallback text.</p>

<tr id="at-embed-height"><td><code>height</code><br><span class="ref-alt">ارتفاع</span></td><td>The height of the embedded area, in pixels when it is a bare number. <small class="ref-accepts">[ulength]</small></td><td><code class="snip" dir="ltr">embed: url = &quot;report.pdf&quot; type = &quot;application/pdf&quot; width = 500 height = 300 end</code></td></tr>
<tr id="at-embed-url"><td><code>url</code><br><span class="ref-alt">نشانی</span></td><td>The address of the resource, required. <small class="ref-accepts">[url]</small></td><td><code class="snip" dir="ltr">embed: url = &quot;slides.pdf&quot; type = &quot;application/pdf&quot; width = 400 height = 300 end</code></td></tr>

<h3 id="el-object"><code>object</code><span class="ref-alt"> (Persian: <code>شیء</code>; HTML: <code>&lt;object&gt;</code>)</span></h3>
<p>An external resource shown in the page, with fallback content (HTML <code>object</code>). The <code>url</code> is required. If the browser cannot show the file, it shows the children instead, which is the place for a link to download it.</p>

<h3 id="ref-drawing">Drawing</h3>
<h3 id="el-canvas"><code>canvas</code><span class="ref-alt"> (Persian: <code>بوم</code>; HTML: <code>&lt;canvas&gt;</code>)</span></h3>

<tr id="at-canvas-height"><td><code>height</code><br><span class="ref-alt">ارتفاع</span></td><td>The height of the drawing surface in pixels. <h3 id="el-svg"><code>svg</code><span class="ref-alt"> (Persian: <code>اس‌وی‌جی</code>; HTML: <code>&lt;svg&gt;</code>)</span></h3>
<p>A vector picture written in place (HTML <code>svg</code>). Its <code>content</code> is the markup of the shapes, inserted as written and not escaped, so use only markup you wrote yourself. The picture stays sharp at every size.</p>

<h3 id="el-math"><code>math</code><span class="ref-alt"> (Persian: <code>ریاضی</code>; HTML: <code>&lt;math&gt;</code>)</span></h3>
<p>A mathematical formula written in MathML (HTML <code>math</code>). Its <code>content</code> is the markup, inserted as written: <code>mi</code> for a name, <code>mn</code> for a number, <code>mo</code> for an operator, <code>mfrac</code> for a fraction, <code>msup</code> for a power, <code>msqrt</code> for a square root.</p>
<pre class="code snip" dir="ltr"><code>math: content = &quot;&lt;msqrt&gt;&lt;mi&gt;x&lt;/mi&gt;&lt;/msqrt&gt;&lt;mo&gt;=&lt;/mo&gt;&lt;mfrac&gt;&lt;mn&gt;1&lt;/mn&gt;&lt;mn&gt;2&lt;/mn&gt;&lt;/mfrac&gt;&quot; end</code></pre>
