<h2 id="settings">Settings of the page itself</h2>
<p>The first lines inside <code>page:</code>, before any element, describe the page and not something on it. <code>title</code> is the text on the browser tab, in bookmarks and in a search result. <code>lang</code> says which language the text is in, and the values are <code>en</code>, <code>fa</code> and <code>ar</code>. Screen readers choose their voice from it and browsers choose the right quotation marks and word breaks. <code>dir</code> sets the direction of the text: <code>ltr</code> or <code>rtl</code>, or the words <code>left to right</code> and <code>right to left</code>. <code>favicon</code> is the address of the small icon on the tab.</p>
<p>A file written in English starts with <code>lang = "en"</code> and <code>dir = "ltr"</code>, and a Persian file with <code>fa</code> and <code>rtl</code>, so you write these two only when the page differs from its file. Any style property written at this level, such as <code>background</code>, <code>color</code> or <code>font family</code>, styles the whole page body.</p>
{{example.web-head-settings}}
<p>The page does not show most of what you set here, so it is worth knowing what the compiler builds for you. Every page starts with <code>&lt;!doctype html&gt;</code>, then a head that holds <code>&lt;meta charset="utf-8"&gt;</code>, which makes every letter of every language display correctly, and <code>&lt;meta name="viewport" content="width=device-width, initial-scale=1"&gt;</code>, which tells phones to use the real screen width instead of pretending to be a wide desktop. You never have to write these two. Without a <code>title</code>, the tab says "Salam Page".</p>

<h2 id="head">Meta tags, links and base</h2>
<p>Some elements describe the page and are never drawn. You can write them anywhere inside <code>page:</code>, and the compiler moves them into the head: <code>meta</code>, <code>head link</code>, <code>base</code> and <code>style</code>.</p>
<p><code>meta</code> carries a fact as a pair, <code>name</code> and <code>content</code>. A <code>description</code> is the summary under a search result. <code>robots</code> with <code>noindex</code> asks search engines to skip the page. <code>theme-color</code> colours the browser bar on a phone. For link previews in chat apps, the Open Graph protocol uses <code>property</code> instead of <code>name</code>: <code>og:title</code>, <code>og:description</code>, <code>og:image</code>. And <code>http_equiv</code> lets a tag behave like an HTTP header.</p>
<p><code>head link</code> connects the page to another address and names the relation in <code>rel</code>. <code>stylesheet</code> loads CSS, <code>icon</code> sets an icon, <code>canonical</code> says which address is the real one when the same page can be reached in several ways, <code>preload</code> asks the browser to start downloading a font or image early, and <code>alternate</code> with a <code>hreflang</code> points to the translation. Its address is <code>url</code>. The name has two words so that it does not clash with <code>link</code>, the clickable link in the body.</p>
<p><code>base</code> changes the address that all relative addresses start from. It can help a page that lives deep in a site, but it changes every relative link and file after it, so most pages leave it out.</p>
<p>The example below puts a <code>description</code> and a <code>canonical</code> link in its head, and a button reads them back with <code>dom.Query</code>, which finds an element by a CSS selector, and <code>dom.GetAttr</code>, which reads one of its attributes.</p>
{{example.web-head-inspect}}
<div class="note"><p>The compiler already writes the <code>charset</code> and the <code>viewport</code> tags. Writing a second <code>charset</code> only gives the page two of them. Add a <code>meta</code> to say something the compiler cannot know: the description, the author, the preview of the page.</p></div>

<h2 id="scripts">Styles, scripts and noscript</h2>
<p>Salam has style properties and event attributes for most work, but two elements are kept for raw text. <code>style</code> holds plain CSS in its <code>content</code>, for the things the properties do not cover: <code>@keyframes</code>, custom properties, rules for printing or for dark mode. With <code>media</code> the rules apply only when the query matches. Like <code>meta</code>, it moves to the head.</p>
<p><code>script</code> holds JavaScript, either in <code>content</code> or in a file given with <code>url</code>. Unlike the elements above, a script stays where you write it, so put it after the elements it changes. If the code contains double quotes, write the string between backticks. Four attributes decide when a script from a file runs. A classic script runs the moment the browser reaches it, and stops the page until it is done. <code>defer</code> downloads the file while the page is read and runs it after the whole page is read, in order. <code>async</code> runs it the moment it has arrived, in any order, which suits an independent script such as statistics. <code>type = "module"</code> makes it an ES module and also waits for the page like <code>defer</code>. <code>nomodule</code> is the opposite switch: browsers that know modules skip it, so it is a fallback for very old ones. For a script from another site, add <code>integrity</code> (a hash of the file you expect) and <code>crossorigin</code>, so that a changed file cannot run on your page.</p>
<p>In the example two scripts write into the same paragraph. The module script is written first, but the classic script comes out first, because the module waits for the page.</p>
{{example.web-head-script}}
<p><code>noscript</code> is shown only when scripts are off or blocked. Give it a short message or a plain fallback, so that a visitor without JavaScript sees something useful instead of an empty space. In the preview above the script ran, so you cannot see it.</p>

<h2 id="shadow">Templates, slots and shadow trees</h2>
<p>A <code>template</code> is a block of elements that the browser reads but does not draw. Scripts copy it to build new pieces of a page. Give it <code>shadowrootmode</code> and it becomes something more useful: the private inside of its parent element, called a shadow tree. Styles from the rest of the page do not enter a shadow tree and its styles do not leak out, which makes it a good place for a self-contained widget.</p>
<p>The parent element is the host. Its own children are not drawn directly. They are shown in the <code>slot</code> elements of the shadow tree: a slot with a <code>name</code> takes the children whose <code>slot</code> attribute is that name, and an unnamed slot takes the rest. What you write inside a slot is shown only when nothing was given for it.</p>
{{example.web-head-shadow}}
<p>Here <code>shadowrootmode = "open"</code> lets scripts reach the tree through <code>element.shadowRoot</code>, and <code>closed</code> hides it. Three more attributes, <code>shadowrootdelegatesfocus</code>, <code>shadowrootclonable</code> and <code>shadowrootserializable</code>, are switches for focus, copying and saving, and are listed in the reference. A shadow tree can open a door for outside styles: give an inside element a <code>part</code> and the page can style it with <code>::part(name)</code>, and <code>exportparts</code> passes parts through one more level.</p>
<div class="note"><p>A <code>style:</code> element moves to the head, even if you write it inside a template, so it styles the outside page and not the shadow tree. Inside a shadow tree, style an element with <code>inline style</code>, as the example does.</p></div>

<h2 id="global">Attributes that every element has</h2>
<p>A few attributes work on any element, whatever its name. You already know <code>content</code>, the text of the element. These are the ones to learn first.</p>
<p><code>id</code> names one element, uniquely in the page. Links, labels and scripts find the element by it, and the compiler checks the ids that you write in the same page, so a wrong name in <code>dom.ById</code> is an error at build time and not a silent bug. <code>class</code> is a group name. Salam makes its own classes for your style properties and shares one class between elements with identical styles, so you rarely write one yourself. When you do, remember the rule: two elements with the same class and different style properties are an error (E136), because they would fight over the class. <code>title</code> is a tooltip, and it does not show on touch screens, so it is only a hint. <code>inline style</code> takes a string of CSS and overrides everything else, which makes it the last choice. <code>hidden</code> hides an element. With <code>until-found</code> the element is hidden but the browser can still find its text in a search and open it.</p>
<p>The next group is about how a visitor works with the element. <code>tabindex = 0</code> puts an element in the Tab order, and <code>-1</code> lets only a script focus it. <code>accesskey</code> gives it a shortcut key. <code>contenteditable</code> lets the visitor edit its content. <code>draggable</code> lets them drag it. <code>inert</code> turns an element and everything in it off. <code>autofocus</code> moves the cursor into an element when the page opens. The example below makes a note editable, reads it on every keystroke with an <code>input</code> handler, and shows it in a second paragraph.</p>
{{example.web-head-editable}}
<p>For text input there are hints for phone keyboards: <code>inputmode</code> picks the keyboard, <code>enterkeyhint</code> labels the Enter key, and <code>autocapitalize</code>, <code>autocorrect</code>, <code>spellcheck</code> and <code>writingsuggestions</code> control what the keyboard and the browser do to the text. <code>lang</code> and <code>dir</code> work on a single element too, so an English name inside a Persian paragraph can carry its own direction. <code>translatable = "no"</code> asks translation tools to leave a word, such as a brand name, as it is.</p>
<div class="note"><p>Do not hide important text only with <code>title</code> or <code>accesskey</code>. They help some visitors and are invisible to others. Write what matters as ordinary visible text.</p></div>

<h2 id="popover">Popovers without a script</h2>
<p>A popover is a box that stays hidden until something opens it, and then floats above the page. The browser does all the work: no handler, no <code>hidden</code> toggling, no z-index. Give the box <code>popover</code> and an <code>id</code>. Give a button <code>popover target</code> with the same id. With <code>popover = "auto"</code> the box closes when the visitor clicks outside it or presses Escape, and it closes other auto popovers first. With <code>manual</code> it stays until something closes it. A second attribute, <code>popover target action</code>, says what the button does: <code>toggle</code> (the default), <code>show</code> or <code>hide</code>.</p>
{{example.web-head-popover}}

<h2 id="aria">ARIA: when the element is not enough</h2>
<p>Screen readers and other assistive tools do not see your page. They read what the browser knows about each element: its role, its name, and its state. A <code>button</code> is known as a button, a <code>list</code> as a list, and nothing more is needed. The first rule of ARIA is to use the native element when one exists. ARIA attributes exist for the cases where you build something by hand or the state changes: <code>role</code> names what a plain box is (<code>progressbar</code>, <code>status</code>, <code>tablist</code>), and the attributes written <code>aria</code> and a name add a label, a state or a link between elements.</p>
<p>Three are used all the time. <code>aria label</code> gives a name to an element without visible text, such as a button that holds only an icon. <code>aria hidden</code> hides decoration from screen readers. <code>aria expanded</code> and <code>aria controls</code> say that a button opens or closes something, and which element it is. The browser does not keep <code>aria expanded</code> up to date. Your code must change it each time the state changes, as the example does.</p>
{{example.web-head-aria}}
<p>The handler flips a variable, sets <code>aria-expanded</code> to the new value with <code>dom.SetAttr</code>, changes the button text, and shows or hides the list with <code>dom.SetBool</code> on its <code>hidden</code> property. Any other ARIA attribute is written the same way: <code>aria</code>, a space, then the name, such as <code>aria live</code> or <code>aria describedby</code>.</p>
<div class="note"><p>A wrong ARIA attribute is worse than none: a <code>role = "button"</code> on a box tells the reader that it is a button, but does not make it focusable or answer to the Enter key. When a native <code>button</code> can do the job, use it.</p></div>

<h2 id="data">Data attributes</h2>
<p>Sometimes an element needs to carry a small fact for your own code: the id of a record, a price, a mode. For that, write <code>data</code>, a space and a name. <code>data price = "12"</code> becomes <code>data-price</code> in the HTML, and several words are joined with hyphens. Values are always strings. The attribute is invisible, CSS can match it with a selector like <code>[data-mode='dark']</code>, and a handler can read it with <code>dom.GetAttr</code>.</p>
<p>In the example all three buttons share one handler. It receives the event, asks <code>dom.EventTarget</code> which button was clicked, and reads that button's data. This is a good way to avoid writing one function for each button.</p>
{{example.web-head-data}}
<p>Names such as <code>mode</code>, <code>lang</code>, <code>view</code>, <code>only</code> and <code>id</code> are listed in the reference, but only as examples of the pattern. Any name works. Write the name in English letters if a script has to read it.</p>

<h2 id="parts">Splitting a site into parts</h2>
<p>A page that repeats the same box ten times, or ten pages that repeat the same footer, are signs that you need parts. Salam has three tools. A <code>component</code> is a named, reusable element with parameters. Inside it, <code>content: end</code> marks the place where the children written at the call go. A <code>const</code> above the page holds a value that is used in several places. <code>repeat</code> on an element writes it that many times. The example below uses all three.</p>
{{example.web-head-component}}
<p>The third tool is <code>include</code>, which pulls another file into this one. Put your components, or a footer shared by every page, into a file of their own, and include it at the top of each page:</p>
<pre class="code"><code>component Panel(title):
    section:
        heading: size = 3 content = title end
        content: end
    end
end
</code></pre>
<p>This is <code>parts.salam</code>, which contains only the component. Then every page that needs it says:</p>
<pre class="code"><code>page:
    include = "parts.salam"
    Panel: title = "Hours"
        paragraph: content = "Every day from 7 to 19." end
    end
end
</code></pre>
<h3 id="ga-include"><code>include</code></h3>
<p>The path is relative to the file that includes the other one. An included file may hold components and also a <code>page:</code> block, whose elements are placed where the <code>include</code> is. Including a file that does not exist is a build error, and so is a file that includes itself.</p>

<h2 id="reference">Reference: head elements and global attributes</h2>
<p>Below are the elements that live in the head or around it, then the global attributes, ARIA and data attributes. Every example is checked by the compiler. Persian names work in any file, and the Persian lessons use them.</p>
<h3 id="el-page"><code>page</code><span class="ref-alt"> (Persian: <code>صفحه</code>)</span></h3>
<p>The page block itself. It is not an HTML tag: it stands for the whole document. Directly inside it you can set <code>title</code>, <code>lang</code>, <code>dir</code> and <code>favicon</code>, any style property (it styles the page body), and then the elements of the page. The compiler writes the <code>&lt;head&gt;</code> for you, with <code>charset</code> and <code>viewport</code> already in it.</p>
<pre class="code snip" dir="ltr"><code>page:
    title = &quot;Corner Bakery&quot;
    lang = &quot;en&quot;
    background = &quot;#fdf6ec&quot;
    paragraph: content = &quot;Fresh bread every morning.&quot; end
end</code></pre>

<h3 id="el-head-link"><code>head link</code><span class="ref-alt"> (Persian: <code>پیوند سر</code>; HTML: <code>&lt;link&gt;</code>)</span></h3>
