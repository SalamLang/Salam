<h2 id="properties">Style properties are attributes</h2>
<p>A style property is written exactly like any other attribute: <code>name = value</code> inside the element. Property names have spaces where CSS has dashes, so <code>max-width</code> is <code>max width</code> and <code>border-radius</code> is <code>border radius</code>. A misspelled name is a compile error, and the message suggests the nearest real one.</p>
<p>The styles do not stay on the element. The compiler collects the styles of each element into one rule under a short generated class and puts the rules into the stylesheet. <code>box: padding = 20 background = "#eef" end</code> turns into <code>&lt;div class="a"&gt;</code> and the rule <code>.a{padding:20px;background:#eef}</code>. Elements whose styles are identical share one class, which keeps the page small.</p>
<div class="note"><p>You can also give an element a <code>class</code> of your own, but a class name must mean one set of styles. If two elements use the same <code>class</code> with different styles, the compiler stops with error E136 instead of letting one silently override the other. Give each its own class, drop the <code>class</code> and let the compiler name it, or style the shared class once with a <code>global</code> rule (shown below).</p></div>

<h2 id="values">Values</h2>
<p>Most values are one of four things. A <strong>bare number</strong> is pixels where a length is expected: <code>padding = 24</code> is <code>24px</code>, and <code>1.5</code> is <code>1.5px</code>. Properties that take a plain number, such as <code>line height</code> and <code>aspect ratio</code>, keep it as a number. A <strong>string</strong> holds anything else: units, colors with <code>#</code>, several words. A <strong>keyword</strong> can be written without quotes: <code>display = flex</code>, <code>overflow = hidden</code>, <code>color = white</code>. And a <strong>function</strong> with simple arguments can be unquoted too, as in <code>background = rgb(37, 99, 235)</code>.</p>
<p>Several lengths in one string form a shorthand. <code>padding = "8 40"</code> is <code>8px 40px</code>: the first number is for top and bottom, the second for left and right. Up to four values are allowed, and a number without a unit gets <code>px</code> while a number with a unit keeps it, so <code>"1rem 2"</code> is <code>1rem 2px</code>.</p>
{{example.web-css-values}}
<p>Values can also be computed while compiling: <code>padding = GAP * 2 + "px"</code> uses a constant (the section on reuse below shows how it is declared), and <code>+</code> joins a number and a unit into text.</p>
<div class="note"><p>Quote any value that has a <code>#</code>, a <code>%</code> or a unit inside a function, or a space-separated list. The compiler does not accept them bare, and <code>calc()</code> written without quotes is worse: it is accepted and silently becomes an empty <code>calc()</code>. Always write <code>width = "calc(100% - 20px)"</code>.</p></div>

<h2 id="units">Units</h2>
<p>A length is a number and a unit. The ones you will use all the time:</p>
<ul>
<li><code>px</code>: a CSS pixel. Good for borders and fine details.</li>
<li><code>rem</code>: the font size of the page, normally 16px. Sizes in <code>rem</code> grow when a reader raises the font size in the browser, so use it for text and spacing.</li>
<li><code>em</code>: the font size of the element itself, which makes a padding follow the text size of its own box.</li>
<li><code>%</code>: a share of the parent. For widths and horizontal padding and margin it is the parent's width, for a height it is the parent's height.</li>
<li><code>vw</code> and <code>vh</code>: one percent of the width or height of the window. <code>vmin</code> and <code>vmax</code> take the smaller or larger of the two.</li>
<li><code>ch</code>: the width of the digit 0 in the current font. <code>max width = "65ch"</code> keeps lines of text at a readable length.</li>
<li><code>cm</code>, <code>mm</code> and <code>in</code>: real-world lengths, meant for printing.</li>
</ul>
{{example.web-css-units}}
<p>The unit <code>fr</code>, a share of the free space in a grid, belongs to <a href="/learn/css-layout/">the layout lesson</a>.</p>

<h2 id="colors">Colors</h2>
<p>Wherever a color is expected you can write it in any CSS notation. The text color, the background and the fancy fills have their own lessons (<a href="/learn/css-backgrounds/">backgrounds and colors</a>); this is only the list of ways to write the value.</p>
<ul>
<li>A name: <code>teal</code>, <code>crimson</code>, <code>white</code>.</li>
<li>Hex: <code>"#0f766e"</code>, the short <code>"#fa0"</code>, and with transparency <code>"#0f766e80"</code>.</li>
<li><code>rgb(37, 99, 235)</code>: red, green and blue from 0 to 255. With transparency write <code>"rgb(37 99 235 / 50%)"</code>.</li>
<li><code>hsl(160, 84%, 39%)</code>: hue as an angle on the color wheel, then saturation and lightness. Easy to adjust by hand.</li>
<li><code>oklch(0.7 0.15 30)</code>: lightness, chroma and hue in a space where equal steps look equal.</li>
<li><code>color-mix(in srgb, red 40%, white)</code>: a blend of two colors.</li>
<li><code>transparent</code> and <code>currentColor</code>. The second is the element's own text color, so a border written with it follows the text.</li>
</ul>
{{example.web-css-colors}}

<h2 id="box">The box model</h2>
<p>Every element is a rectangular box made of four layers, from the inside out. The <strong>content</strong> is the text or the children. <strong>Padding</strong> is the room between the content and the border, and it shows the element's background. The <strong>border</strong> is the line around the padding. The <strong>margin</strong> is empty space outside the border that keeps other boxes away. Padding and margin both take one to four values, in the order top, right, bottom, left, and each side also has its own property: <code>padding top</code>, <code>margin left</code> and so on.</p>
{{example.web-css-box}}
<p>The next question is what <code>width = 240</code> measures. By default (<code>content-box</code>) it measures only the content, so a box with 20px of padding and a 6px border on each side is really <code>240 + 40 + 12 = 292</code> pixels wide, and a layout of several such boxes never adds up the way you wrote it. With <code>box sizing = "border-box"</code> the width includes padding and border, and 240 means 240. Click the button to see the same box measured both ways.</p>
{{example.web-css-boxsizing}}
<p>That is why nearly every page begins with the same line. A <code>global</code> element with no selector styles every element on the page:</p>
<pre class="code snip" dir="ltr"><code>global: box sizing = "border-box" end</code></pre>

<h2 id="sizes">Width, height and their limits</h2>
<p><code>width</code> and <code>height</code> set the size. By default a block is as wide as its parent and as tall as its content, and <code>auto</code> names that default. A percentage is a share of the parent, though a percentage <code>height</code> only works when the parent has a height of its own. Since a fixed size breaks when the window or the text changes, you will mostly set limits instead: <code>min width</code> and <code>max width</code>, <code>min height</code> and <code>max height</code>. A minimum beats a maximum, and a maximum beats the width. The sizes <code>min-content</code>, <code>max-content</code> and <code>fit-content</code> size a box by its text. <code>aspect ratio</code> keeps a box in shape (<code>"16 / 9"</code>) when you give one side and leave the other free.</p>
{{example.web-css-sizes}}
<p>A very common recipe is <code>width = "100%"</code> with <code>max width = "40rem"</code>, optionally with <code>margin = "0 auto"</code> to center it: a box that fills a phone and stops growing on a monitor.</p>

<h2 id="logical">Logical properties</h2>
<p>Left and right are physical directions. A page in English starts its lines on the left, a Persian page on the right, and a layout built from <code>margin left</code> has to be rewritten for the other language. Logical properties name the sides by the flow of the text. The <strong>inline</strong> direction is the one the text runs in and the <strong>block</strong> direction is the one the lines stack in. In English and Persian that makes inline horizontal and block vertical, and <code>start</code> is where a line begins: left in English, right in Persian.</p>
<p>So <code>inline size</code> is the width and <code>block size</code> the height, <code>margin inline start</code> and <code>padding inline end</code> are the sides at the start and the end of a line, and <code>margin block</code> and <code>padding block</code> are top and bottom. The example gives two boxes the very same styles and sets <code>dir</code> on the wrappers: the indent and the stripe change sides on their own.</p>
{{example.web-css-logical}}
<p>For a site in both languages, logical properties are usually the better choice. Use <code>left</code> and <code>right</code> when you really mean the screen: a shadow that must fall to the right, for instance.</p>

<h2 id="margins">Margins in practice</h2>
<p>Four rules about margins explain most surprises.</p>
<ul>
<li><strong>Centering.</strong> A block with a width and <code>margin = "0 auto"</code> is centered: <code>auto</code> splits the free space between the two sides. A block without a width fills the parent, so there is nothing to split.</li>
<li><strong>Collapsing.</strong> When two blocks are stacked, the margin between them is not the sum of the two but the larger one. A <code>margin bottom = 40</code> above a <code>margin top = 20</code> leaves 40. The same happens between a parent and its first or last child when nothing (padding, border, a height) separates them. Margins inside a flex or grid layout never collapse.</li>
<li><strong>Negative margins.</strong> A margin may be negative, which pulls the element toward its neighbour or out of its parent. Use it sparingly; it hides the real structure.</li>
<li><strong>Which one to use.</strong> Padding when the space should be part of the box and show its background, margin when it should push other boxes away.</li>
</ul>
{{example.web-css-margins}}

<h2 id="display">Display and visibility</h2>
<p><code>display</code> decides how an element takes part in the layout. <code>block</code> starts a new line and fills the width, <code>inline</code> sits inside a line of text and ignores <code>width</code> and <code>height</code>, and <code>inline-block</code> sits in a line but obeys them. <code>flex</code> and <code>grid</code> turn the element into a container that lays out its children, which is the whole topic of <a href="/learn/css-layout/">the layout lesson</a>. <code>contents</code> removes the element's own box and lets its children take part in the parent's layout as if it were not there, and <code>flow-root</code> makes a box that contains everything inside it, floats included. Every element starts with a default: a <code>box</code> is block and a <code>span</code> is inline.</p>
{{example.web-css-display}}
<p>To hide an element you have two choices that behave differently. <code>display = none</code> takes it out of the page completely: it has no box and the following elements move up. <code>visibility = hidden</code> only stops it being drawn: the gap stays. In both cases the element cannot be clicked, cannot receive keyboard focus and is skipped by screen readers. The two buttons below set the style from a script, so you can watch the paragraph that follows.</p>
{{example.web-css-hiding}}

<h2 id="overflow">Overflow</h2>
<p>What happens when the content is bigger than its box is the job of <code>overflow</code>. With <code>visible</code>, the default, it spills out and covers what is next to it. <code>hidden</code> cuts it at the border, <code>scroll</code> always shows scrollbars, and <code>auto</code> shows them only when there is something to scroll, which is nearly always what you want. <code>clip</code> cuts like <code>hidden</code> but never allows scrolling, even from a script, and it is the only value that works with <code>overflow clip margin</code>. <code>overflow x</code> and <code>overflow y</code> set one direction at a time, and <code>overflow block</code> and <code>overflow inline</code> are their logical forms, which fewer browsers know today.</p>
{{example.web-css-overflow}}
<div class="note"><p>A box with a fixed <code>height</code> and a lot of text is the usual cause of text running over the next paragraph. Prefer <code>min height</code>, or give the box an <code>overflow</code> value on purpose. The values <code>hidden</code>, <code>scroll</code> and <code>auto</code> also stop a child's margin from escaping through the box, and make the box contain its floats.</p></div>

<h2 id="functions">calc, min, max, clamp and var</h2>
<p>CSS can do arithmetic where a length goes. <code>calc()</code> mixes units: <code>"calc(100% - 80px)"</code> is everything but 80 pixels, and the spaces around <code>+</code> and <code>-</code> are required. <code>min()</code> picks the smallest of its arguments and <code>max()</code> the largest, so <code>"min(100%, 20rem)"</code> says "at most 20rem". <code>clamp(least, ideal, most)</code> is the pair in one: <code>"clamp(1rem, 4vw, 2rem)"</code> is a font size that scales with the window but stays between 1 and 2 rem.</p>
<p><code>var()</code> reads a CSS custom property, a value you name yourself. They are declared in raw CSS, which you give to a <code>style</code> element at the top of the page. The name starts with two dashes, and it can be used anywhere below through <code>"var(--brand)"</code>.</p>
{{example.web-css-functions}}
<p>The difference from the constants of Salam is when the value is known. A constant is fixed while compiling. A custom property lives in the browser, so it can change with the window size, with a dark mode rule, or from a script.</p>

<h2 id="global">Global rules</h2>
<p>Styles on an element are the right tool for that element. The <code>global</code> element is for everything else: a rule for a whole kind of element, or for the page. Its <code>selector</code> is any CSS selector, written as text. A tag name styles every element of that kind, <code>".tip"</code> every element with that class, <code>"#lead"</code> one element with that id, and <code>"li:nth-child(odd)"</code> or <code>"nav a"</code> pick by position or place. Leave the selector out and the rule applies to every element, which is how the <code>box sizing</code> line above works.</p>
{{example.web-css-global}}
<p>Two details to know. The selector is passed to the stylesheet as written, so the compiler cannot tell you that it is misspelled. And when two rules reach the same element the more specific one wins: a class beats a tag, an id beats a class. Use <code>global</code> for defaults and shared classes, element styles for what is unique.</p>

<h2 id="reuse">Constants and components</h2>
<p>Write a number once and use it everywhere. A <code>const</code> above the page holds a value that is worked out while compiling, and style values may use it in expressions: <code>padding = GAP * 2 + "px"</code>. A <code>component</code> does the same for a whole piece of page: it takes parameters, builds a styled element tree, and <code>content: end</code> marks where the children of each use go. Parameters work in styles too: a value such as <code>overflow = mode</code> reads the parameter <code>mode</code>. Uses with identical styles share one generated class, so a card used ten times adds one rule.</p>
{{example.web-css-components}}

<h2 id="speed">Skipping work for big pages</h2>
<p>Three properties help a long page load and scroll faster, at the price of some promises. <code>contain</code> tells the browser that the inside of an element does not affect anything outside it, so a change inside never needs the whole page to be laid out again. <code>content visibility = auto</code> goes further: the browser does not draw or lay out the element while it is far off screen. Because a skipped element has no height, add <code>contain intrinsic size</code> with a guess, <code>auto 600px</code> meaning "use the real size once you have seen it, and 600px before". Use it on the sections of a page that is long, not on small pages, where it only adds risk.</p>
<pre class="code snip" dir="ltr"><code>section:
    content visibility = auto
    contain intrinsic size = "auto 600px"
    heading: size = 2 content = "Far down the page" end
    paragraph: content = "Drawn only when the reader scrolls near it." end
end</code></pre>

<h2 id="more">Reset and field sizing</h2>
<p><code>all</code> resets every property of an element at once. Only the keywords that work for any property are allowed: <code>initial</code>, <code>inherit</code>, <code>unset</code> and <code>revert</code>. Put it first and then add back the styles you want, the way the reference example turns a button into a plain box. <code>field sizing = content</code> lets a text box grow while the user types, with no script, in browsers that support it. The properties <code>appearance</code>, <code>resize</code> and <code>zoom</code> are in <a href="/learn/css-responsive/">the responsive lesson</a>.</p>
{{example.web-css-fieldsizing}}
