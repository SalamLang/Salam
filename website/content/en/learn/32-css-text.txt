<h2 id="family">Choosing a font</h2>
<p>You cannot know which fonts a visitor has installed. <code>font family</code> therefore takes a list, called a font stack: the browser tries the names from left to right and uses the first font that exists and has the letters it needs to draw. A name that contains spaces goes in single quotes inside the string. The last name should be a generic family, which every browser can always fill: <code>serif</code> (letters with small feet), <code>sans-serif</code> (without feet), <code>monospace</code> (equal width, for code), <code>cursive</code> and <code>fantasy</code> (decorative, and different on every system) and <code>system-ui</code> (the font of the operating system's own windows). <code>ui-monospace</code> is the system's code font.</p>
{{example.web-font-family}}
<p>Look at the last line of the preview. The first name does not exist, so the browser skips it silently and takes the next. This is also how a missing Persian glyph is handled: if the first font has no such letter, the browser asks the next font in the list for that single letter.</p>
<p>Put the rule on <code>body</code> with a <code>global</code> element, as the examples do, and every element inherits it. Only set <code>font family</code> on a single element when that element really needs a different font, such as code.</p>

<h2 id="size">Size</h2>
<p><code>font size</code> accepts a bare number (pixels), or a string with a unit. The useful units are <code>rem</code>, which is relative to the font size of the whole page, <code>em</code> and <code>%</code>, which are relative to the parent element, and <code>vw</code>, which is a part of the window width. There are also keywords from <code>xx-small</code> to <code>xx-large</code>, and <code>clamp(min, preferred, max)</code>, which grows with the window but never leaves the two limits. Prefer <code>rem</code> to pixels for text: people who raise the default size in their browser then get bigger text on your page too.</p>
{{example.web-font-size}}
<p>The second line is an expression. Any number or string that the compiler can compute is a valid value, so you can also use a constant declared above the page, such as <code>font size = BASE * 2</code>, and change one number to resize many elements.</p>
<p>Before the next sections, try the settings yourself. The slider and the list below run small functions that use the <code>dom</code> package, which is explained in <a href="/std/dom/">its own page</a>. Each time the slider moves, its function reads the value and sets the CSS property <code>font-size</code> of the sample. Inside such a function, CSS properties keep their original names with dashes.</p>
{{example.web-font-tester}}

<h2 id="weight">Weight, style and width</h2>
<p><code>font weight</code> is a number from 1 to 1000: 400 is normal text, 700 is bold. <code>normal</code> and <code>bold</code> are the same as 400 and 700, and <code>bolder</code> and <code>lighter</code> move one step away from the parent. A font file has only the weights its designer drew. If you ask for 300 and the font has 400 and 700, the browser shows 400, so in the preview below the first lines may look equal. <code>font style</code> chooses upright, <code>italic</code> (a separate design) or <code>oblique</code> (the upright letters leaned over). <code>font stretch</code> and its newer name <code>font width</code> choose narrower or wider designs and only matter for fonts that have them.</p>
{{example.web-font-weight}}
<p>The last line uses the shorthand <code>font</code>. It sets style, weight, width, size, line height and family in one string, in this order, with the line height after a slash. Only the size and the family are required.</p>
<div class="note"><p>The shorthand <code>font</code> resets every property it does not mention. If you write <code>font = "16px serif"</code> after a <code>font weight = 700</code> on the same element, the weight is back to 400. When you only want to change one thing, write that one property.</p></div>
<p>If a font has no bold or italic design, the browser fakes one by thickening or leaning the normal letters. The result is often a little ugly. <code>font synthesis</code> forbids this, and its parts <code>font synthesis weight</code>, <code>font synthesis style</code>, <code>font synthesis small caps</code> and <code>font synthesis position</code> forbid a single kind of faking.</p>

<h2 id="webfonts">Web fonts</h2>
<p>To use a font that visitors do not have, ship the file with the page. The <code>font</code> element describes one file: <code>name</code> is the name you will use in <code>font family</code>, and <code>url</code> is the address of the file. Salam turns it into an <code>@font-face</code> rule, and the browser downloads the file only when some text uses the font. When one family has several files, write one <code>font</code> element per file with the same name and the <code>weight</code> or <code>style</code> that the file provides.</p>
{{example.web-font-face}}
<p>The two files of this example do not exist in the preview, so the page shows the next font of the stack. That is the right way to build a page: the fallback must always be good enough to read. On your own site, put the files in a folder that your server serves, and the page starts using them. Salam checks the address while compiling: an unsafe address is an error, and a relative file that cannot be found next to the program is a warning. If you leave out <code>type</code>, Salam finds out the format from the end of the address.</p>
<p>Three attributes shape the loading. <code>display = swap</code> shows the fallback font at once and swaps in the real one when it arrives, so the text is never invisible. <code>range</code> lists the Unicode ranges a file covers, so a Persian file is downloaded only by pages that contain Persian letters. <code>weight</code> can be a range such as <code>"100 900"</code> for a variable font.</p>
<div class="note"><p>Every font file is a download, and a page that waits for five of them feels slow. Use one or two families, only the weights you really use, and the <code>woff2</code> format, which is the smallest. And check the licence: a font on your computer is not always a font you may publish.</p></div>

<h2 id="variants">Features, variants and variable fonts</h2>
<p>A good font contains more than letters: small capitals, several kinds of digits, ligatures (shapes where two letters join, such as fi) and alternate forms. They are called OpenType features, and each has a four letter tag such as <code>smcp</code> or <code>liga</code>. The properties that start with <code>font variant</code> switch the common ones in words: <code>font variant caps</code>, <code>font variant numeric</code>, <code>font variant ligatures</code>, <code>font variant position</code>, <code>font variant alternates</code>, <code>font variant east asian</code> and <code>font variant emoji</code>. <code>font feature settings</code> is the raw version for the rest: <code>"'smcp' 1"</code> turns a feature on, and 0 turns it off. <code>font kerning</code> controls the pair spacing, which is on by default and should stay on.</p>
{{example.web-font-variants}}
<p>A variable font is one file that contains a whole range of designs along axes, such as weight (<code>wght</code>) or width (<code>wdth</code>). <code>font variation settings</code> sets the axes by their tag, and <code>font optical sizing</code> lets a font with an optical size axis change its shape with the text size. When an ordinary property exists, use it: <code>font weight = 650</code> sets the weight axis and is easier to read. <code>font palette</code> picks one of the colour sets of a colour font.</p>
<div class="note"><p>Features only work if the font has them. A font without small capitals shows the normal letters or, in some browsers, faked ones, and a line in the preview above may look unchanged. Test with the font you really use.</p></div>

<h2 id="align">Aligning and transforming text</h2>
<p><code>text align</code> places the lines of a block. Use <code>start</code> and <code>end</code> and not <code>left</code> and <code>right</code>: they follow the direction of the text, so the same rule is correct for English and for Persian. <code>center</code> centres every line and <code>justify</code> stretches every line but the last to the full width. <code>text align last</code> sets the last line separately, and <code>text justify</code> chooses whether the extra space goes between words or between letters. <code>text indent</code> pushes the first line in, the way books mark a new paragraph. <code>text transform</code> changes the case of the shown letters without changing the text, which is better than typing capitals because a screen reader and a search still see the real text.</p>
{{example.web-font-align}}
<p>Justified text needs wide lines. In a narrow column the gaps between words become large and uneven, so use <code>justify</code> only for wide blocks.</p>

<h2 id="decoration">Lines, shadows and outlines</h2>
<p><code>text decoration</code> draws lines on text. It is a shorthand of four properties: <code>text decoration line</code> (<code>underline</code>, <code>overline</code>, <code>line-through</code>), <code>text decoration style</code> (<code>solid</code>, <code>double</code>, <code>dotted</code>, <code>dashed</code>, <code>wavy</code>), <code>text decoration color</code> and <code>text decoration thickness</code>. Two more properties tune underlines: <code>text underline offset</code> moves the line away from the letters, and <code>text decoration skip ink</code> decides if the line jumps over the tails of letters like g and y. <code>text shadow</code> adds one or more shadows, each as horizontal offset, vertical offset, blur and colour; two shadows of the same colour make a glow. <code>webkit text stroke</code> and <code>webkit text fill color</code> outline letters; the name starts with <code>webkit</code> because browsers adopted the idea under that prefix, and all of them still use it.</p>
{{example.web-font-decoration}}
<div class="note"><p>People expect an underline to mean a link. Do not underline other text, and do not remove the underline of real links without another clear sign, such as a different colour plus a weight. Shadows and outlines also reduce contrast, so check that the text stays readable.</p></div>

<h2 id="spacing">Line height and spacing</h2>
<p><code>line height</code> is the most important property for reading. Give it a plain number, without a unit: <code>1.6</code> means 1.6 times the font size of that element, and a child with a larger size gets a larger line height by itself. A length such as <code>"24px"</code> is passed to the children as a fixed result and makes big headings overlap. Around 1.5 suits English, and Persian needs about 1.9 because of its dots and marks above and below the line. <code>letter spacing</code> and <code>word spacing</code> add space between letters and between words. A small positive letter spacing is good for capitals, and a tiny negative one for very large headings. <code>vertical align</code> moves an inline element up or down within the line, as <code>super</code> and <code>sub</code> do for powers and indices. <code>tab size</code> sets the width of a tab character in preformatted text.</p>
{{example.web-font-spacing}}
<div class="note"><p>Do not use <code>letter spacing</code> on Persian or Arabic. The letters of these scripts are joined, and a gap between them cuts the word into pieces. Browsers treat it differently, and where a gap is added it cuts the word apart, so the safe value is always <code>0</code> or nothing.</p></div>

<h2 id="wrapping">Wrapping and cutting</h2>
<p>Normally the browser breaks a line at spaces. <code>white space</code> changes this: <code>nowrap</code> never breaks, <code>pre</code> keeps the text as typed, <code>pre-wrap</code> keeps it and still wraps, and <code>pre-line</code> keeps only the line breaks. <code>white space collapse</code> is the "what happens to spaces" half of it. When a single word is longer than its box, <code>overflow wrap = "anywhere"</code> lets it break so it does not stick out of the page, which is exactly what a long web address needs. <code>word break = "break-all"</code> breaks everywhere, even where the word would fit, and <code>keep-all</code> is for Chinese, Japanese and Korean, where it forbids breaks inside a word. <code>hyphens = "auto"</code> hyphenates words in languages the browser has a dictionary for, if the element has the right <code>lang</code>. <code>text wrap = "balance"</code> evens out the lines of a short heading, and <code>pretty</code> avoids a last line with one short word.</p>
{{example.web-font-wrapping}}
<p>To show only the first lines of a long text, you have two tools. <code>text overflow = "ellipsis"</code> replaces the cut-off end of one line with an ellipsis, and <code>line clamp</code> limits a block to a number of lines. Both are new or fussy, so build the example below the way it is written: with a <code>max height</code> and <code>overflow = "hidden"</code> as a safety net that works everywhere.</p>
{{example.web-font-clamp}}
<div class="note"><p><code>text overflow</code> does nothing alone. It needs three properties together: <code>overflow</code> (anything but visible), <code>white space = "nowrap"</code> and a limited width. If you see no ellipsis, one of the three is missing.</p></div>

<h2 id="direction">Direction and vertical text</h2>
<p><code>direction</code> chooses <code>ltr</code> or <code>rtl</code> for the text of an element. In practice you set the direction with the <code>dir</code> attribute (see <a href="/learn/page-head/">the lesson on the head and global attributes</a>) because it tells screen readers too, and use the CSS property only for a rule that applies to many elements. <code>unicode bidi</code> controls how text of mixed directions is ordered, and <code>bidi-override</code> forces the order whatever the letters are; the elements <code>isolate</code> and <code>direction override</code> in <a href="/learn/page-text/">the lesson on text elements</a> do the same job.</p>
<p><code>writing mode</code> goes further and turns the lines themselves: <code>vertical-rl</code> writes down the page and stacks the lines from right to left, as in Japanese and Chinese. <code>text orientation</code> decides whether the letters of other scripts stand up or lie down, and <code>text combine upright</code> squeezes a short run, such as a year, into the space of one character.</p>
{{example.web-font-vertical}}

<h2 id="ruby">Ruby and emphasis marks</h2>
<p>Ruby is a small annotation above or below a word, mostly the pronunciation of a Chinese or Japanese word, written with the <code>ruby</code> and <code>ruby text</code> elements. <code>ruby position</code> sets the side and <code>ruby align</code> how the annotation is spread over the word. East Asian text has no italics, so emphasis is drawn as small marks on each character, with <code>text emphasis style</code>, <code>text emphasis color</code> and <code>text emphasis position</code>. The shorthand is <code>text emphasis</code>.</p>
{{example.web-font-ruby}}

<h2 id="persian">Persian and Arabic text</h2>
<p>Everything above works for Persian, and a few points need care. A page in a Persian file already has <code>lang = "fa"</code> and the right-to-left direction. Then:</p>
<ul>
<li>Choose a font that has Persian letters, and put a safe one at the end of the stack, such as <code>Tahoma</code>. Many fonts made for English have no Persian letters, and the browser fills the gap letter by letter from another font, which looks uneven. A web font such as Vazirmatn or Estedad is the real fix: load it with the <code>font</code> element and the <code>range</code> of the Persian block.</li>
<li>Set <code>line height</code> to about 1.9 for body text. Persian letters carry dots and marks that need space above and below.</li>
<li>Use <code>text align</code> <code>start</code> and <code>end</code>, never <code>left</code> and <code>right</code>.</li>
<li>Keep <code>letter spacing</code> at zero. Do not turn ligatures off either, because the joined forms are the script itself.</li>
<li>Digits are characters, not a style. <code>۱۲۳</code> and <code>123</code> are different letters, and no CSS property converts one into the other. <code>font variant numeric</code> only changes the look of the digits a font has, such as the equal width form for columns.</li>
<li>Browsers do not hyphenate Persian, and <code>justify</code> works well if the lines are long.</li>
<li>Italics are rare in Persian type. A line that is only <code>oblique</code> looks slanted, which is fine for a short quotation but tiring for a paragraph. Use bold, or a different size, for emphasis.</li>
</ul>
{{example.web-font-persian}}
<p>The example puts the same text three times. The first box has a comfortable line height, the second a tight one where the lines nearly touch, and the third is justified. The preview shows the page as the compiler built it, with Persian letters from the system.</p>

<h3 id="ref-features">Fonts: features, variants and variable fonts</h3>
<p>These switch the extra forms and axes a font offers. The effect depends on the font.</p>

<h3 id="ref-fontelement">Web font element</h3>
<p>The <code>font</code> element goes directly inside the page.</p>
<h3 id="el-font"><code>font</code><span class="ref-alt"> (Persian: <code>قلم</code>)</span></h3>
<p>Declares a web font, which becomes an <code>@font-face</code> rule. <code>name</code> and <code>url</code> are required, and the element goes directly inside the page. Afterwards write the name in <code>font family</code>. Browsers download the file only when some text uses the font, and until then they show the next font of the stack.</p>
<pre class="code snip" dir="ltr"><code>font:
    name = &quot;Course Serif&quot;
    url = &quot;/fonts/course-serif.woff2&quot;
    weight = 400
    display = swap
end
box: font family = &quot;Course Serif, Georgia, serif&quot; content = &quot;Set in the course font&quot; end</code></pre>
<p class="ref-meta">Required: <code>name</code>, <code>url</code> · Only inside: <code>page</code> · Void element, it cannot have children</p>
<div class="table-wrap"><table class="ref-table"><thead><tr><th>Attribute</th><th>What it does</th><th>Example</th></tr></thead><tbody>
<tr id="at-font-name"><td><code>name</code><br><span class="ref-alt">نام</span></td><td>The family name you choose for the font. It is free text and has nothing to do with the name of the file: you write the same name later in <code>font family</code>. Required. <small class="ref-accepts">[string]</small></td><td><code class="snip" dir="ltr">font: name = &quot;Course Serif&quot; url = &quot;/fonts/course-serif.woff2&quot; end

<tr id="at-font-url"><td><code>url</code><br><span class="ref-alt">نشانی</span></td><td>Where the font file is. A relative address is read from the page, an unsafe one such as <code>javascript:</code> is an error, and a relative file that does not exist next to the program gives a warning.
