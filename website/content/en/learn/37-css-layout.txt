<h2 id="flow">Normal flow</h2>
<p>If you set nothing, the browser lays boxes out in the <em>normal flow</em>. A <strong>block</strong> box, such as a <code>box</code> or a <code>paragraph</code>, takes the full width of its parent and starts on a new line. An <strong>inline</strong> box, such as a <code>span</code> or a <code>link</code>, stays inside the line of text and is only as wide as its content. Width and height do not apply to inline boxes. <code>display = "inline-block"</code> is the middle way: it sits in the line like a word, but it has a width, a height and vertical margins like a block.</p>
{{example.web-layout-flow}}
<p>Everything else in this lesson changes how boxes leave this flow. Most of the time you do not take boxes out of it. You set <code>display = flex</code> or <code>display = grid</code> on a parent, and the parent arranges its children.</p>
<p>Two things in the examples are worth knowing. <code>global: box sizing = "border-box"</code> makes <code>width</code> include padding and border, which is easier to reason about. And a bare number such as <code>padding = 10</code> means pixels; for another unit write a string, like <code>"2rem"</code> or <code>"50%"</code>.</p>

<h2 id="position">Position and the offsets</h2>
<p><code>position</code> chooses how a box is placed, and <code>top</code>, <code>right</code>, <code>bottom</code> and <code>left</code> (or the shorthand <code>inset</code>) say how far from which edge. The default is <code>static</code>: normal flow, and the offsets do nothing.</p>
<ul>
<li><code>relative</code>: the box keeps its place and its space in the flow, and is then drawn shifted by the offsets. The other boxes do not notice.</li>
<li><code>absolute</code>: the box leaves the flow completely. It is placed against the nearest ancestor that is itself positioned (anything but <code>static</code>), or against the page if there is none.</li>
<li><code>fixed</code>: like absolute, but against the window, so it stays in place while the page scrolls. Use it for a bar that must always be visible.</li>
<li><code>sticky</code>: normal flow until the box would scroll past its offset, then it sticks there until its parent ends.</li>
</ul>
<p>The usual pattern is a <code>relative</code> parent with <code>absolute</code> children: the parent is only there to be the reference. Below, the card is the reference for the badge and the bottom strip.</p>
{{example.web-layout-position}}
<div class="note"><p>An absolute box with no positioned ancestor is placed against the whole page, which is rarely what you want. If a badge flies off to a corner of the window, give its parent <code>position = relative</code>.</p></div>
<p>Try the three values yourself. The blue box has <code>top = 30</code> and an offset from the start side. While it is <code>static</code> the offsets are ignored. With <code>relative</code> it moves but its space stays, so the green box does not move up. With <code>absolute</code> it leaves the flow: the green box moves up to take its place, and the blue box is measured from the dashed container.</p>
{{example.web-layout-position-play}}
<p>The offsets come in two families. <code>top</code>, <code>right</code>, <code>bottom</code> and <code>left</code> are physical: right is always the right of the screen. <code>inset inline start</code>, <code>inset inline end</code>, <code>inset block start</code> and <code>inset block end</code> are logical: they follow the writing direction, so the start is the left in English and the right in Persian. The two-value forms <code>inset inline</code> and <code>inset block</code> set both ends. Prefer the logical ones for anything that is about reading order, such as the badge above.</p>

<h2 id="sticky">Sticky and fixed</h2>
<p>A sticky box needs an offset to know where to stick, usually <code>top = 0</code>. It sticks inside the nearest scrolling ancestor, and it can never leave its own parent, so a sticky heading is pushed away when the next section arrives. The box has a fixed <code>height</code> and <code>overflow = auto</code>, so it scrolls by itself. Scroll it: each heading stays at the top until the next one takes over.</p>
{{example.web-layout-sticky}}
<p><code>fixed</code> works like this too, but against the window and without the parent limit. Give a fixed bar <code>top = 0 left = 0 right = 0</code> and it spans the window. Because it leaves the flow, the content below it starts under the bar, so add the bar's height as padding at the top of the page.</p>

<h2 id="stacking">Stacking and z index</h2>
<p>When positioned boxes overlap, the one that comes later in the code is drawn on top. <code>z index</code> changes that: a bigger whole number is drawn above a smaller one, and a negative number goes behind. It applies to positioned boxes and to flex and grid items.</p>
{{example.web-layout-zindex}}
<p>A few boxes create their own <em>stacking context</em>, a group that is ordered as one block: a positioned box with a <code>z index</code>, an element with <code>opacity</code> below 1, or one with a <code>transform</code>. Inside a context the numbers only compete with each other. This is why a menu with <code>z index = 9999</code> can still hide behind a box that has <code>z index = 2</code>: they are in different contexts. When a number seems to do nothing, look for a parent that made a context.</p>

<h2 id="float">Float and clear</h2>
<p>A floated box leaves the line and moves to one side, and the text that follows wraps around it. That is its job today: a picture or a pull quote inside text. Pages were once built with floats, but flexbox and grid replaced that. <code>clear</code> makes a box start below the floats instead of beside them. The value <code>inline-start</code> follows the text direction, so the example works in both languages.</p>
{{example.web-layout-float}}
<div class="note"><p>A float is ignored on a flex or grid item. If the parent of a float is shorter than the float, the parent does not grow to hold it. Put a <code>clear = both</code> element after it, or make the parent <code>display = "flow-root"</code>.</p></div>

<h2 id="flexbox">Flexbox: items in a line</h2>
<p>Set <code>display = flex</code> on a parent and its children become <em>flex items</em>, laid out along one line called the <strong>main axis</strong>. The other direction is the <strong>cross axis</strong>. <code>flex direction</code> chooses the main axis: <code>row</code> (the default, along the text direction), <code>column</code>, or their <code>-reverse</code> forms. Two properties place the items:</p>
<ul>
<li><code>justify content</code> spreads the items along the main axis: <code>flex-start</code>, <code>flex-end</code>, <code>center</code>, <code>space-between</code>, <code>space-around</code>, <code>space-evenly</code>.</li>
<li><code>align items</code> places them across the cross axis: <code>stretch</code> (the default, so items are as tall as the line), <code>flex-start</code>, <code>flex-end</code>, <code>center</code>, <code>baseline</code>.</li>
</ul>
<p>Together they give the shortest way to center a box, both ways:</p>
{{example.web-layout-center}}
<p>The playground below changes the two properties and the direction with buttons. Notice how the meaning of <em>justify</em> and <em>align</em> swaps when you choose <code>column</code>: justify is always the main axis, whichever way it points.</p>
{{example.web-layout-flex-play}}
<p><code>gap</code> puts space between items without margins on the items. One value is used both ways, two values are the row gap then the column gap. <code>row gap</code> and <code>column gap</code> set them one at a time. <code>flex wrap = wrap</code> lets items move to a new line when they do not fit, and <code>flex flow</code> sets direction and wrap together, as in <code>"row wrap"</code>. When there is more than one line, <code>align content</code> distributes the lines in the container.</p>

<h2 id="flex-sizes">How flex items get their size</h2>
<p>Each flex item starts from its <code>flex basis</code> (its width in a row, when the basis is <code>auto</code>), then the free space is shared out. <code>flex grow</code> says how many shares of the extra space the item takes, and <code>flex shrink</code> how much of a shortage it absorbs when the items do not fit. The shorthand <code>flex</code> sets all three: <code>flex = 1</code> means "grow equally, starting from nothing", and <code>flex = "0 0 120px"</code> is a fixed 120 pixel item. Prefer the shorthand, because it resets the parts you did not write to sensible values.</p>
{{example.web-layout-flex-sizes}}
<p>Two properties work on a single item. <code>align self</code> overrides <code>align items</code> for that item. <code>order</code> changes where it is drawn: items are sorted by their order number, the lowest first, and items with equal numbers stay in code order.</p>
{{example.web-layout-flex-order}}
<div class="note"><p><code>order</code> only changes what people see. Screen readers and the Tab key still follow the order of the code. Use it for small visual adjustments and write the content in its real reading order.</p></div>

<h2 id="recipes">Flexbox recipes</h2>
<p>Four layouts you will write again and again. A navigation bar: a flex row, and an <code>auto</code> margin on the end of the first item that pushes the rest away. The auto margin takes all the free space, and <code>margin inline end</code> follows the text direction.</p>
{{example.web-layout-navbar}}
<p>A sidebar with content: the sidebar has a fixed basis and does not grow, the content takes whatever is left.</p>
{{example.web-layout-sidebar}}
<p>Cards that wrap: every card has <code>flex = "1 1 160px"</code>, which says "I would like 160 pixels, but I will grow and shrink". On a wide screen five cards fit in a line, on a phone one per line, with no media query. The last line stretches; if you prefer it not to, use grid below.</p>
{{example.web-layout-cards-wrap}}
<p>A footer at the bottom of a short page: the page is a column with at least the window's height, and the main part grows to fill it.</p>
{{example.web-layout-footer}}

<h2 id="grid">Grid: rows and columns together</h2>
<p>Flexbox lays out one line at a time. Grid lays out both directions at once. Set <code>display = grid</code> and describe the columns with <code>grid template columns</code>, with one size for each column. Sizes can be lengths, percentages, <code>auto</code>, and the unit <code>fr</code>, a fraction of the free space: <code>"1fr 2fr"</code> makes the second column twice as wide as the first. <code>repeat(3, 1fr)</code> is three equal columns. Rows are made as needed, and <code>grid template rows</code> and <code>grid auto rows</code> size them. <code>gap</code>, <code>row gap</code> and <code>column gap</code> work as in flexbox.</p>
{{example.web-layout-grid}}
<p>Change the columns in the next page and watch the same five boxes rearrange. The last button is the most useful grid line you will learn:</p>
{{example.web-layout-grid-play}}
<p><code>repeat(auto-fit, minmax(90px, 1fr))</code> reads "make as many columns as fit, each at least 90 pixels, and share the leftover space". <code>minmax(a, b)</code> gives a size between two limits. With <code>auto-fit</code> the empty columns shrink to nothing, so the real ones stretch. With <code>auto-fill</code> they stay and keep their width. A card grid built this way adapts to every screen with no media queries:</p>
{{example.web-layout-autofit}}

<h2 id="areas">Placing items: lines, spans and areas</h2>
<p>Grid lines are numbered from 1: a grid with three columns has four vertical lines, and <code>-1</code> is the last one. <code>grid column</code> and <code>grid row</code> place an item between two lines: <code>"1 / 3"</code> is from line 1 to line 3, which is two columns, and <code>"span 2"</code> means two tracks wide from wherever the item lands. <code>grid column start</code>, <code>grid column end</code>, <code>grid row start</code> and <code>grid row end</code> set the ends one by one. When items of different sizes leave holes, <code>grid auto flow = "row dense"</code> back-fills them, at the price of an order that no longer matches the code.</p>
{{example.web-layout-grid-span}}
<p>For a whole page, name the cells instead. <code>grid template areas</code> takes one string that draws the layout, one quoted name for each cell of each row; repeating a name merges cells. Then every child says where it goes with <code>grid area</code>. In Salam the string goes in backticks, on a single line, so the quotes inside need no escaping.</p>
{{example.web-layout-grid-areas}}
<p><code>grid template</code> is the shorthand for rows, columns and areas together: <code>`"top top" 50px "side main" 1fr / 150px 1fr`</code>. The areas and the row sizes are written together, then a slash, then the column sizes. <code>grid</code> is the longest shorthand; it also sets the automatic tracks and the flow, as in <code>"auto-flow 60px / 1fr 2fr"</code>. Beginners do well with the long names; the shorthands are for reading other people's code.</p>
<p>Notice that the page layout above needs no wrapper boxes and no floats, and that moving the sidebar to the other side means editing one string.</p>

<h2 id="alignment">Alignment in flex and grid</h2>
<p>The same few words appear everywhere, and a rule makes them easy: <strong>justify</strong> works along the inline axis (the way text runs), <strong>align</strong> along the block axis (the way paragraphs stack), <strong>content</strong> positions the whole set of tracks or lines inside the container, <strong>items</strong> aligns all the items inside their cells, and <strong>self</strong> does that for one item. <strong>place</strong> sets align and justify together. In flexbox <code>justify</code> always means the main axis and <code>align</code> the cross axis, and <code>justify items</code> and <code>justify self</code> do not apply to flex items.</p>
<p>The values are <code>start</code>, <code>end</code>, <code>center</code>, <code>stretch</code> and, for content, the three <code>space-</code> forms. The word <code>end</code> also closes an element in Salam, so write <code>"end"</code> in quotes when it is a value. The page below shows items inside grid cells, with <code>place items</code> on the container and a different alignment on some items.</p>
{{example.web-layout-grid-align}}

<h2 id="columns">Multi-column text</h2>
<p>A long paragraph is hard to read when the lines are very wide. <code>columns</code> splits the content of a box into newspaper columns that fill one after the other. Set <code>column count</code> for a fixed number, or <code>column width</code> for an ideal width and let the browser decide how many fit. <code>columns = "10rem 3"</code> says both: at least 10rem wide, at most 3 columns. <code>column gap</code> is the space between them and <code>column rule</code> draws a line in the middle of the gap, written like a border; its parts are <code>column rule width</code>, <code>column rule style</code> and <code>column rule color</code>, and the style must be set or nothing shows.</p>
{{example.web-layout-columns}}
<p>A child with <code>column span = all</code> stretches across all the columns, like the heading above. <code>column fill</code> chooses between balanced columns (the default) and filling one column to the box's height before starting the next. The <code>break</code> properties control where a column may end: <code>break inside = avoid</code> keeps a card in one piece, <code>break after = avoid</code> keeps a heading with the paragraph that follows it, and <code>break before = column</code> forces a new column. The same properties decide page breaks when the page is printed.</p>
<div class="note"><p>A single number as the value of <code>columns</code> is read as pixels, so <code>columns = "3"</code> does not mean three columns. Write <code>column count = 3</code> for a count.</p></div>

<h2 id="rtl">Right-to-left pages</h2>
<p>Flexbox and grid follow the page direction by themselves. In a Persian page a row starts at the right, the first column of a grid is the right one, and <code>flex-start</code> and <code>start</code> mean the right edge. The same code gives the mirror image of the English page, which is what a Persian reader expects. You do not have to change anything.</p>
<p>The trap is in the physical names: <code>left</code>, <code>right</code>, <code>margin left</code>, <code>float = left</code> and <code>text align = left</code> never flip. Wherever the side is about reading order (a badge at the end of a line, a gap after an icon, text that wraps around a picture), use the logical names: <code>inset inline start</code> and <code>end</code>, <code>margin inline start</code> and <code>end</code>, <code>float = inline-start</code>, <code>text align = start</code>. This lesson's examples already do. Use <code>left</code> and <code>right</code> only when you mean the screen, as for a shadow that falls to the right.</p>
