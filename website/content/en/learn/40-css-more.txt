<h2 id="lists">Lists and their markers</h2>
<p>Every item of a list has a <em>marker</em>: the bullet of a <code>list</code> or the number of an <code>ordered list</code>. The browser draws it, and you choose how with three properties. <code>list style type</code> sets the look. It takes a keyword such as <code>disc</code>, <code>square</code>, <code>decimal</code>, <code>lower-roman</code> or <code>upper-alpha</code>, <code>none</code> for no marker, or a text of your own. A text must keep its quotes in the CSS, so in Salam write it between backticks: <code>list style type = `"» "`</code>. <code>list style position</code> says whether the marker hangs outside the text (<code>outside</code>, the default) or sits inside the first line (<code>inside</code>). <code>list style image</code> uses a picture or a gradient instead of a character.</p>
<p><code>list style</code> is the shorthand for all three, written as one string such as <code>"square outside"</code>. Look at the last two lists in the preview: with a marker outside, every line of a long item starts at the same edge, and with a marker inside the second line wraps under the marker.</p>
{{example.web-more-lists}}
<div class="note"><p>These properties style the marker as a whole. You cannot give one marker a color of its own with them. The marker takes the color and the font of its item, so to change it, change the item.</p></div>

<h2 id="counters">Counters: numbering with CSS</h2>
<p>A counter is a number that the browser keeps under a name. Three properties work with it. <code>counter reset</code> creates it on an element, or sets it back to a start value: <code>"chapter"</code> starts at 0 and <code>"chapter 4"</code> at 4. <code>counter increment</code> adds to it each time an element that has the property is drawn, by 1 or by the number you give. <code>counter set</code> puts a value into it without adding. When both increment and set sit on one element, the set wins.</p>
<p>A counter is invisible until you print it. For that, write <code>counter(chapter)</code> in the <code>generated content</code> of a <code>before</code> or <code>after</code> rule, which adds text in front of or behind an element. A text next to it goes in quotes inside the string: <code>"counter(chapter) \". \""</code>. If you reset a lesson counter on every chapter heading, it starts again in each chapter and gives <code>1.1</code>, <code>1.2</code>, <code>2.1</code>. The example does exactly that: every chapter heading resets the lesson counter and every lesson paragraph increments it.</p>
{{example.web-more-counters}}
<p>The appendix heading uses <code>counter set = "chapter 9"</code>: it jumps to 9 and its lessons follow as 9.1. The <code>counter()</code> function takes a second value, a list style, and the Persian version of the example uses it as <code>counter(chapter, persian)</code> to print Persian digits. For nested numbers such as 1.2.3 in one go, <code>counters(name, ".")</code> joins every level of the counter with a separator.</p>
<div class="note"><p>The <code>before</code> and <code>after</code> prefixes work on elements and components, but not inside a <code>global</code> rule, where they are silently dropped. If the numbering does not appear, check where the rule is written. Also note that two elements with the same styles share one CSS class, while two with different styles that you named with the same <code>class</code> are a compile error, so name a class only on elements that really look alike.</p></div>

<h2 id="quotes">Quotation marks</h2>
<p>The <code>quote</code> element puts quotation marks around its text, and which marks it uses comes from the <code>quotes</code> property. The value is pairs of strings: the first pair is the outer level, the second pair is for a quote inside a quote, and so on. Quote marks in the value need backticks again. The first two paragraphs of the example show the same nested sentence with two sets of marks. <code>quotes = "none"</code> removes the marks, and for a <code>block quote</code>, which has none of its own, you can add them with the keywords <code>open-quote</code> and <code>close-quote</code> in <code>generated content</code>, as in the last line of the example. Those keywords use the same <code>quotes</code> pairs, so the marks stay consistent.</p>
{{example.web-more-quotes}}

<h2 id="tables">Table borders and layout</h2>
<p>A table has two models for its borders. With <code>border collapse = separate</code> (the default) every cell keeps a complete border of its own and the gaps between cells are set with <code>border spacing</code>: one length for both directions, or two for horizontal and vertical. With <code>collapse</code> neighbouring borders merge into a single line and <code>border spacing</code> does nothing. <code>empty cells = hide</code> leaves out the border and background of a cell with no content, but only in the separate model. <code>caption side</code> moves the <code>caption</code> to the <code>bottom</code>. The first table below shows the separate model with its hidden empty cell, and the second shows collapsed borders.</p>
{{example.web-more-table}}
<p>The second table uses <code>table layout = fixed</code>. With the default <code>auto</code> layout the browser measures every cell before it decides on column widths, so one long cell can stretch its column and the table can end up wider than you asked. A fixed layout reads only the table width and the first row and divides the space, so the columns stay put and long text wraps inside them. It also draws a big table faster. It needs a <code>width</code> on the table to have any effect.</p>

<h2 id="scroll">Scrolling that snaps</h2>
<p>Scroll snapping makes a scrolling box come to rest on chosen points instead of anywhere, like the pages of a gallery. It takes two sides. On the scroll container, <code>scroll snap type</code> turns it on: an axis (<code>x</code>, <code>y</code> or <code>both</code>) and a strictness. <code>mandatory</code> always comes to rest on a point, <code>proximity</code> only when the scroll stops near one. On each child, <code>scroll snap align</code> says which edge of the child lines up with the container: <code>start</code>, <code>center</code> or <code>end</code>. <code>scroll snap stop = "always"</code> adds that a fast flick may not skip past the child, which is what you want for a slide show.</p>
<p>The example below is a strip of four slides. The container has <code>overflow x = auto</code> to scroll and <code>scroll snap type = "x mandatory"</code>. The slides are styled with one <code>global</code> rule using the selector <code>#strip &gt; *</code>, which is shorter than repeating the same line on four boxes. Scroll the strip with your finger, a mouse wheel or the keys and watch it settle on a slide.</p>
{{example.web-more-snap}}
<p>Two more properties adjust where "start" is. <code>scroll padding</code> goes on the container and shrinks the area that counts: <code>"0 20"</code> keeps a slide 20 pixels away from the left and right edges, so that the next slide peeks in, and it stops a fixed header from covering a heading that the page jumps to. <code>scroll margin</code> goes on the child and grows its snap area on its own. Both come in sides: <code>top</code>, <code>right</code>, <code>bottom</code> and <code>left</code>, and the logical ones, <code>block</code> and <code>inline</code> with <code>start</code> and <code>end</code>, which turn around in a right to left page. Use the logical ones for anything that scrolls sideways, because in a Persian page the first slide is at the right.</p>
<p>The little dots in the preview are made by the browser, not by elements. <code>scroll marker group = "after"</code> asks for a row of markers after the container, one for each child, and the raw <code>style</code> element styles them with <code>::scroll-marker</code> and <code>::scroll-marker-group</code>, which the page language has no names for. The dot of the slide in view also matches <code>:target-current</code>, so it can have its own color, and clicking a dot scrolls to its slide. <code>scroll target group = "auto"</code> does the same job for a list of links, such as a table of contents that highlights the section you are reading. Both exist today in Chromium browsers only, so keep the page usable without them.</p>
<div class="note"><p>Snapping only helps readers who scroll. Do not use it to hide content: keep everything within reach of a plain scroll, and try the page with the keyboard too, which moves the container in the same way.</p></div>

<h2 id="anchors">Anchor positioning</h2>
<p>A tooltip, a menu or a popup belongs next to the thing it explains. For years that needed JavaScript that measured the page. Anchor positioning does it in CSS. You give an element a name with <code>anchor name</code>, which must start with two hyphens, like <code>"--target"</code>. Another element that is <code>position = absolute</code> chooses that name with <code>position anchor</code> and says where to sit with <code>position area</code>. The area is a cell of a three by three grid around the anchor: <code>top</code>, <code>bottom</code>, <code>left</code>, <code>right</code>, <code>center</code>, corners such as <code>top right</code>, and stretched cells like <code>top span-right</code>.</p>
<p>The example has four buttons. Each one runs a small function when it is clicked, and the function sets the <code>position-area</code> of the tooltip with <code>dom.SetStyle</code>. The tooltip jumps around the anchor and no coordinates are calculated anywhere. The functions of <code>dom</code> are described on <a href="/std/dom/">the dom page</a>.</p>
{{example.web-more-anchor}}
<p>Two more properties make the tooltip behave near the edge of the screen. <code>position try fallbacks = "flip-block"</code> lists other places to try when the first one would run off screen: <code>flip-block</code> mirrors it to the other side, <code>flip-inline</code> does so sideways. <code>position visibility = "anchors-visible"</code> hides the tooltip when its anchor has scrolled out of view, so that it does not float alone. <code>position try order</code> and the shorthand <code>position try</code> rank the fallbacks by the room they leave. Finally <code>anchor scope</code> keeps names local to a part of the page, so that a component used ten times can use the same name in each copy without mixing them up.</p>
<div class="note"><p>Anchor positioning is new. Chromium browsers have it and the others are catching up, and a browser that lacks it ignores these lines, so the tooltip stays where it would be without them. Test it in the browsers your readers use, and have a plain fallback such as showing the text below the button.</p></div>

<h2 id="svg">SVG presentation properties</h2>
<p>The <code>svg</code> element holds a drawing. Its <code>content</code> is raw SVG markup that the compiler passes on unchanged, so shapes such as <code>&lt;circle&gt;</code> and <code>&lt;path&gt;</code> are written as text. What the page language adds is the styling. The properties of this section are SVG presentation properties, and they reach the shapes in two ways.</p>
<p>The first way is inheritance. <code>fill</code>, <code>stroke</code>, <code>stroke width</code>, <code>paint order</code>, <code>text anchor</code> and the <code>marker</code> properties are inherited, so one line on the <code>svg</code> element styles every shape inside. <code>fill</code> is the color inside a shape and <code>stroke</code> is the line along its edge; with no stroke only the fill shows. The first example puts them on three drawings. <code>fill rule = "evenodd"</code> leaves a hole in the star where its lines cross. <code>stroke dasharray</code> alternates dash and gap, <code>stroke dashoffset</code> shifts the pattern, and a round <code>stroke linecap</code> turns the dashes into dots. <code>stroke linejoin</code> shapes a corner, and <code>stroke miterlimit</code> cuts a sharp point flat when it would stick out too far.</p>
{{example.web-more-svg-stroke}}
<p>Text in SVG has its own rules. <code>text anchor</code> decides which part of the text sits on its <code>x</code> point: <code>middle</code> centres it. <code>paint order = "stroke fill"</code> draws the outline first, so the fill covers its inner half and outlined letters stay thick. <code>dominant baseline</code> and <code>baseline shift</code> change the line that letters rest on, and they are not inherited, so they go on one text only. That is the second way to reach a shape: a <code>global</code> rule with a <code>selector</code> such as <code>"#b"</code>. The page language does not name the shapes inside the raw markup, but CSS can still find them by id, class or tag.</p>
{{example.web-more-svg-text}}
<p>The same way works for the properties that only a shape has. <code>cx</code>, <code>cy</code> and <code>r</code> place and size a circle, <code>rx</code> and <code>ry</code> do it for an ellipse or round the corners of a rectangle, <code>x</code> and <code>y</code> move a rectangle, and <code>d</code> holds the outline of a path. They are attributes in old SVG and CSS properties in modern browsers, which is what lets a <code>hover</code> rule grow the circle below and a <code>transition</code> animate it.</p>
{{example.web-more-svg-geometry}}
<div class="note"><p>Write the path in <code>d</code> with <code>C</code> or <code>L</code> rather than <code>Q</code>. A number followed by a space and <code>Q</code> can be read by the page compiler as the length unit <code>q</code>, which breaks the path. This only happens in CSS written with the page language: the <code>d</code> attribute inside the raw markup is passed on untouched.</p></div>
<p>Gradients and filters are written in the raw markup too, but their colors are CSS properties. <code>stop color</code> and <code>stop opacity</code> color a gradient stop, <code>flood color</code> and <code>flood opacity</code> color an <code>feFlood</code> step of a filter, and <code>lighting color</code> does so for the lighting steps. <code>color interpolation filters</code> picks the color space in which a filter works, <code>sRGB</code> or <code>linearRGB</code>. Because stops and filter steps are not inherited, you reach them through <code>global</code> rules again.</p>
{{example.web-more-svg-paint}}
<p>Markers are small shapes drawn on the points of a line. <code>marker start</code>, <code>marker mid</code> and <code>marker end</code> take <code>url(#id)</code> of a <code>marker</code> element, and the shorthand <code>marker</code> sets all three at once. Put the <code>marker</code> elements in a separate <code>svg</code> as the example does, because markers inherit the stroke and the marker properties of the drawing they sit in. <code>vector effect = "non-scaling-stroke"</code> keeps a line the same thickness when the drawing is scaled, and <code>shape rendering</code> and <code>color interpolation</code> are hints for how edges and gradients are drawn.</p>
{{example.web-more-svg-markers}}

<h2 id="math">Math</h2>
<p>The <code>math</code> element draws a formula. Like <code>svg</code>, its content is raw markup, here MathML, such as <code>&lt;mfrac&gt;</code> for a fraction and <code>&lt;msup&gt;</code> for a power. Three properties change how it is set. <code>math style</code> is <code>normal</code> for a display formula, with large operators and limits above and below, or <code>compact</code> for one inside a line of text, with everything tighter. <code>math depth</code> says how deeply the formula is nested, so that it can be drawn smaller. It changes the size only where <code>font-size</code> is the keyword <code>math</code>, which the page language does not accept yet, so the example sets it in a raw <code>style</code> element. <code>math shift</code> chooses how far superscripts are raised: <code>compact</code> raises them less, as in the denominator of a fraction.</p>
{{example.web-more-math}}

<h2 id="reading">Reading order, the top layer and HDR</h2>
<p>Keyboard focus and screen readers move through a page in the order of the source. When a layout changes the visual order, for example with <code>flex direction = row-reverse</code>, the two disagree and a keyboard user jumps around the screen. <code>reading flow</code> on the container fixes that: <code>flex-visual</code> follows what is drawn, <code>grid-rows</code> and <code>grid-columns</code> do the same for a grid, and <code>source-order</code> lets the <code>reading order</code> number of each child decide, lowest first. In the example press Tab: the first row is read in source order, the second in the order you see.</p>
{{example.web-more-reading}}
<p>In a right to left page the visual order starts at the right, so the same property gives a different sequence, and the Persian version of this example shows it. Two more properties are for special cases. <code>overlay</code> reports whether an element is in the top layer, where popovers and dialogs are drawn; you list it in a <code>transition</code> so that an element leaving the top layer can finish its exit animation first. <code>dynamic range limit</code> limits how bright HDR images and video may get on a screen that supports it, from <code>standard</code> to <code>no-limit</code>.</p>
