<h2 id="media-intro">Media elements and a sound to play</h2>
<p>The <code>audio</code> and <code>video</code> elements play a file and report what happens to it. Their attributes are <code>source</code> (the file), <code>controls</code> (the browser's own buttons), <code>preload</code> (how much to fetch before the user presses play: <code>none</code>, <code>metadata</code> or <code>auto</code>), <code>loop</code> and <code>muted</code>. Their events follow the life of the file: it starts loading, it knows its length, it can play, it plays, it ends. Event attributes work as in <a href="/learn/events-drag-touch/">the previous lesson</a>: a function name, a short lambda, or a JavaScript string.</p>
<p>The examples of this lesson have no network, so they make their own sound. The function <code>clip</code> returns a WAV file as a <code>data:</code> address: a 54 byte header, written in base64, and a short square wave tone that is added 400 times, which makes three seconds of beeping. Every example sets the <code>src</code> of the audio element from a button, so you see the load events in their real order. Browsers only play sound after the user clicked something on the page, so the Play buttons are real clicks, not code that runs on load.</p>

<h2 id="lifecycle">The life of a media file</h2>
<p>This page logs the events of loading and playing. Press Load, then Play, and compare the log with the list below. The log is what Chrome produces; the order of neighbours such as <code>suspend</code> and <code>loaded data</code> can differ in other browsers.</p>
{{example.web-mediaev-log}}
<ul>
<li><code>load start</code>: the browser begins to fetch the file.</li>
<li><code>suspend</code>: it stopped fetching on purpose. With <code>preload = "none"</code> it waits for the first play, and later it also stops when its buffer is full.</li>
<li><code>loaded metadata</code>: the length (and, for video, the size) is known. Read <code>duration</code> here.</li>
<li><code>loaded data</code>: the first moment can be shown.</li>
<li><code>can play</code>: enough data to start. <code>can play through</code>: enough to reach the end at the current speed.</li>
<li><code>play</code>: playing was requested. <code>playing</code>: it is really running. <code>pause</code> and <code>ended</code> close the story.</li>
</ul>
<p>One thing deserves a name: <code>play</code> and <code>playing</code> are not the same. <code>play</code> fires the moment the button is pressed, even when no data has arrived. <code>playing</code> fires when sound or picture is moving, and again after every pause for buffering. A button that must show Pause should follow <code>playing</code> and <code>pause</code>, not the click.</p>
<div class="note"><p>Do not set <code>src</code> after the page asked for <code>play()</code> and expect the old sound to go on. Changing the source resets the element, and the browser fires <code>emptied</code> and starts the whole life cycle again.</p></div>

<h2 id="player">A small custom player</h2>
<p>The browser's controls are fine, but a page often wants its own. The example has a button, a progress bar and a volume slider, and every part reacts to an event instead of to the click that caused it. <code>play</code> and <code>pause</code> change the label of the button, so it is right even when something else pauses the sound. <code>time update</code> fires about four times a second and moves the bar with the share <code>currentTime / duration</code>. <code>volume change</code> writes the new volume next to the slider. The slider itself sets <code>volume</code> from its <code>input</code> event.</p>
<p>The state of the element is read with <code>dom.GetNum</code> and <code>dom.GetBool</code> (<code>currentTime</code>, <code>duration</code>, <code>paused</code>) and changed with <code>dom.SetNum</code> and <code>dom.Call0</code>, which calls methods such as <code>play</code> and <code>pause</code>.</p>
{{example.web-mediaev-player}}

<h2 id="seek-rate">Seeking, speed and length</h2>
<p><code>seeking</code> fires when a jump to another time starts and <code>seeked</code> when it is finished. Setting <code>currentTime</code> causes both, and so does the user dragging the slider of the browser controls. <code>rate change</code> fires when <code>playbackRate</code> changes: 1 is normal, 0.5 is half speed. <code>duration change</code> fires when the length becomes known or changes, and <code>emptied</code> when the element is reset, as the Reset button does by calling <code>load()</code>.</p>
{{example.web-mediaev-seek}}

<h2 id="captions">Captions and cue change</h2>
<p>A <code>track</code> element inside an audio or video element holds captions in the WebVTT format, a plain text file with time ranges. Its <code>cue change</code> event fires whenever a caption begins or ends. The text of the current one is in <code>track.activeCues</code>: the example reads the list with <code>dom.GetProp</code>, checks its <code>length</code>, and shows the first cue's <code>text</code> in a heading. The track needs <code>default = true</code> (or a script that sets its mode) or no cues become active. The page language accepts only ordinary addresses for the file, so the example gives the track a placeholder name and sets the real <code>src</code>, a <code>data:</code> address, from code when Play is pressed.</p>
{{example.web-mediaev-cues}}

<h2 id="animation">Animation events</h2>
<p>A CSS animation moves an element by itself, and four events tell what stage it is at. <code>animation start</code> fires when it begins, <code>animation iteration</code> at the end of each round except the last, <code>animation end</code> after the last round, and <code>animation cancel</code> if it is cut off: for instance when the element is hidden with <code>display: none</code>. The animation here is defined in a <code>style:</code> element with <code>@keyframes</code>, and a class switches it on, three rounds of half a second each. So the log of an uninterrupted run is one start, two iterations and one end, and a cancelled run is a start and a cancel.</p>
<p>The end handler removes the class, which lets the button start it again. That is the usual job of <code>animation end</code>. An animation that never ends (<code>infinite</code>) never fires it.</p>
{{example.web-mediaev-animation}}

<h2 id="transition">Transition events</h2>
<p>A transition is the smooth change of a property after it was set, and it has four events. <code>transition run</code> fires when the transition is created, before its delay. <code>transition start</code> fires when the delay is over and the value begins to move. <code>transition end</code> fires when it arrives. <code>transition cancel</code> fires when something interrupts it. All four carry <code>propertyName</code>, so a transition of two properties fires each event twice. The example gives the move a delay of 0.3 seconds, so run and start are visible apart, and the second button flips the class twice at once to cut the transition off.</p>
<p>There is one trap that is not in your code. In our tests Chromium, the engine of Chrome and Edge, read <code>transition end</code> from an HTML attribute but not <code>transition run</code>, <code>transition start</code> or <code>transition cancel</code>; Firefox reads all four. Writing them as attributes compiles and works in Firefox, and silently does nothing in Chrome. The reliable way is <code>dom.OnEventE(element, "transitionrun", ...)</code>, which the example uses for those three, and it also shows the plain attribute for <code>transition end</code>.</p>
{{example.web-mediaev-transition}}

<h2 id="slot">Slots and slot change</h2>
<p>A <code>template</code> with <code>shadow root mode = "open"</code> turns its parent into a shadow host: the content of the template becomes a separate little tree, and the original children of the host are shown wherever a <code>slot</code> is. <code>slot change</code> fires on the slot when the nodes that fill it change, so it is how a component notices that someone added a child. <code>assignedNodes()</code>, called with <code>dom.Call0</code>, lists them. Page styles do not reach inside a shadow tree, which is why the example puts the colours on the host.</p>
{{example.web-mediaev-slot}}

<h2 id="policy">Security policy violations</h2>
<p>A Content Security Policy is a list of things a page promises not to do, set by a <code>meta</code> element with <code>http equiv = "Content-Security-Policy"</code> or by a header. When the page breaks its own promise the browser blocks the act and fires <code>security policy violation</code>, with the blocked address in <code>blockedURI</code> and the rule in <code>violatedDirective</code>. The example forbids style attributes. Setting one with <code>dom.SetAttr(el, "style", ...)</code> is blocked and reported on the element itself, while <code>dom.SetStyle</code> works because it changes the style object, not the attribute. Some violations, such as a blocked image, are reported on the document and not on the element.</p>
{{example.web-mediaev-policy}}

<h2 id="rare">Events you cannot trigger here</h2>
<p>A few events need a network that fails or a graphics system that breaks, so no example can show them. This is when the browser fires them.</p>
<ul>
<li><code>stalled</code>: it wants more data and none has come for a few seconds, for example on a slow mobile connection. It may recover on its own.</li>
<li><code>waiting</code>: playback stopped because the buffer ran dry. <code>playing</code> follows when data arrives again. Show a spinner between them.</li>
<li><code>progress</code>: the browser downloaded another chunk of a remote file. A short <code>data:</code> address does not produce it.</li>
<li><code>context lost</code> and <code>context restored</code>: a 2D canvas loses its memory when the graphics driver resets or the system switches graphics cards, and gets an empty drawing back when it recovers. Everything on it has to be drawn again in <code>context restored</code>. A page cannot cause it.</li>
</ul>

<h2 id="reference">Reference: every event of this lesson</h2>
<p>All of these are global attributes, but each one only fires on the elements named in its description. The examples are compiled by the checker; where an example needs a media file it uses an address that does not exist, so the event is described and not run. Three events of this lesson end in <em>end</em> or <em>ended</em>: <code>ended</code>, <code>animation end</code> and <code>transition end</code>. In Persian their names start with <code>اتمام</code> and not <code>پایان</code>, because <code>پایان</code> on its own would end the element.</p>
