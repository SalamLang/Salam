<h2 id="model">Events that move</h2>
<p>An event attribute takes a function. You can give it the name of a function declared above the <code>page:</code> block, a short lambda such as <code>(): dom.SetText(dom.ById("out"), "hi") end</code>, or a plain JavaScript string. A function that needs the event itself takes one parameter, <code>e: i64</code>, and passes it to the helpers of <a href="/std/dom/">the dom package</a>: <code>dom.EventX(e)</code>, <code>dom.PreventDefault(e)</code>, <code>dom.GetProp(e, "dataTransfer")</code> and so on. <a href="/learn/events-mouse/">The lesson on mouse events</a> explains the model in full. Here you will use it for events that carry more data than a click: where the finger is, what is being dragged, how far the page has scrolled.</p>

<h2 id="drag-drop">Drag and drop</h2>
<p>HTML has its own drag and drop, and it needs three parts. The element you pick up has <code>draggable = true</code> and a <code>drag start</code> handler that puts something in <code>dataTransfer</code>, the small package the browser carries during the drag. The place you drop on has a <code>drag over</code> handler that calls <code>dom.PreventDefault</code>, because the browser refuses every drop unless it is told that this place accepts one. And that place has a <code>drop</code> handler that takes the package out again.</p>
<p>In the example the package is the text <code>parcel</code>, set with <code>dom.CallS2(dt, "setData", ...)</code>. On drop, <code>getData</code> gives it back and the handler uses it to find the element and move it into the zone. <code>dom.GetProp(e, "dataTransfer")</code> returns the package as an object, and <code>dom.CallS1</code> and <code>dom.CallS2</code> call its methods with one or two strings.</p>
{{example.web-drag-basic}}
<div class="note"><p>The most common reason a drop does nothing is a missing <code>drag over</code> handler. The second most common is a missing <code>setData</code> in <code>drag start</code>: Firefox does not start a drag at all without it. Write both, even when you do not need the data.</p></div>

<h2 id="drag-feedback">Feedback while dragging</h2>
<p>Four more events tell you what is going on. <code>drag</code> fires on the dragged element again and again, <code>drag end</code> fires once when the drag is over, and <code>drag enter</code> and <code>drag leave</code> fire on the places the item passes. A drop zone usually uses the last two to add and remove a highlight: a class that the <code>style:</code> element defines, switched with <code>dom.AddClass</code> and <code>dom.RemoveClass</code>.</p>
<p>The example also reads <code>dataTransfer.dropEffect</code> in <code>drag end</code>. It is <code>none</code> when the item was dropped on a place that did not accept it, so you can tell a successful drop from a cancelled one. Other values (<code>copy</code>, <code>move</code>) depend on the browser, so only compare with <code>none</code>.</p>
{{example.web-drag-feedback}}

<h2 id="drag-lists">Moving items between lists</h2>
<p>A board with columns is the same recipe with one change: the handlers are shared. <code>drag start</code> stores the id of the card in the package, and every column's <code>drop</code> reads the id, finds the card with <code>dom.ById</code> and appends it to the column that received the drop. <code>dom.GetProp(e, "currentTarget")</code> is the element the handler is attached to, so one function serves all columns even when the drop lands on a card inside the column. Each card and column here is a component, which keeps the page short.</p>
{{example.web-drag-board}}
<p>Sorting inside one list needs a decision: before or after the row you dropped on? The example compares the pointer's height with the middle of that row, taken from <code>getBoundingClientRect</code>, and then puts the rows back in order with <code>dom.Append</code>, which moves an element that is already in the page.</p>
{{example.web-drag-sort}}

<h2 id="pointer">Pointer events</h2>
<p>A mouse, a pen and a finger are all pointers, and pointer events cover them with one set of names: <code>pointer down</code>, <code>pointer move</code> and <code>pointer up</code>. New code uses these and leaves <code>mouse down</code> and <code>touch start</code> to old pages, because one handler then works on every device. <code>event.pointerType</code> tells which device it was.</p>
<p>The example drags a ball by hand, without HTML drag and drop. On <code>pointer down</code> it remembers where the pointer and the ball were. On each <code>pointer move</code> it adds the distance travelled to the ball's position with <code>dom.SetStyle</code>. The important call is <code>setPointerCapture</code>: it tells the browser to send all later events of this pointer to the ball, even when the pointer runs ahead of it or leaves it. The events <code>pointer capture start</code> and <code>pointer capture end</code> report when that begins and ends. The <code>touch action = none</code> property keeps a finger from scrolling the page instead.</p>
{{example.web-drag-pointer}}
<p>Hand made dragging is the better choice when the item must follow the pointer exactly, as in a slider, a drawing tool or a game. HTML drag and drop is the better choice when something is carried to a drop target, and it comes with the browser's drag image and the keyboard escape for free.</p>

<h2 id="pointer-states">Entering and leaving</h2>
<p>Four events tell where the pointer is. <code>pointer enter</code> and <code>pointer leave</code> fire once as the pointer comes and goes, and ignore the children of the element. <code>pointer over</code> and <code>pointer out</code> bubble, so they also fire when the pointer crosses between the element and a child. Pick enter and leave for hover effects. The fifth event, <code>pointer cancel</code>, means the browser took the pointer away, most often because a touch turned into a page scroll; end your gesture there.</p>
{{example.web-drag-states}}
<p>In the log, a mouse that moves from the outer box into the inner one gives <code>out:outer</code> and then <code>over:inner</code>, with no <code>enter</code> or <code>leave</code>, because it never left the outer box.</p>

<h2 id="touch">Touch events</h2>
<p>Touch events came first, and they still exist: <code>touch start</code>, <code>touch move</code>, <code>touch end</code> and <code>touch cancel</code>. They give you every finger, which pointer events do one at a time. <code>dom.TouchX(e)</code> and <code>dom.TouchY(e)</code> read the position of the finger that changed, and <code>touches</code> counts all fingers on the screen, as the example shows. On <code>touch end</code> the finger is already gone from <code>touches</code>, so the last position comes from the changed finger.</p>
<p>The CSS property <code>touch action</code> belongs with these events. By default a finger that moves on the page may scroll or zoom it, and the browser then cancels your gesture. <code>touch action = none</code> on your element says that you handle it yourself. Use <code>pan-y</code> instead if the page may still scroll vertically.</p>
{{example.web-drag-touch}}

<h2 id="scroll">Scroll and scroll end</h2>
<p><code>scroll</code> fires on a scrollable element every time its position changes, and a single flick causes dozens of events. Read <code>scrollTop</code>, <code>scrollHeight</code> and <code>clientHeight</code> with <code>dom.GetNum</code>: the first is how far you are, and the last two give the room there is. The example turns that into a progress bar. <code>scroll end</code> fires once when the movement has come to rest, which is the moment to save a position or load a picture. The button sets <code>scrollTop</code> back to zero with <code>dom.SetNum</code>, and <code>scroll behavior = smooth</code> makes that an animation.</p>
{{example.web-drag-scroll-bar}}
<p>An endless list is a scroll handler that checks how much room is left and adds items when it gets small. This one adds five paragraphs with <code>dom.Create</code> and <code>dom.Append</code> whenever the reader is within 30 pixels of the end.</p>
{{example.web-drag-scroll-more}}
<div class="note"><p>Keep scroll handlers cheap, because they run very often. The example above does arithmetic and one style change. Work that is slow, such as a network request, belongs in <code>scroll end</code>, which runs once.</p></div>

<h2 id="window">The window, and images</h2>
<p>Two events belong to the window and not to an element. <code>scroll</code> on the whole page and <code>resize</code> are fired at the window, and the page language cannot attach code to the window: the HTML attribute exists only on the <code>body</code> element, which a page does not write. The way out is to register them with <code>dom.OnWindow("scroll", ...)</code> and <code>dom.OnResize(...)</code>, and to run that registration from the <code>load</code> event of a one pixel image, which the browser fires as soon as the page is ready. The example shows the size of the window, and a progress bar for the whole page.</p>
{{example.web-drag-window}}
<p>The <code>load</code> event also does its normal job on images, and so do <code>error</code> and <code>abort</code>. <code>error</code> fires when the file cannot be loaded or decoded, and the handler can put a spare picture in its place with <code>dom.SetAttr</code>. <code>abort</code> fires when loading is stopped half way, for example because the page changed the source. In the example the second picture is not an image at all, so it fails and the page swaps it for a spare. Check that the spare differs from the current source, or a broken spare would start an endless loop.</p>
{{example.web-drag-image}}

<h2 id="reference">Reference: every event of this lesson</h2>
<p>Each event is a global attribute, so it can go on any element, although some only make sense on certain ones. The examples are checked by the compiler. They use lambdas or short JavaScript strings; in a real page a function declared above the page is easier to read. Four events of this lesson end in <em>end</em>: <code>drag end</code>, <code>pointer capture end</code>, <code>touch end</code> and <code>scroll end</code>. In Persian their names start with <code>اتمام</code> and not <code>پایان</code>, because <code>پایان</code> on its own would end the element.</p>
