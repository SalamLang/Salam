<h2 id="default">The default look</h2>
<p>You do not turn the design on. Every page uses shadcn by default, so a plain <code>button</code> is already a styled button, and <code>variant</code> and <code>size</code> pick another one with a single word. The behaviour (open and close, keyboard, focus, ARIA) is generated for you in the same way, so a <code>dialog</code> opens and a <code>tabs</code> element answers the arrow keys without a line of script.</p>
{{example.ds-overview-start}}
<h2 id="settings">Page settings</h2>
<p>Four settings in the <code>page</code> block control the design for the whole page. Write enum values in quotes.</p>

<p><code>auto</code> follows the system setting of the visitor, <code>light</code> and <code>dark</code> force one. The example below is dark with the zinc palette.</p>
{{example.ds-overview-settings}}
<h2 id="theme-toggle">Theme toggle</h2>
<p>The <code>theme toggle</code> element is a button with a sun and a moon that flips light and dark and remembers the choice of the visitor in the browser. It is a <code>button</code>, so it takes <code>variant</code> and <code>size</code> as well.</p>
{{example.ds-overview-toggle}}
<h2 id="tokens">Tokens: change everything from one place</h2>
<p>The whole look is a set of named values, the shadcn variables: <code>background</code>, <code>foreground</code>, <code>card</code>, <code>popover</code>, <code>primary</code>, <code>secondary</code>, <code>muted</code>, <code>accent</code>, <code>destructive</code>, <code>border</code>, <code>input</code>, <code>ring</code>, <code>radius</code>, <code>chart-1</code> to <code>chart-5</code> and the <code>sidebar</code> group, plus <code>font-sans</code> and <code>font-mono</code>. Components never use a fixed colour; they read these values, so changing one token restyles every component that uses it.</p>
<p>List the ones you want to change in <code>design tokens</code>, separated by semicolons. A bare name sets both themes; <code>light name</code> and <code>dark name</code> set one side only. Fonts go through the same place: <code>font-sans: "Inter", sans-serif</code>.</p>
{{example.ds-overview-tokens}}
<h2 id="scope">Light and dark on any element</h2>
<p><code>theme</code> works on every element, not only on the page. A <code>box</code>, a <code>card</code> or any other element with <code>theme = "dark"</code> gets the dark colours for itself and everything inside it, even on a light page.</p>
{{example.ds-overview-scope}}
<h2 id="saved">No flash with the saved theme</h2>
<p>With <code>theme = "auto"</code> a page that has a <code>theme toggle</code> also reads the saved choice (the browser key <code>salam-theme</code>) in the head, before anything is drawn, so a visitor who picked dark never sees a light page first. Pages without a toggle get no script.</p>
<h2 id="fonts">Fonts from one place</h2>
<p>Set the families with <code>font-sans</code> and <code>font-mono</code>, then say where the files come from. <code>font-url</code> is a stylesheet address such as a Google Fonts link; <code>font-face</code> lists your own files as <code>Family url weight</code>, separated by commas (write <code>+</code> for a space in the family, add <code>italic</code> for an italic file). The page gets the <code>link</code> and <code>@font-face</code> rules for you.</p>
<pre class="code snip" dir="ltr"><code>design tokens = "font-sans: Inter, sans-serif; font-face: Inter /fonts/inter.woff2 400 700"</code></pre>
<p>Inside <code>design tokens</code> a semicolon ends a token and an ampersand cannot be used, so write <code>%3B</code> and <code>%26</code> in a URL there, or put the font settings in the project file below.</p>
<h2 id="project">One file for the whole project</h2>
<p>Put the defaults in <code>design.toml</code> next to your project, or in a <code>[design]</code> table of <code>salam.toml</code>. The compiler looks in the folder you build from and in the folders above it. Whatever the page sets itself wins over the file.</p>
<pre class="code snip" dir="ltr"><code>[design]
palette = "brand"
theme = "auto"
font-sans = "Inter, sans-serif"
font-url = "https://fonts.googleapis.com/css2?family=Inter:wght@400;700"

[design.tokens]
radius = "0.5rem"
dark-ring = "oklch(0.7 0.15 260)"

[design.palette.brand]
base = "zinc"
primary = "oklch(0.6 0.2 260)"
dark-primary = "oklch(0.7 0.15 260)"</code></pre>
<p>In <code>design.toml</code> the same keys are written without the <code>design.</code> prefix (<code>[tokens]</code>, <code>[palette.brand]</code>). A <code>[design.palette.NAME]</code> table is your own palette: <code>base</code> is the built in palette it starts from, and every other key is a token, with <code>dark-</code> or <code>light-</code> in front for one side only. Then <code>palette = "brand"</code> in the file or on a page uses it.</p>
<h2 id="typos">Mistakes are reported</h2>
<p>A token name that does not exist (<code>primry</code>) or a palette that is not defined is not silently ignored: the page carries a <code>salam-design-warning</code> meta tag and prints the same message to the browser console. To set your own CSS variable, start the name with two dashes, as in <code>--brand-x: #123</code>.</p>
<h2 id="variants">Variants and sizes</h2>
<p>A component with several looks has a <code>variant</code> attribute, and one with several sizes has a <code>size</code> attribute. Each takes a single word, and the list of words is in the lesson of the component.</p>
<h2 id="override">Your own styles win</h2>
<p>Every rule of the design has the lowest possible weight, so anything you write on an element, such as <code>background = red</code> or <code>padding = 4</code>, overrides it without a fight. You never need to undo the design first.</p>
<h2 id="none">Without a design</h2>
<p>Set <code>design = "none"</code> and the components lose their styling but keep their behaviour: the tabs below still switch, a dialog still opens, a menu still closes on Escape. This is also how you start your own look from nothing.</p>
{{example.ds-overview-none}}
<h2 id="platforms">Where it applies</h2>
<p>The design is drawn on the web build today. The native, Android and iOS builds ignore it and keep their own drawing. More design systems will be added behind the same <code>design</code> setting, and each component page in the next lessons will say which ones it supports.</p>
<p>A new design is a new name in the <code>design</code> list plus its own styles, one set per component (the files <code>ds_&lt;design&gt;_*.salam</code> in <code>layoutgen</code>). The markup, the keyboard handling and the events stay the same, only the styles change. A component that the chosen design does not style yet falls back to the shadcn version, so a page never loses a component when you switch designs.</p>
