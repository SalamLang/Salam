speed.limits_title = What these numbers do not show
speed.limits <<
<ul>
<li>Most programs finish in 2 to 30 ms (the median C time is 10.5 ms), so process start-up is part of every time and a millisecond is a large share. One sign of it: Salam built with tcc and no optimiser still averages 11.0 ms, close to the optimised build. The suite separates compiled languages from interpreted ones clearly; between compiled languages, read it as the same range, not as a ranking.</li>
<li>Each time is the fastest of 10 runs on a shared GitHub Actions virtual machine. Gaps under about 5% can flip on the next run.</li>
<li>Three programs (40 to 42) use Salam's own matrix and tensor library while C, <bdi>C++</bdi>, Rust and Go use hand-written loops, so they compare libraries, not compilers, and are left out of the averages above. Salam is ahead on two (14.3 ms vs 42.5 ms for C, and 7.3 ms vs 38.1 ms for <bdi>C++</bdi>) and far behind on the third (36.4 ms vs 4.1 ms for C, where gcc removes most of the loop work).</li>
<li>Every language implements the same algorithm with the same output, written the way that language is normally written. These are small programs; they do not measure large applications, memory-heavy workloads or how long a big project takes to build.</li>
</ul>
>>

speed.method_title = Method
speed.method_text = Each of the 42 programs was written in C, <bdi>C++</bdi>, Rust, Go, Python, PHP and Salam with the same algorithm, and every version's output was checked against C's before timing. Each program ran 10 times after one untimed warm-up and the fastest run was kept; the averages are geometric means of those times. C and <bdi>C++</bdi> were built with <code>gcc -O3</code>, Rust with <code>-C opt-level=3</code>, and Salam with its LLVM backend at <code>-O3</code>. Plain <code>salam build</code> with no options uses tcc without an optimiser and averaged 11.0 ms on the same 39 programs.
