speed.router_links = The full per-route table, the exact machine and software versions, and the <a href="https://github.com/SalamLang/Salam/tree/main/tests/en/apps/httpbench">harness itself</a> (including the raw, request-by-request results) are on GitHub in <a href="https://github.com/SalamLang/Salam/blob/main/tests/en/apps/httpbench/bench/BENCHMARK.md">BENCHMARK.md</a>. It ran on a shared 6-vCPU sandbox with steady background load from unrelated work (a load average around 11). Every server shared that load, because each route was measured on all of them back to back, but it favours servers that keep few threads, Salam's included: on a quiet machine Salam's lead over Fiber was about 16% on the geometric mean. Don't compare req/s numbers across the two benchmarks on this page, and rerun it on your own hardware for numbers to plan capacity against.

speed.method_title = Method
speed.method_text = Forty-two programs (numeric work, primes, sorting, strings, matrices, tensors and more) were implemented the same way in C, <bdi>C++</bdi>, Rust, Go, Python, PHP and Salam, and every language's output was compared before timing to make sure they agreed. For each program the fastest run was recorded, and for each language the geometric mean of those times was taken; C and <bdi>C++</bdi> were built at the highest optimisation level (O3). The Salam numbers on this page come from the LLVM backend at O3, so that the comparison with C and Rust is fair; plain <code>salam build</code> with no options uses tcc with no optimiser and averages 16.32 ms.
