pkg.intro <<
<p>Most programs have to read something and write something. The <code>io</code> package holds the simplest ways to do it: read one line from the user, read or write a whole file in one go, or work through an open file piece by piece.</p>
<p>The functions that take a file name, such as <code>ReadFile</code>, open and close the file themselves. The functions that take a <code>File*</code> work on a file you opened yourself with <code>os.Open</code>; remember to close it with <code>Close</code>.</p>
<p>Use <code>io</code> for the everyday jobs. For checking whether a path exists, listing folders, deleting or renaming files, go to <a href="/std/fs/">fs</a>; for building paths, <a href="/std/fs/path/">fs/path</a>; for formatted output, <a href="/std/fmt/">fmt</a>.</p>
<div class="note"><p>Things that catch people out:</p>
<ul>
<li>A missing file is not an error here. <code>ReadFile</code> returns an empty string, and <code>Lines</code> returns a vector with one empty string in it, so an empty file and a missing one look the same. When the difference matters, check first with <code>os.Exists</code>.</li>
<li>Lines are split on <code>\n</code> only. A file saved with Windows line endings keeps a <code>\r</code> at the end of each line from <code>Lines</code> and <code>Readline</code>; trim the line before comparing it.</li>
<li>Sizes are counted in <strong>bytes</strong>, not characters. Outside ASCII one character takes several bytes, so reading a file in chunks can split a character across two chunks.</li>
<li>The text functions work on <code>str</code>, which ends at the first zero byte. Binary files such as images are cut short there, so keep this package for text.</li>
</ul></div>
<h2 id="guide-config">Reading a settings file</h2>
<p>A small <code>key = value</code> file is the most common thing a program reads at start up. <code>Lines</code> gives you the file as a vector of lines, so the loop only has to skip blank lines and comments and cut each line at the first <code>=</code>. Warnings about bad lines go to standard error with <code>EPrintln</code>, so they never mix with the program's real output.</p>
{{example.io-guide-config}}
<p>Every value comes back as text; convert it where you use it, here with <code>to_int</code>. <code>Lines</code> returns a fresh vector, so free it with <code>defer</code> as soon as you have it. For a structured format with nesting, use <a href="/std/encoding/json/">encoding/json</a> or <a href="/std/config/">config</a> instead of parsing by hand.</p>

<h2 id="guide-log">Appending to a log</h2>
<p><code>AppendFile</code> opens the file, adds the text at the end and closes it again on every call, so the log is complete on disk even if the program stops halfway. That makes it a good fit for a log or an audit trail. Both <code>WriteFile</code> and <code>AppendFile</code> return minus one when the file cannot be opened, which is worth checking when the path comes from the user or from a setting.</p>
{{example.io-guide-log}}
<p>Here <code>WriteFile</code> with an empty string starts a new log each time the program runs. Leave that line out and the log keeps growing across runs.</p>

<h2 id="guide-chunks">Reading a large file in pieces</h2>
<p><code>ReadFile</code> and <code>Lines</code> hold the whole file in memory. For a file of hundreds of megabytes, open it yourself with <code>os.Open</code> and read a fixed number of bytes at a time with <code>Read</code>. An empty string means the end of the file. Check the handle against <code>null</code> before using it: that is how <code>os.Open</code> says the file could not be opened.</p>
{{example.io-guide-chunks}}
<p>The size is in bytes, so a chunk boundary can fall in the middle of a multi-byte character. When you only count or copy bytes this does not matter. When you need whole lines, read with <code>Readline</code> instead, as in the next section.</p>

<h2 id="guide-csv">Processing a file line by line</h2>
<p><code>Readline</code> returns one line at a time without its line ending, so only the current line is in memory. Read the header once, then loop until the empty string that marks the end of the file.</p>
{{example.io-guide-csv}}
<p>One catch: an empty line in the middle of the file also comes back as an empty string, and this loop would stop there. If your files can contain blank lines, compare the position with the file size, or read with <code>Lines</code> when the file is small enough. For real CSV with quoted fields, use <a href="/std/encoding/csv/">encoding/csv</a>.</p>

doc.Input = Reads one line from standard input, usually the keyboard, and returns it without the line ending. It is the same thing <code>input ""</code> does. The example below waits for you to type, so here it is only compiled and not run.
doc.Read = Reads up to <code>size</code> bytes from the current position in the file. At the end of the file it returns an empty string.
doc.Readline = Reads one line from the file, without the <code>\n</code> at its end (a <code>\r</code> before it stays). At the end of the file it returns an empty string, and so does a blank line, so a loop that stops on <code>""</code> also stops at the first blank line.
doc.Write = Writes a string to an open file and returns the number of bytes written, or minus one when the handle is <code>null</code>.
doc.Seek = Moves the reading and writing position in a file. <code>offset</code> is a distance in bytes and <code>whence</code> says where to count from: zero is the start of the file, one is the current position and two is the end. It returns zero on success and minus one on failure.
doc.Close = Closes the file. Every file you open has to be closed once, and <code>defer</code> is a good place for it.
doc.ReadFile = Reads the whole content of a file in one go. If the file does not exist, or cannot be read, it returns an empty string.
doc.WriteFile = Creates the file, or empties it if it already exists, and writes the string into it. It returns the number of bytes written, or minus one if the file could not be opened.
doc.AppendFile = Adds the string to the end of the file, leaving what was already there alone. If the file does not exist it is created. Like <code>WriteFile</code> it returns a byte count or minus one.
doc.Lines = Reads a file and returns its lines in a vector. The whole text is trimmed first, so blank lines at the end disappear, and so does any indentation on the very first line. A missing file gives one empty line. Release the vector with <code>free</code> when you are done with it.
doc.EPrint = Writes a string to standard error, without a line break. Errors and warnings belong here rather than in the program's real output.
doc.EPrintln = Like <code>EPrint</code>, but moves to the next line after the message.
doc.Flush = Writes out whatever is still sitting in the output buffer. Useful when you have written something with <code>print</code> that has no line ending and want the user to see it at once.
doc.ReadAll = Reads everything left from the current position to the end of the file.
doc.Copy = Writes everything left in the file <code>src</code> into the file <code>dst</code> and returns the number of bytes copied. It suits large files, since it never holds the whole file in memory.
doc.WriteLines = Writes each element of a vector as one line of the file. An existing file is rewritten. It returns a byte count, or minus one.

ex.Seek = io-Read
ex.Close = io-Read
ex.ReadAll = io-Read
ex.WriteFile = io-ReadFile
ex.AppendFile = io-ReadFile
ex.WriteLines = io-Lines
