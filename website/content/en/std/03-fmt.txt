pkg.intro <<
<p>When you want tidy, readable output, the <code>fmt</code> package is what you reach for. With it you turn numbers into text, line text up in fixed-width columns, and build sentences from a template.</p>
<p>The templates are simple: every <code>{}</code> in the template is filled with the next element of the vector of values. Since the values are strings, convert numbers first with a function such as <code>Int</code>.</p>
<div class="note"><p>Coming from <code>printf</code> or Go, watch for these:</p>
<ul>
<li>There are no verbs such as <code>%d</code> or <code>{:.2}</code>. A hole is always a bare <code>{}</code>; widths and decimals are set by formatting the value first with <code>PadLeft</code> or <code>FloatPrec</code>.</li>
<li>A literal <code>{}</code> cannot be written in a template, because there is no escape for it.</li>
<li><code>Hex</code> and <code>Uint</code> take a <code>u64</code>, so an <code>int</code> needs a cast: <code>fmt.Hex(n as u64)</code>.</li>
</ul></div>
<h2 id="guide-table">Printing a table</h2>
<p>A table in plain text is a row of padded cells. Text columns read best aligned to the left with <code>PadRight</code>, and number columns aligned to the right with <code>PadLeft</code>, so the digits of each place line up. A small helper that builds one row keeps every line of the table the same shape, header included.</p>
{{example.fmt-guide-receipt}}
<p>Money is printed with <code>FloatPrec</code> and two places, so <code>7</code> shows as <code>7.00</code> and every amount has the same width. The widths count characters, not bytes, so the same code lines up Persian or Arabic names too. A value longer than its column is never cut, it only pushes the rest of the row to the right; pick widths that fit your longest value.</p>
<p>If the names are in Persian or Arabic and you look at the table in a terminal, the columns may appear in a different order, because how mixed right-to-left text and numbers are shown depends on the Unicode bidirectional algorithm. The strings themselves are correct; for exact display on the web, use an HTML table.</p>

<h2 id="guide-templates">Filling a message template</h2>
<p><code>Sprintf</code> fills each <code>{}</code> with the next string from a vector. Keeping the sentence in one template, instead of a long chain of <code>+</code>, makes it easy to read and easy to change later, or to swap for a translated template. Numbers and booleans go in through <code>Int</code>, <code>Float</code> or <code>Bool</code> first, because every value is a string.</p>
{{example.fmt-guide-messages}}
<p>The vector of values belongs to you, so free it when the message is built. When the result should go to a file instead of a string, <code>Fprintf</code> takes the same template and values and writes them to an open <code>File*</code>.</p>

<h2 id="guide-hex">Hexadecimal output</h2>
<p><code>Hex</code> writes a number in base sixteen with lower case letters and no <code>0x</code>, and it does not add leading zeros. Formats with a fixed width, such as a CSS color where each channel is exactly two digits, need that zero added by hand.</p>
{{example.fmt-guide-colors}}
<p><code>PadLeft</code> always pads with spaces, which is right for the shade column on the left but not for hex digits. For anything bigger than one byte, compare the length with the width you need and add as many zeros as are missing.</p>

doc.Int = Turns a whole number into text, with a minus sign where one is needed.
doc.Float = Turns a decimal number into the shortest text that reads back as the same number: <code>1.0</code> becomes <code>1</code>, <code>0.1</code> stays <code>0.1</code> and <code>1.0 / 3.0</code> becomes <code>0.3333333333333333</code>. Very large or very small numbers use an exponent, such as <code>1e+21</code>. Use <code>FloatPrec</code> when the number of places must be fixed.
doc.Bool = Turns a boolean into <code>"true"</code> or <code>"false"</code>.
doc.PadLeft = If the text is shorter than <code>width</code>, adds spaces on its left until it reaches that width. The width counts characters, so it behaves correctly outside ASCII too. In a column of numbers this is what lines them up on the right.
doc.PadRight = Like <code>PadLeft</code>, but puts the spaces on the right of the text.
doc.Center = Places the text in the middle of the given width. When the padding does not divide evenly, the extra space goes on the right.
doc.Sprintf = Takes the template and fills each <code>{}</code> in turn from the <code>args</code> vector. If the values run out the remaining holes are left empty, and extra values are ignored.
doc.Fprintf = Like <code>Sprintf</code>, but writes the result straight into an open file and returns the number of bytes written.
doc.FloatPrec = Turns a decimal number into text with the number of decimal places you ask for. Halves round away from zero, as on paper: <code>2.675</code> with two places is <code>2.68</code> and <code>-1.5</code> with none is <code>-2</code>.
doc.Uint = Turns an unsigned 64-bit number into text, for numbers too large to fit in an <code>i64</code>.
doc.Hex = Writes the number in base sixteen in lower case, with no <code>0x</code> prefix and no leading zeros. It takes a <code>u64</code>, so cast an <code>int</code> with <code>as u64</code>.
