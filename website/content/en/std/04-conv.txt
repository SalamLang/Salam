pkg.intro <<
<p>Text arriving from a user, a file or the network is always a string; to do arithmetic with it you have to turn it into a number, and to show the result you turn it back into text. The <code>conv</code> package does both halves of that.</p>
<p>The parsing functions also understand Persian digits (<code>۰۱۲۳۴۵۶۷۸۹</code>) and Arabic ones (<code>٠١٢٣٤٥٦٧٨٩</code>), so a number typed on a Persian keyboard is read without any fuss. These functions never fail: they read from the start of the string for as long as it makes sense as a number and ignore the rest, and return zero when they find no digits at all.</p>
<p><a href="/std/fmt/">fmt</a> wraps the formatting half of this package with padding and templates; reach for <code>conv</code> when you need the parsing half, or one of the three float formats below. The string methods <code>to_int</code> and <code>to_float</code> do the same parsing as <code>ParseInt</code> and <code>ParseFloat</code>.</p>
<div class="note"><p>Things that catch people out:</p>
<ul>
<li>A number that does not fit is not reported. <code>ParseInt</code> wraps around past the 64-bit range, and <code>Atoi</code> cuts the result to 32 bits, so <code>Atoi("3000000000")</code> is <code>-1294967296</code>. Use <code>ParseInt</code> for ids, sizes and timestamps.</li>
<li><code>ParseBool</code> is case sensitive: <code>True</code> and <code>YES</code> are false.</li>
<li>A comma is not a decimal separator: <code>ParseFloat("1,5")</code> is 1.</li>
</ul></div>
<h2 id="guide-strict">Strict parsing of user input</h2>
<p>Because <code>ParseInt</code> never fails, <code>"12abc"</code> quietly becomes 12 and an empty field becomes 0. That is handy for loose input, but a form usually has to reject such values. A simple strict check: normalise the digits, parse, format the number back with <code>FormatInt</code> and compare. If anything was dropped on the way, the two strings differ.</p>
{{example.conv-guide-strict}}
<p><code>str.ToEnglishDigits</code> turns Persian and Arabic digits into ASCII ones first, so <code>۱۴۰۳</code> passes the comparison. This check also rejects leading zeros, as in <code>-0015</code>; if you want to allow them, strip the zeros before comparing. Report the problem to the user with the original text, not the parsed number.</p>

<h2 id="guide-mixed-digits">Adding up numbers in mixed digits</h2>
<p>Text pasted from different sources often mixes ASCII, Persian and Arabic digits, and writes the decimal point as <code>.</code> or as the Persian separator <code>٫</code>. The parsing functions accept all of them, so no clean up is needed before the arithmetic.</p>
{{example.conv-guide-sum}}
<p><code>ParseInt</code> stops at the decimal point and keeps only the whole part, which is why the two sums differ. Use <code>ParseFloat</code> whenever a value may have a fraction. <code>FormatFloatShort</code> prints the result without a trailing <code>.0</code> or long tails of digits.</p>

<h2 id="guide-settings">Booleans and hex values from a settings file</h2>
<p>Settings files spell their switches in many ways. <code>ParseBool</code> accepts <code>true</code>, <code>1</code>, <code>yes</code> and <code>on</code>, in lower case, with any spaces around them and treats everything else as false, so a missing or misspelled value turns a feature off rather than on. <code>ParseHex</code> reads colors, masks and ids written in base sixteen, in either case.</p>
{{example.conv-guide-settings}}
<p>The prefix <code>0x</code> is optional for <code>ParseHex</code> (the upper case <code>0X</code> is not understood), and neither is <code>#</code>, so it is cut first with <code>str.TrimPrefix</code>. The shifts and masks then take the three color channels out of the single number.</p>

<h2 id="guide-floats">Choosing a float format</h2>
<p>A decimal number can be turned into text in three ways, and each one suits a different job. <code>FormatFloat</code> writes every digit needed to read back exactly the same number, which is what you want in a file another program will read. <code>FormatFloatShort</code> rounds to six significant digits, like <code>%g</code> in C, which is what a person expects to see. <code>FormatFloatPrec</code> rounds to a fixed number of places, for money and reports.</p>
{{example.conv-guide-floats}}
<p>The output shows the trade off: the short form of <code>0.1 * 3.0</code> reads as <code>0.3</code>, but parsing that text gives a slightly different number. Save data with <code>FormatFloat</code> and show it with one of the other two.</p>

doc.FormatUint = Turns an unsigned 64-bit number into text.
doc.FormatInt = Turns a 64-bit whole number into text, with a minus sign for negative values.
doc.FormatBool = Turns <code>true</code> into <code>"true"</code> and <code>false</code> into <code>"false"</code>.
doc.ParseBool = Turns a string into a boolean. <code>"true"</code>, <code>"1"</code>, <code>"yes"</code> and <code>"on"</code>, with any surrounding spaces, count as true, and anything else as false. The check is case sensitive, so <code>"True"</code> is false.
doc.ParseInt = Reads a whole number from the start of a string. Leading spaces are ignored and a <code>+</code> or <code>-</code> sign is accepted. Persian, Arabic and English digits are all understood, and reading stops at the first character that is not a digit. There is no overflow check: a number past the 64-bit range wraps around.
doc.Atoi = The same as <code>ParseInt</code>, but returns an <code>int</code>, which is 32 bits. Larger values are cut to their low 32 bits without warning.
doc.ParseFloat = Reads a decimal number from a string. Scientific notation such as <code>2.5e3</code>, and Persian digits with the Persian decimal separator (<code>۳٫۷۵</code>), are both accepted. A comma is not read as a decimal point, and text with no number in it gives 0.
doc.IsNaNF = Returns true when the number is "not a number" (NaN), for instance the result of parsing <code>"nan"</code>. No comparison with <code>==</code> can detect this case, because NaN is not even equal to itself.
doc.FormatFloat = Turns a decimal number into text with every digit needed to read exactly the same number back.
doc.FormatFloatShort = Rounds to six significant digits and drops trailing zeros, like <code>%g</code> in C: <code>0.1 + 0.2</code> comes out as <code>0.3</code> and <code>3.14159265</code> as <code>3.14159</code>. From a million up, and below 0.0001, it switches to an exponent, so <code>1234567.0</code> is <code>1.23457e+06</code>.
doc.FormatFloatPrec = Turns a decimal number into text with the number of decimal places you ask for, rounding halves away from zero. At most 15 places are written, and a value above about 9e14 falls back to <code>FormatFloat</code>.
doc.FormatHex = Writes the number in base sixteen in lower case, with no <code>0x</code> prefix.
doc.ParseHex = Reads a base sixteen number. The <code>0x</code> prefix is optional and both upper and lower case digits are accepted, but the prefix itself must be a lower case <code>0x</code>. Reading stops at the first character that is not a hex digit.

ex.FormatUint = conv-FormatInt
ex.FormatBool = conv-FormatInt
ex.FormatHex = conv-FormatInt
ex.ParseBool = conv-ParseInt
ex.Atoi = conv-ParseInt
ex.ParseHex = conv-ParseInt
ex.IsNaNF = conv-ParseFloat
ex.FormatFloat = conv-ParseFloat
ex.FormatFloatShort = conv-ParseFloat
ex.FormatFloatPrec = conv-ParseFloat
