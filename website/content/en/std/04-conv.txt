pkg.intro <<
<p>Text arriving from a user, a file or the network is always a string; to do arithmetic with it you have to turn it into a number, and to show the result you turn it back into text. The <code>conv</code> package does both halves of that.</p>
<p>The parsing functions also understand Persian digits (<code>۰۱۲۳۴۵۶۷۸۹</code>) and Arabic ones (<code>٠١٢٣٤٥٦٧٨٩</code>), so a number typed on a Persian keyboard is read without any fuss. Spaces, tabs and line breaks around the text are ignored, and one <code>+</code> or <code>-</code> may come first. Anything else makes the parser throw an <a href="/std/core/">Error</a> instead of guessing: an empty string, a stray character such as the <code>abc</code> in <code>12abc</code>, a sign with no digits, or a number too large for its type. Catch it with <code>try:</code> ... <code>catch e:</code>, or pass it on with <code>try</code> in a function that is itself <code>throws</code>.</p>
<p>When a bad value should simply turn into a default, use the <code>Or</code> form of the parser: <code>ParseIntOr</code>, <code>AtoiOr</code>, <code>ParseFloatOr</code>, <code>ParseBoolOr</code> and <code>ParseHexOr</code> take the fallback as their second argument and never throw.</p>
<p><a href="/std/fmt/">fmt</a> wraps the formatting half of this package with padding and templates; reach for <code>conv</code> when you need the parsing half, or one of the three float formats below. The string methods <code>to_int</code> and <code>to_float</code> are the old lenient readers: they report nothing and give 0 for text that is not a number, so prefer the functions here for anything a user typed.</p>
<div class="note"><p>Things that catch people out:</p>
<ul>
<li><code>Atoi</code> returns an <code>int</code>, which is 32 bits, so <code>Atoi("3000000000")</code> throws <code>OutOfRange</code>. Use <code>ParseInt</code> for ids, sizes and timestamps.</li>
<li>Separators are not digits: <code>1_000</code>, <code>1 000</code> and <code>1,000</code> all throw, and so does a decimal point in <code>ParseInt</code>.</li>
<li><code>ParseBool</code> is case sensitive: <code>True</code> and <code>YES</code> throw.</li>
<li>A comma is not a decimal separator: <code>ParseFloat("1,5")</code> throws. The Persian separator <code>٫</code> is fine.</li>
<li>The error says where the problem is. <code>e.kind</code> is <code>Syntax</code> or <code>OutOfRange</code>, <code>e.code</code> is one of <code>conv.empty</code>, <code>conv.no_digits</code>, <code>conv.invalid_char</code>, <code>conv.not_bool</code> and <code>conv.overflow</code>, and <code>e.offset</code>, <code>e.line</code> and <code>e.column</code> point at the bad character.</li>
</ul></div>
<h2 id="guide-strict">Rejecting bad user input</h2>
<p>A form has to say no to <code>12abc</code> or an empty field, and tell the user why. <code>ParseInt</code> does the checking for you: wrap it in <code>try:</code> and show the message from the error.</p>
{{example.conv-guide-strict}}
<p>Persian digits and the spaces around <code>۱۴۰۳</code> are accepted as they are, and leading zeros, as in <code>-0015</code>, are fine too. <code>e.message</code> names the character that broke the number and <code>e.column</code> says where it is, so the user can find it. A number past the 64-bit range is an <code>OutOfRange</code> error rather than a wrapped value.</p>

<h2 id="guide-mixed-digits">Adding up numbers in mixed digits</h2>
<p>Text pasted from different sources often mixes ASCII, Persian and Arabic digits, and writes the decimal point as <code>.</code> or as the Persian separator <code>٫</code>. The parsing functions accept all of them, so no clean up is needed before the arithmetic.</p>
{{example.conv-guide-sum}}
<p>A whole number has no decimal point, so <code>ParseInt</code> rejects <code>4.5</code> and <code>۰٫۵</code>; here <code>ParseIntOr</code> counts them as 0, which is why the two sums differ. Use <code>ParseFloat</code> whenever a value may have a fraction. <code>FormatFloatShort</code> prints the result without a trailing <code>.0</code> or long tails of digits.</p>

<h2 id="guide-settings">Booleans and hex values from a settings file</h2>
<p>Settings files spell their switches in many ways. <code>ParseBool</code> reads <code>true</code>, <code>1</code>, <code>yes</code> and <code>on</code> as true and <code>false</code>, <code>0</code>, <code>no</code> and <code>off</code> as false, in lower case, with any spaces around them; anything else throws. Where a misspelled switch should just stay off, <code>ParseBoolOr</code> with a fallback of <code>false</code> does that. <code>ParseHex</code> reads colors, masks and ids written in base sixteen, in either case.</p>
{{example.conv-guide-settings}}
<p>The prefix <code>0x</code> is optional for <code>ParseHex</code> (the upper case <code>0X</code> throws), and so does <code>#</code>, so it is cut first with <code>str.TrimPrefix</code>. The shifts and masks then take the three color channels out of the single number.</p>

<h2 id="guide-floats">Choosing a float format</h2>
<p>A decimal number can be turned into text in three ways, and each one suits a different job. <code>FormatFloat</code> writes every digit needed to read back exactly the same number, which is what you want in a file another program will read. <code>FormatFloatShort</code> rounds to six significant digits, like <code>%g</code> in C, which is what a person expects to see. <code>FormatFloatPrec</code> rounds to a fixed number of places, for money and reports.</p>
{{example.conv-guide-floats}}
<p>The output shows the trade off: the short form of <code>0.1 * 3.0</code> reads as <code>0.3</code>, but parsing that text gives a slightly different number. Save data with <code>FormatFloat</code> and show it with one of the other two.</p>
<div class="table-wrap"><table>
<thead><tr><th>Purpose</th><th>Function</th></tr></thead>

<tr><td>Prices, percentages, aligned columns</td><td><code>FormatFloatPrec</code></td></tr>
<tr><td>Detecting a NaN after parsing</td><td><code>IsNaNF</code></td></tr>

</table></div>

doc.FormatUint = Turns an unsigned 64-bit number into text.
doc.FormatInt = Turns a 64-bit whole number into text, with a minus sign for negative values.
doc.FormatBool = Turns <code>true</code> into <code>"true"</code> and <code>false</code> into <code>"false"</code>.
doc.ParseBool = Turns a string into a boolean. <code>"true"</code>, <code>"1"</code>, <code>"yes"</code> and <code>"on"</code> are true, <code>"false"</code>, <code>"0"</code>, <code>"no"</code> and <code>"off"</code> are false, with any spaces around them. Anything else throws a <code>Syntax</code> error (code <code>conv.not_bool</code>, or <code>conv.empty</code> for an empty string). The check is case sensitive, so <code>"True"</code> throws.
doc.ParseBoolOr = Like <code>ParseBool</code>, but returns <code>fallback</code> instead of throwing.
doc.ParseInt = Reads a whole number, a 64-bit <code>i64</code>. Spaces around it are ignored and one <code>+</code> or <code>-</code> sign may come first; Persian, Arabic and English digits are all understood, even mixed. Throws a <code>Syntax</code> error for an empty string, a sign with no digits or any other character (a decimal point, a separator, a letter), with the offset, line and column of that character, and <code>OutOfRange</code> (code <code>conv.overflow</code>) when the number does not fit in 64 bits.
doc.ParseIntOr = Like <code>ParseInt</code>, but returns <code>fallback</code> instead of throwing.
doc.Atoi = The same as <code>ParseInt</code>, but returns an <code>int</code>, which is 32 bits; a number outside that range throws <code>OutOfRange</code>.
doc.AtoiOr = Like <code>Atoi</code>, but returns <code>fallback</code> instead of throwing.
doc.ParseFloat = Reads a decimal number. Scientific notation such as <code>2.5e3</code>, a leading or trailing point (<code>.5</code>, <code>5.</code>), <code>inf</code>, <code>infinity</code> and <code>nan</code> in any case, and Persian digits with the Persian decimal separator (<code>۳٫۷۵</code>) are all accepted, with spaces around. A comma, a second point, an exponent with no digits or any other character throws a <code>Syntax</code> error; a number too large for a 64-bit float throws <code>OutOfRange</code>. A number too small to represent becomes 0.
doc.ParseFloatOr = Like <code>ParseFloat</code>, but returns <code>fallback</code> instead of throwing.
doc.ScanFloat = Reads the decimal number at the start of the text without reporting any problem: Persian digits and a Persian decimal separator are accepted, <code>"12abc"</code> reads as <code>12</code>, and text with no number in it gives <code>0</code>. It is the unchecked reader behind <code>ParseFloat</code>; use <code>ParseFloat</code> when bad input must be an error.
doc.IsNaNF = Returns true when the number is "not a number" (NaN), for instance the result of parsing <code>"nan"</code>. No comparison with <code>==</code> can detect this case, because NaN is not even equal to itself.
doc.FormatFloat = Turns a decimal number into text with every digit needed to read exactly the same number back.
doc.FormatFloatShort = Rounds to six significant digits and drops trailing zeros, like <code>%g</code> in C: <code>0.1 + 0.2</code> comes out as <code>0.3</code> and <code>3.14159265</code> as <code>3.14159</code>. From a million up, and below 0.0001, it switches to an exponent, so <code>1234567.0</code> is <code>1.23457e+06</code>.
doc.FormatFloatPrec = Turns a decimal number into text with the number of decimal places you ask for, rounding halves away from zero. At most 15 places are written, and a value above about 9e14 falls back to <code>FormatFloat</code>.
doc.FormatHex = Writes the number in base sixteen in lower case, with no <code>0x</code> prefix.
doc.ParseHex = Reads a base sixteen number. The <code>0x</code> prefix is optional and both upper and lower case digits are accepted, but the prefix itself must be a lower case <code>0x</code>; spaces around are ignored and there is no sign. Up to 16 digits fit; a value above <code>7fffffffffffffff</code> comes back negative with the same 64 bits, and a longer one throws <code>OutOfRange</code>. Any other character throws a <code>Syntax</code> error.
doc.ParseHexOr = Like <code>ParseHex</code>, but returns <code>fallback</code> instead of throwing.

ex.ParseFloatOr = conv-ParseIntOr
ex.ScanFloat = conv-ParseFloat
ex.ParseHexOr = conv-ParseIntOr

ex.FormatFloat = conv-ParseFloat
ex.FormatFloatShort = conv-ParseFloat
ex.FormatFloatPrec = conv-ParseFloat
