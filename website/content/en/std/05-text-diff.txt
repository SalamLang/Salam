pkg.intro <<
<p>The <code>diff</code> package finds what changed between two texts. It compares them line by line, finds the shortest list of lines to remove and add, and can print the result as a <em>unified diff</em>, the format of <code>diff -u</code> and <code>git diff</code>: a <code>---</code> and a <code>+++</code> header, then hunks that start with <code>@@ -1,3 +1,4 @@</code> and mark lines with <code> </code>, <code>-</code> and <code>+</code>. The output follows Python's <code>difflib.unified_diff</code> exactly, so tools that read one read the other. Use it for a test that compares generated output with an expected file, for a build step that shows what a generator changed, and for an update check that asks whether anything is different.</p>
<p>There are two levels. <code>Unified</code> and <code>UnifiedText</code> give the finished lines; <code>Opcodes</code> gives the edit script itself, a list of <code>Opcode</code> records that say "lines a[i1:i2] were replaced by b[j1:j2]", for a program that wants to draw the difference its own way. <code>Ratio</code> and <code>RatioText</code> give a number between 0 and 1 for how alike two inputs are.</p>
<p>What people get wrong:</p>
<ul>
<li>Expecting nothing back to mean an error. When both inputs are equal, <code>Unified</code> returns an empty list and <code>UnifiedText</code> an empty string, not even a header. That is how you test for "no difference".</li>
<li>Passing text where lines are expected. <code>Unified</code> takes <code>Vector&lt;str&gt;</code>; split a text with <code>Lines</code> first, or call <code>UnifiedText</code>. <code>Lines</code> drops the last empty piece after a final newline and a trailing <code>\r</code> on each line, so files with Windows line ends compare equal to files with Unix ones.</li>
<li>Reading the ratio as an edit distance. <code>Ratio</code> is <code>2*M/T</code>, where <code>M</code> is the number of lines the two share in order and <code>T</code> the total of both lengths. It is built from a longest common subsequence, so it can be a little higher than <code>difflib.SequenceMatcher.ratio()</code>, which stops early on some inputs.</li>
<li>Diffing huge, completely different inputs. The search stops after 3000 edits and then treats what is left as one block replaced by another. The result is still a correct diff, only not the shortest.</li>
<li>Forgetting to free. <code>Lines</code>, <code>Unified</code>, <code>Opcodes</code> and <code>GroupedOpcodes</code> return vectors the caller frees (and each inner vector of <code>GroupedOpcodes</code>).</li>
</ul>
<h2 id="guide-files">Showing what changed between two files</h2>
<p>Read both files, hand them to <code>UnifiedText</code> with their names for the header, and print the answer when it is not empty. The third argument after the names is the number of unchanged lines to show around each change (3 is the usual choice, 0 shows only the changes).</p>
{{example.text-diff-guide-files}}
<h2 id="guide-similar">Suggesting the closest name</h2>
<p><code>RatioText</code> turns "how alike are these two words" into a number, so a program can answer a typo with "did you mean". The example below tries each option, keeps the one with the highest score and only suggests it when the score is at least 0.6. <code>Ratio</code> does the same for lists of lines: three of the four lines are shared, so the score is 0.75.</p>
{{example.text-diff-guide-similar}}
>>

doc.Equal = The opcode tag for lines that are the same in both inputs.
doc.Replace = The opcode tag for lines of the first input that were replaced by different lines of the second.
doc.Delete = The opcode tag for lines that are only in the first input.
doc.Insert = The opcode tag for lines that are only in the second input.
doc.Opcode = One step of the edit script: what happened to <code>a[a_start:a_stop]</code> compared with <code>b[b_start:b_stop]</code>. The range of the second input is empty for a delete, and the range of the first input is empty for an insert.
doc.Opcode.tag = One of <code>Equal</code>, <code>Replace</code>, <code>Delete</code> and <code>Insert</code>.
doc.Opcode.a_start = Index of the first line of the first input this step covers.
doc.Opcode.a_stop = Index after the last line of the first input this step covers.
doc.Opcode.b_start = Index of the first line of the second input this step covers.
doc.Opcode.b_stop = Index after the last line of the second input this step covers.
doc.Opcodes = The edit script that turns <code>a</code> into <code>b</code>: opcodes that follow each other and together cover both inputs from start to end. Neighbouring removals and additions are joined into one <code>Replace</code>. The caller frees the vector.
doc.GroupedOpcodes = The opcodes cut into hunks, each with at most <code>context</code> unchanged lines on either side of a change, and no hunk at all when the inputs are equal. A negative <code>context</code> counts as 0. The caller frees the outer vector and every inner one.
doc.Unified = The difference as the lines of a unified diff: the <code>---</code> and <code>+++</code> headers with the two names, then each hunk with its <code>@@</code> line. The lines have no line terminator. Equal inputs give an empty vector. The caller frees the vector.
doc.Lines = Splits a text into lines: on <code>\n</code>, dropping the empty piece after a final newline and a <code>\r</code> at the end of a line. An empty text has no lines. The caller frees the vector.
doc.UnifiedText = The same as <code>Unified</code> for two texts, as one string with a newline after every line; empty when the texts have the same lines.
doc.Ratio = How alike two lists of lines are, from 0 (nothing shared) to 1 (the same): twice the number of lines they share in order, divided by the sum of their lengths. Two empty lists give 1.
doc.RatioText = The same measure for two strings, counted in characters (code points, so Persian text is counted by letter). Use it for fuzzy matching of names and commands.
