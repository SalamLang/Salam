pkg.intro <<
<p>Salam strings are UTF-8, but some systems, Windows and a few C libraries above all, want text in UTF-16. In UTF-16 an ordinary character is one 16-bit "unit" and a rarer one, such as an emoji, takes two.</p>
<p>The <code>text</code> package converts in both directions and counts strings the way UTF-16 systems count them. Everything else you do with text, such as searching, splitting and changing case, lives in <a href="/std/str/">str</a>; for character classes, normalisation and grapheme clusters see <a href="/std/unicode/">unicode</a>.</p>
<div class="note"><p>Things to keep in mind:</p>
<ul>
<li>The memory <code>ToUtf16</code> returns is yours. It ends with a zero unit and must be released with <code>mem.Free</code>.</li>
<li><code>Utf16UnitAt</code> does no bounds check. Stop at the zero unit; reading past it reads whatever memory follows.</li>
<li>The input is not validated. Broken UTF-8 is converted as best it can be, and a lone surrogate in a UTF-16 array is copied into the result as is, which gives a string that is not valid UTF-8.</li>
</ul></div>
<h2 id="guide-limit">Checking a length limit the way JavaScript counts</h2>
<p>A browser, a JSON API written in JavaScript, Java or C#, and many databases measure a string in UTF-16 units. If your Salam server checks a limit in bytes or in characters, it can disagree with the form that sent the text: a limit of 12 that the browser enforced may look like 22 bytes to you, or a message the browser rejected may look short enough to Salam. <code>Utf16Len</code> counts the same way they do.</p>
{{example.text-guide-limit}}
<p>The three numbers per line are the byte length (<code>len</code>), the character count (<code>char_count</code>) and the UTF-16 length. For plain English they are equal. An accented letter adds a byte but not a unit. Each emoji is one character but two units, so the last message is only 10 characters long yet goes over a limit of 12.</p>

<h2 id="guide-truncate">Shortening text to a UTF-16 limit</h2>
<p>When the other side counts in UTF-16, a preview, a push notification or an SMS has to be cut in the same units. Cutting by bytes can split a Persian letter, and cutting by units can split an emoji into half a surrogate pair, which shows up as a box or a question mark. Walking whole characters with <code>str.Chars</code> and adding up the units of each one avoids both.</p>
{{example.text-guide-truncate}}
<p>One unit is kept back for the <code>…</code> at the end, so the result never goes over the limit. The emoji line stops one unit short of 16 because the next emoji needs two units and only one is left. A sequence that the reader sees as one symbol, such as a flag or a family emoji, is made of several characters and can still be cut in the middle; for that, walk <code>str.Graphemes</code> instead of <code>str.Chars</code>.</p>

<h2 id="guide-pairs">Walking UTF-16 units and surrogate pairs</h2>
<p><code>ToUtf16</code> builds a zero terminated array of 16-bit units, the shape that Windows functions with a <code>W</code> in their name and many C libraries want. Characters above U+FFFF, such as most emoji, take two units: a high surrogate between 55296 and 56319 followed by a low surrogate between 56320 and 57343. The example reads the units back one by one and joins each pair into its code point.</p>
{{example.text-guide-pairs}}
<p>The array is allocated on the heap and belongs to you: release it with <code>mem.Free</code>, here through <code>defer</code>. <code>FromUtf16</code> goes the other way and turns the units, pairs included, back into an ordinary Salam string, which is how you read text that a UTF-16 API handed back.</p>

doc.Utf16Len = Returns the number of UTF-16 units in the string. For most scripts this equals the number of characters, but each emoji counts as two.
doc.ToUtf16 = Converts a string into a zero-terminated UTF-16 array and returns its address. The array is yours to release with <code>mem.Free</code>.
doc.Utf16UnitAt = Reads unit number <code>i</code> from a UTF-16 array, as a number from 0 to 65535. For an emoji you see two consecutive units, a surrogate pair. There is no bounds check, so stop at the zero unit.
doc.FromUtf16 = Converts a zero-terminated UTF-16 array back into a Salam string, joining surrogate pairs. A <code>null</code> pointer gives an empty string.

ex.ToUtf16 = text-Utf16Len
ex.Utf16UnitAt = text-Utf16Len
ex.FromUtf16 = text-Utf16Len
