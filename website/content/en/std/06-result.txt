pkg.intro <<
<p>Salam has no exceptions. A function that may fail returns a <code>Result</code> rather than throwing: either <code>Ok</code> with a value, or <code>Err</code> with an explanation of what went wrong. The caller checks both cases with <code>match</code>, and the compiler will not let either be forgotten.</p>
<p>Inside a function that returns a Result itself, the <code>?</code> operator shortens the work: written after a call, it pulls out the successful value, and on an error returns that error straight away. The <a href="/learn/enums/#result">enums lesson</a> walks through the pattern step by step.</p>
<h2 id="guide-chain">Passing errors up with ?</h2>
<p>Real input is checked in several steps, and each step can fail with its own message. Write each step as a small function that returns a <code>Result</code>, then join them with <code>?</code>. The first step that fails ends the whole chain and its message reaches the caller unchanged, so the top level needs only one <code>match</code>.</p>
{{example.result-guide-address}}
<p>The success value does not have to be a number: here it is a whole <code>Address</code> struct. Note how the message for <code>cache:99999</code> comes from <code>parse_port</code> even though the caller only called <code>parse_address</code>. The check <code>str.FromInt(n) != text</code> catches text such as <code>http</code> that <code>to_int</code> would quietly read as 0.</p>

<h2 id="guide-enum-error">An enum as the error type</h2>
<p>A string is fine when the error is only shown to a person. When the caller has to react differently to different failures, make the error an enum with data. The compiler then makes every <code>match</code> on it handle every case, and each case carries exactly the details it needs.</p>
{{example.result-guide-enum-error}}
<p>The function that builds the error no longer decides the wording, which keeps the message in one place and makes it easy to translate. A web handler could map <code>UnknownUser</code> and <code>WrongPassword</code> to 401 and <code>Locked</code> to 423 with the same <code>match</code>.</p>
<p>A naming rule worth knowing: the enum name and the names of its data fields are single words, while members may have several words if a comma separates them and no word after the first is a keyword. In Persian code this is why a member is called <code>رمز اشتباه</code> rather than using the keyword <code>نادرست</code>.</p>

<h2 id="guide-batch">Collecting every error in a batch</h2>
<p><code>?</code> stops at the first failure, which is right for one request but wrong for an import of many rows, where the user wants to see every bad row at once. Loop over the input, <code>match</code> each result, add up the good values and keep the messages of the bad ones.</p>
{{example.result-guide-batch}}
<p>Put the row number into each message while you still know it. When a default value is good enough and the reason does not matter, <code>UnwrapOr</code> is shorter than a <code>match</code>; <code>IsOk</code> and <code>IsErr</code> answer a yes or no question without taking the value out.</p>

<h2 id="guide-which">Which tool for which job</h2>
<div class="table-wrap"><table>
<thead><tr><th>You want to</th><th>Write</th></tr></thead>

<tr><td>Handle both cases</td><td><code>match r: Ok(v): ... end Err(e): ... end end</code></td></tr>

doc.Result = A generic enum with two cases. <code>T</code> is the type of the successful value and <code>E</code> the type of the error, which is most often a <code>str</code>. Build one with <code>result.Result.Ok(...)</code> or <code>result.Result.Err(...)</code>.
doc.Result.Ok = The work succeeded, and the value is in <code>value</code>.
doc.Result.Err = The work did not happen, and the explanation is in <code>error</code>.
doc.IsOk = Returns true when the result is <code>Ok</code>.
doc.IsErr = Returns true when the result is <code>Err</code>.
doc.UnwrapOr = Returns the value when the result succeeded, and the default you supplied when it did not.
doc.Expect = Returns the value of a successful result. If the result is an error, the program stops with the message you gave, so use it only where you are sure an error is impossible.
