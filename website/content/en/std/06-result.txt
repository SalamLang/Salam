pkg.summary = Returning either a value or an error from a function, instead of throwing an exception.
pkg.title = The result package in Salam | Error handling without exceptions
pkg.description = The result package in Salam: the Result enum with its Ok and Err cases, the ? operator, and IsOk, UnwrapOr and Expect, with examples.
pkg.intro <<
<p>Salam has no exceptions. A function that may fail returns a <code>Result</code> rather than throwing: either <code>Ok</code> with a value, or <code>Err</code> with an explanation of what went wrong. The caller checks both cases with <code>match</code>, and the compiler will not let either be forgotten.</p>
<p>Inside a function that returns a Result itself, the <code>?</code> operator shortens the work: written after a call, it pulls out the successful value, and on an error returns that error straight away. The <a href="/learn/enums/#result">enums lesson</a> walks through the pattern step by step.</p>
>>

doc.Result = A generic enum with two cases. <code>T</code> is the type of the successful value and <code>E</code> the type of the error, which is most often a <code>str</code>. Build one with <code>result.Result.Ok(...)</code> or <code>result.Result.Err(...)</code>.
doc.Result.Ok = The work succeeded, and the value is in <code>value</code>.
doc.Result.Err = The work did not happen, and the explanation is in <code>error</code>.
doc.IsOk = Returns true when the result is <code>Ok</code>.
doc.IsErr = Returns true when the result is <code>Err</code>.
doc.UnwrapOr = Returns the value when the result succeeded, and the default you supplied when it did not.
doc.Expect = Returns the value of a successful result. If the result is an error, the program stops with the message you gave, so use it only where you are sure an error is impossible.

ex.IsErr = result-IsOk
ex.UnwrapOr = result-IsOk
ex.Expect = result-IsOk
