pkg.intro <<
<p>Arabic-script text does not arrive in one shape. One source writes «كتاب» with an Arabic kaf and another with a Persian one; one adds vowel marks, another a tatweel (ـــ), and some text, from a PDF for instance, carries the presentation forms of the letters. To a reader they are the same word; to a computer they are different strings, and the search fails.</p>
<p>The <code>arabic</code> package removes those differences. <code>Normalize</code> works from flags you choose, combined with <code>+</code>. For most purposes <code>NormalizePersian</code> or <code>SearchKey</code> is all you need.</p>
<p>This package works on letters. To change how numbers look, <a href="/std/str/">str</a> has <code>ToPersianDigits</code> and <code>ToEnglishDigits</code>; for the general Unicode forms behind it see <code>str.NFKC</code> and <a href="/std/unicode/">unicode</a>; for displaying mixed Persian and English text in the right order see <a href="/std/bidi/">bidi</a>.</p>
<div class="note"><p>Things that catch people out:</p>
<ul>
<li><code>FoldPresentation</code>, which <code>NormalizePersian</code> and <code>SearchKey</code> both use, runs the whole string through <code>str.NFKC</code>. That also rewrites characters outside Arabic script: the ligature <code>ﬁ</code> becomes <code>fi</code>, <code>²</code> becomes <code>2</code> and <code>½</code> becomes <code>1⁄2</code>. Usually that is what you want, but not for a formula.</li>
<li>A space and a zero width non-joiner are not the same to the key: <code>SearchKey</code> removes the non-joiner, so <code>هوش‌مند</code> matches <code>هوشمند</code> but not <code>هوش مند</code>.</li>
<li><code>SearchKey</code> lowers only ASCII letters, so <code>Café</code> and <code>CAFÉ</code> still get different keys.</li>
</ul></div>
<h2 id="guide-search">Searching titles whatever the spelling</h2>
<p>Build a <code>SearchKey</code> for every stored text once, build one for the query, and compare keys instead of the original strings. A query typed on an Arabic keyboard (<code>كتاب</code> with an Arabic kaf, <code>ايران</code> with an Arabic yeh) then finds the Persian titles, and <code>مدرسة</code> with a teh marbuta finds <code>مدرسهٔ</code>.</p>
{{example.arabic-guide-search}}
<p>One query fails, and it shows the most common trap: <code>برنامه نویسی</code> was typed with a space, while the title has a zero width non-joiner. The key removes the non-joiner, so the title becomes one word and the query stays two. If your users mix the two, also remove spaces from both keys with <code>str.Replace(key, " ", "")</code> before comparing. Show the original title to the user, never the key.</p>

<h2 id="guide-dedupe">Finding duplicate names</h2>
<p>The same person typed by different operators can arrive with an Arabic yeh, with a tatweel, or with a hamza on the alef. Using the search key as the key of a <code>HashMap</code> groups those spellings together, so a sign up form or a data import can warn about duplicates.</p>
{{example.arabic-guide-dedupe}}
<p>The map stores the first spelling that was seen, which is the one to keep and display. <code>EqualLoose</code> does the same comparison for just two strings, when you do not need a map.</p>

<h2 id="guide-flags">Cleaning text for display or for a field</h2>
<p>Text for people to read and text for a program to compare need different treatment. <code>NormalizePersian</code> is for display: it fixes the letters and the presentation forms that PDFs produce and removes tatweel, but keeps vowel marks, the non-joiner and the digits, so the text still reads as written. For a field such as a user name, combine exactly the flags you want with <code>+</code>.</p>
{{example.arabic-guide-clean}}

doc.FoldLetters = A flag: converts Arabic letters to their Persian counterparts: "ي", "ى", "ے" and "ۓ" to "ی", and "ك", "ڪ" and "ګ" to "ک".
doc.StripHarakat = A flag: removes the vowel marks, fatha, kasra, damma, tanwin, shadda, the hamza above and below, the superscript alef and the Quranic marks. The single letter "ۀ" becomes "ه", the same as "هٔ" written with a separate hamza.
doc.StripTatweel = A flag: removes the tatweel (ـ).
doc.FoldDigits = A flag: converts Persian and Arabic digits to English ones.
doc.FoldAlef = A flag: converts the forms of alef (أ, إ, آ) to plain "ا".
doc.FoldTehMarbuta = A flag: converts "ة" to "ه".
doc.StripZWNJ = A flag: removes the zero width non-joiner, so that «می‌خواهم» and «میخواهم» become one string.
doc.FoldPresentation = A flag: converts the presentation forms of letters, such as «ﻻ» and «ﻣ», back to the ordinary letters. It does this with <code>str.NFKC</code> on the whole string, so other compatibility characters, such as ligatures and superscript digits, are rewritten too.
doc.IsArabicScript = True when the character belongs to the Arabic script, which includes the Persian letters.
doc.IsHaraka = True when the character is one of the vowel marks.
doc.IsTatweel = True when the character is a tatweel (ـ).
doc.Normalize = Normalises the text with the flags you give. Any aspect whose flag you leave out is left untouched.
doc.NormalizePersian = The default normalisation for Persian text: it converts Arabic letters to Persian ones, removes tatweel and expands presentation forms, but keeps the vowel marks, the zero width non-joiner and the digits, so the text still reads as it was written.
doc.SearchKey = Builds a key for searching: it applies every flag and then lowers the ASCII letters, so that two spellings a reader sees as the same produce the same key. Do not display the key; it is only for comparing and indexing.
doc.EqualLoose = Compares two strings after building a search key for each, so that «مي‌خواهم» and «میخواهم» count as equal.
