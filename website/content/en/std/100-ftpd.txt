pkg.intro <<
<p>This package is an FTP server written in Salam. Give it a root directory, a user and a password, call <code>Listen</code> and then <code>Serve</code>, and any FTP client can list, upload, download, rename and delete files below that directory. Nothing outside the root is reachable. It is the other half of the <a href="/std/ftp/">ftp</a> client package, and the two work together.</p>
<p>It speaks plain FTP and FTPS. Transfers use passive mode (<code>PASV</code> and <code>EPSV</code>) on a port range you choose, so open that range in the firewall. Login is either one configured user with a password, or anonymous access when <code>allow_anonymous</code> is on; with neither, nobody can log in. With a certificate and a key the server also takes explicit FTPS (<code>AUTH TLS</code>, then <code>PROT P</code> for the data connection) and, with <code>implicit_tls</code>, implicit FTPS where the connection is encrypted from the first byte.</p>
<p>What to know before you use it:</p>
<ul>
<li><strong>There is one user.</strong> <code>user</code> and <code>password</code> describe a single account; a list of accounts, per-user directories and permissions are not part of this package.</li>
<li><strong>Clients are served one after another.</strong> <code>Serve</code> handles one connection to the end before it accepts the next, so it suits a small drop box or a build artefact server, not a busy public one.</li>
<li><strong>Plain FTP sends the password in the clear.</strong> Turn on <code>tls_enabled</code> with <code>cert_file</code> and <code>key_file</code>, and set <code>require_tls</code> so that no login is accepted before the connection is encrypted.</li>
<li><strong>Port 0 picks a free port</strong>, and <code>Port</code> tells you which. That is how the examples and the tests run without clashing with anything.</li>
</ul>

<h2 id="guide-serve">Serve a directory with a login</h2>
<p>Make a configuration with <code>NewConfig</code>, set the root, the user and the passive port range, create the server with <code>New</code>, and call <code>Listen</code>. <code>Listen</code> is false when the port is taken or you may not use it; check it before <code>Serve</code>, which runs until the server is stopped. Ports below 1024, including the usual 21, need extra rights on most systems, which is why the example uses 2121.</p>
{{example.ftpd-serve-files}}
<p>This runs until it is stopped, so it is only checked here. Point any client at it, for example the <a href="/std/ftp/">ftp</a> package with <code>Dial</code> and <code>Login</code> using the same user and password.</p>

<h2 id="guide-ftps">Encrypt the connection with FTPS</h2>
<p>A certificate and a private key in PEM files turn on TLS. A client then upgrades the connection with <code>AUTH TLS</code> and protects the file data with <code>PROT P</code>. <code>require_tls</code> goes one step further and refuses <code>USER</code> and <code>PASS</code> until that has happened, so a client that forgets to encrypt cannot leak its password. With <code>implicit_tls</code> the server expects TLS from the very first byte, the older FTPS style that uses its own port.</p>
{{example.ftpd-ftps}}
<p>If the certificate or the key cannot be read, TLS stays off even when <code>tls_enabled</code> is true, so test the setup with a real client once before you trust it.</p>

<h2 id="guide-listen">Defaults and a free port</h2>
<p>A fresh configuration listens on all interfaces on port 21, serves the current directory, and lets nobody in until you set a user or turn on anonymous access. Passive transfers use ports 40000 to 40100. The program below shows the defaults, then binds to port 0 on the loopback address to find out which port the system gave it. Nothing connects, so it runs without a network.</p>
{{example.ftpd-listen}}
<p>After <code>Listen</code> the configuration inside the server holds the real port, which is what <code>Port</code> returns. <code>Close</code> stops the server and releases the port.</p>
