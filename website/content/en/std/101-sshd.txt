pkg.intro <<
<p>This package is an SSH server written in Salam. Make a configuration, add the users who may log in, call <code>Listen</code> and then <code>Serve</code>, and an ordinary client such as OpenSSH, or the <a href="/std/ssh/">ssh</a> package, can connect, log in with a password or a public key, run a command, open an interactive shell, and move files with SFTP. It needs no OpenSSH on the machine.</p>
<p>The package holds the settings and the lifecycle of the server: what to listen on, who may log in, and what a logged-in user may do. The protocol itself, the key exchange, the encryption and the channels, is done by the same <a href="/std/ssh/">ssh</a> package that the client uses.</p>
<p>What to know before you use it:</p>
<ul>
<li><strong>Set a host key.</strong> A client trusts the server by its host key. With <code>host_key_file</code> the server reads an unencrypted OpenSSH ed25519 or RSA private key (made with <code>ssh-keygen -t ed25519 -N ""</code>) and keeps the same identity on every start. Without it <code>Listen</code> makes a new random key, so the server has a different identity each time it starts and clients that remember it will warn; that is fine for tests, but a real server needs the file.</li>
<li><strong>Public keys are listed in <code>authorized_keys_file</code></strong>, one OpenSSH public key per line. Unlike <code>sshd</code> the list is shared: a key in it can log in as any user in <code>users</code>, so give each service its own server and file. Turn off <code>allow_password</code> when keys are enough.</li>
<li><strong>Each user has a name, a password and a home</strong>. The home is a directory below <code>root</code>, and it is where that user's SFTP session starts. All users share the same <code>root</code>.</li>
<li><strong>Switches for what is allowed:</strong> <code>allow_exec</code> for single commands, <code>allow_shell</code> for an interactive shell and <code>allow_sftp</code> for file transfer. <code>allow_shell</code> alone does not stop a user from running commands, because a command is run through <code>/bin/sh -c</code> with the rights of the server process; switch <code>allow_exec</code> off too for a server that only moves files.</li>
<li><strong>Each connection is served on its own thread</strong>, up to <code>max_connections</code> (64 by default) at once; a connection over the limit is closed right away. A client must finish logging in within <code>login_grace_ms</code> (two minutes by default), or the server closes it, so a client that connects and stays silent does not hold a slot for long. <code>ServeOnce</code> still serves a single connection on the calling thread.</li>
<li><strong><code>Listen</code> is false when <code>host_key_file</code> names a file that is not there or cannot be read as a private key</strong>, and it prints why on standard error. The server never starts with some other key in its place.</li>
</ul>

<h2 id="guide-users">Users, defaults and a free port</h2>
<p><code>NewConfig</code> listens on all interfaces on port 22 and allows passwords, public keys, commands, a shell and SFTP. <code>AddUser</code> appends a user; when the home is left out it is <code>/</code>. Binding to port 0 on the loopback address lets the system pick a port and <code>Port</code> tells you which, so this program runs without a network and without clashing with a real SSH server.</p>
{{example.sshd-users}}
<p><code>Listen</code> returns false when the port cannot be bound, and <code>Close</code> frees it again. The banner is shown to a client before it logs in.</p>

<h2 id="guide-serve">Serve files with public keys only</h2>
<p>A server that exists to receive deployments should not accept passwords and should not hand out a shell. The example reads its identity from a host key file, lets in only the keys listed in <code>authorized_keys_file</code>, and does not give out a shell. Commands stay allowed there; switch <code>allow_exec</code> off as well for a server that only moves files.</p>
{{example.sshd-serve}}
<p>This runs until it is stopped, so it is only checked here. Connect to it with <code>ssh -p 2222 deploy@host</code> or with <code>ssh.Connect</code> and a key.</p>
