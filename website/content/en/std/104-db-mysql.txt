pkg.intro <<
<p>This package speaks the MySQL and MariaDB client protocol itself and needs no outside library: there is no <code>libmysqlclient</code> to install and nothing to link. It logs in with <code>mysql_native_password</code> or <code>caching_sha2_password</code>, encrypts the connection with TLS whenever the server offers it, and asks for <code>utf8mb4</code> during the handshake, so Persian text and emoji work from the first query. The functions follow the shape of the C API (<code>Open</code>, <code>Exec</code>, <code>Query</code>, <code>Next</code>, <code>Finish</code>), and <code>Conn</code> turns a connection into the shared <code>Connection</code> of <a href="/std/db/">db</a>, so code written against that interface also runs on SQLite and PostgreSQL. This page starts with a tutorial; the reference of every function comes after it.</p>

<h2 id="tutorial">Tutorial: a small bookshop in eleven steps</h2>
<p>The steps below build the database of a small bookshop: a table of books, a table of orders, and the code to sell, restock and report on them. Each step is a complete program, and the output under it is what it printed against a real MariaDB 11.8 server. Run them in order, because each step uses the rows the earlier ones left behind.</p>
<p>First start a server. With Docker that is one command, and it also creates the database and the user the programs log in with:</p>
<pre class="code" dir="ltr"><code>docker run -d --name shop-db -p 3306:3306 -e MARIADB_ROOT_PASSWORD=rootpw -e MARIADB_DATABASE=shop -e MARIADB_USER=salam -e MARIADB_PASSWORD=secret mariadb:11.8</code></pre>
<p>The programs connect to <code>127.0.0.1</code> on port 3306 as <code>salam</code> with the password <code>secret</code> and use the database <code>shop</code>. The outputs come from MariaDB. MySQL 8 speaks the same protocol and the package works with it too, but a few statements here use MariaDB names: on MySQL the status table of step 1 is <code>performance_schema.session_status</code>.</p>

<h2 id="connect">1. Connect</h2>
<p><code>Open</code> takes the host, user, password, database name and port, and always returns a <code>Database</code>. Check it with <code>Ok</code> before anything else: when the login fails the handle is empty and <code>Error</code> says why. A database name of <code>""</code> connects without choosing one, and <code>SelectDB</code> picks it later. <code>Close</code> sends the server a polite goodbye and frees the connection, so <code>defer</code> it right after the check.</p>
{{example.db-mysql-connect}}
<p>The <code>tls</code> line shows that the session is encrypted even though the program asked for nothing: MariaDB 11.8 has TLS on by default and the client uses it when it is there. <a href="#guide-tls">Encryption and TLS modes</a> below shows how to require it or turn it off. Note that <code>Errno</code> only works on a connection that exists; for a failed <code>Open</code> there is just the message.</p>

<h2 id="schema">2. Create the tables</h2>
<p><code>Exec</code> runs one statement and returns 0 when it worked and -1 when it did not. SQL that spans several lines is easiest to write as a backtick string, which keeps newlines and quotes exactly as typed. One <code>Exec</code> runs one statement; to run several, call it once for each.</p>
{{example.db-mysql-schema}}
<p>The <code>books</code> table has a nullable <code>isbn</code> and a <code>JSON</code> column for details that differ from book to book. <code>InnoDB</code> is the engine that gives transactions and foreign keys, and <code>utf8mb4</code> is the real four byte UTF-8; the older <code>utf8</code> of MySQL cannot store every character.</p>

<h2 id="insert">3. Insert rows</h2>
<p>After an <code>INSERT</code>, <code>LastInsertId</code> gives the <code>AUTO_INCREMENT</code> id the server chose and <code>AffectedRows</code> (or its other name <code>Changes</code>) how many rows went in. One <code>INSERT</code> with several value lists is much faster than many single ones, and for it <code>LastInsertId</code> is the id of the <em>first</em> new row.</p>
{{example.db-mysql-insert}}
<p>Inside SQL a single quote is written twice (<code>O''Brian</code>). That is fine for text you typed yourself; text that comes from a user goes through <code>Quote</code> or <code>Escape</code>, as step 5 shows.</p>

<h2 id="structs">4. Read rows into your own structs</h2>
<p><code>Query</code> returns a <code>Result</code> with every row already read from the server. Keep it in a <code>mut</code> variable, because <code>Next</code> moves it to the next row and returns false when none is left. <code>Text</code>, <code>Int</code>, <code>Int64</code> and <code>Float</code> read a column of the current row by its position, starting at 0, and <code>Finish</code> frees the result. Wrapping that loop in a function that returns a <code>Vector</code> of your own struct keeps the SQL in one place.</p>
{{example.db-mysql-structs}}
<p>The server sends every value as text and the column functions convert it, so a <code>DECIMAL</code> read with <code>Text</code> stays exact (<code>14.50</code>), while <code>Float</code> would turn it into a binary fraction. Keep money as text or as whole cents, and let SQL do the sums. <code>ColumnCount</code> and <code>ColumnName</code> describe the columns, which is handy for printing a header or a CSV file; <code>LIMIT 0</code> gets the columns without any rows.</p>

<h2 id="safe">5. Values from users, safely</h2>
<p>This package has no prepared statements, so a value is put into the SQL text. Never paste user text in directly. <code>Quote</code> (a method of <code>Database</code>) escapes the text and adds the quotes around it; <code>Escape</code> only escapes, for when you write the quotes yourself. Both escape quotes, backslashes, newlines and NUL bytes the way the server reads them.</p>
{{example.db-mysql-safe}}
<p>The pasted query counts every book, because the attacker's quote ended the string and <code>OR '1'='1'</code> became part of the condition. The quoted one looks for an author whose name is literally that text and finds nothing. <code>LIKE</code> needs one more step: <code>%</code> and <code>_</code> are wildcards there and <code>Escape</code> leaves them alone, so <code>like_pattern</code> puts a backslash before each. Numbers are safest as real numbers: convert the input to <code>int</code> first and write it back with <code>str.FromInt</code>.</p>

<h2 id="nulls">6. NULL values</h2>
<p><code>IsNull</code> tells a NULL apart from an empty string. The other column functions give a neutral value for NULL (<code>""</code>, 0 or 0.0), which is convenient but means you cannot tell <em>no value</em> from <em>zero</em> without asking. JSON fields come back through <code>JSON_VALUE</code> as ordinary text, and NULL when the document or the key is missing.</p>
{{example.db-mysql-null}}
<p>In SQL nothing is equal to NULL, not even NULL, so <code>isbn = NULL</code> finds no rows; write <code>IS NULL</code>. <code>COALESCE</code> replaces a NULL with a default inside the query, which saves a check in the program.</p>

<h2 id="update">7. Update and delete</h2>
<p><code>UPDATE</code> and <code>DELETE</code> are run with <code>Exec</code> as well, and <code>AffectedRows</code> says how many rows they changed. Arithmetic belongs in the SQL (<code>stock = stock + 10</code>), so two programs restocking at the same time cannot overwrite each other.</p>
{{example.db-mysql-update}}
<p>MySQL and MariaDB count rows that actually <em>changed</em>, not rows that matched the <code>WHERE</code>: setting <code>stock</code> to the value it already has reports 0. Keep that in mind before you treat 0 as <em>not found</em>; check with a <code>SELECT</code> when the difference matters.</p>

<h2 id="transactions">8. Transactions</h2>
<p>An order takes two writes: lower the stock and add the order row. Either both happen or neither. <code>Begin</code> starts a transaction, <code>Commit</code> keeps its writes and <code>Rollback</code> throws them away. The <code>UPDATE</code> only lowers the stock when there is enough of it, and <code>AffectedRows</code> tells the program whether it did.</p>
{{example.db-mysql-tx}}
<p>Ali wanted more copies than the shop had and the order for book 99 found no book, so both rolled back and left no trace. Inside a transaction InnoDB locks the rows it changes until <code>Commit</code>, so two orders for the last copy cannot both succeed. <code>Autocommit(d, false)</code> is the other way to work: every statement then waits for an explicit <code>Commit</code>. A <code>CREATE</code>, <code>ALTER</code> or <code>DROP</code> commits on its own in MySQL, so do not put schema changes in the middle of a transaction you might roll back.</p>

<h2 id="errors">9. Errors</h2>
<p>When <code>Exec</code> returns -1 or <code>QueryOk</code> is false, <code>Errno</code> gives the server's error number and <code>Error</code> its message. The number is what a program should branch on: 1062 is a duplicate key, 1452 a missing parent row, 1364 a required column with no value, 1064 a syntax error and 1146 a missing table.</p>
{{example.db-mysql-errors}}
<p>An error in one statement does not break the connection; the next statement runs normally, as the last two lines show. A lost connection is different: <code>Ping</code> returns false and the only cure is a new <code>Open</code>. The 1062 error is also the clean way to find out that a row exists: insert it and handle the duplicate, instead of checking first and racing another program.</p>

<h2 id="pool">10. The shared interface and a pool</h2>
<p><code>Conn</code> wraps a connection as a <code>dyn db.Connection</code>. Through it the helpers of <a href="/std/db/">db</a> work on MySQL: <code>db.QueryInt</code>, <code>db.Run</code>, <code>db.InTx</code> and the rest. <code>db.Pool</code> keeps several open connections and lends them out by number with <code>Acquire</code> and <code>Release</code>, so a server does not log in again for every request.</p>
{{example.db-mysql-pool}}
<p>Each connection is its own session with its own <code>CONNECTION_ID()</code>, its own transaction and its own last insert id. A connection is not safe to use from two threads at once: give each thread its own, or one leased from a pool. When <code>Acquire</code> returns <code>db.NO_LEASE</code> every connection is busy; wait and try again, or open another one. <code>DropDead</code> pings the idle connections and removes the ones the server has closed.</p>

<h2 id="report">11. A sales report</h2>
<p>The point of keeping orders in SQL is that the questions become one query each. <code>JOIN</code> and <code>GROUP BY</code> sum the sales per book, <code>GROUP_CONCAT</code> folds a list into one text value, and the JSON functions search inside the <code>details</code> column. <code>RowCount</code> says how many rows a result holds before you loop over it.</p>
{{example.db-mysql-report}}
<p>The bookshop is done: its schema, writes that cannot half happen, reads into structs and reports. The sections below cover jobs that did not fit the story.</p>

<h2 id="guide-upsert">Bulk import and upsert</h2>
<p>A delivery of books, some new and some already on the shelf, is one statement: a multi-row <code>INSERT</code> with <code>ON DUPLICATE KEY UPDATE</code>. A row whose <code>UNIQUE</code> title already exists updates that row instead of failing with 1062. Each value still goes through <code>Quote</code>, and <code>str.Join</code> puts the rows together.</p>
{{example.db-mysql-guide-upsert}}
<p>For an upsert, <code>AffectedRows</code> counts 1 for each new row and 2 for each updated one, so 4 here means two new books and one restock. The server limits the size of one statement (<code>max_allowed_packet</code>, 16 MB by default in MariaDB), so split a large import into chunks of a few thousand rows, and wrap the chunks in a transaction when the import must go in whole or not at all.</p>

<h2 id="guide-migrate">Schema migrations</h2>
<p>A real application changes its schema over time. <code>db.Migrator</code> from <a href="/std/db/">db</a> keeps numbered steps, each with an <code>up</code> and a <code>down</code> SQL text, and records the applied ones in a <code>schema_migrations</code> table. Run <code>MigrateUp</code> when the program starts and it applies only the new steps.</p>
{{example.db-mysql-guide-migrate}}
<p>The migrator runs each step in a transaction, but MySQL commits every <code>CREATE</code> and <code>ALTER</code> on its own, so a step that fails halfway can leave part of its work behind. Keep each step to one schema change, or write steps that are safe to run again, such as <code>CREATE TABLE IF NOT EXISTS</code>.</p>

<h2 id="guide-tls">Encryption and TLS modes</h2>
<p>The client encrypts whenever the server offers TLS, with no setting in the program. Two environment variables change that. <code>SALAM_MYSQL_SSL_MODE</code> is <code>DISABLED</code> (never encrypt), <code>REQUIRED</code> (refuse a server without TLS) or <code>VERIFY_IDENTITY</code> (also check the certificate and the host name); left unset, it encrypts when it can without checking the certificate. <code>SALAM_MYSQL_SSL_CA</code> names the CA file to check against.</p>
{{example.db-mysql-guide-tls}}
<p>The same program with encryption turned off:</p>
<pre class="code" dir="ltr"><code>SALAM_MYSQL_SSL_MODE=DISABLED ./guide-tls
SALAM_MYSQL_SSL_MODE: DISABLED
this connection is not encrypted</code></pre>
<p>Use <code>VERIFY_IDENTITY</code> with a CA file whenever the database is on another machine. Without a certificate check, TLS still hides the traffic from someone listening, but not from someone who can pretend to be the server.</p>
