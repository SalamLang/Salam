pkg.intro <<
<p>Server programs reach the Google APIs through a "service account". Get the account JSON file from the Google console, read it with <code>ParseServiceAccount</code>, and get a token for the scope you need with <code>AccessToken</code>; then send it in your <a href="/std/net/http/">net/http</a> requests with <code>Authorization</code>. Keep the service account file as carefully as a password.</p>
<p>The package does one job: it signs a JWT with the account's RSA key (RS256), trades it at Google's token endpoint for an OAuth access token, and keeps that token for reuse. The calls to the APIs themselves are ordinary HTTP requests that you write. For Web Push to browsers without Firebase, see <a href="/std/webpush/">webpush</a>.</p>
<div class="note"><p>Things that catch people out:</p>
<ul>
<li>Only service account keys are supported. A user's own Google login (the OAuth consent screen) and the metadata server that Google Cloud machines offer are not.</li>
<li>When <code>AccessToken</code> fails, <code>ok</code> is false and there is no message. Check in this order: the account's <code>ok</code>, the clock of the machine (a clock that is minutes off makes Google reject the signature), the network, and whether the API is enabled for the project.</li>
<li>A token is kept for 59 minutes per account and scope, shared by all threads. After you change the account's roles, call <code>Forget</code> so the next call fetches a fresh one.</li>
</ul></div>
<h2 id="guide-load">Loading the service account safely</h2>
<p>Download the JSON key from the Google Cloud console (IAM, Service accounts, Keys) and keep it outside the source tree; the usual place to point at it is the <code>GOOGLE_APPLICATION_CREDENTIALS</code> environment variable, read with <a href="/std/env/">env</a>.<code>GetOr</code>. <code>ParseServiceAccount</code> never fails loudly: it returns an account whose <code>ok</code> is false when the text is empty or <code>client_email</code> or <code>private_key</code> is missing. Check it once at start up and stop with a clear message, so a bad deployment fails at once instead of at the first push notification.</p>
{{example.google-guide-load}}
<p>The program prints the project and the account email, which are safe to log, but only whether the key was loaded. Never print or log <code>private_key</code>, and never commit the file: anyone who has it can act as your service.</p>

<h2 id="guide-fcm">Sending a push notification with Firebase</h2>
<p>Firebase Cloud Messaging takes one HTTP request per message. Get a token for <code>SCOPE_FCM</code>, put it in the <code>Authorization</code> header, and post the message to <code>/v1/projects/PROJECT/messages:send</code>. <code>AccessToken</code> keeps the token and reuses it until shortly before it expires, so calling it before every message costs nothing after the first time.</p>
{{example.google-guide-fcm}}
<p>This needs a real service account with the Firebase Cloud Messaging API enabled and a device registration token from your app, so it is only compiled here. Save the key as <code>service-account.json</code> and replace <code>DEVICE_REGISTRATION_TOKEN</code>. On success the body holds the message name, <code>{"name": "projects/.../messages/..."}</code>; an error whose body says <code>UNREGISTERED</code> means the app was removed from the device and you should delete that token. The title and body are put into the JSON as they are; if they can contain quotes, build the message with <a href="/std/encoding/json/">encoding/json</a> instead.</p>

<h2 id="guide-storage">Uploading a file to Cloud Storage</h2>
<p>A simple upload is one <code>POST</code> of the file's bytes to the upload endpoint, with the object name in the query string and the content type in a header. The token comes from <code>SCOPE_STORAGE</code>. Object names may contain <code>/</code>, so encode the name with <a href="/std/encoding/url/">encoding/url</a> before it goes into the URL.</p>
{{example.google-guide-storage}}
<p>Replace <code>my-bucket</code> with a bucket the service account can write to (the Storage Object Creator role is enough). A status of 200 means the object was stored; 403 means the account lacks permission on that bucket. <code>Forget</code> drops the kept token, which is useful after you rotate the key or change the account's roles.</p>

doc.AccessToken = Gets an OAuth access token for the given scope. Several scopes can be passed separated by spaces. doc.Forget = Throws away the kept token of the account, so the next one is fetched fresh.
doc.Authorization = The value of the <code>Authorization</code> header with the token.
