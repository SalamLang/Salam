pkg.intro <<
<p>Text is stored in memory in the order it was typed, but when right to left and left to right scripts are mixed, the order seen on screen is not that order. Browsers and editors do the rearranging with the Unicode bidirectional algorithm.</p>
<p>If you are drawing text yourself somewhere that does not do this for you, onto an image, in a terminal or on a simple display, the <code>bidi</code> package runs the same algorithm and tells you where every character goes.</p>
<p>Each function takes a paragraph direction: <code>DirAuto</code> infers it from the first strong character in the text, and the other two set it in advance. The "level" of each character is a number: even means left to right and odd means right to left.</p>
<h2 id="guide-direction">Which way does a line run?</h2>
<p>Before you can draw a line you need to know which edge it starts from. <code>ParagraphLevel</code> with <code>DirAuto</code> answers that: it looks for the first <em>strong</em> character, a letter with a direction of its own, and returns one for right to left and zero for left to right. Digits and punctuation are weak, so a line that starts with a year still takes its direction from the first word after it. A line with no strong character at all counts as left to right.</p>
{{example.bidi-guide-direction}}
<p>This is the same rule <code>dir="auto"</code> follows in HTML. Use it to align each line of a chat log or a table cell to the right edge or the left one.</p>

<h2 id="guide-runs">Splitting text into direction runs</h2>
<p><code>Levels</code> returns one number per character, not per byte, so it lines up with <code>str.Chars</code> from the <a href="/std/str/"><code>str</code></a> package. Consecutive characters with the same level form a run. In a right to left paragraph the Persian runs are at level one and the embedded English words at level two; the spaces between them belong to the paragraph's own direction.</p>
{{example.bidi-guide-runs}}
<p>Runs are what a text renderer works with: each run is shaped and drawn as one piece, often with a different font for each script.</p>

<h2 id="guide-visual">Drawing characters in display order</h2>
<p><code>VisualOrder</code> tells you, for each column on the screen from left to right, which character goes there. Walking it and appending the characters builds exactly the string that <code>Reorder</code> returns. Use the index form when you draw character by character or need to map a click on the screen back to a position in the text, and <code>Reorder</code> when you only want the finished string.</p>
{{example.bidi-guide-visual}}
<p>The reordered string is meant for a surface that does no bidi of its own, such as an image or a plain terminal. Do not send it to a browser or a modern editor: they apply the algorithm again and the text comes out backwards. That is also why the outputs on this page may look scrambled to you, because your browser is reordering them a second time.</p>

<h2 id="guide-which">Which function for which job</h2>
<table>
<tr><th>Job</th><th>Function</th></tr>
<tr><td>Align a line left or right</td><td><code>ParagraphLevel</code> with <code>DirAuto</code></td></tr>
<tr><td>Find the right to left and left to right pieces</td><td><code>Levels</code></td></tr>
<tr><td>Map screen columns to characters</td><td><code>VisualOrder</code></td></tr>
<tr><td>Get the whole line in drawing order</td><td><code>Reorder</code></td></tr>
</table>
>>

doc.DirAuto = Take the paragraph direction from the first strong character in the text: right to left when it is an Arabic-script letter, left to right when it is a Latin one.
doc.DirLTR = The paragraph is left to right, as on an English page.
doc.DirRTL = The paragraph is right to left, as on a Persian page.
doc.ParagraphLevel = Returns the base level of the paragraph: zero for left to right and one for right to left.
doc.Levels = Returns the level of every character in a vector; odd levels are displayed right to left.
doc.VisualOrder = Says which characters are seen, in which order, reading the screen from left to right. Element <code>i</code> is the index of the character that appears in position <code>i</code>.
doc.Reorder = Rearranges the text into the order it should be drawn in from left to right: the same string, in display order.

ex.DirAuto = bidi-Reorder
ex.DirLTR = bidi-Reorder
ex.DirRTL = bidi-Reorder
ex.ParagraphLevel = bidi-Reorder
ex.Levels = bidi-Reorder
ex.VisualOrder = bidi-Reorder
