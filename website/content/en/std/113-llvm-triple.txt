pkg.intro <<
<p>A target triple, such as <code>x86_64-unknown-linux-gnu</code>, names the architecture, the vendor, the operating system and the environment. Without linking against LLVM, this package gives from it what a compiler needs before it generates code, such as the pointer size and the data layout.</p>
<p>The parts are separated by dashes and the later ones may be missing: <code>x86_64-linux-musl</code> has no vendor, and <code>aarch64-apple-darwin</code> no environment. The functions here only read the text, so they work the same on every machine and for targets you cannot run, which is what a cross compiler needs.</p>

<h2 id="guide-sizes">Laying out a struct for another target</h2>
<p>The size of a pointer decides the size of every struct that holds one, and therefore every offset a code generator writes. <code>PointerBits</code> gives it for any triple. The program below lays out a list node with a name pointer, a 32 bit age and a next pointer, aligning each field to its own size as C does.</p>
{{example.llvm-triple-guide-sizes}}
<p>The node is twice as big on 64 bit targets: two eight byte pointers plus a four byte integer padded to eight. On a 32 bit target, WebAssembly included, every field is four bytes and nothing is padded. For an exact answer for every type, give the string from <code>Datalayout</code> to LLVM, as the <a href="/std/llvm/"><code>llvm</code></a> package does.</p>

<h2 id="guide-output">Choosing the file name and libc</h2>
<p>A build tool makes a few decisions straight from the triple: Windows programs end in <code>.exe</code>, a glibc program needs a compatible glibc wherever it runs, and a musl program can be linked fully static and copied to any Linux machine. <code>IsWindows</code> and <code>IsGlibc</code> answer the first two; anything else can be read from the triple with <a href="/std/str/"><code>str</code></a>.</p>
{{example.llvm-triple-guide-output}}
<p>When <code>Datalayout</code> returns an empty string the target is one this package does not know. That is not an error: leave the data layout out of the module and LLVM fills in its own default for the triple.</p>
>>
