pkg.intro <<
<p>An optimiser updates the model parameters from the gradients. A training loop always has this shape: reset the autograd tape, zero the gradients of the <code>ParamStore</code>, work out the loss, call <code>Backward</code>, and then the <code>step</code> of the optimiser.</p>
<p>The <code>...LR</code> functions work out the learning rate for a given step; put it in the <code>lr</code> field of the optimiser before <code>step</code>.</p>
<h2 id="guide-compare">Choosing an optimiser</h2>
<p>The three optimisers here minimize the same bowl, <code>x&#178; + 50y&#178;</code>, from the same start for forty steps. The bowl is fifty times steeper in one direction than the other, which is what real losses look like. Plain <code>SGD</code> must keep its learning rate below the limit the steep direction allows (here anything at or above 0.02 never settles), so it crawls along the flat one. Momentum keeps a running velocity, carrying the step along the flat direction while the bouncing in the steep one cancels out.</p>
{{example.optim-guide-compare}}
<p><code>Adam</code> scales each weight's step by its own gradient history, so it needs the least tuning and is the usual first choice for a network. On this tiny problem its steps of about <code>lr</code> make it hover near the minimum instead of settling, which is a good reminder to lower the rate as training goes on. <code>NewAdamW</code> is Adam with decoupled weight decay, the common choice for transformers.</p>

<h2 id="guide-schedule">Learning rate schedules</h2>
<p>A schedule is just a function from the step number to a learning rate; you assign the result to the optimiser's <code>lr</code> field before each <code>step</code>. <code>WarmupCosine</code> climbs linearly for the warmup steps, then follows half a cosine down to the minimum. <code>StepLR</code> multiplies the rate by <code>gamma</code> every so many steps.</p>
{{example.optim-guide-schedule}}
<p>Warmup matters most for Adam and for large models: the first gradients are noisy and the moment estimates are still empty, so full sized steps at the start can throw the weights far off.</p>

<h2 id="guide-clip">Clipping gradients</h2>
<p>One bad batch can produce a huge gradient and undo many steps of training. <code>ClipGradNorm</code> measures the length of all gradients together and, when it is above the limit, scales them down to that length while keeping their direction. It returns the length before clipping, which is worth logging: a norm that keeps growing is an early sign the learning rate is too high. Call it after <code>Backward</code> and before <code>step</code>.</p>
{{example.optim-guide-clip}}
<p>The loss is <code>500w&#178;</code> for each weight, so the raw gradient is about 1400 long, and clipping cuts it to exactly 1. The program also halves the learning rate every step with <code>StepLR</code>. <code>ClipGradValue</code> is the blunter tool: it caps every single gradient value, which changes the direction too.</p>
>>

doc.SGD = Stochastic gradient descent, with optional momentum and Nesterov.
doc.SGD.lr = The learning rate.
doc.SGD.momentum = The momentum; zero means none.
doc.SGD.weight_decay = Weight decay, meaning an L2 penalty.
doc.SGD.nesterov = Nesterov momentum.
doc.SGD.step = One update step over every parameter in the store, from the current gradients.
doc.SGD.free = Frees the internal state.
doc.ClipGradNorm = Shrinks the gradients so their total norm does not pass the limit, and returns the norm before clipping; it keeps gradients from exploding.
doc.ClipGradValue = Holds every gradient within minus the limit to the limit.
doc.Adam = The Adam optimiser; a good default for most networks.
doc.Adam.lr = The learning rate.
doc.Adam.beta1 = The coefficient of the gradient average.
doc.Adam.beta2 = The coefficient of the squared gradient average.
doc.Adam.eps = A small number that keeps a division by zero from happening.
doc.Adam.weight_decay = Weight decay.
doc.Adam.decoupled = Apply the weight decay apart from the gradient, meaning AdamW.
doc.Adam.step = One update step.
doc.Adam.free = Frees the internal state.
doc.RMSProp = The RMSProp optimiser.
doc.RMSProp.lr = The learning rate.
doc.RMSProp.alpha = The coefficient of the squared gradient average.
doc.RMSProp.eps = A small number that keeps a division by zero from happening.
doc.RMSProp.weight_decay = Weight decay.
doc.RMSProp.step = One update step.
doc.RMSProp.free = Frees the internal state.
doc.NewAdamW = Adam with decoupled weight decay, meaning AdamW.
doc.StepLR = A step learning rate: every so many steps it is multiplied by gamma.
doc.CosineLR = A cosine learning rate: it falls from the base rate to the minimum along half a cosine wave.
doc.WarmupCosine = A linear warmup over the first steps, then a cosine decay; the usual choice for training transformers.
