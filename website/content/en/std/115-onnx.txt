pkg.intro <<
<p>ONNX is a common format for machine learning models: export a model you trained in PyTorch or TensorFlow to <code>.onnx</code> and read it in Salam with <code>LoadOnnx</code>. <code>Run</code> runs the graph over the input tensors.</p>
<p>So that it works without an outside file, the example below builds a small model with <a href="../encoding-protobuf/">encoding/protobuf</a>; in practice nothing but <code>LoadOnnx</code> and <code>Run</code> is needed.</p>
<h2 id="guide-errors">Checking every step</h2>
<p>Both <code>ParseOnnx</code> (or <code>LoadOnnx</code>) and <code>Run</code> report success through their last argument, a <code>bool</code> they set, and leave the reason in the model's <code>error</code> field. Check it after each call: a file that is not ONNX, a graph with an operator this package does not implement, or the wrong number of inputs all come back this way instead of stopping the program. The model in this example is built in memory, a single <code>Relu</code>, so the program runs without any file.</p>
{{example.onnx-guide-errors}}
<p><code>feed_names</code> lists the inputs you must supply, in order. It leaves out the graph inputs that are really weights stored in the file, which older exporters list as inputs too.</p>

<h2 id="guide-inspect">Looking inside a model file</h2>
<p>Before wiring a model into a program, look at what it expects. This tool prints the inputs and outputs, how many nodes of each operator the graph has, and how many numbers the weights hold. Run it on any <code>.onnx</code> file:</p>
<pre class="code" dir="ltr"><code>salam build onnx-guide-inspect.salam
./onnx-guide-inspect model.onnx</code></pre>
{{example.onnx-guide-inspect}}
<p>Run on the small model that the reference example at the bottom of this page writes, it prints:</p>
<pre class="code" dir="ltr"><code>IR version 8
feeds ["x"] outputs ["y"]
  Mul 1
  LeakyRelu 1
1 weight tensors, 3 numbers</code></pre>
<p>The supported operators cover common feed forward and convolutional networks: <code>MatMul</code>, <code>Gemm</code>, <code>Conv</code>, the pools, the normalizations, the usual activations, <code>Softmax</code>, the reductions and the shape operators such as <code>Reshape</code>, <code>Transpose</code>, <code>Concat</code>, <code>Slice</code> and <code>Gather</code>. All tensors are 32 bit floats.</p>

<h2 id="guide-classify">Running a trained classifier</h2>
<p>Train the model where it is convenient, export it once, and run it from Salam with no Python at run time. With PyTorch, a classifier of the iris flowers with four inputs and three outputs is exported like this:</p>
<pre class="code" dir="ltr"><code>torch.onnx.export(model, torch.zeros(1, 4), "iris.onnx",
    input_names=["x"], output_names=["logits"],
    dynamic_axes={"x": {0: "batch"}})</code></pre>
<p>The program feeds two flowers at once as a <code>2x4</code> tensor, turns the logits into probabilities with <code>tensor.Softmax</code> and takes the most likely class of each row.</p>
{{example.onnx-guide-classify}}
<p>The <code>dynamic_axes</code> setting is what lets the batch size change; without it the exported graph only accepts exactly one row. The model must be given the same preprocessing it was trained with, here the raw measurements in centimetres.</p>
>>

doc.Node.attrs = The attributes.

doc.ParseOnnx = Reads the model from bytes in memory.
doc.LoadOnnx = Reads the model from a <code>.onnx</code> file.
doc.Run = Runs the model over the inputs and returns the outputs in the order of the graph outputs; the usual operators are supported, among them Gemm, MatMul, Add, Mul, Relu, LeakyRelu, Softmax and Transpose.
