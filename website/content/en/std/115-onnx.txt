pkg.intro <<
<p>ONNX is the common exchange format for trained machine learning models. Train in PyTorch, TensorFlow or scikit-learn, export to <code>.onnx</code> once, and this package runs the model inside a Salam program with no Python and no ONNX Runtime library. <code>LoadOnnx</code> reads the file, <code>Run</code> computes the outputs from your input tensors, and the results are ordinary <a href="/std/tensor/">tensor</a> values.</p>
<p>Use it for inference: scoring, classifying, embedding. To train or fine tune a network in Salam itself, build it with <a href="/std/nn/">nn</a> and <a href="/std/optim/">optim</a>. For large language models in the GGUF format, see <a href="/std/gguf/">gguf</a> and <a href="/std/llm/">llm</a>.</p>
<h3>Core ideas</h3>
<ul>
<li>A <code>Model</code> is the graph from the file: <code>nodes</code> in the order they run, the weights (<code>inits</code>), and the names of the graph's inputs and outputs.</li>
<li><code>feed_names</code> lists the inputs you supply, in order; <code>Run</code> takes one tensor for each and returns one tensor per graph output.</li>
<li>Nothing stops the program. Every failure sets the <code>ok</code> argument to false and puts the reason in <code>model.error</code>.</li>
</ul>
<h3>Limits to know before you export</h3>
<ul>
<li>Every tensor is <code>f32</code> inside. Integer and double weights are converted when the file is read, so an <code>int64</code> above 16777216 loses precision.</li>
<li>About 65 operators are implemented, enough for feed forward, convolutional and normalization layers (the list is below). Anything else, such as <code>LSTM</code>, <code>Resize</code> or the quantized operators, fails with <code>unsupported op: NAME</code>.</li>
<li><code>Conv</code> has no groups (so no depthwise convolutions), no dilations and only symmetric padding. <code>MaxPool</code> and <code>AveragePool</code> have no padding.</li>
<li>Weights must be inside the <code>.onnx</code> file. Models exported with external data (a separate <code>.data</code> file, used above 2 GB) do not load.</li>
<li>Input shapes are not checked against the file and the opset version is ignored. A wrong shape shows up as an error from the first operator that cannot use it.</li>
</ul>
<h2 id="guide-errors">Checking every step</h2>
<p>Both <code>ParseOnnx</code> (or <code>LoadOnnx</code>) and <code>Run</code> report success through their last argument, a <code>bool</code> they set, and leave the reason in the model's <code>error</code> field. Check it after each call: a file that is not ONNX, a graph with an operator this package does not implement, or the wrong number of inputs all come back this way instead of stopping the program. The model in this example is built in memory with <a href="/std/encoding/protobuf/">encoding/protobuf</a>, a single <code>Relu</code>, so the program runs without any file.</p>
{{example.onnx-guide-errors}}
<p><code>feed_names</code> lists the inputs you must supply, in order. It leaves out the graph inputs that are really weights stored in the file, which older exporters list as inputs too.</p>

<h2 id="guide-inspect">Looking inside a model file</h2>
<p>Before wiring a model into a program, look at what it expects. This tool prints the inputs and outputs, how many nodes of each operator the graph has, and how many numbers the weights hold. Run it on any <code>.onnx</code> file:</p>
<pre class="code" dir="ltr"><code>salam build onnx-guide-inspect.salam
./onnx-guide-inspect model.onnx</code></pre>
{{example.onnx-guide-inspect}}
<p>Run on the small model that the reference example at the bottom of this page writes, it prints:</p>
<pre class="code" dir="ltr"><code>IR version 8
feeds ["x"] outputs ["y"]
  Mul 1
  LeakyRelu 1
1 weight tensors, 3 numbers</code></pre>

<h2 id="guide-classify">Running a trained classifier</h2>
<p>Train the model where it is convenient, export it once, and run it from Salam with no Python at run time. With PyTorch, a classifier of the iris flowers with four inputs and three outputs is exported like this:</p>
<pre class="code" dir="ltr"><code>torch.onnx.export(model, torch.zeros(1, 4), "iris.onnx",
    input_names=["x"], output_names=["logits"],
    dynamic_axes={"x": {0: "batch"}})</code></pre>
<p>The program feeds two flowers at once as a <code>2x4</code> tensor, turns the logits into probabilities with <code>tensor.Softmax</code> and takes the most likely class of each row.</p>
{{example.onnx-guide-classify}}
<p>The <code>dynamic_axes</code> setting is what lets the batch size change: without it PyTorch may write the batch size of 1 into <code>Reshape</code> and <code>Expand</code> nodes as a constant, and a batch of two then fails inside the graph. The model must be given the same preprocessing it was trained with, here the raw measurements in centimetres.</p>
