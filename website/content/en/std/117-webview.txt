pkg.intro <<
<p>This package opens a native desktop window with the browser engine the operating system already has in it: WebView2 on Windows, WKWebView on macOS and WebKitGTK on Linux. You write the interface in HTML, CSS and JavaScript, show it with <code>SetHTML</code> or <code>Navigate</code>, and <code>Run</code> keeps the window open until the user closes it. The program stays one native executable with no browser to bundle.</p>
<p>Use it for a small desktop tool, a viewer for data your program computed, or a native window around a web interface your program serves. For pages that run in the user's own browser, see <a href="/std/dom/">dom</a>; to generate the HTML, see <a href="/std/template/">template</a>.</p>
<h3>How data moves, and what does not work</h3>
<ul>
<li><strong>Put the data in the page.</strong> The reliable way to give the page your data is to write it into the HTML you pass to <code>SetHTML</code>, as JSON inside a <code>&lt;script&gt;</code>. There is no way for the page to call back into Salam.</li>
<li><code>Init</code> installs a script for every page loaded later, before the page's own scripts run. <code>Eval</code> runs once, on whatever page is loaded at that moment.</li>
<li>Pages load in the background, so code sent with <code>Eval</code> right after <code>SetHTML</code> or <code>Navigate</code> can run before the new page exists. Use <code>Init</code>, or wait for <code>OnLoad</code>.</li>
<li>The page can talk back with <code>OnMessage</code>. For a whole application, with commands, events, packaged files and installers, use <a href="/std/desktop/"><code>desktop</code></a>, which is built on this package.</li>
<li><code>Create</code> reports failure by returning a window that is already closed; check <code>IsClosed()</code> right after it, for example on a Linux server with no display.</li>
</ul>
<p>A window needs a desktop session, so the site only compiles these programs; run them on your own machine with <code>salam run</code>. On Linux install the WebKitGTK development package first (<code>libwebkit2gtk-4.1-dev</code> on Debian and Ubuntu); Windows 10 and 11 already ship WebView2, and macOS ships WKWebView.</p>

<h2 id="guide-report">Showing data your program computed</h2>
<p>The simplest desktop program builds an HTML string and shows it. Everything the page needs, the style sheet included, can travel in that one string, so there are no files to ship next to the executable. <code>HINT_FIXED</code> keeps the window at the size you chose, which suits a small dialog like this order summary.</p>
{{example.webview-guide-report}}
<p>The item names go into the HTML as they are. When the text comes from a user or a file, pass it through <code>EscapeHTML</code> from <a href="/std/template/"><code>template</code></a> first, or a name with a <code>&lt;</code> in it breaks the page.</p>

<h2 id="guide-data">Handing structured data to the page</h2>
<p>For anything bigger than a table, let JavaScript draw the page and give it the data as JSON. <code>Marshal</code> from <a href="/std/encoding/json/"><code>encoding/json</code></a> turns a vector of structs into a JSON array whose keys are the field names, and that text goes straight into a <code>&lt;script&gt;</code> in the page. The script runs as the page loads, so the data is there before anything is drawn.</p>
{{example.webview-guide-data}}
<p>JSON is valid JavaScript, so no parsing step is needed. One caution: if a value could contain the text <code>&lt;/script&gt;</code>, it would end the script early; replace <code>&lt;/</code> with <code>&lt;\/</code> in the JSON first when the data comes from users.</p>

<h2 id="guide-launch">Opening a site or a local server</h2>
<p><code>Navigate</code> loads an address instead of a string, so the window can show a remote site or a web interface your own program serves on <code>127.0.0.1</code>. This one takes the address from the command line, so <code>salam run webview-guide-launch.salam http://127.0.0.1:8000</code> wraps a local development server in a native window.</p>
{{example.webview-guide-launch}}
<p><code>Run</code> blocks until the user closes the window; the lines after it are where you save state and clean up. Call <code>Destroy</code> once at the end in every case. <code>Terminate</code> makes <code>Run</code> return at its next turn; on Linux and Windows that turn only comes with the next window event, such as a mouse move. On macOS it quits the whole application instead, so the lines after <code>Run</code> do not run there.</p>
>>

doc.Request.url = The whole address.
doc.Request.scheme = The scheme, such as <code>app</code>.
doc.Request.method = The HTTP method, usually <code>GET</code>.
doc.Request.path = The path, starting with a slash.
doc.Request.query = The text after the question mark.
doc.Response = What a custom scheme answers with. The data is copied, so the handler keeps ownership.
doc.Response.status = The HTTP status, 200 by default.
doc.Response.mime = The content type.
doc.Response.data = A pointer to the body.
doc.Response.size = The body size in bytes.
doc.Response.headers = Extra headers, as name and value pairs.
doc.Response.Header = Adds one header.
doc.WebView = A window with a browser inside it.
doc.WebView.id = The number of this window inside the package.
doc.WebView.Destroy = Closes the window and frees the resources.
doc.WebView.Run = Runs the event loop until this window is closed or <code>Terminate</code> is called.
doc.WebView.Terminate = Asks <code>Run</code> to return. The window stays open until <code>Destroy</code>.
doc.WebView.SetTitle = The window title.
doc.WebView.SetSize = Resizes the window, with one of the <code>HINT</code> constants: <code>HINT_FIXED</code> stops the user from resizing it.
doc.WebView.SetMinSize = The smallest size the user can drag the window to.
doc.WebView.SetIcon = The window icon, from a file: any image GTK reads on Linux, <code>.ico</code> on Windows, any image on macOS.
doc.WebView.SetHTML = Shows the HTML content.
doc.WebView.Navigate = Opens the address.
doc.WebView.Eval = Runs JavaScript in the page loaded right now, without waiting for a result. Call it on the UI thread.
doc.WebView.EvalLater = The same as <code>Eval</code>, but safe from any thread: the code runs on the UI thread soon after.
doc.WebView.Init = Installs JavaScript that runs at the start of every page loaded later, before the page's own scripts. Pass <code>true</code> to run it in frames too.
doc.WebView.URL = The address of the page now. The caller frees the string.
doc.WebView.Show = Shows the window and brings it forward.
doc.WebView.Hide = Hides the window without closing it.
doc.WebView.Focus = Brings the window forward.
doc.WebView.Minimize = Minimizes the window.
doc.WebView.Maximize = Maximizes the window.
doc.WebView.Center = Moves the window to the middle of the screen.
doc.WebView.IsActive = The window has the keyboard focus.
doc.WebView.Native = The window handle in the operating system: <code>GtkWindow*</code>, <code>HWND</code> or <code>NSWindow*</code>.
doc.WebView.Content = Where native widgets go: a <code>GtkBox</code> on Linux, the window elsewhere.
doc.WebView.OpenDevTools = Opens the developer tools.
doc.WebView.SetContextMenu = Turns the page's right-click menu on or off.
doc.WebView.OnMessage = Called with the text a page posts with the function from <code>PostScript</code>.
doc.WebView.OnNavigate = Called before a page loads. Return false to cancel it. On Linux frames come here too; see <code>NavigationIsMainFrame</code>.
doc.WebView.OnNewWindow = Called when a page asks for a new window. No window opens; the address is handed to you.
doc.WebView.OnClose = Called when the user closes the window. Return false to keep it open.
doc.WebView.OnLoad = Called when a page starts loading (false) and when it finishes (true).
doc.WebView.OnCrash = Called when the page process dies, for example out of memory.
doc.WebView.OnResize = Called with the new size.
doc.WebView.IsClosed = The window has been closed.
doc.Dispatch = Runs a function on the UI thread, from any thread.
doc.RunAll = Runs the event loop until every window is closed or <code>Quit</code> is called.
doc.Quit = Makes the running event loop return.
doc.SetApp = The application id and name. Call it before the first window.
doc.SetDataDir = The folder for cookies and local storage. Call it before the first window.
doc.RegisterScheme = Serves a custom address scheme from your own function, so pages can load from memory.
doc.SchemeURL = The address of a path in a scheme, for this operating system: <code>app://localhost/x</code>, or <code>https://app.localhost/x</code> on Windows.
doc.SchemeOrigin = The origin of a scheme, for this operating system.
doc.OnCommand = Called with the number of a native menu item that was chosen.
doc.OnTrayMessage = Windows only: called with tray icon events.
doc.OnCopyData = Windows only: called with <code>WM_COPYDATA</code> data sent to the message window.
doc.MenuHost = The object native menus report to: the message window on Windows, the application delegate on macOS.
doc.NameMessageWindow = Windows only: the title of the hidden message window, so another process can find it.
doc.NavigationIsMainFrame = Inside <code>OnNavigate</code>: whether the page itself is navigating. WebKitGTK cannot tell a frame from the page, so on Linux this reports a user gesture instead.
doc.PostScript = JavaScript for a function that posts a string to <code>OnMessage</code>. The caller frees it.
doc.Create = Makes a new window. The first flag turns on developer tools, the second shows the window at once. On failure the window it returns is already closed.
doc.LastError = Why the last window could not open, or empty text.
doc.Trace = Adds a line to the file named by the <code>SALAM_WEBVIEW_TRACE</code> environment variable, and does nothing when it is unset. The backends use it to record each startup step, navigation and message, so a window that stays blank can be diagnosed, including in an application with no console.
