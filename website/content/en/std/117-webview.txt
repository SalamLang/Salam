pkg.intro <<
<p>This package opens a native desktop window with the browser engine the operating system already has in it: WebView2 on Windows, WKWebView on macOS and WebKitGTK on Linux. You write the interface in HTML, CSS and JavaScript, show it with <code>SetHTML</code> or <code>Navigate</code>, and <code>Run</code> keeps the window open until the user closes it. The program stays one native executable with no browser to bundle.</p>
<p>Use it for a small desktop tool, a viewer for data your program computed, or a native window around a web interface your program serves. For pages that run in the user's own browser, see <a href="/std/dom/">dom</a>; to generate the HTML, see <a href="/std/template/">template</a>.</p>
<h3>How data moves, and what does not work</h3>
<ul>
<li><strong>Put the data in the page.</strong> The reliable way to give the page your data is to write it into the HTML you pass to <code>SetHTML</code>, as JSON inside a <code>&lt;script&gt;</code>. There is no way for the page to call back into Salam.</li>
<li><code>Init</code> does not install a script for later pages. On every platform it runs the code once, at once, exactly like <code>Eval</code>, so a variable it sets is gone when <code>SetHTML</code> loads the new page.</li>
<li><code>Eval</code> runs on whatever page is loaded at that moment. Pages load in the background, so code sent right after <code>SetHTML</code> or <code>Navigate</code> usually reaches the old page and is lost.</li>
<li>The <code>debug</code> flag of <code>Create</code> only opens developer tools in the Chromium (CEF) build; the system webviews ignore it.</li>
<li><code>Create</code> reports failure by returning a window that is already closed; check <code>IsClosed()</code> right after it, for example on a Linux server with no display.</li>
</ul>
<p>A window needs a desktop session, so the site only compiles these programs; run them on your own machine with <code>salam run</code>. On Linux install the WebKitGTK development package first (<code>libwebkit2gtk-4.1-dev</code> on Debian and Ubuntu); Windows 10 and 11 already ship WebView2, and macOS ships WKWebView.</p>

<h2 id="guide-report">Showing data your program computed</h2>
<p>The simplest desktop program builds an HTML string and shows it. Everything the page needs, the style sheet included, can travel in that one string, so there are no files to ship next to the executable. <code>HINT_FIXED</code> keeps the window at the size you chose, which suits a small dialog like this order summary.</p>
{{example.webview-guide-report}}
<p>The item names go into the HTML as they are. When the text comes from a user or a file, pass it through <code>EscapeHTML</code> from <a href="/std/template/"><code>template</code></a> first, or a name with a <code>&lt;</code> in it breaks the page.</p>

<h2 id="guide-data">Handing structured data to the page</h2>
<p>For anything bigger than a table, let JavaScript draw the page and give it the data as JSON. <code>Marshal</code> from <a href="/std/encoding-json/"><code>encoding/json</code></a> turns a vector of structs into a JSON array whose keys are the field names, and that text goes straight into a <code>&lt;script&gt;</code> in the page. The script runs as the page loads, so the data is there before anything is drawn.</p>
{{example.webview-guide-data}}
<p>JSON is valid JavaScript, so no parsing step is needed. One caution: if a value could contain the text <code>&lt;/script&gt;</code>, it would end the script early; replace <code>&lt;/</code> with <code>&lt;\/</code> in the JSON first when the data comes from users.</p>

<h2 id="guide-launch">Opening a site or a local server</h2>
<p><code>Navigate</code> loads an address instead of a string, so the window can show a remote site or a web interface your own program serves on <code>127.0.0.1</code>. This one takes the address from the command line, so <code>salam run webview-guide-launch.salam http://127.0.0.1:8000</code> wraps a local development server in a native window.</p>
{{example.webview-guide-launch}}
<p><code>Run</code> blocks until the user closes the window; the lines after it are where you save state and clean up. Call <code>Destroy</code> once at the end in every case. <code>Terminate</code> makes <code>Run</code> return at its next turn; on Linux and Windows that turn only comes with the next window event, such as a mouse move. On macOS it quits the whole application instead, so the lines after <code>Run</code> do not run there.</p>
>>

doc.HINT_NONE = The user can resize the window.
doc.HINT_FIXED = The window size is fixed.
doc.WebView = A window with a browser inside it.
doc.WebView.handle = The handle of the browser on Linux and CEF.
doc.WebView.window = The handle of the window in the operating system.
doc.WebView.webview = The handle of the browser on macOS.
doc.WebView.closed = The window has been closed.
doc.WebView.Destroy = Closes the window and frees the resources.
doc.WebView.Run = Runs the event loop until the window is closed or <code>Terminate</code> is called.
doc.WebView.Terminate = Asks <code>Run</code> to return; it does so after the next window event. On macOS it quits the application.
doc.WebView.SetTitle = The window title.
doc.WebView.SetSize = Resizes the window, with one of the <code>HINT</code> constants: <code>HINT_FIXED</code> stops the user from resizing it.
doc.WebView.SetHTML = Shows the HTML content.
doc.WebView.Navigate = Opens the address.
doc.WebView.Eval = Runs JavaScript in the page loaded right now, without waiting for a result. Code sent while a new page is still loading is lost.
doc.WebView.Init = Runs JavaScript once, at once; the same as <code>Eval</code> on every platform. It is not kept for pages loaded later.
doc.WebView.IsClosed = The window has been closed.
doc.Create = Makes a new window and shows it. The debug flag opens developer tools only in the CEF build. On failure the window it returns is already closed.
