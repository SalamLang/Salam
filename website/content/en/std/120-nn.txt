pkg.intro <<
<p>This package has the ready made layers for building a neural network in Salam: linear, convolution, pooling, normalization, embedding, LSTM and GRU, attention and transformer blocks, plus weight initializers and checkpoints. The weights of every layer live in one <code>ParamStore</code>. Make each layer with a <code>New...</code> function and a unique name, and call its <code>forward</code> on the <a href="/std/ai/autograd/">autograd</a> tape at every step. <code>Sequential</code> runs several layers one after the other. Training itself is done by <a href="/std/ai/optim/">optim</a>.</p>
<p>For a model someone else trained, load it with <a href="/std/ai/onnx/">onnx</a> instead. For classical models such as decision trees, k-means or logistic regression on tabular data, <a href="/std/ai/ml/">ml</a> is shorter and needs no training loop.</p>
<h3>Things that trip people up</h3>
<ul>
<li>A layer value holds only the numbers of its weights in the store, not the weights. Pass the same store to <code>forward</code> that you passed to <code>New...</code>.</li>
<li>Names must be unique. <code>add</code> does not check, and a checkpoint loads each tensor into the first parameter with its name, so a repeated name breaks loading.</li>
<li><code>Sequential</code> takes only layers whose <code>forward</code> receives the store: <code>Linear</code>, <code>Conv2D</code>, the norms and the activation layers. Call <code>Dropout</code>, <code>MaxPool2D</code>, <code>AvgPool2D</code> and <code>Flatten</code> yourself between them.</li>
<li>A checkpoint holds the <code>ParamStore</code> only. The running mean and variance of <code>BatchNorm</code> and the optimiser's state are not saved.</li>
<li>Set <code>tape.training = false</code> before you evaluate, so dropout stops dropping and batch normalization uses its running averages.</li>
</ul>
<h2 id="guide-xor">A first network: XOR</h2>
<p>XOR is the smallest problem a straight line cannot solve, so it is the classic first test of a network with a hidden layer. <code>Sequential</code> chains a <code>Linear</code> layer of eight units, a <code>TanhLayer</code> and a second <code>Linear</code> layer with one output. The loss is <code>BCEWithLogits</code>, which takes the raw output and applies the sigmoid itself, more stably than doing it in two steps. After training, <code>tensor.Sigmoid</code> turns the outputs into probabilities and rounding gives the answer.</p>
{{example.nn-guide-xor}}
<p>The training loop has the same five lines in every program: <code>reset</code> the tape, <code>zero_grad</code> the store, run <code>forward</code> and the loss, <code>Backward</code>, and the optimiser's <code>step</code>. The seed passed to <code>NewRng</code> fixes the starting weights, so a run can be repeated exactly.</p>

<h2 id="guide-classify">Classifying into several classes</h2>
<p>For more than two classes the last layer has one output per class and the loss is <code>CrossEntropyLogits</code>, which takes the class numbers as a plain <code>Vector&lt;int&gt;</code>. The prediction is the class with the largest output, found with <code>tensor.ArgMaxAxis</code>. Here sixty points around three centres are separated perfectly; on real data, measure accuracy on examples the model did not train on.</p>
{{example.nn-guide-classify}}
<p>Write <code>((group % 2) as f64) * 2.0</code> with the parentheses. Without them <code>as f64 *</code> reads as the pointer type <code>f64*</code> and the line does not compile.</p>

<h2 id="guide-checkpoint">Saving and loading weights</h2>
<p>A checkpoint stores every tensor of a <code>ParamStore</code> under its layer name. To load it, build the same layers with the same names and shapes, then call <code>LoadCheckpoint</code> (a file) or <code>LoadCheckpointBuf</code> (memory); the starting weights are overwritten. The second model below starts from different random weights, gives a different answer, and after loading answers exactly like the first.</p>
{{example.nn-guide-checkpoint}}
<p><code>LoadCheckpoint</code> and <code>LoadCheckpointBuf</code> are <code>throws</code>. The whole file is checked before any weight is written: the CRC (<code>nn.crc</code>), the parameter count (<code>nn.param_count</code>, as for the third store above, which has the layers twice), every name (<code>nn.unknown_param</code>) and every shape (<code>nn.shape</code>). So after an error the store is exactly as it was. A path ending in <code>.gz</code> is compressed with gzip on save and decompressed on load. Loading matches by name, so renaming a layer breaks old checkpoints. Keep the names stable, and keep the code that builds the model in one function used both for training and for loading, as <code>build</code> is here.</p>

<h2 id="guide-which">Which layer for which job</h2>
<table>
<tr><th>Data</th><th>Layers</th></tr>
<tr><td>Rows of numbers</td><td><code>NewLinear</code> with <code>ReluLayer</code>, <code>GeluLayer</code> or <code>TanhLayer</code> between</td></tr>
<tr><td>Images</td><td><code>NewConv2D</code>, <code>MaxPool2D</code>, <code>NewBatchNorm</code>, then <code>Flatten</code> and <code>NewLinear</code></td></tr>

</table>
