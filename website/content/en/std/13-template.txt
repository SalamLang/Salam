pkg.intro <<
<p>A template is text with holes in it; every <code>&#123;&#123;name&#125;&#125;</code> is filled with the value of that name from a "context". A context is a map from name to value.</p>
<p>If the output is HTML and the values came from a user, always use <code>RenderHTML</code>. It escapes the dangerous characters such as <code>&lt;</code>, so that nobody can inject code into your page. This website is built with this package.</p>
<p>Use it for emails, notifications, generated configuration files and small HTML fragments. For whole web pages with components and styles, the layout language of Salam is the better tool; for formatting numbers and dates into a sentence, <a href="/std/fmt/">fmt</a> is shorter.</p>
<h3>What the language has, and what it does not</h3>
<ul>
<li>Only three tags: <code>&#123;&#123;name&#125;&#125;</code>, <code>&#123;&#123;#if name&#125;&#125;</code> with an optional <code>&#123;&#123;else&#125;&#125;</code> and a closing <code>&#123;&#123;/if&#125;&#125;</code>, and the comment <code>&#123;&#123;! ... &#125;&#125;</code>. There are no loops, filters or dotted paths: build repeated parts in Salam and put the result in the context, as the HTML example does.</li>
<li>The context holds only strings. Turn numbers and bools into text before you <code>put</code> them.</li>
<li>Values are inserted as they are and never scanned again, so a value that contains <code>&#123;&#123;</code> cannot inject a tag.</li>
<li><code>RenderHTML</code> escapes <code>&amp; &lt; &gt; " '</code>. That makes a value safe as page text and inside a quoted attribute, but not inside a <code>&lt;script&gt;</code> block or as a link address: a value such as <code>javascript:...</code> passes through unchanged.</li>
</ul>

<h2 id="guide-email">Fill a plain text message</h2>
<p>The common job is a message with a few names in it: an email, a notification or a receipt. Put every value in the context with <code>put</code>, then call <code>Render</code>. The same context can be filled again and rendered a second time, so one template serves every customer. A section wrapped in <code>&#123;&#123;#if key&#125;&#125;</code> ... <code>&#123;&#123;/if&#125;&#125;</code> appears only when the key has a value, and <code>&#123;&#123;! ... &#125;&#125;</code> is a comment that never reaches the output.</p>
{{example.template-guide-email}}

<h2 id="guide-conditions">Conditions and else</h2>
<p><code>&#123;&#123;#if key&#125;&#125;</code> takes an optional <code>&#123;&#123;else&#125;&#125;</code> branch, and the blocks can be nested. A key counts as false when it is missing, empty, <code>"false"</code> or <code>"0"</code>; any other text, such as <code>"yes"</code> or <code>"3"</code>, counts as true. The context only holds strings, so a number or a bool has to be turned into text first, for example with <code>str.FromInt</code>.</p>
{{example.template-guide-conditions}}

<h2 id="guide-html">Safe HTML from user data</h2>
<p>A page is usually built from small pieces. Render each row with <code>RenderHTML</code>, so that whatever a visitor typed is escaped, and then place the finished rows into the outer layout with <code>Render</code>. If you used <code>RenderHTML</code> for the outer step too, the rows would be escaped a second time and the browser would show the tags as text.</p>
{{example.template-guide-page}}
<p>The rule to remember: escape a value exactly once, at the moment it is put into HTML. Text that you already escaped, or HTML that your own program built, goes in with <code>Render</code>.</p>

<h2 id="guide-config">Configuration files and edge cases</h2>
<p>Templates are not only for HTML. A configuration file, a SQL migration header or a shell script can be generated the same way, and <code>Var</code> builds the placeholder when the template itself is put together in code. A key that is missing from the context is replaced with nothing, not with an error, and a <code>&#123;&#123;</code> without its closing braces is copied as it is.</p>
{{example.template-guide-config}}

<p>Because a missing key renders as empty text, a typo in a key name fails silently. When a value is required, check it with <code>has</code> on the context before rendering. For full HTML pages with components and styles, look at the layout language instead; this package is for filling text.</p>

doc.NewContext = Creates an empty context: a map from name to value. Add values with <code>put</code> and free it when you are done.
doc.EscapeHTML = Escapes the special HTML characters so the text is shown exactly as written.
doc.Render = Fills every <code>{{name}}</code> in the template from the context, with no escaping at all. For plain text, email or a configuration file.
doc.RenderHTML = Like <code>Render</code>, but escapes every value for HTML before placing it.
doc.Var = Builds the placeholder for a name, that is, <code>{{name}}</code>. Useful when you are building the template in code.

ex.NewContext = template-Render
ex.EscapeHTML = template-Render
ex.RenderHTML = template-Render
ex.Var = template-Render
