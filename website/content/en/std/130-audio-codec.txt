pkg.intro <<
<p>This package is the one call that does not care what format a file is in. <code>Open</code> reads the first bytes, works out the format and hands back a <a href="/std/audio/">clip</a>; <code>Save</code> looks at the extension and writes the right thing. <code>Probe</code> and <code>ProbeFile</code> do the same for a header alone.</p>
<p>It sits in its own package for a plain reason: <a href="/std/audio/">audio</a> cannot import the format packages, because they import it. So the sniffing lives in <code>audio</code>, where it needs nothing, and the dispatch lives here, where it can reach every codec.</p>
<h3>Things to know</h3>
<ul>
<li>Knowing a format and being able to read it are different things. <code>audio.DetectFormat</code> names ten formats; <code>CanDecode</code> tells you which of them this build actually carries, and <code>Formats</code> lists them.</li>
<li>Today that list is WAV, AIFF and au. The rest of the family is being written, and nothing here changes when they land.</li>
<li><code>Save</code> returns false for an extension it cannot write, rather than writing the wrong format.</li>
<li>Free the clip with <code>audio.Free</code> and any buffer with <code>compress.BufFree</code>.</li>
</ul>

<h2 id="guide-save">Saving and opening by file name</h2>
<p><code>codec.Save</code> picks the format from the file extension, so the same call writes a <code>.wav</code>, <code>.aiff</code>, <code>.au</code> or <code>.flac</code> file. It returns <code>false</code> for a format it cannot write, such as MP3. <code>CanEncode</code> and <code>CanDecode</code> tell you in advance.</p>
{{example.audio-codec-guide-save}}
<p><code>ProbeFile</code> reads the header only and reports the format name, length, depth and whether the format is lossless. <code>Open</code> then decodes the file, whatever format it turns out to be, since it looks at the contents and not at the name.</p>

<h2 id="guide-memory">Encoding and decoding in memory</h2>
<p>Without a file, <code>Encode</code> returns a byte buffer in the format you name, and <code>Decode</code> turns bytes back into a clip. The 32 frame mono clip becomes 108 bytes: a 44 byte header and 64 bytes of 16 bit samples. <code>audio.DetectFormat</code> names the format from the bytes alone.</p>
{{example.audio-codec-guide-memory}}
<p>Bytes that are not audio do not crash anything: <code>Decode</code> sets its flag to <code>false</code> and returns an empty clip. Always check the flag before using the result, and free the buffers you were given.</p>
>>
