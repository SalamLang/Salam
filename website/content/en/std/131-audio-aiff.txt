pkg.intro <<
<p>AIFF is the big-endian cousin of <a href="/std/audio/wav/">WAVE</a>: the same idea of a chunked container, written the other way round because it came from the Motorola side of the world. AIFF-C adds a compression tag, and this package reads the ones that matter: plain PCM, the little-endian <code>sowt</code> variant Apple tools write, IEEE floating point, and A-law and mu-law.</p>
<p>The one genuinely odd part is the sample rate, which AIFF stores as an 80 bit extended float. This package reads and writes it, so 44100 comes back as 44100 and not 44099.</p>
<h3>Things to know</h3>
<ul>
<li>8, 16 and 24 bit PCM makes the round trip through a <a href="/std/audio/">clip</a> exactly. Unlike WAVE, 8 bit AIFF is <strong>signed</strong>.</li>
<li><code>ReadCommon</code> gives you the COMM and SSND chunks in one struct, because you always need both: one says the shape, the other says where the sound is.</li>
<li>A file whose COMM frame count disagrees with the bytes actually present decodes to whichever is shorter, rather than reading off the end.</li>
<li>Writing always produces plain big-endian AIFF. The AIFC variants are read, not written.</li>
</ul>
>>

doc.CompALaw = Eight bit A-law.
doc.CompFloat32 = 32 bit IEEE floating point samples.
doc.CompFloat64 = 64 bit IEEE floating point samples.
doc.CompMuLaw = Eight bit mu-law.
doc.CompNone = Plain big-endian PCM, which is what AIFF means without AIFC.
doc.CompSowt = PCM stored little-endian instead. Common in files Apple tools wrote.
doc.DecodeAIFF = Decodes a whole AIFF or AIFC file from memory into a clip.
doc.EncodeAIFF = Encodes a clip as AIFF at the depth the clip remembers, or 16 bit when it has none.
doc.EncodeAIFFBits = Encodes a clip as AIFF at a depth you choose.
doc.IsAIFF = True when these bytes start with a FORM header naming AIFF or AIFC.
doc.OpenAIFF = Reads an AIFF file from disk into a clip.
doc.ProbeAIFF = Reads only the header, so you learn the length and rate without decoding.
doc.ReadCommon = Reads the COMM and SSND chunks together, so one call gives you the shape and where the sound is.
doc.SaveAIFF = Writes a clip to an AIFF file.
doc.SaveAIFFBits = Writes a clip to an AIFF file at a depth you choose.
doc.Common = What an AIFF COMM chunk says, plus where the samples are.
doc.Common.channels = How many channels.
doc.Common.frames = How many frames the header claims.
doc.Common.bits = Bits per sample.
doc.Common.rate = Frames per second, read from the 80 bit float AIFF stores it in.
doc.Common.compression = Which Comp number the file uses. Plain AIFF is always CompNone.
doc.Common.data_offset = Where the samples start, past the SSND header and its offset field.
doc.Common.data_size = How many bytes of samples there are.
