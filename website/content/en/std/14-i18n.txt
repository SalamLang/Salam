pkg.intro <<
<p>If your program has to speak several languages, do not write the messages into the code. Put them in a translation catalog under a key, and ask for the user's language when you display one.</p>
<p>Every catalog has a fallback language. When a message has no translation in the user's language, the fallback is shown, and when that is missing too, the key itself; so the program never shows an empty message.</p>
<p>For formatting dates in the Persian calendar see <a href="/std/calendar/">calendar</a>, and for Persian digits and text direction <a href="/std/unicode/">unicode</a> and <a href="/std/bidi/">bidi</a>; this package only handles which message to show.</p>
<h3>Things to know</h3>
<ul>
<li>An empty translation counts as missing, so <code>T</code> falls back past it.</li>
<li><code>Plural</code> knows two forms: <code>.one</code> for exactly 1 and <code>.other</code> for everything else, 0 included. Languages with more forms, such as Arabic or Russian, need their own logic around it.</li>
<li><code>DetectLocale</code> checks <code>SALAM_LOCALE</code>, then <code>LANG</code>, then <code>LC_ALL</code>, so <code>LANG</code> wins over <code>LC_ALL</code>, the reverse of the POSIX rule. With none of them set it returns <code>en</code>; with <code>LANG=C</code> it returns <code>c</code>.</li>
<li>Lookups walk the whole catalog, which is fine for a few hundred messages per language. For thousands, keep your own <code>HashMap</code> of the lines you use most.</li>
</ul>

<h2 id="guide-menu">Translate the words of a menu</h2>
<p>Pick short, stable keys such as <code>menu.save</code> and keep the real text out of the code. Fill the catalog once at start up, then ask <code>T</code> for each label in the user's language. A language with only some of the keys still works: the missing labels come from the fallback language, and a language you never added at all shows the fallback everywhere.</p>
{{example.i18n-guide-menu}}

<h2 id="guide-files">Keep translations in files</h2>
<p>Translators should not have to edit Salam code. Give each language its own file of <code>key = value</code> lines and load it with <code>LoadLocale</code>, which returns how many keys it read. Placeholders such as <code>{name}</code> stay in the text and <code>Tf</code> fills them in the same call that translates.</p>
{{example.i18n-guide-files}}
<p>The files are read with the same parser as <code>.env</code> files (see <a href="/std/config/">config</a>). That means a line starting with <code>#</code> is a comment, an unquoted <code>#</code> in a value starts a comment too, and <code>${...}</code> is expanded. Put a value in single quotes, as the <code>price</code> line does, when it contains either of them.</p>

<h2 id="guide-plural">Numbers and plurals</h2>
<p><code>Plural</code> chooses between <code>key.one</code> and <code>key.other</code>, and <code>Interpolate</code> then places the number in the chosen text. Persian usually needs one form only (<em>۵ فایل</em>), but watch the fallback: if the fallback language has a <code>.one</code> form and your language does not, n = 1 shows the fallback's text. Defining <code>.one</code> in every language avoids the surprise.</p>
{{example.i18n-guide-plural}}

<h2 id="guide-detect">Choose the user's language</h2>
<p><code>DetectLocale</code> reads <code>SALAM_LOCALE</code>, then <code>LANG</code> and <code>LC_ALL</code>, and reduces a value like <code>fa_IR.UTF-8</code> to <code>fa</code>. It returns whatever language the system names, so compare the result with the list you actually ship and fall back to your default otherwise. A web server would read the <code>Accept-Language</code> header instead and pass the same short code to <code>T</code>.</p>
{{example.i18n-guide-detect}}

<h2 id="guide-audit">Find missing translations</h2>
<p><code>T</code> never fails, which is good for users and bad for spotting gaps. <code>Has</code> checks one language only and ignores the fallback, so it can tell you which keys a translator still has to do. The catalog's <code>keys</code> field lists every entry as <code>language:key</code>.</p>
{{example.i18n-guide-audit}}

doc.Catalog = A catalog of translations. Build one with <code>New</code> and release it with <code>Free</code>.
doc.Catalog.keys = The stored keys, in the form "language:key".
doc.Catalog.vals = The translations, in the same order as the keys.
doc.Catalog.fallback = The fallback language.
doc.New = Creates an empty catalog with the given fallback language.
doc.Set = Records the translation of a key for a language, replacing any earlier one.
doc.Has = True when a translation is recorded for this language and key. It does not look at the fallback language.
doc.RawGet = Returns the recorded translation with no substitution at all, or an empty string when there is none.
doc.T = Returns the translation of the key, or the fallback language's translation, or, failing that, the key itself.
doc.Interpolate = Replaces every <code>{name}</code> in the message with the value of that name. The names and the values are given in two vectors in the same order.
doc.Tf = Translation and interpolation in one step.
doc.Plural = Chooses the right form of a message for the number <code>n</code>: the key <code>.one</code> for one and <code>.other</code> for the rest. It does not place the number in the message itself; use <code>Interpolate</code> for that. A language that needs only one form can define <code>.other</code> alone, but only when the fallback language has no <code>.one</code> either; otherwise the fallback's <code>.one</code> is shown for n = 1, so define <code>.one</code> as well.
doc.LoadLocale = Loads the translations of one language from a file of <code>key = value</code> lines and returns how many keys were read.
doc.DetectLocale = Guesses the user's language from the environment: <code>SALAM_LOCALE</code> first, then <code>LANG</code> and <code>LC_ALL</code>. When none is set it returns <code>en</code>.
doc.Free = Releases the catalog's memory.
