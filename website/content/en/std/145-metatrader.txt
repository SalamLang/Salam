<p><code>metatrader</code> is a client for a local bridge to a running MetaTrader 5 terminal. The package speaks HTTP and JSON: every call sends a request to the bridge, and the bridge asks the terminal for the data or the trade. There is no DLL, no COM and no terminal plugin inside your program, so the same Salam program runs on Linux, macOS and Windows as long as the bridge is reachable.</p>
<p>The terminal itself must be running and logged in, and a bridge must be listening on the address you set. The default is <code>http://127.0.0.1:18812</code>, the value of <code>DEFAULT_BRIDGE_URL</code>. The bridge implements the endpoints below; the package only calls them and decodes the JSON.</p>

<h2 id="guide-start">Start with the account</h2>
<p>Set the bridge address once, call <code>Initialize</code>, then read the account. Every call returns a value even when it fails, so check <code>Ok</code> or <code>LastError</code> after the calls that matter, and stop when the bridge is not there.</p>
{{example.metatrader-quickstart}}
<p><code>Initialize</code> and <code>Login</code> mark the session connected only when the bridge answers with a 2xx status. <code>IsConnected</code> reports that flag, not a live socket: call <code>Version</code> or <code>GetTerminalInfo</code> when you need to know that the terminal is still there. <code>Shutdown</code> only asks the bridge to close; it does not free anything in your program.</p>

<h2 id="guide-errors">Errors and retcodes</h2>
<p>A failed call returns the zero value of its type, an empty vector, an empty struct, or <code>false</code>, and leaves the reason in <code>LastError</code>. <code>Ok</code> is true exactly when the last code is <code>RES_S_OK</code>. The bridge uses the <code>RES_E_*</code> constants for transport and parameter errors, and the trade server uses <code>TRADE_RETCODE_*</code> in the result of <code>OrderCheck</code> and <code>OrderSend</code>.</p>
<pre class="code"><code>a := metatrader.GetAccountInfo()
if not metatrader.Ok():
    e := metatrader.LastError()
    printerrln "account failed:", e.code, e.description
    ret 1
end
println a.balance</code></pre>
<p>An HTTP error and a rejected trade are different: the first leaves <code>Ok</code> false, the second is a normal answer with a <code>retcode</code>. Always read <code>retcode</code> after <code>OrderSend</code>; a successful HTTP call does not mean the trade was accepted.</p>

<h2 id="guide-symbols">Symbols, prices and ticks</h2>
<p><code>SymbolsGet</code> returns every symbol with its contract rules and session data; the group forms filter with a mask such as <code>*USD*</code>, where <code>*</code> matches any text. <code>GetSymbolInfo</code> asks for one symbol, and <code>SymbolInfoTick</code> is the cheap call for the current bid and ask.</p>
{{example.metatrader-symbols}}
<p><code>digits</code> and <code>point</code> tell you how to round a price; <code>volume_min</code>, <code>volume_max</code> and <code>volume_step</code> tell you which volumes the server accepts; <code>trade_stops_level</code> is the shortest distance in points between the price and a stop loss or take profit.</p>

<h2 id="guide-rates">Candles and ticks</h2>
<p>Rates are returned oldest first. <code>CopyRatesFromPos</code> counts from the newest candle, so position 0 is the candle that is still forming, and <code>CopyRatesFrom</code> starts at a time. Times are seconds since the epoch, as in <code>time</code>; tick times are milliseconds in <code>time_msc</code>, which is what <code>CopyTicksRange</code> expects.</p>
{{example.metatrader-rates}}
<p>The tick filters keep the payload small: <code>COPY_TICKS_INFO</code> keeps bid and ask changes, <code>COPY_TICKS_TRADE</code> keeps trades, and <code>COPY_TICKS_ALL</code> keeps both. Check <code>flags</code> on each tick when you need to know which side changed.</p>

<h2 id="guide-trade">Checking and sending an order</h2>
<p>Fill a <code>TradeRequest</code>, call <code>OrderCheck</code>, and look at its margin fields before you send anything. Then call <code>OrderSend</code> and read <code>retcode</code>. A check returning <code>0</code> means the request is valid; the send returns <code>TRADE_RETCODE_DONE</code> for a filled order, <code>TRADE_RETCODE_PLACED</code> for a pending order, and an error code otherwise.</p>
{{example.metatrader-trade}}
<p><code>action</code> selects what the request does: <code>TRADE_ACTION_DEAL</code> for a market order, <code>TRADE_ACTION_PENDING</code> for a pending one, <code>TRADE_ACTION_SLTP</code> to change stops, <code>TRADE_ACTION_MODIFY</code> and <code>TRADE_ACTION_REMOVE</code> for pending orders, and <code>TRADE_ACTION_CLOSE_BY</code> to close one position with another. Set <code>type_filling</code> to a mode the symbol allows, and set <code>magic</code> so you can find your own orders later.</p>

<h2 id="guide-history">Orders, positions and history</h2>
<p><code>OrdersGet</code> returns active orders, <code>PositionsGet</code> returns open positions, and the history calls return what is already closed. Every filter has a total and a get form; the get form returns a vector, even when you ask by ticket, because the bridge keeps one answer shape.</p>
<p>History times are seconds since the epoch. Give both ends of the range; an empty range returns an empty vector, not an error.</p>
{{example.metatrader-history}}

<h2 id="guide-book">Market depth</h2>
<p>Market depth is a subscription. Call <code>MarketBookAdd</code> once, read the levels with <code>MarketBookGet</code> as often as you need, and call <code>MarketBookRelease</code> when you stop. The depth stays empty until the terminal has it and the subscription is active.</p>

<h2 id="guide-limits">What the package does not do</h2>
<ul>
<li>It does not start the terminal. The bridge must be running and the terminal logged in; <code>Initialize</code> is a request to the bridge, not to the terminal process.</li>
<li>It does not retry. A timeout, a closed bridge or an HTTP 5xx is returned once; decide in your own code whether to repeat the call.</li>
<li>It does not replace <code>OrderCheck</code> with local validation. The broker has the last word on volume, stops, filling and market hours.</li>
<li>It does not keep a cache. Every call asks the bridge for fresh data, so a tight loop of <code>SymbolInfoTick</code> is a lot of HTTP requests; sleep between them.</li>
</ul>
