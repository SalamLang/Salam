pkg.intro <<
<p><code>db/clickhouse</code> talks to a ClickHouse server over its HTTP interface, so it needs no native client library. <code>Open</code> takes an <code>Options</code> value and <code>OpenURL</code> takes a connection string; both return a <code>Conn</code> whose <code>Ok</code> and <code>Error</code> tell you whether it worked. <code>Query</code> returns <code>Rows</code> that you walk with <code>Next</code>, and <code>Exec</code> runs a statement that returns nothing.</p>

<h2 id="guide-bind">Arguments</h2>
<p>Values reach the server as SQL text, so never join them into a query by hand. <code>StrArg</code>, <code>IntArg</code>, <code>UIntArg</code>, <code>FloatArg</code>, <code>BoolArg</code> and <code>NullArg</code> turn a value into a safe literal, <code>ArrayArg</code>, <code>TupleArg</code> and <code>MapArg</code> build the container literals, and <code>Bind</code> replaces each <code>?</code> in the query with the next argument. <code>QuoteIdent</code> quotes a table or column name.</p>
{{example.db-clickhouse-bind}}
<p><code>RawArg</code> inserts SQL text as it is, which is the one escape hatch; use it only with text you wrote yourself.</p>

<h2 id="guide-types">Column types</h2>
<p>ClickHouse reports each column type as text such as <code>Nullable(Int64)</code> or <code>Array(String)</code>. <code>BaseType</code> strips the wrappers, <code>IsNullableType</code> asks whether a value can be null, <code>TypeKind</code> sorts a type into one of the <code>KIND_</code> constants and <code>ElementType</code> gives the item type of an array.</p>
{{example.db-clickhouse-types}}

<h2 id="guide-batch">Batch inserts</h2>
<p><code>PrepareBatch</code> starts a batch for an <code>INSERT</code> statement, you add rows with <code>Append</code>, and <code>SendBatch</code> sends them in one request. Inserting in batches is the way ClickHouse is meant to be fed; one row per request is slow.</p>
