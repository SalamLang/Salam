pkg.intro <<
<p><code>events</code> is a small publish and subscribe hub for the inside of one program. You register handlers on a topic, and <code>Emit</code> calls every handler whose topic matches. The payload type is a parameter, so one emitter carries one kind of data: <code>Emitter&lt;int&gt;</code>, <code>Emitter&lt;str&gt;</code>, or an emitter of your own struct.</p>
<p>Topics are dot-separated words such as <code>user.login</code>. In a handler's topic, <code>*</code> stands for exactly one word and <code>#</code> for the rest of the topic, including nothing at all, so <code>user.*</code> matches <code>user.login</code> but not <code>user.a.b</code>, and <code>order.#</code> matches <code>order</code>, <code>order.new</code> and <code>order.new.eu</code>.</p>
<p>Things to know:</p>
<ul>
<li><strong>A handler is a lambda</strong>, and a lambda captures the variables around it by value. Share state with a pointer, a heap collection or a <code>mut</code> global, as the examples do.</li>
<li><strong>Handlers run outside the lock</strong>, so a handler may call <code>On</code>, <code>Off</code> or <code>Emit</code> on the same emitter. Handlers added during an <code>Emit</code> first see the next event.</li>
<li><strong><code>On</code> returns an id</strong>; <code>Off</code> takes that id. Functions are not compared.</li>
<li><strong>An async emitter handles events on the thread you give it.</strong> <code>NewAsync</code> makes the queue and starts no thread; run <code>Drain</code> on one thread of your own, and its handlers run one at a time, in the order the events were queued. <code>Flush</code> waits until the queue is empty and the last handler has returned; never call it from inside a handler.</li>
<li>Release an emitter with <code>Free</code>. For an async one, call <code>Close</code> and join the thread running <code>Drain</code> first, since <code>Free</code> does not wait for it.</li>
</ul>

<h2 id="guide-basic">Register, emit, remove</h2>
<p><code>On</code> and <code>Once</code> take a topic and a handler. <code>OnAny</code> receives every event. <code>Emit</code> returns how many handlers were called.</p>
{{example.events-basic}}

<h2 id="guide-async">Handle events on a worker thread</h2>
<p><code>NewAsync</code> makes a queue of the given size, and <code>Drain</code> run on a thread of your own is its worker. <code>EmitAsync</code> puts an event on the queue and returns at once, and waits only when the queue is full. <code>Close</code> stops accepting events; <code>Drain</code> finishes what is queued and returns, so join the thread after it.</p>
{{example.events-async}}

<h2 id="guide-payload">Structs as payloads</h2>
<p>The payload type is a parameter, so a struct travels as easily as an int: <code>Emitter&lt;Order&gt;</code> hands every handler a whole <code>Order</code> in <code>ev.data</code>. <code>OnAny</code> sees every topic, including ones nobody else listens to, which makes it a good place for an audit counter or a log line. <code>Emit</code> returns how many handlers ran, so <code>order.shipped</code> below reports 1 (only the audit handler).</p>
{{example.events-guide-payload}}

<h2 id="guide-cascade">Emitting from a handler</h2>
<p>Handlers run outside the emitter's lock, so a handler may emit again on the same emitter. The nested <code>Emit</code> runs its handlers at once, before the outer handler returns, and the outer <code>Emit</code> still counts only its own handlers. Keep such chains short and make sure they end, because nothing stops a handler that emits its own topic unconditionally.</p>
{{example.events-guide-cascade}}

<h2 id="guide-teardown">Removing a component's handlers</h2>
<p>A component that registers handlers should remember their ids and give them back when it goes away, otherwise the emitter keeps calling code that is no longer meant to run. <code>Off</code> takes one id, and <code>Len</code> after teardown is an easy check that nothing was left behind. Emitting a topic with no handlers is not an error: it simply returns 0.</p>
{{example.events-guide-teardown}}

doc.New = Creates a synchronous emitter; <code>Emit</code> calls handlers on the caller's thread.
doc.On = Registers a handler for a topic pattern and returns its id.
doc.Once = Registers a handler that is called once and then removed.
doc.OnAny = Registers a handler for every topic.
doc.Off = Removes the handler with this id; returns false when there is none.
doc.OffTopic = Removes every handler registered with exactly this pattern and returns how many.
doc.Count = The number of handlers that would receive an event on this topic.
doc.Len = The number of registered handlers.
doc.Emit = Calls the matching handlers now, in the order they were added, and returns how many were called.
doc.NewAsync = Creates an emitter with a queue of this size. It starts no thread: run <code>Drain</code> on a thread of your own.
doc.EmitAsync = Queues an event for the worker; false when the emitter is closed or not async.
doc.Pending = The number of queued events that have not been handled yet.
doc.Flush = Waits until every queued event has been handled.
doc.Drain = The worker loop of an async emitter: handles queued events one at a time and returns once the emitter is closed and the queue is empty. Call it on its own thread.
doc.Close = Stops accepting events; <code>Drain</code> then finishes the queue and returns. Safe to call twice.
doc.Free = Closes the emitter and releases its memory. Join the thread running <code>Drain</code> first.
