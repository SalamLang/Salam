pkg.intro <<
<p>This is the file format behind the files of a <a href="/std/gui/webview/"><code>webview</code></a> application: a compressed and scrambled set of files, read from the end of an executable or from a file of its own. You rarely call it directly, because <code>salam bundle</code> does the packing and <code>webview</code> does the reading. Scrambling keeps names and contents out of sight; it is not encryption.</p>

<h2 id="guide-roundtrip">Pack a folder and read it back</h2>
<p><code>PackDir</code> compresses every file of a folder into one pack file and returns how many it stored, or -1. The key scrambles the content: it must be the same when you open the pack, and <code>webview</code> uses the application id. <code>Open</code> fills a <code>Pack</code> you declare first, <code>Count</code> says how many files it holds, and <code>Read</code> returns a <code>Blob</code>. A name that is not there gives a blob whose <code>data</code> is null, so test that before using it. The caller owns the bytes of a blob.</p>
{{example.gui-webview-pack-guide-roundtrip}}

<h2 id="guide-executable">Putting the pack inside a program</h2>
<p><code>AppendPack</code> adds a pack to the end of an executable, and <code>Open</code> accepts that executable as its path: it finds the pack at the end of the file. This is how a desktop program carries its pages in one file, and it is what <code>salam bundle</code> does for you. On macOS the pack goes into the application folder instead, so the signature of the program stays valid.</p>
<pre><code>pack.PackDir("www", "app.pack", "com.example.app")
pack.AppendPack("notes", "app.pack")
</code></pre>
>>
