<p>This package is what runs when you type <code>salam bundle</code>. It reads the <code>[app]</code> table of <code>salam.toml</code>, builds the program, packs its assets and makes installers. See <a href="/std/gui/webview/#guide-bundle">making installers</a> for how to use it.</p>

<h2 id="guide-manifest">The [app] table</h2>
<p>Everything <code>salam bundle</code> needs is in the <code>[app]</code> table of <code>salam.toml</code>. Only <code>id</code> and <code>name</code> matter much: the version defaults to 0.1.0, the entry file to <code>main.salam</code> and the category to Utility. <code>slug</code> is made from the name for file names. <code>ReadManifest</code> returns false when there is no table.</p>
{{example.gui-webview-bundle-guide-manifest}}

<h2 id="guide-formats">Formats and targets</h2>
<p>The default formats are tar and deb on Linux, zip on Windows, and app and tar on macOS. Name others with <code>--format</code>; each needs its tool on the <code>PATH</code>.</p>
<pre><code>$ salam bundle --format=rpm,appimage      # rpmbuild, appimagetool
$ salam bundle --target=x86_64-w64-windows-gnu --format=nsis   # makensis
$ salam bundle --target=arm64-apple-macos --format=app,dmg     # hdiutil
$ salam bundle --output=dist</code></pre>
<p>A cross build needs no extra software, because the compiler links Windows and macOS programs itself. A PNG icon is converted to <code>.ico</code> and <code>.icns</code>. Nothing is signed, so sign and notarize before you hand a program to other people.</p>

<p>The web engine is part of the <code>[app]</code> table too. By default a program uses the web view of the operating system. Set <code>engine = "chromium"</code>, or pass <code>--engine=chromium</code>, to build against Chromium Embedded Framework, and point <code>runtime</code> (or <code>--runtime=DIR</code>, or the <code>SALAM_CEF_DIR</code> environment variable) at the folder with the built <code>salam_webview_cef</code> library, <code>salam_cef_helper</code> and the CEF runtime files. That folder is copied next to the program, and only for tar on Linux and zip on Windows. See <a href="/std/gui/webview/#guide-engine">choosing the web engine</a> for what the Chromium engine can do today.</p>

<h2 id="guide-ci">Building installers in CI</h2>
<p>Run the same command on one Linux runner for every system, passing a different <code>--target</code> and <code>--output</code> each time, and upload the results. The <code>desktop.yml</code> workflow in the Salam repository does this and then runs each result on a real Windows, macOS and Linux machine.</p>
>>
