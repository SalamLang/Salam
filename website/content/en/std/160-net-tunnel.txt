pkg.intro <<
<p>This package is the common core of Salam's proxy tools. It does not speak one proxy protocol itself. It gives the packages of this family one shared shape, so any inbound (the side that accepts clients) can be joined to any outbound (the side that reaches the world): <a href="/std/net/socks/">net.socks</a>, <a href="/std/net/httpproxy/">net.httpproxy</a> and <a href="/std/net/trojan/">net.trojan</a> all plug into it, and so will the protocol packages that follow. To see how the pieces fit together in an app, read <a href="/std/net/tunnel/#guide-vpn-app">Building a v2ray style or VPN app</a>.</p>
<p>It is a toolkit for a <em>proxy</em>, not for a system wide VPN: there is no virtual network interface, so an application has to be pointed at the local port (SOCKS or HTTP) or be proxy aware. Its purpose is privacy and access to information. Use it on networks and with servers you are allowed to use, and keep the people who rely on it safe.</p>
<pre class="code"><code>application  -&gt;  inbound  -&gt;  router  -&gt;  outbound  -&gt;  remote server  -&gt;  target
             mixed       rules      direct, proxy chain, block
             SOCKS/HTTP  .ir direct
</code></pre>
<p>Core ideas:</p>
<ul>
<li>A <code>Stream</code> is a two way byte connection. TCP, TLS, WebSocket and in memory pipes all look the same, so a protocol or a relay never cares what is underneath.</li>
<li>An <code>Addr</code> is a target: a host name or IP and a port. Every dialer and every inbound speaks in <code>Addr</code> values.</li>
<li>A <code>Dialer</code> opens an outgoing connection. <code>DirectDialer</code>, <code>BlockDialer</code>, <code>Chain</code> (several proxy hops in a row), <code>Fallback</code> and <code>RouterDialer</code> are all dialers, and they nest. A <code>Connector</code> is one proxy hop that a chain can use.</li>
<li>An <code>InboundProtocol</code> reads a client's request and answers it; <code>ListenTcp</code> accepts connections and a <code>Handler</code> (usually <code>ForwardHandler</code>) serves them. <code>MixedProtocol</code> puts SOCKS4, SOCKS5 and HTTP proxy on one port.</li>
<li>A <code>Router</code> turns a target into a tag (<code>direct</code>, <code>proxy</code>, <code>block</code>) using ordered rules, with <code>IranRouter</code> as a ready preset.</li>
<li><code>ParseLink</code> and <code>ParseSubscription</code> read <code>vmess://</code>, <code>vless://</code>, <code>trojan://</code> and <code>ss://</code> share links, and <code>ParseConfig</code> reads v2ray style JSON.</li>
</ul>
<p>Things that catch people out:</p>
<ul>
<li><strong>Failure is a closed stream, not an exception.</strong> A dial that fails returns a stream whose <code>Ok</code> is false. Check it before you write.</li>
<li><strong>A config does not build protocols by itself.</strong> <code>BuildDialer</code> knows <code>freedom</code> (direct) and <code>blackhole</code> (block). Any other outbound protocol needs a maker registered with <code>RegisterOutbound</code>; until one is, that outbound refuses traffic instead of leaking it. The packages in this family give you dialers and connectors you can build in code, as the guide below does.</li>
<li><strong>It is TCP.</strong> Streams carry TCP. UDP relays are the business of the individual protocol packages.</li>
<li><strong>Examples use IPv4 loopback; tests cover IPv6 too.</strong> Listeners accept <code>::1</code> and <code>::</code> (both families), <code>DirectDialer</code> reaches IPv6 targets and races IPv6 and IPv4 addresses of a name, and the per-source limit treats IPv4-mapped clients as IPv4 and groups IPv6 clients by their /64 prefix.</li>
<li><strong>Share links are untrusted input.</strong> <code>ParseLink</code> rejects what it cannot read, but a subscription comes from someone else's server. Look at <code>allow_insecure</code> before you trust a node.</li>
<li><strong>A <code>Stats</code> value and a <code>IdleTimer</code> own native counters.</strong> Free them with <code>FreeStats</code> and <code>Free</code> when you are done.</li>
</ul>

<h2 id="guide-vpn-app">Building a v2ray style or VPN app</h2>
<p>A v2ray style app is a small pipeline: something accepts the application's connection (<em>inbound</em>), something decides where it should go (<em>router</em>), and something carries it there (<em>outbound</em>). In Salam each piece is a value, and this package joins them.</p>
<pre class="code"><code>              +--------------------------- your process ----------------------------+
application   |  inbound          router              outbound                   |   remote server
(browser,     |  MixedProtocol  Router            Dialer                   |   (trojan, ...)
 curl, app) -&gt; |  SOCKS4/5 + HTTP  rules decide a tag  direct                    | -&gt;      |
127.0.0.1:1080|  -&gt; Session      .ir, private: direct  Via(hop), Chain         |           -&gt; target
              |     target Addr everything else: proxy BlockDialer           |
              +----------------------------------------------------------------------+
                         ForwardHandler relays bytes both ways (Relay)</code></pre>
<p>The example runs this whole pipeline on loopback. Two echo servers stand in for the Internet: <code>local</code> is reached directly and <code>abroad</code> only through a Trojan server, which the router chooses by port. A mixed inbound takes a SOCKS5 client and an HTTP <code>CONNECT</code> client on the same port.</p>
{{example.net-tunnel-guide-app}}
<p>The pieces, in order: <code>ParseRules</code> builds the <code>Router</code>; a <code>RouterDialer</code> maps each tag to a dialer (<code>Direct</code> for <code>direct</code>, <code>Via</code> with a trojan <code>Connector</code> for <code>proxy</code>); <code>NewMixed</code> with <code>MixedSetSocks5</code> and <code>MixedSetHttp</code> is the inbound protocol; <code>NewForwarder</code> joins the dialer and the protocol into a handler; <code>ListenTcp</code> and <code>ServeBackground</code> start serving. To add more hops use <code>Chain</code>; to try several outbounds in turn use <code>Fallback</code>.</p>
<h3 id="guide-iran">Practical advice for Iran</h3>
<ul>
<li><strong>Send domestic traffic direct.</strong> <code>IranRouter</code> sends <code>.ir</code> (and the Persian <code>.ایران</code> forms), private addresses and a few large domestic services straight out, and everything else to your proxy tag. That keeps banking, delivery and government sites working at normal speed and with their normal IP, and keeps the load on your server down. Add your own lines with <code>RuleSuffix</code> or a rule file for <code>ParseRules</code>.</li>
<li><strong>Use TLS, and give the server a real face.</strong> A Trojan server that holds a real certificate and a real website behind it (<code>trojan.SetFallback</code>) looks like any HTTPS site to a probe: anything that is not an authenticated client is handed to that site. Use a domain you own, a valid certificate and a fallback that serves actual content.</li>
<li><strong>Fragment the TLS hello.</strong> Some filters read the server name in the first TLS record. <a href="/std/net/censor/">net.censor</a> can split that record into pieces (<code>censor.FragmentClientHello</code>, <code>censor.SNISplitSizes</code>) before it is sent. Treat it as one tool that works on some networks and not on others, and test it where you are.</li>
<li><strong>Resolve names over an encrypted channel.</strong> Plain DNS on UDP port 53 is readable and easy to tamper with. <a href="/std/net/doh/">net.doh</a> resolves over DNS over HTTPS or TLS, caches answers, and can run a local stub resolver for other programs. Resolve through the proxy side where you can, so that the name lookup does not reveal what you visit.</li>
<li><strong>Keep the rules honest.</strong> A proxy that sends everything out hurts everyday browsing, and one that sends too much direct leaks. Review your rule list the same way you review a firewall.</li>
<li><strong>Protect the people on the other end.</strong> Do not log targets, rotate passwords, and do not share a server with a shared password across people you cannot vouch for.</li>
</ul>
<p>This package is a tool for privacy and for reaching information. It cannot make you anonymous, it does not hide that you use a proxy from your network provider, and it is not meant for abuse of other people's services or networks.</p>
<h3 id="guide-config">From a config or a share link</h3>
<p>If your app takes a subscription, <code>ParseSubscription</code> gives a list of <code>Node</code> values and <code>ConfigFromNodes</code> turns them into a ready <code>Config</code> (a mixed inbound, one outbound per node, direct and block, and the <code>.ir</code> rule). <code>BuildDialer</code> then builds the dialer, but only for outbound protocols that have a registered maker. Writing a maker is a few lines, see <code>OutboundMaker</code>.</p>

<h3 id="guide-quickstart">Quick start: building a proxy or VPN app with Salam</h3>
<p>This is the short path from a share link to a local proxy that a browser or any other program can connect to. Each step is one call, and the program below puts them together.</p>
<ol>
<li><strong>Read the link or the subscription.</strong> <code>ParseLink</code> reads one <code>vless://</code>, <code>vmess://</code>, <code>trojan://</code> or <code>ss://</code> link and <code>ParseSubscription</code> reads a text with many links (Base64 or one link per line). A bad line is dropped and counted in <code>skipped</code>; the program does not stop. A link that comes from someone else is untrusted input: look at <code>allow_insecure</code> before you trust a node.</li>
<li><strong>Build a config.</strong> <code>ConfigFromNodes</code> makes a mixed inbound (SOCKS4, SOCKS5 and HTTP on one local port), one outbound per node, the <code>direct</code> and <code>block</code> outbounds and the <code>.ir</code> rule. With no extra work, <code>.ir</code> domains and private addresses go direct and everything else goes through your node.</li>
<li><strong>Turn on DoH and fragmenting.</strong> With <code>RegisterWith</code>, the <code>fragment</code> option sends the ClientHello in several packets and <code>use_doh</code> resolves names with DNS over HTTPS. Both are only options: they help on some networks and not on others.</li>
<li><strong>Start.</strong> <code>StartAll</code> brings the inbounds up and <code>Stop</code> closes each one. If the config is a V2Ray style JSON file, <code>RunConfig</code> loads it, checks it and runs it until Ctrl-C.</li>
<li><strong>Connect your programs.</strong> The inbound listens on <code>127.0.0.1</code> only. In a browser or an app, set the SOCKS5 or HTTP proxy to that port. To test from a command line, <code>curl --socks5-hostname 127.0.0.1:1080 https://example.com</code> resolves the name through the proxy too.</li>
</ol>
{{example.net-tunnel-guide-quickstart}}
<p>The example has made up servers (<code>example.org</code>) and only shows building and listening; put your own link in, save it to a file and run it:</p>
<pre class="code" dir="ltr"><code>salam run proxy.salam</code></pre>
<p>A few honest points before you use it:</p>
<ul>
<li>This is a tool for privacy and for reaching information. It does not make you anonymous and it does not promise that you will not be seen: a network that can recognize a proxy from its TLS fingerprint, its traffic pattern or active probing can block it.</li>
<li>Fragmenting and DoH are small measures. Test both on the network you are really on, and do not rely on one trick alone.</li>
<li>Only work with servers and links you know. The operator of any proxy can see where you connect, and a share link is itself a password or key; do not publish it.</li>
<li>Before you run a service for other people, or use one, learn the laws and rules of the country and the network you are in. The responsibility for how you use it is yours.</li>
<li>The limits of each protocol (not tested against a real server, no ML-KEM, the server clock for VMess and so on) are on the page of that package.</li>
</ul>

<h2 id="guide-streams">Streams and relays</h2>
<p>Everything above sits on <code>Stream</code>. Wrap a TCP, TLS or WebSocket connection with <code>WrapTcp</code>, <code>WrapTls</code> or <code>WrapWebSocket</code>, or make two in memory ends with <code>NewPipe</code>, and the rest of the code is the same. <code>Relay</code> copies both ways until one side ends; <code>RelayWith</code> adds counters and an idle limit and is what <code>ForwardHandler</code> uses. Helpers such as <code>ReadFull</code>, <code>ReadUntil</code> and <code>WriteAll</code> deal with short reads and writes.</p>
<p>In memory pipes make protocol code easy to test without a socket: write the client's bytes to one end, run the handshake on the other, and compare the reply.</p>

<h2 id="guide-routing">Routing rules</h2>
<p>A <code>Router</code> holds ordered <code>Rule</code> values. A rule has destination conditions (exact host, suffix, keyword, regular expression, CIDR) and port conditions; a target matches when it passes one destination condition and one port condition (each only if the rule has some). The first matching rule gives its tag; when none match, the default tag is used. Matching ignores case and a trailing dot, and a suffix such as <code>ir</code> matches <code>a.b.ir</code> but not <code>evilir</code>.</p>
<p>Rules come from code, from <code>ParseRules</code> or <code>LoadRules</code> (the Clash like line format shown there), or from the <code>routing</code> part of a v2ray config through <code>BuildRouter</code>. A rule that names no condition never matches. <code>ParseRules</code> keeps the good lines and lists the bad ones in <code>errors</code> with their line numbers, so a typo does not silently drop a rule.</p>
<pre class="code"><code># one rule per line: KIND,value,tag
DOMAIN-SUFFIX,ir,direct
DOMAIN-KEYWORD,tracker,block
IP-CIDR,203.0.113.0/24,direct
GEOIP,PRIVATE,direct
DST-PORT,25,block
FINAL,proxy</code></pre>
<p><code>GEOIP</code> understands only <code>PRIVATE</code>. There is no country database in the package, which is why Iranian destinations are recognised by their domain suffix and a short list of well known domains rather than by IP ranges.</p>

<h2 id="guide-limits">What to know</h2>
<ul>
<li>This is a proxy toolkit, not a VPN with a virtual interface.</li>
<li>Streams are TCP. IPv6 is parsed, routed, dialed and accepted.</li>
<li>A failed dial returns a closed stream. Check <code>Ok</code>.</li>
<li>Outbound protocols in a config need a registered maker, otherwise the outbound refuses traffic.</li>
<li>A <code>Stats</code> and an <code>IdleTimer</code> must be freed. A <code>TcpInbound</code> stops with <code>Stop</code>; connections already relayed carry on to their end.</li>
<li><code>TcpInbound</code> serves each connection on a pool thread. The default handshake limit is 15 seconds, so a client that connects and says nothing is dropped.</li>
<li>No logging happens by itself. Add your own where it is safe to do so.</li>
</ul>
