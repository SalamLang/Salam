pkg.intro <<
<p>Trojan is a proxy protocol built to look like nothing. A client opens a normal TLS connection to a server and sends one line that holds a password hash and the target it wants; if the hash is right the server connects there and relays bytes. If the first bytes are <em>not</em> a valid Trojan request, the server does not complain. It hands the connection, bytes and all, to an ordinary website, so a visitor or a probe gets a real page from a real site. This package has both sides: <code>Dial</code> is the client and <code>Serve</code> runs the server. It also plugs into <a href="/std/net/tunnel/">net.tunnel</a> as an <code>Inbound</code> and a <code>Connector</code> for routing and proxy chains. To see how the pieces fit together in an app, read <a href="/std/net/tunnel/#guide-vpn-app">Building a v2ray style or VPN app</a>.</p>
<p>Core ideas:</p>
<ul>
<li>A password is never sent. What goes on the wire is its SHA-224 hash (<code>PasswordHash</code>), as 56 hex characters. The server keeps hashes (<code>AddPassword</code>, <code>AddPasswordHash</code>).</li>
<li>TLS does the hiding. The Trojan request is inside the TLS stream, and a server with a valid certificate and a real <code>fallback_port</code> website looks like any HTTPS site.</li>
<li>Failure is silent. A wrong password, a browser, a scanner: all get the fallback site. <code>fallbacks</code> counts them.</li>
<li>A <code>Link</code> is a connection over TCP, TLS or WebSocket. <code>Dial</code> returns one; read and write it with <code>LinkRead</code> and <code>LinkWriteStr</code>, and close it with <code>LinkClose</code>. <code>use_ws</code> carries Trojan inside a WebSocket so that a CDN or reverse proxy can sit in front.</li>
<li><code>DialUDP</code> opens a UDP session where every packet names its own target (<code>SendUDP</code>, <code>ReadUDPPacket</code>).</li>
</ul>
<p>Things that catch people out:</p>
<ul>
<li><strong>Use TLS, with a real certificate.</strong> <code>Serve</code> is the real server. <code>ServePlain</code> and <code>ServeWS</code> have no TLS: the password hash and all traffic are readable by anyone on the path, and the hash can be replayed. Use them on loopback, in tests, or behind a reverse proxy that ends TLS. <code>insecure</code> switches certificate checking off; never use it outside a test.</li>
<li><strong>The fallback site must be real.</strong> A fallback that is missing, empty or obviously fake makes the server easy to recognise. Without <code>fallback_port</code>, a failed client is just disconnected, which is itself a sign. Serve real content, on the same machine, with the same certificate name.</li>
<li><strong>WebSocket mode has no fallback.</strong> A failed client of <code>ServeWS</code> is simply closed. Let the reverse proxy in front decide what the outside world sees.</li>
<li><strong>No replay protection.</strong> The request holds no nonce, so anyone who can read it (a plain connection, a broken certificate check) can replay it. <a href="/std/net/censor/">net.censor</a> has a <code>censor.ReplayCache</code> and a <code>censor.ProbeGuard</code>, but this package does not use them for you.</li>
<li><strong>A server listens on all IPv4 addresses.</strong> The port is bound on every interface. Anyone who can reach it can try passwords, so use long random ones.</li>
<li><strong>The password and its hash are equivalent.</strong> Whoever has the hash can authenticate. Protect the config like a password file.</li>
<li><strong>A <code>Link</code> is not a <code>tunnel.Stream</code>.</strong> <code>Link</code> is the package's own connection type. For <code>tunnel.Chain</code> and routing use the <code>Connector</code> and <code>Inbound</code> adapters, which work on streams.</li>
</ul>

<h2 id="guide-loopback">A server, a client and a fallback</h2>
<p>This runs the whole idea on loopback with no certificate: a Trojan server in front of an echo server, with a web server as the fallback. The real client gets the echo; anyone else sends ordinary web traffic to the same port and gets the web page. In production <code>Serve</code> adds TLS in front of exactly this behaviour.</p>
{{example.net-trojan-guide-loopback}}
<p>With TLS, give the config the certificate and the key and start it with <code>Serve</code>. Point <code>SetFallback</code> at a real web server on the same machine, and use the domain of the certificate as the name clients connect to.</p>
<pre class="code"><code>mut config := trojan.NewServerConfig("fullchain.pem", "privkey.pem")
trojan.AddPassword(config, "a long random password")
trojan.SetFallback(config, "127.0.0.1", 8080)
server := trojan.Serve(config, 443)</code></pre>

<h2 id="guide-chain">Using Trojan in a proxy chain</h2>
<p>For routing and chains, a <code>Connector</code> writes the Trojan request over any stream that already reaches the server, and an <code>Inbound</code> reads it on the server side. The stream underneath decides what is private: over a plain TCP stream the hop is readable, so put TLS under it. With a <code>tunnel.Dialer</code> that provides TLS as the upstream, <code>tunnel.Via</code> makes a complete outbound:</p>
<pre class="code"><code>hop := trojan.NewConnector("proxy.example.com", 443, "a long random password")
outbound := tunnel.Via(your_tls_dialer, hop)</code></pre>
<p>The guide of <a href="/std/net/tunnel/">net.tunnel</a> shows the whole pipeline with this connector in it. For a client that does not need routing, <code>Dial</code> does the TLS itself and is simpler.</p>

<h2 id="guide-limits">What to know</h2>
<ul>
<li>Use <code>Serve</code>, with a real certificate and a real fallback website. <code>ServePlain</code> and <code>ServeWS</code> are for loopback, tests and use behind something that ends TLS.</li>
<li>No replay protection and no brute force limit of its own. Use long random passwords.</li>
<li>The server listens on every IPv4 interface.</li>
<li>Only IPv4 loopback is tested. Names are resolved by the server for the target.</li>
<li>UDP runs inside the same connection. <code>ReadUDPPacket</code> gives one packet at a time.</li>
<li>Free what you allocate: <code>LinkClose</code> for a <code>Link</code>, <code>FreeSession</code> for a <code>Session</code>.</li>
<li>No logging happens by itself.</li>
</ul>
>>
