pkg.intro <<
<p>The <code>stats</code> package answers the first questions you ask of a list of numbers: how many, the total, the typical value, the spread and the extremes. Use it for reports, monitoring (latency percentiles), grading and checking a simulation. It covers descriptive statistics only; there is no mode, correlation, regression or histogram. For scalar maths use <a href="/std/math/">math</a>, for fitting models <a href="/std/ml/">ml</a>, and to generate the numbers in the first place <a href="/std/rand/">rand</a>.</p>
<p>Every function takes a <code>Vector&lt;f64&gt;</code> and never changes it. Whole numbers have to be converted with <code>as f64</code> on the way in. <code>Median</code> and <code>Percentile</code> sort a private copy on each call, so asking for p50, p90 and p99 sorts three times; that is fine for thousands of values and worth knowing for millions.</p>
<p>Variance and standard deviation come in two forms. <code>Variance</code> and <code>Stdev</code> treat the data as a <em>sample</em> of a larger group and divide by n−1; <code>PopVariance</code> and <code>PopStdev</code> treat it as the whole group and divide by n. The sample form is the usual choice.</p>
<p>What people get wrong:</p>
<ul>
<li>Trusting the result of an empty list. Nothing fails: <code>Mean</code>, <code>Median</code>, <code>Min</code>, <code>Max</code> and <code>Percentile</code> return 0, which looks like real data. Check <code>len()</code> first.</li>
<li>Reporting the mean of skewed data. One slow request or one very rich customer moves the mean a long way; the median and percentiles do not move.</li>
<li>Averaging growth rates with <code>Mean</code>. Factors that multiply need <code>Geomean</code>.</li>
</ul>

<h2 id="guide-report">A summary of a class</h2>
<p>The usual job is a short report on a list of numbers: how many, the middle, the spread and the extremes. Put the values in a <code>Vector&lt;f64&gt;</code> once and call the functions you need; none of them changes the vector. The standard deviation also lets you flag values that are far from the rest: a value more than one standard deviation from the mean is unusual in a small group.</p>
{{example.stats-guide-report}}
<p>A class or a survey is usually a sample, so <code>Stdev</code> is the right choice. Use <code>PopStdev</code> only when the list holds every member of the group you are describing, for example all the machines in a cluster.</p>

<h2 id="guide-latency">Response times: median and percentiles</h2>
<p>One slow request can pull the mean far away from what most users see. In this example nine requests take about 40 ms and one takes 1200 ms; the mean says 157 ms, while the median (the 50th percentile) says 41.5 ms. Monitoring therefore uses percentiles: p90 is the time 90% of requests stay under, and p99 shows the worst cases.</p>
{{example.stats-guide-latency}}
<p><code>Percentile</code> interpolates between the two nearest values, so with few samples the high percentiles land between a normal value and the outlier. Collect a few hundred values before you trust p99.</p>

<h2 id="guide-growth">Growth rates and the geometric mean</h2>
<p>When values are multiplied, as with yearly returns or growth factors, the arithmetic mean overstates the result. A gain of 50% followed by a loss of 40% is not an average gain. <code>Geomean</code> gives the single factor that, repeated, reaches the same end value.</p>
{{example.stats-guide-growth}}

<h2 id="guide-parse">Reading numbers from text</h2>
<p>Data usually arrives as text, with empty cells, labels such as <code>n/a</code> and sometimes Persian digits. Check each cell with <code>types.IsNumeric</code> from <a href="/std/types/">types</a>, turn Persian digits into English ones with <code>str.ToEnglishDigits</code> and parse with <code>conv.ParseFloat</code>. Count what you skipped, so that a report on bad data does not look like a report on good data.</p>
{{example.stats-guide-parse}}

<h2 id="guide-edge">Empty and tiny lists</h2>
<p>The functions do not fail on awkward input; they return a number, and that number can mislead. An empty vector gives 0 for the mean, the median and the maximum. One value has a variance of 0. A zero or a negative value makes the geometric mean 0, and a percentile outside 0 to 100 is moved to the nearest end. Check <code>len()</code> before you report anything.</p>
{{example.stats-guide-edge}}

doc.Sum = The sum of all the numbers; 0 for an empty vector.
doc.Mean = The arithmetic mean; 0 for an empty vector.
doc.Min = The smallest number; 0 for an empty vector, which you cannot tell from a real 0.
doc.Max = The largest number; 0 for an empty vector.
doc.Median = The middle number after sorting, or the mean of the middle two when there is an even count; 0 for an empty vector. It stands up to outliers better than the mean. Sorts a copy on each call.
doc.Variance = The sample variance, dividing by n−1 after a first pass for the mean. Fewer than two values give 0.
doc.PopVariance = The population variance, dividing by n; 0 for an empty vector.
doc.Stdev = The sample standard deviation, the square root of <code>Variance</code>. Fewer than two values give 0.
doc.PopStdev = The population standard deviation, the square root of <code>PopVariance</code>.
doc.Geomean = The geometric mean, the n-th root of the product, computed through logarithms so it does not overflow. It suits growth factors and ratios. Every number has to be positive: a zero or a negative value makes the result 0, and so does an empty vector.
doc.Percentile = The <code>p</code>th percentile, with <code>p</code> from 0 to 100, interpolating linearly between the two nearest sorted values (the method of Excel <code>PERCENTILE.INC</code> and the NumPy default). <code>p</code> outside that range is moved to the nearest end; 0 gives the minimum and 100 the maximum. Sorts a copy on each call.
