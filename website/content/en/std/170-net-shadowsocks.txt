pkg.intro <<
<p>Shadowsocks is a small encrypted proxy protocol. A client connects to a Shadowsocks server and says which host and port it wants to reach; the server connects there and carries bytes both ways. Everything after the first byte looks like random data, so there is no handshake to recognise. <code>net.shadowsocks</code> is a client and a server for it written in Salam, with no native library. It is one of the proxy packages built on <a href="/std/net/tunnel/">net.tunnel</a> and can be plugged into the same routers and chains as the others.</p>
<p>The main calls are few. <code>Dial</code> opens a <code>Conn</code> through a server to a target such as <code>example.com:443</code>; <code>Read</code>, <code>Write</code> and <code>Close</code> then work like on any socket. <code>Listen</code> starts a server and <code>Serve</code> or <code>ServeRelay</code> answers clients. <code>Config</code> holds the server address, the cipher <code>method</code>, the <code>password</code> and the optional <code>obfs</code> disguise. Everything else (<code>Buf</code>, <code>Encoder</code>, <code>Decoder</code>, the BLAKE3 and key functions) is the lower level the protocol is built from, public so you can test it or build your own framing.</p>

<h2 id="guide-quickstart">Quick start</h2>
<p>This program starts a server on a free port, connects a client through it to <code>example.com:443</code> and sends one message. The handler never connects to <code>example.com</code>; it only reads the target the client asked for with <code>TargetOf</code> and echoes the bytes back, so the whole run stays on the loopback interface. <code>Stop</code> wakes the accept loop so that <code>Serve</code> returns, and <code>Destroy</code> frees the server.</p>
{{example.net-shadowsocks-guide-loopback}}
<p>A real server uses <code>ServeRelay</code>, which does the forwarding for you: for each client it connects to the requested target and copies bytes in both directions until either side closes. The next example runs a relay in front of a small TCP echo server and sends a message through it.</p>
{{example.net-shadowsocks-guide-relay}}
<p>The client side is just <code>Dial</code> with a <code>Config</code>. <code>Dial</code> returns at once without waiting for the server: the target address travels in the first encrypted packet together with your first <code>Write</code>. So a wrong password is not reported by <code>Dial</code>; the server drops the connection and your first <code>Read</code> returns 0 or a negative number. Check <code>Ok</code> for a connection that could not even start (an unknown method, or the server not reachable).</p>

<h2 id="guide-methods">Ciphers</h2>
<p>The <code>method</code> is a name from this table. <code>LookupMethod</code> turns a name into a <code>Method</code> and returns one with <code>ok</code> false for a name it does not know. The name <code>chacha20-poly1305</code> is accepted too, as an alias of <code>chacha20-ietf-poly1305</code>. Old stream ciphers such as <code>rc4-md5</code> and <code>aes-256-cfb</code> are not supported and never will be: they are broken.</p>

<p>For the first three, the password is any text and the key is derived from it the classic way (<code>BytesToKey</code>, MD5 based), so use a long random password. For the 2022 ciphers the password <em>is</em> the key: it must be the base64 of exactly the key length, for example the output of <code>openssl rand -base64 32</code>. A password of the wrong length makes <code>MakeKey</code> return a <code>Buf</code> with <code>bad</code> set, and <code>Listen</code> or <code>Dial</code> then fail. The 2022 ciphers add replay protection with a timestamp (a request more than 30 seconds off is refused) and a salt cache, and the connection header is authenticated.</p>

<h3 id="limits">What is not there</h3>
<ul>
<li>Shadowsocks 2022 is implemented for TCP only. <code>UdpListen</code>, <code>UdpDial</code>, <code>PackUdp</code> and <code>UnpackUdp</code> refuse the three 2022 methods.</li>
<li>No multi user support: the 2022 extensible identity headers (EIH, a key per user behind one port) are not implemented. A server has one password.</li>
<li>No real server was used to test the interoperability of <code>simple-obfs</code> and of the 2022 TCP stream. They are tested against this package itself and against separate Python reimplementations written from the specifications, not against <code>ssserver</code>, <code>shadowsocks-rust</code> or the real <code>obfs-server</code>. The classic AEAD ciphers are checked against published test vectors. Treat the 2022 methods and the obfuscation as young and test against your own server before relying on them.</li>
<li>AES is done in software (bitsliced, to avoid timing leaks) and is slow: in the tests here about four to five times slower than ChaCha20. Prefer <code>chacha20-ietf-poly1305</code>.</li>
<li>The relay has no half close: when one side closes, the whole connection is shut down. A protocol that depends on a client finishing its request with a close and still reading the answer will break.</li>
<li>No anti probing behaviour: a server that receives a bad first packet closes the connection at once instead of draining it as a real web server would, so a prober can tell it is not one.</li>
<li>UDP is IPv4 only, and the UDP relay has no replay filter (TCP has one, a salt cache of 100000 entries).</li>
<li>Only the HTTP and TLS shapes of <code>simple-obfs</code> exist, not the plugin <code>v2ray-plugin</code> or other plugins.</li>
</ul>

<h2 id="guide-uri">ss:// links and plugin options</h2>
<p>Shadowsocks servers are shared as <code>ss://</code> links. <code>ParseUri</code> reads the SIP002 form <code>ss://base64(method:password)@host:port/?plugin=...#tag</code>, the form with the user info in plain percent encoded text (used by the 2022 ciphers), and the old form where the whole <code>method:password@host:port</code> is base64. It returns a <code>Uri</code> whose <code>ok</code> is true only when the link is well formed and the method is known. <code>FormatUri</code> writes the link back (a 2022 link is written with the method and password in text, the others as base64). <code>ToConfig</code> turns a <code>Uri</code> into a <code>Config</code> that <code>Dial</code> accepts, including the obfuscation options of the plugin.</p>
<p>The <code>plugin</code> text is a plugin name followed by <code>key=value</code> options separated by semicolons, with a backslash to escape a semicolon or equals sign. <code>ParsePlugin</code> splits it into a <code>Plugin</code> and <code>PluginGet</code> and <code>PluginHas</code> read the options. Free it with <code>PluginFree</code>. <code>ToConfig</code> understands the plugin names <code>obfs-local</code> and <code>simple-obfs</code> with the options <code>obfs</code> (<code>http</code> or <code>tls</code>) and <code>obfs-host</code>; any other plugin is ignored, so check <code>u.plugin</code> yourself if you need to refuse it.</p>
{{example.net-shadowsocks-guide-uri}}

<h2 id="guide-obfs">simple-obfs</h2>
<p><code>simple-obfs</code> hides the first bytes of a Shadowsocks connection inside something that looks like ordinary web traffic, which helps against filters that classify connections by their first packet. Set <code>obfs</code> in the client <code>Config</code> to <code>"http"</code> or <code>"tls"</code>, set <code>obfs_host</code> to the host name to show (the <code>Host</code> header or the TLS server name, default <code>www.bing.com</code>), and start the server with <code>ListenObfs</code> and the same mode. Both sides must agree: a server without obfs does not understand an obfs client and the other way round.</p>
<ul>
<li><code>http</code>: the first client packet is sent as an HTTP request with a WebSocket upgrade header, the server answers with a <code>101 Switching Protocols</code>, and after that the data flows as is.</li>
<li><code>tls</code>: the first client packet is a fake TLS ClientHello carrying the data in a session ticket extension and the server name you chose, the server answers with a fake ServerHello, and the rest is wrapped in TLS application data records.</li>
</ul>
<p>This is camouflage, not encryption: the Shadowsocks cipher underneath still protects the data. The fake handshake is simple and a determined censor can fingerprint it; it also does not make the connection look like a real site to an active prober. <code>ObfsMode</code> turns the names into the constants <code>OBFS_NONE</code>, <code>OBFS_HTTP</code> and <code>OBFS_TLS</code>, and <code>ObfsInit</code>, <code>ObfsWrap</code>, <code>ObfsUnwrap</code> and <code>ObfsFree</code> expose the framing for your own use.</p>
{{example.net-shadowsocks-guide-obfs}}

<h2 id="guide-udp">The UDP relay</h2>
<p>Shadowsocks carries UDP too, for DNS and for games, one encrypted datagram at a time: the packet holds a random salt, the target address and the payload, sealed as a whole. <code>UdpListen</code> starts a relay on a UDP port; <code>UdpServe</code> loops until <code>UdpStop</code> is called, and <code>UdpStep</code> handles one packet and returns 1 when it did, so you can drive it yourself. The relay keeps one outgoing socket per client and forgets a client after 60 seconds of silence. On the client, <code>UdpDial</code> makes a <code>UdpClient</code>, <code>UdpSend</code> sends a payload to a target through the relay and <code>UdpRecv</code> returns the next reply and who it came from; <code>UdpSetTimeout</code> bounds the wait. UDP also works with the three 2022 ciphers (SIP022): the client picks a random session ID, numbers its packets, and the first 16 bytes of each datagram are that header encrypted on its own (AES-ECB for the AES methods, an XChaCha20-Poly1305 nonce for the ChaCha one). Packets carry a timestamp that must be within 30 seconds, and the relay drops any packet ID it has already seen in a 64 packet window. The classic methods get a salt filter on the relay, so a recorded datagram is answered once. UDP targets must be IPv4 or domain names.</p>
{{example.net-shadowsocks-guide-udp}}

<h2 id="guide-users">Several users on one 2022 server</h2>
<p>An AES 2022 server can serve many users, each with their own key. Give the server its own key as the password, then call <code>AddUser</code> (<code>UdpAddUser</code> for UDP) once per user key. A client connects with the password <code>serverkey:userkey</code>: it sends an identity header that names its user without revealing the key, and the server picks that user's key for the session. <code>ChainOf</code>, <code>EihSeal</code> and <code>EihOpen</code> are the pieces underneath. The ChaCha 2022 method has no identity headers, so it takes a single key. <code>ListenOn</code> and <code>UdpListenOn</code> bind to one address instead of every interface, for example <code>127.0.0.1</code>. When a handshake fails the server keeps the socket open for a random 1.5 to 4.5 seconds and reads what is sent before closing, so a probe cannot tell a refusal from a slow server. <code>Relay</code> passes a half close in both directions: when one side stops sending, the other side is told and can still answer.</p>

<h2 id="guide-over-stream">Running over a tunnel.Stream</h2>
<p>The client normally dials its server with TCP, but <code>DialOver</code> takes any <code>tunnel.Stream</code> instead: a WebSocket, a TLS connection, the output of another proxy hop, or a stream you made. The server side has <code>AcceptOver</code>. In both cases the Shadowsocks layer treats the stream as the wire, so you can put Shadowsocks inside a transport from <a href="/std/net/transport/">net.transport</a>, or behind a proxy chain from <a href="/std/net/tunnel/">net.tunnel</a>. <code>AsStream</code> does the opposite: it wraps a <code>Conn</code> as a <code>tunnel.Stream</code>, so a Shadowsocks connection can be handed to anything that takes a stream, such as a router outbound or another protocol layer.</p>
{{example.net-shadowsocks-guide-over-stream}}

<h2 id="guide-codec">The framing layer</h2>
<p>The bottom of the package is public. An <code>Encoder</code> seals a byte stream into length prefixed AEAD chunks (<code>EmitSalt</code> first, then <code>EncodeStream</code>); a <code>Decoder</code> takes in the bytes as they arrive with <code>Feed</code> and returns the plaintext with <code>NextChunk</code>, or all at once with <code>DecodeAll</code>. <code>EncodeTarget</code> and <code>ParseTarget</code> write and read the address header (<code>ATYP_IPV4</code>, <code>ATYP_DOMAIN</code>, <code>ATYP_IPV6</code>), and <code>PackUdp</code> and <code>UnpackUdp</code> do the same for one datagram. <code>Buf</code> is the growable byte buffer all of them use: you own it, free it with <code>BufFree</code> and wipe key material with <code>BufWipe</code> first. This is how the protocol is tested against known vectors, and how you can write a custom front end.</p>
<p>The example under <a href="#Buf">Buf</a> below runs a whole round trip: it seals a stream and opens it again, writes and reads an address header, and packs and unpacks one UDP datagram.</p>

<h2 id="guide-iran">Practical notes for Iran</h2>
<p>These are tips for people building tools for networks with heavy filtering. They come from how the protocol works, not from tests against any particular ISP, and what works changes from month to month.</p>
<ul>
<li><strong>Pick ChaCha20.</strong> Use <code>chacha20-ietf-poly1305</code> unless the other end only offers something else. It is the fastest cipher here by a wide margin, and the security is the same as AES-GCM. Choose a 2022 method only when your server also speaks it and you can test it end to end; it has the best design (replay protection, authenticated header) but the least interoperability testing.</li>
<li><strong>Use a long random password</strong> for the classic methods, at least 20 characters from a password generator. Short passwords can be guessed offline from a captured connection.</li>
<li><strong>Do not rely on plain Shadowsocks alone.</strong> Pure random looking traffic on an unusual port is itself a signal, and the lack of an anti probing reply makes it easier to confirm. Put it on port 443, behind a transport that looks like a web site (a WebSocket over TLS, with <code>DialOver</code> and <code>AcceptOver</code>), or use <code>simple-obfs</code> with <code>tls</code> and a host name that is allowed and common on that network.</li>
<li><strong>Use the tunnel router.</strong> <a href="/std/net/tunnel/">net.tunnel</a> has routing rules with an Iran preset: domestic sites go direct and the rest goes through the proxy, so the local network is not slowed down and domestic sites do not see a foreign address. Make a Shadowsocks outbound from a <code>Config</code>, wrap it as a stream with <code>AsStream</code> where a dialer wants a stream, and let the router choose. For a local SOCKS or HTTP entry point see <a href="/std/net/socks/">net.socks</a> and <a href="/std/net/httpproxy/">net.httpproxy</a>.</li>
<li><strong>Resolve names remotely.</strong> Pass the host name to <code>Dial</code> and let the server resolve it; do not resolve it locally first, or the lookup leaks. When a local lookup is unavoidable, <a href="/std/net/doh/">net.doh</a> sends it over HTTPS.</li>
<li><strong>Keep sharing safe.</strong> A link carries the password in clear text apart from base64: send it over a private channel, and do not publish servers you want to keep alive.</li>
</ul>

doc.ObfsWrap = Wraps outgoing bytes in the disguise (the fake request or hello for the first packet, TLS records after that) and appends the result to the buffer.
doc.ObfsUnwrap = Removes the disguise from incoming bytes and appends the payload to the buffer. Returns the number of bytes consumed, 0 when more bytes are needed, or a negative number when the data is not a valid disguise.
doc.ObfsInit = Makes the state for a mode, for the client or the server side, with the host name to show.
doc.ObfsFree = Frees an <code>Obfs</code>.
doc.ObfsMode = Turns <code>http</code> or <code>tls</code> into the <code>OBFS_</code> constant; anything else gives <code>OBFS_NONE</code>.
doc.UdpClient = A UDP client that talks to a Shadowsocks UDP relay.
doc.UdpClient.sock = The local UDP socket.
doc.UdpClient.host = The relay host.
doc.UdpClient.port = The relay port.
doc.UdpClient.method = The cipher method.
doc.UdpClient.key = The master key.
doc.UdpClient.rbuf = The receive buffer.
doc.UdpClient.ok = True when the client could be set up.
doc.UdpServer = A Shadowsocks UDP relay with one outgoing socket per client.
doc.UdpServer.sock = The UDP socket clients send to.
doc.UdpServer.method = The cipher method.
doc.UdpServer.key = The master key.
doc.UdpServer.rbuf = The receive buffer.
doc.UdpServer.assoc = The outgoing socket of each client, keyed by the client address.
doc.UdpServer.seen = When each client was last heard from, in milliseconds.
doc.UdpServer.clients = The address each client sends from, for the replies.
doc.UdpServer.stopc = The flag that stops <code>UdpServe</code>.
doc.UdpServer.ok = True when the relay started.
doc.PackUdp = Builds one UDP datagram: a random salt, then the target and the payload sealed together. Appends it to the buffer. Returns false for a 2022 method or a bad target.
doc.UnpackUdp = Opens a datagram, fills the target and appends the payload to the buffer. Returns false when authentication fails, the packet is short or the method is a 2022 method.
doc.UdpDial = Makes a UDP client for the server and the method in the <code>Config</code>. <code>ok</code> is false for a 2022 method or a bad password.
doc.UdpSend = Sends a payload to a target through the relay. Returns true when the datagram was sent.
doc.UdpRecv = Waits for one reply, opens it and copies the payload to the buffer (up to <code>max</code> bytes), filling <code>from</code> with the sender. Returns the length, or a negative number on timeout or on a packet that does not authenticate.
doc.UdpSetTimeout = How many milliseconds <code>UdpRecv</code> waits at most.
doc.UdpClose = Closes the client and frees its buffers.
doc.UdpListen = Starts a UDP relay on a port with a classic method and a password. <code>ok</code> is false for a 2022 method, a bad password or a port that is taken.
doc.UdpServerPort = The port the relay listens on.
doc.UdpStep = Handles at most one waiting datagram, forwards it, hands pending replies back to their clients and drops idle clients. Returns 1 when a datagram was handled, else 0. It waits about 20 ms for a packet.
doc.UdpServe = Calls <code>UdpStep</code> in a loop until <code>UdpStop</code>. Run it on its own thread.
doc.UdpStop = Asks <code>UdpServe</code> to return.
doc.UdpDestroy = Closes the relay, its sockets and its key.
doc.Config = How to reach a Shadowsocks server: its address, the cipher, the password and the optional disguise. Pass it to <code>Dial</code>, <code>DialOver</code> or <code>UdpDial</code>.
doc.Config.host = The server host name or address. Not used by <code>DialOver</code>.
doc.Config.port = The server port. Not used by <code>DialOver</code>.
doc.Config.method = The cipher method name. The default is <code>aes-256-gcm</code>; prefer <code>chacha20-ietf-poly1305</code>.
doc.Config.password = The password; for a 2022 method the base64 of the key.
doc.Config.obfs = <code>http</code>, <code>tls</code> or empty for no <code>simple-obfs</code>.
doc.Config.obfs_host = The host name the disguise shows. The default is <code>www.bing.com</code>.
doc.ConnState = Everything one connection needs: the socket or underlying stream, both ciphers, the buffers and the handshake progress. You only hold a pointer to it inside a <code>Conn</code>.
doc.ConnState.sock = The TCP socket, when the connection does not run over a stream.
doc.ConnState.method = The cipher method.
doc.ConnState.key = The master key.
doc.ConnState.enc = The encoder for the data that is sent.
doc.ConnState.dec = The decoder for the data that is received.
doc.ConnState.plain = Decrypted bytes that were not read yet.
doc.ConnState.plain_pos = How much of <code>plain</code> was read.
doc.ConnState.out = A scratch buffer for the bytes about to be sent.
doc.ConnState.rd = The receive buffer.
doc.ConnState.pending = The address header held back until the first write.
doc.ConnState.target = The destination of the connection: asked for by the client, or read by the server.
doc.ConnState.obfs = The disguise layer.
doc.ConnState.up = The underlying stream, when <code>use_up</code> is true.
doc.ConnState.use_up = True when the connection runs over a stream and not a socket.
doc.ConnState.obuf = A scratch buffer for disguised output.
doc.ConnState.oin = Raw bytes received before the disguise was removed.
doc.ConnState.rd2 = The raw receive buffer.
doc.ConnState.v2022 = True for a 2022 method.
doc.ConnState.is_server = True on the server side.
doc.ConnState.wphase = The write side handshake step.
doc.ConnState.rphase = The read side handshake step.
doc.ConnState.first_len = The length announced by the first 2022 header.
doc.ConnState.target_ok = True once the target was received.
doc.ConnState.vtmp = A scratch buffer for the 2022 header.
doc.ConnState.live = True while the connection is open.
doc.Conn = One Shadowsocks connection, as a client or on a server. It holds a pointer to its <code>ConnState</code>; with a null pointer the connection is not usable.
doc.Conn.st = The state of the connection, or null when it could not be made.
doc.Ok = Tells whether a connection was made. After <code>Dial</code> it only means the setup and the TCP connect worked, not that the server accepted the password.
doc.TargetOf = The destination of a connection: on a server, the host and port the client asked for.
doc.Write = Encrypts and sends bytes. Returns the number sent, or -1 on failure. On a new client connection the first write carries the target address too.
doc.WriteStr = Sends a string. Same as <code>Write</code> with its length.
doc.Read = Waits for data and copies up to <code>max</code> bytes to the buffer. Returns the length, 0 when the other side closed, or a negative number on error or a failed authentication.
doc.ReadStr = Reads up to <code>max</code> bytes as a string, empty at the end or on error. Binary data can contain zero bytes that cut a string short, so use <code>Read</code> for that.
doc.Close = Closes the connection and frees its state. Using the <code>Conn</code> afterwards is an error.
doc.Shutdown = Shuts the connection down without freeing it, which wakes a thread that is blocked reading.
doc.Dial = Connects to a Shadowsocks server and asks it to reach a target host and port. The host may be a name; the server resolves it. Returns at once, with the target sent along with the first write.
doc.DialOver = Like <code>Dial</code> but runs over a stream you give it instead of opening a TCP connection. <code>host</code> and <code>port</code> of the config are ignored.
doc.AsStream = Wraps a connection as a <code>tunnel.Stream</code>, so any code that takes a stream can use it.
doc.Blake3Hash = The BLAKE3 hash of bytes, written as <code>outlen</code> bytes to <code>out</code> (32 is the usual length).
doc.Blake3KeyedHash = The keyed BLAKE3 hash, for a 32 byte key.
doc.Blake3DeriveKey = BLAKE3 key derivation with a context string.
doc.Blake3SessionKey = The Shadowsocks 2022 session key: derived from the pre shared key and the salt.
doc.MAX_CHUNK = The largest payload of one chunk in a classic stream, 16383 bytes.
doc.TAG_LEN = The length of the AEAD authentication tag, 16 bytes.
doc.Method = A cipher method: its name, key and salt sizes, and whether it is a 2022 method.
doc.Method.name = The method name, with aliases resolved.
doc.Method.kind = The AEAD kind, as <code>net.tls</code> names it.
doc.Method.key_len = The key length in bytes, 16 or 32.
doc.Method.salt_len = The salt length in bytes, 16 or 32.
doc.Method.v2022 = True for the 2022 methods.
doc.Method.ok = True when the name was a known method.
doc.LookupMethod = Finds a method by name. The result has <code>ok</code> false for an unknown name.
doc.BytesToKey = The classic password to key function (repeated MD5), writing <code>klen</code> bytes to <code>out</code>.
doc.HkdfSha1 = HKDF with SHA-1: derives <code>olen</code> bytes from a key, a salt and an info string. The classic session key uses it.
doc.SessionSubkey = The classic session key for a master key and a salt (HKDF with the info <code>ss-subkey</code>).
doc.RandomSalt = Fills <code>out</code> with a random salt of the length of the method.
doc.PasswordKey = The master key of a classic method from a password, as a new <code>Buf</code>.
