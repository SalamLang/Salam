pkg.intro <<
<p>This package turns styled text into lines of positioned glyphs and draws those glyphs as coverage masks. It is the text half of the native UI runtime: the page language uses it to lay out every heading, paragraph and input, and a painter blends its masks into pixels. It is written in Salam with no outside library, and Persian and mixed Persian and English text are the main case it is built for.</p>
<p>The steps are the ones a browser takes. A <code>FontCollection</code> holds fonts, picks a face for every character from a family list like CSS <code>font-family</code> and falls back per script to other faces, the system fonts included. <code>NewParagraph</code> splits styled spans into bidi, script and font runs and shapes each run once with the font's OpenType tables: joining forms, ligatures, kerning and mark positioning. <code>LayoutParagraph</code> breaks lines at any width without shaping again, reorders each line for right to left text and aligns it. <code>RasterizeGlyph</code> and <code>GlyphCache</code> give 8 bit masks, and <code>HitTest</code>, <code>CaretRect</code> and <code>SelectionRects</code> give the geometry an editor needs.</p>
<h3>Things to know</h3>
<ul>
<li>TrueType outlines only. Fonts with CFF outlines (most <code>.otf</code> files) are skipped by the collection and refused by <code>LoadFont</code>.</li>
<li>Offsets are UTF-8 byte offsets into <code>Paragraph.text</code>, the span texts joined together. <code>SpanAt</code> maps an offset back to its span, and every glyph run carries the <code>tag</code> of its span.</li>
<li>Layout math is fixed point in 1/64 pixel and masks are made with integer math, so the numbers and the pixels are the same on every OS and backend.</li>
<li>When a font has no Arabic joining features the shaper uses the Unicode presentation forms instead, like <code>std/ai/image</code> always did; that package now uses this one for its fonts.</li>
<li>A mask from <code>CachedGlyph</code> belongs to the cache and stays valid until a later call may evict it; draw it before asking for more.</li>
<li>The examples read fonts from the <code>books/fonts</code> folder of the Salam repository.</li>
</ul>

<h2 id="guide-paragraph">Lay out a mixed Persian and English paragraph</h2>
<p>Each span has its own family list and size; the tag lets you find which element a run came from. The paragraph is shaped once, then laid out at two widths. In this right to left paragraph the English word keeps its own left to right order inside the line, and every line is aligned to the right, the start side.</p>
{{example.typeset-guide-paragraph}}
<p><code>MinContentWidth</code> and <code>MaxContentWidth</code> are what a flex or table layout needs before it decides the width. Changing only the width calls <code>LayoutParagraph</code> again; the fonts and the shaping stay cached in the paragraph.</p>

<h2 id="guide-caret">Caret and selection in a text input</h2>
<p>An input keeps a <code>TextPosition</code>: a byte offset and whether it sticks to the text before it. <code>HitTest</code> turns a click into a position, <code>MoveVisual</code> moves it as the arrow keys do on screen, and <code>CaretRect</code> says where to draw it. On a line that mixes directions the caret walks through the English letters from right to left of the screen, the way the eye follows them.</p>
{{example.typeset-guide-caret}}
<p>The selection of a range that crosses a direction change can need more than one rectangle; here it stays one because the selected pieces sit next to each other on screen. <code>NextGrapheme</code> and <code>NextWordEnd</code> give the logical moves for Backspace, Delete and Ctrl with an arrow key.</p>
>>
