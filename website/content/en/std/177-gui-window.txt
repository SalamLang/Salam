pkg.intro <<
<p><code>gui.window</code> opens real windows and shows pixels you draw yourself. It is the bottom layer of Salam's native user interface: the program renders a frame into memory (for example with <code>gui.paint</code>), and this package puts it on the screen and reports what the user does. It talks to the system directly: X11 on Linux, Win32 on Windows and Cocoa on macOS, with no GTK, no web view and no other library. A headless backend keeps windows in memory, so the same program can be tested on any machine.</p>
<p>A frame is a buffer of 32-bit pixels, premultiplied alpha, with the value <code>0xAARRGGBB</code> (bytes B, G, R, A in memory), described by a pointer, a width, a height and a stride. Sizes and positions in the API are logical pixels; the buffer is in physical pixels, which is the logical size times <code>ScaleFactor</code>.</p>
<ul>
<li>Events are pulled, not pushed: call <code>Wait</code> in a loop. This is what macOS needs, since its windows only work on the main thread.</li>
<li>Closing is a request. The close button sends <code>CloseRequested</code>, and the window stays until you call <code>Close</code>.</li>
<li>Redraw requests merge. Call <code>RequestRedraw</code> as often as you like; one <code>RedrawRequested</code> arrives.</li>
<li>Keys and text are separate. <code>KeyDown</code> names the key by its position, the same on every keyboard language; the characters come in <code>TextInput</code> and, from an input method, in <code>ImePreedit</code> and <code>ImeCommit</code>.</li>
</ul>
<div class="note"><p>The text of an event belongs to the package and is freed at the next <code>Wait</code> or <code>Poll</code>. Clone it with <code>str.Clone</code> if you keep it.</p></div>

<h2 id="guide-loop">The event loop</h2>
<p>A window program opens a window, then waits for events until it closes. <code>RedrawRequested</code> asks for a frame: allocate a buffer of the physical size, fill it and give it to <code>PresentAll</code>. A repeating timer drives anything that changes over time. This example is headless and uses the test clock, so it runs anywhere and prints the same lines every time; drop <code>headless</code> and <code>SetManualClock</code> and the same loop drives a real window.</p>
{{example.gui-window-guide-loop}}

<h2 id="guide-input">Mouse, keys and text</h2>
<p>Pointer events carry logical coordinates and the button. <code>clicks</code> counts a double or triple click: presses of the same button close together in time and place. A key event names the key with <code>Key</code>, by position, and the system's own key code in <code>code</code>. Text never comes from key events: insert the text of <code>TextInput</code> and <code>ImeCommit</code>, and draw <code>ImePreedit</code> as the composition underline. <code>SetImeRect</code> places the input method's candidate window at your caret.</p>
{{example.gui-window-guide-input}}

<h2 id="guide-hidpi">Scale factor and partial updates</h2>
<p>On a high density screen one logical pixel is several device pixels. Draw in physical pixels and use <code>ScaleFactor</code> to convert. Moving a window to another screen sends <code>ScaleChanged</code> and then <code>Resized</code>. When only part of the frame changed, pass the changed rectangles to <code>Present</code>; it copies those alone and clips them to the buffer.</p>
{{example.gui-window-guide-hidpi}}

<h2 id="guide-testing">Testing without a screen</h2>
<p>A headless window behaves like a real one: it gets focus, redraw requests, resize events and timers, and keeps every presented frame. <code>PixelAt</code> reads the frame back, <code>Inject</code> plays any event, and <code>SetManualClock</code> makes time jump straight to the next timer, so a test of a one second animation takes no time. The environment variable <code>SALAM_WINDOW_BACKEND=headless</code> makes every window headless without changing the program.</p>
{{example.gui-window-guide-testing}}
