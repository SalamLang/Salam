pkg.intro <<
<p>This package computes where every box of a user interface goes, using the rules of CSS, so that a page drawn natively has the same geometry as the same page in a browser. You build a <code>Tree</code> of boxes, give each one a <code>Style</code> (display, size, margins, padding, border, flex properties and so on), and call <code>Compute</code> with the size of the window. <code>Layout</code> then gives each box its position, size, content box and scrollable area. The package draws nothing and knows nothing about fonts: text and images are leaves whose size comes from a measure callback you supply.</p>
<p>Block flow follows CSS 2 with margin collapsing between siblings, between a parent and its first or last child, and through empty boxes. Flexbox follows the CSS flexbox specification: flex base sizes, the grow and shrink loop with freezing, wrapping, every justify and align value, auto margins, baselines, reverse directions, <code>order</code> and right to left rows. Absolute and fixed boxes are placed against their containing block, including their static position when insets are auto. Floats, inline text flow and writing modes other than horizontal are not done.</p>
<p>Grid follows CSS Grid Level 1: track lists with pixels, percentages, <code>fr</code>, <code>auto</code>, <code>min-content</code>, <code>max-content</code>, <code>fit-content()</code>, <code>minmax()</code> and <code>repeat()</code> including <code>auto-fill</code> and <code>auto-fit</code>, named lines, <code>grid-template-areas</code>, implicit tracks from <code>grid-auto-rows</code> and <code>grid-auto-columns</code>, sparse and dense auto placement in either direction, spans and negative lines, the full track sizing algorithm, every <code>justify</code> and <code>align</code> value for items and content, baselines, and absolutely positioned items placed in their grid area. Subgrid is not done. Grid properties are strings in CSS syntax, such as <code>grid_template_columns = "repeat(3, 1fr)"</code>; the tree keeps its own copy, and <code>IsTrackList</code> and the other checks tell whether a value is valid.</p>
<p>Tables follow the CSS 2.1 table model the way Chrome lays it out: rows, row groups, header and footer groups (moved to the top and bottom), columns and column groups, captions on either side, anonymous rows and cells around misplaced children, <code>col_span</code> and <code>row_span</code>, automatic column widths from each cell's minimum and maximum content width (with percentage and fixed cells), fixed table layout, <code>border-spacing</code>, collapsed borders, extra height given to rows, and <code>vertical-align</code> in cells.</p>
<p>The block, flex and grid algorithms are ports of <a href="https://github.com/DioxusLabs/taffy">Taffy</a>, and the package is tested against 1,527 of Taffy's fixtures measured in Chrome (616 of them with grid), in both box sizing models and both directions. Tables were written from the specification and checked against 53 cases measured in headless Chrome.</p>
<h3>Things to know</h3>
<ul>
<li>Lengths are already resolved: give pixels or percentages. Convert em, rem, vw and vh before building the style.</li>
<li>Defaults are the CSS initial values: <code>display</code> is block, <code>position</code> is static and <code>box_sizing</code> is content-box.</li>
<li>Ids are plain integers in the order of <code>AddNode</code>; the node you pass to <code>Compute</code> is the root.</li>
<li>Results are rounded to whole pixels the way Chrome rounds them. Turn this off with <code>SetRounding(false)</code> to read fractions.</li>
<li>Each node caches its last results. After a style change only the changed node and its ancestors are laid out again; call <code>MarkDirty</code> when the content behind a measure callback changes.</li>
</ul>

<h2 id="guide-flex">A toolbar with flexbox and text</h2>
<p>A row with a growing title, a button and a badge moved first with <code>order</code>. The measure callback stands in for text: it answers how wide the text is with unlimited room, how narrow it can get, and how tall it is at a given width. Switching the direction to right to left mirrors the row.</p>
{{example.gui-cssbox-guide-flex}}

<h2 id="guide-block">Block flow and absolute positioning</h2>
<p>The header's bottom margin and the card's top margin collapse into one 30 pixel gap, the card is centred with auto margins, and the close button is placed in the corner of the page, which is its containing block because it is positioned. A box with <code>display</code> none takes no space.</p>
{{example.gui-cssbox-guide-block}}

<h2 id="guide-incremental">Changing one box</h2>
<p>The counters show the cache at work: a second <code>Compute</code> with nothing changed computes nothing, and changing one leaf recomputes that leaf and its ancestors. Laying out a 5,000 box page (50 wrapping flex rows of 100 text leaves) takes about 15 ms the first time on one desktop core, and about 0.7 ms after one leaf changes; most of that is rounding the whole tree.</p>
{{example.gui-cssbox-guide-incremental}}

<h2 id="guide-grid">A page grid with named areas</h2>
<p>A header, sidebar, main area and footer are placed by area name; the main box is centred in its cell with <code>justify_self</code>. The second grid fills a 250 pixel row with as many 70 pixel columns as fit, then stretches them, and the fourth tile wraps to the next row. A 20 by 50 grid of measured text cells lays out in about 1 to 3.5 ms the first time and about 0.8 to 3.3 ms after one cell changes, on one desktop core.</p>
{{example.gui-cssbox-guide-grid}}

<h2 id="guide-table">A table with spans and a caption</h2>
<p>Column widths come from the cells' content. The first cell spans two rows and is centred vertically, the last spans two columns, and the caption sits below. The table then switches to a fixed 300 pixel layout with collapsed borders: the four columns share the width equally and each cell keeps half of every shared border. A table of 200 rows and 5 measured columns takes about 0.7 to 1 ms the first time and about 0.4 to 0.5 ms after one cell changes.</p>
{{example.gui-cssbox-guide-table}}
