pkg.intro <<
<p>When data arrives from a CSV file, a form, an environment variable or the command line, everything is text. The <code>types</code> package says what kind of value a piece of text looks like, so you can decide before you convert it. It does not convert anything: once a check passes, <a href="/std/conv/">conv</a> does the parsing. For whole documents with their own typing rules use <a href="/std/encoding/json/">encoding/json</a> or <a href="/std/encoding/csv/">encoding/csv</a>.</p>
<p>The checks trim spaces first and turn Persian and Arabic digits into English ones, so <code> ۳۴ </code> is a whole number. A kind is one of five <code>int</code> constants: null (empty text), bool, int, float and string. <code>KindOf</code> tries them in that order, so <code>true</code> is a bool and <code>12</code> is an int, never a float.</p>
<p>What people get wrong:</p>
<ul>
<li>Thinking a check means the value fits. <code>IsInt</code> looks only at the characters, so a 20-digit number passes and then overflows in <code>conv.ParseInt</code>.</li>
<li>Expecting <code>yes</code>, <code>1</code> or <code>on</code> to be a bool. Only <code>true</code> and <code>false</code> count, in any letter case.</li>
<li>Expecting blank text to be null. Only text of length zero is <code>TypeKindNull</code>; three spaces are a string.</li>
</ul>

<h2 id="guide-form">Check form input before converting it</h2>
<p>A form field is text, and <code>conv.ParseInt</code> on bad text gives a wrong number without telling you: <code>12abc</code> becomes 12 and <code>abc</code> becomes 0. Ask first: <code>IsInt</code>, <code>IsNumeric</code> and <code>IsBool</code> say whether the conversion makes sense, so you can show the user a clear message instead. Persian digits pass the checks, but the converters in <a href="/std/conv/">conv</a> expect English digits, so run <code>str.ToEnglishDigits</code> first. The Persian decimal separator <code>٫</code> is accepted by <code>IsNumeric</code> and is not changed by <code>ToEnglishDigits</code>, so replace it with a dot yourself.</p>
{{example.types-guide-form}}
<p>The checks are strict about the characters: <code>12.0</code> is a decimal, not a whole number, and <code>Yes</code> is not a bool. Spaces around a value are ignored by the checks, and <code>conv.ParseInt</code> ignores them too, but trim the text yourself before you store it.</p>

<h2 id="guide-config">Branch on the kind of a value</h2>
<p><code>KindOf</code> returns one of the five <code>TypeKind</code> constants, which suits a <code>switch</code>. Empty text has its own kind, <code>TypeKindNull</code>, so a missing value can fall back to a default rather than being treated as text. Scientific notation such as <code>1e3</code> counts as a decimal.</p>
{{example.types-guide-config}}

<h2 id="guide-columns">Guess the type of CSV columns</h2>
<p>Before you import a CSV file into a database you need a type for each column. Look at every cell and widen the guess as you go: whole numbers and decimals together make a decimal column, any text makes a text column, and empty cells do not change the guess. <code>KindName</code> turns the result into a name for a report or a <code>CREATE TABLE</code> statement.</p>
{{example.types-guide-columns}}

<h2 id="guide-equal">Compare two vectors</h2>
<p>Two vectors cannot be compared with <code>==</code>; the compiler rejects it (E021). <code>Equal</code> compares them: the same length, and equal elements in the same order. It is generic, so it works for <code>Vector&lt;int&gt;</code>, <code>Vector&lt;str&gt;</code> and the other element types that support <code>==</code>, and it is handy in small tests.</p>
{{example.types-guide-equal}}

<h2 id="guide-limits">What the checks do not catch</h2>
<p>A check answers "does this look like a number", not "is this a valid value for my field". A port, an age or a quantity needs a range check of its own after the kind check, and a length check before parsing guards against numbers too large for an <code>int</code>. Convert the digits first, because a Persian digit takes two bytes and would double the length. The function below turns a port setting into a number, with a default for an empty value and -1 for anything invalid.</p>
{{example.types-guide-limits}}
<p><code>1e</code> passes <code>IsFloat</code> because the check allows an exponent with no digits after it; <code>conv.ParseFloat</code> then reads it as 1. If that matters for your data, reject text that ends in <code>e</code> or <code>E</code>.</p>

doc.TypeKindNull = The kind of empty text, 0. Text of only spaces is <code>TypeKindStr</code>, not this.
doc.TypeKindBool = The kind of a boolean, <code>true</code> or <code>false</code>; 1.
doc.TypeKindInt = The kind of a whole number; 2.
doc.TypeKindFloat = The kind of a decimal number; 3.
doc.TypeKindStr = Any other text; 4.
doc.IsInt = True when the text, after trimming spaces, is a whole number: an optional <code>+</code> or <code>-</code> and digits. Persian and Arabic digits are accepted. It does not check the size, so a number too large for <code>int</code> still passes.
doc.IsFloat = True when the text is a decimal number: digits with one <code>.</code> or Persian <code>٫</code> (<code>.5</code> and <code>5.</code> both count), or scientific notation such as <code>2e5</code>. A whole number does not count here. It also accepts a bare trailing exponent such as <code>1e</code>.
doc.IsNumeric = True when the text is a whole or a decimal number: <code>IsInt</code> or <code>IsFloat</code>. <code>inf</code> and <code>nan</code> are not numbers here.
doc.IsBool = True when the trimmed text is <code>true</code> or <code>false</code>, in any letter case. <code>yes</code>, <code>1</code> and Persian words are not accepted.
doc.KindOf = Returns the kind of the text as one of the constants above, testing null, bool, int and float in that order.
doc.KindName = Returns the English name of a kind: <code>null</code>, <code>bool</code>, <code>int</code>, <code>float</code> or <code>string</code>. Any other number also gives <code>string</code>.
doc.Equal = True when two vectors have the same length and equal elements in the same order. It is generic and needs an element type that supports <code>==</code>.
