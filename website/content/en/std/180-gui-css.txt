pkg.intro <<
<p>This package is the style engine of the native UI runtime. For each element of a page it takes what the web generator writes for it today (its own declarations, the extra ones for hover, focus and active, its element key, classes and id) together with the page's <code>global</code> and <code>media</code> rules, and computes the final value of every property exactly as a browser would. The native window then looks like the web page.</p>
<p>A <code>Sheet</code> starts with the user agent style sheet, the browser defaults that give a heading its size and a paragraph its margins, written after Chromium's own and compared with Chromium property by property. You add rules with <code>AddRule</code>, <code>AddMediaRule</code> or a whole style sheet with <code>AddCss</code>, describe the elements as a vector of <code>Element</code> in document order, and call <code>Compute</code>. <code>Style</code> then gives each element a <code>ComputedStyle</code>: lengths in pixels (percentages stay relative until layout), colours as straight RGBA, keywords as enums, and lists for backgrounds, shadows, transforms and transitions. <code>ToBox</code> turns it into a <code>gui.cssbox</code> style for layout.</p>
<p>Supported: type, class, id and attribute selectors, descendant, child and sibling combinators, <code>:hover</code>, <code>:focus</code>, <code>:focus-visible</code>, <code>:active</code>, the child and type position pseudo-classes, <code>:not()</code>, <code>:is()</code> and <code>:where()</code>; specificity and <code>!important</code>; inheritance with <code>inherit</code>, <code>initial</code> and <code>unset</code>; media queries on size, orientation, colour scheme, reduced motion, hover and pointer; every length unit, <code>calc()</code>, <code>min()</code>, <code>max()</code> and <code>clamp()</code>; colours in every common syntax; gradients, shadows, transforms, transitions, fonts, logical properties for right to left pages, and <code>var()</code> with fallbacks. Grid and table properties are parsed, cascaded and checked: track lists, areas, placements and their shorthands (<code>grid</code>, <code>grid-template</code>, <code>grid-area</code>, <code>grid-row</code>, <code>grid-column</code>), <code>border-collapse</code>, <code>border-spacing</code>, <code>table-layout</code> and <code>caption-side</code>; <code>ToBox</code> hands them to the layout engine. Pseudo-elements, subgrid, animations and container queries are not done.</p>
<h3>Things to know</h3>
<ul>
<li>An element's own declarations act like a class rule written after the global rules, which is what the web generator emits. Its hover, focus and active declarations act like the same class with that pseudo-class.</li>
<li>Elements must come in document order, each after its parent. The page itself has parent -1; an implicit <code>html</code> root above it matches <code>:root</code>.</li>
<li>Elements with the same inputs share one computed style. Each distinct declaration string is parsed once.</li>
<li>After a pointer move, call <code>HoverChain</code> and pass its result to <code>Restyle</code>: only the elements whose state changed, and their descendants when an inherited value changed, are computed again.</li>
<li>Strings returned by the text helpers belong to the caller. The vectors inside a <code>ComputedStyle</code> belong to the sheet.</li>
<li><code>border-image</code> and its longhands, gradient colour hints and <code>calc()</code> stop positions are supported. Gradient stops are resolved when painting with <code>GradientStops</code>, which expands hints and non-sRGB segments in the interpolation colour space the way Chromium does. Colour transitions between non-legacy colours mix in Oklab.</li>
<li>Values are applied by keyword id, not by comparing strings, and the cascade passes its large structures by reference: computing all styles of a 202-element page shaped like <code>tools/bench/gui_ui.salam</code> went from about 282 us to about 113 us (minimum of 500 runs, one core, C backend).</li>
</ul>

<h2 id="guide-page">Styling a page</h2>
<p>A card with a heading and a paragraph. The global rule sets the heading's margins, the user agent sheet gives it its size and weight, and the card's own declarations are converted to a layout style and placed with <code>gui.cssbox</code>.</p>
{{example.gui-css-guide-page}}

<h2 id="guide-states">Hover, pressed and media</h2>
<p>The button's hover background applies once the pointer is over it, and only the elements on the hover path are computed again. A <code>media</code> condition changes the navigation into a column when the window is narrow. Computing styles for 5,000 elements with 11 distinct styles takes about 10 ms on one desktop core; a hover change restyles four elements in about 0.1 ms. With 5,000 different styles it takes about 100 ms the first time and about 50 ms once the declarations are parsed.</p>
{{example.gui-css-guide-states}}
<h2 id="guide-program">Compiled style programs</h2>
<p>A page built with <code>--ui=native</code> does not parse CSS when it runs. At compile time the compiler fills a <code>Program</code> with <code>CompileDecls</code> (one id per distinct declaration list), <code>CompileRule</code> and <code>CompileCss</code>: shorthands are expanded, values are tokenized and validated, selectors and media conditions are compiled, and anything invalid is reported through <code>ProgramErrors</code>. <code>ProgramSource</code> then writes a Salam function that rebuilds the same program from literals, one call per declaration, and the program turns it into a sheet with <code>SheetFromProgram</code>. Elements point at declaration lists through <code>decl_base</code>, <code>decl_hover</code>, <code>decl_focus</code> and <code>decl_active</code>, so computing styles never touches CSS text. Only a style value that is a runtime expression goes through <code>DynDecl</code>, which parses that one value once and caches it. The user agent sheet is itself a generated program, so <code>NewSheet</code> no longer parses CSS either.</p>
{{example.gui-css-guide-program}}

<h2 id="guide-typed">Typed values and colours</h2>
<p>The program that <code>ProgramSource</code> writes carries values decided at compile time. A declaration is <code>AddTyped</code> with the integer property id from <code>PropertyId</code>; keywords, units and function names are indexes into one name table (<code>KeywordId</code>); lengths keep their number and unit, with absolute units already in pixels and angles in degrees; a <code>calc()</code> that needs nothing from the page is folded to one value; and every colour that does not depend on <code>currentColor</code> is resolved to straight RGBA for the light and the dark scheme. Loading such a program compares no strings and parses nothing.</p>
<p>Colours follow CSS Color 4 and 5: hex, the 148 named colours, <code>transparent</code>, <code>currentColor</code>, <code>rgb()</code>, <code>hsl()</code> and <code>hwb()</code> in the modern and the comma syntax, <code>lab()</code>, <code>lch()</code>, <code>oklab()</code>, <code>oklch()</code>, <code>color()</code> in srgb, srgb-linear, display-p3, a98-rgb, prophoto-rgb, rec2020, xyz, xyz-d50 and xyz-d65, <code>color-mix()</code> in any of those spaces with the four hue interpolation methods, relative colours such as <code>rgb(from red r g calc(b * 2))</code>, <code>light-dark()</code> and the system colours with Chromium's values for each scheme. Every colour inside sRGB matches Chromium; colours outside it are gamut mapped with the CSS Color 4 algorithm, where Chromium clips. Gradients interpolate in the space given with <code>in</code>, and in Oklab when a stop uses one of the newer syntaxes. When the operating system switches between light and dark, <code>SetColorScheme</code> restyles only the elements that depend on the scheme.</p>
{{example.gui-css-guide-typed}}
