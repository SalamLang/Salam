pkg.intro <<
<p>This package runs a page as a native desktop window that Salam draws itself. The compiler turns a <code>page:</code> into the same HTML document it writes for the web, with the page's CSS in a <code>&lt;style&gt;</code> element and event attributes such as <code>onclick="add()"</code> that name Salam functions. <code>gui.ui</code> is a small browser engine for exactly that output: it parses the document, computes styles with <code>gui.css</code> (the user agent style sheet, hover, focus, active and media rules), lays boxes out with <code>gui.cssbox</code> (block, flex and absolute positioning), breaks and shapes text with <code>gui.typeset</code> (inline elements, bidi, Persian shaping, list markers), paints with <code>gui.paint</code> and shows the result with <code>gui.window</code>.</p>
<p>A program registers its handlers with <code>Handle</code> and calls <code>Run</code> with a function that returns the page. After every handler the view function runs again (a compiled page re-runs only the parts whose state changed, see below); the new document is matched against the old one by position, tag, <code>id</code> and <code>key</code>, so hover, focus, scroll offsets, the caret and the values typed into inputs survive, and only the parts of the window that changed are painted again. <code>RunHtml</code> shows a fixed document. <code>Render</code> draws a page without a window, for tests and screenshots.</p>
<p>Form controls are drawn by the runtime and follow the page's CSS: buttons, text, password, number, email and search inputs with a caret, selection, clipboard and undo, checkboxes, radio groups, ranges, text areas, selects with a popup list, progress, meter, details with summary, and labels that focus or toggle their control. Links to <code>http</code> and <code>https</code> addresses open in the user's browser; a relative link opens another page registered with <code>Page</code>.</p>
<h3>Things to know</h3>
<ul>
<li>Changes made through <code>ById</code> (text, classes, attributes) last until the next time the view runs; the view is the source of truth. Values typed into inputs are kept until the view writes a different <code>value</code> attribute.</li>
<li>Fonts come from the system font folders unless the program adds its own with <code>AddFontFile</code> or <code>AddFontDir</code> before the first page is shown, which also makes the output the same on every machine.</li>
<li>With <code>SALAM_WINDOW_BACKEND=headless</code> the window is drawn in memory. If <code>SALAM_UI_SCRIPT</code> then names a text file, <code>Run</code> follows its steps, one per line, and returns at <code>quit</code> or at the end: <code>click SELECTOR</code>, <code>dblclick SELECTOR</code>, <code>hover SELECTOR</code>, <code>press SELECTOR</code>, <code>release SELECTOR</code>, <code>move X Y</code>, <code>key NAME</code> (such as <code>Tab</code>, <code>Enter</code>, <code>ctrl+a</code>, <code>shift+Tab</code>), <code>type TEXT</code>, <code>ime TEXT</code> and <code>commit TEXT</code> (input method composition), <code>drag X1 Y1 X2 Y2</code>, <code>tripleclick SELECTOR</code>, <code>sel</code> (prints the selection, caret and text scroll of the focused control), <code>scroll SELECTOR DY</code>, <code>resize W H</code>, <code>wait MS</code>, <code>dump</code> (prints each element's tag, id, text and border box), <code>hash</code>, <code>focus</code>, <code>shot FILE.png</code> and <code>quit</code>. Selectors are CSS selectors; lines starting with <code>#</code> or <code>//</code> are skipped. Without a script a headless <code>Run</code> draws once and returns.</li>
<li>CSS <code>transform</code>, <code>transform-origin</code>, <code>translate</code>, <code>rotate</code> and <code>scale</code> apply to painting, hit testing and repainting, and transitions of <code>transform</code> run on the animation clock. <code>filter</code>, <code>backdrop-filter</code>, <code>text-shadow</code>, <code>outline-offset</code> and dashed or dotted rounded borders are drawn as in a browser.</li>
<li>Text inputs and text areas show the input method composition underlined at the caret, keep the caret in view by scrolling (a text area scrolls with the wheel too, and sideways with <code>wrap="off"</code>), move the caret visually in mixed Persian and English text, and select with the mouse, Shift with the arrow keys, a double click (a word) and a triple click (a line).</li>
<li>Long lists are cheap to scroll: scrolling only moves boxes, painting and repainting skip everything outside the visible area, and elements that stay off screen are not compared. A list of 10,000 rows is still laid out in full once.</li>
<li>CSS grid and tables are laid out by <code>gui.cssbox</code> the way Chrome lays them out: track sizing, named areas and auto placement for grid; column widths from content, <code>colspan</code> and <code>rowspan</code>, captions, header and footer groups, <code>border-spacing</code>, collapsed borders and <code>vertical-align</code> in cells for tables. In a page, <code>table</code>, <code>header</code>, <code>main</code>, <code>footer</code>, <code>row</code>, <code>column</code> (or <code>cell</code>) and <code>caption</code> build the same table as the HTML output.</li>
<li>The layout tree is kept between view re-runs and restyles: each element keeps its layout box, only boxes whose style, text, children or content changed are laid out again, and the rest come from the layout cache. A click that changes one label on a 202 element page runs about 60% fewer layout instructions than a full layout.</li>
<li>A scroll container with a fixed height or maximum height and at least 200 block children lays out only the rows near what is visible (one viewport above and below) and stands in for the rest with their measured heights, or the average of the measured rows until they are seen. Scrolling, clicking, focus with the Tab key and keyed <code>each</code> rows work as before; rows outside the window have no box until they scroll in. On a 10,000 row list the first frame takes about 70 to 100 ms instead of about 600 ms, and a scroll frame about 15 to 18 ms instead of about 100 ms.</li>
</ul>

<h2 id="guide-compiled">Compiled pages</h2>
<p>A page built with <code>--ui=native</code> does not go through HTML or CSS text at all. The compiler compiles the page's styles into a <code>gui.css</code> program and writes a view that takes a <code>Builder</code> and creates the elements with direct calls: <code>Open</code> and <code>Close</code> for each element, <code>Decls</code> for the ids of its compiled declaration lists, <code>Text</code>, <code>Id</code>, <code>Class</code>, <code>Attr</code> and <code>On</code> with a Salam closure for each handler. <code>RunCompiled</code> builds the program once and runs the view again after every handler. The new tree goes through the same matching, restyling, layout, paint and events as an HTML view, so the two give the same pixels. Only style values that are runtime expressions are parsed, once each, through <code>Dyn</code>.</p>
<p>For the 200 element page in <code>tools/bench/gui_ui.salam</code> on one desktop core, a view re-run after a click (building the tree, matching, restyling, layout and the partial repaint) takes about 7.2 ms on the compiled path and 7.7 ms on the HTML path; layout and paint are shared and take most of it. Shaped text paragraphs whose text and style did not change are reused across re-runs on both paths.</p>
{{example.gui-ui-guide-compiled}}
<h2 id="guide-reactive">Re-running only what changed</h2>
<p>A compiled page does not run its whole view after a handler. The compiler puts every component instance, and every element, <code>if</code> or <code>each</code> outside a component that reads state, in its own <code>Scope</code>, and works out at compile time which mutable globals each scope reads. It gives each such global a change bit and sets the bit before every statement in the program that may write it (assignments, <code>++</code>, methods such as <code>push</code>, passing it by reference). A write to a component's <code>state</code> marks just that instance. After a handler, timer or animation step the runtime reads the bits: when none is set nothing runs at all; otherwise only the scopes that read a changed global run again, outermost first, and a component instance runs again as a whole. When a scope's elements keep their shape the new text and attributes are copied into the existing elements, only those are restyled, and changed text is reshaped in place, so layout runs only when a size can change.</p>
<p>For a page of 200 elements where one counter changes (<code>tools/bench/gui_ui.salam</code>, on a loaded six-core desktop), a click took 3.4 to 4.0 ms when the whole view ran again and 0.5 to 0.7 ms when only the counter's scope ran. A click whose handler changes nothing took 3.1 to 3.8 ms before and 0.2 to 0.3 ms now; what is left is event dispatch and the pressed-state repaint. Writes the compiler cannot see, such as changes inside another package, need <code>Invalidate</code>.</p>

doc.Handle = Registers a Salam function under a name, so that event attributes such as <code>onclick="name()"</code>, <code>onclick="name(event)"</code> and <code>onclick="window['name']()"</code> run it. Registering the same name again replaces the function.
doc.CurrentEvent = The event being handled, while a handler runs: its kind, the target's id, the pointer position, the button, the key, the text and the value of the target control.
doc.Start = Opens a window for a view function, shows its first frame and returns at once; drive it with <code>Step</code> or <code>RunSteps</code>. Returns false when no window can be opened.
doc.StartHtml = Like <code>Start</code> for a fixed document.
doc.Step = Handles the waiting window events, runs the view again when a handler ran, and paints what changed. Waits up to the given milliseconds for an event when none is waiting. Returns false once the window is closed.
doc.Stop = Closes the window opened by <code>Start</code> or <code>Run</code>.
doc.RunWith = Opens a window for a view function with the given options and runs until the window closes. The view runs again after every handler.
doc.Run = Opens a window for a view function, sized 1024 by 768 and titled from the page's <code>title</code>, and runs until the window closes. This is what the compiler calls for a page.
doc.RunHtmlWith = Shows a fixed document in a window with the given options until the window closes.
doc.RunHtml = Shows a fixed document in a window until the window closes.
doc.Refresh = Asks for the view to run again before the next frame, for changes made outside a handler.
doc.Render = Draws a document without a window into a new canvas of the given size, at one device pixel per CSS pixel. The caller frees the canvas.
doc.RenderScaled = Like <code>Render</code> at a scale factor, for high density screens: the canvas has the size times the scale.
doc.RenderPNG = Renders a document and saves it as a PNG file. Returns false when the file cannot be written.
doc.Dump = A text outline of the current window's page: one line per shown element with its tag, id, own text, control value or state, focus and border box. The caller frees it.
doc.DumpHtml = The same outline for a document rendered without a window.
doc.Measure = Renders a document once without a window and reports how long each phase took.

doc.RepaintAll = Paints the whole window again. Tests use it to check that a partial repaint gave the same pixels.
doc.LastDamageCount = How many damage rectangles the last frame painted; 0 means the whole window.

doc.LastLayoutCalls = How many boxes the last layout computed instead of taking from the cache; after a view re-run that changes one text it counts only that text's box and its ancestors.
doc.Frame = The canvas the window shows. It belongs to the runtime.
doc.FrameCount = How many frames have been painted.
doc.CurrentWindow = The <code>gui.window</code> window that shows the page.
doc.Page = Registers another view for a path, so a link with that relative address opens it in the same window.
doc.SetUrlOpener = Replaces the function that opens <code>http</code>, <code>https</code> and <code>mailto</code> links, for tests or for an app that wants to handle them itself.
doc.SetNavigator = Sets a function that sees every relative link first; when it returns true the link is handled and the registered pages are not searched.
doc.OpenedUrls = Every link address followed so far, in order. It belongs to the runtime.
doc.OpenUrl = Opens an address in the user's browser: <code>xdg-open</code> on Linux, <code>open</code> on macOS and <code>ShellExecuteW</code> on Windows. Nothing is opened when <code>SALAM_UI_NO_BROWSER</code> is set or the address is empty.
doc.AddFontFile = Adds the faces of a font file to the fonts pages use and returns how many were added.
doc.AddFontDir = Adds every font file in a folder and its subfolders and returns how many faces were added.
doc.ById = The element with an id, for handlers that change the page directly.
doc.Options = How a window is opened.

doc.Options.title = A window title to use instead of the page's <code>title</code>.
doc.Options.resizable = Whether the user can resize the window.
doc.Options.background = A CSS colour for the window behind the page, used instead of the page's own.

doc.Options.scale = A device scale factor to use instead of the screen's.
doc.Options.script = Scripted steps that a headless <code>RunWith</code> follows instead of waiting for input.

doc.Element.SetAttr = Sets an attribute, until the view runs again.
doc.Element.Style = The element's computed style.
doc.Element.Rect = The element's border box in logical window pixels.

doc.Builder.Title = Sets the window title, like a page's <code>title</code>.
doc.Builder.Lang = Sets the page language, like <code>lang</code> on <code>html</code>.
doc.Builder.Dir = Sets the page direction, <code>ltr</code> or <code>rtl</code>, like <code>dir</code> on <code>html</code>.
doc.Builder.Open = Opens an element with the HTML tag the web build would use, such as <code>div</code>, <code>h1</code>, <code>button</code> or <code>input</code>, as the last child of the open element. Every <code>Open</code> needs a <code>Close</code>, empty elements included.
doc.Builder.Decls = Gives the open element its compiled declaration lists: its own, and those for hover, focus and active. -1 means none.
doc.Builder.Dyn = Adds a style value known only at runtime, such as a width computed from state. Each distinct value is parsed once and cached.
doc.Builder.Id = Sets the element's id.
doc.Builder.Class = Adds a class to the element.
doc.Builder.Key = Sets the key that keeps an element matched to its old self across re-runs when siblings move.
doc.Builder.Attr = Sets an attribute such as <code>href</code>, <code>type</code>, <code>value</code> or <code>placeholder</code>.
doc.Builder.BoolAttr = Sets a boolean attribute such as <code>checked</code> or <code>disabled</code> when the value is true.
doc.Builder.Text = Adds text to the open element. Text added next to child elements forms one paragraph with them, as in HTML.
doc.Builder.On = Runs a closure when an event of the given name reaches the element: <code>click</code>, <code>dblclick</code>, <code>input</code>, <code>change</code>, <code>submit</code>, <code>keydown</code>, <code>keyup</code>, <code>focus</code>, <code>blur</code> and the others, named like the HTML attribute without <code>on</code>. Events bubble; <code>CurrentEvent</code> describes the event inside the closure.
doc.Builder.Close = Closes the open element.
doc.Builder.Scope = Builds part of the page in a closure that the runtime can run again on its own. <code>site</code> names the place in the view, registered with <code>ScopeSite</code>; the closure receives the builder and is run at once. A compiled page puts every component instance, and every element, <code>if</code> or <code>each</code> that reads state, in a scope.
doc.Builder.Reactive = Turns on partial re-runs for a compiled view: the number of change words, a function that returns and clears one word of change bits, and a function that registers the sites once. The view calls it first. Without it the whole view runs after every handler.
doc.Builder.Instance = Inside a component's scope, the slot of this instance among the live instances of component <code>comp</code>. The slot stays the same when the parent re-runs, so the component's state can be stored per slot.
doc.Builder.Fresh = True while a component instance builds for the first time, when its state should be set from its declarations.
doc.ScopeSite = Registers what a site depends on: the component it belongs to (-1 for none) and a mask of change bits in one word. A site that registers several words is called once per word.
doc.TouchInstance = Marks one component instance as changed, so it alone re-runs after the handler. The compiler writes this after every write to a component's <code>state</code>.
doc.Invalidate = Runs the whole view again after the current handler. Use it when state changed in a way the compiler cannot see: inside another package, through a pointer, or through a second name for the same Vector.
doc.ScopeRuns = How many scopes have run again since the page started; a whole view run counts as one. Tests print it to check that a click re-ran only what it should.
doc.RunCompiled = Opens a window for a compiled page: a function that returns its style program and a view that builds the elements with a <code>Builder</code>. Runs until the window closes. This is what the compiler calls for a page built with <code>--ui=native</code>.
doc.RunCompiledWith = Like <code>RunCompiled</code> with options such as the size, the title or a headless script.
doc.RenderCompiled = Draws a compiled page without a window into a new canvas of the given size. The caller frees the canvas.
