pkg.intro <<
<p><code>gui.color</code> is the colour part of the Salam UI standard. It reads every colour a page may use, in the same syntax in page source, in a string and in a value computed at run time, and it turns a colour into what each target needs: a packed <code>u32</code> for the native renderer and CSS text for the web.</p>
<p>A <code>Color</code> holds sRGB channels from 0 to 1 and an alpha. A colour from a wider gamut, such as <code>color(display p3, 1, 0, 0)</code>, keeps channels below 0 or above 1, so nothing is lost until it is drawn.</p>
<p>What <code>Parse</code> accepts:</p>
<ul>
<li><strong>Names</strong>: all 148 CSS colour names plus <code>transparent</code> and <code>current</code> (the text colour), in any case and with or without spaces (<code>alice blue</code>), and Persian names such as <code>قرمز</code>, <code>آبی</code> and <code>قهوه ای</code>.</li>
<li><strong>Hex</strong>: <code>#rgb</code>, <code>#rgba</code>, <code>#rrggbb</code> and <code>#rrggbbaa</code>.</li>
<li><strong>Functions</strong>: <code>rgb</code>, <code>rgba</code>, <code>hsl</code>, <code>hsla</code>, <code>hwb</code>, <code>lab</code>, <code>lch</code>, <code>oklab</code>, <code>oklch</code>, <code>cmyk</code> (also <code>device cmyk</code>) and <code>color(space, c1, c2, c3)</code> with the spaces <code>srgb</code>, <code>srgb linear</code>, <code>display p3</code>, <code>a98 rgb</code>, <code>prophoto rgb</code>, <code>rec2020</code>, <code>xyz</code>, <code>xyz d50</code> and <code>xyz d65</code>. Values are separated by commas, as in <code>rgb(51, 102, 170)</code>, or by spaces with <code>/</code> before the alpha, as in CSS. The hyphenated CSS spellings (<code>display-p3</code>) work too.</li>
<li><strong><code>mix(a, b, amount, space)</code></strong>: <code>amount</code> is how much of <code>b</code>, as a number from 0 to 1 or a percent, 50% when left out; the space is oklab unless given.</li>
<li><strong><code>light dark(a, b)</code></strong>: a colour with a light and a dark variant.</li>
<li><strong>Numbers</strong>: a percent with <code>%</code> or <code>٪</code>, Persian digits, the Persian comma <code>،</code>, and hue angles as a bare number of degrees or with <code>deg</code>, <code>rad</code>, <code>grad</code> or <code>turn</code>.</li>
</ul>
<p>Things to know:</p>
<ul>
<li><strong>Values are checked, not clamped.</strong> <code>rgb(300, 0, 0)</code> is an error, not red. <code>Error</code> says what was expected and the column where the problem starts, and suggests a name when one is close.</li>
<li><strong><code>Css</code> writes what every current browser draws the same</strong>: <code>#rrggbb</code> or <code>#rrggbbaa</code> inside sRGB, <code>color(display-p3 ...)</code> for a wide gamut colour that fits Display P3, <code>oklch(...)</code> beyond that, <code>currentColor</code> and <code>light-dark(a, b)</code>.</li>
<li><strong><code>Argb</code> clamps each channel to sRGB</strong>, so a wide gamut colour is drawn as its nearest sRGB colour on the native target.</li>
<li><strong><code>cmyk</code> is the plain formula</strong> (red is <code>(1 - c) * (1 - k)</code>), with no printer profile.</li>
<li><strong><code>current</code> cannot be mixed</strong> while parsing, because the text colour is only known when the page is shown.</li>
</ul>

<h2 id="guide-theme">A light and dark palette</h2>
<p>A theme starts from one brand colour. Each role gets a <code>LightDark</code> pair, <code>Lighten</code> and <code>Darken</code> move the lightness in oklch and stay inside sRGB, and <code>Mix</code> works on both variants at once. <code>Contrast</code> then checks every pair against the 4.5 ratio that WCAG asks of body text, in light and in dark mode.</p>
{{example.gui-color-guide-theme}}

<h2 id="guide-input">Checking colours that people type</h2>
<p>A settings screen that takes a colour as text needs to say what is wrong with it. <code>Error</code> returns an empty string for a colour <code>Parse</code> accepts, and otherwise one line with the column and the expected form, so it can be shown under the field as it is.</p>
{{example.gui-color-guide-input}}
>>

doc.Color = A colour: sRGB channels from 0 to 1, an alpha, and an optional dark variant made by <code>light dark</code>. Channels may be below 0 or above 1 for colours outside sRGB.
doc.Color.r = The red channel, 0 to 1 inside sRGB.
doc.Color.g = The green channel, 0 to 1 inside sRGB.
doc.Color.b = The blue channel, 0 to 1 inside sRGB.
doc.Color.a = The alpha, from 0 (transparent) to 1 (opaque), not premultiplied.
doc.Color.current = True for <code>current</code>, the text colour of the element; the channels are then unused.
doc.Color.has_dark = True when the colour has a dark variant, as made by <code>light dark(a, b)</code> or <code>LightDark</code>.
doc.Color.dark_r = The red channel of the dark variant. Read the dark variant with <code>Dark</code> instead of these fields.
doc.Color.dark_g = The green channel of the dark variant.
doc.Color.dark_b = The blue channel of the dark variant.
doc.Color.dark_a = The alpha of the dark variant.
doc.Color.dark_current = True when the dark variant is <code>current</code>.
doc.Parse = Reads a colour in any syntax the package accepts into <code>out</code> and returns true. On an error it returns false and leaves <code>out</code> as it was; <code>Error</code> gives the message.
doc.Error = Returns an empty string when <code>Parse</code> accepts the text, and otherwise a message that starts with the column and says what was expected. The caller owns the string.
doc.New = Makes a colour from sRGB channels and an alpha, all from 0 to 1. Channels outside 0 to 1 describe colours outside sRGB.
doc.Rgb = Makes an opaque colour from 8-bit channels, 0 to 255.
doc.Rgba = Makes a colour from 8-bit channels and an alpha from 0 to 1.
doc.Hex = Makes an opaque colour from a number written as <code>0xrrggbb</code>.
doc.FromArgb = Makes a colour from a packed <code>0xAARRGGBB</code> value, straight (not premultiplied) alpha.
doc.Argb = Packs a colour as <code>0xAARRGGBB</code> with straight alpha, clamping every channel to sRGB. Gives the light variant of a light dark colour and 0 for <code>current</code>.
doc.Hsl = Makes a colour from a hue in degrees and a saturation and lightness from 0 to 1.
doc.Hwb = Makes a colour from a hue in degrees and a whiteness and blackness from 0 to 1.
doc.Lab = Makes a colour from CIE Lab (D50): lightness 0 to 100 and the a and b axes.
doc.Lch = Makes a colour from CIE LCh (D50): lightness 0 to 100, chroma and a hue in degrees.
doc.Oklab = Makes a colour from Oklab: lightness 0 to 1 and the a and b axes.
doc.Oklch = Makes a colour from Oklch: lightness 0 to 1, chroma and a hue in degrees.
doc.Cmyk = Makes a colour from cyan, magenta, yellow and black, each 0 to 1, with the plain formula and no printer profile.
doc.WithAlpha = Returns the colour with a new alpha, for both variants of a light dark colour.
doc.Current = Returns <code>current</code>, the text colour of the element, which the renderer fills in.
doc.LightDark = Makes a colour with a light and a dark variant. A light dark argument gives its light variant to the first place and its dark variant to the second.
doc.Light = Returns the light variant of a colour, or the colour itself when it has no dark variant.
doc.Dark = Returns the dark variant of a colour, or the colour itself when it has no dark variant.
doc.HasDark = Reports whether the colour has a dark variant.
doc.Css = Returns the CSS the web target writes for the colour: <code>#rrggbb</code> or <code>#rrggbbaa</code> inside sRGB, <code>color(display-p3 ...)</code> or <code>oklch(...)</code> outside it, <code>currentColor</code>, or <code>light-dark(a, b)</code>. The caller owns the string.
doc.Source = Returns a Salam expression, such as <code>color.Rgb(51, 102, 170)</code>, that builds the same colour without parsing. The caller owns the string.
doc.Mix = Mixes two colours in oklab with premultiplied alpha. <code>amount</code> is how much of <code>b</code>, clamped to 0 to 1. Light dark colours mix each variant.
doc.MixIn = Like <code>Mix</code>, in the colour space named by <code>space</code> (<code>oklab</code>, <code>oklch</code>, <code>lab</code>, <code>lch</code>, <code>srgb</code>, <code>srgb linear</code>, <code>hsl</code>, <code>hwb</code>, <code>display p3</code>, <code>a98 rgb</code>, <code>prophoto rgb</code>, <code>rec2020</code>, <code>xyz</code>, <code>xyz d50</code>, <code>xyz d65</code>). Hues take the shorter arc. An unknown name mixes in oklab.
doc.Lerp = Interpolates from <code>a</code> to <code>b</code> for transitions, in oklab with premultiplied alpha. <code>t</code> is not clamped, so an easing curve may overshoot. With <code>current</code> it switches at the middle.
doc.Luminance = Returns the relative luminance from WCAG, 0 for black and 1 for white, of the colour clamped to sRGB.
doc.Contrast = Returns the WCAG contrast ratio of two colours, from 1 to 21. Body text needs at least 4.5.
doc.Lighten = Raises the Oklch lightness by <code>amount</code> (0 to 1). A colour inside sRGB loses chroma where needed to stay inside it.
doc.Darken = Lowers the Oklch lightness by <code>amount</code>, like <code>Lighten</code> the other way.
doc.InGamut = Reports whether the colour, and its dark variant if it has one, is inside sRGB, so that <code>Css</code> writes it as hex.
doc.Equal = Reports whether two colours are the same, comparing channels with a small tolerance, <code>current</code> and both variants.
