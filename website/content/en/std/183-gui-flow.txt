pkg.intro <<
<p><code>gui.flow</code> computes the rectangle of every box of a native user interface. It implements exactly the layouts of the Salam style standard and nothing else: <code>column</code> and <code>row</code> (the flex model with grow, shrink, basis, wrapping, gaps, alignment and order), <code>grid</code> (track lists with pixels, percent, fr, auto, minmax, repeat, fit and content sizes, explicit lines, spans and auto placement), <code>stack</code> (every child in one cell) and <code>flow</code> (children placed like words, wrapped onto lines and baseline aligned). It is not a CSS engine: there is no display, float, block formatting context, margin collapsing or table.</p>
<p>You build a <code>Tree</code>, give every box a <code>FlowStyle</code>, give leaves such as text and images a measure function, and call <code>Layout</code> with the size of the window. Then <code>X</code>, <code>Y</code>, <code>W</code> and <code>H</code> give each box relative to its parent. The package depends on nothing else in <code>gui</code>; <code>gui.ui</code> maps the style of an element to a <code>FlowStyle</code>.</p>
<p>Things to know:</p>
<ul>
<li><strong>Every box is border box.</strong> Width and height include padding and border, and margins apply in every layout, <code>auto</code> margins included.</li>
<li><strong>Lengths come resolved.</strong> em, rem, vw and vh are converted to pixels by the caller; only percent stays, because only the layout knows the reference.</li>
<li><strong>Content is not crushed.</strong> <code>min_width</code> and <code>min_height</code> default to <code>Auto()</code>: a child of a row or column does not shrink below its min content width or content height, as in a browser. Set them to 0 to allow it, or give a child an overflow other than visible.</li>
<li><strong>The flow layout has no gaps.</strong> It is formatted like inline text, so space its children with margins.</li>
<li><strong>Absolute and fixed boxes keep their static position</strong> on an axis with no inset: where the parent's justify and align would place them as the only child.</li>
<li><strong>A root fills the viewport</strong> when its width or height is auto; use <code>Fit()</code> to size it to its content.</li>
<li><strong>Right to left</strong> mirrors rows, flow lines, grid columns, start and end. <code>left</code> and <code>right</code> stay physical.</li>
<li><strong>Layout is incremental.</strong> Changing a style or a measure marks the box and its ancestors; <code>Layout</code> lays out only those again and reuses cached sizes elsewhere. <code>LayoutCalls</code> and <code>MeasureCalls</code> show the work done.</li>
</ul>

<h2 id="guide-app">An application shell</h2>
<p>A header, a body with a side bar and a scrolling content area, and a footer. The body has <code>basis = 0</code>, grows, and has <code>min_height = 0</code>, so its long content does not push the header and footer away (by default a child of a column is never shorter than its content); the content area scrolls instead, and <code>ContentH</code> tells how far. The same tree in right to left puts the side bar on the right.</p>
{{example.gui-flow-guide-app}}

<h2 id="guide-text">Text through a measure function</h2>
<p>A leaf's measure function gets the available width and returns the size of the wrapped text. Here a one word label and a long paragraph sit in a row aligned on their baselines; the paragraph has <code>basis = 0</code> and grows, so it takes the rest of the row and wraps when the window narrows. A layout with nothing changed does no work, and marking the paragraph dirty measures it once.</p>
{{example.gui-flow-guide-text}}

doc.Tree.ScrollY = Vertical scroll offset in use.
doc.Tree.Layer = The layer from the style.
doc.Tree.PaintOrder = Visible children sorted by layer, keeping their order within a layer: the order to paint them in. The caller frees the vector.
doc.Tree.LayoutCalls = How many times a box was laid out or measured since the last reset; a cached result does not count.
doc.Tree.MeasureCalls = How many times a measure function ran since the last reset.
doc.Tree.ResetCounters = Sets both counters to zero.
doc.Tree.Free = Releases the memory of every box. The tree is empty afterwards.
