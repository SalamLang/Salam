pkg.intro <<
<p><code>tui</code> builds full-screen terminal programs: file managers, dashboards, installers, editors, anything that takes over the window instead of printing lines. It is <em>retained mode</em>: you build a tree of long-lived widgets once, change their state when something happens, and the <code>Screen</code> turns key presses, clicks and resizes into events, and widget drawings into frames. It repaints only the cells that changed, so a large screen stays fast over a slow connection. It sits on top of <a href="/std/term/">term</a> and uses <a href="/std/os/signal/">os.signal</a> to learn about window resizes.</p>
<p>The library started as <a href="https://github.com/curedbylethe/basalam">basalam</a> by Parsa and is now part of the standard library.</p>
<p>The pieces:</p>
<ul>
<li><strong>Screen</strong> owns the terminal, the widget tree, the focus and the event loop. <code>NewTerminalScreen</code> sizes it to the terminal; <code>NewScreen</code> gives a fixed size and never touches the terminal, which is how you test.</li>
<li><strong>Widgets</strong> are structs that embed <code>BaseWidget</code> and override what they need: <code>render</code> to draw, <code>handle_event</code> to react, <code>focusable</code> to take keys. Ready-made ones: <code>Text</code>, <code>Input</code>, <code>Button</code>, <code>Checkbox</code>, <code>List</code>, <code>Progress</code>, <code>Separator</code>, <code>Table</code>, <code>TableView</code>, <code>Panel</code> and <code>Modal</code>.</li>
<li><strong>Layout</strong> containers (<code>Row</code>, <code>Column</code>, <code>Grid</code>, <code>Stack</code>) give their children positions, so you never compute coordinates by hand.</li>
<li><strong>Events</strong> go first to the focused widget and bubble up to its parents until one consumes them; whatever nobody consumes reaches the optional <code>Keymap</code> and then your loop.</li>
</ul>
<h2 id="guide-hello">A complete program</h2>
<p>A widget, a screen, and the event loop. <code>start</code> switches the terminal to raw mode and the alternate screen; the <code>defer screen.close()</code> right after it puts the terminal back on every exit path, so a crash never leaves the user's shell broken. <code>next_event</code> waits for the next key, click, tick or resize; <code>dispatch</code> hands it to the widgets; <code>present</code> draws what changed. A key the widgets did not consume is yours: here q quits. This program needs a real terminal, so the page only compiles it.</p>
{{example.tui-guide-hello}}

<h2 id="guide-preview">See a frame without a terminal</h2>
<p>A screen made with <code>NewScreen</code> never touches the terminal. You can still send it events with <code>dispatch</code> (or <code>post</code> and <code>next_event</code>), draw with <code>draw</code>, and read every row back with <code>buffer.row_text</code>. That is how the examples on this page produce their output, and how you write tests for your own screens.</p>
{{example.tui-guide-preview}}

<h2 id="guide-layout">Lay out a screen</h2>
<p>Hand widgets to a container and the container places them. A <code>Column</code> stacks its children; <code>set_height</code> with a <code>LayoutSize</code> chooses each share: <code>Fixed</code> cells, a <code>Fill</code> weight of what is left, or <code>Pref</code> for the widget's own preferred size. Make the container the root of the screen, and add each child to the screen too: the container decides <em>where</em>, the screen decides what is drawn and focused. On a resize the screen gives the root the new size and the layout runs again.</p>
{{example.tui-guide-layout}}

<h2 id="guide-form">A form: focus, typing and callbacks</h2>
<p>Focusable widgets take turns receiving keys. The first focusable widget added gets the focus; with <code>NewDefaultKeymap</code> installed, Tab and the arrow keys move it. Values come back through callbacks: <code>on_submit</code> for an <code>Input</code> when Enter is pressed, <code>on_toggle</code> for a <code>Checkbox</code>, <code>on_click</code> for a <code>Button</code>. Callbacks are lambdas and cannot capture local variables, so keep the state they change in globals or in your own widget.</p>
{{example.tui-guide-form}}

<h2 id="guide-lists">Lists and tables</h2>
<p><code>List</code> shows one selectable item per row and moves with j and k (the arrow keys stay free for focus moves); Enter calls <code>on_select</code>. <code>TableView</code> is a scrolling table with a selected row; Up and Down move it and Enter calls <code>activate</code> with the data row. Columns take a <code>LayoutSize</code> width, an alignment and what to do with text that does not fit.</p>

<p>What to keep in mind:</p>
<ul>
<li>Always <code>defer screen.close()</code> on the line after <code>start()</code>.</li>
<li>A child given to a container or a <code>Panel</code> must also be added to the screen, or it is placed but never drawn.</li>
<li>A <code>dyn Widget</code> cannot be turned back into its struct, so read values through callbacks or keep them in your own state.</li>
<li>Draw only inside <code>render</code>; change state in <code>handle_event</code> or in your loop, then the next <code>present</code> shows it. After changing state the widgets cannot see, set <code>screen.dirty = true</code>.</li>
<li>Glyphs fall back to ASCII on terminals without UTF-8; set <code>SALAM_TUI_GLYPHS</code> to <code>ascii</code> or <code>unicode</code> to choose. Colors follow <code>NO_COLOR</code>, <code>COLORTERM</code> and <code>TERM</code>.</li>
<li>On Windows resizes are noticed by polling the size about every 20 milliseconds instead of by a signal.</li>

doc.SplitMain = Splits a main-axis length of <code>length</code> cells between sizes, in order (R5). Fixed takes max(0, cells) and ignores weight. <code>gap</code> is the cells between adjacent slots. A negative gap clamps to 0. The budget is gap * max(0, k - 1), where k is the slot count, including zero-size slots; k &lt;= 1 charges nothing. Fill and Pref share the leftover R = max(0, length - sum of those Fixed sizes - budget). Arrange resolves a measured Pref to Fixed before this call, and a Pref that cannot measure to Fill weight 1. This function does not measure; a Pref still in the vector stays in the weight pool. Each pool entry's weight is max(0, weight). The share is floor(R * weight / sum of weights), then one extra cell goes to each remaining cell, given to the pool entries with the largest (R * weight) mod sum of weights. Ties go to the earliest pool slot. A weight sum of 0 gives every pool entry 0 and leaves R unused, with no division. Fixed overflow, or a budget that uses up the length, makes R 0, so every pool entry is 0 and Fixed is not shrunk. The gap is not part of the returned sizes and is not refunded. The vector has one entry per input. Weight 1 on every pool entry is an equal split, remainder to the earliest entries.

Assumes total &gt;= 0 (content lengths are never negative; on a negative total the division truncates toward zero and the exact-sum claim below does not hold). Track k is floor(total/n) plus one for each of the earliest total mod n tracks, so the tracks sum to total exactly. A non-positive n gives an empty vector.

doc.StyleMerge = The style a child ends up with under a parent, by sentinel patch: a child's color is used unless it is Color.Default (then the parent's color is inherited), and each attribute is the OR of the two. Pure: it returns a new value and never mutates its inputs. a child can add an attribute or override a color but cannot remove an inherited attribute (child false is indistinguishable from unset) or force the terminal-default color under a colored parent (child Default means inherit). doc.Keymap.bind_seq = Binds a key sequence to an action in the global scope. seq is decoded per rune; an empty string is ignored. A later bind of the same sequence replaces this one.
doc.Keymap.bind_for_seq = Binds a key sequence to an action for the widget with this ID. NoWidget binds globally. An empty string is ignored.
doc.Keymap.unbind = Removes the global binding for one key. A no-op when there is none. Scoped bindings are not touched (use bind_for to replace one, or unbind_for to drop one). unbind_for(NoWidget, key) does the same work.
doc.Keymap.unbind_for = Removes the binding for one widget on one key: bind_for's inverse. Only that widget's override is removed, so the global binding and every other widget's override on the same key still apply, and no trie node is deleted. A no-op when the map is empty, the key was never bound, or the widget never bound it. NoWidget removes the global binding, so unbind_for(NoWidget, key) is unbind(key). Resets a pending sequence.
doc.Keymap.unbind_for_seq = Removes one widget's binding for one key sequence: bind_for_seq's inverse. Only that widget's override is removed, so the global sequence and every other widget's override on the same sequence still apply. The trie is walked read-only, so no node is created or deleted and a later bind_for_seq on the same sequence still works. A no-op when the map is empty, the sequence was never bound, or the widget never bound it; NoWidget removes the global sequence binding, and an empty string is ignored. Resets a pending sequence.
doc.Keymap.handle = Handles one event against the bindings. Only KeyEvents reach the trie; every other kind returns false and leaves <code>pending</code> untouched. Returns true when an action ran. Reads resolve the key before any action is invoked; nothing touches the trie after an invocation.
doc.Keymap.free = Releases every node's children map and binding vector, then the node storage itself. The actions and their captured values are the caller's; only the trie is freed. Call once.
doc.Keymap.cancel_pending = Forgets a key sequence that was half typed, for example the first g of gg. The screen calls it when a widget consumes a key, so keys that were not typed in a row never complete a sequence.
doc.NewKeymap = Creates an empty keymap. Feed it keys with bind and the bind_* variants and release it with free. The root node is created on the first bind.
doc.NewDefaultKeymap = Creates an opt-in keymap with the library's default focus bindings: exactly five rows: Tab moves the focus to the next widget, and Up, Down, Left and Right move it in those directions. Nothing installs this map on its own; pass it to set_keymap (or bind through a screen's keymap field) to use it. Shift+Tab is deliberately not bound: Salam decodes the backtab sequence to KeyUnknown.
doc.NewVimKeymap = Creates an opt-in vim-style preset. It is a superset of NewDefaultKeymap, so Tab and the four arrows keep working, and it adds h, j, k and l for the same four directions; "gg" and "G" move to the top and the bottom of the focused widget's column, by repeated directional moves, so the column is kept; Esc pops the focus stack, but only while a pushed focus remains, and is reported unconsumed at the root so the application still sees it; and "/" runs on_search, the application's own action, whose boolean is the dispatch result. Enter and Space are deliberately not bound: dispatch offers every key to the focused widget first, where Button, Checkbox, List and Modal already act on them, and Widget has no generic activation to bind. doc.Screen.keymap = The opt-in key bindings, consulted as a dispatch fallback for KeyEvents no widget consumed. Empty by default, so an app that never touches it behaves exactly as before. Bind through this field to extend it in place, or install a whole map with set_keymap. Never assign a Keymap directly: it would leak the current map's buffers.
doc.Screen.dirty = True when the next present() must repaint the whole frame: a resize, a tick, an added widget, raise/unraise, a keymap-consumed key, or invalidate of an unknown widget. A precise change is a region.
doc.Screen.focus_stack = Widget IDs; the top (last) entry is the focused widget, and an empty stack means nothing is focused. Change it through focus, push_focus, pop_focus, and the navigation methods, which keep <code>focused</code> in sync and queue the old and new bounds.
doc.Screen.add = Adds w under parent (an ID; RootId for top level) and returns the new widget's ID. Unraised widgets paint in ID order, which is the order they were added. The first reachable focusable widget added while nothing has focus receives it; a child of a hidden container is not reachable, so it is skipped.
doc.Screen.raise = Assigns every id one fresh stamp, shared by this whole call, so the ids form a single layer above every widget raised earlier and above every unraised widget. Within the layer, paint order stays ID order. When the resulting focus order is non-empty and the current focus is outside it, saves that focus and moves to the order's first id. Otherwise leaves the focus and the saved id unchanged. An id that is not in the tree is recorded and does not crash; it changes painting only once that id is registered.
doc.Screen.unraise = Clears the stamp of every id to 0, so those widgets return to plain ID order. Idempotent: an id that was not raised, or that is not in the tree, is left at 0. Does not rewind the stamp counter. When nothing remains raised, focuses the saved id if it is still focusable outside a hidden subtree, otherwise the first focusable widget outside a hidden subtree, and clears the saved id. While a layer remains, focuses the first id of the new focus order when the current focus is outside it.
doc.Screen.raise_subtree = Raises id and every descendant of id as one layer: one fresh stamp for the whole subtree, so it paints above every other widget. Inside the layer, ascending ID order keeps each parent before its children. Focus follows raise: when the current focus is outside the layer's focus order, it moves to that order's first id and the old focus is saved for unraise_subtree. An id that is not in the tree, including NoWidget, does nothing. The saved focus is one level deep: a second raise overwrites it, so nest layers with push_focus and pop_focus. Rejected: a public subtree query followed by raise(), which is two calls on every modal open. Also rejected: a blocking-owner field that dispatch and hit_test consult, which duplicates the geometric block and can fall out of step with it.
doc.Screen.unraise_subtree = Clears the stamp of id and every descendant to 0, returning them to plain ID order, and restores focus exactly as unraise does. An id that is not in the tree, including NoWidget, does nothing.
doc.Screen.widget = The widget with this ID (the root for an invalid ID).
doc.Screen.focused_id = The ID of the focused widget, or NoWidget when nothing has focus (events then start at the root).
doc.Screen.can_focus = True when id names a widget that is currently focusable and no widget on its path to the root reports itself hidden.
doc.Screen.focus = Moves the focus to id, replacing the top of the focus stack (or starting it). Returns false, changing nothing, when id is not a focusable widget outside a hidden subtree.
doc.Screen.push_focus = Focuses id and remembers the previous focus underneath it, for example while a dialog is open. pop_focus returns to it. Returns false, changing nothing, when id is not a focusable widget outside a hidden subtree.
doc.Screen.pop_focus = Drops the top of the focus stack, returning the focus to whatever was focused before the matching push_focus. Returns false when the stack was already empty.
doc.Screen.focus_next = Moves the focus to the next widget in focus order, wrapping from the last to the first. doc.Screen.focus_prev = Moves the focus to the previous widget in focus order, wrapping from the first to the last. A current focus outside the order lands on the last entry. With no such widget, does nothing. Returns true when the focus moved.

doc.Screen.hit_test = The ID of the widget drawn at cell (x, y), both 0-based, or NoWidget when no widget covers it. doc.Screen.set_keymap = Replaces the screen's keymap with km. Frees the current map's buffers first, so this is the only safe way to swap a Keymap (assigning to the field directly leaks the old one). doc.Screen.invalidate = Queues a repaint of widget id's bounds. An unknown id, or a widget whose rect is empty, marks the whole screen instead. Legal before start(): it only marks, and the flush still waits until the screen is attached.

doc.TableView = A focusable, vertically scrollable Table. It embeds Table, so columns, rows, header, rule, styles and every setter are Table's.
