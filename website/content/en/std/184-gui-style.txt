pkg.intro <<
<p><code>gui.style</code> is the style standard of the Salam UI, in the spirit of QML: one vocabulary of properties that works the same on the web and in a native window. A page never contains CSS. The compiler checks every style attribute with this package, writes CSS from it for the web target and builds typed values from it for the native target, so both look the same.</p>
<p>Every property has an int id (<code>P_WIDTH</code>, <code>P_PADDING</code>, ...), an English and a Persian name, a value kind, a keyword set with English and Persian names, a default, and flags that say whether it is inherited and whether it can be animated. The table is in the package, and <code>Info</code> returns one row of it.</p>
<p>The value syntax:</p>
<ul>
<li><strong>Numbers</strong> in the property's natural unit: pixels for lengths, milliseconds for times, degrees for angles, a plain number for <code>opacity</code>, <code>grow</code> and <code>scale</code>. Units: <code>px</code>, <code>%</code>, <code>em</code>, <code>rem</code>, <code>vw</code>, <code>vh</code>, <code>vmin</code>, <code>vmax</code>, <code>fr</code>, <code>ms</code>, <code>s</code>, <code>deg</code>, <code>turn</code>, <code>rad</code>, also as calls like <code>px(12)</code>.</li>
<li><strong>Length arithmetic</strong>: <code>100% - 20</code> and <code>50% + 1em</code>; the web target writes <code>calc()</code>.</li>
<li><strong>Lists</strong> with a comma (<code>padding = 8, 16</code>) and <strong>groups</strong> in brackets (<code>shadow = [0, 4, 8, black], [0, 1, 2, red]</code>).</li>
<li><strong>Composites in any order</strong> where the parts differ: <code>border = 2, solid, #3366aa</code> or <code>border = red, 1</code>.</li>
<li><strong>Calls</strong>: <code>linear(90, red, blue)</code>, <code>radial(circle, [30%, 40%], white, black)</code>, <code>conic(...)</code>, <code>image("a.png")</code>, <code>minmax(100, 1fr)</code>, <code>repeat(fill, 200)</code>, <code>fit(300)</code>, <code>ease(0.2, 0, 0, 1)</code>, <code>steps(4)</code>, <code>spring(170, 26)</code>, and every colour of <code>gui.color</code>.</li>
<li><strong>Persian</strong>: keywords and property names in Persian, Persian digits, <code>٪</code> and the comma <code>،</code>.</li>
<li><strong>Strings</strong> are read with the same syntax: <code>"8, 16"</code> is the same as <code>8, 16</code>.</li>
</ul>
<h3>Things to know</h3>
<ul>
<li>Sides and corners follow the text direction: four values are top, end, bottom, start, and <code>radius</code> goes top start, top end, bottom end, bottom start. <code>left</code> and <code>right</code> become start or end by the direction when they are set.</li>
<li><code>gap</code> has no effect in <code>flow</code> (the lines and items there are spaced by margins and line height), on both targets; it is accepted and ignored. <code>min width</code> and <code>min height</code> start at <code>auto</code>, the automatic minimum, so a flex child does not shrink below its content unless a smaller minimum is given.</li>
<li>In <code>flow</code>, inline text elements (span, bold, italic, code, link and the like) stay inline content on the web so text wraps across them; every other child is one atomic item on the line, baseline aligned.</li>
<li>Every box is a column by default and text elements use <code>flow</code>. <code>BaseCss</code> gives the web the same defaults, so plain HTML does not look different from the native window.</li>
<li><code>Css</code> returns declarations. Filters and <code>reverse</code> set <code>--salam-*</code> variables that the base sheet reads, and <code>layout = stack</code> and <code>flow</code> end with a nested <code>&amp;&gt;*</code> rule for the children, so the web target has to put them in a style rule, not in a <code>style</code> attribute.</li>
<li><code>Source</code> writes code that uses only this package, for programs the compiler generates for the native target.</li>
</ul>

<h2 id="guide-card">One style for the web and a native window</h2>
<p>A card is described with attribute values as a page would write them. Each one is parsed and checked; a value out of range gives a message with the expected form. The same values become CSS for the web and typed fields that a native renderer reads.</p>
{{example.gui-style-guide-card}}
<p>Lengths keep their units until layout: <code>100% - 32</code> stays a percent plus pixels, and the native layout resolves the percent against the parent.</p>

<h2 id="guide-hover">A hover transition, frame by frame</h2>
<p>A transition needs the same curve on both targets. The web gets the CSS timing function, and a native renderer computes each frame with <code>EaseAt</code> and <code>Lerp</code>, which mix colours in oklab and lengths unit by unit.</p>
{{example.gui-style-guide-hover}}
<p><code>spring(stiffness, damping)</code> works the same way: the native target uses <code>EaseAt</code>, and <code>Css</code> writes the same curve as a CSS <code>linear()</code> timing function.</p>
>>
