pkg.intro <<
<p>A ULID is a 128 bit identifier made of a 48 bit timestamp in milliseconds and 80 random bits, written as 26 characters of Crockford base32. It is the sortable alternative to a random UUID: the text sorts in the order the ids were made, so a database index stays compact and a range of time is a range of ids. This package follows the <a href="https://github.com/ulid/spec">ULID specification</a> and is written in Salam.</p>
<p>The text uses the digits and the letters without I, L, O and U. The largest id is <code>7ZZZZZZZZZZZZZZZZZZZZZZZZZ</code>, because 130 bits are used to hold 128. Parsing accepts lowercase, reads I and L as 1 and O as 0, and refuses U and anything above that largest id.</p>

<tr><td><code>New</code>, <code>NewString</code>, <code>NewBatch</code></td><td>Ids from the default generator. Strictly increasing in one process, safe from any number of threads.</td></tr>

<h2 id="guide-basics">Make, print and read back</h2>
<p><code>New</code> gives the next id of the default generator and <code>String</code> writes the 26 characters. <code>NewAt</code> makes an id for a time you choose. Every id is a value: copy it, compare it, keep it in a struct.</p>
{{example.encoding-ulid-guide-basics}}
<h2 id="guide-parse">Parsing and the rules of the text</h2>
<p><code>Parse</code> follows the specification: lowercase and the aliases I, L and O are accepted, U is not, and the first character may not be above 7 because the value would not fit in 128 bits. <code>ParseStrict</code> wants exactly what <code>String</code> writes. Errors are codes, with <code>ErrorText</code> for a message.</p>
{{example.encoding-ulid-guide-parse}}
<h2 id="guide-order">Order and range queries</h2>
<p>Text order is time order, so ids sort by a plain string sort. To select the ids of a time window ask for everything between <code>MinAt(start)</code> and <code>MaxAt(end)</code>; in SQL that is a <code>BETWEEN</code> on the id column.</p>
{{example.encoding-ulid-guide-order}}
<h2 id="guide-monotonic">The monotonic generator</h2>
<p>Two ids made in the same millisecond must still sort in the order they were made. A <code>Generator</code> does what the specification says: in a new millisecond it draws fresh randomness, in the same one it adds 1 to the last random part, and when the clock moves back it keeps the last timestamp. If the 80 bits ever overflow, the timestamp moves one millisecond ahead instead of failing. The example uses a fake clock and a fixed entropy function so every character is known.</p>
{{example.encoding-ulid-guide-monotonic}}
<h2 id="guide-threads">Many threads</h2>
<p>The default generator and every <code>Generator</code> guard their state with a mutex, so threads share one without duplicates and without going out of order: every thread sees its own ids increase, and all ids together are distinct. <code>NewBatch</code> takes the lock once for n ids. The cost is one lock and one clock read per id.</p>
{{example.encoding-ulid-guide-threads}}
<h2 id="guide-entropy">When the random source fails</h2>
<p>The built in source reads the operating system random generator through <code>crypto.RandomBytes</code>, which stops the program if the system cannot give random bytes: a weak id is never made. A source of your own, passed to <code>NewGeneratorWith</code>, can fail politely by returning a negative number. <code>Next</code> then returns <code>ERR_ENTROPY</code> and leaves the generator untouched, so the next call can succeed.</p>
{{example.encoding-ulid-guide-entropy}}
<h2 id="guide-bytes">Bytes, UUIDs and fixed ids</h2>
<p><code>Bytes</code> gives 16 bytes, big endian, the same size as a UUID, and <code>FromBytes</code> reads them back; the package does not depend on a UUID type, only on the bytes. <code>FromParts</code> builds an id from a time and 10 bytes you pick, which is how tests get exact answers. Free the byte vectors.</p>
{{example.encoding-ulid-guide-bytes}}
<p>What people get wrong:</p>
<ul>
<li>Expecting <code>NewAt</code> to be ordered inside one millisecond. It keeps no state; use a <code>Generator</code>.</li>
<li>Treating the time as secret. The first 10 characters are the creation time, readable by anyone who sees the id.</li>
<li>Comparing text with lowercase or aliases without <code>Parse</code>: <code>01arz</code> and <code>01ARZ</code> are the same id but different strings.</li>
<li>Forgetting to <code>Free</code> a generator or to free the vectors of <code>Bytes</code>, <code>Entropy</code> and <code>Batch</code>.</li>
<li>Comparing ids made by different generators or machines for strict order: clocks differ, so only ids of one generator are strictly ordered.</li>
</ul>
>>

doc.MAX_TIME = The largest timestamp a ULID can hold, 281474976710655 milliseconds (48 bits), which is the year 10889.
doc.OK = Error code 0: nothing went wrong.
doc.ERR_LENGTH = The text is not 26 characters long.
doc.ERR_CHAR = The text has a character outside the Crockford alphabet, such as U.
doc.ERR_OVERFLOW = The value is larger than 7ZZZZZZZZZZZZZZZZZZZZZZZZZ (first character above 7), or an increment would overflow the 80 random bits.
doc.ERR_TIME = The timestamp is outside 0 to MAX_TIME.
doc.ERR_ENTROPY = The entropy source reported a failure; no id was made and the generator state did not change.
doc.ERR_BYTES = A byte list had the wrong length (16 for FromBytes, 10 for FromParts).
doc.ULID = A 128 bit identifier: a 48 bit millisecond timestamp and 80 random bits. It is a plain value, copy it freely. Ids compare in the same order as their times.
doc.ULID.time = The timestamp in milliseconds since the Unix epoch.
doc.ULID.hi = The upper 40 bits of the 80 random bits.
doc.ULID.lo = The lower 40 bits of the 80 random bits.
doc.Result = What parsing and the generators return: <code>ok</code>, the <code>id</code> and an <code>err</code> code.
doc.Result.ok = True when the operation worked.
doc.Result.id = The id; the zero id when <code>ok</code> is false.
doc.Result.err = One of the error codes, <code>OK</code> on success.
doc.Generator = A monotonic generator. It owns a lock and its last id, so the copies of one Generator share state and any number of threads may call it. Release it with Free.
doc.Generator.state = The shared last timestamp and random parts, behind the lock.
doc.Generator.mu = The lock that guards the state.
doc.Generator.clock = The function that returns the current time in milliseconds.
doc.Generator.entropy = The function that returns 40 random bits, or a negative number when it fails.
doc.ErrorText = A short English message for an error code.
doc.Default = The process wide generator behind New, NewString and NewBatch. Do not free it.
doc.New = A new id from the default generator, using the system clock and the operating system random source. Ids from one process are strictly increasing, even from many threads at once.
doc.NewString = Shorthand for String(New()).
doc.NewAt = An id for a chosen millisecond with fresh random bits. It keeps no state, so two calls in one millisecond are not ordered; use a Generator when order matters. Fails with ERR_TIME outside 0 to MAX_TIME.
doc.NewBatch = Makes n ids from the default generator under one lock, so they are consecutive and increasing. Free the vector.
doc.NewGenerator = A generator with the system clock and the operating system random source.
doc.NewGeneratorWith = A generator with your own clock and entropy functions, for tests and for sources that can fail. The entropy function returns 40 random bits (0 to 1099511627775) or a negative number on failure, which makes Next report ERR_ENTROPY.
doc.Next = The next id of a generator. In a new millisecond the random part is fresh; in the same millisecond, or when the clock went back, the previous random part grows by one. If the 80 bits run out the timestamp moves one millisecond ahead. Safe from many threads.
doc.NextAt = Like Next with the time given instead of read from the clock. A time before the last id keeps the last timestamp.
doc.Batch = Makes n ids under one lock with one clock read. A failing entropy source ends the batch early, so check the length. Free the vector.
doc.Last = The last id the generator made, or ERR_TIME when it has made none yet.
doc.Free = Releases a generator made by NewGenerator or NewGeneratorWith.
doc.FromParts = Builds an id from a timestamp and exactly 10 entropy bytes, with no randomness, so tests can know every character.
doc.FromBytes = Reads the 16 byte binary form (6 bytes of time, 10 of randomness, big endian).
doc.FromUUIDBytes = The same as FromBytes: a ULID fits the 16 bytes of a UUID.
doc.String = The 26 character canonical text, uppercase Crockford base32.
doc.Bytes = The 16 byte binary form. Free the vector.
doc.ToUUIDBytes = The same 16 bytes, for code that stores or sends them as a UUID.
doc.Entropy = The 10 random bytes. Free the vector.
doc.Time = The timestamp in milliseconds.
doc.Compare = -1, 0 or 1 by time first, then by the random part.
doc.Equal = True when two ids are the same.
doc.Less = True when the first id is older than the second, or smaller in the random part at the same time.
doc.IsZero = True for the all zero id.
doc.MinAt = The smallest id of a millisecond (random part all zero). Use it as the lower bound of a range query. The time is clamped to 0 to MAX_TIME.
doc.MaxAt = The largest id of a millisecond (random part all ones), the upper bound of a range query.
doc.Increment = The id right after this one, with the random part grown by one. Fails with ERR_OVERFLOW when it is already all ones.
doc.Parse = Reads 26 characters. Lowercase is accepted, I and L mean 1, O means 0, U is refused, and a first character above 7 is ERR_OVERFLOW.
doc.ParseStrict = Reads only the canonical form: uppercase, no aliases.
doc.ParseOr = Parse, or the fallback id when the text is not valid.
doc.IsValid = True when Parse accepts the text.
doc.Now = The system clock in milliseconds since the Unix epoch, kept inside 0 to MAX_TIME.
