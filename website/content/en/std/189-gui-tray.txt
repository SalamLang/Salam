pkg.intro <<
<p><code>gui.tray</code> puts one icon in the system tray (Linux, Windows) or the menu bar (macOS), with a tooltip and a menu. It works with any app: a native <code>gui.ui</code> page, a <code>gui.window</code> program or a program with no window at all. It does not need <code>gui.webview</code>.</p>
<p>Call <code>Show</code> with the path of the icon, the tooltip and the menu items. Later calls to <code>SetMenu</code>, <code>SetTooltip</code> and <code>SetIcon</code> update the icon in place, and <code>Hide</code> removes it. Clicks and chosen menu items become <code>Event</code> values in a queue: read them with <code>Take</code>. <code>SetWake</code> gives a function that is called after every new event, from any thread, so a <code>gui.ui</code> app passes <code>ui.Invalidate</code> and reads the queue in its view.</p>
<p>How each system shows it:</p>
<ul>
<li><strong>Linux:</strong> a StatusNotifierItem with a com.canonical.dbusmenu menu on the D-Bus session bus, served from its own thread. KDE Plasma, Xfce, Cinnamon, Budgie, LXQt, waybar and GNOME with the AppIndicator extension (the default on Ubuntu) show it, on X11 and on Wayland. <code>Supported</code> is false when nothing on the bus hosts tray icons; <code>LastError</code> says why.</li>
<li><strong>Windows:</strong> a notification area icon owned by a hidden window on its own thread. A left click is <code>Click</code>, a double click is <code>DoubleClick</code> (after a <code>Click</code>), and a right click opens the menu. The icon comes back by itself when Explorer restarts.</li>
<li><strong>macOS:</strong> a status item in the menu bar. Clicking it opens the menu, so a <code>Menu</code> event is what you get. Call the functions from the main thread; the events arrive while the <code>gui.window</code> or <code>gui.ui</code> event loop runs.</li>
</ul>
<p>Things to know:</p>
<ul>
<li><strong>Icons.</strong> A PNG is decoded and scaled down to at most 64 pixels; the system scales it again to the tray size. Windows also takes an <code>.ico</code> file, and macOS takes any image format the system reads.</li>
<li><strong>Menu items are flat.</strong> Each item has an <code>id</code> that comes back in the event, a label, and can be disabled, checked or a separator. There are no submenus.</li>
<li><strong>Close to the tray.</strong> With <code>ui.OnCloseRequest</code> returning false and <code>ui.HideWindow</code>, closing the window keeps the app running in the tray; <code>ui.ShowWindow</code> brings it back.</li>
</ul>

<h2 id="guide-menu">A menu that follows the app state</h2>
<p>A program with no window: the menu offers Connect or Disconnect depending on the state, and the tooltip says which one is active. The loop reads the queue and rebuilds the menu with <code>SetMenu</code> after every change.</p>

<h2 id="guide-hide">Close the window to the tray</h2>
<p>A <code>gui.ui</code> page whose close button hides the window instead of quitting. A click on the icon or the Show item brings it back, and Quit leaves for real. <code>SetWake</code> asks the page to run its view again, and the view reads the tray events.</p>

doc.EventKind = What happened to the tray icon.
doc.EventKind.Click = The icon was clicked once (left click on Windows, activation on Linux).
doc.EventKind.DoubleClick = The icon was double clicked on Windows, or middle clicked on Linux.
doc.EventKind.Menu = A menu item was chosen; the event's <code>id</code> is the item's id.
doc.Item = One entry of the tray menu.
doc.Item.id = The id that comes back in the <code>Menu</code> event when the item is chosen.
doc.Item.label = The text of the item.
doc.Item.enabled = False shows the item greyed out; it cannot be chosen.
doc.Item.checked = True shows a check mark next to the item.
doc.Item.separator = True makes the item a separator line; its other fields are ignored.
doc.Event = One click or chosen menu item, read with <code>Take</code>.
doc.Event.kind = What happened, an <code>EventKind</code>.
doc.Event.id = The id of the chosen item for a <code>Menu</code> event, empty otherwise.
doc.Supported = Reports whether a tray icon can be shown now. On Linux it is false without a session bus or a tray host; <code>LastError</code> says which.
doc.Backend = Names the system part in use: <code>sni</code>, <code>win32</code>, <code>cocoa</code> or <code>none</code>.
doc.LastError = The reason of the last failure, empty after a successful <code>Show</code>.
doc.Show = Shows the icon with a tooltip and a menu, or updates it when it is already shown. False when the tray is not available or the icon file cannot be read.
doc.SetMenu = Replaces the menu items. Works before <code>Show</code> too.
doc.SetTooltip = Changes the tooltip (and the title on Linux).
doc.SetIcon = Changes the icon. False when the file cannot be read.
doc.Hide = Removes the icon. <code>Show</code> brings it back.
doc.IsShown = Reports whether the icon is shown.
doc.SetWake = Sets a function that is called after each new event, from the thread that received it. Keep it short and thread safe, such as <code>ui.Invalidate</code>.
doc.Post = Puts an event in the queue as if the tray had sent it, and calls the wake function. Useful in tests and to feed the same handler from other places.
doc.Take = Moves the oldest event into the argument and returns true, or returns false when the queue is empty.
doc.Pending = Number of events waiting in the queue.
doc.NewItem = A normal menu item with an id and a label.
doc.CheckItem = A menu item with a check mark when <code>checked</code> is true.
doc.Separator = A separator line for the menu.
