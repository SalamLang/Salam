pkg.intro <<
<p>An <code>i64</code> stops at about 9.2 × 10<sup>18</sup> and wraps around without warning. <code>bigint.Int</code> is a whole number whose size is limited only by memory: use it for factorials and combinatorics, exact counters that can grow without bound, token amounts in their smallest unit, and number theory such as modular exponentiation. For money with a fixed number of decimal places use <a href="/std/decimal/">decimal</a>, and for real keys and signatures use <a href="/std/crypto/">crypto</a>.</p>
<p>A number is a sign and a vector of 32-bit limbs. Multiplication is the schoolbook method and conversion to text divides repeatedly, so numbers of a few thousand digits are quick and numbers of a million digits are slow.</p>
<p>Most functions return a new number and leave their arguments alone. The ones whose names end in <code>To</code>, <code>From</code> or <code>By</code>, such as <code>AddTo</code>, store the result in their first argument and free its old value for you. They still allocate the new value, so they are not faster; what they save is the bookkeeping of freeing every intermediate result. Release a number you no longer need with <code>Free</code>.</p>
<p>What people get wrong:</p>
<ul>
<li>Copying with <code>=</code>. <code>b := a</code> copies only the header, so both names share one set of limbs, and the next in-place call on <code>b</code> frees the memory <code>a</code> still points to. Use <code>Clone</code> for a second, independent number.</li>
<li>Dividing by zero. <code>Div</code>, <code>Rem</code>, <code>Mod</code> and <code>ModExp</code> do not stop the program; they return 0. When the divisor can be zero, use <code>DivMod</code>, which returns <code>false</code>.</li>
<li>Expecting an error for impossible input. A negative exponent in <code>Pow</code>, the square root of a negative number and the factorial of a negative number all return 0, and <code>ToStrBase</code> with a base outside 2 to 36 returns empty text.</li>
</ul>

<h2 id="guide-fibonacci">Past the end of i64</h2>
<p>The 93rd Fibonacci number is the first one that does not fit in an <code>i64</code>; with ordinary integers it would wrap around to a negative value without warning. With <code>bigint.Int</code> the loop just keeps going. <code>ToInt</code> converts back and tells you, through its <code>bool</code> argument, whether the value fitted, so you can move to plain integers when the numbers are small again.</p>
{{example.bigint-guide-fibonacci}}
<p>Each <code>Add</code> returns a new number, so the loop frees the value it no longer needs before it moves the names along. Without the <code>Free</code> calls the program would still be correct, but it would keep every intermediate number in memory.</p>

<h2 id="guide-inplace">Updating one number in a loop</h2>
<p>A loop that updates one number with <code>Add</code> has to free the old value on every step, as the Fibonacci loop above does. <code>MulIntBy</code>, <code>AddTo</code>, <code>ShlBy</code> and the other functions named with <code>To</code>, <code>From</code> or <code>By</code> do that for you: they put the result into their first argument and free what was there. Build the result in one variable and free it once at the end.</p>
{{example.bigint-guide-inplace}}

<h2 id="guide-copy">Copies and snapshots</h2>
<p>To keep an old value while you change the number, take a copy with <code>Clone</code>. A plain <code>opening := balance</code> would not work: both names would share the same limbs, and the first <code>AddIntTo</code> would free them under <code>opening</code>, which then prints garbage. Each clone is its own allocation and needs its own <code>Free</code>.</p>
{{example.bigint-guide-copy}}

<h2 id="guide-digits">Digits of very large numbers</h2>
<p><code>ToStr</code> gives the decimal text, so its length is the number of digits. <code>DivModInt</code> divides by an ordinary integer and puts the remainder into an <code>i64</code>, which is the way to walk through the digits one by one, here to add them up. <code>TrailingZeros</code> counts zero bits, not decimal zeros.</p>
{{example.bigint-guide-digits}}

<h2 id="guide-parse">Reading and printing in other bases</h2>
<p><code>Parse</code> reads decimal text and reports through its <code>bool</code> argument whether the text was a whole number; an empty string, a stray letter or a trailing space fails. Leading spaces, a sign, Persian digits and <code>_</code> between digits (<code>1_000_000</code>) are accepted. With base 0, <code>ParseBase</code> reads a <code>0x</code>, <code>0b</code> or <code>0o</code> prefix and falls back to decimal. <code>ParseBase</code> and <code>ToStrBase</code> handle bases from 2 to 36, and <code>ToHex</code> is the usual form for keys and hashes. <code>ToIntClamped</code> gives the largest or smallest <code>i64</code> when the value is out of range.</p>
{{example.bigint-guide-parse}}

<h2 id="guide-division">Division, remainders and zero</h2>
<p>There are three ways to divide, and they differ only for negative numbers. <code>Div</code> and <code>Rem</code> round towards zero, as C and Go do. <code>FloorDiv</code> and <code>FloorMod</code> round down, as Python does, so the remainder takes the sign of the divisor. <code>Mod</code> and <code>ModInt</code> always give a remainder from 0 up to the divisor, which is what modular arithmetic and a day-of-week calculation want. <code>DivMod</code> gives the quotient and the remainder from one division, and its <code>bool</code> is the only way to notice a zero divisor.</p>
{{example.bigint-guide-division}}

<h2 id="guide-rsa">Modular arithmetic: a toy RSA</h2>
<p>Public key cryptography is built on <code>ModExp</code>, <code>ModInverse</code> and <code>Gcd</code>. The program below makes an RSA key from two small primes, encrypts a number with the public exponent and decrypts it with the private one. <code>ModInverse</code> fails, through its <code>bool</code>, when the two numbers share a factor.</p>
