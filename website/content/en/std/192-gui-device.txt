pkg.intro <<
<p><code>gui.device</code> reaches the features of a phone that a page cannot draw: the share sheet and more as they are added. Every call has the same signature on every system. On a desktop, or when the phone does not offer the feature, the call returns false or an empty value and the program carries on.</p>
<p><code>Platform</code> names the system the program runs on: <code>android</code>, <code>ios</code> or <code>none</code> on a desktop. <code>CanShare</code> tells whether a share sheet exists, and <code>Share</code> opens it with a text and a link. Either may be empty, but not both. The call returns once the sheet is shown; it does not tell what the user chose.</p>
<p><code>Haptic</code> gives a short system feedback (<code>Tap</code>, <code>Heavy</code>, <code>Success</code> or <code>Failure</code>) and needs no permission. <code>Vibrate</code> runs the motor for a number of milliseconds, at most 5000; on Android the build script adds the <code>VIBRATE</code> permission to the manifest only when the program calls it.</p>
<p>Runtime permissions: <code>CheckPermission</code> answers <code>NotAsked</code>, <code>Granted</code> or <code>Denied</code> at once, and <code>RequestPermission</code> opens the system dialog. The answer arrives later: <code>OnChange</code> sets a function that runs on the UI thread when any request finishes, and a <code>gui.ui</code> app calls <code>ui.Invalidate</code> there and reads <code>CheckPermission</code> in its view. A program that uses <code>gui.window</code> directly receives an <code>EventKind.HostResult</code> event and calls <code>Notify</code>. On Android the manifest must declare the permission: build with <code>--permission camera</code> (also <code>microphone</code>, <code>location</code>, <code>notifications</code>). Without a declaration the request is denied at once. Systems without permissions report <code>Denied</code>.</p>
<p>Notifications: <code>ShowNotification</code> posts one now, <code>ScheduleNotification</code> posts one after a number of seconds, even when the app is not in front, and <code>CancelNotification</code> removes it. The id replaces an earlier notification with the same id. Tapping a notification opens the app. They return false until the <code>Notifications</code> permission is granted (ask with <code>RequestPermission</code> first; from Android 13 it is asked at run time). The build script adds the permission to the manifest when the program shows or schedules a notification. A scheduled notification is inexact and does not survive a restart of the phone.</p>
<p>Location, one fix at a time: <code>RequestLocation</code> asks for the current position and returns at once, <code>LocationStatus</code> says <code>Pending</code>, <code>Ready</code> or <code>Failed</code>, and <code>LastLocation</code> reads the answer. <code>OnChange</code> runs when the fix arrives. The <code>Location</code> permission must be granted first; the build script declares it when the program asks for a location. GPS is used when it is on, the network provider otherwise, and a fix can take several seconds.</p>
<p>Photos: <code>PickPhoto</code> opens the system photo picker and <code>TakePhoto</code> opens the camera app, both without any permission, because the system apps do the work. <code>PhotoStatus</code> says <code>Pending</code>, <code>Ready</code> or <code>Failed</code> (also when the user cancels) and <code>LastPhoto</code> is the path of a JPEG copy in the app cache directory, which <code>image</code> can open. <code>OnChange</code> runs when the picture is ready. The camera app asks for its own permission; if the app declares the camera permission itself (<code>--permission camera</code>) it must be granted before <code>TakePhoto</code>.</p>
<p>App folders: <code>DataDir</code> is the private folder for files the app keeps, <code>CacheDir</code> holds files the system may delete when space runs low, <code>DocumentsDir</code> is the folder the user can reach (the app folder on shared storage on Android, Documents on iOS) and <code>TempDir</code> is for short lived files. Each returns the path of a folder that exists, or an empty string where the system has no such folder. No permission is needed.</p>
<p>Secure storage keeps small secrets such as a login token: <code>SecureSet</code> saves a value under a key, <code>SecureGet</code> reads it back (empty when there is none) and <code>SecureDelete</code> removes it. On Android the value is encrypted with an AES key that never leaves the Android Keystore; on iOS it goes to the Keychain. Keys are up to 200 bytes and values up to 16000 bytes. Where the system has no secure storage, <code>SecureSet</code> and <code>SecureDelete</code> return false and <code>SecureGet</code> returns an empty string.</p>
<p>Calls go through the host layer of the phone shell, so they work in apps built with <code>tools/bash/build-android-app.sh</code>.</p>

doc.Platform = Names the system the program runs on: <code>android</code>, <code>ios</code> or <code>none</code>.
doc.CanShare = Reports whether the system share sheet is available.
doc.Share = Opens the system share sheet with a text and a link, joined on two lines. False when both are empty or the system has no share sheet.
doc.HapticKind = The kind of feedback for <code>Haptic</code>.
doc.HapticKind.Tap = A light tap, like pressing a key.
doc.HapticKind.Heavy = A firmer pulse, like a long press.
doc.HapticKind.Success = A confirmation pulse.
doc.HapticKind.Failure = A rejection pulse.
doc.CanVibrate = Reports whether the system can vibrate or give haptic feedback.
doc.Vibrate = Vibrates for the given milliseconds, at most 5000. False when the number is not positive or the system cannot vibrate.
doc.Haptic = Gives short haptic feedback of the given kind. False when the system has none.
doc.Permission = A permission the app can ask for.
doc.Permission.Camera = Taking pictures.
doc.Permission.Microphone = Recording sound.
doc.Permission.Location = Reading the position of the phone.
doc.Permission.Notifications = Showing notifications (asked at run time from Android 13).
doc.PermissionState = What is known about a permission.
doc.PermissionState.NotAsked = The user has not been asked yet.
doc.PermissionState.Granted = The app may use the feature.
doc.PermissionState.Denied = The user refused, or the system has no such permission.
doc.OnChange = Sets the function that runs on the UI thread after a permission request or another host answer arrives. <code>gui.ui</code> apps get it called by the event loop.
doc.Notify = Runs the function set by <code>OnChange</code>. <code>gui.ui</code> calls it for you; call it yourself from a <code>HostResult</code> event of <code>gui.window</code>.
doc.CheckPermission = Returns the state of a permission without asking.
doc.RequestPermission = Opens the system dialog for a permission. Returns false when the system has no such permission or it is not declared; the answer comes through <code>OnChange</code>.
doc.ShowNotification = Posts a notification now with an id, a title and a body. False when notifications are not allowed, both texts are empty or the system has none.
doc.ScheduleNotification = Posts a notification after the given seconds, even if the app is closed by then. False when the seconds are not positive or notifications are not allowed.
doc.CancelNotification = Removes the notification with the id and cancels it if it is still scheduled.
doc.LocationState = Where a location request stands.
doc.LocationState.Idle = No request was made.
doc.LocationState.Pending = A fix is being looked for.
doc.LocationState.Ready = A fix arrived; read it with <code>LastLocation</code>.
doc.LocationState.Failed = No fix could be made: the permission is missing or no provider is on.
doc.Location = One position fix.
doc.Location.latitude = Degrees north of the equator.
doc.Location.longitude = Degrees east of the prime meridian.
doc.Location.accuracy = The error radius in meters, 0 when unknown.
doc.RequestLocation = Starts a one shot location request. False when the system has no location or the permission is missing.
doc.LocationStatus = Returns the state of the last request.
doc.LastLocation = Returns the last fix, zeros before the first one.
doc.PhotoState = Where a photo request stands.
doc.PhotoState.Idle = No request was made.
doc.PhotoState.Pending = The picker or camera is open.
doc.PhotoState.Ready = A photo was saved; read its path with <code>LastPhoto</code>.
doc.PhotoState.Failed = The user cancelled or the system has no picker or camera.
doc.PickPhoto = Opens the system photo picker. False when the system has none; the answer comes through <code>OnChange</code>.
doc.TakePhoto = Opens the camera app to take one picture. False when the system has none; the answer comes through <code>OnChange</code>.
doc.PhotoStatus = Returns the state of the last photo request.
doc.LastPhoto = Returns the path of the last photo, empty before the first one.
doc.DataDir = Returns the private folder for the files the app keeps. Empty where the system has none.
doc.CacheDir = Returns the folder for files the system may delete when space is low. Empty where the system has none.
doc.DocumentsDir = Returns the folder the user can reach: the app folder on shared storage on Android, Documents on iOS. Empty where the system has none.
doc.TempDir = Returns the folder for short lived files. Empty where the system has none.
doc.SecureSet = Saves a value under a key in the Android Keystore backed storage or the iOS Keychain. False when the key is empty or longer than 200 bytes, the value is longer than 16000 bytes or the system has no secure storage.
doc.SecureGet = Returns the value saved under the key, or an empty string when there is none.
doc.SecureDelete = Removes the value saved under the key. False when there was none or the system has no secure storage.
