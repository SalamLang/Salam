pkg.intro <<
<p>A page often has to talk to a server: send a form, ask for new chat messages, let the visitor copy an answer. This package does those jobs from event handlers and component code. A request does not stop the page: the call returns at once, and later your function receives the status number and the response text. State that the function changes is drawn again, also inside a component that is one row of a list.</p>
<p>Things that catch people out:</p>
<ul>
<li><strong>Status 0 means there was no answer</strong>: the network failed, the time limit passed, or the browser refused to hand over the response. An answer such as 404 or 500 keeps its own status and text.</li>
<li><strong>Other sites must allow you.</strong> The browser's cross origin rules apply, so a server on another address has to send <code>Access-Control-Allow-Origin</code>, and a JSON request is announced first with an <code>OPTIONS</code> request that the server has to answer. Cookies are not sent to other sites.</li>
<li><strong>The body is not sent with GET or HEAD</strong>, and the content type is only sent together with a body.</li>
<li><strong>Call these from events</strong>, such as <code>click</code>, or from functions they call. A call in code that runs on every drawing of the page repeats the request each time. While a page is prepared ahead of time, requests and copying do nothing and <code>QueryParam</code> gives an empty text.</li>
<li><strong>A removed list row should not wait for answers.</strong> If the row that sent a request is deleted before the answer arrives, a new row can take its place in the page's memory and receive that change.</li>
</ul>

<h2 id="guide-form">Sending a form</h2>
<p>Build the body as JSON text with <a href="/std/encoding/json/">encoding.json</a>, send it with <code>PostJson</code>, and decide what to show from the status. The page below also reads <code>?ref=</code> from its own address and offers to copy the message. Replace the address with that of your server.</p>
{{example.web-browser-Register}}

<h2 id="guide-poll">Asking again later</h2>
<p>Waiting and repeating are done with <code>SetTimeout</code> and <code>SetInterval</code> from <a href="/std/dom/">dom</a>. This page asks until the server answers with 200, two seconds apart, and uses <code>Request</code> for another method.</p>
{{example.web-browser-Poll}}

<h2 id="guide-native">Outside the browser</h2>
<p>In a native build the same code sends the request with <a href="/std/net/http/">net.http</a> and calls your function before the call returns, so the window waits for the answer: give a short time limit. Copying uses <code>gui.clipboard</code>, and <code>QueryParam</code> is empty because there is no address. The timers of <a href="/std/dom/">dom</a> are only available in the browser. In an app with a <code>pages</code> folder, <code>page.route.Query</code> reads the query of the current route; to take apart any query text use <a href="/std/nav/">nav</a>.</p>
>>

doc.Request = Sends an HTTP request: method, address, body, content type, time limit in milliseconds (0 for none) and the function that receives the status and the response text. The status is 0 when there is no answer.
doc.Get = Asks for an address with GET; the function receives the status and the response text.
doc.PostJson = Sends JSON text with POST and the content type <code>application/json</code>.
doc.CopyText = Puts a text on the clipboard. The second form tells your function whether it worked; a browser only allows it on a secure page, usually right after a click.
doc.QueryParam = The value of a name in the query of the page's own address, such as <code>ref</code> in <code>?ref=ali</code>; an empty text when it is missing.
