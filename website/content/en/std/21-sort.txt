pkg.intro <<
<p>The <code>sort</code> package orders a <code>Vector</code> and searches one that is already in order. For most work two functions are enough: <code>Sort</code> for numbers and strings, and <code>SortBy</code> when you decide yourself what "smaller" means, students by their marks for instance. Every function is generic, so it works for any element type that supports <code>&lt;</code>, or for any type at all with a comparison of your own. For containers that stay sorted as you add to them (an ordered map, a priority queue) see <a href="/std/collections/">collections</a>; for the median and percentiles of numbers see <a href="/std/stats/">stats</a>.</p>
<p>The functions sort the vector in place. <code>Sorted</code> and <code>SortedBy</code> return a sorted copy instead and leave the original alone; free the copy when you are done with it. The functions named after an algorithm (quick, merge, bubble and the rest) all give the same order and are here mostly for teaching and comparing; <code>Sort</code> is an introsort, which stays fast on any input.</p>
<p>What people get wrong:</p>
<ul>
<li>Assuming the order of equal elements is kept. <code>Sort</code>, <code>SortDesc</code>, <code>SortBy</code> and <code>SortIndex</code> are not stable. Use <code>StableSortBy</code> when it matters.</li>
<li>Using <code>SortBy</code> on data with few distinct keys. It is a plain quick sort, and when many elements compare equal (sorting 100,000 orders by a status with three values) it slows down to quadratic time. <code>StableSortBy</code> is a merge sort and stays fast there.</li>
<li>Searching an unsorted vector. <code>BinarySearch</code>, <code>LowerBound</code> and <code>UpperBound</code> return wrong answers without any error when the vector is not sorted the same way.</li>
<li>Calling <code>Min</code> or <code>Max</code> on an empty vector. They read element 0 and stop the program.</li>
</ul>

<h2 id="guide-records">Sort records by several fields</h2>
<p>Real data is a vector of structs, and the order has more than one rule: team first, then the highest salary, then the name. Write those rules in one comparison function that returns true when <code>a</code> should come before <code>b</code>, and pass it to <code>SortBy</code>. Compare the first field, and only when it is equal move on to the next. To sort descending on a field, swap the comparison for that field only.</p>
{{example.sort-guide-records}}
<p><code>SortBy</code> does not promise to keep equal elements in their old order, which is why the comparison above goes all the way down to the name: with a full tie-break the result is the same however the sort works. <code>SortedBy</code> returns a sorted copy and leaves the original order alone. <code>IsSortedBy</code> checks an order, which is handy in a test or before a binary search.</p>

<h2 id="guide-stable">Sort by one column after another</h2>
<p>A table that the user sorts by date and then by status should show each status group still in date order. <code>StableSortBy</code> keeps equal elements in the order they arrived, so sorting by the secondary key first and the primary key second gives exactly that. It is a merge sort: it always takes n log n steps and needs a second buffer the size of the vector.</p>
{{example.sort-guide-stable}}
<p>Dates written as <code>YYYY-MM-DD</code> sort correctly as plain text, which is why the example compares them with <code>&lt;</code>. The same trick fails for <code>D/M/YYYY</code>.</p>

<h2 id="guide-leaderboard">Rank one list by another</h2>
<p>When the data lives in parallel vectors, such as names, scores and wins, sorting one of them would break the link with the others. <code>SortIndex</code> and <code>SortIndexDesc</code> sort a vector of positions instead and leave the data where it is; you then read every vector through those positions. The keys must be a <code>Vector&lt;f64&gt;</code> and both vectors are passed by reference, so declare them with <code>mut</code>. Fill the positions with 0 to n-1 first.</p>
{{example.sort-guide-leaderboard}}

<h2 id="guide-ranges">Search a sorted vector</h2>
<p>Once a vector is sorted, finding things in it is fast. <code>LowerBound</code> gives the first position not below a value and <code>UpperBound</code> the first position above it, so the two together give a price range, the count of one value, or the place where a new value keeps the order. <code>BinarySearch</code> returns the index of a value or -1. All three assume the vector is already sorted; on an unsorted vector they return wrong answers without any error.</p>
{{example.sort-guide-ranges}}

<h2 id="guide-unique">Distinct words and custom orders for strings</h2>
<p>Sorting puts equal values next to each other, so removing duplicates is one pass that skips a word equal to the last one kept. <code>SortBy</code> with a lambda gives any other order, here the longest words first and alphabetical among equal lengths. <code>SortDesc</code> sorts in reverse.</p>
{{example.sort-guide-unique}}

<h2 id="guide-persian">Persian alphabetical order</h2>
<p><code>Sort</code> compares strings byte by byte, which is the order of Unicode code points. For Persian that order is wrong: <em>پ</em>, <em>چ</em>, <em>ژ</em>, <em>ک</em> and <em>گ</em> were added to Unicode after the Arabic letters and sort after <em>و</em>, and <em>ه</em> comes before <em>و</em>. A comparison that looks each letter up in the Persian alphabet fixes it.</p>
{{example.sort-guide-persian}}
<p>The comparison reads two bytes at a time, which is right for Persian letters only. Names with spaces, the zero-width non-joiner or Latin letters need a fuller comparison that walks the text letter by letter.</p>

doc.Swap = Exchanges two elements of a vector.
doc.SortBy = Sorts the vector with the comparison function <code>less</code>; <code>less(a, b)</code> has to return true when a should come before b. It is a quick sort and not stable, and it becomes slow when many elements compare equal; use <code>StableSortBy</code> then.
doc.StableSortBy = Like <code>SortBy</code>, but equal elements keep the order they were in; in the example Sara stays before Reza because she came first. A merge sort: n log n on any input, with a temporary copy of the vector.
doc.SortedBy = A sorted copy, using your own comparison (with <code>SortBy</code>, so not stable). The original is unchanged.
doc.IsSortedBy = True when the vector is sorted according to the comparison function.
doc.BucketSort = Bucket sort for whole numbers; fast when the numbers are spread evenly over a range.
doc.CountingSort = Counting sort for whole numbers; very fast when the range of values is small. It allocates one counter for every value between the smallest and the largest, so a wide range uses a lot of memory.
doc.RadixSort = Radix sort for whole numbers; it sorts digit by digit and makes no comparisons.
doc.PancakeSort = Pancake sort, which sorts using nothing but reversals of a prefix. For teaching.
doc.CombSort = Comb sort, an improved bubble sort.
doc.BubbleSort = Bubble sort: simple and slow, for teaching.
doc.BinarySearch = Finds <code>x</code> in a <em>sorted</em> vector by binary search, or returns minus one when it is not there. With duplicates it returns one of their positions, not necessarily the first; use <code>LowerBound</code> for the first.
doc.LowerBound = The first position whose element is not less than <code>x</code>: where <code>x</code> would be inserted to keep the vector sorted.
doc.UpperBound = The first position whose element is greater than <code>x</code>. The distance between the upper and the lower bound is how many times <code>x</code> occurs.
doc.SortIndex = Instead of sorting the data, sorts the indices in <code>idx</code> by <code>keys</code> (a <code>Vector&lt;f64&gt;</code>) in ascending order. Use it when several vectors share an order and you want to see all of them sorted together. Not stable.
doc.SortIndexDesc = Like <code>SortIndex</code>, descending; it sorts ascending and reverses, so tied keys come out in reverse.
doc.OddEvenSort = Odd-even sort, designed for parallel processing.
doc.GnomeSort = Gnome sort: like insertion sort, simple and slow.
doc.SelectionSort = Selection sort, which brings the smallest remaining element forward each time.
doc.HeapSort = Heap sort: always fast, n log n, and needs no extra memory.
doc.MergeSort = Merge sort: always fast and stable, but it needs extra memory.
doc.ShellSort = Shell sort, a faster insertion sort.
doc.InsertionSort = Insertion sort, very good on small or nearly sorted vectors.
doc.BinaryInsertionSort = An insertion sort that finds the insertion point by binary search.
doc.IntroSort = Introsort: it starts as a quick sort and switches to a heap sort when it has to, so it never degrades.
doc.IsSorted = True when the vector is sorted in ascending order.
doc.Reverse = Reverses the order of the vector's elements.
doc.Min = The smallest element of the vector. The vector must not be empty.
doc.Max = The largest element of the vector. The vector must not be empty.
doc.Sort = Sorts the vector in ascending order with an introsort: n log n on any input, not stable. The default choice for sorting. Strings are compared byte by byte.
doc.SortDesc = Sorts the vector in descending order: an ascending sort followed by a reverse.
doc.Sorted = An ascending sorted copy of the vector; the original is unchanged.
doc.QuickSort = Quick sort, the fastest in practice for random data; it can become slow on many equal values.
doc.CocktailSort = Cocktail sort, a bubble sort that runs left to right and back again on each pass.
