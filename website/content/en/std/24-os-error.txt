pkg.intro <<
<p>When an operation in the <a href="/std/fs/file/">fs.file</a>, <a href="/std/fs/dir/">fs.dir</a>, <a href="/std/os/process/">os.process</a> or <a href="/std/os/temp/">os.temp</a> packages fails, it records a short report here: a code, a message, the operation and the path. Call <code>Clear</code>, run the operation, then ask <code>HasError</code> and <code>Last</code>. It is a single global record, like C's <code>errno</code>, not a returned value.</p>
<p>The plain functions of the <a href="/std/os/">os</a> package do not record anything here; they only return -1. This package is a different thing from the general-purpose <a href="/std/error/">error</a> package, which builds error values to return from your own functions; prefer that for new code that is not about files or processes.</p>
<p>Know what the standard packages actually record before you branch on it:</p>
<div class="table-wrap"><table>
<thead><tr><th>Code</th><th>Recorded by</th></tr></thead>
<tbody>
<tr><td><code>IOError</code></td><td>Almost every failure: <code>fs.dir</code> (<code>Mkdir</code>, <code>MkdirAll</code>, <code>Remove</code>, <code>RemoveAll</code>, <code>Copy</code>, <code>Move</code>), <code>fs.file</code> (<code>AtomicWrite</code>, <code>Copy</code>, <code>Move</code>) and <code>os.temp</code></td></tr>
<tr><td><code>FileNotFound</code></td><td>Only <code>fs.file.Delete</code>, for any failure to delete, a missing permission included</td></tr>
<tr><td><code>ProcessFailed</code></td><td><code>os.process</code>, when a program cannot be started</td></tr>
<tr><td>the others</td><td>Nothing in the standard library yet; they are there for your own <code>Set</code> calls</td></tr>
</tbody>
</table></div>
<p>Reads and plain writes such as <code>fs.file.ReadText</code> and <code>WriteText</code> record nothing; check their results instead. The messages are fixed English phrases such as <code>delete failed</code>, not the system's reason, and <code>system_code</code> is filled in only by <code>os.process</code>.</p>
<h2 id="guide-check">Check an operation and explain the failure</h2>
<p>The usual pattern has three steps: call <code>Clear</code>, run the operation, then ask <code>HasError</code>. <code>Last</code> returns an <code>OSError</code> with the code to branch on, the path that failed and the name of the operation, which is enough to turn the failure into a message a person understands.</p>
{{example.os-error-guide-explain}}
<p>Compare <code>code</code> with the constants of this package, never <code>message</code>: the message is meant for people and may change between releases.</p>

<h2 id="guide-clear">Errors stay until you clear them</h2>
<p>A failed call records an error, but a successful call does not remove it. So <code>HasError</code> after a good call can still be true because of something that failed much earlier. Call <code>Clear</code> just before the operation you want to check.</p>
{{example.os-error-guide-clear}}
<p>The record is a single global value for the whole program, so it is not a safe channel between threads: a failure in one thread can overwrite another thread's error before it is read. Check the error in the same thread, right after the call.</p>

<h2 id="guide-own">Report errors from your own functions</h2>
<p><code>Set</code> records an error the same way the standard packages do. A helper that reads files can use it, and its callers then check it with the same <code>HasError</code> and <code>Last</code> they use everywhere else. Pass the name of your function as the operation and the file as the path, so the message says where things went wrong.</p>
{{example.os-error-guide-own}}

<h2 id="guide-process">A program that will not start</h2>
<p>The <a href="/std/os/process/">os.process</a> package records <code>ProcessFailed</code> here when it cannot start a program at all, for example when the path is wrong. That is different from a program that starts and then exits with a non-zero code: then there is no error here, and you read the code from <code>Wait</code>.</p>
{{example.os-error-guide-process}}
<p>The <code>system_code</code> field holds the operating system's own number when the package knows it: the <code>posix_spawnp</code> result on Unix and <code>GetLastError</code> on Windows, from <code>os.process</code> only. Everywhere else it is zero. It is useful in logs; branch on <code>code</code>.</p>
>>

doc.None = No error.
doc.FileNotFound = The file or directory was not found. In the standard library only <code>fs.file.Delete</code> records it, for any failed delete.
doc.PermissionDenied = Access is not allowed. No standard package records it yet; a denied operation shows up as <code>IOError</code>.
doc.AlreadyExists = It is already there. Not recorded by the standard packages; for your own <code>Set</code> calls.
doc.InvalidPath = The path is not valid. Not recorded by the standard packages; for your own <code>Set</code> calls.
doc.NotSupported = This system does not support the operation. Not recorded by the standard packages.
doc.IOError = A read, write or file system error: the code most failures in <code>fs.dir</code>, <code>fs.file</code> and <code>os.temp</code> record.
doc.Timeout = Time ran out. Not recorded by the standard packages.
doc.ProcessFailed = Running the process failed.
doc.OSError = The detail of an error.
doc.OSError.code = The error code; one of the constants above.
doc.OSError.message = A short fixed English phrase such as <code>mkdir failed</code>; it does not carry the system's reason.
doc.OSError.operation = The name of the function that failed.
doc.OSError.path = The path that had the problem.
doc.OSError.system_code = The operating system's own error number when known; only <code>os.process</code> fills it in, everywhere else it is 0.
doc.Set = Records an error, replacing the previous one, for when you are writing a package of your own and want to report through the same mechanism.
doc.Clear = Clears the recorded error, before an operation whose error you want to check on its own.
doc.Last = The last recorded error with all its detail; a successful call does not reset it.
doc.LastCode = The code of the last error.
doc.LastMessage = The message of the last error.
doc.HasError = True when an error has been recorded since the last <code>Clear</code>.
