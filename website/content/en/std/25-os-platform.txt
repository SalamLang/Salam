pkg.intro <<
<p>The <code>os.platform</code> package says at run time what system the program is on: the operating system, the processor family, the number of cores and the amount of memory. Use it for reports and logs, for automatic settings such as a worker count or a cache size, and for small per-system differences such as a file extension. For code that only compiles on one system, use the constants such as <code>SALAM_OS_WINDOWS</code> and <a href="/learn/compile-time/">conditional compilation</a> instead. For the user and their home folder see <a href="/std/os/user/">os.user</a>; for environment variables, <a href="/std/env/">env</a>.</p>
<p>The <code>Is...</code> functions, <code>OS</code> and <code>Arch</code> are fixed when the program is compiled, so they cost nothing to call. The hardware questions are asked of the running system, and how they are answered differs:</p>
<div class="table-wrap"><table>
<thead><tr><th>Function</th><th>Linux</th><th>macOS and BSD</th><th>Windows</th></tr></thead>
<tbody>
<tr><td><code>CpuCount</code></td><td><code>sysconf</code>, instant</td><td>runs <code>sysctl</code></td><td>the <code>NUMBER_OF_PROCESSORS</code> variable</td></tr>
<tr><td><code>TotalMemory</code></td><td><code>/proc/meminfo</code></td><td>runs <code>sysctl</code></td><td>runs PowerShell, often a second or more</td></tr>
<tr><td><code>AvailableMemory</code></td><td><code>/proc/meminfo</code></td><td>not known, -1</td><td>runs PowerShell</td></tr>
</tbody>
</table></div>
<p>What people get wrong: calling the memory functions in a loop (on Windows each call starts PowerShell, so ask once and keep the number), forgetting that every hardware function returns -1 when it cannot find out, and treating <code>CpuCount</code> as physical cores. It counts the logical processors online, hyper-threads included, and inside a container it counts the whole machine.</p>
<p>The programs below print whether a rule held rather than the raw numbers, so their output is the same on any machine.</p>

<h2 id="guide-workers">Choose how many workers to run</h2>
<p>Work that splits into independent pieces, such as resizing images, goes faster with one thread or process per core. <code>CpuCount</code> gives the number of cores; keep the result between one and a limit of your own, because a machine with 128 cores does not mean your job wants 128 threads.</p>
{{example.os-platform-guide-workers}}
<p>Inside a container the count is the whole machine's, not the share the container may use. If the program runs under Docker or Kubernetes, let a flag or an environment variable override it.</p>

<h2 id="guide-memory">Size a cache from the system memory</h2>
<p><code>TotalMemory</code> and <code>AvailableMemory</code> return bytes as an <code>i64</code>. A cache can take a fraction of the total memory, kept between a floor and a ceiling, and never more than half of what is free right now. <code>AvailableMemory</code> returns minus one on systems where it is not known, so check for that before using it.</p>
{{example.os-platform-guide-memory}}

<h2 id="guide-dispatch">Small differences between systems</h2>
<p>Most differences between systems are small: Windows programs end in <code>.exe</code>, and each desktop opens a file with a different command. A function that asks <code>IsWindows</code> or <code>IsMac</code> and returns the right piece keeps the rest of the program free of such checks.</p>
{{example.os-platform-guide-dispatch}}

<h2 id="guide-compile">Run time or compile time</h2>
<p>The functions of this package are answered when the program runs, so both branches of an <code>if</code> are compiled on every system. That fails when one branch calls a function that only exists on one system, such as a Windows API. Then use the constant itself: a plain <code>if SALAM_OS_WINDOWS:</code> is decided while compiling and the other branch is left out. See <a href="/learn/compile-time/">compile-time code</a> for the full list of constants.</p>
{{example.os-platform-guide-compile}}

doc.IsLinux = True on Linux.
doc.IsWindows = True on Windows.
doc.IsMac = True on macOS.
doc.IsBSD = True on the BSD family.
doc.IsFreeBSD = True on FreeBSD.
doc.IsAndroid = True on Android.
doc.IsWasm = True when the program was compiled to WebAssembly.
doc.OS = The name of the operating system: <code>linux</code>, <code>mac</code>, <code>windows</code>, <code>freebsd</code>, <code>android</code>, <code>wasm</code> or <code>unknown</code>. Fixed at compile time.
doc.IsX64 = True on a 64-bit Intel or AMD processor.
doc.IsArm64 = True on a 64-bit ARM processor, such as Apple silicon.
doc.IsX86 = True on a 32-bit Intel processor.
doc.IsArm = True on a 32-bit ARM processor.
doc.Arch = The name of the processor architecture: <code>x64</code>, <code>arm64</code>, <code>x86</code>, <code>arm</code>, <code>wasm</code> or <code>unknown</code>.
doc.CpuCount = The number of logical processors online (hyper-threads count), for deciding how many things to do at once; -1 when it cannot be found. In a container it is the whole machine's count.
doc.TotalMemory = The system's total memory in bytes, or -1 when unknown. On Windows each call runs PowerShell, so call it once.
doc.AvailableMemory = The memory available to new programs in bytes (<code>MemAvailable</code> on Linux). Supported on Linux and Windows only; elsewhere it returns minus one. On Windows each call runs PowerShell.
