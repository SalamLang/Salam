pkg.import = os.dl
pkg.intro <<
<p>Most programs link their libraries when they are built. This package is for the other case: the library is chosen while the program runs. <code>Open</code> loads a shared library (<code>dlopen</code>), <code>Sym</code> finds a function or a variable in it by name (<code>dlsym</code>), and <code>Call</code> calls the function pointer you get, with up to eight integer or pointer arguments, and returns the integer or pointer it returns. <code>OpenSelf</code> opens the running program itself, which gives you the C library and everything else already loaded. It is the basis for plug-ins, for probing optional libraries and for tools that load a function they have just written into <a href="/std/os/mmap/">executable memory</a>.</p>
<p>Arguments and the result are <code>size</code>, an integer as wide as a pointer (64 bits on a 64 bit system). Pass a pointer by converting it, <code>(p as void*) as size</code>, and turn a returned pointer back with <code>r as void*</code>. A small integer is passed as it is. The package works on Linux, macOS and the BSDs; on Windows <code>Supported</code> is false and the functions return empty results.</p>
<p>What people get wrong:</p>
<ul>
<li>Calling something that is not a function, or a function with the wrong number of arguments. <code>Call</code> cannot check that; a wrong pointer or a wrong count crashes the program or returns garbage. Give exactly the arguments the C function takes.</li>
<li>Calling a function that takes or returns a floating point number, a struct by value, or a variable argument list such as <code>printf</code>. Those use other registers or a different calling convention. Only integer and pointer arguments are supported.</li>
<li>Not checking for <code>null</code>. <code>Open</code> and <code>Sym</code> return <code>null</code> when the library or the symbol is missing, and <code>Call</code> on <code>null</code> returns 0; ask <code>Error</code> why.</li>
<li>Using a symbol after <code>Close</code>. Once the last user of a library closes it, its code is gone and a stale pointer crashes.</li>
<li>More than 8 arguments: <code>Call</code> refuses and returns 0.</li>
</ul>
>>

doc.Supported = True where dynamic loading works (every system except Windows).
doc.Open = Loads the shared library at <code>path</code> (a name such as <code>libm.so.6</code> is searched for by the system) and returns its handle, or <code>null</code>.
doc.OpenSelf = Opens the running program, so <code>Sym</code> can find the C library and anything else already loaded. <code>null</code> where it is not supported.
doc.Sym = The address of the function or variable called <code>name</code> in the library, or <code>null</code>. Use <code>null</code> checks, not exceptions.
doc.Close = Gives the library back; true on success. Do not use its symbols afterwards.
doc.Error = The system's text for the last failure of <code>Open</code> or <code>Sym</code>, or an empty string.
doc.Call = Calls the function at <code>fn</code> with the integer and pointer arguments in <code>args</code> (0 to 8 of them) and returns its integer or pointer result. A <code>null</code> pointer or more than 8 arguments gives 0. The arguments are passed in exactly the registers and stack slots a C compiler would use.
