pkg.intro <<
<p>Ordinary allocation (<a href="/std/mem/">mem.Allocate</a>) gives memory you can read and write. This package gives you whole pages straight from the operating system and lets you choose what the program may do with them: <code>PROT_READ</code>, <code>PROT_WRITE</code> and <code>PROT_EXEC</code>, combined with <code>|</code>. <code>Alloc</code> maps zero-filled pages, <code>Protect</code> changes the permissions (<code>mprotect</code>) and <code>Free</code> unmaps them. Use it for guard pages, for read-only data that must not change by accident, and for loading machine code: write the bytes while the page is writable, switch it to read and execute, then call it with <a href="/std/os/dl/">os/dl</a>.</p>
<p>Sizes are rounded up to whole pages by the system; <code>PageSize</code> tells the page size (usually 4096, 16384 on Apple silicon). The package works on Linux, macOS and the BSDs. On Windows <code>Supported</code> is false and <code>Alloc</code> returns <code>null</code>.</p>
<p>What people get wrong:</p>
<ul>
<li>Asking for write and execute together. Several systems refuse it (SELinux, hardened kernels, macOS on Apple silicon, which also needs a special <code>MAP_JIT</code> flag this package does not set). Do it in two steps: map as <code>PROT_READ | PROT_WRITE</code>, fill, then <code>Protect</code> to <code>PROT_READ | PROT_EXEC</code>.</li>
<li>Passing a different size to <code>Free</code> or <code>Protect</code> than to <code>Alloc</code>. Use the same size; the permissions of whole pages change.</li>
<li>Using the memory after <code>Free</code>, or writing to a page that is now read-only. Both crash the program at once.</li>
<li>Machine code is only valid for one processor family. Code written for x86-64 will not run on an ARM computer, and some ARM systems need the instruction cache flushed after the code is written.</li>
</ul>
<h2 id="guide-jit">Running a few machine instructions</h2>
<p>The example below maps a page, writes seven bytes of x86-64 code that add up its first two arguments, makes the page executable and calls it. It only runs on a 64 bit x86 system, which the example checks with <code>SALAM_ARCH_X64</code>.</p>

>>

doc.PROT_NONE = Permission value: the pages may not be touched.
doc.PROT_READ = Permission value: the pages may be read.
doc.PROT_WRITE = Permission value: the pages may be written.
doc.PROT_EXEC = Permission value: the pages may be run as machine code.
doc.Supported = True where memory mapping works (every system except Windows).
doc.PageSize = The size of one memory page in bytes.
doc.Alloc = Maps <code>size</code> bytes (rounded up to whole pages) of zero-filled private memory with the given permissions and returns its address, or <code>null</code> when it fails, when <code>size</code> is not positive and on Windows.
doc.Protect = Changes the permissions of the pages that hold <code>size</code> bytes from <code>p</code>; true on success. <code>p</code> must be the address of a page, as returned by <code>Alloc</code>.
doc.Free = Unmaps the pages; true on success. The memory must not be used afterwards.
