pkg.intro <<
<p>The <code>os.process</code> package runs another program directly, with no shell in between. The program's path and its arguments are given separately, so nothing has to be quoted and spaces or special characters in an argument cause no trouble.</p>
<p>If you need the program's output, run it with <code>StartCaptured</code>, wait for it to finish and then read the output. Call <code>Cleanup</code> when you are done.</p>
<h2 id="guide-args">Pass arguments exactly as they are</h2>
<p>Each element of the argument vector reaches the program as one argument, byte for byte. Spaces, quotes, a <code>$</code> or a <code>;</code> mean nothing special, because no shell reads them. That makes this package the safe way to pass file names and other text that came from a user.</p>
{{example.os-process-guide-args}}
<p>The program name is looked up on the <code>PATH</code> like in a terminal, so <code>printf</code> works without a full path. The vector does not include the program name itself; the package adds it.</p>

<h2 id="guide-exitcode">Exit code, output and error output</h2>
<p>A program reports success with exit code zero and anything else on failure, and it writes its complaints to the error output. After <code>Wait</code>, read both: <code>ReadStdout</code> for the results and <code>ReadStderr</code> for the reason it failed. Call <code>Cleanup</code> after reading, because the captured output is kept in temporary files until then.</p>
{{example.os-process-guide-exitcode}}

<h2 id="guide-parallel">Run several programs at once</h2>
<p><code>StartCaptured</code> returns as soon as the program has started, so you can start several and wait for them afterwards. The total time is about that of the slowest one rather than the sum of all. Waiting in the order you started them keeps the output in a fixed order, even when a later job finished first.</p>
{{example.os-process-guide-parallel}}
<p>Keep the number of programs you run at once reasonable; <a href="/std/os-platform/">os.platform</a>'s <code>CpuCount</code> is a good limit for work that keeps the processor busy.</p>

<h2 id="guide-helper">A helper that runs a program and returns its output</h2>
<p>Most programs need the same few lines every time: start, check that it started, wait, read, clean up. Put them in one function. A <code>defer</code> right after the start makes sure <code>Cleanup</code> runs on every way out of the function, and an out-parameter tells the caller whether the program succeeded.</p>
{{example.os-process-guide-helper}}

doc.Process = A process, running or finished.
doc.Process.pid = The process id.
doc.Process.handle = The process handle on Windows.
doc.Process.running = True while it is still running.
doc.Process.exit_code = The exit code, once it has finished.
doc.Process.stdout_path = The temporary file holding the captured output.
doc.Process.stderr_path = The temporary file holding the captured error output.
doc.Start = Runs a program with its arguments and does not wait; its output goes straight to your own program's output.
doc.StartCaptured = Like <code>Start</code>, but captures the program's output and error output for you to read later.
doc.WaitPid = Waits for the process with this id to finish and returns its exit code.
doc.Wait = Waits for the process to finish and returns its exit code.
doc.Fork = Splits the current process in two: it returns zero in the child and the child's id in the parent. On Unix systems only; its example is not run here.
doc.ExitNow = Ends the process immediately with no cleanup at all, for finishing a child after <code>Fork</code>.
doc.Kill = Kills the process at once (SIGKILL).
doc.Terminate = Asks the process to finish gracefully (SIGTERM) so it has a chance to clean up. On Windows it is the same as <code>Kill</code>.
doc.ReadStdout = Reads the captured output once the process has finished.
doc.ReadStderr = Reads the captured error output.
doc.Cleanup = Removes the temporary capture files.
doc.ExitCode = The process's exit code.
doc.Pid = The process id.
doc.IsRunning = True while the process is still running.
