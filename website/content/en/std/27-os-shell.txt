pkg.intro <<
<p>The <code>os.shell</code> package runs a command, waits for it and gives back the whole result at once in a <code>CmdResult</code>: the exit code, the standard output and the error output. It is a thin layer over <a href="/std/os/process/">os.process</a> (<code>StartCaptured</code>, <code>Wait</code>, read, <code>Cleanup</code>) for the common case where you want all three and do not need to run anything in parallel. Compared with <code>os.RunCapture</code> in <a href="/std/os/">os</a>, it also captures the error output and, through <code>Run</code>, passes arguments without a shell.</p>
<p>The three functions differ in who reads the command:</p>
<div class="table-wrap"><table>
<thead><tr><th>Function</th><th>Shell</th><th>Arguments</th><th>Result</th></tr></thead>
<tbody>
<tr><td><code>Run(program, args)</code></td><td>none</td><td>a vector, passed exactly</td><td><code>CmdResult</code>; code -1 when the program cannot start</td></tr>
<tr><td><code>Exec(command)</code></td><td>none</td><td>the string split on single spaces</td><td><code>CmdResult</code></td></tr>
<tr><td><code>System(command)</code></td><td><code>/bin/sh -c</code>, or <code>cmd</code> on Windows</td><td>the shell parses them</td><td>exit code only; output goes to the screen</td></tr>
</tbody>
</table></div>
<div class="note"><p><code>Exec</code> splits the command on spaces alone and no shell is involved: pipes (<code>|</code>), redirection (<code>&gt;</code>), quoting and tabs do not work. For those, call <code>sh -c</code> through <code>Run</code>, as the first example does.</p></div>
<p>Every call waits for the command to finish, with no timeout, and keeps the whole output in memory. The command gets an empty standard input, so a tool that asks a question reads end of file.</p>
<h2 id="guide-pipe">Pipes and redirection through sh</h2>
<p>For a pipeline, hand the whole script to <code>sh -c</code>. Wrapping that in a small function keeps the call sites short, and the result still has all three parts: the code of the last command, the output and the error output.</p>
{{example.os-shell-guide-pipe}}
<p>Only put text you wrote yourself into such a script. Values from users belong in separate arguments of <code>Run</code>, where no shell can read them.</p>

<h2 id="guide-lines">Work with the output line by line</h2>
<p>Most tools print one item per line. Trim the output, split it on newlines and handle each line. The program below lists the current directory with <code>ls</code> and picks out the CSV files.</p>
{{example.os-shell-guide-lines}}
<p>To list files in a real program, prefer <a href="/std/fs/dir/">fs.dir</a> or <a href="/std/os/">os</a>: they need no external program and they work the same on Windows. Running a tool is the right choice when the tool does the real work, such as <code>git</code> or <code>ffmpeg</code>.</p>

<h2 id="guide-check">Check whether a command worked</h2>
<p>A command that fails returns a non-zero code and usually says why in the error output. Check <code>code</code> first; <code>err</code> is for the message you show or log. A program that cannot be found at all comes back with code -1 instead of stopping your program, and the reason is in <a href="/std/os/error/">os.error</a>.</p>
{{example.os-shell-guide-check}}
<p>The exact codes and messages belong to each tool and differ between systems: <code>ls</code> returns 2 for a missing folder on Linux and 1 on macOS. Test for zero or non-zero unless the tool documents its codes.</p>

<h2 id="guide-quote">Exec does not understand quotes</h2>
<p><code>Exec</code> only splits on spaces, so quotes stay in the text and a quoted phrase still becomes two arguments. When an argument contains a space, use <code>Run</code> with the arguments in a vector, or let <code>sh -c</code> read the quotes.</p>
{{example.os-shell-guide-quote}}
<div class="table-wrap"><table>
<thead><tr><th>Need</th><th>Use</th></tr></thead>
<tbody>
<tr><td>A simple command with no quotes or special characters</td><td><code>Exec</code></td></tr>
<tr><td>Arguments with spaces or text from users</td><td><code>Run</code> with a vector</td></tr>
<tr><td>Pipes, redirection, <code>&amp;&amp;</code></td><td><code>Run("sh", ...)</code> with <code>-c</code></td></tr>
<tr><td>Only the exit code, output straight to the screen</td><td><code>System</code></td></tr>
<tr><td>Start without waiting, or stop a program</td><td><a href="/std/os/process/">os.process</a></td></tr>
</tbody>
</table></div>
>>

doc.CmdResult = The result of a command.
doc.CmdResult.code = The exit code; zero means success, 128 plus the signal number when a signal ended it, and -1 when the program could not start.
doc.CmdResult.out = The standard output, newlines included; it stops at the first zero byte.
doc.CmdResult.err = The error output.
doc.Run = Runs a program with its arguments given separately (no shell, the name searched on <code>PATH</code>), waits for it to finish and returns the code, the output and the error output. Code -1 when it cannot start.
doc.Exec = Splits a command string on single spaces into a program and its arguments and runs it with <code>Run</code>, with no shell. Quotes are kept as ordinary characters.
doc.System = Runs a command in the real shell (<code>/bin/sh -c</code>, or <code>cmd</code> on Windows) and returns only the exit code; the output is printed directly. 127 when the shell cannot start.
