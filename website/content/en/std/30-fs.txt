pkg.intro <<
<p>The <code>fs</code> package holds a few functions about a file's metadata (its times and its permissions) and three sub-packages you will use far more often: <a href="/std/fs/file/">fs.file</a> for reading and writing files, <a href="/std/fs/dir/">fs.dir</a> for folders and <a href="/std/fs/path/">fs.path</a> for building paths. The simpler <a href="/std/os/">os</a> package covers whole-file reads, folder listings and existence checks; come here for when a file changed and who may read it.</p>
<p>Times are whole seconds since the start of 1970 (Unix time), as an <code>i64</code>. Every function returns <code>-1</code> when the path does not exist or the system cannot answer.</p>
<p>Write permissions in octal, such as <code>0o644</code>, meaning the owner reads and writes and everyone else reads. <code>Permissions</code> returns the same digits as an ordinary number, such as <code>644</code>, so that it reads easily. The two are not the same number (<code>0o644</code> is 420), so never pass the result of <code>Permissions</code> back to <code>Chmod</code> unchanged.</p>
<h2 id="guide-private">Keep a secret file private</h2>
<p>A new file gets the system default permissions, usually <code>644</code>, which lets every account on the machine read it. For tokens, keys and passwords, write the file and then narrow it to <code>0o600</code>. Keep the two notations apart: <code>Chmod</code> takes octal (<code>0o600</code>), while <code>Permissions</code> gives the same digits back as an ordinary number (<code>600</code>). That is why <code>p % 100 == 0</code> below means that the group and everyone else have no rights at all.</p>
{{example.fs-guide-private}}

<h2 id="guide-rwx">Reading the permission digits</h2>
<p>The three digits are for the owner, the group and everyone else, in that order. Inside one digit, 4 means read, 2 means write and 1 means execute, and the digit is their sum:</p>
<div class="table-wrap"><table>
<thead><tr><th>Digit</th><th>Letters</th><th>Meaning</th></tr></thead>
<tbody>
<tr><td><code>7</code></td><td><code>rwx</code></td><td>read, write and run</td></tr>
<tr><td><code>6</code></td><td><code>rw-</code></td><td>read and write</td></tr>
<tr><td><code>5</code></td><td><code>r-x</code></td><td>read and run</td></tr>
<tr><td><code>4</code></td><td><code>r--</code></td><td>read only</td></tr>
<tr><td><code>0</code></td><td><code>---</code></td><td>nothing</td></tr>
</tbody>
</table></div>
<p>This example turns the number into the letters that <code>ls -l</code> prints. A script needs the execute bit for its owner (<code>0o755</code> or <code>0o700</code>) before the shell runs it, and a directory needs it before anyone can open it.</p>
{{example.fs-guide-rwx}}

<h2 id="guide-rebuild">Rebuild only what changed</h2>
<p><code>ModTime</code> is how build tools such as <code>make</code> decide what to do: an output is out of date when its source changed after the output was written. For a path that does not exist <code>ModTime</code> returns <code>-1</code>, which the example reads as "build it". Times are in whole seconds, so a source and an output written in the same second count as up to date. That is the right answer here, because the output was written after the source.</p>
{{example.fs-guide-rebuild}}

<h2 id="guide-platforms">Platform notes</h2>
<ul>
<li><code>CreatedTime</code> is <code>0</code> where the file system does not record a creation time, which is common on Linux. Use <code>ModTime</code> when you need a value that is always there.</li>
<li>On Linux, macOS and BSD the time functions and <code>Permissions</code> run the system <code>stat</code> command through the shell, with the path quoted. That is quick for a handful of files, but over thousands of files in a loop the process starts add up. <code>Chmod</code> calls the system directly.</li>
<li>Windows has no Unix permission bits, only a read only flag, so <code>Chmod</code> can only switch that flag, and <code>Permissions</code> returns 292 (<code>0o444</code>) for a read only file and 438 (<code>0o666</code>) otherwise: the octal value, not the digits it gives on Unix. Write permission logic for Unix and test it there.</li>
</ul>
>>

doc.ModTime = When the file's content was last changed, in Unix seconds; -1 when the path does not exist.
doc.AccessedTime = When the file was last read, in Unix seconds. Many systems update it lazily or not at all (<code>noatime</code>), so do not rely on it.
doc.CreatedTime = When the file was created, in Unix seconds, or zero where the file system does not keep it.
doc.Chmod = Changes a file's permissions; give them in octal, such as <code>0o644</code>. Returns 0 on success and -1 on failure. On Windows only the read only flag can change.
doc.Permissions = A file's permissions as their octal digits read as a decimal number, such as <code>644</code>; -1 when the path does not exist. On Windows it returns 292 or 438 instead.
