pkg.intro <<
<p>The <code>fs.dir</code> package covers everything you do with directories: create them, list them, walk a tree, measure it, copy, move and delete it. It is built on the folder functions of <a href="/std/os/">os</a> and adds two things: when a function fails it records the detail (an <code>IOError</code> with the operation and the path) in <a href="/std/os/error/">os.error</a>, and <code>Move</code> works across disks. For files use <a href="/std/fs/file/">fs.file</a>, and to build the paths <a href="/std/fs/path/">fs.path</a>.</p>
<p>Listing functions return bare names; <code>Walk</code> returns full paths. Functions that change the disk return 0 or -1.</p>
<p>What people get wrong:</p>
<ul>
<li>Using <code>Exists</code> for files. Here it is true only for a <em>directory</em>; for files use <code>fs.file.Exists</code>.</li>
<li>Expecting <code>Copy</code> and <code>Move</code> to refuse an existing target. Both merge into it: files with the same name are replaced and other files stay.</li>
<li>Pointing <code>RemoveAll</code>, <code>Walk</code>, <code>Size</code> or <code>Copy</code> at a tree with symbolic links. They follow a link to a folder as if it were part of the tree, so <code>RemoveAll</code> deletes the contents of the link's target and a link loop never ends.</li>
</ul>
<h2 id="guide-skeleton">Create a project layout</h2>
<p><code>MkdirAll</code> creates every missing parent and succeeds when the folder is already there, so it is the safe choice for setting up a layout that may partly exist. <code>List</code>, <code>ListDirs</code> and <code>ListFiles</code> return bare names, not full paths, in whatever order the file system keeps them, and that order differs between systems. Sort them with <a href="/std/sort/">sort.Sort</a> before you show or compare them.</p>
{{example.fs-dir-guide-skeleton}}

<h2 id="guide-walk">Walk a whole tree</h2>
<p><code>Walk</code> returns the path of every file below a directory, already joined to the directory you passed in, so each one can go straight to an <a href="/std/fs/file/">fs.file</a> function. Directories themselves are not in the list, and like the listing functions it has no fixed order. This example counts files by extension and adds up their sizes, which is what <code>Size</code> does in one call.</p>
{{example.fs-dir-guide-walk}}

<h2 id="guide-backup">Keep rotating backups</h2>
<p><code>Copy</code> copies a tree with everything in it (file contents only; permissions are not kept), and <code>Move</code> renames one, falling back to copy and delete when the rename fails, for example because the target is on another disk. Together they make a simple rotation: drop the oldest backup, shift the others up by one, and copy the live folder to <code>.bak1</code>. The oldest is removed first so that its name is free before anything moves onto it.</p>
{{example.fs-dir-guide-backup}}

<h2 id="guide-errors">Errors and pitfalls</h2>
<p>Every function that changes the disk returns <code>0</code> or <code>-1</code>, and on failure it leaves a short message in <a href="/std/os/error/">os.error</a>. The message names the operation that failed, not the reason, so when the reason matters, check the likely causes yourself: the folder already exists, its parent is missing, or it is not empty.</p>
{{example.fs-dir-guide-errors}}
<ul>
<li><code>Mkdir</code> fails when the folder exists or its parent is missing; <code>MkdirAll</code> handles both.</li>
<li><code>Remove</code> only removes an empty folder. <code>RemoveAll</code> deletes everything inside without asking, so build its argument carefully and never pass it a path straight from user input; <a href="/std/fs/path/">path.IsSafe</a> checks that a path stays inside a base folder.</li>
<li><code>Exists</code> is false for a file, and <code>List</code> on a missing folder gives an empty vector rather than an error.</li>
</ul>

doc.Mkdir = Creates one directory; fails (-1, with an <code>os.error</code> record) when it exists or its parent is missing.
doc.MkdirAll = Creates a directory along with every parent it needs; succeeds when it already exists.
doc.Remove = Removes an empty directory; a directory with anything in it fails.
doc.RemoveAll = Removes a directory with everything in it; a missing path counts as success. It follows symbolic links to folders and deletes what is inside their targets.
doc.List = The names of everything inside a directory, hidden entries included, without <code>.</code> and <code>..</code>, in no fixed order. A missing directory gives an empty vector.
doc.ListDirs = Only the names of the subdirectories.
doc.ListFiles = Only the names of the files.
doc.Walk = The paths of every file in a directory and its subdirectories, each starting with the path you passed; directories are not listed. The same as <code>os.Walk</code>.
doc.Copy = Copies a directory with all its contents into <code>dst</code>, creating it if needed and merging with what is already there. Permissions are not copied.
doc.Move = Moves a directory. When the rename fails, across two disks for instance, it copies into the target (merging with an existing one) and then removes the original.
doc.Exists = True when the path exists and is a <em>directory</em>.
doc.IsDir = True when the path is a directory.
doc.Size = The total size of every file in the directory and its subdirectories, in bytes; 0 for a missing directory.
doc.Permissions = The directory's permissions, as octal digits.
doc.ModTime = When the directory's list of entries last changed (a file added, removed or renamed), in Unix seconds; editing a file inside does not change it.
