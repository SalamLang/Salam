pkg.intro <<
<p>The <code>fs.path</code> package takes paths apart and puts them together: join, split, clean, make absolute or relative, and check that a path from a user stays inside a folder. Every function is a thin name over the same function in <a href="/std/filepath/">filepath</a> (with <code>Filename</code> for <code>Base</code>, <code>Dirname</code> and <code>Parent</code> for <code>Dir</code>), so pick one of the two packages and use it throughout a program. One name differs in meaning: <code>filepath.Base</code> keeps the extension, while <code>path.Basename</code> drops it; <code>fs.path</code> reads naturally next to <a href="/std/fs/file/">fs.file</a> and <a href="/std/fs/dir/">fs.dir</a>.</p>
<p>Do not build paths by concatenating strings; <code>Join</code> puts the separator in for you. The separator is always <code>/</code>, on Windows too: every function first turns <code>\</code> into <code>/</code>, and Windows accepts <code>/</code> in paths. When a path comes from a user, check it with <code>IsSafe</code> before opening it, so that nobody climbs out of the permitted directory with <code>../..</code>.</p>
<p>Every function here works on the text of the path alone. None of them looks at the disk, except <code>Abs</code>, <code>Rel</code> and <code>IsSafe</code> with a relative path, which read the current directory. To create, read or list files, combine this package with <a href="/std/fs/dir/">fs.dir</a>, <a href="/std/fs/file/">fs.file</a> or <a href="/std/io/">io</a>, as the guide below does.</p>
<p>What people get wrong:</p>
<ul>
<li>Expecting <code>Join</code> to clean up. It only adds or merges the separator, so <code>Join("a/b", "../c")</code> is <code>a/b/../c</code>; pass the result through <code>Clean</code>. An absolute second part does not replace the first either, unlike Python's <code>os.path.join</code>.</li>
<li>Reading <code>Ext</code> as the whole extension. It is only the last one: <code>.gz</code> for <code>backup.tar.gz</code>, and empty for a dot file such as <code>.bashrc</code>.</li>
<li>Comparing paths as text without <code>Clean</code>. <code>docs/./cv.pdf</code> and <code>docs/cv.pdf</code> are the same file. Comparisons are also case sensitive, which is wrong on Windows and on default macOS disks.</li>
</ul>
<h2 id="guide-user-paths">Serving a file a user asked for</h2>
<p>A download handler gets a name such as <code>2026/report.pdf</code> from the request and has to turn it into a file inside one folder. <code>IsSafe</code> simplifies the joined path first and then checks that it still starts with the folder, so <code>a/../b.txt</code> is fine while <code>../secret.txt</code> and <code>a/../../etc/passwd</code> are refused. An empty name is refused too.</p>
{{example.fs-path-guide-safe}}
<p>Look at the <code>/etc/passwd</code> line: <code>Join</code> does not let an absolute second part replace the first, so the result lands inside the folder and is safe. The check works on text only; it does not follow symbolic links, so do not put links that point outside the folder in a directory you serve.</p>

<h2 id="guide-output-paths">Mapping one folder tree onto another</h2>
<p>A static site generator reads <code>content/blog/hello.md</code> and writes <code>public/blog/hello.html</code>. <code>Rel</code> gives the part below the source folder, <code>Dirname</code> and <code>Stem</code> take it apart, and <code>Join</code> and <code>Clean</code> build the new path. <code>Stem</code> removes only the last extension, so <code>salam.v2.md</code> keeps its <code>.v2</code>.</p>
{{example.fs-path-guide-output}}
<p>For a file directly in the source folder <code>Dirname</code> returns <code>.</code>; the final <code>Clean</code> removes the <code>/.</code> that <code>Join</code> leaves behind. The example uses absolute paths because <code>Rel</code> makes relative ones absolute against the current directory first.</p>

<h2 id="guide-backup">Making a new name next to a file</h2>
<p>To put a backup, a thumbnail or a converted copy next to the original, keep the folder and change only the name. Here <code>Stem</code> and <code>Ext</code> turn <code>plan.md</code> into <code>plan.bak.md</code>, and <a href="/std/fs/dir/">fs.dir</a> and <a href="/std/io/">io</a> do the actual work on disk.</p>
{{example.fs-path-guide-backup}}

<p>Several functions here have close names. <code>Filename</code> keeps the extension; <code>Basename</code> and <code>Stem</code> both drop it. <code>Normalize</code> only changes <code>\</code> to <code>/</code>; <code>Clean</code> is the one that resolves <code>.</code> and <code>..</code>.</p>

doc.PathParts = The two parts of a path.
doc.PathParts.dir = The directory part.
doc.PathParts.base = The file name.
doc.Join = Joins two parts of a path with one <code>/</code> between them. An empty part gives the other part; <code>.</code> and <code>..</code> are kept, so call <code>Clean</code> on the result when it matters.
doc.Split = Splits a path into its directory (<code>Dirname</code>) and its file name (<code>Filename</code>).
doc.Normalize = Turns Windows <code>\</code> separators into <code>/</code> and does nothing else. To resolve <code>..</code> and <code>.</code>, see <code>Clean</code>.
doc.Clean = Simplifies a path: it resolves <code>.</code> and <code>..</code>, removes repeated and trailing separators, and gives <code>.</code> for an empty path. A <code>..</code> above the root of an absolute path is dropped.
doc.IsAbs = True when the path starts with <code>/</code> or with a drive letter such as <code>C:</code>.
doc.Abs = Makes the path absolute against the current directory and cleans it.
doc.Rel = The path of <code>target</code> relative to <code>base</code>, with <code>..</code> steps when it lies outside; <code>.</code> when they are the same. Both are made absolute first.
doc.Parent = The parent directory; the same as <code>Dirname</code>.
doc.Dirname = The directory part of a path: <code>.</code> when there is none, <code>/</code> for a file at the root. A trailing <code>/</code> is ignored.
doc.Filename = The file name with its extension, the last part of the path.
doc.Basename = The file name without the directory and without its extension; the same as <code>Stem</code>. For the name with its extension, use <code>Filename</code>.
doc.Ext = The last extension, with its dot, such as <code>.gz</code>; empty when there is none or the name starts with its only dot (<code>.bashrc</code>).
doc.Stem = The file name without its last extension: <code>backup.tar</code> for <code>backup.tar.gz</code>.
doc.IsSafe = True when <code>p</code>, joined to <code>base</code> and simplified, is <code>base</code> itself or lies inside it. An empty <code>p</code> is refused. It works on text and does not follow symbolic links.
doc.Validate = True when the path is not empty; it checks nothing else.
