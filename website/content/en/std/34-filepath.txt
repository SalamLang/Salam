pkg.intro <<
<p>The <code>filepath</code> package takes path strings apart and builds them: <code>Join</code>, <code>Dir</code>, <code>Base</code>, <code>Ext</code>, <code>Stem</code>, <code>Clean</code>, <code>Abs</code>, <code>Rel</code> and the <code>IsSafe</code> check for paths that come from users. It works on strings alone and never touches the file system, apart from <code>Abs</code>, <code>Rel</code> and <code>IsSafe</code>, which read the current directory for a relative path. Use it in build tools, static site generators, upload handlers and anywhere a path is computed rather than typed. To act on the files themselves, pair it with <a href="/std/fs/file/">fs.file</a>, <a href="/std/fs/dir/">fs.dir</a> or <a href="/std/os/">os</a>.</p>
<p>The <a href="/std/fs/path/">fs.path</a> package is a set of other names for the same functions; use whichever reads better to you, but one per program. The names differ a little: <code>Base</code> here is <code>Filename</code> there, and <code>Dir</code> is <code>Dirname</code>. Watch out for <code>path.Basename</code>, which is <code>Stem</code> and drops the extension, unlike <code>Base</code>. Paths always come out with <code>/</code> as the separator, on Windows too, and Windows accepts that.</p>
<p>What people get wrong:</p>
<ul>
<li>Expecting <code>Join</code> to clean the result. It only places one <code>/</code> between the parts: <code>Join("a/b", "../c")</code> is <code>a/b/../c</code>, and an absolute second part is appended, not substituted. Call <code>Clean</code> afterwards.</li>
<li>Comparing paths as plain text. Clean both first, and remember that the comparison is case sensitive.</li>
<li>Trusting a user's path without <code>IsSafe</code>. Even after <code>Join</code>, <code>../../etc/passwd</code> climbs out of your folder.</li>
</ul>
<h2 id="guide-windows">Windows paths</h2>
<p>A path pasted by a Windows user, or read from a Windows config file, uses <code>\</code>. Every function here calls <code>Normalize</code> first, so <code>Dir</code>, <code>Base</code> and <code>Join</code> accept both kinds. <code>IsAbs</code> also treats a drive letter such as <code>C:/</code> as absolute.</p>
{{example.filepath-guide-windows}}
<p>In a Salam string a single backslash is written <code>\\</code>. <code>Clean</code> treats the drive as an ordinary first part, so <code>C:/../x</code> becomes <code>x</code>; do not climb above the drive with <code>..</code>.</p>

<h2 id="guide-edges">Edge cases worth knowing</h2>
<p>The table below runs <code>Dir</code>, <code>Base</code>, <code>Ext</code> and <code>Clean</code> over inputs that often cause bugs: the root, an empty string, a trailing slash, a dot file and a double extension.</p>
{{example.filepath-guide-edges}}
<p>The rules it shows: a trailing slash is ignored; an empty path counts as <code>.</code>; a name that starts with a dot, like <code>.bashrc</code>, has no extension; <code>Ext</code> returns only the last extension, so test for <code>.tar.gz</code> with <code>str.EndsWith</code> when you need it. <code>Dir</code> does not simplify, so call <code>Clean</code> first when the path may contain <code>.</code> or <code>..</code>.</p>

<h2 id="guide-group">Grouping files by extension</h2>
<p><code>Ext</code> with a <code>HashMap</code> counts files by type, for a report or to pick a handler for each file. A second vector remembers the order in which the extensions first appeared, so the output does not depend on the map's internal order.</p>
{{example.filepath-guide-group}}
<p><code>Ext</code> keeps the case of the name, so <code>photo.JPG</code> gives <code>.JPG</code>. Pass it through <code>str.Lower</code> before comparing when the files come from a camera or from Windows.</p>
>>

doc.Separator = The separator between the parts of a path: always <code>/</code>, on Windows too.
doc.Normalize = Turns <code>\</code> separators into <code>/</code> and changes nothing else; see <code>Clean</code> for <code>.</code> and <code>..</code>.
doc.IsAbs = True when the path is absolute; a Windows path such as <code>C:/</code> counts as absolute.
doc.Join = Joins two parts of a path with exactly one <code>/</code> between them. An empty part gives the other one. It does not resolve <code>..</code> and does not let an absolute second part replace the first.
doc.Base = The last part of a path, extension included; a trailing slash is ignored, <code>/</code> stays <code>/</code> and an empty path gives <code>.</code>.
doc.Dir = The path without its last part: <code>.</code> when there is no folder and <code>/</code> at the root. It does not simplify <code>..</code>.
doc.Ext = The last extension, with its dot, in its original case; empty for a name without one and for a dot file such as <code>.bashrc</code>.
doc.Stem = The last part's name without its last extension.
doc.Clean = Simplifies a path: resolves <code>.</code> and <code>..</code>, removes repeated and trailing slashes, and gives <code>.</code> for an empty path. A drive letter is treated as an ordinary first part.
doc.Abs = Makes a path absolute against the current directory and cleans it; an absolute path is only cleaned.
doc.Rel = The relative path from <code>base</code> to <code>target</code>, using <code>..</code> when the target lies outside; both are made absolute first.
doc.Validate = True when the path is not empty. It is not a safety check.
doc.IsSafe = True when <code>p</code>, joined to <code>base</code> and cleaned, is <code>base</code> or lies inside it; an empty <code>p</code> is refused. Text only, so symbolic links are not followed.
