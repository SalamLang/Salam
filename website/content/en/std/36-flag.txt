pkg.intro <<
<p>The <code>flag</code> package reads command line options. Each flag has a long name (<code>--port</code>), a short name (<code>-p</code>), a default value and a line of help. The value can be given either way: <code>--port=8080</code> or <code>--port 8080</code>. Any argument that is not a flag is "positional", and after <code>--</code> everything counts as positional.</p>
<p><code>--help</code> and <code>-h</code> are always recognised and the <code>Usage</code> text is generated for you. Pass <code>Parse</code> the arguments without the program's own name.</p>

<h2 id="guide-args">Reading the real command line</h2>
<p><a href="/std/os/">os.Args</a> returns every argument, with the program's own name first. <code>cli.RemainingArgs</code> drops that first item, which gives exactly what <code>Parse</code> wants. A program then checks three things in order: did parsing fail, was help asked for, and only then does it read the values. Exit with code 2 on a usage error, as most command line tools do.</p>
{{example.flag-guide-args}}
<p>Run it as <code>salam run greet.salam --name Ali -n 3</code> to pass your own arguments. When it gets none, as here, it uses a built-in sample so that the output above stays the same.</p>

<h2 id="guide-errors">Reporting bad input</h2>
<p><code>Parse</code> stops at the first problem and returns false, and <code>Error</code> says what went wrong in one line, ready to print. There are four kinds: a value that is not a whole number, a value that is not a decimal, a flag that was never declared, and a flag at the end of the line with no value after it.</p>
{{example.flag-guide-errors}}
<p>The messages are in English. Decimal values need a dot, so <code>0,5</code> is rejected. Whole number flags accept Persian digits as well.</p>

<h2 id="guide-precedence">Flag, then environment, then default</h2>
<p>Many programs read a setting from a flag, fall back to an environment variable, and use a built-in default last. <code>WasSet</code> makes that possible: it tells "the user typed <code>--port 8080</code>" apart from "8080 is just the default", which <code>GetInt</code> alone cannot.</p>
{{example.flag-guide-precedence}}
<p>The last line matters: <code>--port=8080</code> is the same number as the default, but the user asked for it explicitly, so it wins over <code>PORT</code>. See <a href="/std/env/">env</a> for the environment side.</p>

<h2 id="guide-positional">Short names, booleans and positional arguments</h2>
<p>Flags and positional arguments can come in any order. A boolean flag never takes the next argument as its value; to turn off one that defaults to true, write <code>--name=false</code>. After <code>--</code>, even arguments that look like flags are positional, which is how a program accepts a file called <code>-r</code>.</p>
{{example.flag-guide-positional}}
<p>Short names cannot be combined: <code>-rv</code> is read as one flag called <code>rv</code> and gives an "unknown flag" error. Write <code>-r -v</code> instead.</p>
>>
