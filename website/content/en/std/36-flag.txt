pkg.intro <<
<p>The <code>flag</code> package reads command line options. Each flag has a long name (<code>--port</code>), an optional short name (<code>-p</code>), a kind (bool, string, int or float), a default value and a line of help. The value can be given either way: <code>--port=8080</code> or <code>--port 8080</code>. Any argument that is not a flag is "positional", and after <code>--</code> everything counts as positional. For a program with subcommands such as <code>tool build</code> and <code>tool test</code>, see <a href="/std/cli/">cli</a>; for settings from the environment, <a href="/std/env/">env</a>.</p>
<p>The steps are always the same: <code>New</code>, one <code>Add...</code> per flag, <code>Parse</code> with the arguments (without the program's own name), then check <code>Parse</code>'s result and <code>HelpWanted</code> before reading values with <code>GetStr</code>, <code>GetInt</code>, <code>GetFloat</code> and <code>GetBool</code>. <code>--help</code> and <code>-h</code> are always recognised and reserved, and the <code>Usage</code> text is generated for you.</p>
<p>What people get wrong:</p>
<ul>
<li>Forgetting that a value flag takes the next argument whatever it is. <code>--name --verbose</code> sets the name to <code>--verbose</code>.</li>
<li>Passing negative numbers as positional arguments. <code>-5</code> looks like a flag and gives "unknown flag"; put <code>--</code> before it, or use <code>--offset=-5</code> for a flag value.</li>
<li>Expecting a bad boolean to be an error. <code>--verbose=maybe</code> is accepted and reads as false; only <code>true</code>, <code>1</code>, <code>yes</code> and <code>on</code> are true.</li>
</ul>
<h2 id="guide-args">Reading the real command line</h2>
<p><a href="/std/os/">os.Args</a> returns every argument, with the program's own name first. <code>cli.RemainingArgs</code> drops that first item, which gives exactly what <code>Parse</code> wants. A program then checks three things in order: did parsing fail, was help asked for, and only then does it read the values. Exit with code 2 on a usage error, as most command line tools do.</p>
{{example.flag-guide-args}}
<p>Run it as <code>salam run greet.salam --name Ali -n 3</code> to pass your own arguments. When it gets none, as here, it uses a built-in sample so that the output above stays the same.</p>

<h2 id="guide-errors">Reporting bad input</h2>
<p><code>Parse</code> stops at the first problem and returns false, and <code>Error</code> says what went wrong in one line, ready to print. There are four kinds: a value that is not a whole number, a value that is not a decimal, a flag that was never declared, and a flag at the end of the line with no value after it.</p>
{{example.flag-guide-errors}}
<p>The messages are in English. Unknown flags and missing values stop the parse where they occur; numbers are checked after the whole line has been read, in the order the flags were declared. Decimal values need a dot (or the Persian <code>٫</code>), so <code>0,5</code> is rejected. Number flags accept Persian digits as well. When a flag is given twice, the last value wins.</p>

<h2 id="guide-precedence">Flag, then environment, then default</h2>
<p>Many programs read a setting from a flag, fall back to an environment variable, and use a built-in default last. <code>WasSet</code> makes that possible: it tells "the user typed <code>--port 8080</code>" apart from "8080 is just the default", which <code>GetInt</code> alone cannot.</p>
{{example.flag-guide-precedence}}
<p>The last line matters: <code>--port=8080</code> is the same number as the default, but the user asked for it explicitly, so it wins over <code>PORT</code>. See <a href="/std/env/">env</a> for the environment side.</p>

<h2 id="guide-positional">Short names, booleans and positional arguments</h2>
<p>Flags and positional arguments can come in any order. A boolean flag never takes the next argument as its value; to turn off one that defaults to true, write <code>--name=false</code>. After <code>--</code>, even arguments that look like flags are positional, which is how a program accepts a file called <code>-r</code>.</p>
{{example.flag-guide-positional}}
<p>Short names cannot be combined: <code>-rv</code> is read as one flag called <code>rv</code> and gives an "unknown flag" error. Write <code>-r -v</code> instead.</p>
>>

doc.New = Creates a new flag set with the program's name and description.
doc.AddBool = Declares a boolean flag; it turns true when present, and <code>--name=false</code> (or <code>=0</code>, <code>=no</code>) turns it off. It never takes the next argument as its value.
doc.AddStr = Declares a string flag. Its value is the text after <code>=</code> or the next argument, even one that starts with <code>-</code>.
doc.AddInt = Declares a whole number flag; a sign and Persian digits are accepted, anything else fails the parse.
doc.AddFloat = Declares a decimal flag; a dot or <code>٫</code>, an exponent such as <code>1e3</code> and Persian digits are accepted.
doc.Parse = Parses the arguments, not including the program name. On an unknown flag, a missing value or a bad number it returns false and <code>Error</code> says why. <code>--help</code> does not make it fail; check <code>HelpWanted</code>.
doc.GetStr = The value of a string flag, or its default; empty for a name that was never declared.
doc.GetInt = The value of a whole number flag.
doc.GetFloat = The value of a decimal flag.
doc.GetBool = The value of a boolean flag: true for <code>true</code>, <code>1</code>, <code>yes</code> or <code>on</code>, false for anything else.
doc.WasSet = True when the flag appeared on the command line; for telling "the default" apart from "the user asked for exactly this".
doc.Positional = A copy of the positional arguments, in order; free it when done.
doc.HelpWanted = True when the user asked for help.
doc.Error = The message of the last parse error.
doc.Usage = The full help text: a usage line, the description, and one line per flag with its short name, kind, help and default, followed by <code>-h, --help</code>.
doc.Free = Releases the set's memory.
