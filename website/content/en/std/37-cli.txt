pkg.intro <<
<p>Many tools have several commands: <code>git commit</code>, <code>salam build</code>, <code>salam run</code>. The <code>cli</code> package holds the list of commands, works out from the first argument which one was asked for, and builds the overall help text. It also asks the user questions in the terminal with <code>Prompt</code>, <code>PromptOr</code> and <code>Confirm</code>.</p>
<p>It is deliberately small and does not parse options. Pick the package by the shape of your program:</p>
<ul>
<li>One command with options, such as <code>resize --width 800 photo.png</code>: <a href="/std/flag/">flag</a> alone is enough.</li>
<li>Several commands, each with its own options: <code>cli</code> picks the command and a <a href="/std/flag/">flag</a> set per command reads its options.</li>
<li>Full-screen or coloured terminal output: <a href="/std/term/">term</a>.</li>
</ul>
<p>The things people get wrong:</p>
<ul>
<li><code>Dispatch</code> wants the arguments <em>without</em> the program's name. <a href="/std/os/">os.Args</a> includes it, so pass <code>RemainingArgs(os.Args())</code>.</li>
<li><code>help</code>, <code>-h</code>, <code>--help</code>, <code>version</code>, <code>-v</code> and <code>--version</code> are taken by <code>Dispatch</code>, and inside each command <a href="/std/flag/">flag</a> treats <code>-h</code> and <code>--help</code> as a help request. Never register <code>h</code> as a short flag of your own.</li>
<li>Command names match exactly: no prefixes, aliases or case folding, and <code>Register</code> does not reject a duplicate (the first one wins).</li>
<li><code>RemainingArgs</code> returns a new vector; free it with <code>defer rest.free()</code>.</li>
</ul>

<h2 id="guide-subcommands">A tool with several commands</h2>
<p>The usual shape: <code>Dispatch</code> picks the command from the first argument, <code>RemainingArgs</code> hands everything after it to that command, and each command declares its own <a href="/std/flag/">flag</a> set, so <code>todo add</code> and <code>todo list</code> can have different options. Each command returns an exit code.</p>
{{example.cli-guide-subcommands}}
<p><code>cli.Usage</code> ends with a hint to run <code>todo &lt;command&gt; --help</code>, but answering it is each command's job: check <code>flag.HelpWanted</code> after parsing and print <code>flag.Usage</code>, as <code>add</code> does here. Both help texts are generated in English; only your descriptions appear as you wrote them.</p>

<h2 id="guide-main">Wiring it to the real arguments</h2>
<p>In a real program the arguments come from <a href="/std/os/">os.Args</a>. Drop the program's own name with <code>RemainingArgs</code> and pass the rest to <code>Dispatch</code>. With no arguments at all <code>Dispatch</code> returns <code>CmdHelp</code>, so running the tool bare prints its help, which is what users expect.</p>
{{example.cli-guide-main}}
<p>The output above is what it prints with no arguments. Try <code>salam run notes.salam show --all</code> or <code>salam run notes.salam --version</code>.</p>

<h2 id="guide-required">Required flags</h2>
<p>A flag with no sensible default, such as the server to deploy to, should be required. <code>RequireFlags</code> takes the names that must appear and returns the ones that did not, so you can report all of them at once instead of one per run.</p>
{{example.cli-guide-required}}
<p>It uses <code>flag.WasSet</code>, so it checks that the flag was typed, not that it has a value: <code>--host=</code> counts as given. Check for an empty string too when that matters.</p>

<h2 id="guide-prompts">Questions that also work in scripts</h2>
<p><code>PromptOr</code> and <code>Confirm</code> read one line from standard input. When nothing is typed, or the program runs in a script with no terminal, <code>PromptOr</code> returns its default and <code>Confirm</code> returns false, so a forgotten question never does something dangerous. Give every question a flag too, here <code>--name</code> and <code>--yes</code>, so the program can run without anyone at the keyboard.</p>
{{example.cli-guide-noninteractive}}
<p>This output is what happens with standard input empty, as in a CI job: the language question takes its default and the confirmation is refused. The questions end without a line break because nobody pressed Enter.</p>
>>

doc.CmdHelp = What <code>Dispatch</code> returns when help was asked for, or no argument was given.
doc.CmdVersion = What <code>Dispatch</code> returns when the version was asked for.
doc.CmdUnknown = What <code>Dispatch</code> returns for a command that was never registered.
doc.App = A command line program and its commands.
doc.App.name = The program's name.
doc.App.desc = The program's description.
doc.App.version = The program's version.
doc.App.cmd_names = The names of the commands.
doc.App.cmd_descs = The descriptions of the commands.
doc.New = Creates a program with a name, a description and a version.
doc.Register = Adds one command with its description. Commands appear in <code>Usage</code> in the order they were registered; a duplicate name is not rejected.
doc.HasCommand = True when the command has been registered.
doc.CommandDesc = The description of a command.
doc.Dispatch = Says from the first argument which command was asked for: its name, or <code>CmdHelp</code>, <code>CmdVersion</code> or <code>CmdUnknown</code>. Pass the arguments <em>without</em> the program's name. <code>help</code>, <code>-h</code> and <code>--help</code> give <code>CmdHelp</code>, as does an empty list; <code>version</code>, <code>-v</code> and <code>--version</code> give <code>CmdVersion</code>.
doc.RemainingArgs = A new vector with every argument after the first, for handing to the flag package. Use it once to drop the program name from <code>os.Args()</code> and again to drop the command name. Free the result.
doc.Usage = The program's overall help text: name and version, description, a usage line and the commands with their descriptions. It ends with a line break, so print it with <code>print</code>.
doc.RequireFlags = Of the names you give, returns the flags that were not typed on the command line, in the same order. A flag given with an empty value, such as <code>--host=</code>, counts as typed.
doc.Confirm = Prints the question with <code>[y/N]: </code> and reads one line. <code>y</code> or <code>yes</code>, in any case and with spaces around it, is true; anything else, an empty line or the end of input is false.
doc.Prompt = Prints the question followed by <code>: </code>, reads one line and returns it with surrounding spaces trimmed. Do not end the question with a colon yourself. At the end of input it returns an empty string.
doc.PromptOr = Like <code>Prompt</code>, but shows the default in brackets, as in <code>language (english): </code>, and returns it when the answer is empty.
