pkg.intro <<
<p>For a program running on a server, <code>println</code> is not enough: you need to know how important each message is and when it was written, and to be able to silence the unimportant ones. The <code>log</code> package has four levels, debug, info, warn and error, and records only the messages at or above the level you set; the default level is info.</p>
<p>By default the log goes to standard error with a timestamp. The examples below turn the time off so their output is stable.</p>
<p>All settings are global to the program: call <code>SetLevel</code>, <code>SetFormat</code>, <code>SetPrefix</code> and one of <code>ToStderr</code>, <code>ToStdout</code> or <code>ToFile</code> once near the start of <code>main</code>, and every package that imports <code>log</code> writes the same way.</p>

<h2 id="guide-level">Choose the level from the settings</h2>
<p>The level should not be fixed in the code. During development you want debug messages; on a busy server you want warnings and errors only. Read the level as text from a settings file or the environment and turn it into a number with <code>ParseLevel</code>. It accepts <code>debug</code>, <code>info</code>, <code>warn</code>, <code>warning</code> and <code>error</code> in any case, and falls back to info for anything else, so a typo never silences the log completely.</p>
{{example.log-level-config}}
<p>The <code>config</code> package used here is described on its own page, <a href="/std/config/">config</a>. The prefix is a good place for the program's name, so that lines from several programs in one log stay apart.</p>

<h2 id="guide-json">JSON logs for a log collector</h2>
<p>Text lines are easy to read; JSON lines are easy for tools such as Loki, Elasticsearch or a cloud log service to search. <code>SetFormat(FormatJSON)</code> turns every line into one JSON object with <code>level</code>, the optional <code>prefix</code>, <code>msg</code>, and one member for each key given to the <code>...KV</code> functions. With the time switched on, a <code>time</code> member in ISO 8601 comes first.</p>
{{example.log-json-requests}}
<p>Picking the level from the result, error for a 5xx answer and warn for a 4xx one, lets you alert on errors without reading every request. Quotes inside a value are escaped, so each line stays valid JSON. All values are written as JSON strings, numbers included.</p>

<h2 id="guide-rotation">Log to a file that does not grow forever</h2>
<p><code>ToFile</code> appends to a file and returns 0, or minus one when the file cannot be opened. <code>SetRotation(max_bytes, max_backups)</code> keeps it in check: when the file has reached <code>max_bytes</code>, the next line first renames it to <code>.1</code>, shifts the older copies up by one and starts a new, empty file. Copies past <code>max_backups</code> are deleted.</p>
{{example.log-rotation}}
<p>The limit here is tiny so that the example rotates a few times. A real service uses something like <code>10 * 1024 * 1024</code> bytes and five backups. Call <code>CloseFile</code> before the program ends; <code>Fatal</code> closes the file for you before it exits with status 1.</p>

<h2 id="guide-fields">Key and value fields in text logs</h2>
<p>For text logs, <code>Field</code>, <code>FieldInt</code> and <code>FieldBool</code> build <code>key=value</code> pieces and <code>KV</code> joins them after a message. <code>Field</code> puts quotes around a value that contains a space or a quote, and escapes the quotes inside, so a line can still be split into fields by a program.</p>
{{example.log-fields}}
<p>An empty value is written as <code>key=</code> with nothing after it. These helpers only build text; the level filter still applies when you pass the result to <code>Info</code> or <code>Warn</code>.</p>

<h2 id="guide-which">Which function for which job</h2>
