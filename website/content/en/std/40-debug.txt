pkg.intro <<
<p>The <code>debug</code> package holds a few simple tools for when the program is not doing the right thing. <code>Assert</code> checks a condition that should always hold. <code>Enter</code> and <code>Exit</code> build a call stack by hand, so you know where in the program you are. The timers show which part is slow.</p>
<p>None of these tools change what the program computes. The call stack and the timers are kept by the package itself, so they cost a little memory and time; trace messages cost nothing while tracing is off. Trace lines and failed assertions go to standard error, so they do not mix with the program's normal output.</p>

<h2 id="guide-stack">Say where an error happened</h2>
<p>An error message like <em>empty price</em> is hard to act on in a big program: which item, and who asked for it? Call <code>Enter</code> at the start of the functions you care about and <code>defer debug.Exit()</code> right after it, so the frame is removed on every return path. <code>Stack</code> then gives the path from the outermost frame to the current one, joined with <code>&gt;</code>. The frame is just text, so it can carry the item being worked on.</p>
{{example.debug-stack-errors}}
<p>After the outer function returns, <code>Depth</code> is back at 0. If it is not, some function called <code>Enter</code> without a matching <code>Exit</code>, which is exactly the bug that <code>defer</code> prevents.</p>

<h2 id="guide-trace">Trace the calls of a recursive function</h2>
<p><code>EnableTrace(true)</code> switches tracing on: from then on <code>Enter</code> and <code>Exit</code> print an <code>enter</code> and an <code>exit</code> line, and <code>Trace</code> prints its message after the current stack. With tracing off, <code>Trace</code> prints nothing, so trace calls can stay in the code and be switched on with a flag, for instance from a setting or a command line option.</p>
{{example.debug-trace-calls}}
<p>Reading the lines from top to bottom shows the order of the calls; the indentation you would draw by hand is the length of each stack. All of it goes to standard error, like the last line, which this example prints with <code>printerrln</code>.</p>

<h2 id="guide-timers">Time parts of a program</h2>
<p><code>StartTimer</code> starts a named timer and <code>StopTimer</code> returns the milliseconds since it started, measured with the monotonic clock, so a change of the system time does not disturb it. Starting a timer that already exists restarts it. <code>StopTimer</code> does not remove the timer: calling it again later gives a larger number, which is handy for lap times. A name that was never started gives 0.</p>
{{example.debug-timers}}
<p>Times differ from run to run and from machine to machine, so the example only prints comparisons. In your own program print the numbers themselves, for instance with <a href="/std/log/">log</a> at the debug level. Measure a part several times, or over many iterations, before deciding it is slow; the first run often includes one time costs.</p>

<h2 id="guide-assert">Assertions guard your own promises</h2>
<p><code>Assert</code> is for conditions that must hold if the code is correct, such as a balance that never goes below zero after a checked withdrawal. It is not for bad input from users or files: those are expected, and the program should answer them with an error value, as <code>withdraw</code> does with <code>false</code> when the balance is too small.</p>
{{example.debug-assert}}
<p>When an assertion fails, the program prints the message to standard error and stops at once with <code>abort</code>, so the exit status is 134 on Linux and no deferred code runs. With the first assertion broken, the run ends like this:</p>
<pre class="code" dir="ltr"><code>assertion failed: withdraw needs a positive amount
Aborted (core dumped)</code></pre>
<p>Under a debugger (<code>salam debug file.salam</code>) the abort stops in the failing function, so you can look at its variables. <code>Break</code> stops there on purpose, without a failed condition. Do not leave it in code that runs without a debugger: with nothing attached, the program is stopped by the signal.</p>
>>

doc.Assert = If the condition is false, prints the message and stops the program.

doc.Exit = Takes the last step off the stack, at the end of a function.
doc.Stack = The current stack as <code>root > child</code>.
doc.Depth = The depth of the hand-kept stack.
doc.EnableTrace = Turns trace messages on or off.
doc.TraceEnabled = True when tracing is on.
doc.Trace = When tracing is on, prints the message with a <code>[TRACE]</code> label.
doc.StartTimer = Starts a timer under the given name.
doc.StopTimer = Stops a timer and returns the time it took, in milliseconds.
doc.Break = When the program runs under a debugger such as gdb, it stops right here.
doc.MemStats = A summary of the memory statistics as text.
