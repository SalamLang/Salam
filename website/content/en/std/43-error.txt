pkg.intro <<
<p>Salam has no exceptions, so a function that may fail says so in its result. The <code>error</code> package gives your own code one error type for that: an <code>error.Error</code> is either nil, meaning everything went well, or an error with a <strong>kind</strong>, such as <code>not_found</code>, and a <strong>message</strong>. The kind is for the code to decide on; the message is for a person to read. The usual shape is an <code>err &amp;: error.Error</code> out parameter, as in the standard library.</p>
<p>When an error comes up from a lower layer, <code>Wrap</code> it so the current layer's explanation is added. The final message shows the whole chain, as in <em>could not save the report: the disk is full</em>, and <code>RootMessage</code> gives the original cause. For transient errors, such as a dropped network connection, <code>RetryPolicy</code> says how often to try again and how long to wait between attempts.</p>
<p>Neighbouring packages: <a href="/std/result/">result</a> and <a href="/std/option/">option</a> return a value or its absence in one result, which suits short chains with <code>?</code>; <a href="/std/os-error/">os/error</a> holds the last error of a file or process call. Many std packages, such as the database clients, have an <code>Error</code> type of their own; turn it into an <code>error.Error</code> at the edge of your code when you want one type throughout.</p>
<p>The things people get wrong:</p>
<ul>
<li><code>Wrap</code> and <code>WithMeta</code> on a nil error make a real error. Check <code>Ok</code> before you wrap.</li>
<li>Every <code>Wrap</code>, <code>WithMeta</code> and <code>WrapKind</code> returns a new error with its own copies, and leaves the old one as it was. Free the ones you no longer need with <code>Free</code>.</li>
<li><code>Is</code> and the <code>Is...</code> helpers look at every layer, not only the outer kind. After <code>WrapKind</code> to <code>internal</code>, an error that started as a timeout still answers true to <code>IsTimeout</code> and <code>IsRetryable</code> (see <a href="#guide-format">below</a>). Compare <code>Kind</code> when only the outer kind should count.</li>
<li><code>DelayForAttempt</code> only computes the wait; your loop has to sleep. It adds no random jitter, so many clients that fail together retry together.</li>
</ul>

<h2 id="guide-layers">Errors through the layers of a program</h2>
<p>A typical program has layers: one reads data, the next builds something from it, and the top one answers a user. Each layer that can fail takes an <code>err &amp;: error.Error</code> out parameter, sets it to <code>error.Nil()</code> on success, and on failure either makes a new error or wraps the one it got from below. Only the top layer decides what to do, and it decides by <strong>kind</strong>, not by reading the message.</p>
{{example.error-guide-layers}}
<p>Wrapping keeps the kind of the original error, so the top layer can still see that the root cause was "not found" and answer 404. <code>WithMeta</code> attaches a detail, here the missing id, that the code can read back with <code>Meta</code> without parsing text.</p>

<h2 id="guide-retry">A retry loop</h2>
<p><code>ShouldRetry</code> answers the whole question in one call: is there an error at all, is it the kind that may go away by itself (<code>unavailable</code>, <code>timeout</code> or <code>io</code>), and are there attempts left? <code>DelayForAttempt</code> gives the wait before the next try, doubling each time up to the maximum.</p>
{{example.error-guide-retry}}
<p>An invalid argument is never retried: sending the same bad request again gives the same answer. In a server, keep the total wait well below the time the caller is willing to wait for you.</p>

<h2 id="guide-validate">Collect every problem at once</h2>
<p>For a form or a config file, stopping at the first mistake makes the user fix them one by one. Collect the errors in a vector instead and show them all. <code>Newf</code> fills the <code>{}</code> placeholders of a message from a vector of strings, and a <code>field</code> meta entry says which input each error is about.</p>
{{example.error-guide-validate}}

<h2 id="guide-format">Logging an error with its trace</h2>
<p><code>NewAt</code> and <code>WrapAt</code> also record where the error passed, which <code>Trace</code> joins with <code>-&gt;</code>. <code>WrapKind</code> gives the error a new outer kind, here <code>internal</code> once the program has decided it cannot start. <code>Format</code> puts everything on a few lines for a log: the outer kind in brackets, the full message, the trace and each meta entry.</p>
{{example.error-guide-format}}
<p>The last two lines are the trap from the list above: the error now reads as <code>internal</code>, but <code>Is</code> still finds the <code>io</code> kind of its root cause, so <code>IsRetryable</code> says yes. Each layer frees the error it got from below with <code>defer error.Free(inner)</code>; that is safe because the wrapped error has its own copies.</p>

doc.WrapAt = Like <code>Wrap</code>, and adds the place to the trace.
doc.WrapKind = Like <code>Wrap</code>, and sets a new outer kind. The earlier kinds stay in the error, so <code>Is</code> still finds them.
doc.WithMeta = A copy of the error with a key and value pair added, such as a user id or a file path. On a nil error it makes an error of kind <code>unknown</code>.
doc.Meta = The value of a metadata key, or an empty string when it is absent. With a repeated key, the first value wins.
doc.Kind = The outer kind of the error; empty for nil.
doc.Is = True when this kind is the error's kind at any layer, including kinds replaced by <code>WrapKind</code>.

doc.RootMessage = The message of the innermost cause.
doc.Trace = The recorded places, joined with <code> -&gt; </code>.
doc.Format = The full text for a log: the kind in brackets and the message, then the trace and each meta entry on lines of their own. <code>&lt;nil&gt;</code> for nil.

doc.IsPermissionDenied = For the "permission denied" kind.
doc.IsAlreadyExists = For the "already exists" kind.
doc.IsTimeout = For the "timeout" kind.
doc.IsCanceled = For the "cancelled" kind.
doc.IsUnavailable = For the "unavailable" kind.
doc.IsInternal = For the "internal" kind.
doc.IsRetryable = True when the error is transient and worth retrying: a timeout, unavailability or a read or write error.
doc.NewRetryPolicy = Builds a policy with a maximum number of attempts and a base and maximum delay.
doc.DelayForAttempt = How many milliseconds to wait after attempt number <code>attempt</code> failed: the base delay after the first, then doubling each time up to the ceiling. It does not sleep.
doc.ShouldRetry = True when an error happened, is retryable at any layer, and <code>attempt</code> is still below <code>max_attempts</code>.
doc.Free = Releases the error's vectors. Wrapped copies are not affected.
