pkg.intro <<
<p>In Salam you start a function that should run alongside the rest of the program with <code>spawn</code>. It takes a function with no parameters and no result and gives back a number, the thread's handle. <code>join</code>, or <code>thread.Join</code>, waits for that thread to finish.</p>
<p>The <code>thread</code> package wraps that handle in a <code>Thread</code> so you can keep several of them in a vector and wait for all of them at once, and <code>SpawnStack</code> starts a thread with a stack of the size you choose. Threads share the program's globals and heap; for shared data use <a href="/std/sync/">sync</a> or <a href="/std/atomic/">atomic</a>, to pass values between threads <a href="/std/chan/">chan</a>, and to spread a loop over every core <a href="/std/pool/">pool</a>. A thread cannot be stopped from outside; to ask one to finish early, use <a href="/std/ctx/">ctx</a> or an atomic flag it checks.</p>

<h2 id="guide-split">Split one job across threads</h2>
<p>The most common use of threads is to cut a big job into parts and give each part its own thread. Give each thread its own piece of memory to write its answer into, start them all, then wait for all of them with <code>JoinAll</code>. Because no two threads write to the same place, there is nothing to lock. <code>spawn</code> also takes a second argument, a pointer the function receives as its parameter; that is how each thread learns which part is its own.</p>
{{example.thread-guide-split}}
<p>The parts may finish in any order, but the program reads the answers only after <code>JoinAll</code> and in the order it stored them, so the output is always the same.</p>

<h2 id="guide-background">Do something else while a thread works</h2>
<p>A thread does not have to be part of a group. Start one slow task in the background, carry on with other work on the main thread, and call <code>Join</code> at the point where you need the result. Until <code>Join</code> returns, do not read what the thread is writing.</p>
{{example.thread-guide-background}}
<p>Here only the main thread prints. If both threads printed, the lines could come out in a different order on every run.</p>

<h2 id="guide-stack">Deep recursion on a bigger stack</h2>
<p>A thread from <code>spawn</code> gets the system's default stack, which deep recursion can overflow. <code>SpawnStack</code> starts the function on a stack of the size you ask for. The system may refuse a very large stack, so check the thread with <code>Valid</code> and have a plan for the case where it is not.</p>
{{example.thread-guide-fallback}}
<p>The function given to <code>SpawnStack</code> takes a <code>void*</code>, so the same function can also be called directly with <code>null</code> when no thread could be started.</p>

<h2 id="guide-pitfalls">Pitfalls, and which tool to use</h2>
<ul>
<li>Join every thread you start. A program that returns from <code>main</code> while threads are still running cuts them off midway.</li>
<li>Globals are shared by every thread. Two threads that change the same variable without a lock give a different answer from run to run.</li>
<li>Output from several threads interleaves in no fixed order. Collect results and print them from one thread.</li>
<li>A handle of zero means the thread did not start. <code>Join</code> on it does nothing, so check <code>Valid</code> when it matters.</li>
<li>Join each thread exactly once. On Linux and macOS <code>Join</code> also frees the handle, so a second <code>Join</code> of the same thread uses freed memory and can crash.</li>
<li><code>Collect</code> returns the vector it was given, grown by one; always assign the result back, as in <code>group = thread.Collect(group, spawn(work))</code>.</li>
</ul>

doc.Thread = A thread, running or finished.
doc.Thread.handle = The handle <code>spawn</code> returned; zero means invalid.
doc.New = Wraps a <code>spawn</code> handle in a <code>Thread</code>.
doc.SpawnStack = Starts a function on a new thread with a stack of the size you give, in bytes, for work that needs more than the default, such as deep recursion. The function takes a <code>void*</code> and returns nothing. If the system cannot give that stack it returns an invalid handle, so check with <code>Valid</code>.
doc.Join = Waits for the thread to finish and releases its handle. It does nothing for an invalid thread. Join a thread only once.
doc.JoinAll = Waits for every thread in a vector to finish, in order, and releases their handles. The vector itself is not freed.
doc.Valid = True when the handle is not zero.
doc.Handle = The thread's handle.
doc.Collect = Adds a new thread with this handle to a vector and returns the vector; assign the result back to your variable.
