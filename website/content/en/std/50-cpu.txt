pkg.intro <<
<p>Modern processors can run one round of AES, or multiply two 64-bit values without carries, in a single instruction. This package makes those instructions available on <code>u128</code> values, and tells you at run time whether the machine in front of you has them. It is the building block for hardware AES-GCM in <a href="/std/tls/">tls</a>, which is wired to it in a later change; most programs never need to call this package.</p>
<p>The instructions are real only when the program is built with the LLVM backend, which every release build uses. On the C backend, the native backend, the interpreter and in the browser every function still works, but as a slow software model of the instruction, and <code>HasHardwareCrypto</code> is false so that callers choose their own faster code. The software model gives the same bytes, which is what lets a test run the same data both ways.</p>
<p>Things to know:</p>
<ul>
<li><strong>Test first, then call.</strong> The <code>Hw</code> functions work everywhere, but only where <code>HasHardwareCrypto</code> is true are they one instruction each.</li>
<li><strong>The switch is read when a cipher is made.</strong> <code>SetHardware(false)</code> affects the next <code>AeadNew</code> or one shot call, not a context that already exists. The environment variable <code>SALAM_NO_HWCRYPTO</code> does the same for a whole run.</li>
<li><strong><code>HwClmul</code> wants a literal.</strong> Its third argument becomes part of the instruction, so write <code>0</code>, <code>1</code>, <code>16</code> or <code>17</code> there, not a variable.</li>
<li><strong>Constant time.</strong> The instructions take the same time for any data, which the table based software AES cannot promise.</li>
</ul>

<h2 id="guide-switch">Check the fast path against the slow one</h2>
<p><code>SetHardware</code> turns the fast path off, so one program can seal the same message both ways and compare. This is how the tests of the package check that the two paths give the same bytes. On a machine without the instructions both runs take the software path and the answer is still the same.</p>
{{example.cpu-guide-switch}}
<p>The tag line is the tag of 32 zero bytes under an all zero key and nonce; the algorithm fixes it, so it is the same on every machine.</p>

doc.FEATURE_HW_CRYPTO = The bit of <code>Features</code> that says the AES and carry-less multiply instructions are there and the program was built to use them.
doc.FEATURE_X86 = The bit of <code>Features</code> that says the processor is x86-64 (AES-NI and PCLMULQDQ).
doc.FEATURE_ARM64 = The bit of <code>Features</code> that says the processor is AArch64 (the Crypto Extensions).
doc.Features = The features of this processor as bits: <code>FEATURE_HW_CRYPTO</code> together with <code>FEATURE_X86</code> or <code>FEATURE_ARM64</code>. It is 0 when the backend does not lower the instructions or the processor lacks them.
doc.HwAesEnc = One round of AES on a block, the <code>aesenc</code> of x86 (SubBytes, ShiftRows, MixColumns, then xor with the round key). The block is the 16 bytes in memory order, read as a little endian <code>u128</code>.
doc.HwAesEncLast = The last round of AES, without MixColumns, the <code>aesenclast</code> of x86.
doc.HwClmul = The carry-less product of one 64-bit half of <code>a</code> and one of <code>b</code>, as the 128-bit result. Bit 0 of <code>imm</code> picks the half of <code>a</code> and bit 4 the half of <code>b</code>, as in <code>pclmulqdq</code>. It must be an integer literal.
doc.HwSwap64 = Swaps the two 64-bit halves.
doc.HwBswap = Reverses all 16 bytes.
doc.HwLoad = Reads 16 bytes from any address, aligned or not.
doc.HwStore = Writes 16 bytes to any address, aligned or not.
doc.SetHardware = Turns the fast path on or off for ciphers made afterwards. It cannot turn on what the processor or the backend does not have.
doc.HasHardwareCrypto = True when the instructions are there, the build uses them, and the switch is on.
doc.HasAesNi = True on an x86-64 processor with AES-NI, PCLMULQDQ, SSSE3 and SSE4.1, when the build uses them.
doc.HasPclmul = True when carry-less multiplication is available; it is checked together with AES, so it equals <code>HasAesNi</code>.
doc.HasArmCrypto = True on an AArch64 processor with the AES and PMULL instructions, when the build uses them.
