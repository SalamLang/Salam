pkg.intro <<
<p>If each turn of a loop is independent of the others, such as processing each slot of an array on its own, <code>ParallelFor</code> spreads the turns across several worker threads and waits for all of them. The loop body is a function taking an <code>i64</code>, the turn's number.</p>
<p>The package also has a long-lived, bounded worker pool, the Salam answer to goroutines. <code>spawn</code> starts one operating-system thread per call with no limit; a <code>Pool</code> starts its threads once and never more, keeps at most <code>queue</code> tasks waiting, and makes <code>Submit</code> wait when the queue is full, so a fast producer cannot pile up unbounded work. <code>Go</code> runs a task on a shared pool sized to the cores, <code>Group</code> limits how many tasks run at once and keeps the first error, and <code>Async</code> hands back a <code>Future</code> you can <code>Await</code>. To receive from several channels, see <code>Select</code> in <a href="/std/chan/">chan</a>.</p>
<p>Tasks are threads, not green threads: a task that blocks keeps its worker busy, so a task must not wait for a task queued behind it. Use <code>SubmitOrRun</code> when tasks submit tasks. For shared state, use <a href="/std/sync/">sync</a> and <a href="/std/atomic/">atomic</a>.</p>
<p>The things people get wrong:</p>
<ul>
<li>Relying on the order of the turns, or changing shared data from them without a lock. Each turn writing to its own slot is safe; anything else needs <a href="/std/atomic/">atomic</a> or a mutex.</li>
<li>Making the turns too small. Taking the next turn number costs a lock, and every call starts and joins threads, so a turn should do a fair amount of work (see <a href="#guide-chunks">chunks</a>).</li>
<li>Calling <code>ParallelFor</code> in a hot loop. Each call pays for creating threads; parallelize the outer loop instead of the inner one.</li>
</ul>

<h2 id="guide-rows">One turn per row</h2>
<p>The natural fit for <code>ParallelFor</code> is data laid out in rows, such as the pixels of an image or the lines of a table. Make each turn handle one row: the turns touch different memory, so they need no lock, and the result is the same whatever order they ran in.</p>
{{example.pool-guide-pixels}}
<p>The loop body here is a short lambda that calls a named function. Keeping the real work in a named function makes it easy to test on its own, without any threads.</p>

<h2 id="guide-chunks">Chunks, not single items</h2>
<p>Each turn has a small cost of its own, so a million turns that each add one number spend more time on bookkeeping than on adding. Cut the work into a few large chunks instead, let each turn handle one chunk and write its partial result to its own slot, and combine the slots on the main thread at the end.</p>
{{example.pool-guide-chunks}}
<p><code>ParallelForAuto</code> picks the number of workers from the processor count. A few chunks per worker is a good size: enough for the work to even out when some chunks are slower, few enough that the overhead stays small.</p>

<h2 id="guide-shared">Combine results with an atomic counter</h2>
<p>When the turns produce something that has to be added into one place, such as a count of matches, the simplest safe choice is an <a href="/std/atomic/">atomic</a>.<code>I64</code>. Here every number below 100000 is one turn, and each turn that finds a prime adds one to the shared counter.</p>
{{example.pool-guide-primes}}
<p>An atomic add per match is fine when matches are rare compared with the work of each turn. If every turn would update the counter, use partial results per chunk as in the previous section instead.</p>

<h2 id="guide-rules">Rules for the loop body</h2>
<ul>
<li>Never rely on the order of the turns. Turn 5 can finish before turn 0.</li>
<li>A turn may write to its own slot freely. Anything shared needs a <a href="/std/sync/">sync</a>.<code>Mutex</code> or an atomic.</li>
<li>Do not print from the loop body; the lines come out mixed up. Store the results and print after <code>ParallelFor</code> returns.</li>
<li><code>ParallelFor</code> waits for every turn, so as soon as it returns all results are ready and no join is needed.</li>
<li>Small loops are faster without threads. Parallelize only when one run of the loop takes noticeable time.</li>
</ul>
>>

doc.CPUCount = The number of processor cores that are online, at least one.
doc.ParallelFor = Runs the body for the numbers zero to <code>n - 1</code> on <code>workers</code> new threads, at most <code>n</code> of them, and returns when every turn is done. Nothing happens when <code>n</code> is zero or less.
doc.ParallelForAuto = Like <code>ParallelFor</code>, with one thread per core from <code>CPUCount</code>.

doc.New = Starts a pool with <code>workers</code> threads and room for <code>queue</code> waiting tasks. Both are raised to at least one. The thread count never grows.
doc.NewAuto = A pool with one worker per core and a queue four times that size.
doc.Submit = Queues a task. It waits while the queue is full, which is the backpressure that bounds the pool. Returns false only if the pool is stopped.
doc.TrySubmit = Queues a task without waiting. Returns false when the queue is full or the pool is stopped.
doc.SubmitOrRun = Queues a task, or runs it on the calling thread when the queue is full. Safe for tasks that submit tasks.
doc.Wait = Waits until the queue is empty and no task is running. The pool can be used again afterwards.
doc.Stop = Finishes the queued tasks, joins the workers and frees the pool. Do not use the pool after this.
doc.Running = The number of tasks running now.
doc.Pending = The number of tasks waiting in the queue.
doc.Workers = The number of worker threads of the pool.
doc.Go = Runs a task on a shared pool with one worker per core, created on first use.
doc.GoWait = Waits until every task started with <code>Go</code> has finished.
doc.Group = A set of tasks with a limit on how many run at once and a shared first error.
doc.NewGroup = Creates a group that runs at most <code>limit</code> tasks at a time.
doc.GroupGo = Adds a task that returns an error text, empty for success. Once any task fails, tasks not yet started are skipped.
doc.GroupFailed = True once any task of the group has returned an error.
doc.GroupWait = Waits for the group and returns the first error text, or an empty text.
doc.GroupStop = Frees the group and its threads.
doc.Future = The result of a task that is still running.
doc.Async = Runs a task that returns an <code>i64</code> and gives back a future for it.
doc.AsyncStr = Like <code>Async</code> for a task that returns a text.
doc.Await = Waits for the task and returns its <code>i64</code> result.
doc.AwaitStr = Waits for the task and returns its text result.
doc.Ready = True when the task has finished, without waiting.
doc.Release = Frees a future after its result has been taken.
doc.Pool = A bounded pool of worker threads.
