pkg.intro <<
<p>This package holds the common ways of writing bytes as plain text: <strong>Base64</strong> for fitting binary data into JSON or email, <strong>hexadecimal</strong> for showing bytes, and <strong>URL encoding</strong> for putting text or special characters into a web address.</p>
<p>The larger formats, such as JSON, YAML and XML, have sub-packages of their own, listed in this same group.</p>

<p>Every function takes and returns <code>str</code>, except the two <code>...Bytes</code> forms, which work on a pointer and a length for binary data. The encoders cannot fail. The decoders <code>Base64Decode</code>, <code>Base64DecodeBytes</code>, <code>HexDecode</code> and <code>URLDecode</code> are declared <code>throws</code>: on bad input they throw an <a href="/std/core/">Error</a> whose <code>kind</code> is <code>Syntax</code> (a character that does not belong), <code>UnexpectedEnd</code> (the text stops in the middle of a group, a pair or an escape) or <code>OutOfRange</code> (the buffer is too small), with the byte <code>offset</code> and the <code>line</code> and <code>column</code> of the problem. Neighbouring packages: <a href="/std/encoding/binary/">encoding/binary</a> for numbers packed into bytes, <a href="/std/crypto/">crypto</a> for hashes that you then show in hex, and <a href="/std/jwt/">jwt</a> for tokens.</p>
<p>The things people get wrong:</p>
<ul>
<li>Decoding binary into a <code>str</code>. A <code>str</code> ends at the first zero byte, so <code>Base64Decode</code> and <code>HexDecode</code> cut binary data short; use <code>Base64DecodeBytes</code> into a buffer.</li>
<li>Forgetting that decoding can fail. Every decoder call needs <code>try</code>: inside a <code>try:</code> block to handle the error, or in front of the call in a function that is itself <code>throws</code> to pass it on.</li>
<li>Expecting <code>HexDecode</code> to skip spaces or a <code>0x</code> prefix. It reads exactly two hex digits per byte and nothing else; strip separators first.</li>
<li><code>URLEncode</code> writes a space as <code>%20</code>, while <code>URLDecode</code> reads both <code>%20</code> and <code>+</code> as a space. A <code>%</code> that is not followed by two hex digits, such as the one in <code>50%</code>, is an error; send it as <code>%25</code>.</li>
</ul>

<h2 id="guide-basic-auth">Guide: an HTTP Basic login header</h2>
<p>HTTP Basic authentication sends <code>user:password</code> in Base64 after the word <code>Basic</code>. Base64 is not encryption, anyone can decode it, so this only belongs on HTTPS. Building the header is one call; reading it on the server side means decoding with <code>Base64Decode</code> and splitting at the first colon, since the password itself may contain more colons.</p>
{{example.encoding-guide-basic-auth}}
<p><code>Base64Decode</code> throws when the text is not valid Base64, so a garbled header is refused instead of being turned into a random user name.</p>

<h2 id="guide-strict">Guide: what the Base64 decoder accepts</h2>
<p><code>Base64Decode</code> accepts the forms Base64 really comes in: padded or unpadded, the standard alphabet (<code>+</code> and <code>/</code>) or the URL-safe one (<code>-</code> and <code>_</code>), and spaces, tabs and line breaks anywhere, because MIME and PEM files wrap Base64 at 76 or 64 characters. Anything else is an error, so a typo is never turned into damaged bytes.</p>
{{example.encoding-guide-strict}}
<p>A character outside both alphabets is a <code>Syntax</code> error at its position; so is anything after the <code>=</code> padding, or more <code>=</code> than the last group needs. Text that stops one character into a group of four, or that starts padding but leaves out an <code>=</code>, is <code>UnexpectedEnd</code>. For binary data use <code>Base64EncodeBytes</code> and <code>Base64DecodeBytes</code>, which work on a pointer and a length, because a <code>str</code> stops at the first zero byte.</p>

<h2 id="guide-hex">Guide: seeing the bytes with hex</h2>
<p>Hexadecimal writes each byte as two digits, which makes it the easiest way to see what a string really holds. Persian letters take two bytes each in UTF-8, so <code>len</code> of a Persian word counts bytes, not letters. Hex is also the usual form for hashes, keys and colours.</p>
{{example.encoding-guide-hex}}
<p><code>HexEncode</code> writes lower case; <code>HexDecode</code> reads both cases, and throws on an odd number of digits or a character that is not a hex digit.</p>

<h2 id="guide-url">Guide: putting text into a URL</h2>
<p>A query value cannot contain spaces, <code>&amp;</code>, <code>=</code> or non-ASCII letters as they are. <code>URLEncode</code> escapes everything except letters, digits and <code>- _ . ~</code>, so the result is safe anywhere in a URL. <code>URLDecode</code> undoes it and also reads <code>+</code> as a space, the way HTML forms send it; a broken escape such as <code>50%off</code> makes it throw.</p>
{{example.encoding-guide-url}}
<p>Encode each value on its own and join them with <code>&amp;</code>, as <code>link</code> does: encoding the whole URL at once would also escape the <code>?</code> and <code>&amp;</code> that hold it together. For whole query strings with repeated keys, <a href="/std/encoding/query/">encoding/query</a> does the bookkeeping, and <a href="/std/encoding/url/">encoding/url</a> parses and rebuilds complete URLs.</p>

doc.Base64Encode = Turns text into standard Base64, padded with <code>=</code>.
doc.Base64EncodeBytes = Turns <code>n</code> bytes of memory into Base64.
doc.Base64Decode = Turns Base64 back into text. Both the standard (<code>+/</code>) and the URL-safe (<code>-_</code>) alphabet are read, padding is optional and whitespace is skipped. Throws <code>Syntax</code> for any other character, data after the <code>=</code> padding or too much padding, and <code>UnexpectedEnd</code> when the text stops one character into a group or misses an <code>=</code>; the error has the offset, line and column.
doc.Base64DecodeBytes = Decodes Base64, read as <code>Base64Decode</code> reads it, into the buffer <code>out</code> of capacity <code>cap</code>, and returns how many bytes it wrote. Throws the same errors as <code>Base64Decode</code>, and <code>OutOfRange</code> when the data needs more than <code>cap</code> bytes.
doc.HexEncode = Writes each byte of the text as two lower case hexadecimal digits.
doc.HexVal = The value of the first character as a hexadecimal digit, or -1 when it is not one.
doc.HexDecode = Turns a hexadecimal string back into bytes, reading upper and lower case. Throws <code>Syntax</code> at the first character that is not a hex digit and <code>UnexpectedEnd</code> when the number of digits is odd.
doc.URLEncode = Percent-encodes text for a web address, byte by byte with upper case hex; letters, digits and <code>-_.~</code> are left as they are, and a space becomes <code>%20</code>.
doc.URLDecode = Undoes percent encoding and turns <code>+</code> into a space. Throws <code>Syntax</code> when a <code>%</code> is followed by something other than two hex digits, and <code>UnexpectedEnd</code> when the text ends inside an escape.
