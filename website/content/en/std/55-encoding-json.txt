pkg.intro <<
<p>There are three ways to work with JSON here. For simple jobs, functions such as <code>Member</code>, <code>Object</code> and <code>Get</code> work directly on JSON text. For real programs, <code>Marshal</code> and <code>Unmarshal</code> convert a Salam struct to JSON and back. For data whose shape you do not know in advance, <code>Decode</code> returns a dynamic <a href="/std/encoding-value/">Value</a>.</p>
<p>Set the key name of a field with <code>@json "name"</code> above it; <code>@json "-"</code> leaves the field out. Without it, the field's own name becomes the key.</p>

<p>Use this package for APIs, config files and anything another program will read. Its neighbours: <a href="/std/encoding-yaml/">encoding/yaml</a> and <a href="/std/encoding-toml/">encoding/toml</a> for files people edit, <a href="/std/encoding-msgpack/">encoding/msgpack</a> when the data should be small and binary, and <a href="/std/encoding-serde/">encoding/serde</a> to read or write the same struct in several formats.</p>
<p>The things people get wrong:</p>
<ul>
<li><code>GetInt</code> returns an <code>int</code>, 32 bits, and clamps anything larger: <code>3000000000</code> comes back as <code>2147483647</code>. For ids and timestamps, read the field with <code>Unmarshal</code> into an <code>i64</code>, or parse the text from <code>Get</code>.</li>
<li><code>Get</code>, <code>GetInt</code> and <code>Has</code> look only at the top level of an object. For nested values use <code>GetPath</code>, such as <code>GetPath(text, "user.address.city")</code>.</li>
<li>Strict or lenient. <code>Unmarshal</code> fails on a missing field, an unknown key or a type that does not match; <code>UnmarshalLenient</code> keeps the struct's defaults for missing fields and skips unknown keys, but a wrong type still fails.</li>
<li>Key order. <code>Marshal</code> writes fields in struct order. A decoded <code>Value</code> object keeps the order of the text and <code>Encode</code> writes its keys in that order; pass <code>sort_keys</code> to <code>Encode</code> when output must be alphabetical.</li>
</ul>

<h2 id="guide-config">Guide: load a config file into a struct</h2>
<p>A config file is the most common JSON a program reads. Describe it as structs, give every field the default you want, and let <code>UnmarshalLenient</code> fill in what the file has. Nested objects map to nested structs and arrays map to <code>Vector</code> fields.</p>
{{example.encoding-json-guide-config}}
<p>The file left out <code>debug</code> and <code>db.pool</code>, so they keep their defaults. That is the reason for the lenient form here: plain <code>Unmarshal</code> is strict and fails with <code>missing key 'pool'</code> when a field is absent, and with <code>unknown key</code> when the file has a key the struct does not. Strict is right for messages between programs, where a missing field is a bug; lenient is right for files people edit by hand. To read a file from disk, pass the text of <code>file.ReadAll</code> from <a href="/std/fs-file/">fs/file</a>.</p>

<h2 id="guide-response">Guide: build an API response</h2>
<p>Going the other way, <code>Marshal</code> turns a struct into compact JSON for the wire and <code>MarshalIndent</code> into readable JSON for logs and files. A <code>Vector</code> of structs becomes an array of objects, quotes inside strings are escaped, and the field order is the order of the struct.</p>
{{example.encoding-json-guide-response}}
<p><code>@json "price_cents"</code> renames a field in the JSON without renaming it in the code, and <code>@json "-"</code> keeps internal fields such as <code>cache_key</code> out of the output. Use it for passwords and tokens too, so they can never leak into a response by accident.</p>

<h2 id="guide-dynamic">Guide: explore JSON of unknown shape</h2>
<p>When you do not know the shape ahead of time, for example a webhook from another service, <code>Decode</code> gives a tree of <a href="/std/encoding-value/">Value</a> nodes. Ask each node what it is with <code>IsString</code>, <code>IsInt</code>, <code>IsObject</code> and the rest, then read it with the matching <code>As</code> function.</p>
{{example.encoding-json-guide-dynamic}}
<p>Whole numbers come back as <code>int</code> and numbers with a fraction as <code>float</code>; <code>IsNumber</code> accepts both. A decoded object keeps its keys in the order of the text, but a sender is free to change that order, so walk a list of the keys you expect, as this program does, and use <code>ObjectHas</code> for the optional ones.</p>

<h2 id="guide-errors">Guide: report bad input</h2>
<p>Every decoding function takes an <code>EncodingError</code> from <a href="/std/encoding-encerr/">encoding/encerr</a>. When it fails, <code>message</code> says what was wrong and <code>position</code> is the byte offset where the reader stopped, which is what you show the user. The text helpers like <code>Get</code> never fail; they return an empty string for a missing key, so check with <code>Has</code> or <code>Valid</code> first when that matters.</p>
{{example.encoding-json-guide-errors}}

<h2 id="guide-ndjson">Guide: stream newline-delimited JSON</h2>
<p>Logs and exports often hold one JSON value per line (NDJSON). A decoder reads them one at a time: <code>More</code> says whether another value is left, and <code>Decode</code> returns the next one. <code>NewBufDecoder</code> reads from a string and <code>NewDecoder</code> from an open file. Encoders write the same format, one value per line.</p>
{{example.encoding-json-guide-ndjson}}
<p><code>until d.More():</code> reads naturally as "while there is more", because <code>until</code> in Salam runs while its condition holds.</p>

doc.Marshal = Turns any Salam value, from a number or a string to a struct, a vector or a map, into compact JSON.
doc.MarshalIndent = Like <code>Marshal</code>, indented.
doc.Unmarshal = Fills the struct <code>out</code> from JSON. Every field has to be present with a matching type and an unknown key is an error too; on failure <code>err</code> is filled in and it returns false.
doc.UnmarshalLenient = Like <code>Unmarshal</code>, but unknown keys are skipped and missing fields keep the value they already had. A value of the wrong type is still an error.
doc.JSONEncoder = A streaming writer: it writes several JSON values one after another, each on its own line.

doc.JSONEncoder.useFile = Whether it writes to a file or into memory.
doc.JSONEncoder.buf = The text buffer, when it writes into memory.
doc.JSONEncoder.indent = The indent unit; empty means one value per line.
doc.JSONEncoder.count = How many values have been written.
doc.JSONEncoder.Encode = Writes one value and a newline after it.
doc.JSONEncoder.String = The text written into memory.
doc.JSONEncoder.Close = Closes the writer.
doc.JSONDecoder = A streaming reader: it reads consecutive JSON values one at a time, as in a JSON Lines file.
doc.JSONDecoder.src = The source file.
doc.JSONDecoder.useFile = Whether it reads from a file.
doc.JSONDecoder.buf = The text that was read.
doc.JSONDecoder.pos = The current position in the text.
doc.JSONDecoder.loaded = Whether the file has been read.
doc.JSONDecoder.eof = It has reached the end of the text.
doc.JSONDecoder.bad = An error happened while reading.
doc.JSONDecoder.More = True when another value is left.
doc.JSONDecoder.Decode = Reads the next value.
doc.NewEncoder = A writer that writes into an open file.
doc.NewEncoderIndent = A file writer with indenting.
doc.NewBufEncoder = A writer that writes into memory; get the text with <code>String</code>.
doc.NewBufEncoderIndent = A memory writer with indenting.
doc.NewDecoder = A reader that reads from an open file.
doc.NewBufDecoder = A reader that reads from a string.
doc.SchemaEnvelope = Builds the JSON Schema of a value's type, along with the definitions of the nested types, inside an envelope to be combined later with <code>SchemaMerge</code>.
doc.Schema = The complete JSON Schema of a value's type, for documenting an API or validating at the other end.
doc.SchemaMerge = Merges several schema envelopes into one document with shared definitions.
doc.JSONOptions = The options for <code>Encode</code>.
doc.JSONOptions.indent = The indent unit; empty means one line.
doc.JSONOptions.sort_keys = Write the keys in alphabetical order. Without it they are written in the order the object holds them: the order they were added or decoded.
doc.JSONOptions.ignore_null = Leave out the keys whose value is null.
doc.Decode = Turns JSON into a dynamic <code>Value</code>; on an error <code>err</code> is filled in.
doc.Encode = Turns a <code>Value</code> into JSON with the given options.
doc.EncodeDefault = Turns a <code>Value</code> into JSON with the default options.
