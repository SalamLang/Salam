pkg.intro <<
<p>YAML is the usual format for configuration files. This package converts YAML to JSON internally, which is what makes its reading functions simple and what lets it work alongside the <a href="/std/encoding/json/">json</a> package.</p>
<p>The reading functions take a <strong>path</strong>: keys separated by dots, with a list index in square brackets, as in <code>app.hosts[1]</code>. A path that is not there gives an empty string or zero; to tell that apart from a real value, use <code>Has</code>.</p>

<p>It reads the YAML that configuration files use: nested maps, lists in dashed and <code>[flow]</code> form, quoted strings, <code>|</code> and <code>&gt;</code> block text, comments and several documents. For flat <code>key = value</code> settings with sections and overrides, <a href="/std/config/">config</a> is simpler, and it reads YAML too.</p>
<p>The things people get wrong:</p>
<ul>
<li>Anchors and aliases (<code>&amp;base</code>, <code>*base</code>, <code>&lt;&lt;: *base</code>) are not supported. A value like <code>&amp;a 1</code> is read as the string <code>&amp;a 1</code>, and an anchor on a map, as in <code>base: &amp;base</code> followed by indented keys, loses the rest of the document without an error. Write such files out in full, or expand them with another tool first.</li>
<li><code>yes</code>, <code>no</code>, <code>on</code> and <code>off</code> are strings, as in YAML 1.2, so <code>GetBool</code> is false for them. Only <code>true</code> and <code>false</code> are booleans.</li>
<li><code>GetInt</code> returns a 32-bit <code>int</code> and wraps around for larger numbers. Read sizes, ids and timestamps through <code>ToJSON</code> into an <code>i64</code> field (see <a href="#guide-types">below</a>).</li>
<li>Every path function parses the whole text again. For many reads from a large file, call <code>ToJSON</code> or <code>Decode</code> once and work on the result.</li>
</ul>

<h2 id="guide-config">Guide: read a config file with defaults</h2>
<p>The path functions are the quickest way to read a config file. Check first that the sections you depend on exist with <code>HasKeys</code>, then read each setting with the typed getter. For optional settings, wrap <code>Get</code> in a small helper that falls back to a default when <code>Has</code> says the key is not there.</p>
{{example.encoding-yaml-guide-config}}
<p>Comments starting with <code>#</code> are ignored. <code>GetInt</code> and <code>GetBool</code> return 0 and <code>false</code> for a missing key, which is also a real value, so a default other than zero needs the <code>Has</code> check.</p>

<h2 id="guide-struct">Guide: YAML into a struct</h2>
<p>For a config with many fields, a struct is easier to pass around than a text and a list of paths. There is no YAML <code>Unmarshal</code> of its own, but there does not need to be: <code>ToJSON</code> turns the YAML into JSON, and <a href="/std/encoding/json/">encoding/json</a> fills the struct, with the same <code>@json</code> names and defaults.</p>
{{example.encoding-yaml-guide-struct}}
<p><code>replicas</code> is not in the file, so it keeps its default of 1 because the lenient form was used. With <code>json.Unmarshal</code> the missing key would be an error.</p>

<h2 id="guide-list">Guide: walk a list of records</h2>
<p>A list of objects, such as the jobs of a CI file, is read with <code>Len</code> and an index in the path. Build the path for item <code>i</code> once and add the field names to it. <code>[lint]</code> is the short flow form of a list, and reads the same way as the dashed form.</p>
{{example.encoding-yaml-guide-list}}

<h2 id="guide-multi">Guide: several documents in one file</h2>
<p>Kubernetes manifests and some log formats put several YAML documents in one file, separated by a line with <code>---</code>. <code>SplitDocuments</code> cuts them apart, and each piece is then an ordinary YAML text for the other functions.</p>
{{example.encoding-yaml-guide-multi}}
<p><code>ToJSON</code> is also how you hand YAML to anything that speaks JSON, such as an HTTP API. Going the other way, <code>Dump</code> writes JSON text as YAML.</p>

<h2 id="guide-types">Guide: what type did the value get?</h2>
<p>YAML decides the type of a value from how it looks, and the result is not always what the author meant. <code>TypeOf</code> shows what the reader saw. Here <code>yes</code> stayed a string, <code>007</code> kept its zeros as a string, and the five gigabyte limit is too big for <code>GetInt</code> but fine for an <code>i64</code> field.</p>
{{example.encoding-yaml-guide-types}}
<p>The struct route also checks the types for you: <code>public: yes</code> is refused instead of read as false. Writing <code>true</code> and quoting values that must stay text, such as <code>"007"</code>, makes the file mean the same to every reader.</p>

doc.DumpWith = Converts JSON to YAML with the indent unit of your choice.
doc.Dump = Converts JSON to YAML indented with two spaces; strings that need them get quotes.
doc.DumpTabs = Like <code>Dump</code>, with tabs.
doc.Escape = Escapes a string so it can go inside YAML quotes.
doc.Str = Turns a string into a ready value, with quotes.
doc.Member = One key and string pair, for building an object.
doc.MemberInt = A key and whole number pair.
doc.MemberBool = A key and boolean pair.
doc.MemberFloat = A key and decimal pair.
doc.MemberRaw = A key paired with a ready-made value.
doc.Object = Puts the pairs together into an object. The result is JSON, which <code>Dump</code> turns into YAML.
doc.Array = Puts values together into a list.
doc.Get = The value at a path as text; strings come back without their quotes, and a missing path or <code>null</code> gives an empty string.
doc.Has = True when the path is there.
doc.GetInt = The whole number at a path as a 32-bit <code>int</code>; 0 when it is missing. Larger numbers wrap around.
doc.GetFloat = The decimal value at a path.
doc.GetBool = The boolean at a path: true only for <code>true</code>. <code>yes</code> and <code>on</code> are strings and give false.
doc.TypeOf = The kind of value at a path: <code>map</code>, <code>list</code>, <code>string</code>, <code>int</code>, <code>float</code>, <code>bool</code>, <code>null</code>, or <code>none</code> when it is absent.
doc.Len = The number of list elements, or object keys, at a path.
doc.Keys = The keys of the object at a path; an empty path means the top level.
doc.HasKeys = True when every key you name is at the top level of the document; for checking a configuration file.
doc.Decode = Turns YAML into a dynamic <code>Value</code>.
doc.Encode = Turns a <code>Value</code> into YAML.
doc.Parse = Reads YAML and returns the same data as JSON.
doc.ToJSON = Converts YAML to JSON.
doc.Valid = True when the text can be read as YAML. It is lenient: it does not reject tabs used for indenting.
doc.SplitDocuments = Splits a file of several documents, separated by <code>---</code>, into separate ones.
