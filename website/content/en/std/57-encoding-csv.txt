pkg.intro <<
<p>CSV is the simplest table format: one row per line, fields separated by commas. A field containing a comma, a quote or a newline is wrapped in quotes, and a quote inside it is doubled. This package follows those rules both ways.</p>
<p>Every field is a string. When the first row is a header, <code>ToValue</code> turns each row into an object with those keys.</p>

<h2 id="guide-report">Guide: totals from a CSV export</h2>
<p>The typical job is a spreadsheet export: read every row, skip the header, convert the number columns and add them up. <code>ReadAll</code> gives a <code>CSVTable</code> whose <code>rows</code> each hold a <code>fields</code> vector, one string per column. A <code>HashMap</code> keeps the totals and a <code>Vector</code> keeps the cities in the order they first appeared.</p>
{{example.encoding-csv-guide-report}}
<p>Guard against short rows, as the <code>row.fields.len() &lt; 4</code> check does: a blank line or a hand-edited file can have fewer columns than the header. Free the table with <code>FreeTable</code> when you are done.</p>

<h2 id="guide-export">Guide: write a CSV file</h2>
<p><code>WriteLine</code> joins one row and adds quotes only where they are needed: around a field with a comma, a quote or a line break, with inner quotes doubled. That is exactly what Excel, LibreOffice and most import tools expect.</p>
{{example.encoding-csv-guide-export}}
<p>Write the header row the same way as the data rows. <code>WriteLine</code> does not add the line break, so add <code>"\n"</code> yourself, or <code>"\r\n"</code> for tools that insist on it. To save the result, write <code>out</code> with <a href="/std/fs-file/">fs/file</a>.</p>

<h2 id="guide-json">Guide: CSV to JSON</h2>
<p><code>ToValue</code> uses the header row as keys and turns every other row into an object, which <a href="/std/encoding-json/">encoding/json</a> can then print. That is a small CSV to JSON converter in a few lines. <code>FromValue</code> goes back from an array of objects to CSV text.</p>
{{example.encoding-csv-guide-json}}
<p>Every field stays a string, even <code>12</code>, because CSV has no types. Convert the columns you know are numbers with <code>to_int()</code> or <code>to_float()</code>. With <code>CSVOptions { header = false }</code>, <code>ToValueWith</code> returns arrays instead of objects for files without a header.</p>

<h2 id="guide-pitfalls">Guide: edge cases</h2>
<p>The reader keeps fields exactly as they are written. That matters in a few places:</p>
{{example.encoding-csv-guide-pitfalls}}
<ul>
<li>An empty field, including one after a trailing comma, is an empty string, not a missing column.</li>
<li>Spaces around a field are kept; trim them with <code>str.Trim</code> if your source pads columns.</li>
<li>Windows line endings (<code>\r\n</code>) are handled by <code>ReadAll</code>.</li>
<li><code>ReadAll</code> splits the text into lines before it reads the fields, so a quoted field that contains a line break comes back cut in two. If your data can hold line breaks, replace them before writing the file.</li>
</ul>
>>

doc.CSVRow = One row.
doc.CSVRow.fields = The row's fields.
doc.CSVTable = A table.
doc.CSVTable.rows = The rows, including the header row.
doc.CSVOptions = The options for converting to and from a value.
doc.CSVOptions.header = The first row is a header; true by default. When false, each row becomes an array.
doc.ReadAll = Turns a whole piece of CSV text into a table.
doc.FreeTable = Releases the table's memory.
doc.WriteAll = Turns a table into CSV text.
doc.ToValueWith = Turns CSV into a <code>Value</code> with the given options.
doc.ToValue = Turns CSV with a header into an array of objects.
doc.FromValueWith = Turns an array of objects, or of arrays, into CSV with the given options.
doc.FromValue = Turns an array of objects into CSV with a header.
doc.ReadLine = Splits one CSV line into its fields.
doc.WriteLine = Turns fields into one CSV line, quoting wherever it has to.
