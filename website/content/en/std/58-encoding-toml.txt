pkg.intro <<
<p>TOML is a straightforward configuration format of <code>[section]</code> tables and <code>key = value</code> pairs. This package turns it into a dynamic <a href="../encoding-value/">Value</a> and back.</p>
<p>Tables become objects, <code>[[name]]</code> becomes an array of objects, and inline tables, arrays, dotted keys, strings in single or double quotes, integers, floats and booleans are all read. Dates are kept as strings. Multi-line strings in triple quotes are not supported yet and make the document invalid.</p>

<h2 id="guide-manifest">Guide: read a project manifest</h2>
<p>Project files such as <code>Cargo.toml</code> or <code>pyproject.toml</code> mix plain tables, inline tables and arrays of tables. <code>DecodeStrict</code> reads the whole file into a <a href="/std/encoding-value/">Value</a> and tells you through <code>ok</code> whether it was valid; from there the <code>value</code> functions walk it.</p>
{{example.encoding-toml-guide-manifest}}
<p>A dependency can be a plain version string or an inline table with more detail, so the program asks <code>IsString</code> before reading it. Objects do not keep the order of their keys; sorting <code>ObjectKeys</code> with <code>sort.QuickSort</code> gives a stable listing.</p>

<h2 id="guide-struct">Guide: TOML into a struct</h2>
<p>For settings you use all over a program, load them into a struct once. Encode the decoded value as JSON with <code>json.EncodeDefault</code> and let <code>json.UnmarshalLenient</code> fill the struct: keys the file leaves out keep the struct's defaults, and a <code>[server]</code> table fills a nested struct.</p>
{{example.encoding-toml-guide-struct}}

<h2 id="guide-write">Guide: write a TOML file</h2>
<p>To write TOML, build a <a href="/std/encoding-value/">Value</a> object and pass it to <code>Encode</code> or <code>EncodeStrict</code>. A nested object becomes a <code>[table]</code>. The top level must be an object, since a TOML document is always a table; <code>EncodeStrict</code> reports <code>false</code> for anything else.</p>
{{example.encoding-toml-guide-write}}
<p>Keys are written in no particular order, so do not compare the text with a fixed string. Compare the data instead, as <code>value.Equal</code> does here after reading the text back.</p>

<h2 id="guide-errors">Guide: catching mistakes</h2>
<p>Use <code>DecodeStrict</code> or <code>Valid</code> on any file a person edits. They catch broken syntax: a key without a value, an unclosed string, array or table header.</p>
{{example.encoding-toml-guide-errors}}
<p>The check is about syntax, not every rule of the TOML specification: a key defined twice is accepted, and the later value wins. If a duplicate would be a real problem in your files, check the keys you care about yourself.</p>
>>

doc.DecodeStrict = Reads TOML, setting <code>ok</code> false when the text is not valid.
doc.Decode = Turns TOML into a <code>Value</code>; when the text is not valid it returns whatever was read before the error.
doc.Valid = True when the text is valid TOML.
doc.EncodeStrict = Turns a value into TOML; the top level has to be an object, or <code>ok</code> turns false.
doc.Encode = Turns a value into TOML.
