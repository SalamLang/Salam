<p>TOML is the configuration format of <code>[section]</code> tables and <code>key = value</code> lines used by <code>Cargo.toml</code>, <code>pyproject.toml</code> and many server configs. This package reads TOML text into a dynamic <a href="/std/encoding/value/">Value</a> and writes a Value back as TOML. It has five functions: <code>DecodeStrict</code>, <code>Decode</code> and <code>Valid</code> for reading, <code>EncodeStrict</code> and <code>Encode</code> for writing.</p>
<p>Pick TOML for files people edit by hand. For data that programs exchange use <a href="/std/encoding/json/">encoding/json</a>; for YAML files such as CI or Kubernetes configs use <a href="/std/encoding/yaml/">encoding/yaml</a>; for <code>KEY=value</code> secrets files use <a href="/std/encoding/envfile/">encoding/envfile</a>. If you only want settings loaded from a file with defaults and environment overrides, <a href="/std/config/">config</a> may already do the job.</p>

<h3 id="pitfalls">What trips people up</h3>
<ul>
<li><strong>Use <code>DecodeStrict</code>, not <code>Decode</code>, on files people edit.</strong> <code>Decode</code> never reports an error: on broken input it returns whatever it read before the mistake, so a typo silently drops the rest of the file.</li>
<li><strong>The parser is lenient.</strong> It checks syntax, not every rule of the TOML specification. A key or <code>[table]</code> defined twice is accepted (the tables merge, the later key wins), and an unquoted word such as <code>mode = fast</code> is read as the string <code>"fast"</code> instead of being rejected.</li>
<li><strong>Some syntax is missing.</strong> Multi-line strings in triple quotes (<code>"""</code> or <code>'''</code>) make the document invalid, and the 8-digit <code>\U</code> escape is not decoded. Dates stay strings; parse them with <a href="/std/time/">time</a> if you need them.</li>
<li><strong>Writing is not formatting.</strong> <code>Encode</code> writes keys in no fixed order, drops keys whose value is null, and writes an array of objects as an inline array <code>[{...}, {...}]</code> rather than <code>[[table]]</code> blocks. The result is valid TOML that reads back to the same data, but comments and layout of an original file are lost.</li>
</ul>

<h2 id="guide-manifest">Guide: read a project manifest</h2>
<p>Project files such as <code>Cargo.toml</code> or <code>pyproject.toml</code> mix plain tables, inline tables and arrays of tables. <code>DecodeStrict</code> reads the whole file into a <a href="/std/encoding/value/">Value</a> and tells you through <code>ok</code> whether it was valid; from there the <code>value</code> functions walk it.</p>
{{example.encoding-toml-guide-manifest}}
<p>A dependency can be a plain version string or an inline table with more detail, so the program asks <code>IsString</code> before reading it. Objects do not keep the order of their keys; sorting <code>ObjectKeys</code> with <code>sort.QuickSort</code> gives a stable listing.</p>

<h2 id="guide-struct">Guide: TOML into a struct</h2>
<p>For settings you use all over a program, load them into a struct once. Encode the decoded value as JSON with <code>json.EncodeDefault</code> and let <code>json.UnmarshalLenient</code> fill the struct: keys the file leaves out keep the struct's defaults, and a <code>[server]</code> table fills a nested struct.</p>
{{example.encoding-toml-guide-struct}}

<h2 id="guide-write">Guide: write a TOML file</h2>
<p>To write TOML, build a <a href="/std/encoding/value/">Value</a> object and pass it to <code>Encode</code> or <code>EncodeStrict</code>. A nested object becomes a <code>[table]</code>. The top level must be an object, since a TOML document is always a table; <code>EncodeStrict</code> reports <code>false</code> for anything else.</p>
{{example.encoding-toml-guide-write}}
<p>Three things show in the output. The null <code>password</code> is left out, because TOML has no null. The array of replica objects is written inline on one line. The float <code>30.0</code> keeps its <code>.0</code>, so it reads back as a float and not as the integer <code>30</code>. Keys come out in no particular order, so never compare the text with a fixed string; compare the data, for example with <code>value.Equal</code> after decoding the text again.</p>

<h2 id="guide-errors">Guide: catching mistakes</h2>
<p>Use <code>DecodeStrict</code> or <code>Valid</code> on any file a person edits. They catch broken syntax: a key without a value, an unclosed string, array or table header.</p>
{{example.encoding-toml-guide-errors}}
<p>The last two lines are the leniency described above: a duplicate key is accepted and the later value wins, and <code>mode = fast</code> passes as the string <code>"fast"</code>, although real TOML requires quotes. If either would hide a real mistake in your files, check the keys you care about after decoding, for example with <code>value.IsString</code> and a list of allowed values.</p>

doc.DecodeStrict = Reads TOML, setting <code>ok</code> false when the text is not valid.
doc.Decode = Turns TOML into a <code>Value</code> without reporting errors: on invalid text it returns whatever was read before the error, so prefer <code>DecodeStrict</code> for files people edit.
doc.Valid = True when the text is valid TOML.
doc.EncodeStrict = Turns a value into TOML. <code>ok</code> turns false when the top level is not an object or an array holds a null; null keys in a table are skipped.
doc.Encode = Turns a value into TOML, ignoring problems; a top level that is not an object gives an empty string.
