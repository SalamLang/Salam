pkg.intro <<
<p>HTML cannot hold a bare <code>&lt;</code> or <code>&amp;</code> in its text, so they travel as <em>entities</em>: <code>&amp;lt;</code>, <code>&amp;amp;</code>, <code>&amp;eacute;</code> or a number such as <code>&amp;#233;</code> and <code>&amp;#xE9;</code>. <code>Unescape</code> turns every entity in a string back into the character it names; <code>Escape</code> and <code>EscapeText</code> go the other way. Use them when you read text out of a page or a feed, and when you put text of unknown origin into a page.</p>
<p><code>Unescape</code> follows the HTML5 rules the way Python's <code>html.unescape</code> does, and gives the same answer on every input tried against it: all the named entities of the HTML standard (including the ones that stand for two characters), decimal and hexadecimal numbers, the older names that browsers accept without the closing <code>;</code> (<code>&amp;copy</code>, <code>&amp;amp</code>), numbers 128 to 159 read as Windows-1252 characters, and the replacement character for <code>&amp;#0;</code>, surrogates and numbers beyond Unicode. Anything that is not an entity stays as it is.</p>
<p>What people get wrong:</p>
<ul>
<li>Unescaping text before using it as HTML. After <code>Unescape</code> the text is plain text again; if it goes back into a page, escape it again.</li>
<li>Using <code>EscapeText</code> inside an attribute. It leaves quotes alone, so a value with <code>"</code> in it breaks out of <code>href="..."</code>. Use <code>Escape</code> for attributes.</li>
<li>Expecting <code>Escape</code> to make a URL or a script safe. It only protects the places where HTML text or a quoted attribute goes. A <code>javascript:</code> link or text inside <code>&lt;script&gt;</code> needs more than escaping.</li>
<li>Unescaping twice. <code>&amp;amp;lt;</code> is the text <code>&amp;lt;</code>; one pass gives that, a second pass would give <code>&lt;</code>.</li>
</ul>
<p>The <a href="/std/template/">template</a> package has its own <code>EscapeHTML</code>; for XML text and attributes see <a href="/std/encoding/xml/">encoding/xml</a>.</p>
<h2 id="guide-roundtrip">Escaping and getting the text back</h2>
<p>Escaping and unescaping are inverses: whatever <code>Escape</code> produces, <code>Unescape</code> turns back into the original. The example escapes three comments and checks the round trip.</p>
{{example.encoding-html-guide-roundtrip}}
<h2 id="guide-page">Building markup from untrusted text</h2>
<p>A name that comes from a user can hold <code>&amp;</code>, <code>&lt;</code> or a quote. Put it in a tag's text with <code>EscapeText</code> and in an attribute value with <code>Escape</code>, which also covers both kinds of quote. In the other direction, text scraped from a page has to go through <code>Unescape</code> before it is compared or shown.</p>
{{example.encoding-html-guide-page}}

doc.Unescape = Replaces every HTML entity in the text by the characters it stands for: named (<code>&amp;eacute;</code>), decimal (<code>&amp;#233;</code>) and hexadecimal (<code>&amp;#xE9;</code>), with the same rules as Python's <code>html.unescape</code>. Text that is not a valid entity is left unchanged. The result is a new string.
doc.Escape = Replaces <code>&amp;</code>, <code>&lt;</code>, <code>&gt;</code>, <code>"</code> and <code>'</code> by <code>&amp;amp;</code>, <code>&amp;lt;</code>, <code>&amp;gt;</code>, <code>&amp;quot;</code> and <code>&amp;#x27;</code>, so the text is safe in HTML text and in a quoted attribute.
doc.EscapeText = Replaces only <code>&amp;</code>, <code>&lt;</code> and <code>&gt;</code>. Safe in HTML text, not in an attribute.

ex.Unescape = encoding-html-Unescape
ex.Escape = encoding-html-Unescape
ex.EscapeText = encoding-html-Unescape
