pkg.intro <<
<p>This package works with whole web addresses. <code>Parse</code> splits a URL such as <code>https://user@shop.example.co.uk:8443/path?page=2#top</code> into a <code>URL</code> struct with the fields <code>scheme</code>, <code>userinfo</code>, <code>host</code>, <code>port</code>, <code>path</code>, <code>raw_query</code> and <code>fragment</code>, and <code>String</code> puts it back together. Around that come helpers to edit query parameters, resolve relative links with <code>Join</code>, and find the registrable domain of a host.</p>
<p>Use it whenever you have a full address. For the <code>a=1&amp;b=2</code> part on its own, such as a form body, use <a href="/std/encoding/query/">encoding/query</a>; for percent-encoding a single string, <code>encoding.URLEncode</code> in <a href="/std/encoding/">encoding</a>; to fetch the address, <a href="/std/net/http/">net/http</a>.</p>
<h3 id="concepts">Raw and decoded parts</h3>
<p>The fields hold the text exactly as it appeared, percent escapes included, so <code>String(Parse(x))</code> normally gives back <code>x</code>. Read the human form with <code>DecodedPath</code>, <code>DecodedUserinfo</code> or <code>Query</code>. When you set a field yourself, put encoded text in it: escape path segments with <code>EncodePathSegment</code> and build queries with <code>SetQuery</code>.</p>
<h3 id="pitfalls">What trips people up</h3>
<ul>
<li><strong><code>Parse</code> never fails.</strong> It does no validation: a port that is not a number becomes <code>0</code>, and text without <code>://</code> (including <code>mailto:sara@example.com</code>) has no scheme or host and lands whole in <code>path</code>. Check <code>scheme</code> and <code>host</code> yourself before trusting an address from a user.</li>
<li><strong>Nothing is lowercased.</strong> <code>HTTPS://Shop.Example.COM</code> keeps its case in <code>scheme</code> and <code>host</code>, and <code>Domain</code> returns <code>Example.COM</code>. Lowercase with <code>str.Lower</code> before you compare hosts or domains.</li>
<li><strong>Editing one parameter rewrites the whole query.</strong> <code>RemoveParam</code>, <code>SetParam</code> and <code>KeepParams</code> decode the query and encode it again: <code>%20</code> becomes <code>+</code>, characters such as <code>*</code> get escaped, a bare <code>flag</code> becomes <code>flag=</code>, and repeated keys are grouped together. The meaning stays the same; the text may not.</li>
<li><strong><code>Join</code> with only <code>?query</code> or <code>#fragment</code> loses the file name</strong> of the base, unlike a browser. See the links guide.</li>
</ul>

<h2 id="guide-clean">Guide: strip tracking parameters</h2>
<p>Links copied from email and social media carry <code>utm_</code> and click id parameters that only serve analytics. Before you store or compare links, parse them, drop those parameters with <code>RemoveParam</code>, clear the fragment and print the result with <code>String</code>. The parameters that stay keep their order.</p>
{{example.encoding-url-guide-clean}}
<p><code>ParamNames</code> returns a copy of the names, so removing parameters inside the loop is safe. The fields of <code>URL</code> are plain strings you can set directly, as <code>u.fragment = ""</code> does. The last line shows the rewrite described above: <code>salam%20lang</code> comes out as <code>salam+lang</code> and the bare <code>debug</code> as <code>debug=</code>. Both mean the same to a server, but if you use the cleaned link as a cache or database key, clean every link the same way so equal links give equal text.</p>

<h2 id="guide-links">Guide: resolve the links of a page</h2>
<p>A crawler or a link checker finds relative links like <code>../api/json.html</code> in a page and needs the full address. <code>Join</code> resolves a reference against the page's own URL the way a browser does: <code>./</code> and <code>../</code> move through the folders, a leading <code>/</code> starts at the site root, <code>//host</code> keeps the scheme, and a full URL replaces everything.</p>
{{example.encoding-url-guide-links}}
<p>A reference that is only a query (<code>?lang=fa</code>) or only a fragment (<code>#top</code>) does not keep the file name of the base yet, so resolve those yourself by setting <code>raw_query</code> or <code>fragment</code> on a copy of the base.</p>

<h2 id="guide-site">Guide: is it the same site?</h2>
<p>To allow redirects only within your own site, or to group links by owner, compare the registrable domain instead of the host name. <code>Domain</code> is the part a person registers, such as <code>example.co.uk</code>; <code>PublicSuffix</code> is the part under which anyone can register; <code>Subdomain</code> is what is left on the left. An address made of an IP has no domain, so compare the host name there. Host names are not case sensitive but the package keeps their case, so the program lowercases both addresses before parsing them.</p>
{{example.encoding-url-guide-site}}
<p>The package knows the common public suffixes such as <code>com</code>, <code>co.uk</code> and <code>com.au</code>, not the complete Public Suffix List, so hosting platforms that give every customer a subdomain may count as one site. Check those hosts by name when it matters.</p>

<h2 id="guide-build">Guide: build a URL from user input</h2>
<p>When parts of the address come from users, escape each path segment with <code>EncodePathSegment</code>, which also escapes <code>/</code> so a file name cannot add folders. Put the parameters in a <a href="/std/encoding/query/">QueryMap</a> and attach it with <code>SetQuery</code>; <code>Add</code> allows the same key more than once.</p>
{{example.encoding-url-guide-build}}
<p><code>DecodedPath</code> gives the readable path but turns <code>%2F</code> back into <code>/</code>, so it cannot tell a slash inside a name from a folder boundary. Split <code>u.path</code> at <code>/</code> first and decode each segment when you need the names exactly.</p>
>>

doc.URL = A parsed web address.
doc.URL.scheme = The scheme, such as <code>https</code>.
doc.URL.userinfo = The user name and password before the <code>@</code>, still encoded.
doc.URL.host = The host name or numeric address.
doc.URL.port = The port, or zero when none was given.
doc.URL.path = The path, still encoded.
doc.URL.raw_query = The query after the <code>?</code>, still encoded.
doc.URL.fragment = The part after the <code>#</code>.
doc.Parse = Takes an address apart into its pieces. It never fails and does no validation: only text with <code>://</code> (or a leading <code>//</code>) gets a scheme and host, and a port that is not a number becomes 0.
doc.HostPort = The host and port together, such as <code>shop.example.co.uk:8443</code>.
doc.String = Turns the address back into text.
doc.DecodedPath = The path with its percent encoding undone.
doc.DecodedUserinfo = The user information, decoded.
doc.EncodePathSegment = Encodes one path segment; <code>/</code> is encoded too.
doc.Query = Turns the address's query into a <code>QueryMap</code>.
doc.SetQuery = Replaces the address's query with the given map.
doc.Join = Resolves a relative address against a base one, the way a browser does; <code>..</code> and <code>.</code> in the path are worked out. A reference of only <code>?query</code> or <code>#fragment</code> drops the base file name.
doc.Hostname = The host name without the port.
doc.IsIP = True when the host is four dot-separated groups of digits or contains <code>:</code> (an IPv6 address). The digits are not range checked.
doc.Labels = The parts of the host name, separated by dots.
doc.PublicSuffix = The public suffix of the domain, such as <code>co.uk</code> or <code>ir</code>.
doc.Domain = The registered domain: one label before the public suffix, such as <code>example.co.uk</code>. An IP address or a one-label host such as <code>localhost</code> is returned unchanged. Case is kept.
doc.Subdomain = Whatever comes before the registered domain, such as <code>shop</code>.
doc.RemoveParam = Removes every value of a parameter and says whether it was there. Like the other parameter functions it re-encodes the rest of the query.
doc.SetParam = Sets a parameter to one value, replacing any values it had; a new name goes at the end.
doc.KeepParams = Keeps only the parameters you name, for stripping tracking parameters.
doc.ClearQuery = Removes the whole query.
doc.ParamNames = The names of the parameters, in order.
