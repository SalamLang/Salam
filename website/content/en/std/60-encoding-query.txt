pkg.intro <<
<p>A query string is the <code>key=value&amp;key=value</code> text after the <code>?</code> in a web address, and the same format is the body of an HTML form posted as <code>application/x-www-form-urlencoded</code>. This package reads and writes that text: it undoes the percent escapes and <code>+</code> for spaces, and builds correctly escaped strings from your values.</p>
<p>Use it when you hold the query text alone: a form body, the <code>raw_query</code> of a request, a signed API call. When you have a whole address and want to change its parameters, <a href="/std/encoding/url/">encoding/url</a> has <code>SetParam</code>, <code>RemoveParam</code> and <code>KeepParams</code> on top of this package. Inside a <a href="/std/net/http/">net/http</a> handler, <code>http.Query</code> and <code>http.Form</code> read single values for you; take <code>http.RawQuery</code> and this package when you need repeated keys or want to rewrite the query.</p>
<h3 id="concepts">Two ways to work</h3>
<ul>
<li><strong>On the text.</strong> <code>Get</code>, <code>GetAll</code> and <code>Has</code> take the query string itself. Each call decodes the whole string again, which is fine for reading a handful of values.</li>
<li><strong>On a <code>QueryMap</code>.</strong> <code>Decode</code> turns the text into a map you can change with <code>Set</code>, <code>Add</code>, <code>Remove</code> and <code>Retain</code>, then write back with <code>Encode</code>. One key may have several values (<code>tag=a&amp;tag=b</code>), so each key holds a list, and the map remembers the order in which keys first appeared.</li>
</ul>
<h3 id="pitfalls">What trips people up</h3>
<ul>
<li><strong>There is no getter on a <code>QueryMap</code>.</strong> Read the text with <code>Get</code>, or read the map directly: <code>m.data.has("tag")</code> and <code>m.data.get("tag").items</code>.</li>
<li><strong>Missing and empty look the same to <code>Get</code>.</strong> Both <code>page=</code> and no <code>page</code> at all return <code>""</code>; ask <code>Has</code> when it matters. A bare <code>flag</code> counts as present with an empty value, and <code>Encode</code> writes it back as <code>flag=</code>.</li>
<li><strong>Numbers are not checked.</strong> <code>"12abc".to_int()</code> is 12 and <code>"abc".to_int()</code> is 0, so bound every number you read before using it.</li>
<li><strong>Repeated keys are grouped.</strong> <code>a=1&amp;b=2&amp;a=3</code> encodes back as <code>a=1&amp;a=3&amp;b=2</code>. That is the same data, but if a signature or cache key covers the exact text, sign what you send, not what you received.</li>
<li><strong>Keys are case sensitive</strong>, and a leading <code>?</code> is skipped by <code>Decode</code>.</li>
</ul>

<h2 id="guide-search">Guide: read the parameters of a search page</h2>
<p>A search page reads a few parameters, gives the missing ones a default, and converts the numbers. <code>Get</code> already decodes the value, so <code>green+tea</code> arrives as <code>green tea</code>. <code>GetAll</code> returns every value of a repeated key, which is how checkbox filters arrive.</p>
{{example.encoding-query-guide-search}}
<p><code>Get</code> returns an empty string both for a missing key and for <code>key=</code>, so use <code>Has</code> when the difference matters, as the defaults for <code>page</code> and <code>limit</code> do here. Never trust the numbers: the visitor asked for 500 rows, and the handler caps <code>limit</code> at 100 and keeps <code>page</code> at 1 or more, so a bad value cannot make it read the whole table or a negative offset.</p>

<h2 id="guide-pages">Guide: next and previous page links</h2>
<p>Pagination links must keep every filter the visitor chose and change only the page number. Decode the current query into a <code>QueryMap</code>, <code>Set</code> the page (it replaces all values of that key, or adds the key when it is new) and <code>Encode</code> it again.</p>
{{example.encoding-query-guide-pages}}
<p><code>Set</code> keeps an existing key in its place, so the links differ from the address the visitor came from only in the page number, and a cache sees one address per page instead of one per parameter order.</p>

<h2 id="guide-form">Guide: HTML form bodies</h2>
<p>A form sent with <code>method="post"</code> has the body type <code>application/x-www-form-urlencoded</code>, which is the same format as a query string. Decode it with the same functions. Spaces arrive as <code>+</code> and everything else outside plain ASCII as <code>%XX</code> bytes, Persian text included.</p>
{{example.encoding-query-guide-form}}
<p><code>Encode</code> writes spaces as <code>+</code>, as forms do. Some APIs want <code>%20</code> instead; <code>EncodeWith</code> with <code>space_as_plus = false</code> writes that.</p>

<h2 id="guide-allow">Guide: keep only the parameters you know</h2>
<p>Parameters you do not use still change the address, which splits a cache into many copies of the same page and lets anyone pass odd flags along. <code>Retain</code> keeps only a list of allowed keys; <code>Remove</code> drops one and says whether it was there.</p>
{{example.encoding-query-guide-allow}}

doc.QueryOptions = The encoding options.
doc.QueryOptions.space_as_plus = Form style, true by default: a space is written as <code>+</code> and a <code>+</code> is read as a space. When false, <code>%20</code> is written and a <code>+</code> is read as a plus sign.
doc.QueryValues = The values of one key.
doc.QueryValues.items = The values, in order.
doc.QueryMap = A map from key to values that keeps the key order.
doc.QueryMap.data = The values of each key; read it with <code>data.has(key)</code> and <code>data.get(key).items</code>.
doc.QueryMap.order = The keys in the order they first appeared.
doc.NewQueryMap = An empty map.
doc.DecodeWith = Reads a query string with the given options.
doc.Decode = Reads a query string; percent encoding and <code>+</code> are undone, a leading <code>?</code> and empty pairs are skipped, and a key without <code>=</code> gets an empty value.
doc.EncodeWith = Turns a map into a string with the given options.
doc.Encode = Turns a map into a query string, keys in first-seen order with all values of a key together. Everything except letters, digits and <code>-_.~</code> is percent-encoded.
doc.GetAll = Every value of a key in the string.
doc.Get = The first value of a key in the string, or an empty string when it is absent.
doc.Has = True when the key is in the string, even with an empty value.
doc.Size = The number of distinct keys, not values.
doc.Add = Adds another value to a key, keeping the earlier ones.
doc.Set = Replaces every value of a key with one value; an existing key keeps its position, a new one goes at the end.
doc.Keys = The keys, in order.
doc.Remove = Removes a key and its values and says whether it was there.
doc.Retain = Keeps only the keys you name.
