pkg.intro <<
<p><code>Value</code> is the dynamic data type shared by the encoding packages. One <code>Value</code> is a null, a bool, a 64-bit int, a float, a string, an array of values or an object mapping strings to values, and its <code>kind</code> field says which. <a href="/std/encoding-json/">encoding/json</a>, <a href="/std/encoding-yaml/">encoding/yaml</a>, <a href="/std/encoding-toml/">encoding/toml</a>, <a href="/std/encoding-msgpack/">encoding/msgpack</a> and others decode into it and encode from it, and <a href="/std/encoding-serde/">encoding/serde</a> converts between formats through it.</p>
<p>Reach for a <code>Value</code> when the shape of the data is not known when you write the program: a webhook payload, a config with optional sections, a document you only pass along. When the shape is fixed, decoding straight into a struct (for example with <code>json.Unmarshal</code>) is shorter and checks the types for you.</p>

<h3 id="pitfalls">What trips people up</h3>
<ul>
<li><strong>Reading never checks the kind.</strong> <code>AsString</code> of a number is <code>""</code> and <code>AsInt</code> of a string is 0. Ask <code>IsString</code> or <code>IsNumber</code> first when the data comes from outside.</li>
<li><strong>Missing is null, all the way down.</strong> <code>ObjectGet</code> on a missing key, or on something that is not an object, returns null, so a chain like <code>ObjectGet(ObjectGet(doc, "a"), "b")</code> is safe. <code>ArrayGet</code> is not: an index past <code>ArrayLen</code> stops the program.</li>
<li><strong>Copies share parts.</strong> A copy of an object shares its map, so <code>ObjectSet</code> through the copy changes the original. A copy of an array shares its elements but not its length, so <code>ArrayPush</code> on an array you got from <code>ObjectGet</code> is lost until you <code>ObjectSet</code> it back. Use <code>ValueClone</code> for a real copy.</li>
<li><strong>Key order is not kept.</strong> <code>ObjectKeys</code> comes back in hash order; sort it, or encode with <code>sort_keys</code>, when output must be stable.</li>
</ul>

<h2 id="guide-walk">Guide: walk a whole document</h2>
<p>A recursive function over <code>Value</code> handles any shape: for an object, visit each key; for an array, each index; anything else is a leaf. This one prints the path of every leaf, which is handy for logging a webhook payload or comparing two documents line by line.</p>
{{example.encoding-value-guide-walk}}
<p>An object does not remember the order of its keys, so the program sorts <code>ObjectKeys</code> with <code>sort.QuickSort</code> to print the same order every time. <code>ToDebugString</code> shows each leaf together with its kind.</p>

<h2 id="guide-build">Guide: build a payload with optional fields</h2>
<p>A struct always writes all its fields. When some fields should only appear when they have a value, as many HTTP APIs expect, build a <code>Value</code> object instead and set only what you have. <code>json.Encode</code> with <code>sort_keys</code> prints it in a stable order.</p>
{{example.encoding-value-guide-build}}

<h2 id="guide-edit">Guide: change a nested field</h2>
<p>To change something deep in a decoded document, take the inner part with <code>ObjectGet</code>, change it, and store it back with <code>ObjectSet</code>. For objects the store is not strictly needed, because the map is shared, but for arrays it is: the program below shows the new order line missing until the array is set back.</p>
{{example.encoding-value-guide-edit}}
<p>Always writing the changed part back with <code>ObjectSet</code> makes the code correct for both kinds, and keeps working if the representation changes. The last line reads a field of a <code>shipping</code> object that does not exist: the chain of <code>ObjectGet</code> calls returns null and <code>AsString</code> gives an empty string, with no crash.</p>

<h2 id="guide-merge">Guide: deep merge of settings</h2>
<p>Settings often come in layers: built-in defaults, then a file per site. A deep merge keeps every default the site file does not mention and replaces only what it does, one level at a time. Arrays and plain values in the override win as a whole.</p>
{{example.encoding-value-guide-merge}}
<p>The function clones what it keeps, so <code>defaults</code> is the same afterwards. Without the clones, the result would share its objects with the inputs, as the next section shows.</p>

<h2 id="guide-pitfalls">Guide: copies, conversions and missing keys</h2>
<p>Assigning a <code>Value</code> to a new variable does not copy its contents: an object's fields live in a shared map, so a change through the copy shows up in the original. Call <code>ValueClone</code> when you need an independent copy, and <code>ValueFree</code> when you are done with it. Free only values nothing else shares, since freeing a plain copy also frees the original's map.</p>
{{example.encoding-value-guide-pitfalls}}
<ul>
<li><code>AsInt</code> cuts a float toward zero and <code>AsFloat</code> widens an int, but neither parses text: a string gives 0. Check the kind first with <code>IsInt</code>, <code>IsNumber</code> or <code>IsString</code>.</li>
<li><code>Equal</code> compares kinds too, so the integer 1 and the float 1.0 are different values.</li>
<li><code>ObjectGet</code> on a missing key gives a null value; <code>ObjectGetOk</code> also tells you whether the key was there.</li>
</ul>
>>
