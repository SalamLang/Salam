pkg.intro <<
<p>When you read JSON whose shape you do not know in advance, it cannot be poured into a fixed struct. That is what <code>Value</code> is for: every value carries its own kind, and it may be an array or an object of further values.</p>
<p>JSON, YAML, TOML, MessagePack, CSV and XML can all be turned into a <code>Value</code> and built from one; the <a href="../encoding-serde/">encoding.serde</a> package uses exactly this to convert between formats.</p>

<h2 id="guide-walk">Guide: walk a whole document</h2>
<p>A recursive function over <code>Value</code> handles any shape: for an object, visit each key; for an array, each index; anything else is a leaf. This one prints the path of every leaf, which is handy for logging a webhook payload or comparing two documents line by line.</p>
{{example.encoding-value-guide-walk}}
<p>An object does not remember the order of its keys, so the program sorts <code>ObjectKeys</code> with <code>sort.QuickSort</code> to print the same order every time. <code>ToDebugString</code> shows each leaf together with its kind.</p>

<h2 id="guide-build">Guide: build a payload with optional fields</h2>
<p>A struct always writes all its fields. When some fields should only appear when they have a value, as many HTTP APIs expect, build a <code>Value</code> object instead and set only what you have. <code>json.Encode</code> with <code>sort_keys</code> prints it in a stable order.</p>
{{example.encoding-value-guide-build}}

<h2 id="guide-merge">Guide: deep merge of settings</h2>
<p>Settings often come in layers: built-in defaults, then a file per site. A deep merge keeps every default the site file does not mention and replaces only what it does, one level at a time. Arrays and plain values in the override win as a whole.</p>
{{example.encoding-value-guide-merge}}
<p>The function clones what it keeps, so <code>defaults</code> is the same afterwards. Without the clones, the result would share its objects with the inputs, as the next section shows.</p>

<h2 id="guide-pitfalls">Guide: copies, conversions and missing keys</h2>
<p>Assigning a <code>Value</code> to a new variable does not copy its contents: an object's fields live in a shared map, so a change through the copy shows up in the original. Call <code>ValueClone</code> when you need an independent copy, and <code>ValueFree</code> when you are done with it.</p>
{{example.encoding-value-guide-pitfalls}}
<ul>
<li><code>AsInt</code> cuts a float toward zero and <code>AsFloat</code> widens an int, but neither parses text: a string gives 0. Check the kind first with <code>IsInt</code>, <code>IsNumber</code> or <code>IsString</code>.</li>
<li><code>Equal</code> compares kinds too, so the integer 1 and the float 1.0 are different values.</li>
<li><code>ObjectGet</code> on a missing key gives a null value; <code>ObjectGetOk</code> also tells you whether the key was there.</li>
</ul>
>>
