pkg.intro <<
<p>This package converts text from one data format to another in one call. <code>Transcode</code> reads the input with the matching decoder, holds it as a <a href="/std/encoding/value/">Value</a>, and writes it with the target encoder. <code>Detect</code> guesses which format a text is in. The format names are the lowercase strings <code>json</code>, <code>yaml</code>, <code>toml</code>, <code>xml</code> and <code>csv</code>; <code>"JSON"</code> is not recognised.</p>
<p>It suits tools that take whatever format a user hands them, and one-off migrations. When your program needs the data itself, call the format's own package (<a href="/std/encoding/json/">encoding/json</a>, <a href="/std/encoding/yaml/">encoding/yaml</a>, <a href="/std/encoding/toml/">encoding/toml</a>, <a href="/std/encoding/xml/">encoding/xml</a>, <a href="/std/encoding/csv/">encoding/csv</a>): they return a <code>Value</code> or fill a struct and give real error messages, while this package only answers yes or no. MessagePack is binary and is not one of the names here; use <a href="/std/encoding/msgpack/">encoding/msgpack</a>.</p>
<h3 id="lossy">What survives a conversion</h3>
<p>Everything passes through a <code>Value</code>, so comments and formatting are always lost, while keys keep the order they were read in. Beyond that, each format can hold less than JSON:</p>
<div class="table-wrap"><table>
<thead><tr><th>Format</th><th>Reading gives</th><th>Writing loses</th></tr></thead>
<tbody>
<tr><td>JSON, YAML</td><td>every kind</td><td>YAML writes the float <code>2.0</code> as <code>2</code>, which reads back as an int</td></tr>
<tr><td>TOML</td><td>every kind except null; dates as strings</td><td>null keys are dropped; the top level must be an object</td></tr>
<tr><td>XML</td><td>only strings, objects and arrays (for repeated elements); attributes as <code>@name</code>, text as <code>#text</code>; the outer element's name is dropped</td><td>numbers and booleans become text; the output is wrapped in <code>&lt;root&gt;</code></td></tr>
<tr><td>CSV</td><td>an array of objects, one per row, every cell a string</td><td>needs an array of objects; only string fields are written, numbers and booleans come out as empty cells</td></tr>
</tbody>
</table></div>
<h3 id="pitfalls">What trips people up</h3>
<ul>
<li><strong>Detection is a guess.</strong> The order is XML (text starts with <code>&lt;</code>), JSON, TOML, CSV, then YAML, and nearly any plain text such as <code>hello world</code> is valid YAML. Pass the format yourself whenever a file extension or <code>Content-Type</code> tells you.</li>
<li><strong><code>Transcode</code> hides failures</strong> as an empty string. Use <code>TranscodeStrict</code> and check <code>ok</code>.</li>
<li><strong>CSV in never fails</strong>, so <code>ok</code> is true for any text read as CSV.</li>
</ul>

<h2 id="guide-anything">Guide: accept any format</h2>
<p>A tool that takes settings or data from users does not have to insist on one format. <code>Detect</code> looks at the text and names the format: XML when it starts with <code>&lt;</code>, JSON when it parses as JSON, then TOML, CSV and finally YAML. Pass that name to <code>TranscodeStrict</code> to turn whatever came in into the one format your code reads.</p>
{{example.encoding-serde-guide-anything}}
<p>Detection is a guess from the shape of the text. Very short inputs can fit more than one format, and almost any plain text is valid YAML, so when you know the format, from a file extension or a <code>Content-Type</code> header, pass it yourself.</p>

<h2 id="guide-migrate">Guide: move a config to another format</h2>
<p>Changing a project from YAML to TOML, or the other way, is one call. Convert, then check the result: read both the old and the new text back as JSON, decode them, and compare the two values with <code>value.Equal</code>. Comparing the JSON text instead would fail on key order alone.</p>
{{example.encoding-serde-guide-migrate}}
<p>Comments do not survive, because a <code>Value</code> holds data only, so tell people who edit the file by hand before you convert it.</p>

<h2 id="guide-xml">Guide: XML in and out</h2>
<p>XML has no arrays or numbers, so the mapping follows a few rules: an <code>@name</code> key becomes an attribute, an array becomes the same element repeated, <code>#text</code> becomes the element's text, and a converted document is wrapped in a <code>&lt;root&gt;</code> element. Reading XML gives every value as a string and attributes as <code>@</code> keys.</p>
{{example.encoding-serde-guide-xml}}
<p>Numbers and booleans are written as their text, so <code>39.5</code> and <code>true</code> arrive in the XML. The way back shows what XML cannot express: every value returns as a string, and the outer <code>&lt;root&gt;</code> or <code>&lt;book&gt;</code> is gone, leaving only its contents. When the element names, order or namespaces matter, build the document with <a href="/std/encoding/xml/">encoding/xml</a> directly.</p>

<h2 id="guide-errors">Guide: handle failure</h2>
<p><code>TranscodeStrict</code> says through <code>ok</code> whether both halves worked: reading in the source format, and writing in the target. It fails on broken input, on a format name it does not know, and on data the target cannot hold, such as a top level array for TOML. <code>Transcode</code> just returns an empty string in all those cases.</p>
{{example.encoding-serde-guide-errors}}

doc.FormatUnknown = An unknown format.
doc.FormatJSON = JSON.
doc.FormatYAML = YAML.
doc.FormatTOML = TOML.
doc.FormatXML = XML.
doc.FormatCSV = CSV.
doc.DetectFormat = Guesses which format the text is in and returns one of the <code>Format</code> constants: XML if it starts with <code>&lt;</code>, then JSON, TOML, CSV and YAML, whichever parses first.
doc.Detect = The same, but it returns the format's short name, or an empty string when nothing fits.
doc.TranscodeStrict = Converts text from the <code>from</code> format to <code>dest</code>; when reading or writing fails, or a format name is wrong, <code>ok</code> becomes false.
doc.Transcode = Converts text from one format to another; any failure gives an empty string.
