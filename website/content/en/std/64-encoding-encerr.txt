pkg.intro <<
<p>The functions that read JSON, YAML, env files and MessagePack report their errors in an <code>EncodingError</code>. Build one with <code>NoError</code>, pass it to the function, and then check <code>IsError</code>.</p>

<h2 id="guide-position">Guide: point the user at the mistake</h2>
<p><code>position</code> is a byte offset into the text, which is exact but not what a person looks for in an editor. Count the line breaks before it to turn it into a line and a column, and print it the way compilers do: file, line, column, message.</p>
{{example.encoding-encerr-guide-position}}
<p>The reader stops where it noticed the problem, which is often just after the real mistake: here the comma is missing at the end of line 3, and the reader complains at the start of line 4. Columns count bytes, so a line with Persian text before the mistake shows a larger number than the letters you see.</p>

<h2 id="guide-custom">Guide: the same errors in your own parser</h2>
<p>When you write a small parser of your own, report errors in the same type, so callers can handle your format and the standard ones with the same code. <code>ErrUnexpectedEOF</code>, <code>ErrUnexpectedToken</code> and <code>ErrTypeMismatch</code> fill in the kind and a standard message; <code>NewError</code> with <code>KindCustom</code> takes any message. Callers can then branch on <code>kind</code>.</p>
{{example.encoding-encerr-guide-custom}}

doc.EncodingError = An error from reading or writing a format.
doc.EncodingError.kind = The kind of error; one of the Kind constants.
doc.EncodingError.message = The error message, in English.
doc.EncodingError.position = Where the error is in the text, in bytes, or -1 when it is not known.
doc.KindNone = No error.
doc.KindUnexpectedEOF = The text ended sooner than expected.
doc.KindUnexpectedToken = A character or token turned up out of place.
doc.KindInvalidUTF8 = The text is not valid UTF-8.
doc.KindInvalidNumber = An invalid number.
doc.KindDepthExceeded = The nesting went past the allowed depth.
doc.KindTypeMismatch = The value's type does not match the expected one.
doc.KindKeyNotFound = A required key was not found.
doc.KindTrailingData = Extra data turned up after the end of the value.
doc.KindCustom = An error defined by the program.
doc.NoError = The empty error, meaning "no error".
doc.NewError = A new error with a kind, a message and a position.
doc.ErrUnexpectedEOF = An unexpected end of text error at the given position.
doc.ErrUnexpectedToken = An out of place token error with a message.
doc.ErrTypeMismatch = A type mismatch error; its message names the expected type.
doc.IsError = True when an error has been recorded.
