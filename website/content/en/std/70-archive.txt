pkg.intro <<
<p>An archive gathers several files into one. <strong>Zip</strong> compresses each file on its own; <strong>tar</strong> only puts the files one after another and is usually gzipped afterwards (<code>.tar.gz</code>).</p>
<p>The functions work both in memory and on files. They take the archive data as an address and a length, such as <code>b.data</code> and <code>b.len</code> of a byte buffer.</p>

<p>Passwords and multi-volume sets work for RAR only, through <code>RarOpen</code> and <code>RarOpenVolumes</code>. Zip passwords are not supported.</p>

<p>The compression itself comes from <a href="/std/compress/">compress</a>; use that package directly to gzip a single file or stream. For reading and writing the files on disk around an archive, see <a href="/std/fs/file/">fs.file</a>.</p>
<h3 id="limits">Limits to know about</h3>
<ul>
<li><strong>Zip:</strong> no zip64, so archives and entries must stay under 2 GB; only methods 0 (stored) and 8 (DEFLATE) are read, so entries packed with bzip2, LZMA or zstd fail to extract; encrypted entries are refused; the CRC-32 is not checked on extract.</li>
<li><strong>Zip names and dates:</strong> new zips do not set the UTF-8 flag, so tools that assume the old DOS code page, such as Windows Explorer, may show Persian file names garbled, and every entry is dated 1 January 1980. <code>Entry.mtime</code> is always 0 for zip entries.</li>
<li><strong>Tar:</strong> names longer than 100 bytes are cut, both when writing and reading, and the ustar prefix field and GNU or PAX long names are not used. Links and other special entries are listed as ordinary files of size 0. New entries get a time of 0, and the mode you set, or 644 for files and 755 for folders when you leave it at 0.</li>
<li><strong>RAR:</strong> RAR 5 archives are read completely: every compression level, solid archives and the built-in filters, with each entry's CRC-32 checked. Older archives (RAR 1.5 to 4.x) are read the same way, including PPMd text compression and the standard filters. Password-protected archives open with <code>RarOpen</code> and a password, including ones whose file names are encrypted; without it they report <code>RAR_ENCRYPTED</code>, and a wrong password reports <code>RAR_BAD_PASSWORD</code>. Multi-volume archives open from the list of volumes (<code>RarOpenVolumes</code>, or <code>RarReadVolumes</code> to load a set from disk); a set with a missing volume reports <code>RAR_MULTIVOLUME</code> for the files that cross it. A file that is both encrypted and split across volumes is not supported. New archives are RAR 5 with the files stored, because only WinRAR itself can compress to RAR; any RAR tool opens them.</li>
</ul>

<p>The guide below shows the usual jobs: zipping a set of files, making and reading a <code>.tar.gz</code>, telling formats apart by their first bytes, and extracting without letting an archive write outside the target folder.</p>

<h2 id="guide-zip">Zip a set of files</h2>
<p>Each file you put into a zip is a <code>ZipFileInput</code>: its path inside the archive, the address and length of its bytes, and the method, 8 for DEFLATE or 0 to store it as it is. A name that ends with <code>/</code> is a folder. <code>ZipCreateFile</code> writes the archive to disk and returns false when it cannot; <code>ZipCreate</code> keeps it in memory, for example to send it as an HTTP response.</p>
{{example.archive-guide-bundle}}
<p>Text shrinks well. The logo is already compressed, so it uses method 0: running DEFLATE on it again would only cost time and could even make it bigger. The same rule holds for JPEG, PNG, MP4 and other zips.</p>

<h2 id="guide-targz">Make and read a .tar.gz</h2>
<p>Tar does not compress. It puts each file after a 512 byte header and pads its contents to a multiple of 512 bytes, so three small files already take 3.5 KB. The usual answer is to gzip the whole tar, and all that padding then nearly disappears. In memory that is <code>TarCreate</code> followed by <code>compress.GzipCompressBuf</code>; for a tar that is already on disk, <code>GzipCompressFile</code> and <code>GzipDecompressFile</code> do it file to file.</p>
{{example.archive-guide-targz}}
<p>Reading goes the other way: gunzip with <code>compress.GzipDecompressBuf</code>, check <code>ok</code>, then <code>TarList</code> and <code>TarExtractByName</code> on the plain tar. Directory entries in a tar have size 0 and <code>is_dir</code> set.</p>

<p>A file name can lie, the bytes cannot. Every format starts with a fixed signature, so a program that accepts uploads should look at the bytes before it picks a reader:</p>

<h2 id="guide-extract">Extract safely</h2>
<p><code>ZipExtractAll</code> and <code>TarExtractAll</code> create the folders they need under the target directory. An archive from someone else can hold names like <code>../escape.txt</code> or <code>/etc/passwd</code> that would land outside it; both functions skip such entries, write the rest, and return false so you know something was left out. <code>ZipExtractByName</code> and <code>TarExtractByName</code> set <code>ok</code> to false when the name is not in the archive.</p>
{{example.archive-guide-extract}}
<p>A false result from an extract call is therefore not always a disk error: check the entry names with <code>ZipList</code> or <code>TarList</code> when you need to tell the two apart.</p>

<h2 id="guide-gzip">Gzip a single file (.gz)</h2>
<p>A <code>.gz</code> holds one file, not a folder. <code>GzipCompressFile</code> and <code>GzipDecompressFile</code> go from a path to a path and return false when they cannot read, write or decode; in memory, <code>compress.GzipCompressBuf</code> and <code>compress.GzipDecompressBuf</code> do the same on a buffer. Decompressing checks the trailer, so a damaged or cut file is refused instead of giving back wrong bytes. For data from someone else use <code>compress.GzipDecompressMax</code>, which stops at a size you choose, so a tiny file cannot expand into gigabytes.</p>
{{example.archive-guide-gzip}}
<p>To compress several files, put them in a tar first (the <code>.tar.gz</code> section above). To open a <code>.tar.gz</code> you do the same two steps backwards.</p>

<h2 id="guide-check">Check an archive</h2>
<p>"Check" means two different things. To see what is inside without unpacking, list it: <code>ZipList</code>, <code>TarList</code> and <code>RarList</code> (or <code>RarEntries</code>) give every name, size, folder flag and, for zip and RAR, the stored CRC-32; free the list with <code>FreeEntries</code>. To know the data is intact, you need a checksum, and formats differ:</p>
<ul>
<li><strong>gzip and RAR</strong> verify themselves. A gzip call returns <code>ok = false</code>; a RAR call sets the status to <code>RAR_BAD_CRC</code>, or <code>RAR_BAD_PASSWORD</code> when a password was wrong.</li>
<li><strong>zip</strong> stores a CRC-32 for each entry but does not compare it while extracting. Extract the entry and compare <code>compress.CRC32Buf(data)</code> with <code>Entry.crc32</code>, as the example does.</li>
<li><strong>tar</strong> has no checksum for the contents. All you can check is that the listing is sane (names, sizes); for integrity gzip the tar and rely on the gzip trailer, or keep a hash next to the file.</li>
</ul>
{{example.archive-guide-check}}
<p>In the example one byte of the first zip entry was changed. Extraction still reports success for it, but its checksum no longer matches, while the second entry is fine. The RAR entry with the same damage is refused by the extractor itself.</p>

<h2 id="guide-rar">Read and write a RAR</h2>
<p>Reading goes through <code>RarList</code> and <code>RarExtract</code>, the same way as zip. The sample below is a small solid RAR 5 made by WinRAR: the second file is packed against the first, so <code>RarExtract</code> unpacks both to reach it. Every entry is checked against its CRC-32, and the <code>status</code> says what went wrong instead of returning silent garbage.</p>
{{example.archive-guide-rar}}
<p>Making a RAR is simpler: build <code>RarFileInput</code> values and call <code>RarCreate</code> or <code>RarCreateFile</code>. The result is a valid RAR 5 archive with the files stored uncompressed. If you need real compression, use zip, or <code>.tar.gz</code> as shown above. </p>
<h2 id="guide-rar-password">Open a password-protected RAR</h2>
<p>A <code>RarArchive</code> remembers the data and the password, so the list, a single read and a full extraction share them. With the wrong password the archive does not open (when the names are encrypted) or each read fails with <code>RAR_BAD_PASSWORD</code>; with none at all you get <code>RAR_ENCRYPTED</code>. RAR 5 checks the password up front. RAR 3 and 4 have no check value, so for them a wrong password shows up as a failed checksum, and it is reported the same way.</p>
{{example.archive-guide-rar-password}}

<h2 id="guide-rar-volumes">Read a multi-volume RAR</h2>
<p>A big archive is often cut into volumes: <code>name.part01.rar</code>, <code>name.part02.rar</code>, and so on, or the older <code>name.rar</code>, <code>name.r00</code>, <code>name.r01</code>. <code>RarReadVolumes</code> takes the first file name, finds the rest by that naming and loads them; <code>RarOpenVolumes</code> turns the list into a <code>RarArchive</code>, and the usual <code>RarEntries</code> and <code>RarRead</code> work across the cuts. Close the archive with <code>RarClose</code> and free the volumes with <code>RarFreeVolumes</code>.</p>
{{example.archive-guide-rar-volumes}}
