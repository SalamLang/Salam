pkg.intro <<
<p><code>.npy</code> files are the standard way NumPy arrays are stored in Python, and <code>.npz</code> keeps several named arrays in one zip archive. With this package you can move data and model weights between Python and Salam.</p>
<p>An <code>NpyArray</code> is three things: <code>shape</code>, the size of each dimension; <code>data</code>, every element as an <code>f64</code> in row-major (C) order; and <code>dtype</code>, the element type the file declared. The guide below goes from the usual case, moving a weight matrix between NumPy and Salam, to checkpoints with several arrays, arrays with more than two dimensions, the file layout itself and what happens with bad files.</p>

<h2 id="guide-weights">Save a matrix for NumPy, and load it back</h2>
<p><code>FromMatrix</code> turns a <a href="/std/matrix/">matrix</a> into an <code>NpyArray</code> and <code>WriteNpyFile</code> writes it. In Python, <code>numpy.load("weights.npy")</code> opens the file as a 2 by 3 <code>float64</code> array. The way back is <code>ReadNpyFile</code> followed by <code>ToMatrix</code>. Both report failure: <code>WriteNpyFile</code> returns false and <code>ReadNpyFile</code> clears <code>ok</code>.</p>
{{example.npy-weights}}

<h2 id="guide-checkpoint">Several arrays in one .npz checkpoint</h2>
<p>A trained model has more than one array: weights, biases, perhaps the mean and spread used to scale the inputs. <code>NpzWrite</code> stores them in one <code>.npz</code> file under the names you give in <code>keys</code>, the same file <code>numpy.savez</code> writes and <code>numpy.load</code> returns as a dictionary. <code>NpzList</code> shows what a file holds and <code>NpzRead</code> takes one array out by name. Below, a tiny linear layer is saved, loaded again and used for a prediction.</p>
{{example.npy-checkpoint}}
<p>Asking for a name that is not in the file (<code>gamma</code> here) clears <code>ok</code>, so a loader can fall back to a default instead of crashing on an older checkpoint.</p>

<h2 id="guide-shapes">Arrays with more than two dimensions</h2>
<p>A <code>.npy</code> file can hold any number of dimensions, such as a batch of images as <code>(count, height, width)</code>. The package reads and writes them all, but <code>ToMatrix</code> only accepts one or two dimensions (a 1-D array becomes a single row) and clears <code>ok</code> otherwise. For higher dimensions index <code>data</code> yourself: the element at <code>[i][j][k]</code> of shape <code>(A, B, C)</code> is at <code>(i * B + j) * C + k</code>.</p>
{{example.npy-shapes}}

<h2 id="guide-format">What is inside a .npy file</h2>
<p>The format is simple enough to check by hand: the magic bytes <code>\x93NUMPY</code>, a version, a two byte header length, then a header that is a Python dictionary in plain text, padded with spaces, and finally the raw elements. <code>WriteNpy</code> gives you the bytes in a <code>ByteBuf</code> instead of a file, which is handy for sending an array over the network or storing it in a database.</p>
{{example.npy-header}}
<p>The header shows a limit to keep in mind: the writer always stores <code>'&lt;f8'</code>, little-endian 64 bit floats, whatever <code>dtype</code> says. On reading, files with <code>float32</code>, integer or <code>bool</code> elements are accepted, <code>dtype</code> tells you what they were and <code>data</code> holds them converted to <code>f64</code>. If Python needs another type, convert after loading with <code>arr.astype(numpy.float32)</code>.</p>

<h2 id="guide-errors">Bad, short and missing files</h2>
<p>Every reader takes an <code>ok</code> flag and never stops the program. A missing file, a file that is not <code>.npy</code> at all and a file that was cut off in the middle all clear it, and you get an empty array back. Check <code>ok</code> before you use <code>shape</code> or <code>data</code>.</p>
{{example.npy-errors}}
<p>An <code>NpyArray</code> owns its two vectors, so call <code>free</code> on arrays you no longer need in a long running program, and <code>matrix.Free</code> on the matrices made from them.</p>
