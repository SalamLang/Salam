pkg.intro <<
<p>A <strong>workbook</strong> holds several <strong>sheets</strong>, and each sheet holds cells by row and column, from zero. Turn Excel references such as <code>C5</code> into a row and column with <code>CellRef</code> and <code>ParseCellRef</code>.</p>
<p><code>Open</code> and <code>Save</code> work the format out from the file extension. Formulas are stored and read with their last calculated result, but Salam does not evaluate a formula itself.</p>
<p>Use it when people hand you spreadsheets or expect one back: an upload form for price lists, a monthly report for the finance team, an export button. When the data is only ever read by programs, a CSV file with <a href="/std/encoding-csv/">encoding/csv</a> is simpler; for analysis on columns of numbers, load the rows into a table with <a href="/std/data/">data</a>.</p>
<h3 id="pitfalls">What trips people up</h3>
<ul>
<li><strong>Old <code>.xls</code> files are not read.</strong> The binary Excel 97 to 2003 format is not supported: <code>Open</code> fails with a message that asks for xlsx or ods instead, and <code>Save</code> to a <code>.xls</code> path returns false. <code>IsXLS</code> recognises such a file so you can tell the user.</li>
<li><strong>The extension decides the format.</strong> <code>DetectFormat</code>, <code>Open</code> and <code>Save</code> look only at the file name, so an xlsx saved as <code>report.dat</code> will not open. Rename uploads, or check the first bytes (<code>PK</code> for xlsx and ods) yourself.</li>
<li><strong>Formulas are not evaluated.</strong> A formula cell carries the result stored with it; when you write one, compute and pass the result yourself.</li>
<li><strong>Rows and columns count from zero</strong>, while Excel shows 1 and A. <code>ParseCellRef</code> and <code>CellRef</code> convert.</li>
<li><strong><code>SheetToJSON</code> gives strings only</strong>: an array of rows, each an array of the cells' text. Read <code>Cell.kind</code> when you need the numbers.</li>
</ul>

<p>The guide below covers the jobs that come up in real programs: reading a sheet someone else filled in, building a formatted report, working with dates, turning a workbook into CSV files, and finding values by reference or by content.</p>

<h2 id="guide-read">Reading rows from a sheet someone else filled in</h2>
<p>A spreadsheet that people edit by hand is never quite regular: columns move, rows are left empty, a number cell holds a word. Find each column by its header text instead of trusting its position, skip rows with no key, and look at <code>Cell.kind</code> before you treat a value as a number. <code>get_string</code> always gives text, whatever the cell holds, so it is safe for messages. <code>Open</code> reports a file it cannot read through <code>ok</code> and <code>err</code>.</p>
{{example.excel-read-rows}}
<p>Rows count from zero, so the header is row 0 and data starts at row 1. <code>row_count</code> is one past the last row that has a cell, which is why the empty row 3 still appears in the loop and is skipped by <code>has_cell</code>.</p>

<h2 id="guide-report">Building a formatted report</h2>
<p>A <code>Style</code> describes bold text, font size, background colour, alignment and number format. Register each style once with <code>book.styles.get_or_add</code>, which returns an id, and give that id to <code>set_style</code> for as many cells as you like. <code>merge_cells</code> joins a range for a title, and <code>set_formula</code> stores a formula together with the value you computed, because Salam writes formulas but does not evaluate them.</p>
{{example.excel-report}}
<p>Excel recalculates the formulas when it opens the file. Programs that read the file without Excel, this package included, see the value you stored, so always pass the correct result as the last argument of <code>set_formula</code>.</p>

<h2 id="guide-dates">Dates are numbers with a format</h2>
<p>Excel stores a date as a serial number: days since 30 December 1899, with the time of day as the fraction. <code>set_date</code> takes Unix seconds and stores the matching serial with a date format, <code>EpochToSerial</code> and <code>SerialToEpoch</code> convert in both directions, and a cell written with <code>set_date</code> reads back with <code>kind == CellDate</code>. Because serials are plain day counts, the difference of two dates is a number of days, which is what the formula <code>B2-B1</code> stores.</p>
{{example.excel-dates}}
<p>The program prints the parts of each date with the UTC functions of <a href="/std/time/">time</a>. <code>get_string</code> on a date cell formats it in the local time zone, so near midnight it can show a different day from the UTC value.</p>

<h2 id="guide-export">From a workbook to CSV files</h2>
<p><code>Open</code> reads xlsx, ods and csv files and picks the reader from the file extension, which is also what <code>DetectFormat</code> looks at, so a file with the wrong extension will not open. <code>SheetToCSV</code> writes one sheet as CSV text with commas and quotes escaped, so exporting every sheet of a workbook is a short loop over <code>sheet_names</code>. Going the other way, <code>CSVToSheet</code> turns CSV text into a sheet.</p>
{{example.excel-export}}

<h2 id="guide-lookup">Finding values by reference or by content</h2>
<p>People talk about cells as <code>C3</code>, programs use row and column numbers. <code>ParseCellRef</code> turns a reference into zero based numbers and returns false for something that is not a reference, <code>CellRef</code> goes back, and <code>ColumnIndex</code> and <code>ColumnLabel</code> do the same for a column alone. To search by content, <code>filter_rows_equals</code> returns the rows whose cell in one column has a given text and <code>find</code> returns every cell with that text.</p>
{{example.excel-lookup}}
<p><code>find</code> returns its matches in no particular order, so sort them or, as here, use only the count when the order matters.</p>
