pkg.intro <<
<p>A proxy is a middleman that makes the connection on behalf of the program. This package builds the tunnel and gives back an ordinary <a href="/std/net/tcp/">net/tcp</a> connection, read and written exactly as a direct one is.</p>
<p>Two kinds of proxy are supported. An HTTP proxy (<code>NewHTTPProxy</code>, often on port 3128 or 8080) opens the tunnel with a <code>CONNECT</code> request; a SOCKS5 proxy (<code>NewSOCKS5Proxy</code>, port 1080, or 9050 for Tor) uses its own small binary handshake. Both take <code>"host:port"</code>, and the <code>...Auth</code> forms add a user name and password. <code>Dial</code> returns a <code>tcp.Conn</code>; when the proxy cannot be reached or refuses, the connection is empty, so always check it with <code>tcp.ConnOk</code>.</p>
<h3 id="pitfalls">What trips people up</h3>
<ul>
<li><strong>The handshake has no timeout.</strong> A proxy that accepts the connection but never answers makes <code>Dial</code> wait forever, and there is no way to set a deadline before the handshake. Run the dial in a thread you can give up on if that matters.</li>
<li><strong>Nothing is read from the environment.</strong> <code>HTTPS_PROXY</code>, <code>ALL_PROXY</code> and <code>NO_PROXY</code> are ignored; read them yourself, as the first guide does.</li>
<li><strong>The address must be <code>host:port</code> with a name or an IPv4 address.</strong> The text is split at the first colon, so an IPv6 proxy address such as <code>[::1]:1080</code> is not understood, and a missing port becomes 0.</li>
<li><strong>Names are resolved by the proxy.</strong> SOCKS5 sends the target as a host name, so the proxy does the DNS lookup. That is what you want with Tor, but it means the target must be reachable by name from the proxy's network.</li>
<li><strong>The result is a plain TCP connection.</strong> For HTTPS, upgrade it with <code>tcp.UpgradeTLS</code> as the HTTPS guide shows; the package does not do TLS to the proxy itself.</li>
</ul>

<h2 id="guide-url">Reading proxy settings from a URL</h2>
<p>Proxy settings usually arrive as one URL, for example from an <code>HTTPS_PROXY</code> environment variable or a config file: <code>socks5://user:pass@host:1080</code>. The package takes the parts separately, so a program needs a few lines to split the scheme, the credentials and the address. Unknown schemes should be reported rather than silently ignored.</p>
{{example.net-proxy-guide-url}}

<h2 id="guide-local">What the tunnel looks like</h2>
<p>This program runs offline: it starts a tiny fake HTTP proxy on a free local port in a thread, dials through it and prints the request the proxy received. That request is the whole HTTP proxy protocol: a <code>CONNECT host:port</code> line, the <code>Host</code> header, and with credentials a <code>Proxy-Authorization: Basic</code> header holding <code>user:password</code> in Base64. Once the proxy answers <code>200</code>, every byte is passed straight through, which is why the echo reply comes back on the same connection.</p>
{{example.net-proxy-guide-local}}
<p>Basic authentication is only Base64, not encryption. Over an untrusted network, use a proxy you reach through a VPN or SSH tunnel, or send only TLS traffic through it as in the next section.</p>

<h2 id="guide-https">HTTPS through a proxy</h2>
<p>A tunnel carries any bytes, including TLS. Dial the proxy for port 443 of the real host, then turn the connection into TLS with <code>tcp.UpgradeTLS</code> and a <a href="/std/tls/">tls</a> config for that host name. The proxy sees only the host name and encrypted bytes. To try it, start a local proxy such as Squid:</p>
<pre class="code" dir="ltr"><code>docker run -d -p 3128:3128 ubuntu/squid</code></pre>
{{example.net-proxy-guide-https}}
<p>With no proxy listening, the program prints <code>no tunnel through 127.0.0.1:3128</code> and exits with 1.</p>

<h2 id="guide-chain">A chain with a direct fallback</h2>
<p>A <code>Chain</code> connects through several proxies in order: the first proxy opens a tunnel to the second, and so on, and the last one reaches the target. Build it with <code>NewChain</code> and <code>Add</code>, then call <code>DialChain</code>. If any hop fails the result is empty, and a program that may run both inside and outside a corporate network can then try <code>tcp.Dial</code> directly.</p>
{{example.net-proxy-guide-chain}}
<p>Each hop adds a round trip before the first byte of real data, so keep chains short. To use Tor, run it locally (<code>docker run -d -p 9050:9050 dperson/torproxy</code>) and add <code>NewSOCKS5Proxy("127.0.0.1:9050")</code> as the first hop.</p>
>>

doc.Add = Adds a proxy to the end of the chain.
