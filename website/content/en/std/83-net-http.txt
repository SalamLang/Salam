pkg.intro <<
<p>This package has both halves of HTTP/1.1: a server for web pages and JSON APIs, and a client for calling other services. The server hands each request to a <a href="/std/net-router/">net/router</a> router, which picks the handler by method and path. Every handler takes one <code>i64</code>, the context id of the request; you read the request and write the response with the context functions below, or turn the id into a <code>Context</code> struct with <code>Ctx</code> and call the same names on it.</p>
<p>The packages around it:</p>
<ul>
<li><a href="/std/net-http-middleware/">net/http/middleware</a> for access logs, CORS and cache headers, <a href="/std/net-http-session/">net/http/session</a> for logins with a cookie, <a href="/std/net-http-validate/">net/http/validate</a> for checking input, and <a href="/std/net-http-swagger/">net/http/swagger</a> for API documentation;</li>
<li><a href="/std/net-http2/">net/http2</a> for HTTP/2, and <a href="/std/net-websocket/">net/websocket</a> for connections that stay open.</li>
</ul>
<p>Things people get wrong:</p>
<ul>
<li><strong>Register every route before <code>Use</code>.</strong> The server keeps a copy of the router.</li>
<li><strong><code>Post</code>, <code>Put</code> and <code>Patch</code> label a body as a form</strong> (<code>application/x-www-form-urlencoded</code>) unless you pass a <code>Content-Type</code>; send JSON with <code>PostWith</code> and that header.</li>
<li><strong>The client does not follow redirects unless you ask.</strong> A 302 comes back as a 302 with its <code>Location</code> header; set <code>max_redirects</code> in <code>RequestOptions</code> (or call <code>SetMaxRedirects</code> on a client) to follow them. It never hangs or reads without limit: a read or write that is idle for 30 seconds fails, a response over 256 MB fails, and <code>timeout_ms</code> caps the whole request.</li>
<li><strong><code>Ok</code> means a 2xx status.</strong> When the server could not be reached at all, <code>Status</code> is 0 and <code>Error</code> says why.</li>
<li>A value read from a request is freed when the handler returns; see the end of the page.</li>
</ul>
<p>The examples run the server with <code>RunBackground</code> on 127.0.0.1 and send requests to it from the same program.</p>
<h2 id="guide-api">A JSON API in one file</h2>
<p>The most common job is a small JSON API: list some records, show one by its id, and create new ones. Register each route on the router with its handler, hand the router to the server with <code>Use</code>, and start it. Here the records are Salam structs: <code>json.Marshal</code> turns them into the response body, and <code>json.UnmarshalLenient</code> reads the posted body back into a struct, ignoring fields it does not know and leaving the missing ones at their defaults.</p>
{{example.net-http-guide-api}}
<p>Nothing is sent until the handler returns: the status, the headers and the body are collected and go out together, and a second body call replaces the first. That is why a handler returns right after it writes an error. A <code>201</code> with a <code>Location</code> header is the usual answer to a create, and a <code>404</code> with a short JSON error is easier for a client to handle than an empty page. Path parameters such as <code>:id</code> always arrive as text, so convert them with <code>conv.Atoi</code> before comparing.</p>

<h2 id="guide-forms">HTML forms, query strings and redirects</h2>
<p>A browser form arrives as <code>application/x-www-form-urlencoded</code>. <code>Form</code> reads one field and decodes it, so <code>%40</code> becomes <code>@</code> and <code>+</code> becomes a space. <code>Query</code> does the same for the query string. After a successful POST, answer with <code>Redirect</code> so that pressing reload in the browser does not send the form again.</p>
{{example.net-http-guide-forms}}
<p>Anything a user typed must be escaped before it goes into HTML; otherwise a message containing <code>&lt;script&gt;</code> runs in every visitor's browser. <code>template.EscapeHTML</code> does that, as the <code>&amp;amp;</code> in the output shows. On the client side, <code>EncodeForm</code> builds a form body from a map and <code>WithQuery</code> adds a query string to a URL, both with correct escaping.</p>

<h2 id="guide-groups">Route groups and a login check</h2>
<p><code>router.Group</code> puts a route under a common prefix, which is how an API is versioned under <code>/api/v1</code>. There is no separate middleware chain: a check that several handlers share is a plain function that returns <code>true</code> when the request may go on, or writes the error response itself and returns <code>false</code>. Each handler calls it on its first line and returns when it fails.</p>
{{example.net-http-guide-groups}}
<p>A route that is not registered answers <code>404</code> on its own, so <code>/profile</code> without the prefix is not found. For a cookie based login instead of a token, see <a href="/std/net-http-session/">net/http/session</a>.</p>

<h2 id="guide-static">Static files and server settings</h2>
<p><code>router.Static</code> serves a whole directory under a prefix, with the content type taken from the file extension. A path that tries to climb out of the directory with <code>..</code> is refused, and a missing file is a <code>404</code>. <code>HideTokens</code> drops the version number from the <code>Server</code> header, so the answer says only <code>Salam</code>.</p>
{{example.net-http-guide-static}}

<h2 id="guide-deploy">Running a real server</h2>
<p>The examples above use <code>RunBackground</code> so that one program can be both the server and its own client. A real service calls <code>Run</code>, which never returns. Read the port from the environment, listen on <code>0.0.0.0</code> when the server sits in a container or behind a proxy, and turn on the access log while you are getting it running.</p>
{{example.net-http-guide-server}}
<p>Run it and try it from a second terminal:</p>
<pre class="code" dir="ltr"><code>PORT=8080 salam run server.salam
curl http://127.0.0.1:8080/health</code></pre>
<p>The limits are for the whole process: <code>SetMaxBodyBytes</code> and <code>SetMaxHeaderBytes</code> reject requests that are too large, <code>SetKeepAliveIdle</code> closes idle connections, and <code>SetKeepAliveMaxRequests</code> caps how many requests one connection may send. For HTTPS, call <code>RunTLS</code> with a certificate and key file instead of <code>Run</code>, or put the server behind a proxy that handles TLS.</p>

<h2 id="guide-client">Calling an API as a client</h2>
<p><code>Get</code>, <code>Post</code> and the other one-line calls send a request and return a <code>Response</code>; the <code>...With</code> forms take a map of extra headers. The program below shows the four answers a client has to handle. A <code>Post</code> without a content type reaches the server as a form, so a JSON API refuses it with 415; the same body through <code>PostWith</code> with <code>Content-Type: application/json</code> creates the ticket. A redirect is not followed, so <code>Get</code> returns the 302 and you read <code>Location</code> yourself. A server that is not running gives status 0 and the reason in <code>Error</code>.</p>
{{example.net-http-guide-client}}
<p>Gzip and chunked answers are decoded for you, and every request is sent with <code>Connection: close</code>. For a series of calls that share a login, <code>NewClient</code> keeps the cookies from each answer and sends them with the next request, plus any headers set with <code>SetHeader</code>. A cookie is sent back only to the host that set it; a cookie you add with <code>SetCookie</code> goes to the host of the first request, never to a host a redirect leads to.</p>
<p>Any number of threads can use the one-line calls at once, because a call keeps no state outside itself. A <code>Client</code> from <code>NewClient</code> can be shared by threads too: it carries its own lock, so <code>SetHeader</code>, the cookie jar and the settings stay consistent. Call <code>Free</code> when you are done with a shared client. A <code>Client {}</code> written as a literal has no lock and belongs to one thread.</p>

<h2 id="guide-raw">Raw requests: your own headers, bytes and time limits</h2>
<p>The one-line calls above build the request for you. When you need full control of the request line and headers, for example to sign a request, to send a binary body or to talk to an API with unusual headers, write the request head yourself and send it with <code>SendRaw</code>. The <a href="/packages/aws/">aws</a>, <a href="/packages/webpush/">webpush</a>, <a href="/std/db-meilisearch/">db/meilisearch</a>, <a href="/std/db-elasticsearch/">db/elasticsearch</a> and <a href="/std/db-typesense/">db/typesense</a> packages are built on these calls. The examples run against a small server in a thread of the same program, so they need no network.</p>
<p>Every raw call takes an <code>Endpoint</code> from <code>ParseEndpoint</code> (host, port and TLS on or off; any path in the URL is dropped, because the path goes in your request line) and a request head: the request line, the headers and an empty line, each line ending in <code>\r\n</code>. The body is a pointer and a length, so it can hold any bytes. The answer is a <code>RawResponse</code> with the body as bytes, chunked bodies already decoded, freed with <code>FreeRaw</code>. <code>SendRaw</code> waits as long as the server does; <code>SendRawTimeout</code> adds a time limit in milliseconds; <code>SendRawTLS</code> adds your own <code>tls.Config</code>. A response larger than <code>RawLimit</code> (256 MB by default) is reported as an error.</p>
<p>Things that catch people out:</p>
<ul>
<li><strong>Always send <code>Connection: close</code>.</strong> The raw calls read until the server closes the connection; on a kept-alive connection the call waits forever (or until the time limit).</li>
<li><strong><code>ok</code> means a 2xx status</strong>, not "an answer arrived". Check <code>status</code> to tell a 404 from a dead server.</li>
<li>A <code>str</code> stops at the first zero byte, so binary bodies stay in <code>data</code>; <code>RawText</code> cuts at the first zero.</li>
</ul>
<h2 id="guide-raw-post">POST JSON with your own headers</h2>
<p><code>ParseEndpoint</code> turns a URL into the host, port and whether to use TLS. The request head is plain text that you write: the request line, a <code>Host</code> header, and here an <code>Authorization</code> token, the content type and the body length, closed by an empty line. <code>SendRawTimeout</code> sends the head and the body and returns the answer; <code>RawText</code> turns the reply body into a <code>str</code>. <code>HeaderValue</code> finds a header in the response head, ignoring case.</p>
{{example.net-http-raw-post-json}}
<p><code>Content-Length</code> must be the length in bytes, which is what <code>str.len()</code> returns, so it stays right for text in any language. A wrong length makes servers wait for more data or cut the body.</p>

<h2 id="guide-raw-errors">Status codes and failures</h2>
<p>A <code>RawResponse</code> tells three cases apart. <code>ok</code> is true only for a 2xx status. A 4xx or 5xx answer still has its <code>status</code> and a body, which usually explain the problem. When no answer came at all, because the connection was refused, the host was unknown or the URL could not be parsed, <code>status</code> is 0 and <code>error</code> says why.</p>
{{example.net-http-raw-status-errors}}
<p>A 503 or 429 often means "try again later"; read <code>Retry-After</code> with <code>HeaderValue</code> before you retry, and do not retry a 4xx such as 404, which will not change.</p>

<h2 id="guide-raw-client">A small API client</h2>
<p>A struct that holds the endpoint and the token, with one method per kind of request, keeps the header writing in one place. The JSON in the replies is read with <a href="/std/encoding-json/">encoding/json</a>: <code>json.Get</code> for a field and <code>json.Items</code> to walk an array.</p>
{{example.net-http-raw-api-client}}

<h2 id="guide-raw-chunked">Chunked answers and time limits</h2>
<p>A server that does not know the length of its answer in advance sends it in chunks, each one prefixed by its size in hex. <code>SendRawTimeout</code> removes that framing for you. The last parameter of <code>SendRawTimeout</code> is a time limit in milliseconds for each connect, read and write, so a server that accepts the connection and then says nothing cannot hang the program. The second request below hits such a server with a 300 ms limit.</p>
{{example.net-http-raw-chunked}}
<p>A timeout is reported as <code>the request timed out</code> and an answer cut short by a closing connection as <code>the response body was cut short</code>; both are worth a retry later. <code>SendRaw</code> has no time limit at all; give <code>SendRawTimeout</code> a limit for any server you do not control. <code>SendRawTLS</code> takes the same limit plus a <code>tls.Config</code> for a private CA.</p>

<h2 id="guide-raw-binary">Binary downloads</h2>
<p>A <code>str</code> ends at the first zero byte, so an image or a zip file turned into one is cut short. Read it from the <code>RawResponse</code> instead: <code>data</code> points at the body bytes and <code>len</code> is their count. The program downloads twelve bytes of a PNG header and shows that <code>RawText</code>, which turns the body into a <code>str</code>, keeps only the eight bytes before the first zero.</p>
{{example.net-http-raw-binary}}
<p>A <code>RawResponse</code> body is limited to <code>RawLimit</code> bytes, 256 MB unless you change it with <code>SetRawLimit</code>; a larger answer is reported as an error instead of filling memory. The <code>data</code> buffer belongs to you until <code>FreeRaw</code>.</p>

<h2 id="guide-raw-https">HTTPS</h2>
<p>An <code>https://</code> URL gives an endpoint with <code>secure</code> set, and the same calls then speak TLS through <a href="/std/tls/">tls</a>, checking the server certificate. Nothing else changes. This example asks the GitHub API about the Salam repository, so it needs the internet; GitHub requires a <code>User-Agent</code> header.</p>
{{example.net-http-raw-https}}
<p>When this page was written it printed:</p>
<pre class="code" dir="ltr"><code>api.github.com 443 true
status: 200
rate limit left: 58
SalamLang/Salam is written in TeX</code></pre>
<p>The rate limit number counts down with each call from your address, and the language is what GitHub detects for the repository at the time.</p>

<h2 id="guide-limits">Timeouts, limits and redirects</h2>
<p>Every client request is bounded. <code>RequestOptions</code> holds the limits and <code>Do</code> sends a request with them; a <code>Client</code> keeps its own copy, changed with <code>SetTimeout</code>, <code>SetIdleTimeout</code>, <code>SetMaxRedirects</code> and <code>SetMaxBody</code>. <code>idle_ms</code> (30 seconds by default) is how long one read or write may stall, <code>timeout_ms</code> (off by default) is the time for the whole request including redirects, and <code>max_body</code> (256 MB by default) bounds the body, also after gzip is unpacked, so a small compressed answer cannot fill memory. A request that runs out of time reports <code>the request timed out</code>, and an answer cut short by a closing connection is an error rather than a smaller body.</p>
<p>Redirects are followed only when <code>max_redirects</code> is above zero. A 301 or 302 after a POST and every 303 turn into a GET without the body; 307 and 308 repeat the request as it was. When a redirect leads to another host, the <code>Authorization</code> and <code>Cookie</code> headers are dropped, and a redirect from https to http is refused. The final address is in the <code>url</code> field of the response.</p>
<p>The request is checked before anything is sent: a method, header name or address with a space or a control character, and a header value with a line break, are refused with a message in <code>err</code>, so a value taken from outside cannot add headers to the request. A <code>Content-Length</code>, <code>Transfer-Encoding</code>, <code>Connection</code> or <code>Accept-Encoding</code> header of yours is replaced by the one the client computes. The example sends a request to a server that answers late and one that never answers, follows a redirect and refuses an answer that is too large.</p>
{{example.net-http-guide-limits}}
