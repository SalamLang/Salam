pkg.intro <<
<p>Five small helpers for <a href="/std/net/http/">net/http</a> handlers: <code>AllowAll</code> for CORS, <code>Secure</code> for basic security headers, <code>NoCache</code> and <code>Cache</code> for caching, and <code>Log</code> for a line per request. Each takes the context id, as the handler does, and only sets response headers (or prints), so you call them on the first lines of a handler.</p>
<p>There is no middleware chain in Salam and no way to wrap a handler from outside. A middleware is an ordinary function you call with the context id, and the headers it sets go out with whatever the handler writes after it. That keeps the order visible in the handler itself. For logins use <a href="/std/net/http/session/">net/http/session</a>, and for checking input <a href="/std/net/http/validate/">net/http/validate</a>.</p>
<p>What to know before you rely on them:</p>
<ul>
<li><strong><code>AllowAll</code> does not list <code>PATCH</code>.</strong> It allows GET, POST, PUT, DELETE and OPTIONS with the <code>Content-Type</code> and <code>Authorization</code> headers, for every origin. A browser refuses a PATCH from another origin, and <code>*</code> cannot be used with cookies; write your own rule for those (last section).</li>
<li><strong><code>Secure</code> is a minimum.</strong> It sets <code>nosniff</code>, <code>X-Frame-Options: DENY</code> and <code>X-XSS-Protection</code>, a header current browsers ignore. It sets no <code>Content-Security-Policy</code> and no <code>Strict-Transport-Security</code>.</li>
<li><strong>The last call wins.</strong> A header set twice with the same name keeps the last value, so <code>NoCache</code> followed by <code>Cache</code> leaves only <code>max-age</code>.</li>
<li><code>Log</code> prints with <code>println</code> before the handler runs, so it shows no status; <code>http.EnableAccessLog</code> on the server logs the status too.</li>
</ul>

<h2 id="guide-cors">CORS for an API used from a browser</h2>
<p>A page on another origin can only call your API when the response allows it. For anything other than a simple GET the browser first sends an <code>OPTIONS</code> request, the preflight, and checks the <code>Access-Control-Allow-*</code> headers on the answer. Register an <code>OPTIONS</code> route that calls <code>AllowAll</code> and answers <code>204</code> with no body, and call <code>AllowAll</code> in the real handler too.</p>
{{example.net-http-middleware-cors}}
<p><code>AllowAll</code> allows every origin, the methods GET, POST, PUT, DELETE and OPTIONS (not PATCH) and the <code>Content-Type</code> and <code>Authorization</code> headers. That suits a public, read only API. An API that uses cookies or other headers needs its own rule, as the last section shows.</p>

<h2 id="guide-chain">One helper per kind of response</h2>
<p>Instead of repeating the same calls at the top of every handler, group them in a function for each kind of response: private pages that must not be cached and must not appear in a frame, and public files that browsers may keep. <code>Secure</code> adds <code>nosniff</code>, <code>X-Frame-Options: DENY</code> and the XSS header; <code>NoCache</code> forbids caching; <code>Cache</code> allows it for the given number of seconds.</p>
{{example.net-http-middleware-chain}}
<p><code>Log</code> prints one line per request with the method and path, which helps while developing. In production, <code>http.EnableAccessLog</code> on the server logs every request with its status, without a call in each handler.</p>

<h2 id="guide-strict">Stricter headers for pages with private data</h2>
<p>For an invoice or an account page, build on <code>Secure</code> with the headers it leaves out: a <code>Content-Security-Policy</code> that only lets the page load files from its own origin, <code>Strict-Transport-Security</code> so browsers keep to HTTPS (send it only when the site is served over HTTPS), and a <code>Referrer-Policy</code>. The second route shows the "last call wins" rule: it calls <code>NoCache</code> and then <code>Cache</code>, and the answer carries a single <code>Cache-Control</code> with the later value.</p>
{{example.net-http-middleware-strict}}
<p>A policy of <code>default-src 'self'</code> also blocks inline <code>&lt;script&gt;</code> and <code>style</code> attributes, so test your pages with it before you turn it on.</p>

<h2 id="guide-own">Writing your own middleware</h2>
<p>When the ready made headers are not right, write a function of the same shape. A function that only adds headers returns nothing. A function that may stop the request returns a <code>bool</code>: it writes the error response itself and returns <code>false</code>, and the handler returns at once. This example allows a single trusted origin and accepts only JSON bodies.</p>
{{example.net-http-middleware-own}}
<p>Send <code>Vary: Origin</code> whenever the answer depends on the <code>Origin</code> header, so that a shared cache does not hand one origin's answer to another.</p>

doc.Log = Prints <code>[HTTP]</code>, the method and the path of the request to the standard output; no status, since it runs before the handler answers.
doc.AllowAll = Opens CORS to every origin: <code>Access-Control-Allow-Origin: *</code>, the methods GET, POST, PUT, DELETE and OPTIONS, and the headers <code>Content-Type</code> and <code>Authorization</code>. PATCH is not included.
doc.Secure = Sets <code>X-Content-Type-Options: nosniff</code>, <code>X-Frame-Options: DENY</code> and <code>X-XSS-Protection: 1; mode=block</code>. No CSP or HSTS.
doc.NoCache = Tells the browser and any proxies not to keep the response: <code>Cache-Control: no-store, no-cache, must-revalidate</code> and <code>Pragma: no-cache</code>.
doc.Cache = Sets <code>Cache-Control: max-age=</code> with this many seconds, replacing an earlier <code>Cache-Control</code>.
