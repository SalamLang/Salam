pkg.intro <<
<p>Call these at the top of a handler to add the usual headers to the response. Each one takes the context id, just as the handler itself does.</p>
<p>There is no separate middleware chain in Salam. A middleware here is an ordinary function you call with the context id, and the headers it sets go out with whatever the handler writes after it. That keeps the order visible in the handler itself.</p>

<h2 id="guide-cors">CORS for an API used from a browser</h2>
<p>A page on another origin can only call your API when the response allows it. For anything other than a simple GET the browser first sends an <code>OPTIONS</code> request, the preflight, and checks the <code>Access-Control-Allow-*</code> headers on the answer. Register an <code>OPTIONS</code> route that calls <code>AllowAll</code> and answers <code>204</code> with no body, and call <code>AllowAll</code> in the real handler too.</p>
{{example.net-http-middleware-cors}}
<p><code>AllowAll</code> allows every origin, the five common methods and the <code>Content-Type</code> and <code>Authorization</code> headers. That suits a public, read only API. An API that uses cookies or other headers needs its own rule, as the last section shows.</p>

<h2 id="guide-chain">One helper per kind of response</h2>
<p>Instead of repeating the same calls at the top of every handler, group them in a function for each kind of response: private pages that must not be cached and must not appear in a frame, and public files that browsers may keep. <code>Secure</code> adds <code>nosniff</code>, <code>X-Frame-Options: DENY</code> and the XSS header; <code>NoCache</code> forbids caching; <code>Cache</code> allows it for the given number of seconds.</p>
{{example.net-http-middleware-chain}}
<p><code>Log</code> prints one line per request with the method and path, which helps while developing. In production, <code>http.EnableAccessLog</code> on the server logs every request with its status, without a call in each handler.</p>

<h2 id="guide-own">Writing your own middleware</h2>
<p>When the ready made headers are not right, write a function of the same shape. A function that only adds headers returns nothing. A function that may stop the request returns a <code>bool</code>: it writes the error response itself and returns <code>false</code>, and the handler returns at once. This example allows a single trusted origin and accepts only JSON bodies.</p>
{{example.net-http-middleware-own}}
<p>Send <code>Vary: Origin</code> whenever the answer depends on the <code>Origin</code> header, so that a shared cache does not hand one origin's answer to another.</p>

doc.Log = Writes the method and path of the request to the output.
doc.AllowAll = Opens CORS to every domain: <code>Access-Control-Allow-Origin: *</code> and the usual methods and headers.
doc.Secure = The basic security headers: no content type sniffing, no framing and no XSS.
doc.NoCache = Tells the browser and any proxies not to keep the response.
doc.Cache = Tells the browser to keep the response for this many seconds.
