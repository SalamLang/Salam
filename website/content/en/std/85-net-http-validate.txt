pkg.intro <<
<p>Five small checks for input that arrives at a <a href="/std/net-http/">net/http</a> handler: <code>Required</code>, <code>Length</code>, <code>IsEmail</code>, <code>Matches</code> and <code>Assert</code>. The first four take a string and return true or false, so they work anywhere, not only in handlers. <code>Assert</code> is the one that answers: when its condition is false it sends a 400 with a JSON message. For patterns beyond <code>Matches</code>, such as finding or replacing, use <a href="/std/regex/">regex</a> directly; for typed JSON bodies, decode with <a href="/std/encoding-json/">encoding/json</a> and check the fields after.</p>
<p>What the checks really test:</p>
<ul>
<li><strong><code>Required</code> only rejects the empty string.</strong> A value of spaces passes; trim it with <code>str.Trim</code> first.</li>
<li><strong><code>IsEmail</code> only looks for an <code>@</code> and a dot anywhere</strong>, so <code>@.</code> passes. It catches typing slips, nothing more.</li>
<li><strong><code>Matches</code> searches, it does not match the whole value</strong>: anchor the pattern with <code>^</code> and <code>$</code>. A pattern that does not compile returns false for every value, which looks like bad input, so test your patterns.</li>
<li><strong><code>Assert</code> does not stop the handler</strong>, and it pastes the message into the JSON without escaping. Return right after a failed <code>Assert</code>, and keep user input out of its message.</li>
</ul>
<h2 id="guide-rules">Common rules</h2>
<p>Each function answers one question about one string. <code>Matches</code> takes a regular expression; anchor it with <code>^</code> and <code>$</code>, or it accepts any text that merely contains a match. <code>Length</code> counts characters, not bytes, so a Persian name of four letters has length 4 although it takes eight bytes.</p>
{{example.net-http-validate-rules}}
<p>Two of the results are worth a second look. <code>Required</code> only checks that the text is not empty, so a value of spaces passes; trim it first with <code>str.Trim</code>. <code>IsEmail</code> only checks for an <code>@</code> and a dot, so it catches typing mistakes, not fake addresses. The only real proof that an address works is a confirmation email.</p>

<h2 id="guide-signup">Report every problem at once</h2>
<p>A form with several fields should tell the user about all the mistakes in one answer, not one per try. Run every check, collect the messages, and send them together with a <code>422</code>. Building the JSON with <code>json.Str</code> and <code>json.Array</code> escapes the messages correctly.</p>
{{example.net-http-validate-signup}}

<h2 id="guide-assert">Stop at the first problem with Assert</h2>
<p>For a simple API, <code>Assert</code> is shorter: when the condition is false it answers <code>400</code> with <code>{"error": message}</code>. It does not stop the handler, so keep the result in a variable and return when it is false. Otherwise the code after it runs and its response replaces the error.</p>
{{example.net-http-validate-assert}}
<p><code>Assert</code> puts the message into the JSON as it is, so write it without double quotes or backslashes. For messages that include user input, build the answer with <code>json.Member</code> as in the previous section.</p>

doc.Required = True when the value is not the empty string; spaces count as a value.
doc.Length = True when the number of characters (not bytes) is between the minimum and the maximum, both included.
doc.IsEmail = A very simple email check: the text has to hold an <code>@</code> and a dot, in any place. To be sure, send a confirmation email.
doc.Matches = True when the regular expression matches somewhere in the value; anchor it with <code>^</code> and <code>$</code> to test the whole value. False when the pattern does not compile.
doc.Assert = When the condition is false, sets status 400 and the body <code>{"error":"message"}</code>, with the message not escaped. It does not stop the handler.
