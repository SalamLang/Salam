pkg.intro <<
<p>This package has the basic cryptography tools, written in Salam: the SHA-1, SHA-2 and MD5 digests, HMAC, PBKDF2 password hashing, a constant time comparison and secure random bytes from the operating system. It covers hashing, signing and secrets; it does not encrypt. For encryption (AES-GCM, ChaCha20-Poly1305, key exchange) use <a href="/std/tls/">tls</a>, and for signed tokens that carry claims <a href="/std/jwt/">jwt</a>.</p>
<p>Most functions come in three shapes: <code>...Hex</code> takes a <code>str</code> and returns hex text, the simplest; <code>...Bytes</code> and <code>...Raw</code> write the raw digest into memory you allocate; and <code>Sha256New</code>, <code>Sha256Update</code>, <code>Sha256Final</code> hash data that arrives in pieces.</p>
<p>Things to get right:</p>
<ul>
<li><strong><code>HashPassword</code> uses only 1000 PBKDF2 rounds.</strong> That is far below current advice (OWASP asks for 600,000 with SHA-256). For new systems build the same string with more rounds, as the second section shows; <code>VerifyPassword</code> reads the rounds from the stored string, so both kinds keep working.</li>
<li><strong>Compare secrets with <code>SecretEquals</code></strong>, never with <code>==</code>.</li>
<li><strong>A <code>str</code> stops at the first zero byte.</strong> For binary data or a binary key, use the <code>...Bytes</code> and <code>...Raw</code> forms with a pointer and a length; <code>Sha256Hex</code> of a buffer that contains a zero hashes only the part before it.</li>
<li><code>HashStr</code>, <code>HashBytes</code> and <code>HashInt</code> are fast hash table hashes, not cryptographic ones; MD5 and SHA-1 are only for old systems that require them.</li>
</ul>

<h2 id="guide-passwords">Storing passwords</h2>
<p>A login system keeps one string per user: the output of <code>HashPassword</code>. It has four fields separated by <code>$</code>: the algorithm, the number of PBKDF2 rounds, a random salt and the derived key. Because the salt is new every time, two users with the same password get different strings, and a leaked table cannot be attacked with one precomputed list. At login, <code>VerifyPassword</code> reads the rounds and the salt back out of the stored string, so the stored value is all you need to keep.</p>
{{example.crypto-passwords}}
<p>Answer "wrong user" and "wrong password" with the same message, so that a visitor cannot use the login form to find out which accounts exist.</p>

<h2 id="guide-rounds">More rounds, and upgrading old hashes</h2>
<p>The cost of a password hash is the number of rounds: every guess an attacker tries costs the same work as one login. <code>Pbkdf2HmacSha256Hex</code> takes the round count, so a stronger hash is the same four-field string as <code>HashPassword</code> writes, built by hand with 600,000 rounds. Existing users do not have to reset anything. At their next successful login the program sees that the stored hash has fewer rounds than the target and stores a new one, made from the password they just typed.</p>
{{example.crypto-password-rounds}}
<p>600,000 rounds take a noticeable fraction of a second, which is the point, but it also means a login endpoint should be rate limited, or many parallel login attempts can keep the server busy.</p>

<h2 id="guide-webhooks">Checking a webhook signature</h2>
<p>Payment providers, GitHub and most other services sign the requests they send you. They compute an HMAC of the raw body with a secret you both know and put it in a header. To check it, compute the same HMAC over the body exactly as it arrived and compare. Compare with <code>SecretEquals</code>, never with <code>==</code>: <code>==</code> stops at the first different character, and the time that takes tells an attacker how much of a forged signature was right.</p>
{{example.crypto-webhook}}
<p>Sign the bytes you received, not a version you decoded and encoded again: a JSON library may reorder keys or change spaces, and then the signature no longer matches.</p>

<h2 id="guide-checksums">Checksums of large data</h2>
<p><code>Sha256Hex</code> needs the whole text at once. For a file or a download that arrives in pieces, keep a running state: <code>Sha256New</code> starts it, <code>Sha256Update</code> feeds each piece and <code>Sha256Final</code> writes the 32 byte digest. The result is the same as hashing everything in one go, as the program shows.</p>
{{example.crypto-checksum}}
<p>The <code>...Bytes</code> and <code>...Final</code> functions write raw bytes into memory you allocated; turn them into text with <code>Base64EncodeBytes</code> from <a href="/std/encoding/">encoding</a>. The SHA-512 and SHA-384 states work the same way with <code>Sha512New</code>, <code>Sha384New</code>, <code>Sha512Update</code> and <code>Sha512Final</code>.</p>

<h2 id="guide-api-keys">API keys and tokens</h2>
<p>An API key, a password reset link or a session id must be impossible to guess, so make it with <code>RandomToken</code>, which reads the operating system's secure random source. <code>RandomToken(n)</code> returns <code>n</code> random bytes as <code>2n</code> hex characters. Store only the SHA-256 digest of the key: a stolen database then gives no working keys, and checking a key that comes in with a request is one digest and one <code>SecretEquals</code>. A plain digest is enough here because the key is long and random; a password is short and chosen by a person, which is why it needs <code>HashPassword</code> instead.</p>
{{example.crypto-api-keys}}

doc.HashStr = A fast hash of a string.
doc.HashInt = A fast hash of a number.
doc.Md5Bytes = Writes the MD5 digest, 16 bytes, into the output. MD5 is broken; only for compatibility with old systems.
doc.Md5Hex = The MD5 digest as hex.
doc.Sha1Hex = The SHA-1 digest as hex. SHA-1 is no longer strong enough for security either; use SHA-256 for signatures.
doc.Sha1Base64 = The SHA-1 digest as base64; for the WebSocket handshake, for instance.
doc.Sha1Bytes = Writes the SHA-1 digest, 20 bytes, into the output.
doc.Sha256Hex = The SHA-256 digest as hex, 64 characters.
doc.Sha512Hex = The SHA-512 digest as hex, 128 characters.
doc.Sha256Bytes = Writes the SHA-256 digest, 32 bytes, into the output.
doc.Sha384Bytes = The SHA-384 digest, 48 bytes.
doc.Sha512Bytes = The SHA-512 digest, 64 bytes.
doc.Sha256 = The SHA-256 state for data that arrives in pieces, such as a large file.
doc.Sha256.h = The internal state.
doc.Sha256.blk = The partial block.
doc.Sha256.blen = The length of the partial block.
doc.Sha256.total = The total number of bytes.
doc.Sha512 = The SHA-512 or SHA-384 state for data in pieces.
doc.Sha512.h = The internal state.
doc.Sha512.blk = The partial block.
doc.Sha512.blen = The length of the partial block.
doc.Sha512.total = The total number of bytes.
doc.Sha512.outlen = The digest length: 64 for SHA-512 and 48 for SHA-384.
doc.Sha256New = A fresh SHA-256 state.
doc.Sha256Update = Adds the next piece of data.
doc.Sha256Final = Writes the final digest into the output.
doc.Sha384New = A fresh SHA-384 state; carry on with the Sha512 functions.
doc.Sha512New = A fresh SHA-512 state.
doc.Sha512Update = Adds the next piece of data.
doc.Sha512Final = Writes the final digest at the length in <code>outlen</code>.
doc.HmacSha256Hex = The HMAC-SHA256 signature of a message under a key, as hex; for checking that the message is untouched and comes from whoever holds the key. Key and message stop at a zero byte; use <code>HmacSha256Raw</code> for binary ones.
doc.HmacSha384Hex = HMAC-SHA384 as hex.
doc.HmacSha512Hex = HMAC-SHA512 as hex.
doc.HmacSha1Hex = HMAC-SHA1 as hex; for old services.
doc.HmacSha1Base64 = HMAC-SHA1 as base64; an OAuth 1 signature, for instance.
doc.HmacSha256Bytes = Writes HMAC-SHA256, 32 bytes, into the output.
doc.HmacSha384Bytes = HMAC-SHA384, 48 bytes.
doc.HmacSha512Bytes = HMAC-SHA512, 64 bytes.
doc.HmacSha1Bytes = HMAC-SHA1, 20 bytes.
doc.HmacSha256Raw = HMAC-SHA256 with the key and message given as a pointer and a length; for binary data.
doc.HmacSha384Raw = Raw HMAC-SHA384.
doc.HmacSha512Raw = Raw HMAC-SHA512.
doc.HmacSha1Raw = Raw HMAC-SHA1.
doc.RandomHex = n secure random bytes from the operating system, as hex with 2n characters; for ids and salts.
doc.RandomToken = A secure random token of n bytes, as 2n hex characters (the same as <code>RandomHex</code>); for session and password reset tokens.
doc.RandomBytes = Writes n secure random bytes into the given memory. When the operating system cannot, the program stops.
doc.Pbkdf2HmacSha256Hex = Derives a key with PBKDF2-HMAC-SHA256 from a password and a salt, at the given iteration count.
doc.HashPassword = Hashes the password with PBKDF2-HMAC-SHA256, 1000 rounds and a random 16 byte salt, and returns <code>pbkdf2-sha256$1000$salt$hash</code> to keep in your database. The output is different every time. 1000 rounds is low by today's standards; see the guide for a stronger hash.
doc.VerifyPassword = Checks a password against a <code>pbkdf2-sha256$rounds$salt$hash</code> string, with the rounds and salt it holds, in constant time. False for any other format.
doc.BcryptHash = Hashes the password with bcrypt and a random 16 byte salt, and returns the 60 character <code>$2y$cost$salt+hash</code> string that PHP <code>password_hash</code> also writes. The cost is the base 2 log of the rounds: each step up doubles the work; 10 is a common choice, and values are kept between 4 and 31. Only the first 72 bytes of the password count.
doc.BcryptHashWithSalt = Like <code>BcryptHash</code>, with your own 16 byte salt from a pointer instead of a random one, so the same input always gives the same string; for tests and known answers, not for storing real passwords.
doc.BcryptVerify = Checks a password against a stored <code>$2a$</code>, <code>$2b$</code> or <code>$2y$</code> string, with the cost and salt it holds, in constant time; hashes from PHP and other bcrypt libraries work. False for any other format.
doc.IsBcryptHash = True when the string looks like a bcrypt hash: 60 characters starting with <code>$2a$</code>, <code>$2b$</code> or <code>$2y$</code>. Useful when a database holds both bcrypt and <code>HashPassword</code> strings.
doc.BcryptCost = The cost written in a bcrypt hash, such as 10 for <code>$2y$10$...</code>; -1 when the string is not a bcrypt hash. Compare it with your target cost to know when to hash a password again.
doc.SecretEquals = Compares two secrets in constant time, so the answer time gives nothing away about their contents (only whether the lengths differ); for tokens and signatures.
