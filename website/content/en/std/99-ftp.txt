pkg.intro <<
<p>This package connects to FTP servers, for uploading a site to shared hosting or pulling files off old equipment and suppliers' servers. Plain FTP sends the password and the data unencrypted; wherever the server supports it, use <code>DialTLS</code>, which encrypts both the commands and the data with AUTH TLS. When the server also speaks SSH, SFTP through <a href="/std/ssh/">ssh</a> is the better choice: one encrypted connection, no separate data channel.</p>
<p>Transfers go in passive mode (EPSV, or PASV when the server lacks it), which works from behind a firewall; active mode (<code>PORT</code>) is not offered. The parsing functions, such as <code>ParseListLine</code>, are available for writing tools of your own too.</p>
<p>Things to know:</p>
<ul>
<li><strong>Call <code>Binary</code> before transfers</strong>, or a server in ASCII mode may change line endings inside images and archives.</li>
<li><strong><code>Upload</code> and <code>Download</code> hold the whole file in memory</strong>, and an interrupted transfer starts again from the beginning; there is no resume. Fine for site files and reports, not for multi-gigabyte backups.</li>
<li><strong><code>Read</code>, <code>Write</code> and <code>Append</code> carry a <code>str</code></strong>, so they are for text: binary content stops at the first zero byte. Use <code>Upload</code> and <code>Download</code> for anything else.</li>
<li>Servers that require TLS session reuse on the data connection refuse every transfer; see the last section.</li>
</ul>

<h2 id="guide-publish">Publish a site to shared hosting</h2>
<p>The usual job: connect with <code>DialTLS</code>, refuse to go on unless both the commands and the data are encrypted, log in, and upload a build directory with <code>UploadDir</code>. Switch to binary mode with <code>Binary</code> before any transfer, or some servers will change the line endings inside images and archives. Keeping the old <code>index.html</code> under another name with <code>Rename</code> gives you something to go back to.</p>
{{example.ftp-publish-site}}
<p>This needs a real server, so it is only checked here. Every function that talks to the server leaves the reply in <code>LastCode</code> and <code>LastReply</code>, so after a <code>false</code> you can always print what the server said.</p>

<h2 id="guide-sync">Fetch only the new files</h2>
<p><code>List</code> returns one <code>FileInfo</code> per entry with the name, the size and whether it is a directory or a link. Comparing that with what is already on disk turns a full download into a cheap sync, which suits a nightly job that collects reports from a supplier.</p>
{{example.ftp-sync-down}}
<p>For a stricter check than "the file exists", compare <code>f.size</code> with the local size, or <code>ModTime</code> with the time you stored after the last run.</p>

<h2 id="guide-listing">Read a directory listing yourself</h2>
<p>FTP has no fixed format for listings; most servers send the same columns as <code>ls -l</code>. <code>ParseListLine</code> reads such a line into a <code>FileInfo</code>, which is useful when you get listings from somewhere else, such as a log or a <code>ListRaw</code> call, and want to work with them without a connection.</p>
{{example.ftp-listing-report}}

<h2 id="guide-tls-reuse">Servers that require TLS session reuse</h2>
<p>Some FTPS servers insist that the data connection resumes the TLS session of the command connection. vsftpd does this with its default <code>require_ssl_reuse=YES</code>, and so do FileZilla Server and the Rebex test server. This package does not resume sessions yet, so on those servers logging in works but every listing and transfer is refused with reply 425:</p>
{{example.ftp-public-demo}}
<p>Run against <code>test.rebex.net</code>, it printed:</p>
<pre class="code" dir="ltr"><code>encrypted: true true
system: 215 UNIX Type: L8
listing refused: 425 Cannot secure data connection - TLS session resumption required.</code></pre>
<p>If you run the server, set <code>require_ssl_reuse=NO</code> in vsftpd. If you do not, and the server offers SFTP, use <a href="/std/ssh/">ssh</a> instead; fall back to plain <code>Dial</code> only on a network you trust, since it sends the password in the clear.</p>
