<h2 id="extern">درون‌داد</h2>
<p>در بلوک <code>درون‌داد:</code> روال‌های C را با گونه‌ی ورودی‌ها و خروجی‌شان اعلان کنید و بعد مثل هر روال سلام صدایشان بزنید. این اعلان‌ها بدنه ندارند: کد در کتابخانه‌ی C است و سلام فقط باید بداند چطور صدایش بزند. نام روال‌های C همان نام انگلیسی خودشان می‌ماند.</p>
{{example.ffi-extern}}
<p>مترجم به این اعلان‌ها کاملاً اعتماد می‌کند. اگر اعلان با روال واقعی C نخواند، مثلاً <code>صحیح</code> بنویسید جایی که C عدد <code>double</code> می‌خواهد، هیچ هشداری نمی‌بینید و برنامه داده‌ی بی‌معنا می‌خواند. پس امضای هر روال را با دقت از سرآیند کتابخانه یا راهنمای آن بردارید.</p>

<h2 id="printf">printf و روال‌های با ورودی متغیر</h2>
<p>روال C که شمار ورودی‌هایش ثابت نیست، مثل <code>printf</code>، با <code>...</code> پس از ورودی‌های ثابتش اعلان می‌شود. قاعده‌های قالب C برقرارند: <code>%d</code> برای <code>صحیح</code>، <code>%f</code> برای <code>اعشار۶۴</code>، <code>%s</code> برای <code>رشته</code>، و پهناهایی مثل <code>%-8s</code> و <code>%6.2f</code> برای ستون‌بندی:</p>
{{example.ffi-printf}}
<p>خروجی <code>printf</code> و <code>سرچاپ</code> به همان ترتیبی می‌آید که برنامه نوشته است، چون سلام پیش از صدا زدن روال C که چیزی می‌نویسد، بافر خروجی خودش را خالی می‌کند. فاصله‌گذاری <code>%-8s</code> بایت‌ها را می‌شمارد نه حرف‌ها را، و هر حرف فارسی دو بایت است؛ برای همین در این نمونه نام کالاها لاتین است. برای ستون‌بندی متن فارسی از <code>سرچاپ</code> یا بسته‌ی <a href="/std/fmt/">قالب بندی</a> استفاده کنید.</p>

<h2 id="pointers">اشاره‌گر، بافر و بایت صفر</h2>
<p>بسیاری از روال‌های C در حافظه‌ای که به آن‌ها می‌دهید می‌نویسند. این حافظه را با بسته‌ی <a href="/std/mem/">حافظه</a> بگیرید، اشاره‌گرش را بدهید و وقتی کارتان تمام شد آزادش کنید؛ یک <code>دیرکن</code> درست پس از گرفتن حافظه نمی‌گذارد فراموش شود. اشاره‌گر را مثل آرایه شماره بزنید: <code>بافر[ای]</code> یک خانه را می‌خواند یا می‌نویسد.</p>
{{example.ffi-buffer}}
<p>به خط وسط خروجی دقت کنید. رشته در نخستین بایت صفر تمام می‌شود، پس پنج بایت <code>H i 0 ! !</code> به رشته‌ی دوبایتی <code>Hi</code> تبدیل می‌شوند و هیچ خطایی هم دیده نمی‌شود؛ باقی بایت‌ها بی‌صدا از دست می‌روند. متنی که از C می‌آید را می‌شود رشته کرد، اما داده‌ی دودویی مثل تصویر، پرونده‌ی فشرده یا بسته‌ی شبکه را نه. داده‌ی دودویی را به شکل اشاره‌گر و طول نگه دارید و از راه اشاره‌گر بخوانید، همان کاری که حلقه‌ی جمع هر پنج بایت می‌کند.</p>
<p>روال C که ممکن است رشته‌ای برنگرداند، مثل <code>getenv</code> برای متغیری که تعریف نشده، اشاره‌گر تهی برمی‌گرداند. پیش از استفاده آن را با <code>(مقدار برگردان تهی*) == پوچ</code> بسنجید. رشته‌ای که C برمی‌گرداند مال کتابخانه‌ی C است؛ هرگز خودتان آزادش نکنید.</p>

<h2 id="link">پیوند کتابخانه</h2>
<p>روال‌های کتابخانه‌ی استاندارد C چیز دیگری لازم ندارند. برای هر کتابخانه‌ی دیگر، با <code>پیوند</code> پیش از بلوک <code>درون‌داد</code> به پیونددهنده بگویید کدام را بردارد. نوع پیوند همیشه نوشته می‌شود:</p>
<ul>
<li><code>پیوند پویا "sqlite3"</code> کتابخانه‌ی اشتراکی را پیوند می‌دهد، مثل <code>-lsqlite3</code> در ساخت C</li>
<li><code>پیوند ایستا "z"</code> کتابخانه‌ی ایستای <code>libz.a</code> را می‌خواهد که درون برنامه کپی می‌شود</li>
<li><code>پیوند چارچوب "Cocoa"</code> یک چارچوب مک را پیوند می‌دهد</li>
</ul>
<p><code>پیوند "m"</code> بدون نوع خطاست و پیامش هر سه نوع را نام می‌برد. چارچوب فقط روی مک وجود دارد، پس آن را درون یک <code>اگر</code> زمان ترجمه بگذارید، مثل این نمونه که کتابخانه‌ی ریاضی C را پیوند می‌دهد:</p>
{{example.ffi-link}}

<h2 id="export">برون‌داد: روال‌های سلام برای C</h2>
<p>بعضی روال‌های C شما را صدا می‌زنند. <code>qsort</code> آرایه‌ای از هر گونه‌ای را مرتب می‌کند و برای مقایسه‌ی دو خانه از روالی که شما می‌دهید کمک می‌گیرد. روال سلامی که C باید صدایش بزند در بلوک <code>برون‌داد:</code> می‌آید؛ آن وقت یک روال واقعی C با همان نام ساده است و <code>&amp;نام</code> نشانی آن است که جایی که C اشاره‌گر روال می‌خواهد داده می‌شود:</p>
{{example.ffi-qsort}}
<p>روال مقایسه دو اشاره‌گر <code>تهی*</code> به دو خانه می‌گیرد، آن‌ها را به <code>صحیح۳۲*</code> برمی‌گرداند و با <code>[۰]</code> می‌خواند. عددها باید در حافظه‌ای باشند که C به آن دسترسی دارد، برای همین برنامه آن‌ها را در بافری از بسته‌ی حافظه کپی می‌کند، می‌گذارد <code>qsort</code> همان‌جا مرتبشان کند و نتیجه را از راه اشاره‌گر می‌خواند.</p>
<p>روال برون‌داد همیشه یک نماد عمومی و معمولی C است و این قاعده‌ها را دارد:</p>
<ul>
<li>هر روال بلوک باید بدنه داشته باشد؛ اعلان بی‌بدنه جایش در <code>درون‌داد</code> است</li>
<li>متغیر، روال عام و ورودی <code>...</code> مجاز نیست</li>
<li><code>همگانی</code>، <code>درخط</code> و <code>نادرخط</code> مجاز نیست؛ فقط <code>بی‌کاره</code>، <code>ناب</code> و <code>نابرگشت</code></li>
<li>نام باید یک‌کلمه‌ای باشد، چون همان نام C می‌شود. با حروف لاتین بنویسیدش: پشتیبان LLVM مترجم هنوز نمی‌تواند نام برون‌داد غیرلاتین بسازد</li>
</ul>

<h2 id="pointer">صدا زدن از راه اشاره‌گر روال C</h2>
<p>جهت دیگر هم کار می‌کند. <code>(&amp;نام) برگردان درون‌داد روال (اعشار۶۴) اعشار۶۴</code> نشانی یک روال C، یا یک روال برون‌داد سلام، را به مقداری گونه‌دار تبدیل می‌کند که می‌شود نگهش داشت، جابه‌جایش کرد و صدایش زد. <code>درون‌داد روال (...) R</code> گونه‌ی ورودی هم هست، پس یک روال سلام می‌تواند با هر روال C به همان شکل کار کند:</p>
{{example.ffi-pointer}}
<p>نام یک روال معمولی سلام وقتی به‌عنوان مقدار به کار رود، نشانی آن به شکل <code>صحیح۶۴</code> است، همان چیزی که جدول‌های فراخوان مثل مسیریاب وب می‌گیرند. برای جای <code>تهی*</code> یا برای تبدیل به روال C گونه‌دار، <code>&amp;نام</code> بنویسید.</p>

<h2 id="rules">چند قاعده‌ی سرانگشتی</h2>
<ul>
<li>امضای هر روال C را دقیق بنویسید؛ مترجم نمی‌تواند آن را بسنجد.</li>
<li>برای متن از <code>رشته</code> و برای بایت از اشاره‌گر و طول استفاده کنید.</li>
<li>هر چه با بسته‌ی حافظه می‌گیرید آزاد کنید، و چیزی را که C برمی‌گرداند آزاد نکنید مگر راهنمایش بگوید.</li>
<li>اشاره‌گری را که C ممکن است تهی برگرداند پیش از استفاده بسنجید.</li>
<li>وقتی کتابخانه‌ی استاندارد سلام کاری را انجام می‌دهد همان را به کار ببرید: صدا زدن C را برایتان انجام می‌دهد و روی همه‌ی سیستم‌ها یکسان کار می‌کند.</li>
</ul>
